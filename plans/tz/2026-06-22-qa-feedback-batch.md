# ТЗ — QA-фиксы по фидбеку тестировщика (пачка)

## Цель
Закрыть пачку подтверждённых UX/функциональных дефектов из QA-прохода кабинета (под `svmazur@mail.ru`, Org «Ооо луа», 22.06.2026). Каждый дефект верифицирован глазами через Playwright и/или корнем в коде. Три крупные фичи вынесены в отдельные ТЗ (см. `relates_to`).

## Зачем
Тестировщик прошла кабинет и нашла ~20 проблем. Часть — баги, которые рвут ключевую ценность (сотрудники не видят транскрипт), часть — «непонятно зачем раздел» (провал онбординга), часть — дубли в навигации. Без этих фиксов команда не получает общую память встреч, путается в разделах и упирается в тупики (модалка «ждут решения» без действий).

## Фаза 1 — A1: транскрипт по видимости встречи (КРИТИЧНО). Закрывает: R1
**Цель:** сотрудник видит транскрипт встречи везде, где ему видна сама встреча.
**Корень (доказан):** `backend/src/modules/ai/services/transcript-cleaning.service.ts` — метод `getTranscript`, строки ~38-39 (якорь: `meeting.ownerId !== args.userId` → `throw new ForbiddenException('not_meeting_host')`). Эндпоинт `GET :id/transcript` (`backend/src/modules/meetings/meetings.controller.ts:170`). Образец правильной проверки — `MeetingsService.getResult` (`backend/src/modules/meetings/meetings.service.ts:854`: `await this.visibility.assertCanView(meetingId, userId)`).
**Что входит:**
- В `getTranscript` заменить владелец-гейт на `await this.visibility.assertCanView(args.meetingId, args.userId)` (инжектировать тот же сервис видимости, что использует `MeetingsService.getResult`; проверить имя/инъекцию — `VisibilityService`/аналог по `meetings.service.ts`).
- Фронт `frontend/src/ui/components/meeting-result-v2/MeetingResultPageReal.tsx` (`TranscriptTab`, SWR-вызов `meetingsApi.transcript`, `shouldRetryOnError:false`, плашка «Транскрипт ещё не готов» ~стр.1558): различать **403/forbidden** («Нет доступа к транскрипту») и **отсутствие реплик** («ещё не готов»). 403 не маскировать под «не готов».
**Что НЕ входит:** `requestClean` (очистка транскрипта, строки ~77-78) — владелец-гейт там оставить (это запись/действие, не чтение).
**Acceptance:**
- В `transcript-cleaning.service.ts` отсутствует `meeting.ownerId !== args.userId` в `getTranscript` (grep по файлу = 0 в этом методе), присутствует `assertCanView`.
- Юнит/e2e: запрос транскрипта от не-владельца, состоящего в Org, по встрече с `visibilityScope` «вся компания» → 200 + непустые `turns` (если транскрипт есть); по приватной встрече без доступа → 403.
- Фронт: при 403 рендерит «Нет доступа», при пустых turns — «ещё не готов» (разные ветки; grep на новый текст).
- `bun run typecheck` (вкл. `.spec`) · `bun run lint` · `bun run build` зелёные.
