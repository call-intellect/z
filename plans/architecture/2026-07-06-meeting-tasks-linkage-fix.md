# Задачи встречи возвращаем в саму встречу

## Что это и зачем

После встречи Кора разбирает разговор и вытаскивает из него задачи («следующие шаги»). Ожидание простое: открываешь встречу → вкладка «Задачи» → там список того, что решили сделать. Сегодня там **всегда пусто**, хотя задачи Кора на самом деле создала — они просто «оторвались» от встречи и осели в общем списке дел. Человек видит пустую вкладку и делает вывод «Кора не ставит задачи по встречам» — это бьёт по одному из главных обещаний продукта.

Второе, что всплыло: задача, которую по смыслу должен делать **гость** встречи (человек со стороны, не сотрудник компании), автоматически вешается на случайно-подходящего сотрудника. На разобранной встрече задачу «найти компании для пилота», о которой говорил гость Роман, система повесила на сотрудницу Айназ, которой на встрече не было. И почему так вышло — нигде не записано, разобраться постфактум невозможно.

## Как сегодня

- Встреча прошла → Кора сделала отчёт → из отчёта вытащила задачи. **Это работает** — задачи создаются.
- Но когда задача рождается из отчёта встречи, к ней **не прикрепляется «ярлык встречи»**. Без этого ярлыка вкладка «Задачи» встречи (которая показывает только задачи с этим ярлыком) остаётся пустой. Задача при этом живёт — либо уже как полноценная задача в общем списке, либо застряла в «черновиках» (задачи-кандидаты, которые ждут подтверждения).
- Когда у задачи назван исполнитель, система пытается сопоставить имя с сотрудником. Если имя — гость (не сотрудник), сопоставление не срабатывает, и включается **авто-подбор по навыкам**: задачу отдают тому сотруднику, чей профиль лучше всего подходит под текст задачи. Так задача гостя и ушла Айназ.
- Решение авто-подбора **не логируется** — восстановить «почему на этого человека» нельзя.

## Что делаем

Три вещи:

1. **Возвращаем ярлык встречи.** Когда задача рождается из отчёта встречи — прикрепляем к ней ярлык этой самой встречи, чтобы она появилась во вкладке «Задачи» встречи. Технически id встречи у нас на руках (он «зашит» в имя источника-отчёта) — надо его достать и проставить. Это и есть «починка последней мили»: разбор задач уже работает, добавляем недостающую привязку.

2. **Убираем «фантом».** В коде есть недоделанный отдельный разборщик задач для встреч, который «числится, но не работает», и из-за него основной разборщик думает «встречи разберёт кто-то другой» — а разбирать некому. Наводим порядок: единый разборщик, который реально работает, и делает привязку.

3. **Включаем память о решениях (логи).** Записываем, почему задача досталась именно этому человеку (нашли по имени / подобрали по навыкам / оставили без исполнителя) и почему привязалась/не привязалась к встрече. Чтобы в следующий раз такой разбор занимал минуты, а не полдня раскопок.

## Как это будет выглядеть

### Сценарий 1 — вкладка «Задачи» встречи

> **Было:** открываешь встречу «Роман. Встреча по консалтингу» → вкладка «Задачи» → «Задач пока нет», хотя в отчёте есть блок «Следующие шаги» с делами для Сергея и Романа.
>
> **Стало:** открываешь ту же встречу → вкладка «Задачи» → список из тех же «следующих шагов», каждый — кликабельная задача со статусом и исполнителем.

```
┌─ Роман. Встреча по консалтингу ─────────────────────────┐
│  Обзор | Отчёты | Главы | Транскрипт | Чат | [ Задачи ] │
├──────────────────────────────────────────────────────────┤
│  Задачи встречи                                  2 всего  │
│                                                           │
│  ☐  Зафиксировать позиционирование и продумать          │
│     механику тестирования онбординга                     │
│     Исполнитель: Сергей        · создано из встречи      │
│                                                           │
│  ☐  Найти подходящие компании для пилотного внедрения    │
│     Исполнитель: — (по словам гостя: Роман)  ·  из встречи│
│                                                           │
│  [ + Добавить задачу вручную ]                            │
└──────────────────────────────────────────────────────────┘
```

### Сценарий 2 — задача, исполнитель которой — гость

> **Было:** задача «найти компании для пилота» (о ней говорил гость Роман) молча повешена на сотрудницу Айназ, которой на встрече не было. Никакого следа почему.
>
> **Стало (рекомендуемый вариант):** задача создаётся **без исполнителя**, с подписью «по словам гостя: Роман». Руководитель сам решает, кому её отдать. В логах записано: «исполнитель не назначен — названный владелец Роман не является сотрудником».

### Как поймём, что получилось

- Открываешь любую только что прошедшую встречу → во вкладке «Задачи» реально видишь задачи из её «следующих шагов» (а не пусто).
- Задача из встречи, у которой исполнитель — сотрудник, назначена на него; задача гостя — без ложного исполнителя.
- По логам одной задачи видно: к какой встрече привязана и почему исполнитель именно такой.

## Делаем поверх существующего

Это **не новая функция, а починка существующей**. Разборщик задач встречи уже работает в проде — мы добавляем ему недостающую привязку к встрече и убираем недоделанный дубль-разборщик. Вкладка «Задачи» встречи тоже уже есть — она просто сейчас ничего не находит. Никаких новых экранов и новых разделов не появляется.

## Границы — что НЕ делаем

- **Не переписываем разбор отчёта и извлечение задач** — только чиним привязку и назначение.
- **Не трогаем задачи из других источников** (чаты, ежедневные чек-ины) — только производные от встречи.
- **Не переделываем сам авто-подбор по навыкам** — меняем только поведение для случая «владелец — гость» (по выбранному ниже варианту) и добавляем к нему логи.
- **Не делаем массовый пересчёт старых встреч** (backfill исторических задач) — это отдельная возможная задача на потом, если понадобится вернуть привязку задним числом.

## Решения, что я принял за тебя (можно возразить)

| # | Решение | Почему так |
|---|---|---|
| 1 | Чиним существующий разборщик, а не оживляем отдельный «для встреч» | Существующий уже работает в проде; оживлять недоделанный — это второй разборщик на том же материале, двойные задачи и лишние расходы. Меньше риска. |
| 2 | Задачи из встречи должны сразу становиться настоящими задачами (не застревать в черновиках), как это уже сделано для другого «встречного» канала | Иначе половина задач так и висит непринятой — человек их не видит. Приводим оба канала встречи к одинаковому поведению. |
| 3 | Логи назначения и привязки — обязательная часть, а не «потом» | Именно их отсутствие не дало разобраться в истории с Айназ. Без них следующий такой случай снова будет «полдня раскопок». |

## Что реши ты (одна развилка)

**Кому назначать задачу, если её исполнитель по смыслу — гость встречи (не сотрудник)?**

Сейчас такая задача молча уходит случайному подходящему сотруднику (так Айназ получила чужую задачу). Это надо изменить. Варианты:

- **(А) — рекомендую.** Оставлять **без исполнителя**, с подписью «по словам гостя: <имя>». Руководитель сам решит, кому отдать.
  *Почему:* авто-назначение чужой задачи создаёт ложную ответственность — человек получает дело, которое не брал, со встречи, где не был. Честнее показать «владелец — гость» и дать человеку решить.
- **(Б)** Назначать на **ведущего встречи** (того, кто её проводил). *Почему может подойти:* обычно именно ведущий дальше «ведёт» договорённость с гостем. Минус: ведущий формально становится исполнителем того, что обещал не он.
- **(В)** Оставить как есть (авто-подбор по навыкам), но с логом причины. *Почему обычно нет:* это ровно то поведение, которое сейчас и смущает — просто станет видно в логах, но задача по-прежнему у «не того» человека.

Моя рекомендация — **(А)**.

> **РЕШЕНИЕ ВЛАДЕЛЬЦА (2026-07-06):** выбран вариант **(А)** — задача, чей названный владелец не является сотрудником орга, создаётся **без исполнителя** с пометкой «по словам гостя: <имя>»; авто-подбор по навыкам для такого случая НЕ применяется. Не пересматривать.
