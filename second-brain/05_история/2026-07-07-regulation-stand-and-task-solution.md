# Стенд агентов регламентов/инструкций + сущность «Решение задачи»

## Что было поставлено
Собрать тестировочный стенд для агентов, отвечающих за регламенты/инструкции (подача синтетики → проверка «что
создалось» против эталона), а затем — ввести новую сущность «Решение задачи» и добавить её в стенд.

## Как решал (файлы/коммиты)
- **Разобрал пайплайн «Специалист 3.1 (Регламенты)»:** три LLM-агента — `regulation-extract` (классификатор
  вида + суть + фильтры), `regulation-dedupe` (арбитр: new/merge/extension/contradicts), `structured-document-compiler`
  (собирает/дополняет `contentMd`, режимы СОЗДАНИЕ/ДОПОЛНЕНИЕ). Сущности: Regulation/Instruction/Policy/Process(+ProcessStep)/Standard.
- **Стенд:** карта ситуаций 360° [analysis/2026-07-03-regulation-instruction-stand-situation-matrix] + ТЗ
  [tz/2026-07-03-regulation-instruction-stand] + методология слепой разметки. Стартовые 26 сценариев вручную →
  **fan-out Workflow** (18 веток + проверка эталона + критик пробелов) → 493 сценария, паритет 1:1.
- **Ось A4 «Владение»** (+16 сценариев): регламент всегда привязан к человеку (`ownerPersonId`/`personSubjectIds`→клон).
  Корень фабрикации `usedRegulationNames` = **сломанное владение** при смене носителя (старый снимок клона течёт),
  а не «плохой поиск».
- **Сущность «Решение задачи» (TaskSolution):** архитектура [architecture/2026-07-07-task-solution-entity] +
  ТЗ [tz/2026-07-07-task-solution-entity] + orchestrator-промпт. Отдельная сущность (не 6-й вид регламента),
  двойное назначение (материализуем И кормим клон), суточная сборка из сигналов дня, владелец=решавший,
  повтор→кандидат в инструкцию, UI-вкладка. Ось A5 (+12 сценариев) → 521 сценарий.
- **Два хэндофф-промпта:** реализация сущности + прогон стенда (батчи по 50 со стоп-гейтом).
- Коммиты на `work/2026-07-07`, push прошёл (remote = HEAD `a57b8294`).

## Что вышло
Готовый пакет стенда (521 сценарий, эталон 1:1, покрытие A1–A5 + СК), ТЗ на сущность, два промпта. Стенд НЕ
запускался (только подготовка данных). Прод не тронут (всё docs/plans; сущность — будущая реализация).

## Чему научился (грабли)
- **Workflow-субагенты пишут файлы в cwd = корень репо**, а не в переданный scratch-путь (взяли рабочий каталог).
  Итог: 19 `reg-batch-*.json` осели в корне → пришлось сливать node-скриптом и удалять из корня (в коммит не пустил).
  На будущее: заставлять абсолютный путь И всё равно проверять/чистить корень после fan-out.
- **Первый push большой ветки таймаутится на клиенте (exit 143/143), но объекты долетают серверно** — ref
  создаётся. Проверять `git ls-remote --heads` (remote==HEAD), а не верить exit-коду; повторный `-u` push потом
  отклоняется «reference already exists» — это не провал.
- **Корень фабрикации `usedRegulationNames` — владение, не retrieval.** Оформил как отдельную ось стенда (A4),
  с метрикой `desync_no_fabrication` (смена носителя → старый снимок не выдумывает имена).
- Стенд по 493+ сценариям гонять батчами по ~50 со стоп-гейтом — систематическая ошибка класса видна рано.
