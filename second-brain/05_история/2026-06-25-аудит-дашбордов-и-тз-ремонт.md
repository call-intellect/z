# Аудит дашбордов + ТЗ-ремонт (Сегодня / Аналитика / Неделя / Месяц)

## Что было поставлено
Владелец (svmazur@mail.ru, орг «Ооо луа»): дашборды после изменений «корявые» — пустые места, длинные непонятные ленты, неинформативно; «ощущение, что каждый модуль не работает». Задача QA-тестировщика: изучить дашборды, по каждому модулю понять работает/не работает (в т.ч. по API), особое внимание — планы/отчёты сотрудников. Затем — разобрать каждый модуль, предложить новую архитектуру, и в итоге написать ТЗ на ремонт с жёстким условием **ничего не удалять**.

## Как решал
- Вход в прод-кабинет через Playwright (скилл `qa-tester`); креды положены в gitignored `.qa-cabinet.local.json`.
- Обошёл 4 дашборда (`/dashboard`, `/dashboard/operations`, `/week`, `/month`) + под-страницы. По каждому: скрин + снапшот + **перехват реальных API-ответов** через `browser_evaluate(fetch с x-org-id)` + консоль.
- Прочитал фронт-архитектуру: дашборды собираются из `WIDGET_REGISTRY` (20 виджетов) + `DEFAULT_PRESETS` (порядок по ритмам) + `DashboardCanvas` (grid-12). Бэк — `backend/src/modules/dashboard/*` и `operations/*`.
- Зафиксировал доказательную аналитику в `plans/analysis/2026-06-25-dashboards-architecture-audit.md` (+ паспорт модулей Сегодня) и написал ТЗ `plans/tz/2026-06-25-dashboards-repair.md` (9 фаз) скиллом `tz-author`.

## Что вышло (ключевые находки, проверенные кодом+API)
- **Корень «пустот»:** `DashboardCanvas.tsx` — линейный `grid grid-cols-12` по фикс-размерам (md=6/lg=8/xl=12) без балансировки → lg(8) оставляет 4 пустых колонки; длинный список рядом с коротким → дыра.
- **Дублирование ритмов заложено в дизайн:** `DEFAULT_PRESETS` — today ⊂ week ⊂ month (виджеты повторяются на всех трёх).
- **Цель не подхватывается:** `execution-dashboard.service.ts:338` `resolveGoalId` падает в null (нет primary-цели + пуста `personGoalContribution`), хотя активная цель «Запустить 10 компаний» есть (`isPrimary:false, promotionState:suggested`).
- **Дубли с бэка:** `customer-risk-radar.service.ts:303 listForTenant` отдаёт все снапшоты (3 клиента → 20 строк); recurringTopics дублит `themeId`.
- **Период:** `ValueWidget.tsx` на today берёт `director?period=month` (директор-enum знает только week|month, day нет).
- **План/факт:** «1 из 1» вводит в заблуждение (ждали 1, не сдали двое); данные для честной формулы уже есть в `PlanFactWidget` (missing.totalEmployees).
- **Графики:** recharts `width(-1) height(-1)` — контейнеры без minHeight → пустые тёмные полосы.
- **Лента:** `cora-feed.service` уже типизирует события (insight/open_question/activity/…), `FeedWidget` имеет иконки — не хватает текстовых бейджей + фильтра.
- Все эндпоинты 200, кроме `weekly-digest` 404 (/month) и RSC `/me/commitments` 404.

Верификация: чтение реального кода (`path:line`) + живые ответы API под аккаунтом владельца. ТЗ собрано как контракт с машинной приёмкой, инвариант «не удалять» прошит в шапку/границы/DoD. Реализацию ведёт другой агент/сессия (`tz-orchestrator`).

## Чему научился
- **Перехват API через Playwright `browser_evaluate(fetch, {headers:{'x-org-id'}})`** — мощный способ доказательного QA: видно, что бэк реально отдаёт, отдельно от того, как фронт рисует. Куки httpOnly уходят сами (`credentials:'include'`), org-id берётся из заголовка реального запроса.
- **«Нули» ≠ «сломано»:** на маленькой компании половина блоков «Аналитики» легитимно пуста — дашборд переразмерен под объём данных; лечится пустыми-стейтами, а не переделкой.
- **REALITY-CHECK экономит scope:** часть «фиксов» уже частично есть (goal fallback, иконки ленты, данные plan-fact) — нужно достроить, а не писать заново.
