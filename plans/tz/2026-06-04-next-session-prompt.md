4. **После деплоя** — проверить эффект на проде через `diag` (трейс новой встречи: дошла ли до `ai_ready`, есть ли отчёт, наполнился ли граф).

## ПРАВИЛА (из CLAUDE.md / памяти)

- Перед стартом: `git fetch` + `git log --since=...` — в репо параллельные сессии.
- «Крутилки» (пороги linker/theme/entity-graph) — в **AdminSetting + getDynamic**, не в ENV/код.
- **Чини весь КЛАСС, не кейс**; верь коду, не интуиции (мини-e2e); агенты могут лгать про `[x]` — греп-факт-чек после правок.
- Prisma: только `prisma db push`, никогда `migrate`. После правки моделей — `prisma generate`.
- Машинный гард: `tsc` **слеп** к лишним ключам Prisma-литералов — ловить интеграционными тестами против реального Postgres.
- Коммит — по фазам; **push — только по явному подтверждению владельца**; рефлексия в `second-brain/05_история/` — авто после push.
- Prod-операции — через `docs/operations/prod-deploy-log.md` (всё через `docker compose exec backend …`).
