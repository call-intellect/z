### 1.1 🔴 НОВОЕ/ОСТАВШЕЕСЯ — `/tables/[id]` падает (React #185), таблица не рендерится

**Симптом.** Открытие любой детальной таблицы (`/tables/cmpwpjeal00brjvpds3acvw8l` «Команда», `/tables/cmpv3sqwe000g01mkfeo50uvx` «1» — проверены обе, **детерминированно** после reload) показывает русский error-boundary «Не удалось загрузить страницу» вместо грида. Консоль: `Minified React error #185` (Maximum update depth exceeded) в `4bd1b696-*.js` (React-внутренности). ChunkLoadError при этом НЕТ (`hasChunkError=false`) — webpack его убрал.

**Корень (подтверждён кодом).** Селекторы `selectVisibleProperties` ([tableStore.ts:931](../../frontend/app/(authenticated)/tables/[id]/store/tableStore.ts#L931)) и `selectVisibleRows` ([tableStore.ts:960](../../frontend/app/(authenticated)/tables/[id]/store/tableStore.ts#L960)) возвращают **новый массив на каждый вызов** (`.filter()`, `[...visible].sort()`, `applyFilters()`), а используются как Zustand-селекторы `useTableStore(selectVisibleRows)` ([TableClient.tsx](../../frontend/app/(authenticated)/tables/[id]/TableClient.tsx) → GridView). Нестабильная ссылка из `getSnapshot` → `useSyncExternalStore` каждый рендер считает, что стор изменился → бесконечный ре-рендер → React #185. **Баг был всё время, но маскировался ChunkLoadError** (страница падала до рендера грида); webpack починил чанки — баг вскрылся.

**Авто-reload не спасает:** глобальный обработчик ТЗ-1 завязан на `ChunkLoadError`, а тут другой класс ошибки → тихий reload не триггерится, пользователь видит ручную «Обновить» (которая не помогает — краш детерминированный).

**Связанный минор:** `GET /api/v1/tables/pending-patches?tableId=… → 404 (table_not_found)` ([tables.api.ts:382](../../frontend/src/api/tables.api.ts#L382)). Отдельный баг панели правок, не корень #185.

**Рекомендация (для ТЗ).** Обернуть селекторы в `useShallow` (Zustand 5) или вычислять видимые строки/колонки через `useMemo` в компоненте; добавить локальный `error.tsx` уже есть — но нужен фикс самого рендер-лупа. Acceptance: `/tables/<id>` открывает грид, в консоли нет React #185.

## 3. ТЗ-3 — Устойчивость графа знаний (невалидный JSON арбитра)

🟢 **Фикс работает.** В цепочке встречи `01KTGNR4…` **7 раз** `[WARN] LlmRouter dispatch fallback: deepseek/deepseek-v4-flash: ответ не прошёл validate caller'а` — и **каждый раз немедленно** `LlmRouter dispatch success`. То есть битый ответ flash ловится новым validate-callback'ом (ТЗ-3 Ф2) и достраивается на secondary, а не засчитывается «молчаливым успехом» с потерей связи.

Решающее доказательство деплоя: WARN `entity-graph-builder: invalid JSON LLM-арбитра — fallback на none` (потеря связи) встречается **только до ~08:02** (07:00–08:02, 7 записей), после деплоя бэкенда — **исчезает полностью**. tryParseJson+ретрай (ТЗ-3 Ф1) на entity-graph активен.

⚠️ Базовая доля невалидного JSON у `deepseek-v4-flash` всё ещё высокая (7 fallback'ов на одну короткую встречу) — фикс корректно её маскирует (связи строятся через secondary), но первопричина (качество flash в strict-JSON) остаётся; форс `tool_choice`+`strict` (ТЗ-3 Ф3) — за флагом OFF.
