# 13 — Глоссарий русских терминов

Этот глоссарий — авторитетный источник UI-копирайта. Любая user-facing строка должна использовать русское название из этой таблицы. Английские термины сохранены для технической документации и кода.

## Фаза 0 — каркас компании (Z 2026-05-21)

Все термины — на русском. Английские слова в UI запрещены (правило `feedback_admin_ui_russian_only.md`).

## Принципы перевода

1. **Простой человеческий русский.** Без канцеляризма и без англицизмов.
2. **Понятно нетехническому руководителю.** Если CFO малого бизнеса не понимает термина — он плохой.
3. **Согласованность.** Один и тот же англицизм всегда переводится одним и тем же русским словом.
4. **Длина не критична.** «Согласованность стратегии» лучше «Strategy Alignment», даже если длиннее.
5. **Никаких транслитов.** Не «эмбеддинг», а «семантический отпечаток» / «вектор смысла» (в технических разделах). В UI вообще не упоминается.

| Замена (новой версией) / заменить (supersede) | Новая версия старого решения. Старое получает `status='superseded'` + `validUntil`, новое — `supersedesId` + `validFrom`. Через ConflictItem с resolution='evolving'. | Отмена (`cancelled`) — решение признано неактуальным, замены нет. |
| Заменено (superseded) | Статус: это решение заменили новой версией. | Отклонено (`rejected`) — решение не приняли с самого начала. |
| Предложенное (proposed) | Решение озвучили, но ещё не приняли. | Принятое (approved) — финализированное. |
| Принятое (approved) | Решение принято и зафиксировано (default для автоматически извлечённых решений). | Реализованное (implemented) — выполнено фактически. |

| Отклонённое (rejected) | Решение рассмотрели и отвергли. | Отменённое (cancelled) — приняли, потом отменили. |
| Отменённое (cancelled) | Решение отменили после принятия. | Заменённое (superseded) — отменили, потому что приняли новую версию. |
| Действительно с (validFrom) | С какого момента решение действует. Заполняется при создании или supersede. | Принято (decidedAt) — когда формально решили (может быть в прошлом). |
| Действительно до (validUntil) | До какого момента решение действовало. Для superseded — момент замены. | Срок исполнения (deadline) — когда надо реализовать. |
| Срок исполнения (deadline) | Когда решение должно быть реализовано. Если deadline < now AND status ∉ {implemented, cancelled} → probe `decision.overdue`. | Дата принятия (decidedAt). |
| Просрочено (overdue) | Состояние UI: deadline в прошлом, статус не финальный. | Истёк срок действия (validUntil) — это про temporal-валидность, не про срок задачи. |
| Фактический результат (actualOutcomes) | Что в реальности случилось после реализации. Заполняется ретроспективно (probe `decision.outcome_unknown` через 3 мес.). | Обоснование (rationale — почему решили, до факта). |
| На что влияет (affectsEntityIds) | Entity-сущности (Customer/Project/Vendor/Product), на которые решение влияет. Массив с GIN-индексом. | Авторы (`decidedByPersonIds` — кто принял). |
| Автор решения (decidedByPersonIds) | Кто принял решение. Массив Person.id. Резолвится по hint'ам и subject-Person'ам блока. | На что влияет (`affectsEntityIds` — на кого влияет). |
| Эволюция (evolving) | Тип резолюции конфликта: «старое было правильно до даты X, новое — с даты Y». Используется для supersede. | Слияние (merge) — это уточнение того же решения; evolving — содержательная замена. |
| Результат неизвестен (`decision.outcome_unknown`) | Probe-event (cron): status='implemented' AND actualOutcomes=null AND decidedAt < now − 3 мес. | `decision.missing_decider` — нет автора. |
| `decision.missing_decider` | Probe-event: решение без автора. Probe участникам исходной встречи. | `decision.no_deadline_critical` — без срока для критичного. |
| `decision.no_deadline_critical` | Probe-event: критичное решение (`tag='critical'` в блоке) без deadline. Probe владельцу. | `decision.overdue` — срок уже прошёл. |
| `decision.overdue` | Probe-event (cron): deadline < now AND status не финальный. | `decision.outcome_unknown` — реализовано, но без actual outcomes. |
| `decision.competing_versions` | Probe-event: KNN нашёл близкое решение, supersede-detect не уверен. Probe владельцу/admin. | `decision.evolving_supersedes` — это не probe, это conflict-event при автоматическом supersede. |
| 3-3-decisions | Имя специалиста в `RouterService.SPECIALIST.DECISIONS`, в `CardSpecialistRegistry`, в jobName очереди `core.specialist-routing`. | 3-1-regulations / 3-4-project-customer / 3-2-knowledge-clone (соседние специалисты). |
| Specialist 3.3 | «Специалист по решениям». Обрабатывает блоки signalType ∈ {decision, rationale, decision_basis}. Cron `0 5 * * *` для overdue / outcome_unknown. | Слой 4 (триаж + curation). 3.3 публикует proposedPayload через `triage` — а decision всегда critical-type → deep review. |
| `decision` (ResourceType) | RBAC-ресурс. Read: все member'ы Org (decisions — shared knowledge). Write/delete: owner/admin. | `decision-extract` / `decision-supersede-detect` — это LlmTaskType, не ResourceType. |
| Цепочка версий (supersede chain) | Линейная история замен Decision'а: «v1 → v2 → v3 → текущий». В UI — ancestors (вверх) + descendants (вниз). | Темп. валидность (validFrom/validUntil — про каждую версию отдельно). |
| `decision-extract` | LLM-таск-тип: из IdeaBlock → черновик Decision (statement, rationale, alternatives, hints). | `decision-supersede-detect` — арбитр {new/merge/supersedes}. |
| `decision-supersede-detect` | LLM-таск-тип: арбитр по top-K KNN-кандидатам. На supersedes — заполняет evolvingMeta. | `decision-extract` — извлекает черновик из блока. |
