## 0. Что это и зачем (одним абзацем)

Кора строит **клона сотрудника/должности** автоматически из встреч, чатов и закрытых задач (черты рассуждений → персона → регламенты → процедуры). Владелец хочет сделать Кору **лучшей в зарождающейся категории «AI-клоны сотрудников»**: сотрудник уволился — клон отвечает на любой вопрос **как он или лучше**, всегда **как эксперт** (позиция → совет → план действий), опираясь на роль/черты/скиллы/регламенты/знания и **перенос по аналогии** («точно такого не было, но в похожей ситуации я делал так»). Ответ «по факту есть/нет» — это режим справочника, а не эксперта. Задача агента: построить **измерительный стенд + линейку оценки**, снять точку отсчёта, и **петлёй итераций (прогон → диагноз → ТЗ → фикс → перепрогон)** довести клона до планки качества.

## 3. Ключевое, что нужно понять до старта

**Главное противоречие.** Текущий клон спроектирован ПРОТИВОПОЛОЖНО замыслу — «лучше отказ, чем выдумка». Четыре контура отказа (аудит §1.3): (1) < 3 черт → 404; (2) анти-deepfake гейт «< 2 блоков по теме» → отказ ДО LLM; (3) промпт велит отказываться; (4) ответ без цитат заменяется отказом. «Экспертный» режим по аналогии в коде ЕСТЬ (`judgmental`), но заперт за выключенным флагом `CLONE_V2_ENABLED`. Ретрив клона — «последние 20 блоков», не поиск по вопросу; механизм «поиск похожей ситуации» вычисляется, но никуда не подключён. **Baseline это подтвердит числом — и это нормально, это точка отсчёта.**

**Канал «уведомляльщика» реализован** (важно, ранее была ошибка в оценке). Мостик «задача перешла в „решено" → probe „расскажи, как решал" → ответ → reasoning-блок → клон» работает (Ф5/Ф6, 2026-06-29): probe на любой переход в completed, ответ ингестится в общий конвейер. НО у канала есть глушители пропускной способности (complexity-гейт 0.5, rate-limit 20/день, дедупы) — стенд меряет их воронкой кормления, а не «открывает мостик заново».

**Данных для клонов сейчас нет.** В Стреле клонного корма 9 блоков на весь тенант, профили по 1 черте (порог 3), ролей/назначений 0, Елена намеренно слита с Игорем. Поэтому **Фаза 0 (наполнение) — обязательный первый шаг при любом раскладе**: без неё стенд упрётся в «клон не сформирован».

**Рынок подтверждает ставку** (аудит §7): категория живая (Viven $35M, Delphi $16M), но никто не делает лестницу ответа при пробелах, клона должности, автосбор из встреч для SMB, публичную метрику качества. В РФ прямых конкурентов нет. Научный факт для линейки: LLM-судьи оценивают клонов плохо (PersonaEval 69% vs 90.8% у людей) → **линейка опирается на ground truth по построению** (сеем метод сами — знаем эталон каждого ответа), LLM-панель только поверх.

## 6. Линейка оценки — «маркеры идеальности» (кратко; полно — проект §4)

**5 осей (0..1):** E экспертность · M верность методу (шкала 1.0/0.5/0.3/0.0) · G заземлённость (не выдумал) · L опора на нужный слой · P персона.

**Вердикт на вопрос** (детерминированно, сверху вниз): BOUNDARY_OK/FAIL (для boundary+off_domain) → FABRICATED → REFUSED → EXPERT_PASS (E≥0.7 ∧ M≥0.5 ∧ L ∧ P) → WEAK (остаток).

**Планка (приёмка петли):** EXPERT_PASS ≥95% на отвечаемых (96 из 110) И ≥90% на свежем банке ~20; **железные инварианты:** FABRICATED=0, BOUNDARY_OK=14/14, ср. M≥0.7. Планку задаёт владелец.

**Петля, 3 исхода:** планка взята → финал; остаток вне рычагов scope → стоп + честный разбор потолка + решение владельца; иначе → следующая итерация. Чинить КЛАСС провалов, не кейс. Каждый провал сверять с сырым ответом, не с флагом линейки (дефект линейки = отдельный класс, чинится первым).
