# Эталон промпта: `chat-summary`

> «Что пропустил» — сводка непрочитанной переписки рабочего чата для участника, который давно его не открывал. Собираем `Message` с `seq > lastReadSeq` (без `system`, без удалённых), отдаём модели и получаем компактную сводку «кто·что обсудили·решения/действия» с цитатами `[MSG:<id>]` для дип-линка в исходное сообщение.
> **Где живёт:** `backend/src/modules/messaging/prompts/chat-summary.prompt.ts`, `taskType='chat-summary'`, вызывается из `backend/src/modules/messaging/services/chat-summary.service.ts` (эндпоинт `GET /conversations/:id/whats-new`).
> **Контракт реализации:** `plans/tz/2026-06-21-unified-chat-kora-tz.md` Ф5 (R19).

---

## Ключевое решение: цитаты как машинно-разбираемые ссылки

Сводка бесполезна, если из неё нельзя провалиться в исходное сообщение. Поэтому формат цитаты — не «как сказала Аня», а `[MSG:<id>]`, где `<id>` фронт превращает в дип-линк к сообщению в ленте. Каждое сообщение во входе подаётся как `[MSG:<id>] <автор>: <текст>` — модель переносит ровно тот же `id`. SYSTEM явно запрещает выдумывать id.

Гейт «строить ли вообще сводку» держится в коде, не в LLM: при `count < chat_summary_min_messages` (крутилка, код-fallback 5) сервис возвращает `{skipped:'too_few'}` без обращения к модели — для пары сообщений сводка дороже и хуже, чем просто прочитать их.

## Эталонный промпт (канон)

### SYSTEM (стабильный, без переменных → кэшируется)
- **Роль** — «Ты сводишь непрочитанную переписку рабочего чата для участника, который давно её не открывал».
- **Якорь смысла** — даёт «что я пропустил»; кому (участнику, вернувшемуся в чат).
- **Формат (критерии)** — компактный markdown: (1) кто·о чём по темам, без пересказа каждого сообщения; (2) решения/договорённости/действия (кто что должен), если есть.
- **Контракт цитат** — каждый тезис подкреплять `[MSG:<id>]`, id брать из входа, не выдумывать.
- **Запреты Z** — по-русски, без воды/вступлений, не повторять инструкции, не цитировать сообщения целиком.

### USER (переменные — в конце)
```
Разговор: <title>
Непрочитанных сообщений: <N>

Переписка (по порядку):
[MSG:<id>] <автор>: <текст>
…
```

### Выход
Свободный markdown (не JSON) — сводка для прямого показа человеку. Strict-схема не нужна: ошибки форматирования некритичны, парсинг id фронтом устойчив к лишнему тексту.

## Разбор по анатомии (почему классный)

| Блок методологии | Как реализован здесь |
|---|---|
| **1. Роль/персона** | «Ты сводишь непрочитанную переписку… для участника, который давно её не открывал». Узкая роль. |
| **2. Якоря смысла** | зачем (дать «что я пропустил»), кому (вернувшийся участник), что станет (сводка показывается ему сразу). |
| **3. Критерии хорошего** | формат по темам + отдельно решения/действия; «без пересказа каждого сообщения». |
| **6. Контракт** | markdown с обязательными `[MSG:<id>]`; id строго из входа. |
| **7. Запреты Z** | чистый русский, без воды/вступлений, не цитировать целиком, не выдумывать id. |
| **Cache-friendly** | весь текст в SYSTEM (стабилен, ноль переменных); title + N + сообщения — в конце USER. Snapshot-spec фиксирует стабильность SYSTEM. |
| **Гейт ≠ формулировка** | «строить ли сводку» решает код (порог `chat_summary_min_messages`); LLM — только формулировка. |

## Как мерили (ship-on, без блокирующего golden)

Выкат включённым (маршрут `chat-summary` едет `seed-llm-task-routes-chat.ts`, primary deepseek-v4-flash). Жёстко — `typecheck`/`build` + unit (count<min → skipped; count≥min → llm.call со стабильным SYSTEM; system-сообщения исключены; не-член → 403) + snapshot-spec стабильности SYSTEM. Golden не блокирует ([[feedback_no_golden_ship_and_observe_prod]]).
