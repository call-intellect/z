# Разбор «единого окна общения с Мастером» + доработка ТЗ под реализацию

## Что было поставлено
Владелец: единая точка общения с Мастером — плавающая кнопка + вход из меню → полноценное окно (история диалогов слева, новый диалог, поле ввода снизу, переключение «общий разбор / по клонам», у каждого режима свои диалоги). «Сейчас точно не работает — дай полный анализ почему/как/что». Потом: войти в его кабинет и посмотреть вживую; доделать ТЗ под реализацию; сохранить пароль.

## Как решал
- vexp дневной лимит (20/20) исчёрпан → backend/frontend читал точечно `ls/find + Read` (как в памяти `project_vexp-not-indexed`).
- Прочитал арх-ТЗ `2026-06-25-edinyy-pomoshnik-arhitektura.md` и отколотое `chat-surface-convergence.md`, профильную `concierge-agent.md`, фронт-код FAB/ConciergeChat/nav-config/chat page.
- Живая приёмка прода через Playwright (qa-tester, тестовый аккаунт owner): FAB, вкладки, `/chat`. Скриншоты в `plans/analysis/2026-06-27-master-chat-surface/`.
- Написал анализ `plans/analysis/2026-06-27-edinyy-master-chat-surface-state.md`, дополнил ТЗ `chat-surface-convergence` (развилки + разрывы Р1–Р3, FAB → сразу большое окно).
- Коммит `91ee6c65` на ветке `feature/probe-clarify-dialog`, push.

## Что вышло (verified)
- Корень «не работает»: **два движка за двумя входами**. FAB = поповер concierge (умеет действия, но без истории/списка диалогов). Меню «Спросить» → `/chat` = ChatV2Client (это и есть «дом» с историей, но только Q&A, без действий). Бэкенд «единого мозга» сделан, **фронт-консолидация отколота и не начата**.
- 3 разрыва сверх ТЗ: Р1 у владельца нет пункта меню к чату (`/chat` стоит `roles:["manager"]`); Р2 все диалоги в списке называются «Новый диалог»; Р3 «Память» обещает чат, но это сетка ссылок.
- Решение владельца по FAB: открывать **сразу большое окно**, маленький поповер демонтировать.

## Чему научился
- **«Отколол под визуальную приёмку → забыли».** Фронт-консолидацию вынесли в отдельное ТЗ, потому что у агента-реализатора нет локального запуска UI и нужна приёмка глазами — и она зависла. Бэк-часть (тестируется headless) закрыли, фронт остался `[ ]`. Урок: отколотая «под глаза» фаза легко выпадает из горячего пути — её надо явно ставить в очередь, а не просто откалывать.
- **Пароль владельца — в gitignored `.qa-cabinet.local.json` (блок `owner`), НЕ в second-brain** (он в git = утечка в историю). В память — только указатель без пароля (`reference_qa-cabinet-accounts`).
- nav-config: пункт «Спросить» скрыт от лидерских ролей (`roles:["manager"]`) — владелец реально не видит вход в чат из меню; проверять видимость не по коду «есть пункт», а по роли.
