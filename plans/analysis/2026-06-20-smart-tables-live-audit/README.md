# Умные таблицы — живой аудит (2026-06-20)

## TL;DR (вердикт)

**Агенты умных таблиц работают и качество у них хорошее. Но на проде таблицы фактически мертвы по двум причинам и наполовину бессмысленны по третьей:**

1. 🔴 **Не видно** — в боковом меню НЕТ пункта «Таблицы» (удалён при сжатии меню 30→9); попасть можно только по прямому URL или через «Спросить Кору».
2. 🔴 **Нельзя открыть** — деталка `/tables/[id]` на проде **крашится** (React #185, бесконечный ре-рендер). Фикс есть в коде (коммит `26219233`, 2026-06-08), но **прод 12 дней работает на старом билде** — не выкачен.
3. 🟠 **Наполовину пустые по смыслу** — из 10 системных шаблонов авто-наполняются только **4** (`clients_deals`, `team`, `vendors`, `regulations`). Остальные **6** (`ideas`, `risks`, `promises`, `hypotheses`, `content_plan`, `okr`) создаются пустыми и **не наполняются ничем**. А по факту даже у 4 «связанных» все строки в проде — это остаток ручного импорта (`entityId: null`), граф→таблица авто-синк фактически не сработал ни разу.

**Что хорошо:** text-to-schema и Document-to-Table генерят качественные схемы (entitySync, типы, колонки — верно в ~95–100%). **A/B показал: переписанные промпты (12b) лучше живых** — их надо выкатить. **Что плохо помимо 1–3:** латентность агента **41–47 секунд** на один вызов (3 пасса Pro подряд) — тяжёлый UX.

**Приоритет действий:** P0 редеплой прод → P0 вернуть пункт меню → P1 порезать латентность → P1 выкатить промпты 12b → P2 мост граф→6 «мягких» таблиц с гейтом уверенности.

## Часть 1. Где умные таблицы и почему «пропали»

### Бэкенд и фронт реализованы целиком (фазы 0–5)
Модуль `backend/src/modules/tables/`: CRUD таблиц/колонок/строк/видов, импорт, семантический фильтр, enrich из встреч. Фронт: `/tables` (список) + `/tables/[id]` (грид Glide). См. [smart-tables.md](../../../second-brain/01_projects/smart-tables.md).

### 🔴 Находка 1 — нет входа в меню
В [nav-config.ts](../../../frontend/src/ui/components/app-shell/nav-config.ts) (источник правды о меню) **ни в одной секции нет пункта `/tables`**. Секции: Ритмы · Работа (Встречи·Задачи·Память·База знаний·Команда) · Личное · Система. Иконка `Table2` **импортирована, но не используется** ([nav-config.ts:32](../../../frontend/src/ui/components/app-shell/nav-config.ts#L32)) — осиротевший импорт = прямой след того, что пункт «Таблицы» был удалён (вероятно при сжатии меню 30→9 из аудита кабинета 2026-06-12). Подтверждено вживую: в сайдбаре прод-кабинета таблиц нет (скриншот `02-tables-list-no-nav.png`).

Хлебные крошки про таблицы знают (`tables → Таблицы` в [breadcrumb-config.ts](../../../frontend/src/ui/components/breadcrumbs/breadcrumb-config.ts)), но это работает только когда ты УЖЕ на странице таблицы.

**Вход сейчас:** только прямой URL `/tables` или кнопка «Спросить Кору» (CustomEvent `concierge:open`).

### 🔴 Находка 2 — деталка крашится на проде (фикс не выкачен)
Открытие `/tables/<id>` → экран «Не удалось загрузить страницу» (error boundary), грид не рендерится. Консоль:
```
Error: Minified React error #185 (Maximum update depth exceeded — бесконечный ре-рендер)
```
Это ровно баг из находки 2026-06-08, который **уже исправлен** коммитом `26219233` (`useShallow` на Zustand-селекторах + порядок регистрации `PendingPatchesController`). Но React #185 **всё ещё на проде 2026-06-20** → прод собран ДО `26219233`. Скриншот `01-detail-crash.png`.

**Следствие:** прод стоит на билде, где НЕТ всей работы по таблицам после `26219233` — в т.ч. пост-пассов качества **R1–R4** (`e84d8ace`), ASR-нот (`c9339992`) и интеграции таблиц в chat-v2 (`5e3498f9`). Это объясняет, почему ниже воспроизводится F3.

**Действие №1 (P0): редеплой прод.** Эффект: openable-таблицы 0% → 100% + подтянутся R1–R4.

## Часть 3. Промпты и A/B

### 🟠 Находка 4 — переписанные промпты (12b) НЕ выкачены
Промпты таблиц переписаны (батч [12b-smart-tables.md](../2026-06-09-prompt-rewrites/12b-smart-tables.md), 2026-06-09), но в код **не попали**: живой [table-infer-schema.prompt.ts](../../../backend/src/modules/ai/services/prompts/table-infer-schema.prompt.ts) до сих пор содержит старую версию. Git подтверждает: последний коммит промптов таблиц — `c9339992` (ASR-нота), коммита с 12b нет.

### A/B: новый 12b > старый живой (DRAFT-пасс, deepseek-v4-pro, 8×2)
Прогон `backend/scripts/eval/ab-table-infer-schema.ts` (изолирует pass-1 DRAFT, та же модель):

| Метрика (из 8) | OLD (живой) | NEW (12b) |
|---|---|---|
| Распарсилось | 5/8 | **7/8** |
| entitySync верно | 6/8 | **7/8** |
| Ровно 1 isPrimary | 5/8 | **7/8** |
| Допущение в `description` на коротких | 0/3 | **3/3** |
| Среднее время | 18.5с | **12.8с** |
| Недопустимые типы | 0 | 0 |

**Главное:** старый промпт на коротких/неоднозначных запросах («клиенты», «регламенты», «идеи») на одиночном DRAFT-пассе **вернул пустоту** — это и есть корень F1 (DRAFT — единственная точка жёсткого отказа; на проде его спасает 2-й пасс ARCHITECT и/или R1-retry, но R1 не выкачен). Новый 12b устойчивее, быстрее (короче вывод) и заполняет допущение для коротких запросов. NEW не строго доминирует (провалил 1 кейс «протоколы встреч», который OLD прошёл), но в сумме лучше. **Рекомендация: выкатить 12b** (риск низкий — контракт не меняется, инварианты нормализуются сервисом).

### Качество живых агентов (прод)
Text-to-schema на проде даёт хорошие схемы: «оборудование» (11 колонок, selectSingle 12 опций, currency/2×date/person/longtext), «клиенты»→entitySync org, «бюджет по кварталам»→currency×4 + formula. entitySync и типы верны.

### 🟠 Находка 5 — латентность 41–47с
Каждый вызов агента — **41–47 секунд** (3 пасса Pro подряд, ~15с каждый). Это на грани таймаута `LLM_ROUTER_DISPATCH_TIMEOUT_MS=30с` на пасс и тяжёлый UX: пользователь, попросивший Кору «заведи таблицу клиентов», ждёт почти минуту.

### 🟠 Находка 6 — F3 (dedup-дубли) воспроизведён вживую
Живой `import/analyze` CSV-«клиентов» → агент назвал схему **«Сделки»**, `entitySync: null`, **`mergeCandidates: []`** — кандидата на слияние с системной «Клиенты и сделки» не нашёл, хотя колонки совпадают (Стадия/Сумма/Контакт/Телефон). На проде R3 (Jaccard-dedup) не выкачен → импорт создал бы **дубль-таблицу** вместо слияния. Воспроизводит F3 + F5 (агент переименовывает) из аудита 2026-06-08. **Чинится редеплоем (R3 уже в коде).**

## Дизайн: мост граф знаний → 6 «мягких» таблиц + гейт уверенности (P2)

Направление выбрано владельцем 2026-06-20: **наполнять все 10 шаблонов из уже извлечённого графа и встреч, но через порог уверенности — высокая пишется сразу, спорное тихо в фон, без вала «Подтверждений».** (Согласуется с курсом «без human-in-loop, гейт только как рубильник» — [[feedback_no_human_in_loop_for_clone_learning]].)

### Принцип
Переиспользовать существующую инфраструктуру Фазы 3 (`tables.enrich` очередь + `TableCellProvenance` + порог `table.agent.confirmation_threshold`), но добавить **создание новых строк** в 6 «мягких» таблиц из графовых сущностей, а не только патч ячеек 4 sync-таблиц.

### Маппинг источников (что во что течёт)
| Таблица | Источник в графе сегодня | Готовность |
|---|---|---|
| Идеи и бэклог | IdeaBlock (idea/insight), insight-extract | 🟢 источник есть |
| Цели и метрики | Goal (`/goals`, Entity goal) | 🟢 источник есть |
| Гипотезы и эксперименты | Experiment (`/experiments`) | 🟢 источник есть |
| Обещания и обязательства | action-items / Issue из встреч (meeting-extract-actions), «Кто держит слово» | 🟡 источник есть, нужен маппинг в строку |
| Реестр рисков | риск-сигналы (Decision/Insight категории «риск»; операционные алерты) | 🟡 нужен извлекатель/категория |
| Контент-план | нет графового источника (контент-задачи?) | 🔴 оставить ручным/из задач |

### Механика (поверх существующего)
1. **Новый «row-extractor» режим** в enrich-воркере: для каждой 6 «мягкой» таблицы — взять связанные графовые объекты события (встречи/обновления графа) → LLM `table-extract-rows` уже умеет извлекать факты по схеме; добавить ветку «создать строку» (не только «патчить ячейку»), с дедупом по primary-колонке (Jaccard/embedding, как R3).
2. **Гейт уверенности (без очереди подтверждений):**
   - `confidence ≥ confirmation_threshold (0.85)` → строка создаётся сразу, помечается provenance (источник + ссылка на тайминг).
   - `confidence < порога` → НЕ в «Подтверждения», а **в фоновый низкоприоритетный пул** (тихо), который или дозревает при повторном подтверждении из другого источника, или истекает по TTL. Никаких пушей владельцу.
3. **Триггеры:** `meeting.ai_ready` (уже есть) + `entity.created/updated` для Goal/Experiment/Idea (расширить шину, как в Фазе 2).
4. **entitySync для 6 «мягких»:** не через `Entity`-типы (их нет для идей/рисков), а через **новый канал «graph-object→row»** — отдельный конфиг `graphSync` на шаблоне (тип объекта + маппинг полей), параллельный `entitySync`.

### Анти-риски
- **Шум/спам** — закрыт гейтом (спорное не показывается). Бюджет токенов — `table.agent.max_daily_tokens` уже есть.
- **Дубли строк** — дедуп по primary (переиспользовать R3-логику Jaccard).
- **Самоотравление графа** — строки из графа read-only-помечать (provenance), ручные правки не перетирать.
- Это **анализ-направление, не ТЗ.** ТЗ писать отдельно по команде владельца.

## Что НЕ делали и почему
- **Event-to-Cells живой прогон** не запускали (нужна встреча с транскриптом + commit с последующей чисткой). Граница подтверждена по коду: enrich трогает только 4 sync-таблицы и не создаёт строк.
- **import/commit** не вызывали — чтобы не сорить в прод-БД; гоняли только превью `import/analyze` и `infer-schema`.
- **Полный eval text-to-schema** (102 фикстуры) не гоняли — это отдельный gate через `scripts/eval/run-text-to-schema-eval.ts` (требует прод-окружения).
