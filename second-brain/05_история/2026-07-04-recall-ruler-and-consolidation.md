# Recall: честная линейка, консолидация базы, фикс ThemeBranch

## Что было поставлено
Владелец подтвердил последовательность и попросил пройти её самому и вернуться с улучшенным результатом «ближе к 99»: замер-базлайн → консолидация базы (owner «да,да,да» + snapshot) → замер-после → дальше по цифрам.

## Как решал
1. **Снапшот** dev-БД (`pg_dump z_main`, 857МБ) — точка отката перед необратимой консолидацией.
2. **Базлайн 111** своим быстрым harness'ом (`_measure-recall-111.ts`, одиночный LLM-судья) → **28.8% CORRECT**. Число дико разошлось с официальными 77-79%.
3. **Проверка подозрения:** прочитал сами ответы, помеченные WRONG (q002/q019/q089…) — они ОТЛИЧНЫЕ. Значит судья сломан, а не recall. Быстрый одиночный судья дефолтит в WRONG.
4. **Переход на официальную детерминированную линейку** (`scripts/eval/verdict/classify-outcome` — `isRefusal` + `mustMentionCoverage`, gold-50 с обязательными фактами). Написал `_measure-gold.ts`. → **CORRECT 69-73% / +partial 84-87%, 0 галлюцинаций** (в русле 77-79%).
5. **Консолидация** «Стрелы»: `client→customer` (no-op) → `entity-consolidate-same-name` (**0 мёржей** — LLM-арбитр отклонил все 6 кросс-типовых пар как легитимно разные: retention goal/metric и т.п.) → `reconcile-merged-refs` (**25 ссылок** к канону) → `reembed-blocks-no-header` (**299 блоков** header-less + HNSW reindex — выровнял рассогласование блок↔запрос на ветке).
6. **Баг `ThemeBranch = text`** (SQL 42883), валившийся в каждом прогоне: `selectTopThemes` сравнивал enum `"branch"` с `::text[]` без каста (`chat-v2-retrieval.service.ts:726`); из-за try/catch fail-open → тема-контекст терялся для broad. Фикс: `::text` каст (как в строке 157), коммит `96e994e9`.

## Что вышло
- **Честная линейка восстановлена** — главное. Были слепы (сломанный судья), стали видеть: recall ~73%/85%, 0 галлюцинаций на пустом.
- **Число не прыгнуло.** ThemeBranch-фикс и reembed корректны, но их эффект тонет в **шуме синтеза ±3 вопроса** (LLM пере-генерит ответы каждый прогон). Консолидация сущностей дала 0 (арбитр прав).
- **Часть «провалов» — артефакт строгого mustMention** (ждёт «retention», ответ говорит «удержание» → ложный cov=0.5). Истинный recall ВЫШЕ 73%.
- **Доминирующая реальная течь — неполнота синтеза** (Шаг 4): ответ находит область, но не перечисляет все обязательные факты.

## Чему научился
1. **Чини измерение ПЕРВЫМ (Шаг 0 мастер-плана) — буквально.** Я построил быстрый судья и час гонял на нём мусор (28.8%). Спасло чтение самих ответов. Одиночный LLM-судья без калибровки/majority — ненадёжен; детерминированный (сигнатуры/mustMention) — да.
2. **±3 шум синтеза на 45 вопросах** → мелкий фикс (1-2 вопроса) в нём невидим. Для доказательства мелкого улучшения нужен либо крупный рычаг, либо усреднение нескольких прогонов.
3. **Даже детерминированная линейка врёт на синонимах** (retention/удержание, англ/рус) — mustMention-токены надо расширять синонимами, иначе занижает.
4. **Снапшот перед необратимым — дёшево и обязательно** (`pg_dump` 857МБ за секунды).
5. **«Ближе к 99» — не один заход.** Плато ~77-79 подтверждено честной линейкой; остаток — синтез-полнота + точечные дыры данных (фронтенд/ЛПР реально нет в «Стреле») + строгость замера. Один сеанс двигает фундамент (честная линейка, чище база, 2 бага), не цифру.
