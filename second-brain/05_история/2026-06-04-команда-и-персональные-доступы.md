# Команда + персональные доступы сотрудников (реализация Фаз 0–5)

## Что было поставлено

ТЗ [plans/tz/2026-06-03-team-section-and-employee-access.md](../../plans/tz/2026-06-03-team-section-and-employee-access.md), Фазы 0–5. Свести управление людьми компании в один раздел «Команда» и добавить персональные доступы поверх ролей/тарифа:

- **Фаза 0** — приглашение по `personId` (резолв Person, дедуп pending, сохранение в `OrgInvitation`); фикс 400 на турах (единый enum `welcome|project|meeting|overview|demo`); мастер «Знакомства» снова переоткрываем (убран редирект «есть отделы → /dashboard»).
- **Фаза 1** — раздел «Команда» верхним пунктом меню (`/structure`, группа «Каждый день»); вкладка «Сотрудники» открывается первой; дубль убран из «Справочника».
- **Фаза 2** — `GET /api/v1/orgs/:id/team-roster` (объединённый ростер Person ⊕ Membership без карточки) + `POST /persons` с `linkUserId`.
- **Фаза 3** — управление участниками перенесено из Настроек в «Команду»; диалоги в `frontend/src/ui/components/team/`; `/settings/organization` очищена до «Информации».
- **Фаза 4** — карточка сотрудника `/structure/persons/[id]` (вкладки «Профиль» / «Доступы»).
- **Фаза 5** — модель `EmployeeCapabilityOverride` + `CapabilitiesService` + эндпоинты capabilities/effective-access; override как дельта `allow`/`deny`.

## Как решал

- Оркестрация суб-агентами по фазам в отдельном worktree (`feature/team-section-and-employee-access`, каталог `C:/work/z-team`), коммиты по фазам.
- Ростер сделан **self-contained в `OrgsService.listTeamRoster`** — без cross-module DI (persons/users), чтобы не вводить Nest-цикл зависимостей модулей.
- Персональный доступ реализован как **дельта override поверх дефолта роли/тарифа** (а не замена), так что тариф не регрессит: эффективный доступ = дефолт ± override. `useMemoryAccess` на фронте учитывает override. Капабилити-подмножество: `memory:regulations`/`memory:entities`/`feature:graph`/`panel:operations`.
- Модель `EmployeeCapabilityOverride` с unique `[tenantId, grantedToUserId, capability]` + soft-revoke (`revokedAt`/`revokedBy`) как audit.

## Чему научился

1. **Nest module-циклы всплывают на bootstrap, а не на `tsc`.** Если сервису нужны данные из 2–3 чужих модулей, безопаснее собрать запрос self-contained (через PrismaService напрямую), чем тянуть cross-module DI и потом ловить `Nest cannot resolve circular dependency` уже в рантайме.
2. **Override-доступ строить как дельту, а не как замену значения.** Дельта `allow/deny` поверх дефолта роли/тарифа не регрессит тариф и не требует ретроактивного пересчёта — снять override = вернуть дефолт.
3. **Цветовые токены сверять с `tailwind.config.ts`.** В статус-чипах — `text-success` (а не выдуманный `text-status-success`); парные токены `bg-{color}` + `text-{color}-fg`.
4. **`apiClient` имеет метод `put`** — для PUT-эндпоинта capabilities не нужно изобретать обёртку, используется штатный `apiClient.put`.
