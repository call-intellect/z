# Z-Admin — инструкция для оператора платформы

Этот документ — для нового сотрудника с ролью `super_admin`. Здесь описано, что такое продукт Z (Кора), как устроена панель администратора, что означает каждый раздел и какие действия доступны.

---

## Что такое Z (Кора)

Z — платформа памяти компании. Она автоматически собирает граф знаний из встреч, чатов и решений: записывает, кто что сказал, какие решения были приняты, какие задачи поставлены. AI-чат компании отвечает на любой вопрос по базе знаний. «Цифровые двойники» сотрудников (клоны ролей) сохраняют знания людей даже после их ухода.

Первый источник данных в продукте — видео- и аудиовстречи. Платформа записывает их через LiveKit (движок видеосвязи), транскрибирует, разделяет по участникам и генерирует AI-отчёт по типу встречи.

**Ваша роль** — `super_admin`. Это глобальная роль: вы видите данные всех организаций (тенантов) на платформе и управляете инфраструктурой. В отличие от обычного `admin` организации, у вас доступ ко всем клиентам.

> Важно: назначение `super_admin` делается только прямым `UPDATE` в базе данных. UI для назначения не предусмотрен намеренно — это снижает риск несанкционированной эскалации.

---

## Вход в панель администратора

1. Зайдите на сайт платформы и войдите под учётной записью с ролью `super_admin`.
2. В адресной строке перейдите на `/admin`.
3. Слева появится боковое меню с 8 разделами. Кликните на раздел — он раскроется. Текущий активный раздел подсвечен акцентным цветом.
4. Быстрый переход между разделами — **Cmd+K** (Mac) / **Ctrl+K** (Windows): откроется палитра поиска, начните вводить название раздела.

## Раздел 1. Пульс — общий мониторинг

### Дашборд `/admin`

Главная страница. Показывает состояние платформы за выбранный период (сутки / неделя / месяц).

**Что видите:**

- **4 плитки KPI** (ключевых показателя):
  - Расход на AI (в долларах) за период + количество вызовов
  - Доля ошибок (если выше 5% — плитка становится жёлтой, это сигнал тревоги)
  - Количество организаций и пользователей / активные за 7 дней
- **3 графика за 30 дней**: расход, количество вызовов, доля ошибок
- **Расход по AI-провайдерам** — какой провайдер сколько стоит
- **Топ-10 функций по расходу** — какие именно AI-задачи самые дорогие (с кнопкой экспорта в CSV)
- **Топ организаций по расходу** (с кнопкой экспорта в CSV)

**Что делать:** ежедневно открывать и смотреть на долю ошибок и расход. Если что-то выросло — идти в «Инциденты» или «Функции LLM» за деталями.

---

### Здоровье системы `/admin/health`

Техническое состояние всей инфраструктуры. Шесть вкладок:

| Вкладка | Что проверяет |
|---|---|
| **Очереди** | Состояние фоновых задач (BullMQ — движок очередей): сколько задач ждут, выполняются, упало |
| **БД** | Соединение с базой данных PostgreSQL, задержки, пул соединений |
| **Эмбеддинги** | Служба векторного поиска (pgvector — расширение базы данных для AI) |
| **Воркеры** | Процессы-обработчики фоновых задач |
| **S3** | Хранилище файлов (записи встреч, аудиодорожки) |
| **LiveKit** | Медиасервер для видеоконференций |

Зелёный — всё в порядке. Красный/жёлтый — проблема, нужно разбираться.

---

### Инциденты `/admin/incidents`

Страница оперативного реагирования. Три вкладки:

- **«Сейчас горит»** — список очередей, в которых есть упавшие задачи. Кликните по строке, чтобы увидеть текст ошибки последних 3 упавших задач. Здесь же можно перезапустить упавшие задачи.
- **«Очереди»** — полная таблица всех очередей со счётчиками: ожидают / выполняются / упали / отложены / завершены.
- **«История 7д»** — история инцидентов за неделю.

---

### Журнал super_admin `/admin/audit`

Лог всех действий администраторов платформы. Каждая запись содержит:
- **Когда** — дата и время
- **Кто** — email администратора
- **Маршрут** — какой API-адрес был вызван
- **Метод** — GET, POST, PUT, DELETE
- **tenantId** — для какой организации
- **Причина** — если администратор указал (обязательно для высокорисковых действий)

Фильтры: по администратору, по маршруту, по диапазону дат. Есть кнопка «Экспорт в CSV».

**Зачем:** если что-то изменилось и неясно кто — смотрим здесь.

## Раздел 2. Аналитика — данные только для чтения

Все страницы этого раздела только для просмотра. Переключатель периода — в правом верхнем углу.

| Подраздел | Что показывает |
|---|---|
| **Org и пользователи** | Список всех организаций: тариф, владелец, расход за период |
| **Функции LLM** | Разбивка расходов по типу AI-задачи |
| **Юнит-экономика** | Стоимость одной встречи, одного пользователя, маржинальность |
| **Встречи** | Количество встреч по типам, средняя длительность, доля успешных AI-отчётов |
| **Knowledge-Core** | Статистика графа знаний: идей-блоков, связей, кластеров тем |
| **Concierge и AI-чат** | Количество обращений к AI-чату, топ вопросов |
| **Экономика моей Org** | То же, но только для вашей собственной организации |

## Раздел 3. AI и модели

Здесь настраивается работа всех AI-функций платформы.

> **Примечание (2026-05-28):** панель администратора значительно расширена и теперь включает ~90+ страниц, сгруппированных по разделам. Ниже описаны ключевые страницы AI-раздела. Полный перечень дополнительных страниц:
> - `/admin/helpfulness-overview` — карта Helpfulness по команде (агрегированный социальный профиль сотрудников + неотвеченные вопросы)
> - `/admin/feedback` — дашборд обратной связи с AI-кластеризацией по темам (детали: `/admin/feedback/[topicId]`)
> - `/admin/analytics/*` — 7 аналитических подразделов: concierge, economics, functions (+ `functions/[taskType]`), knowledge, meetings, orgs
> - `/admin/content/*` — 5 подразделов: copy, emails, global-channels, meeting-types, system-messages
> - `/admin/integrations/*` — bots, keys, livekit, webhooks
> - `/admin/platform/*` — crons, flags, limits, maintenance, security, workers

### Роутинг моделей `/admin/ai/routing`

Каждая AI-задача в Z называется `taskType` (тип задачи): транскрибация, разделение по спикерам, генерация отчёта, поиск по базе знаний и т.д.

На этой странице настраивается, какая AI-модель выполняет какую задачу. Можно посмотреть текущую конфигурацию и перейти в карточку конкретного типа задачи.

### Управление роутами LLM `/admin/llm-routes`

Детальная таблица маршрутизации: провайдер → модель → класс данных (публичные / конфиденциальные данные). Можно изменить приоритет провайдера или переключить задачу на другую модель.

### Каталог LLM `/admin/ai/catalog`

Справочник доступных AI-моделей: название, провайдер, стоимость за 1000 токенов (единица измерения текста для AI), поддерживаемые возможности. Используется как справочник при настройке роутинга.

### Промпты `/admin/ai/prompts`

**Одна из ключевых страниц для оперативной работы.**

Промпты — инструкции для AI, которые определяют, как она анализирует встречу и пишет отчёт. Хранятся в базе данных и редактируются без деплоя кода (без участия разработчиков).

**Что можно делать:**
- Просматривать все промпты по типу задачи
- Редактировать текст промпта
- Создавать новые промпты
- Просматривать историю изменений

Если промпт в базе повреждён или удалён — система автоматически использует резервный из кода. Это защита от ошибок.

### A/B-эксперименты `/admin/experiments`

Тестирование разных вариантов промптов. Можно запустить эксперимент, где часть встреч обрабатывается промптом А, а часть — промптом Б. После — сравнить результаты и выбрать лучший.

### Knowledge-Core настройки `/admin/ai/knowledge-core`

Параметры пайплайна (цепочки обработки) графа знаний: насколько агрессивно кластеризовать темы, пороги схожести идей, периодичность пересчёта связей.

### Эмбеддинги `/admin/ai/embeddings`

Эмбеддинги — числовые «отпечатки» текста, которые позволяют AI-поиску находить похожие идеи. Здесь можно инициировать пересчёт эмбеддингов для определённых данных.

### Смысловые блоки навыка `/admin/skill-trait-concepts`

Справочник концептов для системы клонов ролей: какие навыки и черты отслеживаются по всем сотрудникам.

### Доступы к клонам `/admin/clones`

Управление тем, кто из сотрудников организации может использовать ролевые клоны (AI-аналоги должностей). Здесь выдаются и отзываются права доступа.

### Preference dataset `/admin/ai/preference-dataset`

Датасет предпочтений — обучающие примеры «правильный ответ / неправильный ответ» для дообучения AI-моделей. Пополняется из оценок пользователей.

### Мониторинг signalType `/admin/ai/signal-type-monitor`

График распределения типов сигналов в графе знаний. Если распределение резко изменилось — это признак «дрейфа» (деградации) классификатора AI.

## Раздел 4. Тенанты — управление организациями

Тенант (Org) — это одна организация-клиент на платформе.

### Список Org `/admin/orgs`

Таблица всех организаций. Для каждой видно: название и ID, тариф, владелец (email), расход за период.

**Действия по каждой Org:**
- **Заморозить** — временно заблокировать доступ (например, при неоплате)
- **Удалить** — безвозвратное удаление, требует подтверждения
- Кликнуть по строке → карточка с полной историей и биллингом

Фильтры: поиск по названию, фильтр по тарифу, показать удалённые организации.

### Тарифы (планы) `/admin/orgs/plans`

Конфигурация тарифных планов: что входит в базовый, про и корпоративный тариф (лимиты участников, записей, AI-вызовов в месяц).

### Entitlements (переопределения) `/admin/orgs/entitlements`

Индивидуальные настройки лимитов для конкретной организации — без смены тарифа. Например, увеличить лимит хранения по запросу клиента.

## Раздел 5. Контент — тексты и настройки продукта

### Типы встреч `/admin/content/meeting-types`

Z поддерживает 9 типов встреч: планёрка, 1-on-1, стратегическая сессия, продажа, ретроспектива и т.д. Для каждого можно настроить:
- Название и описание (как отображается пользователю)
- Включён / выключен (переключателем)

AI-отчёт адаптируется под тип встречи. Шаблон отчёта — в разделе «Промпты».

### Email-шаблоны `/admin/content/emails`

Шаблоны писем: приглашение в организацию, уведомление о готовом отчёте, magic-link для входа и т.д. Можно редактировать тексты.

### Системные сообщения `/admin/content/system-messages`

Баннеры и уведомления внутри интерфейса платформы (для всех пользователей или конкретного тенанта). Например: «Плановые работы 15 июня с 02:00 до 04:00».

### Глобальные каналы `/admin/content/global-channels`

Настройка глобальных разговорных каналов (Telegram-бот и аналоги).

### Глоссарий и UI-строки `/admin/content/copy`

Справочник терминов продукта на русском языке. Если нужно изменить термин во всём продукте — здесь.

## Раздел 6. Каналы и интеграции

### Conversational боты `/admin/integrations/bots`

Настройка чат-ботов: какие команды поддерживают, как связаны с организациями.

### Telegram-бот `/admin/system/telegram-bot`

Управление глобальным Telegram-ботом платформы: статус подключения, токен бота, статистика обращений.

### Webhook subscriptions `/admin/integrations/webhooks`

Список всех подписок на события от организаций. Вебхук — HTTP-запрос, который Z отправляет на сервер клиента при наступлении события («встреча завершена», «отчёт готов»). Здесь можно просматривать и отзывать подписки.

### Integration keys `/admin/integrations/keys`

API-ключи для внешних систем, которые подключаются к Z по API. Создать новый ключ или отозвать существующий.

### LiveKit `/admin/integrations/livekit`

Настройки подключения к медиасерверу LiveKit: URL, статус соединения, активные комнаты.

## Раздел 7. Записи и медиа

### Все встречи `/admin/media/meetings`

Глобальный список всех встреч всех организаций. Фильтры: по статусу, типу встречи, владельцу. Кликните по строке → карточка с деталями, записями и AI-отчётом.

### Истекающие записи `/admin/media/expiring`

Список записей, срок хранения которых заканчивается в ближайшие дни.

### Сроки хранения `/admin/media/retention`

Настройка политик хранения: как долго по умолчанию хранятся записи для каждого тарифа. После истечения срока записи удаляются автоматически.

### S3 хранилище `/admin/media/storage`

Статус объектного хранилища: занятое место, количество файлов, статус соединения.

## Раздел 8. Платформа — техническое управление

### Кроны `/admin/platform/crons`

Список запланированных автоматических задач: название, расписание (например «каждую ночь в 03:00»), время последнего запуска, статус.

### Воркеры BullMQ `/admin/platform/workers`

Подробный инспектор очередей фоновых задач. Для каждой очереди:
- Счётчики: ожидают / выполняются / упали / отложены / завершены
- **Переключатель «пауза»** — временно остановить очередь
- Кнопка «Детали» → диалог с последними упавшими задачами:
  - **Retry failed** — перезапустить все упавшие задачи
  - **Remove** — удалить конкретную упавшую задачу

### Лимиты и квоты `/admin/platform/limits`

Системные ограничения: максимальное число участников в встрече, максимальный размер файла, количество запросов в минуту и т.д.

### Feature flags `/admin/platform/flags`

Флаги функций — переключатели для включения/выключения отдельных возможностей продукта без деплоя кода. Три вкладки:

- **Список** — все флаги с глобальным значением. Изменить переключателем, создать новый, удалить.
- **По Org** — флаги, переопределённые для конкретных организаций (только чтение, изменения — через «Entitlements»)
- **История переключений** — лог изменений

Когда использовать: срочно выключить проблемную функцию без техника или включить бета-функцию для всех.

### Безопасность `/admin/platform/security`

Настройки безопасности платформы: политика сессий, блокировки.

### Обратная связь `/admin/feedback`

Отзывы пользователей, сгруппированные по темам. AI кластеризует сообщения ночью. Можно переименовывать темы, объединять и архивировать.

### Бэкапы и обслуживание `/admin/platform/maintenance`

Управление резервными копиями базы данных и режимом технического обслуживания (когда нужно временно отключить платформу для плановых работ).

## Трекер и спринты (пользовательская зона)

> Эти страницы — в пользовательской зоне продукта, а не в `/admin`. Доступны всем авторизованным пользователям организации, администратор видит то же что и обычный пользователь.

### Проекты `/projects`

Список всех проектов организации. Каждый проект — рабочее пространство для команды или направления.

Внутри каждого проекта доступны вкладки:

| Вкладка | Что это |
|---|---|
| **Список** | Плоский список задач с фильтрами и статусами |
| **Доска** | Канбан-доска: колонки по статусам задач |
| **Календарь** | Задачи по датам на месячной сетке |
| **Гант** | Временная шкала зависимостей задач |
| **Циклы** | Итерации проекта (аналог спринтов внутри проекта) |
| **Документы** | Вики-документация проекта |
| **Intake** | Входящие заявки и идеи для оценки |
| **Нагрузка** | Загрузка участников по времени |
| **Настройки** | Участники, статусы, приоритеты, интеграции проекта |

### Все проекты (admin-вид) `/admin/projects`

Страница только для `super_admin` и владельца Org: показывает **все проекты**, включая архивные и удалённые.

> Эта страница не отображается в боковом меню Z-Admin — перейти можно напрямую по адресу `/admin/projects`.

Когда нужно: если пользователь сообщил «куда делся проект» — смотреть здесь.

### Мои задачи `/tasks`

Личная страница: все задачи, назначенные на пользователя, из всех проектов. Группировка: Просрочено / Сегодня / На неделе / Позже / Без срока.

### Спринты `/sprints`

Недельные (или любой длины) рабочие циклы команды. Спринт объединяет задачи из разных проектов вокруг одной цели.

**Список спринтов** — двухколоночный макет:
- Слева: карточки спринтов с прогресс-баром, датами, областью действия
- Справа: предпросмотр выбранного спринта

Фильтры:
- **Статус:** Активные / Завершённые / Предстоящие / Все
- **Область действия (scope):** Компания / Отдел / Клиент / Поставщик / Сотрудник / Проект
- **Поиск** по названию

Список обновляется в реальном времени без перезагрузки страницы.

**Мастер создания спринта** (кнопка «+ Создать») — расширенный двухшаговый wizard:
1. **Шаг 1:** radio с 6 вариантами области действия (scope) + универсальный комбобокс с поиском и inline-созданием сущностей (Vendor/Card/Department/Person). Для scope «Сотрудник» — двухступенчатый выбор Role → Person.
2. **Шаг 2:** название, длительность, дата начала.

Submit атомарно создаёт Project + Cycle + Board + IssueStates через `POST /api/v1/sprints/quick-create`.

### Дашборд спринта `/sprints/[id]`

Страница конкретного спринта. Автообновление каждые 30 секунд.

**Что видно:**
- Даты и прогресс выполнения
- Список задач с распределением по статусам
- **AI-подсказки** — автоматические выводы системы по ходу спринта (что идёт хорошо, что блокирует, что рискует не успеть)
- Участники с аватарками
- Ссылки на связанные встречи

**Действия:**
- **Начать встречу** — запустить видеовстречу из спринта (тип «Обсуждение спринта»)
- **Завершить спринт** — закрыть цикл и запустить генерацию итогового отчёта

### Итоги спринта `/sprints/[id]/review`

AI-сгенерированный отчёт по завершённому спринту. Пока генерируется — страница автоматически обновляется каждые 10 секунд.

Три состояния: **Готовится** / **Готово** / **Ошибка** (есть кнопка «Пересоздать»).

### Связь спринтов с AI

Спринты интегрированы с AI-движком платформы:
- Спринт может быть связан с встречами → запись → транскрибация → AI извлекает задачи и прогресс автоматически
- AI-подсказки генерируются на основе встреч и состояния задач в спринте
- При завершении спринта AI создаёт итоговый отчёт

## Типичные задачи и где их делать

| Задача | Куда идти |
|---|---|
| Проверить, всё ли работает утром | Дашборд → Здоровье системы |
| Клиент пишет «у нас не работает» | Инциденты → найти упавшие задачи |
| Зарегистрировать нового клиента | Список Org → настроить тариф |
| Заморозить неоплативший аккаунт | Список Org → кнопка «Заморозить» |
| Улучшить качество AI-отчёта | Промпты → найти тип встречи → редактировать |
| Включить новую функцию для всех | Feature flags → найти флаг → переключить |
| Узнать, кто что менял в админке | Журнал super_admin |
| Перезапустить упавшие задачи | Воркеры BullMQ → Retry failed |
| Узнать расход за месяц по клиенту | Список Org → кликнуть по клиенту |
| Изменить тип встречи | Контент → Типы встреч → редактировать |
| Найти удалённый/архивный проект | `/admin/projects` напрямую в адресной строке |

## Что нельзя менять без согласования

- **Удаление организаций** — необратимо, требует согласования с руководством
- **Роутинг AI-моделей** — изменение влияет на качество всех отчётов, согласовывать с разработкой
- **Лимиты и квоты** — изменение может повлиять на биллинг клиентов
- **Промпты** — перед публикацией изменений протестировать на нескольких встречах
