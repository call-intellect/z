## Что НЕ реализовано = scope этого ТЗ

**Фронт показывает блок «Контекст» (`payload.context`) для `probe.question`.**
Для probe-вопроса человеческая формулировка уже выводится отдельно (внутри `ProbeAnswerInput`),
поэтому блок «Контекст» с сырым `message` — это дублирование и протечка одновременно.

### Корень (подтверждён по коду 2026-06-11)

- [`NotificationsClient.tsx:339-344`](../../frontend/app/(authenticated)/me/notifications/NotificationsClient.tsx#L339)
  — блок «Контекст» рендерит `payload.context` **всегда**, без проверки на `isProbeQuestion`
  (рядом, стр. 333, аналогичный блок «Вопрос» уже завёрнут в `!isProbeQuestion` — для context это забыли).
- `payload.context` приходит из [`probe-dispatcher.worker.ts:164`](../../backend/src/modules/probe/probe-dispatcher.worker.ts#L164)
  = `payload.message` **дословно**, минуя и LLM `probe-formulate`, и `humanizeProbeFallback`.
- **Это класс, а не кейс:** `payload.message` кладут ВСЕ эмиттеры probe — `consistency-checker`,
  `temporal-probe`, `strategic-alignment`, `goal-alignment-low`, `process-template-probe`,
  `goals-checkpoint-probe`, `skill-trait-concept-normalizer`. Один фикс на отображении закрывает
  утечку сырья от всех, а не требует чистить `message` у каждого эмиттера по отдельности.

### Почему чинить на фронте, а не «вырезать message из payload»

`payload.message` нужен бэку: это **вход** для `probe-formulate` (из него LLM лепит человеческий вопрос)
и **fallback**, когда LLM недоступен. Удалять его из payload нельзя — прятать сырьё надо на отображении.
Бэк-тексты (Ф2) остаются страховкой для не-probe каналов, где `message`/`context` показывается осмысленно.

## Фаза 1 (единственная) — фронт: для `probe.question` не показывать «контекстные» блоки `[x]`

- [ ] [`NotificationsClient.tsx`](../../frontend/app/(authenticated)/me/notifications/NotificationsClient.tsx) —
      блоки `payload.context` (стр. 339-344), `payload.summary` (345-352), `payload.title` (353-358)
      обернуть в `{!isProbeQuestion && …}` (по образцу блока «Вопрос», стр. 333). `isProbeQuestion`
      уже в скоупе компонента. Блок `payload.body` (359) и все не-probe ветки — **не трогать**.
- [ ] Прочие типы уведомлений (`proactive.notification`, `operations.daily_digest`, модерация) —
      контекст **сохраняют** (там он содержательный): гард строго по `isProbeQuestion`, не глобальный.

**Приёмка:**
- В проде `probe.question` показывает ровно один человеческий вопрос + поле ответа; блока «Контекст»
  с сырым `message`/cuid/латиницей-именами классов **нет**.
- Дайджест / модерация / proactive-уведомления — контекст на месте (регресса нет).
- `bun run typecheck` · `bun run lint` · `bun run build` · `bun run test:unit` (frontend) — зелёные.
