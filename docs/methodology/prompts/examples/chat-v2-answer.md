# Эталон промпта: единый ответчик AI-чата компании (`chat-v2`)

> «Умный ответчик» AI-чата: гибридный поиск по графу знаний → синтез ответа с цитатами `[BLOCK:<id>]`.
> **Где живёт:** `backend/src/modules/knowledge-core/services/chat-v2.service.ts` (`BASE_SYSTEM_PROMPT`), используется `ChatV2Service.ask`, `taskType='chat-v2'`. Обслуживает и старый `chat`-модуль (встреча/архив через V2), и боевой путь AI-чата компании (через `SynthesisService`).
> **Контракт реализации:** `plans/tz/2026-06-15-chat-v2-unified-answer-prompt.md` (Приложение A).

---

## Зачем (что заменил)

Раньше поведение задавалось **четырьмя промптами на одном движке**: `BASE_SYSTEM_PROMPT` (старый chat-модуль) + три режима `factual` / `synthetic` / `clone_style` (файлы `chat-v2/prompts/*.prompt.ts`). На боевом пути `SynthesisService` всегда подменял `BASE` одним из режимов как `systemPromptOverride`. Это давало пять болезней:

1. **🔴 Десинхрон темпоральных пометок.** Билдер контекста всегда вставлял секции «цепочка рассуждения» и «противоречащий факт», но инструкцию, как их читать, содержал только `BASE`. Режимы «факт»/«синтез» её не имели → на боевом пути модель **проглатывала конфликт** (выдавала один факт как истину, хотя в памяти два спорящих) — прямо против обещания «честная память показывает противоречия».
2. Ни один из 4 не по методологии (нет якорей смысла, few-shot, self-check).
3. **Кэш ломался:** `summary`/`history` лежали в SYSTEM (а не в конце USER), плюс смена режима меняла системный префикс → cache-miss на каждом переключении факт↔синтез.
4. Тройной дубль правил формата (три почти одинаковых «## Формат»).
5. **Машинный (английский) контекст:** модель читала `(churn_risk)`, `[REASONING CHAIN FOR BLOCK]`, `[CONTRADICTING BLOCK]` — английские коды и теги.

Теперь — **один промпт на все ответы из графа** (`mode` больше не выбирает текст промпта); темпоральные правила живут внутри единого промпта и не теряются; `summary`/`history` переехали в конец USER; контекст собирается на человеческом русском (русские ярлыки типов + русские теги). `clone_style` как «режим письма» удалён; отдельные движки (`ClonesService.askPerson`, brand-voice) остались, но вызываются не выбором режима, а явно.

## Эталонный промпт (канон)

SYSTEM, часть 1 — копировать байт-в-байт из `chat-v2.service.ts` (`BASE_SYSTEM_PROMPT`). Ключевые блоки: **## Роль** (Кора, память одной конкретной компании) → **## Кому ты отвечаешь и что будет с ответом** (сотрудник, ответ финальный, экономь время) → **## Границы — только дела компании** (посторонние темы / код → вежливый отказ) → **## Как ты отвечаешь** (6 правил: только из контекста · глубина по вопросу без жёсткого лимита · `[BLOCK:<id>]` рядом с фактом · честно про пустоту · честно про надёжность · конфликт не заглаживай) → **## Особые пометки в контексте** (как читать цепочку рассуждения / противоречащий факт / данные из таблиц — темпоральные правила теперь ЗДЕСЬ, не теряются) → **## Примеры (плохо → хорошо)** (4 few-shot: спор фактов · пустота · тех-мусор · «почему») → **## Самопроверка перед ответом** (5 пунктов) → **## Запреты** (никакого английского/кодов в тексте, кроме `[BLOCK:<id>]`; не выдумывать; не выбирать победителя).

SYSTEM, часть 2 — **## О компании** — подмешивается отдельно per-tenant (`buildCompanyAbout`, стабильный хвост; пустой профиль → секция опускается). В стабильную часть 1 не входит.

### Пример USER (`buildUserMessage`)
```
Краткое содержание диалога:
Обсуждали продление договора с клиентом «Заречный».

Последние сообщения диалога:
- Пользователь: Когда продлеваем?
- Ассистент: В следующем квартале.

Контекст:
[BLOCK:b1] Риск ухода клиента (риск оттока): Клиент намекнул, что рассматривает конкурента.
  Из встречи "Звонок с клиентом" [01:05]: "мы думаем уйти к другим"

Противоречащие факты:
[ПРОТИВОРЕЧАЩИЙ ФАКТ] (противоречит [BLOCK:b1]) [BLOCK:c1] Лояльность (решение): Клиент подтвердил продление.

[ЦЕПОЧКА РАССУЖДЕНИЯ К ФАКТУ b1]
  - (обоснование) Маржа падала: Скидка съедала маржу.

Вопрос:
Что у нас по клиенту «Заречный»?
```

Всё переменное — в USER (память диалога в начале, «Вопрос:» в конце). Тип блока — русским ярлыком (`риск оттока`, а не `churn_risk`), теги — русские (`[ПРОТИВОРЕЧАЩИЙ ФАКТ]`, `[ЦЕПОЧКА РАССУЖДЕНИЯ К ФАКТУ <id>]`, `[ТАБЛИЦА: <название>]`). Блок «Данные из таблиц» — только если есть строки (наполняет параллельная ветка таблиц, часть B).

### Выходной контракт
Свободный markdown-текст с инлайн-маркерами `[BLOCK:<id>]` рядом с фактами — постобработка превращает их в кликабельные ссылки-источники (`stripBlockMarkers` режет служебные теги из видимого текста, citations парсятся из сырого ответа ДО чистки). Это НЕ JSON.

## Почему так

| Блок методологии | Как реализован |
|---|---|
| **Роль/персона** | «Ты — Кора, ИИ-помощник по памяти ОДНОЙ конкретной компании», а не универсальный чат-бот. |
| **Якоря смысла** | КОМУ (сотрудник, может быть не из IT) + ЧТО СТАНЕТ (ответ финальный, его покажут как есть) + ЗАЧЕМ (сэкономить время на ручной подъём встреч). |
| **Границы** | явный отказ на посторонние темы / просьбу писать код — та же линия, что у самого помощника. |
| **Критерии хорошего** | 6 нумерованных правил ответа + честность про пустоту и надёжность. |
| **Few-shot** | 4 примера «плохо → хорошо», включая ключевой «конфликт спрятан → конфликт назван». |
| **Self-check** | 5 пунктов перед ответом (про дела компании? цитаты есть? пустоту назвал? конфликт не заглажен? нет английского?). |
| **Темпоральные правила** | «Особые пометки в контексте» — внутри единого промпта, больше не теряются при отсутствии режима (чинит проблему 1). |
| **Человеческий контекст** | русские ярлыки типов (`SIGNAL_TYPE_CONTEXT_RU: Record<SignalType,string>` — compile-guard: новый тип без ярлыка → сборка падает) + русские теги (именованные константы `REASONING_CHAIN_TAG_PREFIX` / `CONTRADICTING_FACT_TAG` / `TABLE_TAG_PREFIX` — единый источник для билдера и чистилки). |
| **Запреты Z** | ни одного английского слова/кода в тексте ответа, кроме `[BLOCK:<id>]`. |
| **Cache-friendly** | весь стабильный текст (роль, правила, few-shot, запреты) + «О компании» (стабильна per-tenant) — в SYSTEM; всё переменное (summary/history/блоки/вопрос) — в конце USER. Смена SYSTEM-промпта разово сбросит prompt-cache — приемлемо. |
