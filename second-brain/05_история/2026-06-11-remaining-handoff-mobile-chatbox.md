# Рефлексия — доделка остатка пакета (Мобильная Кора + ChatBox блок A)

## Что было поставлено

Доделать остаток пакета «6 ТЗ» поверх фундамента `feature/finishable-now-2026-06-11` —
как `tz-orchestrator`, по handoff-ТЗ
[`2026-06-11-remaining-handoff-finishable-now.md`](../../plans/tz/2026-06-11-remaining-handoff-finishable-now.md):

1. **ChatBox блок A** — Ф2 виджет «Чаты в памяти» (видимость результата анализа переписки),
   Ф3 prom-метрики синка/анализа, Ф4 чистый парсер ответа `sendMessage`.
2. **Мобильная Кора Ф2–Ф8** — exec «Обзор»/«Команда»/«Дела»/«Цели», голос в чек-ине,
   «Спросить»/«Память», утренний exec-push, свайп-жесты.

## Как решал

- **Картография 6 read-агентов** перед кодом — снять реальную архитектуру роутов (`page.tsx` десктоп),
  готовых паттернов (`ProbeAnswerInput`, `OrgChatPanel`, `MyDailyBriefClient`), состояния web-push
  (построен ли) и формы ChatBox-ответа.
- **Фаза-за-фазой:** кодеры по точным промптам + независимая приёмка оркестратором
  (typecheck/lint/build обеих сторон, точечные тесты, греп ключевых маркеров в файлах) + коммит по фазам.
  Многоволновая модель без остановок между фазами.
- **6 коммитов** (`9fcdc26c..daf72cbe`): `9fcdc26c` ChatBox блок A (виджет + метрики + парсер) →
  `7aa1e3ed` Мобильная Ф2 (exec «Обзор» + примитивы) → `625a03aa` Ф3 (Команда/Дела/Цели + drill) →
  `27222b0b` Ф4 (голос в чек-ине) → `8e5fe81f` Ф5+Ф6 («Спросить» + «Память») →
  `daf72cbe` Ф7 (утренний exec web-push + PWA).

## Ключевые решения

1. **Остался в основном worktree `c:/work/z`** — параллельные сессии изолированы в worktree
   `z-action-center` / `z-team`, конфликтов веток нет.
2. **B3 голос: ОТКЛОНИЛ Web Speech API → серверный ASR Vox** (паттерн `ProbeAnswerInput`):
   Web Speech не работает на iOS Safari, а iPhone — первичная цель Мобильной Коры. `VoiceInputButton`
   пишет `MediaRecorder` (`pickSupportedMimeType`) → `voiceApi.transcribe`.
3. **B6: web-push был построен, но НИ ОДИН крон не звал `enqueuePushSend`** → новый `ExecMorningPushCron` =
   **первое реальное подключение** браузерного web-push (утреннее окно, owner/admin, `N>0` ожидающих →
   «Требует тебя сегодня: N» → `/dashboard`, NX-идемпотентность, kill-switch
   `operations.daily_digest.deliver_to_webpush`).
4. **Табы «Моё/Чек-ин/Спросить/Память» уже роутятся фундаментом** на рабочие страницы
   (`/me/daily-brief`, `/me/check-ins`, `/chat`, `/decisions`) → **обернул в `MobileShell`-gate вместо
   дублирования** (инвариант №1: «переиспользуй, не плоди»). `MyDailyBriefClient` переиспользован как есть.
5. **B7 свайп + C2 pluralRu отложены** (опц./owner-deprioritized, риск без видимой ценности);
   **C1** (встреча без записи) оформлен ТЗ, **C3/D5** (слияние Входящие+Подтверждения) — design-doc;
   оба — решения владельца.

## Что вышло

- Все фазы **A + B1–B6 зелёные** (typecheck/lint/build обеих сторон, ~150+ юнит/RTL-тестов затронутых
  фаз). Десктоп не тронут — `MobileShell`-gate рендерит мобильное дерево только при `useIsMobile`,
  десктопный клиент той же `page.tsx` остаётся прежним.
- **C1 ТЗ + C3/D5 design-doc написаны** (реализация ждёт владельца).
- Доки обновлены: `feature-flags.md` (2 флага web-push), `prod-deploy-log.md` (новый блок «Накоплено»:
  VAPID + 2 флага + smoke + 2 PromQL-алерта), `04_не-сделано/README.md` (остатки в «Открыто»,
  ChatBox Ф2/Ф3 → «Закрытые»), `frontend-pages.md` (мобильный слой), `workers-queues.md`
  (`ExecMorningPushCron` + chatbox-метрики), `api-layer.md` (`memory-summary`).

## Чему научился

- **Уточняй реальную архитектуру перед реализацией.** Два сюрприза этой сессии: (1) браузерный web-push
  был полностью построен, но НИ ОДИН крон не наполнял очередь `core.push-send` — «добавить пуш» оказалось
  «впервые подключить пуш»; (2) у голосового ввода уже есть канон `ProbeAnswerInput` (серверный Vox),
  а не наивный Web Speech. В обоих случаях **клонирование существующего паттерна** дешевле и надёжнее
  нового — но увидеть это можно только прочитав код, а не ТЗ.
- **«Переиспользуй, не плоди» экономит дубли.** 4 мобильных таба («Моё/Чек-ин/Спросить/Память») уже
  роутились фундаментом на рабочие страницы — обёртка в `MobileShell` вместо новых клиентов убрала
  4 потенциальных дубля-страницы и риск расхождения логики.
