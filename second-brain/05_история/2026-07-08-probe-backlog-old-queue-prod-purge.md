# Кора опять шлёт уточняющие вопросы после выката — диагностика и покой очереди

## Что было поставлено

Владелец: вчера (07.07) выкатили в прод фикс «Кора заваливает уточняющими вопросами», а сегодня (08.07)
опять пришли сообщения («Кора собрала 4 вопроса…», «Подтверждаем у Насти области экспертизы…»). Вопрос:
это старые накопленные уведомления по старой памяти, или под не обновился / фикс не работает? Задача —
проверить логи за сутки и живой прод по SSH, установить обновился ли под и работают ли правки.

## Как решал

**Картография (локально).** Нашёл работу: ТЗ `plans/tz/2026-07-06-probe-questions-unify-and-simplify.md`,
коммит-фикс `964fea2e` (+ доп. `8db54d30` снёс вопрос «ты эксперт?» = `knowledge.new_expertise_detected`,
`649f6219` снёс вопросы шаблонов процессов = `process_template.*`, `c2286ada` — потолок 5/сутки). Оба
сегодняшних сообщения атрибутировал на снесённые reason'ы. Подтвердил `git merge-base --is-ancestor`, что
все они в `origin/dev` (прод тянет `dev`).

**Прод по SSH (read-only, expect-обёртка, база64-блоб).** Грабля: с `-tt` (нужен для su-пароля) `git log`
открывает пейджер `less` и виснет → `GIT_PAGER=cat` + `timeout` на каждую команду. Вторая грабля: при
`echo B64 | base64 -d | bash` внутренний `docker compose exec -T` **съедает stdin-пайп со скриптом** → bash
получает EOF и обрывается на середине → `</dev/null` на каждый docker/psql вызов.

**Что показал прод:**
- Под ОБНОВЛЁН: хост `dev` HEAD `7d8a9fe5`, `backend Up 19h` (старт 07-07 18:24 UTC ≈ 21:24 МСК), в образе
  файл инспектора удалён, эмиттеров экспертизы и process_template НЕТ.
- Фикс РАБОТАЕТ: запрос «снесённые reason'ы, созданные ПОСЛЕ выката» → **0 строк**.
- Сегодняшние сообщения = **старая очередь**: `knowledge.new_expertise_detected` создан 07-07 06:07 (за 12ч ДО
  выката), разослан дайджестом сегодня 09:09 UTC. В `queued_digest` висел **721** старый вопрос (R3=235,
  R2=166, R1=163, attribution≈100, experiment=34, process_template=9, …), часть с **27 июня**. Дайджест
  (крон `0 * * * *`, шлёт в `digestHourUtc`=9 UTC=12 МСК) добивал их по 5/чел/сутки → шёл бы неделями.

**Покой очереди (прод-write, по явному «да» владельца).** UPDATE `status='expired'` для снесённых reason'ов
в `queued_digest/routed_to_digest/pending` → **721** строк; затем companyprofile (разрешённый, но 30 старых
дублей с 29 июня) → **30**. Очередь после = **0 строк**.

**Постоянная защита.** `backend/scripts/patch-expire-retired-probe-backlog.ts` (идемпотентный, префиксы
отставленных reason'ов → `expired`), зарегистрирован в `apply-prod-deploy.ts` STEPS (`phase:'patch'`,
`skipBootstrap`). Запись в `prod-deploy-log.md` Шаг 6 блока probe-noise.

## Что вышло

- Прод-очередь уточняющих вопросов пуста; шум прекратился сразу (а не через недели дренажа).
- Кора шлёт только разрешённое: task-clarify (immediate) + недельный профиль.
- Скрипт: typecheck EXIT 0 (heap 8ГБ), `--dry-run` на dev-БД корректно нашёл 189 отставленных по всем
  префиксам (включая R4/R5 и `helpfulness.new_expertise_helper`), записи не делал.

## Чему научился

- **Снос эмиттера ≠ покой шума.** Отставить probe-повод = убрать источник СОЗДАНИЯ, но накопленная очередь
  `queued_digest` живёт своей жизнью и дренажится дайджестом по потолку неделями. Ретайр повода ОБЯЗАН
  сопровождаться чисткой очереди (`expired`) — иначе владелец получает «призраки» после выката и думает, что
  фикс не сработал. Это была дыра ТЗ Ф7 (деплой) — снесли эмиттеры, забыли очередь.
- **Диагноз «под не обновился» vs «старая память» решается одним запросом:** `created` vs `dispatched` по
  reason. `created` до выката + `dispatched` после = старьё; `created` после выката = регресс. Ноль созданных
  после выката снесённых reason'ов — исчерпывающее доказательство, что код в проде правильный.
- **SSH-грабли на macOS (в дополнение к `docs/operations/prod-ssh-access.md`):** `-tt` + git = пейджер-виснет
  (`GIT_PAGER=cat`); `... | base64 -d | bash` + внутренний `docker exec -T`/`psql` крадёт stdin со скриптом
  (`</dev/null` на каждый). `timeout` на macOS нет (127) — использовать лимит инструмента, а не `timeout`.
