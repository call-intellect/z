## V-#8 ROOT CAUSE (доказано кодом) — транскрипт намеренно отдаётся ТОЛЬКО владельцу встречи
- Фронт: `frontend/src/ui/components/meeting-result-v2/MeetingResultPageReal.tsx` — таб «Транскрипт» дёргает `meetingsApi.transcript(meetingId)` через SWR с `shouldRetryOnError: false`; сообщение «Транскрипт ещё не готов…» рисуется при `!hasTurns && hasTracks` (есть дорожки, нет реплик).
- Бэк-эндпоинт: `GET :id/transcript` → `meetings.controller.ts:170` → `transcriptCleaning.getTranscript({ meetingId, userId })`.
- **Корень:** `backend/src/modules/ai/services/transcript-cleaning.service.ts:38-39`:
  ```ts
  if (meeting.ownerId !== args.userId) {
    throw new ForbiddenException('not_meeting_host');
  }
  ```
  Реплики возвращаются ТОЛЬКО если запросил владелец встречи. Любой сотрудник (даже член той же Org, даже при «Видно всей компании») получает **403 not_meeting_host**. Фронт с `shouldRetryOnError:false` глотает 403 → `data=undefined` → `hasTurns=false` → рисует «Транскрипт ещё не готов». Сообщение ВРЁТ: транскрипт готов, просто запрещён.

- **Точный фикс (доказанный, человеческим языком):** в `getTranscript` заменить владелец-гейт на ту же проверку видимости, что у обзора — `await this.visibility.assertCanView(meetingId, userId)` вместо `ownerId !== userId`. ## V-FREEZE (новая жалоба владельца 22.06) — «после долгого сидения всё перестаёт работать, помогает только Выход» → найден механизм в коде
- Симптом: вкладки не переключаются, клики по меню без эффекта, спасает только «Выход».
- Консоль на проде стабильно показывает фоновые ошибки: повторяющийся **404 `/api/version`** (поллер `useVersionCheck`, раз в 5 мин) и Kaspersky-CSP (антивирус пользователя — безвредно).
- **Корень (доказано кодом):** на 401 `frontend/src/api/api-client.ts:160-167` вызывает `emitAuthExpired()` (событие `auth:expired`) и бросает «Сессия истекла». Обработчик в `frontend/src/contexts/auth-context.tsx:152-158`:
  ```ts
  const handler = () => { setState({ user: null, isLoading: false }); };
  ```
  — он **только обнуляет user, но НЕ редиректит на /login и не показывает модалку**. SWR-запросы идут с `shouldRetryOnError:false`. Поэтому когда cookie-сессия протухает за время сидения: каждый следующий запрос → 401 → `user=null`, но пользователь остаётся на текущем экране; вкладки/меню дёргают API, всё 401 → данные не грузятся, переходы «впустую». Единственное, что уводит со страницы — «Выход» (он явно навигирует на /login). Точное совпадение с симптомом.
- **Фикс (человеческим языком):** при `auth:expired` — жёстко редиректить на `/login?next=…` (или показывать модалку «Сессия истекла, войдите снова» с кнопкой входа), а не молча обнулять пользователя. Лучше — добавить тихий refresh сессии/продление cookie, чтобы она не умирала посреди работы. Плюс починить `/api/version` (сейчас 404 → оповещение «вышла новая версия, обновите страницу» не работает вообще).
- Не воспроизведено вживую (нужна многочасовая сессия с протуханием cookie), но путь в коде объясняет симптом полностью; приоритет высокий — это «убивает» сессии у всей команды.
