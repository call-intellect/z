# Анализ: Хранение записей и retention (TTL для файлов)

## Что хотим сделать

Записи встреч и аудио-дорожки участников хранятся в S3 ограниченное время. Срок зависит от тарифа пользователя. По истечении срока файлы либо удаляются, либо архивируются, либо пользователь должен успеть их скачать.

## Зачем (цель и ценность)

- **Снижение costs.** При 1.8 ТБ/месяц и retention 30 дней — постоянный объём в S3 ~5.4 ТБ. С retention 1 день — 60 ГБ. Разница в счёте × 90.
- **Гибкость тарифов.** Базовый план «1 день хранения» / премиум «30 дней» / enterprise «90 дней + экспорт» — главный рычаг ценообразования.
- **GDPR / законы о персональных данных.** Возможность принудительно удалить записи через N дней — требование compliance.

## Как работает сейчас

Кода нет. В исходном решении про retention — ни слова, фича добавлена 2026-05-06.

## Сценарии retention (на обсуждение)

### Сценарий A — авто-удаление по истечении

В тарифе указан `retention_days`. Через N дней после `meeting.ended_at` запись удаляется из S3. Транскрипт и AI-отчёт остаются в БД.

### Сценарий B — авто-уведомление + grace period

За N дней до удаления — email/push «ваша запись будет удалена через X дней, скачайте». Если не скачали — удаление.

### Сценарий C — авто-перенос в холодный S3 (Glacier-like)

После N дней — переносим в более дешёвое хранилище (Yandex Cold Storage). Потом по запросу пользователя — restore + скачивание. По истечении ещё N дней — окончательное удаление.

### Сценарий D — экспорт в S3 пользователя (enterprise)

После N дней — выгружаем файлы в S3 клиента (его bucket, его credentials). Полезно для крупных клиентов с собственной инфраструктурой.

## Что нужно от системы

1. **Поле `expires_at`** на каждой записи — рассчитывается как `meeting.ended_at + tariff.retention_days`.
2. **Cron-job** раз в час: ищет записи с `expires_at < NOW()` и `status != 'deleted'` → выполняет действие (delete / archive / export).
3. **Действие настраивается на тариф:** `delete` / `notify_then_delete` / `archive` / `export_to_user_s3`.
4. **API для пользователя:**
   - GET `/recordings/:id/download` — получение скачиваемой ссылки (presigned URL).
   - POST `/recordings/:id/extend?days=N` — продление (для тарифов где это разрешено).
   - DELETE `/recordings/:id` — досрочное удаление по запросу.
5. **Логи в БД:** таблица `recording_actions` (created / extended / archived / deleted) — для compliance и аудита.

## Закрыто (2026-05-06)

- [x] **Дефолтный retention для MVP — 30 дней.** Опираемся на стандарт Microsoft Teams (60 дней — слишком, 7 — слишком мало). 30 дней даёт пользователю достаточно времени скачать запись (по статистике 90% доступа в первые 14 дней) и не раздувает Selectel-бакет. На MVP-нагрузке ~60 ГБ/день постоянный объём ~1.8 ТБ. В тарифах потом — бесплатный 7 дней / базовый 30 / премиум 90 / enterprise год.

## Открытые вопросы
- [ ] **Транскрипт и AI-отчёт** — храним вечно (это маленькие текстовые данные) или тоже подвергаем retention?
- [ ] **Аудио-дорожки** удаляются вместе с общей записью или отдельно? (Предложение: вместе.)
- [ ] **Notification:** за сколько дней предупреждаем перед удалением? (Предложение: за 3 дня.)
- [ ] **Восстановление** случайно удалённой записи — через soft-delete (30 дней grace) или жёсткое удаление?
- [ ] **Принудительное удаление по GDPR-запросу** — отдельный API или достаточно DELETE? (Предложение: отдельный, с логированием причины.)
- [ ] **Экспорт в S3 пользователя** — только enterprise или для всех? (Предложение: enterprise V2.)

## Что уходит в data-model

`Recording`:
- `expires_at: timestamp` — когда истекает retention.
- `retention_days: int` — снимок политики на момент создания.
- `archived_at: timestamp | null` — если перенесли в холодное хранилище.
- `deleted_at: timestamp | null` — soft-delete для grace period.

Новая таблица `recording_actions(id, recording_id, action, actor, reason, created_at)`.

## MVP-минимум (без тарифов)

Чтобы не блокировать MVP и сразу заложить архитектуру:
- Поле `expires_at` присутствует на записи.
- Дефолтное значение — 30 дней (хардкод в env, потом переедет в тариф).
- Cron-job удаления работает с первого дня — даже если пока удаляет редко.
- API `download` / `delete` есть.
- Уведомления, экспорт в S3 пользователя, soft-delete — V2.
