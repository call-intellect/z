# ТЗ — Структурное описание задач и подзадач (Т11)

> **Контракт для реализации** (скилл `tz-orchestrator`). Причина: в проде **описание** задачи = дословная
> расшифровка речи постановщика (сырой `sourceQuote`), а не переработанный структурный текст. Заголовок уже
> формулируется чисто — правим **только описание** (и качество пунктов чек-листа). Точные якоря —
> [картография §5а](../analysis/2026-07-03-task-tracking-stand-code-cartography.md). Проверка эффекта —
> стенд `task-stand`, категория **K** (before → after).

## 0. Цель, границы, инвариант

**Цель:** `Issue.description` / `Issue.descriptionStripped` (и текст пунктов чек-листа) должны быть **коротким
структурным текстом по сути** (что нужно сделать / зачем / ключевой контекст), а НЕ дословной речью со словами-
паразитами, расшаркиваниями, эмодзи и обрывками. Дословная фраза сохраняется как **провенанс**.

**Границы:**
- **Заголовок не трогаем** — он уже чистый (`specialists-combined.prompt.ts:614`, `task-extract.prompt.ts:32`).
- Правим **живой** извлекатель `SpecialistsCombined` (главный путь) + симметрично **легаси** per-block, если он
  ещё активен на момент реализации (проверить Т1 стендом — если мёртв, не тратить усилия).
- Способ (одобрен по разведке, Вариант 1): добавить структурное поле **`description`** в тот же LLM-вызов
  извлечения (ноль доп. стоимости/латентности), НЕ отдельным пост-шагом.
- Ship-On: правка всегда включена (это не флаг — улучшение качества текста). Нового рубильника не заводим.

**Инвариант качества текста (проверяется стендом, категория K):**
- описание короче/чище входа, без слов-паразитов/приветствий/эмодзи; **факты сохранены** (срок/имя/сумма/
  контрагент); **ничего не выдумано** (только факты из источника — антигаллюцинация); русский, без кодов/латиницы;
- **сырьё не потеряно** — дословная цитата остаётся в провенансе;
- заголовок и число задач/подзадач **не изменились** относительно текущего поведения (регрессия).

## 1. Изменения (по файлам, с якорями — досверять по символу)

### Ф1 — добавить `description` в combined-извлекатель (главный путь)
1. **Схема + тулза + промпт** `backend/src/modules/knowledge-core/prompts/specialists-combined.prompt.ts`:
   - в `TaskDraftCombinedSchema` (около `:220-234`, рядом с `title`/`sourceQuote`) добавить
     `description: z.string().max(600).nullable().optional()`;
   - в tool-schema `tasks.properties` (около `:523-535`) добавить свойство `description` (string, nullable);
   - в system-инструкцию (около `:614-615`) добавить правило: **«`description` — короткая структурная суть
     задачи своими словами: что нужно сделать, зачем/контекст, ключевые факты (срок, имена, суммы). 1–3
     предложения, деловой русский, без слов-паразитов, приветствий, эмодзи, латиницы и кодов. НЕ копировать речь
     дословно и НЕ выдумывать факты, которых нет в реплике. `sourceQuote` остаётся дословной цитатой-опорой.»**
2. **Маппинг** `backend/src/modules/knowledge-core/services/specialists-combined.service.ts` (около `:1176-1187`):
   в объект `TaskDraftInput` добавить `description: t.description ?? null`.
3. **Тип + материализация** `backend/src/modules/tracker/services/task-draft-materializer.service.ts`:
   - в `TaskDraftInput` (около `:17-28`) добавить `description?: string | null`;
   - на `:185` заменить `extractedDescription: sourceQuote || null` →
     `extractedDescription: (draft.description?.trim() || sourceQuote) || null` (переформулировка с фолбэком на
     цитату, если модель не дала description);
   - `rawContent` (`:172-173`) не трогать — сырьё `«…Цитата: ${sourceQuote}»` уже сохраняется (провенанс цел).

### Ф2 — легаси per-block (симметрично, ТОЛЬКО если путь активен)
`backend/src/modules/knowledge-core/prompts/task-extract.prompt.ts` + `specialist-3-15-tasks.service.ts:291`:
добавить `description` в JSON-схему извлечения рядом с `title`/`sourceQuote`, то же правило текста; на `:291`
`extractedDescription: draft.description ?? draft.sourceQuote ?? null`. Если стенд (Т1) покажет, что per-block
мёртв — Ф2 пропустить, отметить в отчёте.

### Ф3 — провенанс на Issue (сохранить дословную цитату при accept)
`backend/src/modules/tracker/services/intake.service.ts` (около `:692-701`, ветка `triage(accept)` →
`issues.create(...)`): добавить в data `previewQuote` = дословная цитата из `intake.rawContent`/`sourceQuote`
(сейчас `Issue.previewQuote` пустует — `schema.prisma:9642`). Downstream `description ← extractedDescription`
не трогать — чистое описание поедет само. (Если извлечь цитату из `rawContent` дорого — допустимо оставить
провенанс только в `rawContent`; тогда стенд-сценарий K-08 проверяет `rawContent`.)

### Ф4 — качество пунктов чек-листа (усилить инструкцию)
Подзадачи уже приходят как короткие `subtasks:[{title}]` (`specialists-combined.prompt.ts:615`). Усилить
инструкцию: **«каждый пункт — чистая формулировка шага (глагол+объект), без слов-паразитов и дословной речи»**.
Отдельный шаг чистки не вводить (лишний LLM-вызов) — только правило в промпте. Проверка — стенд K-04/K-10.

### Ф5 — снапшоты и промпт-реестр
- Обновить снапшот-тесты промптов (`specialists-combined.prompt.spec.ts` и, если правился, `task-extract`) —
  осознанное обновление под новую схему.
- Если combined/extract-промпты **admin-editable через registry** и в проде есть сохранённая версия: добавить
  `patch-*.ts`-скрипт обновления prompt-текста в registry (иначе admin-override перекроет новое правило), либо
  подтвердить, что прод использует code-fallback. Зафиксировать в `prod-deploy-log.md` (правка промпта, миграции
  БД НЕТ — колонка `extractedDescription` уже есть).

## 2. Прод-операции

- **Миграции БД нет** (пишем в существующую `IntakeIssue.extractedDescription` / `Issue.description`/
  `descriptionStripped`/`previewQuote`).
- Если промпт admin-editable и переопределён в проде → `patch-*` в `apply-prod-deploy.ts STEPS` (Шаг 6). Иначе —
  чистый деплой кода. Отразить в `docs/operations/prod-deploy-log.md` Шаг 6 (+ методология промптов
  `docs/methodology/prompts/` — новый под-контракт «структурное описание»).

## 4. Проверка стендом (обязательна — доказательство «было→стало»)

Гонять `task-stand` (см. [ТЗ стенда](2026-07-03-task-tracking-stand.md)) на категории **K** до и после фикса:
- **до:** K-01..K-10 → `WRONG_OUTCOME`/`PARTIAL` (описание = `sourceQuote`, ось T низкая) — baseline Т11;
- **после:** K-01..K-10 → `PASS` (ось T высокая: чисто, факты целы, без выдумок, провенанс сохранён);
- регрессия: категории A/B/C (заголовок, число задач, чек-лист-как-структура), D (дедуп по эмбеддингу
  description+title — проверить, что смена текста описания не сломала пороги дедупа §3.2 картографии).

> ⚠️ **Побочный эффект на дедуп:** `TaskDedupService.buildText` = `title + "\n\n" + description[:500]`
> (`task-dedup.service.ts:201`). Смена описания с сырой цитаты на структурный текст меняет эмбеддинг кандидата →
> может сдвинуть матчи дедупа. Стенд категории D обязан пере-провериться после фикса (порог 0.88 калибровать при
> необходимости — Т10). Это первый кандидат в регрессию.
