## Что вскрылось (главное)

- `ac7ca44e` (фикс `TasksService.listByMeeting`: `assertMeetingOwner` → `assertCanView`) — **является предком HEAD**, но файл, который он чинил, **физически снесён** последующей унификацией Task→Issue:
  - **Ф7a** (`e0dc1257`) — удалён весь backend-модуль `tasks/` (вместе с `tasks.service.ts`).
  - **Ф7b** (`95f3b963`) — вкладка задач встречи переведена на tracker Issue: фронт ходит `GET /api/v1/issues?linkedMeetingId=<id>`.
  - **Ф8** (`ec41a025`) — снесена модель `Task`.
- Виджет переехал на `IssuesService.findAllAcrossProjects`, где поверх фильтра `linkedMeetingId` накладывается видимость рабочего стола «Задачи» (Р3/Р4): руководитель/`open` → все; **manager+strict → только свои** (assignee=self ИЛИ создатель).

Итог: фикс `ac7ca44e` отменён удалением файла, а баг воспроизводится **новым механизмом** — участник, который ВИДИТ встречу, но не назначен/не автор её задач, получал пустой виджет (раньше — 404 owner-чека, теперь — пустая выборка strict-scope). Утверждение «доп. правок не нужно» для этой ветки неверно.

2. **Переписал ТЗ** под новый путь: новый корень (видимость трекера строже видимости встречи), фикс через `assertCanView`-гейт, §4 (вариант A) сохранён.
3. Кодер (суб-агент) реализовал: в `OrgIssuesController.list` при заданном `linkedMeetingId` — `assertCanView(meetingId, userId)` → `meetingAuthorized=true` пробрасывается в `findAllAcrossProjects`; `seesAll` теперь даёт `true` также при `linkedMeetingId && meetingAuthorized`, минуя strict self-scope. Общий рабочий стол «Задачи» `linkedMeetingId` не шлёт → его видимость не меняется. Фронт без правок.
4. Приёмка сам (не по отчёту агента): git status (ровно 4 файла), re-Read диффа, typecheck 0 ошибок, eslint 0, build зелёный, tracker-модуль 514 тестов зелёные. ## Чему научился
1. **ТЗ устаревает, когда параллельная работа удаляет модуль, на который оно ссылается.** «Фикс уже сделан в коммите X» ≠ «фикс жив»: коммит может быть предком HEAD, но его файл — снесён более поздней фазой той же ветки. Всегда верифицируй на картографии, что путь/файл/эндпоинт ещё существует, прежде чем верить, что правок не нужно. Сигнал был в `git log`: `Ф7a — удалить deprecated модуль tasks/`.
2. **Видимость трекера ≠ видимость встречи; они не взаимозаменяемы.** Любое чтение, отфильтрованное по встрече, но идущее через tracker-эндпоинт (`findAllAcrossProjects` и т.п.), наследует strict self-scope трекера — строже модели видимости встреч. Meeting-scoped чтение надо гейтить `MeetingVisibilityService.assertCanView` и осознанно минуть strict-scope, иначе «0 задач» для легитимных зрителей. Это переиспользуемая грабля для будущих meeting-фильтрованных tracker-ручек.
3. **Унификация задач переносит баг, а не убивает его** — если симптом завязан на модель доступа, смена хранилища (Task→Issue) меняет механизм проявления, но не лечит причину. Корень был в авторизации, и он переехал вместе с виджетом.
