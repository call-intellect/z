# Умные таблицы — живой тест агентов + аудит качества (2026-06-08)

## Что делали

Зашли тестовым аккаунтом в прод-кабинет, прогнали агентскую цепочку умных таблиц
на **синтетических данных 9 разных доменов**, реально наполнили таблицы и
зафиксировали вывод агента по каждому прогону для оценки качества.

**Результат наполнения (верифицировано через rows-API):** 47 строк в 9 таблицах —
8 системных через `merge` + 1 новая «Инвентарь» через `create`.

## Карта агентских цепочек умных таблиц (по коду)

1. **Text-to-Schema (Фаза 1)** — 3 LLM-пасса в `TableAgentService.inferSchemaFromText`:
   `table-infer-schema` (DRAFT) → `table-architect-pass` (ARCHITECT: дедуп колонок,
   типы, 1 isPrimary) → `table-entity-check` (ENTITY: сверка entitySync). Primary →
   DeepSeek V4 Pro. После пассов — жёсткая `normalize()` (инварианты). **За
   feature-flag `feature.tables_text_to_schema`.**
2. **Document-to-Table (Фаза 4)** — тот же 3-pass через `inferSchemaFromTabular`
   (вход = заголовки + 20 строк), затем `alignToHeaders` (столбец↔property 1:1),
   `findSimilarTables` (cosine-dedup, порог 0.85), `linkRowsToEntities`. **Без флага.**
3. **Event-to-Cells (Фаза 3)** — `table-extract-rows` (DeepSeek V4 Flash) патчит
   ячейки из транскрипта; conf≥0.85 → авто, иначе pending.
4. **NL Saved Views (Фаза 5)** — `table-semantic-filter` (Flash) NL→JSON-фильтр.

**Эмпирически на проде:** Phase 4 — работает; Phase 5 — работает; Phase 1 —
выключена флагом; Phase 3 — не тестировали (нужна встреча с транскриптом).

## 🔴 Находка 0 (КРИТ, блокер) — деталка `/tables/[id]` крашится на проде

**Симптом:** открытие ЛЮБОЙ таблицы (даже пустой системной) → экран «Не удалось

бесконечный ре-рендер) + `404` на `GET /api/v1/tables/pending-patches?tableId=…`.
Список таблиц `/tables` работает; открыть нельзя ни одну.

**Корень:** ровно эти два бага уже диагностированы и **исправлены в ветке**
коммитом `26219233` (`fix(tables): TZ A — React #185 + 404 pending-patches`):

  (Zustand v5: селектор возвращает новый массив → петля). См.
  [TableClient.tsx:171](../../frontend/app/(authenticated)/tables/[id]/TableClient.tsx#L171).

**Вывод:** фикс есть в рабочем дереве, но **прод работает на билде ДО 26219233**.

наполненные данные не видны глазами в гриде (хотя в БД они есть — проверено API).

## 🟢 Что у агента хорошо (Document-to-Table, 3-pass)

Корпус: 10 прогонов (9 доменов + 1 retry), ~57 колонок.
- **Типы**: text/longtext/number/currency/percent/date/email/phone/url/checkbox/
  person/status/selectSingle — верно в ~98% колонок. Числа («32000000»),
  деньги, даты, телефоны, e-mail распознаются корректно.
- **entitySync**: 100% верно — `org` для клиентов/поставщиков, `null` для
  контент/цели/идеи/гипотезы/инвентарь.
- **Имя/иконка**: осмысленные (💼/🤝/📰/📦…).
- **Dedup (положительные)**: cosine 0.91–1.0 на совпадающих схемах.
- **Dedup (истинно-негативный)**: новый домен «Инвентарь» → кандидатов нет (верно).
- **Semantic-filter (Фаза 5)**: «сделки на сумму больше 500 тысяч» →
  `{Сумма, op:gt, value:500000}` — верно колонка+оператор+парсинг «500 тысяч».

## 🟡 Находки качества (с доказательством) и улучшения с оценкой %

> Сэмпл маленький (~10 прогонов) — оценки направленные, не статистика. Все
> улучшения на пути Document-to-Table — **единственный живой путь создания**
> (text-to-schema выключен флагом).

### F1 — Pass 1 (DRAFT) = единственная точка ЖЁСТКОГО отказа
**Док-во:** импорт «Реестр рисков» упал с `400 table_schema_generation_failed`,
**тот же файл прошёл со 2-й попытки**. Passes 2–3 деградируют мягко (fallback на
предыдущий), pass 1 — бросает `BadRequestException`, retry нет.
**Частота:** ~1/10 прогонов (транзиент, вероятно таймаут Pro 30с).
**Улучшение:** 1–2 retry для pass-1 `callJson` (тот же cache-friendly промпт; ретрай
только при null/ошибке). **Оценка: hard-fail импортов ~10% → ~1–2%** (≈90% текущих
отказов уходят: при независимых попытках p→p²). Стоимость почти нулевая (срабатывает
только на отказе).

### F2 — Опции select/status неполные (теряются «хвостовые» значения)
**Док-во:** «Стадия» клиентов → опции без **«Отказ»** (есть в данных); «Услуга»
поставщиков → без **«Прочее»**. Оба — «прочее/негатив». При полном наборе значений
в данных (контент-план) — опции собраны 4/4, 5/5, 4/4.
**Частота:** 2/9 option-колонок с хвостовым значением.
**Улучшение (детерминированный пост-пасс, только tabular):** для
`selectSingle/selectMulti/status` собрать DISTINCT значения прямо из распарсенной
колонки и сделать **union** с опциями LLM (LLM — seed, код — гарантия полноты;
цвет round-robin). **Оценка: полнота опций ~78% → ~100%** на импорте; устраняет 100%
«сиротских» значений при `create`. Данные уже на руках — это надёжнее, чем просить
LLM перечислить.

### F3 — cosine-dedup хрупок к переименованию таблицы
**Док-во:** «Идеи и бэклог» — агент назвал схему **«Запросы и пожелания»** →
**кандидата на слияние НЕ нашлось**, хотя набор колонок ИДЕНТИЧЕН системной таблице.
В `schemaToText` имя доминирует над колонками в эмбеддинге.
**Частота:** 1/9 (ложно-негативный dedup).
**Улучшение:** добавить сигнал пересечения по колонкам — Jaccard нормализованных
имён колонок; предлагать merge при `cosine ≥ 0.85 ИЛИ colJaccard ≥ 0.6`. На кейсе
«Идеи» Jaccard=1.0 → флипается в верный merge. **Оценка: ~11% импортов перестают
плодить таблицу-дубль** вместо слияния в нужную.

### F4 — точечный type-misfire на неоднозначной колонке
**Док-во:** «Результат» (свободный текст «Конверсия выросла на 18 процентов») →
агент типизировал как **`date`**. Также «Описание/Формулировка» → `text` вместо
`longtext` (мягко). На merge данные не теряются (маппинг по имени в longtext), но
тип неверный.
**Улучшение (детерминированный guard, tabular):** валидировать выведенный
`date/number/currency/percent` против сэмпла значений; если <50% парсятся —
понизить в `text/longtext`. Кейс «Результат»: 0% значений — дата → авто-понижение.
**Оценка: ~100% tabular type-misfire (date/number) ловятся** детерминированно.
Длинный текст → longtext: правило в DRAFT/ARCHITECT-промпт («примеры >~40 симв. →
longtext; не ставь date/number, если примеры не парсятся»).

### F5 — агент непредсказуемо переименовывает таблицы
**Док-во:** «Сделки» (из klienty), «Запросы и пожелания» (из идей), «Обещания и
поручения», «Инвентарь» (из оборудования). Не «ошибка», но (а) корень F3, (б)
путает пользователя при импорте знакомого файла.
**Улучшение:** для file-import по умолчанию опираться на базовое имя файла /
доминирующую семантику заголовков и не «творить»; для text-to-schema — свобода ок.
Косвенно усиливает F3.

## Сводка улучшений (приоритет)

| # | Улучшение | Где | Тип | Оценка эффекта |
|---|---|---|---|---|
| 0 | **Редеплой** (ship 26219233) | infra | deploy | openable-таблицы **0%→100%** |
| 1 | Retry pass-1 DRAFT | `table-agent.service.ts` | code | hard-fail импортов **~10%→~1–2%** |
| 2 | Union опций из данных | `table-agent`/import (tabular) | code | полнота опций **~78%→~100%** |
| 3 | Jaccard-сигнал в dedup | `findSimilarTables` | code | **~11%** меньше дублей-таблиц |
| 4 | Type-guard date/number по сэмплу | import/agent (tabular) | code | **~100%** type-misfire пойман |
| 5 | Стабильное имя при file-import | `inferSchemaFromTabular` | code/prompt | косвенно усиливает #3 |

**Ключевой принцип (архитектурный вывод):** на пути Document-to-Table данные
колонок — на руках, поэтому полноту опций, валидность типов и dedup надёжнее
закрывать **детерминированными пост-пассами поверх LLM** (LLM классифицирует — код
проверяет против данных), в духе уже существующих `normalize()`/`alignToHeaders()`.
Для text-to-schema (данных нет) остаётся только промпт-рычаг.
