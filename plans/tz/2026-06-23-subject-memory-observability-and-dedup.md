# ТЗ: Subject Memory — наблюдаемость выученных правил + дочистка висящих дублей

## Проблема (вскрыта живым тестом 2026-06-23)

Самообучение на ответах (`SubjectMemory`, ТЗ `2026-06-21-learned-clarifications-memory.md`) реализовано и **включено** в проде (флаги `subjectMemory.enabled=true`, `retrieveBeforeAskEnabled=true`, `shadowToCanaryMinConfirm=0`), но:

1. **Работу фичи невозможно наблюдать.** Выученные правила не выведены никуда — ни UI в кабинете, ни диаг-команды, ни read-эндпоинта. Метрики `subject_memory_*` per-process (прод многонодовый) → `/metrics` показывает нули. Лог-стор `platform/logs` воркер `subject-memory-derive` не покрывает (только «worker запущен»). Итог: нельзя проверить, выводятся ли правила и подавляются ли вопросы.
2. **Висящие дубли не подчищаются.** `retrieve-before-ask` подавляет только **новые** probe при генерации. Уже накопленные одинаковые вопросы (в тесте — 3 шт. про один «Дамп от 05.06.2026 13:05») остаются висеть даже после ответа на один из них.

**Доказательство (тест в Org «ооо ромашка», 2026-06-23):** ответ на probe про дамп → вопрос принят и ушёл (10→9 вопросов), цепочка `ProbeResponseHandler` запущена. Но подтвердить вывод правила нельзя (нет наблюдаемости), а 2 дубля про тот же дамп остались в очереди.

**Эффект для владельца:** фичу выкатили, но «не видно, работает ли» — поэтому эффекта обучения не заметно, а старые дубли продолжают засорять очередь.

## Что делаем

### Часть 1 — Наблюдаемость выученных правил

- **Read-доступ к `SubjectMemory` по Org:** эндпоинт `GET /api/v1/subject-memory` (или admin-scope) — список правил с полями: `contextText`, `ruleText`, `kind`, `status` (shadow/canary/active/rolled_back/superseded), `confidence`, `confirmCount`/`refuteCount`, `sourceProbeIds`, `createdAt`. Фильтры по `status`. Per-Org изоляция (`tenantId`).
- **Просмотр в кабинете:** страница/раздел «Что Кора выучила» (в «Память» или «Админка компании») — человеческим языком: «На вопрос про X Кора теперь отвечает: Y» + статус (испытывается / активно) + сколько вопросов это сняло.
- **Диаг-команда** (read-only, для проверки): добавить в `backend/scripts/diag.ts` команду `subject-memory --org <id>` — список правил + счётчики, чтобы тестировать обучение без UI.
- **Метрики в стор:** дублировать ключевые события (`rule_extracted`, `probe_suppressed`, `rule_activated`, `rolled_back`) в `platform/logs` (структурный лог с `tenantId`), чтобы они переживали рестарт и были видны в диаге.

### Часть 2 — Дочистка висящих дублей при выводе правила

- При создании/активации правила (`upsertWithSupersede` / переход в `active`) найти **открытые** `ProbeEvent` (`status='pending'`) той же Org, семантически близкие к `contextText` правила (тот же порог `matchMinSimilarity`), и погасить их (`status='suppressed_by_memory'`) — чтобы накопленные дубли уходили из очереди, а не только будущие.
- Крутилка-флаг `subjectMemory.sweepPendingOnLearnEnabled` (AdminSetting, kill-switch, ON).

## Фазы

- **Ф1.** Read-эндпоинт `SubjectMemory` + диаг-команда (быстрая проверяемость).
- **Ф2.** Дочистка висящих дублей при выводе правила (Часть 2) + флаг.
- **Ф3.** Страница «Что Кора выучила» в кабинете (человеческий вид).
- **Ф4.** Дублирование событий обучения в `platform/logs`.

## Проверка (после Ф1-Ф2)

Повторить тест: ответить на один из дублей-probe в тестовой Org → через диаг увидеть выведенное правило (Часть 1) → убедиться, что остальные дубли той же темы погашены (Часть 2).

## Не входит

- Изменение самой логики обучения/активации (она реализована — ТЗ `2026-06-21`).
- Подстановка правил в chat-v2/ассистент (отдельное ТЗ vNext).
- Edit-distance сигнал (правки черновиков) — отдельное vNext-ТЗ.
