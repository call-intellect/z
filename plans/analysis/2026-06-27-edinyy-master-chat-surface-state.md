> Цель разбора: почему «единая точка общения с Мастером» (плавающая кнопка + вход из меню → полноценное окно: история диалогов слева, новый диалог, поле ввода снизу, переключение «общий разбор / по клонам») сейчас НЕ работает как одно целое, и что с этим делать.
> Это НЕ про probe-петлю (та — в [[2026-06-27-probe-clarify-dialog-reliability]]). Это про **поверхность чата** (UI единого помощника).

# Анализ: состояние «единого окна общения с Мастером»

## 0. TL;DR (вердикт)

**Бэкенд «единого мозга» сделан, фронт-консолидация — нет.** Сегодня в кабинете живут **два разных движка чата за двумя разными входами**, и они не сведены в одно окно:

1. **Плавающая кнопка (FAB)** → маленький поповер 380×600 «Мастер» (движок **concierge**). Умеет действия (поставить задачу, undo, инструменты), но **без списка диалогов, без «нового диалога», без истории** — один эфемерный тред.
2. **Пункт меню «Спросить» → `/chat`** → большая страница (движок **chat-v2**). Это **и есть** «дом чата как в ChatGPT/Claude»: слева колонка «Диалоги» + «Новый» + Активный/В архиве, скоупы, цитаты, временной срез, закрепить/архив. Но это **только вопрос-ответ** — действий/инструментов/undo нет. И в меню **владельца этого пункта нет вообще** (он только для роли manager).

Итог для владельца: единственный доступный вход — FAB, а это движок-поповер **без истории**. Красивый «дом» с историей (`/chat`) для владельца **недостижим из навигации** и при этом не умеет действий. Это и есть ощущение «не работает».

Хорошая новость: **починка уже расписана** в ТЗ [`2026-06-25-edinyy-pomoshnik-chat-surface-convergence.md`](../tz/2026-06-25-edinyy-pomoshnik-chat-surface-convergence.md) (КФ1–КФ5, все `[ ]` — не начато). Этот разбор подтверждает диагноз на живом проде и добавляет 3 разрыва, которых в ТЗ нет.

## 1. Что должно быть (твоя картина)

- **Один вход** к Мастеру: плавающая кнопка **и** пункт в левом меню.
- **Полноценное окно** (как любой LLM-чат): слева — история диалогов + «новый диалог»; справа — переписка; снизу — большое поле ввода.
- **Переключение режима**: «общий разбор» ↔ «по клонам»; у каждого режима — **свои диалоги**.
- Это работает как единое целое из любой точки кабинета.

## 2. Что по факту (verified)

### 2.2 Код, подтверждающий разрыв

- `frontend/src/ui/concierge/ConciergeFloatingButton.tsx` — поповер с локальным `useState(mode: company|clones)`, рендерит `ConciergeChat` либо `ConciergeClonesTab`. Никакого `listConversations`.
- `frontend/src/ui/concierge/ConciergeChat.tsx` — тред в `useState<ChatRow[]>`, один `currentConv`; принимает `conversationId` пропом, **но FAB его не передаёт и UI выбора прошлых диалогов отсутствует**. То есть API истории есть (`GET /concierge/conversations`, см. [[concierge-agent]]), а в поверхности Мастера он не используется.
- `frontend/app/(authenticated)/chat/page.tsx` — рендерит `ChatV2Client`, **не** Мастера. То есть редиректы `/chat-v2`→`/chat` и `/assistant`→`/chat` свели URL, но **не движок**: `/chat` по-прежнему старый chat-v2.
- `frontend/src/ui/components/app-shell/nav-config.ts` — пункт «Спросить» (`/chat`) имеет `roles: ["manager"]` + `gateFeature: "feature.chat_org"`. Значит owner/admin/coo (`LEADERSHIP_ROLES`) его **не видят**. Подтверждено на проде.

## 3. Почему не работает (корневые причины)

1. **Фронт-консолидация не сделана.** «Единый мозг» на бэке готов (Мастер single-pass → chat-v2 `askEphemeral` в процессе, петля уточнения замкнута — коммиты `f51e5a0e…8dac5210`, ветка `feature/edinyy-pomoshnik-arhitektura`). Но «схлопнуть 3 движка ответа в один на 4 живых поверхностях» **отколото в отдельное ТЗ** [`chat-surface-convergence`](../tz/2026-06-25-edinyy-pomoshnik-chat-surface-convergence.md) и **не начато** (нужна была визуальная приёмка). Поэтому в проде остались оба движка.
2. **«Дом чата» и «движок действий» — это разные поверхности (split-brain).** Красивый дом с историей = chat-v2 = только Q&A. Движок с действиями = concierge = поповер без дома. Ни одна поверхность не даёт всё сразу.
3. **У владельца нет двери в дом из меню.** «Спросить» спрятан за `roles:["manager"]`; «Память» — дверь к реестрам, не чат. Остаётся только FAB → поповер без истории.
4. **«Режимы» не унифицированы.** «Общий разбор / по клонам» в FAB — это вкладки `company/clones`; в `/chat` режим выражен скоупом диалога («Вся компания / Карточка»). Это две разные механики, не сведённые в один переключатель; у каждого «режима» история живёт (если живёт) в своём движке.

## 4. Разрывы сверх существующего ТЗ (новое из этого прохода)

ТЗ `chat-surface-convergence` их не фиксирует — добавить:

- **Р1. Владельцу недоступен вход в меню.** Пункт «Спросить»/«Мастер» в `nav-config` нужно показать лидерским ролям (сейчас только manager). Иначе «дом чата» после консолидации владелец всё равно не откроет из навигации.
- **Р2. Названия диалогов не генерируются.** В списке `/chat` все 8 диалогов называются «Новый диалог» (отличаются только скоупом и датой) — историю нельзя различить, она бесполезна. `summary` персистится cron'ом, но заголовок списка не выводится из содержимого. Нужна генерация/показ заголовка диалога (из первого сообщения или summary).
- **Р3. «Память» как дверь в чат не реализована.** `/memory` — это сетка ссылок на реестры; обещанного «Спросите у Мастера» там нет (текст есть, чата/двери нет). Если «Память» должна открывать новый диалог Мастера (по Ф5 арх-ТЗ) — это тоже не сделано.

## 5. Что уже готово (не переделывать)

- Бэкенд «единый мозг»: `concierge.process` single-pass; `chatV2.askEphemeral({history,summary,intent,scope?})` без своей `ChatV2Conversation`; clarify-петля замкнута; цепочка chat-v2 = 4 вызова. См. [[concierge-agent]] и арх-ТЗ Ф2/Ф3/Ф4/Ф6.
- FAB → чат напрямую, вкладки «Помощник/Клоны», пузырь Поддержки разведён.
- `PendingActionsBell` (единый колокольчик), редиректы `/chat-v2`,`/assistant` → `/chat`.
- API истории диалогов Мастера (`GET /concierge/conversations`) — есть, не подключён к UI.

## 6. Предложение (как / что) — по приоритету

Цель: **одно окно, один движок (concierge/Мастер), история слева, новый диалог, режим = скоуп/собеседник, доступно из FAB и из меню**. Берём готовое ТЗ `chat-surface-convergence` и дополняем разрывами §4.

1. **Дом Мастера на `/chat` (ядро, КФ2 ТЗ).** Сохранить раскладку `ChatV2Client` (левая колонка диалогов + «Новый» + архив/пин + цитаты + временной срез), но **движок ответа заменить на concierge** — чтобы в том же окне работали и ответы, и действия (задача/встреча/undo), и passthrough-цитаты `[BLOCK:id]`. Список диалогов — `conciergeApi.listConversations`.
2. **Scope в Мастере (КФ1, бэк, малая).** Протащить `scope/scopeRefId` через `ProcessInput → askEphemeral` (он уже принимает) — чтобы один движок отвечал и «по всей компании», и «по встрече/задаче/клону».
3. **Унифицировать «режим».** Один переключатель собеседника/скоупа наверху дома: «Помощник компании (общий разбор)» ↔ «Клон роли» ↔ scoped (встреча/задача). У каждого режима свои диалоги в левом списке (скоуп в карточке уже есть). Снять отдельные вкладки FAB и отдельный `AssistantTargetSelect` chat-v2 — свести в один контрол.
4. **Двери (Р1+Р3).** Добавить пункт меню «Мастер/Спросить» лидерским ролям; FAB → открывает тот же дом (или компактный поповер на ТОМ ЖЕ движке + «развернуть в полный чат»); «Память» → новый диалог Мастера.
5. **Названия диалогов (Р2).** Генерировать/показывать заголовок из первого сообщения или summary — иначе история нечитаема.
6. **Scoped-чаты и Cmd+K (КФ3–КФ4).** Чат встречи/задачи/мобайл и палитра — на Мастер со scope. Затем чистка legacy (КФ5).

**Принцип:** не плодить третий движок — `concierge` остаётся единственным лицом, `chat-v2` — внутренний ответчик. Из `ChatV2Client` переносим только UI-фичи (цитаты/asOf/архив/пин/список), не его прямой вызов `chatV2Api.ask`.

## 7. Развилки владельцу (каждая — с рекомендацией)

1. **FAB после консолидации: компактный поповер на движке Мастера + «развернуть», или сразу полный экран?**
   *Рекомендую: поповер на ТОМ ЖЕ движке + ссылка «развернуть в полный чат» → `/chat`.* Почему: быстрый доступ из любой страницы (1 клик до поля) сохраняется, а длинная работа/история — в полном доме; оба используют один движок и один список диалогов.
2. **«Режим» = один переключатель (Помощник / Клон / по встрече-задаче) или оставить вкладки?**
   *Рекомендую: один переключатель собеседника+скоупа наверху дома.* Почему: совпадает с твоей картиной «общий разбор / по клонам, у каждого свои диалоги», и убирает расхождение FAB-вкладки vs chat-v2-скоуп.
3. **Делать консолидацию целиком или поэтапно?**
   *Рекомендую: поэтапно — сперва §6 п.1+4+5 (дом + двери + названия), это сразу даёт владельцу рабочее единое окно; потом scoped/Cmd+K/чистка.* Почему: п.1+4+5 закрывают 80% боли «не работает», а scoped-миграция рискованнее (меняет endpoint встречи/задачи) — её отдельной фазой под визуальную приёмку.
4. **Готовить ТЗ заново или дополнить существующее?**
   *Рекомендую: дополнить `chat-surface-convergence` тремя разрывами §4 (Р1–Р3) и взять в работу.* Почему: ТЗ уже описывает КФ1–КФ5 корректно; не хватает только двери для владельца, названий диалогов и двери из «Памяти».
