> Цель разбора: собрать разрозненную машинерию целей (8 фоновых агентов, бьющих в разное время по UTC) в **один ночной движок по Москве**, залатать дыры (ручные цели, суточная пересборка иерархии, мёртвый каскад), сохранить и укрепить «вектор людей» (отвязать от вычищаемых обещаний), слить два движка движения в один, ужесточить извлечение. **Принцип: оптимизируем и наводим порядок, НЕ удаляем функциональность.**
> Следующий шаг → архитектура (solution-blueprint): plans/architecture/2026-06-29-goals-engine-consolidation.md

# Движок целей: консолидация и оптимизация (анализ под архитектуру)

## 0. Решения владельца (зафиксированы в разговоре 2026-06-29)

1. **Извлечение целей из разговоров — ОСТАВЛЯЕМ**, это ядро ценности («память сама собирает цели из встреч»). Но **ужесточаем промпт** — ловить только настоящие цели компании (большие и маленькие-ступеньки: «10 платящих клиентов», «50 кастдев-встреч»), а не задачи/болтовню.
2. **«Назвал цель словами → ночь её подхватывает и ведёт»** — ХОТИМ. Сейчас этого нет для ручных целей (дыра §3.3). Достраиваем.
3. **Суточная пересборка иерархии** — ХОТИМ. Кубик (арбитр) есть, как суточный агент не запущен (§3.4). Запускаем.
4. **Каскад статуса по дереву** — ПОДКЛЮЧАЕМ (сейчас мёртвый код, §3.5). Не удаляем — оживляем.
5. **Два числа «движемся к цели» → СЛИВАЕМ в одно** (§3.1). Смысл сохраняем, дубль убираем.
6. **«Вектор людей» (кто двигает к цели / кто мимо) — ОСТАВЛЯЕМ** (дифференциатор). Но **отвязываем от статусов обещаний** (их вычищает [[2026-06-29-commitment-task-unification]]) → кормим из закрытых задач + идей + работы по цели (§3.6).
7. **Получасовые линкеры → раз за ночь** в общей цепочке (§3.7).
8. **Три оси статуса цели — оставляем внутри, показываем одну** (§3.8).
9. **Всё время → `Europe/Moscow`, единая ночная цепочка**, заканчивающаяся ДО сборки дашборда в 06:00 МСК (чинит баг компаса §3.7).
10. **Крутилки из кода → AdminSetting** (§3.9).

**Что НЕ входит (вынесено):** единая схема ingest для 3 боковых дверец создания блоков (§4) — владелец решает отдельно; сама чистка обещаний — [[2026-06-29-commitment-task-unification]]; конвейер AI-отчёта встречи — другой продукт.

---

## 1. Принцип: оптимизируем, не удаляем

Машинерия целей переусложнена **для стадии** (~4 пользователя, прод почти пуст — [[project_prod-scale-early]]), но почти всё несёт смысл. «Упрощение» здесь = **консолидация** (8 агентов в один порядок), **дедупликация** (2 alignment → 1), **залатывание дыр** (ручные цели, иерархия, каскад) и **развязка терминов** («обещание» в двух смыслах). Удаляем только дубли и мёртвое; функции-фичи сохраняем.

## 3. Корень боли (по коду)

### 3.1. Два разных числа «движемся к цели»
- **По графу знаний** (LLM-ревизор, `StrategicAlignmentWorker`) → `cachedAlignment` + `GoalAlignmentSnapshot` → **компас директора и дневной/недельный/месячный**.
- **По задачам трекера** (счётный, `StrategicAlignmentIssuesService`) → Redis 26ч → `GET /goals/:id/alignment-snapshot`.
- Два класса с именем `StrategicAlignmentCron` (KC `0 4 * * *` vs goals `0 6 * * *`) — путаются. → **слить смысл в одно число.**

### 3.2. Два «вектора цели»
- Движение **цели** (`cachedAlignment`, для компаса) ≠ вклад **людей** (`PersonGoalContribution`, экран исполнения). Называются одинаково, питают разные экраны. → **развести по имени, оба оставить.**

### 3.3. ⚠️ Дыра: ручные цели «словами» не ведутся
- Привязчик тем берёт **только** `source: 'ai'` + непустые `sourceBlockIds` ([goal-theme-linker.cron.ts:64-66](../../backend/src/modules/knowledge-core/workers/goal-theme-linker.cron.ts#L64)).
- Агент движения **пропускает цель без тем** (`reason: 'no_themes'`, [strategic-alignment.worker.ts:151](../../backend/src/modules/knowledge-core/workers/strategic-alignment.worker.ts#L151)).
- Ручное создание цели ставит в очередь **только embed** ([goals.service.ts:202](../../backend/src/modules/goals/services/goals.service.ts#L202)) — ни тем, ни иерархии, ни alignment.
- **Итог:** владелец называет главную цель «10 платящих клиентов» → у неё нет тем → **компас её не видит**. Фичи «проговорил → ночь подхватила» по факту нет. → **достроить: ночь обходится с ручными целями как с AI.**

### 3.4. Нет суточной пересборки иерархии
- Арбитр `goal-hierarchy-link` вызывается **только** при рождении AI-цели и по кнопке `suggest-parent` ([goals.controller.ts:154](../../backend/src/modules/goals/goals.controller.ts#L154)). Крона «взять весь список целей + дерево → пересобрать» нет. → **запустить как ночной проход.**

### 3.5. Мёртвый каскад статуса
- `GoalCascadeService` (все подцели достигнуты → родитель achieved; родитель заброшен → дети `cascadeMissed`) зарегистрирован, но **нигде не вызывается** (только в `.spec.ts`). Поле `cascadeMissedCount` уже выводится в дашборде операций. → **подключить.**

### 3.6. ⚠️ Вектор людей завязан на вычищаемые обещания
- `GoalVectorTrackerCron` собирает артефакты: идеи + **сдержанные/сорванные обещания** (`commitment_kept`/`commitment_broken`) + закрытые задачи. Чистка обещаний ([[2026-06-29-commitment-task-unification]]) дропает `commitmentStatus` → артефакты обещаний **высохнут**, вектор начнёт отдавать нули. → **перекормить из задач + идей + работы по цели**, без статусов обещаний.

### 3.7. Расписание в UTC вразнобой + баг компаса
- Движение цели пересчитывается в **07:00 МСК** (`0 4 * * *` UTC), а дашборд+компас собираются в **06:00 МСК** — **на час раньше**. Компас утром показывает вчерашнее; ночные разговоры доезжают только в 07:00. → **единая цепочка по МСК, движение считается ДО сборки.**
- Линкеры каждые 30 мин для ~10 целей избыточны → **раз за ночь.**

### 3.8. Три оси статуса у одной цели
- `status` (active/paused/achieved/abandoned) + `promotionState` (suggested/active/dismissed) + `progressStatus` (on_track/at_risk/stalled/achieved/dropped). Глазами не различить. → **внутри оставить, пользователю — один вердикт** (механизм `movementVerdict` уже есть в `domain/goal.ts`).

### 3.9. Крутилки в коде (нарушение принципа 9)
- Захардкожены: окна тренда, пороги риска/алерта, TTL, KNN top-k, лимиты линкеров, часы кронов, пороги «вектора людей» и `goal-alignment-low` (`PERIOD_DAYS=14`, `MIN_ISSUES=5`, `LOW_RATIO=0.8`). Крутилками сделаны только пороги пульса и пара рубильников. → **вынести в AdminSetting через getDynamic.**

### 3.10. Извлечение — широкий промпт
- `goal-extract` ловит «цель vs задача» широко. → **поднять планку:** цель = результат уровня компании («было→стало»), маленькие цели-ступеньки допускаются, мусор/задачи — нет.

## 4. Хаб ingest — для целей единая схема УЖЕ работает

`RawEvent` — общий хаб ([ingest.service.ts:132](../../backend/src/modules/ingest/ingest.service.ts#L132)). Единственный нарезщик `block-ingest.worker` обрабатывает **все** типы одной схемой: `meeting`, `meeting_report`, `chat`, `chatbox`, `bitrix`, `document` ([block-ingest.worker.ts:85-91](../../backend/src/modules/knowledge-core/workers/block-ingest.worker.ts#L85)). Агент целей сидит на выходе нарезщика → **источник уже не важен.**

**Исключения (вынесено, владелец решает):** блоки в обход нарезщика создают 3 места — `operations/services/commitment-response.handler.ts`, `messaging/services/poll.service.ts`, `support/services/support-contour.service.ts`. Если «всё строго одной схемой» — сводить к нарезщику надо именно их (встречи/чаты уже сведены).

## 6. Единая ночная цепочка (целевая, МСК)

```
00:00 МСК  забор чатов/Битрикса (единый, см. sync-bitrix-chatbox-same-time)
00:00–04   нарезщик: разметка + дозревание блоков (block-ingest)
   ↓       Specialist 3-14-goals: родились/обновились цели (строгий промпт O1)
   ↓       embed целей (для KNN/дедупа)
   ↓       пересборка иерархии по всему списку (O3) + каскад статусов (O4)
   ↓       привязка тем/задач — ВКЛЮЧАЯ ручные цели (O2)
   ↓       прогресс KR + статус цели
   ↓       ОДНО число движения → cachedAlignment (O5) — компас
   ↓       вклад людей: на задачах/идеях (O6)
05:00–06   сборка дневного отчёта + компас на СВЕЖИХ данных (O10)
06:00      дашборд показывает сегодняшнюю ночь, не вчера
```

Недельные (пульс, alignment-low) — отдельным проходом, тоже МСК, по понедельникам.

## 7. Границы scope (что НЕ делаем здесь)
- **Не трогаем** саму чистку обещаний — [[2026-06-29-commitment-task-unification]] (но учитываем её эффект на вектор людей, O6).
- **Не решаем** единую схему ingest для 3 боковых дверец (§4) — владелец решает отдельно.
- **Не трогаем** конвейер AI-отчёта встречи (транскрибация/диаризация/отчёт) — другой продукт.
- **Не вводим** новых экранов целей — карта/дерево/деталь остаются; меняется откуда и когда в них попадают данные.
