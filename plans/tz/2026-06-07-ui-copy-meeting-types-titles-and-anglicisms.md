# ТЗ — Копирайт/UX полировка: русские типы встреч, `<title>` «— Кора», убрать англицизмы «AI», дубль чата

> **Приоритет: 🟡 P3** (полировка; не ломает функционал, но нарушает правило «UI Коры — только русский» [[feedback_admin_ui_russian_only]] и брендинг). Вскрыто ретестами №1 и №2 ([plans/analysis/2026-06-07-retest2-RESULTS-technical.md](../analysis/2026-06-07-retest2-RESULTS-technical.md) §8).
> **Тип:** copy/UX-фикс (frontend). **Одна функция:** убрать английские слова из пользовательского UI + единый суффикс заголовка вкладки.

## 1. Находки и корни (все подтверждены кодом)

### 1.1 Тип встречи отображается по-английски — ДВА дублирующих маппинга
- [MeetingsJournalReal.tsx:81-91](../../frontend/src/ui/components/meetings-journal/MeetingsJournalReal.tsx#L81) — список встреч;
- [MeetingResultPageReal.tsx:124](../../frontend/src/ui/components/meeting-result-v2/MeetingResultPageReal.tsx#L124) — страница результата (бейдж + хлебные крошки).

Оба содержат английские значения: `team: 'Team sync'`, `standup: 'Standup'`, `sales: 'Sales'`, `custdev: 'Custdev'`, `customer_success: 'Customer Success'`. На проде у владельца встречи типа `team` подписаны «Team sync».

### 1.2 `<title>` без суффикса «— Кора» на части страниц
Корневой layout [layout.tsx:13](../../frontend/app/layout.tsx#L13) задаёт `title: 'Кора — память компании'` **строкой**, без `title.template`. Поэтому страницы, экспортирующие свой `metadata.title` (или ставящие `document.title`), получают «голый» заголовок: «Цели», «Идеи», «Решения», «Сущности», «AI-темы», «Карточки». А страницы с явным полным заголовком («Таблицы — Кора», «Настройки — Кора») — несогласованны по стилю.

### 1.3 Англицизм «AI» в пользовательском тексте
- [IntakeClient.tsx:296](../../frontend/app/(authenticated)/intake/IntakeClient.tsx#L296): «…внешних сервисов. **AI** заранее заполнил подсказки…»;
- заголовок страницы тем — «**AI**-темы» (`/themes`), текст «Темы — это кластеры идей, которые **AI** собрал»;
- `/goals`: «**AI** оценивает движение компании».

### 1.4 Дубль чата `/chat` ↔ `/chat-v2` (S3-02b) — РАЗВИЛКА P-1 РЕШЕНА
[ChatClient.tsx:45](../../frontend/app/(authenticated)/chat/ChatClient.tsx#L45) — баннер «Доступна новая версия чата… Попробовать» на `/chat`, при этом живёт и `/chat-v2`. Два «помощника» путают. Плюс «чата—» без пробела перед тире.

**Анализ (проведён 2026-06-07, код + живая прод-проверка):**
- `/chat` ([ChatClient.tsx](../../frontend/app/(authenticated)/chat/ChatClient.tsx)) — тонкая обёртка над `<OrgChatPanel withHistory>`: одна панель Q&A. Бэкенд — legacy `/chat`-контроллер, делегирующий в ChatV2 при `CHAT_V2_ENABLED` (дефолт **OFF**). `ChatModule` помечен `@deprecated` ([app.module.ts:429](../../backend/src/app.module.ts#L429)).
- `/chat-v2` ([ChatV2Client.tsx](../../frontend/app/(authenticated)/chat-v2/ChatV2Client.tsx) + `ChatV2Module`) — **строго функциональнее**: постоянная история диалогов (список active/архив), закрепление, архивация, цитаты с таймкодами, temporal-запрос «на момент», индикатор кэша, режимы (Синтез).
- **Живая проверка на проде** (аккаунт владельца): `/chat-v2` корректно ответил на «Что обсуждали на последней встрече?» — про встречу «111», 4 задачи, блок «Источники», создал постоянный диалог. **Production-ready.**

| Критерий | `/chat` (OrgChatPanel) | `/chat-v2` (ChatV2) |
|---|---|---|
| Постоянная история диалогов | ❌ (одна сессия) | ✅ список + архив |
| Закрепление/архив | ❌ | ✅ |
| Цитаты с таймкодами | частично | ✅ |
| Temporal «на момент» | ❌ | ✅ |
| Статус бэкенда | legacy `@deprecated` | целевой `ChatV2Module` |
| URL пользователю | чистый `/chat` | «грязный» `/chat-v2` (версия в URL) |

**РЕШЕНИЕ (decisive): канонический чат — ChatV2, но под чистым URL `/chat` и именем «Помощник компании».** Не «redirect /chat→/chat-v2» (это навсегда светит уродливый `/chat-v2` пользователю) и не «оставить простой /chat» (потеря истории/цитат — это и есть продуктовое направление). Лучшее — **продвинуть ChatV2 на место `/chat`**.

**Доп. находки ChatV2 из живой пробы (включить в фикс):**
- (a) в текст ответа протекают сырые маркеры `[BLOCK:cmq3kg…]` — рендерить как чистые ссылки/убирать из текста (есть отдельный блок «Источники»);
- (b) плавающий FAB «Помощник компании» (concierge, `bottom-6 right-6 z-40`) **перекрывает кнопку отправки** ChatV2 — поправить layout/z-index, когда ChatV2 станет `/chat`;
- (c) англицизмы «AI печатает ответ…», «Спросите AI о памяти компании…», «AI ответит» в ChatV2 — под Фазу 3 (убрать «AI»).
- (d) наблюдение: имя «Помощник компании» носят ТРИ сущности — пункт навигации (/chat), заголовок страницы и FAB-concierge (Срочное/Сигналы/Вопросы/Спросить). Развести нейминг — отдельный продуктовый вопрос (вне P-1).

## 2. Решение

### Фаза 1 — Единый русский справочник типов встреч 🟡
Вынести **один** общий справочник (напр. `frontend/src/domain/meeting.ts` → `MEETING_TYPE_LABEL_RU: Record<MeetingType, string>`), удалить оба локальных дубля, и подключить его в `MeetingsJournalReal` и `MeetingResultPageReal`. Русские подписи (рекомендация — владелец может уточнить формулировки):

| type | было | стало (рекоменд.) |
|---|---|---|
| `team` | Team sync | **Командная** |
| `standup` | Standup | **Планёрка** |
| `plan_fact` | План-факт | План-факт |
| `project` | Проект | Проект |
| `sales` | Sales | **Продажи** |
| `custdev` | Custdev | **Кастдев** (исследование клиента) |
| `partner` | Партнёр | Партнёр |
| `interview` | Интервью | Интервью *(или «Собеседование» — по смыслу типа)* |
| `customer_success` | Customer Success | **Работа с клиентом** |

> Сверить полный список значений `MeetingType` в `domain/*` (если есть `demo`/`one_on_one`/`retro` — дать им русские подписи тоже). Источник истины терминов — глоссарий проекта, если существует; иначе закрепить эти.

### Фаза 2 — Шаблон заголовка вкладки 🟡
В [layout.tsx](../../frontend/app/layout.tsx) перевести `metadata.title` на объект-шаблон:
```ts
title: {
  default: 'Кора — память компании',
  template: '%s — Кора',
},
```
Тогда дочерние страницы с `export const metadata = { title: 'Цели' }` автоматически дают «Цели — Кора». Затем:
- страницы, что сейчас ставят полный «X — Кора» вручную, упростить до `title: 'X'` (иначе выйдет «X — Кора — Кора»);
- клиентские страницы, ставящие `document.title` вручную, перевести на серверный `metadata`/`generateMetadata` либо привести к единому суффиксу.

Минимально-достаточно: добавить `template` + пройтись по страницам из §1.2, выровняв их `title`.

### Фаза 3 — Убрать «AI» из текста 🟡
- IntakeClient: «**Кора** заранее заполнила подсказки» (бренд как актор; «AI» убрать);
- `/themes`: «**AI**-темы» → «**Темы**» (или «Темы Коры»); «…которые **Кора** собрала из встреч»;
- `/goals`: «**Кора** оценивает движение компании».
> Правило: в пользовательском UI вместо «AI» — либо «Кора» (где это действующее лицо), либо «ИИ» (где нужен нейтральный термин). [[feedback_admin_ui_russian_only]].

### Фаза 4 — Консолидация чата: продвинуть ChatV2 на `/chat` 🟡 (P-1 РЕШЕНА, см. §1.4)
Канонический — ChatV2 под чистым URL `/chat`. Шаги:
1. **`/chat/page.tsx`** → рендерить `<ChatV2Client>` внутри существующего `<TierGate feature="feature.chat_org">` (вместо обёртки над OrgChatPanel). Заголовок/имя — «Помощник компании» (ChatV2Client уже даёт его по умолчанию).
2. **`/chat-v2/page.tsx`** → постоянный redirect на `/chat`, **сохраняя query** (`?conversationId=` deep-link'и из CommandPalette должны продолжать работать).
3. **Убрать баннер** «Доступна новая версия чата» ([ChatClient.tsx:39-59](../../frontend/app/(authenticated)/chat/ChatClient.tsx#L39)). Старый `ChatClient` можно удалить (если больше нигде не используется — проверить грепом).
4. **`<OrgChatPanel>` НЕ удалять** — он переиспользуется в `/dashboard` (директорский ad-hoc Q&A, `withHistory={false}`). Остаётся как есть.
5. Поправить находки §1.4 (a) `[BLOCK:id]`-маркеры в тексте ответа, (b) перекрытие кнопки отправки плавающим FAB, (c) англицизмы «AI» (Фаза 3).
6. Навигация: пункт «Помощник компании» уже ведёт на `/chat` — менять не нужно.

> Backend legacy `ChatModule` (`@deprecated`) пока не трогаем — он ещё обслуживает OrgChatPanel в дашборде. Его вывод/миграция OrgChatPanel на `chatV2Api` — отдельная задача (вне этого копирайт-ТЗ).

### Фаза 5 — Прочие копирайт-миноры (перенос из ретеста №1, low-prio) 🟡
В рамках того же прохода по русскому UI:
- `/intake`: плюрализация «**2 меток**» → «2 метки» (правильное склонение), «**email**-рассылок» → «рассылок по почте»/«почтовых рассылок» (локализовать грепом по `frontend/app/(authenticated)/intake` и общим `pluralRu`-хелперам).
- При проходе по «AI» (Фаза 3) — заодно вычесать прочие латинские термины в пользовательских строках, если встретятся.

> Эти пункты вживую в ретесте №2 не перепроверялись (наблюдались в ретесте №1) — локализовать перед правкой. boot-401 `/accounts/me` в консоли (S0-07) — НЕ копирайт, отдельная косметика (см. реестр «не-сделано»), в это ТЗ не входит.

## 3. Acceptance-сигнал

1. На `/meetings` и `/meetings/<id>/result` тип встречи — по-русски («Командная» вместо «Team sync»); ни одного английского `Team sync`/`Standup`/`Sales`/`Custdev`/`Customer Success` в UI.
2. `<title>` всех разделов оканчивается «— Кора» (Цели — Кора, Идеи — Кора, …), без двойного суффикса.
3. Греп по `frontend/app` + `frontend/src/ui` на « AI »/«AI-» в пользовательских строках — ноль (кроме кода/комментариев/тех. идентификаторов).
4. Один помощник в навигации; баннера-дубля чата нет.

---

## 4. Объём / риски / прод

- **Низкий**, чисто frontend-копирайт + один шаблон метаданных. Дублирующий справочник типов — консолидация (минус код).
- Риск: Фаза 2 может дать двойной суффикс на страницах с ручным «— Кора» — закрывается проходом по списку §1.2.
- **Прод-операций нет** (пересборка фронта). Фаза 4 (A) требует решения владельца по P-1.
