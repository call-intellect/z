# Онбординг: вторичные баги + проверка письма и восстановления пароля

После основного фикса demo-org (`40ce79bd`, выкачен на прод и подтверждён живьём) владелец попросил: устранить вторичные баги онбординга, проверить домен в письме регистрации (приходит `meet.crossmark.ru`, нужен `korateam.ru`) и проверить восстановление пароля.

## Письмо регистрации — домен уже правильный
- Все ссылки писем (логин/инвайт/сброс) строятся из `cfg.auth.publicFrontendUrl` = ENV `PUBLIC_FRONTEND_URL`; шаблоны (`mail.templates.ts`) — из кода, без хардкода домена; шаблоны НЕ из БД.
- В проде `PUBLIC_FRONTEND_URL=https://korateam.ru` (и running-контейнер, и `.env:50`). Присланное письмо — для `chydo_002@mail.ru`, регистрация **2026-06-04**, за 5 дней до переезда домена (09.06). Письмо старое — править нечего.
- Стейл-остаток: `MAIL_FROM_NAME="Meet Crossmark"` (прод-`.env`, дефолт в схеме = `Кора`). На ссылку не влияет; смена — отдельная ENV-правка по решению владельца.

## Восстановление пароля — работает
`/forgot-password` → `POST /accounts/password/forgot` 200 (неперечисляющий ответ), `UserVerificationToken{purpose=password_reset}` создан (TTL 60 мин), `/reset-password` рендерит форму нового пароля, `resetUrl=${publicFrontendUrl}/reset-password?token=...` = korateam.ru. Проверено Playwright + read-only SQL.

## Вторичные баги — 4 фикса (`6d2877b5`)
- **(б)** `WizardShell.tsx`: убраны залипающие `guardChecked`/`redirecting` (при `currentOrgRole=null` или незавершённом redirect — вечный Skeleton). Рендер выводится прямо из текущих значений (`!ready||!owner → Skeleton`, `owner → wizard`).
- **(а)** `auth-context.tsx`: `refresh()` теперь возвращает `AccountUser | null`. `welcome/step-6` подтверждает `profileCompletedAt` (с одним ретраем против лага /me) и навигирует `router.replace` — без петли «назад» на step-1.
- **(в)** новый `GET /orgs/:orgId/welcome` (`getWelcome`) + префилл мультивыбора шагов 4/5/6 из сохранённого (только если есть данные и юзер ещё не тыкал). Раньше «Назад» показывал пустые галочки → «Далее» затирал сохранённое пустым (data-loss на шагах 5/6 без min-выбора).
- **(г)** `completeWelcome`: 400 `cannot_complete_on_demo_org` при попытке завершить на референс-демо-орге (defense поверх getMe-фикса); warn-лог вместо тихого пропуска документа «Знакомство», когда у пользователя нет Person в своей Org.

## Чему научился
- **Жалоба «письмо с неправильным доменом» ≠ всегда баг кода.** Сначала проверь дату артефакта vs дату изменения конфига: тут письмо предшествовало переезду домена. Цепочка «шаблон-из-кода → плейсхолдер → ENV → значение в проде» доказывается без догадок.
- **Регидрация форм онбординга — не косметика, а защита от data-loss:** шаги без min-выбора (5/6) при «Назад»+«Далее» затирали сохранённое пустым. Префилл с `prev.size===0 ? saved : prev` не затирает ни клики юзера, ни данные пустым.
- **Гард-флаги в React-shell (`guardChecked`/`redirecting`) — источник вечного Skeleton.** Надёжнее выводить рендер прямо из текущих значений (`ready`/`isOwner`), без латч-стейта, который некому сбросить.
