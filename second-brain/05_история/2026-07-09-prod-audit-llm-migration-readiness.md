# Прод-аудит: готовность к DB-driven LLM + фиксы деплоя

## Что было поставлено

Владелец: (1) подключиться к проду по SSH, снять модели/цепочки/логи и понять, не сломает ли прод предстоящий мерж ChatBox→dev; (2) разобраться, почему migrate-контейнер применяет скрипты до 1400 секунд, хотя есть механизм run-once; (3) подготовить заполнение БД (провайдеры/типы/модели/цепочки) и проверку LLM-функционала после обновления. Плюс до этого: UI создания провайдера «одним окном» (discovery до сохранения + цены на месте).

## Как решал

SSH: root по паролю закрыт, вход `user@46.8.196.29` + `su - root`; многослойные кавычки убил base64-обёрткой (`echo <b64> | base64 -d | bash`). Прод: `/home/docker/z`, dev@352e3a88.

**Находки прод-аудита:**
1. **Прод сломан уже сейчас**: колонки БД vector(768), а код dev пишет `::vector(1536)` → 12 ошибок/сутки, 661 IdeaBlock за 3 дня без эмбеддинга, Entity 0/8913. Свип из ChatBox это чинит.
2. **Мигра 768 не записана в `_prisma_migrations`** (колонки меняли скриптом) → `migrate deploy` при мерже выполнил бы её повторно и стёр частичный backfill. Фикс: `ensureEmbeddings768Resolved` в apply-prod-deploy — авто `resolve --applied`, если колонки уже 768 (`59e80c56`).
3. **1400s деплоя = 2×600s вечных таймаута**: backfill-embeddings в schema-фазе гонялся безусловно мимо журнала и никогда не успевал; backfill-rule-summaries падал об баг фолбэка (модель primary уезжает в KIE — 5083 фейла/3д). Фикс: гейт `embedBackfillFitsDeploy` (COUNT пустых эмбеддингов; хвост > `DEPLOY_EMBED_BACKFILL_MAX_ROWS`=500 → громкий скип с командой ручного прогона) + rule-summaries снят из STEPS до фикса фолбэка (`eb6bc5b9`). Сам журнал (`_deploy_applied_step`, Postgres, не Redis) работал исправно — 152/239 скипов.
4. **Главный риск мержа** (дифф-агент по origin/dev↔ChatBox): боевой трафик прода ходит legacy ENV-путём диспатча, который `1748fe82` удаляет. После мержа ключ берётся только из `llm_providers.apiKeyEncrypted` — а он на проде пуст у ВСЕХ. Умирают deepseek (primary ~180 маршрутов; адаптер openai-chat жёстко требует ключ), grsai (override-ветка без ENV-фолбэка), ollama (адаптер не читает cfg-ключ). kie/minimax/anthropic/openai-via-proxy выживают на ENV-фолбэках своих сервисов. Smoke-крон прода (ходит адаптерным путём) уже показывал ровно эту картину — живой предпросмотр пост-мержевого мира.
5. Фикс риска: `patch-llm-provider-keys-from-env.ts` (everyDeploy, идемпотентен, только пустые ключи; openai-via-proxy пропущен — составной `PREFIX:KEY`) + чек-лист проверки LLM после выката в prod-deploy-log (`a918a439`). Маршруты/модели/цены прода уже в БД, сиды их не затирают (провайдеры/цены — create-if-missing; сид маршрутов не менялся → скип по хэшу журнала).

**UI-часть** (`a0f1bc89`): эндпоинт `POST /admin/llm-providers/models/discover-preview` (discovery по сырым baseUrl/key БЕЗ сохранения = заодно проверка токена) + форма создания: кнопка «Получить список доступных моделей» → чекбокс-таблица с ценами ($/1M вход/выход) → селект дефолтной модели → «Сохранить» создаёт провайдера+модели+прайс одной операцией. Проверено Playwright'ом на mock-`/v1/models` и живым discovery llm-kora-team (4 модели).

## Что вышло

- 5 коммитов запушено: `a0f1bc89` (UI), `258ae8bd` (docs), `59e80c56` (гард 768), `eb6bc5b9` (деплой 23мин→минуты), `a918a439` (перенос ключей + чек-лист).
- Прод-инструкция в prod-deploy-log: Pre-flight (гард — авто; ручной backfill), новый Шаг 7 (перенос ключей — авто), Шаг 12 (чек-лист LLM-проверки).
- Дифф-верификация: typecheck обеих сторон, спеки провайдер-сервиса 32/32, деплой-скрипт dry-run.
- Фоновая переобработка ChatBox на dev продолжается: ~200/563, 1380+ блоков, все с эмбеддингами.

## Чему научился

1. **Smoke-канал может ходить другим кодовым путём, чем боевой трафик** — на проде это дало «парадокс» (smoke красный, трафик зелёный), который оказался точным предсказателем пост-мержевых поломок. Такой рассинхрон — не баг, а бесплатный канареечный сигнал; читать его надо как «что будет после унификации путей».
2. **Периодические 600s-шаги деплоя, которые «никогда не успевают», не видны в саммари как проблема** — шаг «падает» кодом 124, деплой выходит 0 (`--no-fail-on-steps`), и полчаса деплоя нормализуются. Смотреть надо на длительность контейнера и `ТАЙМАУТ` в логе, не на exit-код.
3. **Миграция схемы, применённая «скриптом до миграции», обязана быть немедленно `resolve --applied`** — иначе она мина замедленного действия для любой следующей ветки. Теперь гард делает это hands-free.
4. Кавычки через ssh+su+sh не экранируются — только base64-конверт.

## Хвосты

Реестр не-сделанного пополнен: ручной прогон backfill на проде (Entity 0/8913), баг фолбэка «модель primary уезжает в KIE» (+возврат rule-summaries в STEPS после фикса), перепроверка deepseek-строки после выката, 429-квота openai-via-proxy на грани.
