## S0 — Онбординг и первый вход ✅ пройден

**Что проверено:** вход по временному паролю → стартовый экран новичка → меню профиля → форма смены пароля (валидация + happy-path) → logout → повторный вход новым паролем.

**Результат верификации happy-path:** `POST /api/v1/accounts/me/change-password → 200`; повторный вход новым паролем успешен; logout редиректит на `/login?next=…` и возвращает по назначению. Пароль аккаунта изменён на новый (см. примечание владельцу ниже).

## S1 — Навигация и каркас (в процессе)

### 🔴 Главная находка — сломаны детальные страницы (класс-баг Next.js 16)

```
[S1-01] 🔴 CRIT · 22 динамические страницы · Техника (подтверждает T7 тестировщика)
Что: открытие любой таблицы (и ещё 21 типа детальных страниц) падает — API зовётся с id=undefined.
Воспроизведение: /tables → открыть ЛЮБУЮ таблицу (даже системную «Команда»).
Доказательство (Network + Console):
  GET /api/v1/tables/undefined            → 404
  GET /api/v1/tables/undefined/properties → 404
  GET /api/v1/tables/undefined/rows?...   → 404
  Экран — пустой/«Что-то пошло не так, таблица не найдена» (скриншот тестировщика).
Корень (ВЕРИФИЦИРОВАН эмпирически на 2 разных семействах страниц): frontend на Next.js ^16.2.6,
  где `params` — асинхронный (Promise). Страницы читают `params.id` СИНХРОННО (сигнатура `params: { id: string }`),
  поэтому `params.id === undefined` → дальше прокидывается undefined.
  Корректный паттерн Next 15/16: `params: Promise<{id:string}>` + `await params` (server) или `use(params)` (client).
  ВАЖНО — симптомы РАЗНЫЕ (поэтому часть «выглядит рабочей»):
    • tables/[id]: id уходит в URL API → GET /tables/undefined → 404 → «Таблица не найдена» + ошибки в консоли (заметно).
    • structure/persons/[id]: клиент грузит весь ростер и ищет локально find(personId===undefined) → «Сотрудник не найден»
      БЕЗ сетевой ошибки и БЕЗ /undefined в Network (тихий провал — легко принять за «пусто»).
  Проверка: прямой SSR-переход на /structure/persons/<реальный id владельца> → «Сотрудник не найден», хотя он существует.
  Вывод: «тихие» страницы из списка ниже тоже сломаны, просто не кричат в консоль.
Масштаб (класс): 22 страницы с тем же сломанным синхронным паттерном `params: { ... }`:
  tables/[id], documents/[id], issues/[id], experiments/[id], orchestrator/runs/[id],
  sprints/[id], sprints/[id]/review, team-templates/[slug],
  roles/[id] (+ /map /clone /clone/history /skill-profile),
  structure/persons/[id], persons/[id]/(knowledge-profile|social-contribution|contributions|skill-profile),
  admin/economics/orgs/[id], admin/prompts/[id], admin/ai-models/[taskType], admin/ai/routing/[taskType].
  (Остальные ~40 динамических роутов уже мигрированы на async-params и работают — частичная миграция, эти 22 пропустили.)
Фикс (механический, одинаковый на все 22): сделать params Promise и читать через await/use(params).
Рекомендация: 🔴 чинить классом немедленно — это видимая в проде поломка целых разделов.
```

[S1-06] 🟠 High · весь кабинет (баннер демо-режима) · Техника (уточняет S0-06, связан с T4)

## S2 — Команда / должности / приглашения

```

Воспроизведение: Команда → «Пригласить» → ввести имя → «Отправить приглашение».
Доказательство: POST /api/v1/orgs/<tenant>/invitations → 403 Forbidden. Диалог остаётся на форме.
UX-усугубление: НИКАКОГО сообщения об ошибке (тоста нет) — для пользователя «кнопка не работает молча».
Важно: это НЕ блокетный read-only демо-режима — /dump (создание) только что прошёл 201. Значит инвайты
       гейтятся отдельно — почти наверняка из-за subscription.status=DEMO (см. S1-11), т.е. бонусный тариф
       (tier_standard в entitlements) не снял ограничение на приглашения.
Бизнес-эффект: невозможно набрать команду → продукт «память компании» бесполезен в одиночку. Поднимает S1-11 до CRIT.
Рекомендация: (1) чинить источник статуса оплаты (S1-11); (2) показывать понятную ошибку при 403, а не молча.

```

Тестировщик прямо спросил «что за бот?». Пользователь не понимает назначение Telegram-бота (уведомления? вопросы Коры?).
Рекомендация: одной фразой пояснить роль бота («через бот сотрудник получает напоминания и отвечает на вопросы Коры»).
