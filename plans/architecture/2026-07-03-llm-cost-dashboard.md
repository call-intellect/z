# Архитектура «Расход на LLM — единый дашборд» (человеческим языком)

## 1. Что это и зачем

Сегодня, чтобы понять «сколько мы тратим на AI и на что», нужно открыть до шести разных экранов админки — и на каждом будет своя цифра, своя валюта, свой период расчёта. Один и тот же вопрос «а сколько тратит вот эта компания» на разных экранах может дать разные ответы, потому что каждый экран считает по-своему.

Страдает владелец и любой суперадмин платформы, когда пытается ответить на простой вопрос: «расход вырос — с чего вдруг?» или «какая компания или какая модель тянет больше всего денег?». Сегодня на это нет ни одного экрана с графиком по дням — только сухие итоги за выбранный период, без истории. Ровно сегодня же был найден и исправлен баг, из-за которого один из этих экранов завышал рубли — доверие к цифрам и так было подорвано, а разрозненность только усугубляет.

## 2. Как сегодня (от чего отталкиваемся)

Есть восемь адресов в админке, так или иначе связанных с расходом на AI. Пять из них — рабочие, три — заглушки-перенаправления, оставшиеся с прошлой уборки:

**Рабочие экраны, каждый со своей арифметикой:**
1. Общая «Юнит-экономика» — итог за период плюс список топ-10 организаций и топ типов операций. Только сумма, без графика по дням. Это чистая витрина расхода — больше ничего на этом экране не делается.
2. Та же «Юнит-экономика», но для одной конкретной компании — итог плюс топ-5 операций этой компании. **Но не только расход**: на этом же экране — форма настройки бюджет-лимита компании (сумма в рублях на месяц + пороги алертов). Это чужая функция, которую нельзя просто выбросить при переезде.
3. Список компаний — но это на самом деле не витрина расхода, а общий список организаций платформы (тариф, статус подписки, число участников, число встреч), где расход — всего одна колонка из многих, и показана она в **долларах**, а не в рублях, как везде остальные.
4. Список технических операций («функций») с расходом — сам список ничем, кроме расхода, не занят. Но у **отдельной страницы одной операции** внутри этого раздела есть неожиданная вторая функция: свой собственный редактор «какая модель обслуживает эту операцию» — притом что ровно такой же редактор уже есть на экране «Роутинг моделей» (пункт 5 ниже). Это два разных места, редактирующих одну и ту же настройку одним и тем же способом — независимая от денег проблема, найденная попутно.
5. Метрики одной операции внутри экрана настройки моделей «Роутинг моделей» (тот самый, где сегодня чинили курс рубля) — там же рядом настраивается, какая модель обслуживает эту операцию (это и есть канонический редактор из пункта 4), и в этом же месте видна разбивка по «уровню запасного варианта» модели (основная/запасная/резервная) и по успешности вызова — эти два среза больше нигде не показаны.

**Мёртвые пути (код есть, кнопки в интерфейс нет):**
6. Один адрес просто перенаправляет на пункт 1.
7. Ещё один перенаправляет на пункт 4.
8. Третий должен был вести на список «кто из пользователей сколько потратил», но на деле перенаправляет на пункт 3 (список компаний) — а сам экран «по пользователям» и обслуживающий его код за кулисами существуют, но открыть их сегодня невозможно ни с одной живой страницы.

Матрицы «эта компания тратит на эту модель столько-то» нет нигде — если нужно узнать, кто именно гоняет дорогую модель, приходится вручную сопоставлять два разных экрана и надеяться, что цифры совпадут (не факт — у них разная арифметика).

Отдельно есть ночной фоновый процесс, который **уже больше месяца** тихо копит расход по дням — по одной строке на «компания + день + операция + модель». Его результатом сегодня не пользуется ни один экран.

Есть также экран «Экономика моей организации» — но это не про суперадмина: его открывает сам владелец конкретной компании и видит только свою трату. Это другая аудитория с другими правами доступа, к разбираемой ниже путанице отношения не имеет.

## 3. Что делаем (решение простыми словами)

Строим один новый экран «Расход на LLM» с понятной лестницей из пяти ступенек: **общий итог → по модели → по смысловому разделу → по компании → по компании и модели вместе**. На каждой ступеньке — не только сумма за период, но и график по дням (можно переключить на график по неделям), чтобы сразу было видно, когда именно случился рост.

Технически это **расширение уже существующего**, а не новая тяжёлая стройка: ночной фоновый процесс, который копит расход по дням, уже год как... то есть уже больше месяца работает без единого читателя — просто впервые подключаем к нему экран. Новых тяжёлых вычислений не заводим.

Из пяти живых экранов только два (пункты 1 и 4 из раздела «Как сегодня» — общая «Юнит-экономика» и список операций) — чистые витрины расхода без другой функции, поэтому они целиком уходят на пенсию и превращаются в вежливое перенаправление на новый экран. Оставшиеся три оказались с секретом: под видом «экрана расхода» там же живёт совсем другая, нужная функция (список организаций с тарифами — пункт 3; настройка бюджет-лимита компании — пункт 2; отдельная страница операции с ещё одним редактором модели — пункт 4-детально). Такие экраны не удаляются и не редиректятся целиком — им делают **точечную операцию**: вырезают только денежную часть (заменяют на ссылку/врезку в новый дашборд), а всё остальное оставляют работать как было. Три уже мёртвых заглушки удаляются насовсем. Экран настройки моделей «Роутинг моделей» (где выбирается, какая модель обслуживает какую операцию) не трогаем как инструмент конфигурации — только его вкладка с метриками начинает брать цифры из общего источника, а не считать сама; заодно это становится единственным местом с таким редактором — второй, дублирующий, из пункта 4 убираем (см. «Границы» и «Решения»).

Все 176 внутренних видов операций впервые получают понятную группировку на 4 смысловых раздела («Память/граф», «Извлечение из разговора», «Агент», «Прочее/служебное») — вместо разрозненных технических имён, которые сегодня ничего не говорят человеку, не писавшему код.

## 4. Как это будет выглядеть

### Сценарии «было → стало»

**Сценарий: понять, откуда вырос расход**
- Было: владелец видит суммарную цифру за месяц выше, чем ожидал → открывает «Юнит-экономику» (только итог, без истории по дням) → открывает список компаний (в долларах!) → открывает список операций (третья страница, третья арифметика) → так и не понимает, в какой день и из-за чего случился скачок, потому что нигде нет графика по дням.
- Стало: заходит на «Расход на LLM» → сразу видит график по дням за месяц → видит день, где случился скачок → кликает на этот день/пик → видит, какая модель и какой раздел его вызвали → проваливается ещё на уровень → видит конкретную компанию и конкретную операцию.

**Сценарий: понять экономику одного клиента**
- Было: два разных экрана («по компаниям» и «юнит-экономика этой компании»), у каждого своё окно расчёта (30 дней ленты против календарного месяца) — цифры не совпадают день в день, и непонятно, какой из двух экранов «более правильный».
- Стало: один и тот же источник данных на любом уровне лестницы — сумма по компании на общем экране и сумма на самой глубокой ступеньке «компания × модель» всегда сходятся.

**Сценарий: настройка модели для операции**
- Было: открывает «Роутинг моделей» → вкладку «Метрики» → видит отдельно посчитанную (только что чинили баг с рублём) сумму, которая нигде больше не встречается.
- Стало: та же вкладка «Метрики» показывает вырезку из общего дашборда за эту операцию — одна арифметика везде, тонкая разбивка по «основная/запасная модель» и по успешности вызова остаётся там же, где была (эта деталь не входит в общую лестницу — см. «Границы»).

### Живой образец

Заходишь на «Расход на LLM»: сверху — «612 340 ₽ за 30 дней, рост на 12% к прошлому периоду». Под цифрой — график, на котором виден заметный скачок 28 июня. Кликаешь на этот день — видишь, что в этот день подскочил расход модели `deepseek-v4` в разделе «Извлечение из разговора». Проваливаешься в этот раздел — видишь, что 65% этой суммы съедает одна-единственная операция: запись фактов из разговора во время встречи. Открываешь тот же день на уровне «по компаниям» — видишь, что скачок совпал с ростом активности у «Молочные реки» (у них в этот день было в 3 раза больше встреч, чем обычно). Картина сходится без единого расхождения в цифрах между уровнями — потому что все пять экранов читают одни и те же дневные суммы.

## 5. Делаем поверх существующего (масштаб)

Это расширение, не новая стройка. Ключевой факт: в системе уже больше месяца (с 24 мая 2026) каждую ночь тихо копится табличка «расход по дням» — по одной строке на «компания + день + операция + модель», с уже правильными (сегодня же починенными) суммами в рублях. Строим новый экран поверх неё, а не придумываем параллельный способ считать деньги с нуля.

Дополнительно переиспользуем:
- готовую табличку соответствия «176 внутренних имён операций → один из 4 смысловых разделов» — она уже составлена и почти полностью согласована (см. «Решения» ниже);
- единый стиль admin-таблиц, карточек-цифр, выбора периода и кнопки экспорта в CSV — уже есть на всех текущих экранах, не изобретаем новый визуальный язык.

Честно об объёме: сегодня расход на самом деле считается **шестью разными кусками кода** — три из них по сути повторяют одну и ту же арифметику «сумма по компании за период» с небольшими отличиями в окне расчёта, ещё один показывает деньги в долларах вместо рублей. Весь этот разнобой схлопывается в один источник и один экран.

## 6. Границы — что НЕ делаем

- **Не трогаем список организаций как таковой** (тариф, статус подписки, число участников, число встреч) — только его денежную колонку. Управление организацией — отдельная, нужная функция, дашборд расхода её не заменяет.
- **Не трогаем настройку бюджет-лимита компании** (сумма в рублях на месяц + пороги алертов) — она остаётся редактируемой там же, где сегодня, просто рядом с ней больше не дублируется расчёт расхода (он приходит из общего источника/ссылкой).
- **Не трогаем «Экономика моей организации».** Это самообслуживание владельца одной конкретной компании — он не суперадмин и не должен видеть чужие компании. Другая аудитория, другие права доступа. Если понадобится обновить и его — отдельная небольшая задача позже.
- **Не трогаем экран настройки моделей как инструмент конфигурации** — вкладки «Цепочка моделей», «История переключений», «A/B-тест» продолжают работать как есть. Меняется только его вкладка «Метрики»: та начинает показывать вырезку из общего дашборда вместо собственного отдельного расчёта.
- **Не показываем разбивку «по конкретному пользователю компании».** Такая функция существует в коде сегодня, но её нельзя открыть ни с одной живой страницы уже сейчас — то есть спроса на неё, который стоило бы сохранить, не зафиксировано. В согласованных пяти уровнях лестницы такого среза нет. Понадобится позже — отдельная задача (исходные данные для этого хранятся в другом месте и никуда не денутся).
- **Не показываем на общей лестнице разбивку «по уровню запасного варианта модели» (основная/запасная/резервная) и по проценту успешных вызовов.** Этого среза сегодня тоже нет ни на одном из восьми экранов, кроме одного узкого места — вкладки «Метрики» экрана настройки моделей, для одной конкретной операции. Он там и остаётся, отдельно от общей лестницы.
- **Не восстанавливаем историю графика раньше 24 мая 2026** — до этой даты ночной сборщик ещё не существовал. Недостающие две недели (с 9 по 23 мая, за которые исходные данные ещё физически сохранились) досчитаем один раз тем же способом, каким сборщик считает каждую ночь — но раньше 9 мая данных для восстановления уже нет физически.
- **Не меняем цифры и валюту на уже отправленных письмах/выгрузках** — только сам новый экран.

## 7. Решения, которые я принял за тебя

| # | Решение | Почему так (человечески) |
|---|---|---|
| Р1 | Источник данных нового экрана — уже существующая ночная табличка «расход по дням», а не пересчёт на лету по сырому журналу каждого вызова | Она копится больше месяца, в ней уже верные (сегодня починенные) суммы, и читать из неё в разы дешевле для экрана, который будут открывать часто |
| Р2 | Только два из пяти живых старых экранов (общая юнит-экономика, список операций) не удаляются молча, а превращаются в вежливое перенаправление на новый (как уже сделано с тремя более старыми путями раньше). Ещё три экрана (список организаций, юнит-экономика одной компании, страница одной операции) оказались с секретом — под расходом там же живёт другая нужная функция (управление организацией, настройка бюджет-лимита, ещё один редактор модели) — их не редиректим целиком, а хирургически вырезаем только денежную часть, остальное оставляем работать как есть | Кто-то мог сохранить прежнюю ссылку на чистую витрину — пусть она тихо приведёт на новое место, а не покажет «страница не найдена»; но экраны с чужой функцией внутри при полном редиректе потеряли бы эту функцию — так делать нельзя (владелец подтвердил хирургический подход после того, как это вскрылось при технической проверке) |
| Р3 | Три уже мёртвых экрана-заглушки (перенаправления в никуда без единого пользователя) и обслуживающий их код удаляются насовсем, а не переезжают | Это перенаправление на перенаправление — двойной прыжок без единой функции, чистый мусор |
| Р4 | Функция «показать всех пользователей компании и их расход», которую сегодня физически невозможно открыть ни с одной живой страницы, удаляется вместе с обслуживающим её кодом на сервере | Ей уже сегодня некому пользоваться, а разреза «по пользователю» среди согласованных пяти уровней нет |
| Р5 | Все суммы на новом экране — только в рублях, без вкраплений долларов (как сейчас на одном из старых экранов) | Компания российская, рубли теперь посчитаны точнее, чем раньше; путать два экрана в двух валютах при сравнении неудобно |
| Р6 | Все старые экраны, которые сегодня сами считают расход (список организаций, обе юнit-экономики, список операций) при переезде избавляются от собственного расчёта — денежная часть либо редиректится, либо становится ссылкой/врезкой в общий источник, окно расчёта везде одно и то же | Иначе перенос не решит исходную боль «цифры не совпадают между экранами», а просто скопирует её на новое место |
| Р12 | На «Список организаций» денежная колонка (сегодня в долларах) заменяется ссылкой/врезкой на уровень «по компаниям» нового дашборда; на «Юнит-экономика одной компании» расчёт расхода и топ операций убирается в пользу ссылки/врезки туда же, а форма бюджет-лимита остаётся на месте без изменений | Владелец подтвердил хирургический подход — управление организацией и настройка бюджета не про расход на LLM, дашборд не должен их подменять или ломать |
| Р13 | Дублирующий редактор «какая модель обслуживает операцию» на странице одной операции (в разделе «Функции LLM») убирается в этом же ТЗ; единственным местом редактирования остаётся «Роутинг моделей» → вкладка «Цепочка», страница операции получает ссылку туда вместо своей копии редактора | Владелец подтвердил — это находка не про деньги, но раз уж вскрылась и трогаем этот же экран, дешевле убрать дубль сейчас, чем потом отдельной задачей возвращаться на то же место |
| Р7 | 13 из 14 спорных ярлыков таксономии «операция → раздел» беру как есть (мои прошлые рекомендованные дефолты), кроме `block-ingest`, которую ты уже подтвердил явно как «Извлечение» | Ни одна из оставшихся 13 не сравнима по частоте с `block-ingest` — заметно картину не изменит, а откладывать весь экран ради 13 ярлыков — плохой размен. Ярлык у любой операции можно поправить позже одной строкой, без пересчёта данных |
| Р8 | На верхнем уровне — три параллельные «двери» (по модели / по разделу / по компании), а не один жёстко заданный порядок листания | Так быстрее попасть туда, куда нужно именно сейчас, не проходя лишние ступени |
| Р9 | Кнопка «Экспорт в CSV» сохраняется на каждом уровне нового экрана | Она уже есть и работает на текущих экранах — нет причины терять её только из-за переезда |
| Р10 | Вкладка «Метрики» в «Роутинг моделей» после переезда показывает встроенную сжатую вырезку из нового дашборда (не просто ссылку), рядом отдельно остаётся узкая деталь «основная/запасная модель + успешность» | Владелец подтвердил рекомендацию — при настройке модели удобнее сразу видеть эффект, не уходя со страницы |
| Р11 | Новый дашборд открывается по умолчанию на периоде 30 дней | Владелец подтвердил рекомендацию — самый частый выбор на сегодняшних экранах, достаточно широкое окно для тренда на графике |

Обе развилки, вынесенные в черновике, владелец решил при показе документа (см. Р10, Р11 выше) — открытых вопросов не осталось.

## 9. Как поймём, что получилось

- Владелец за одну минуту после захода на экран понимает, куда уходят деньги на AI: по модели, по смысловому разделу, по компании — не переключаясь между шестью разными страницами с разными цифрами.
- На любом из пяти уровней виден график по дням/неделям, а не только сухой итог за период.
- Сумма по одной и той же операции совпадает независимо от того, с какой стороны до неё добрались — через модель или через компанию.
- Все суммы показаны в рублях без путаницы с долларами на отдельных экранах.
- Старые сохранённые ссылки на две чистые витрины расхода молча приводят на новый экран, а не показывают «страница не найдена».
- Список организаций, настройка бюджет-лимита компании и настройка модели («Роутинг моделей», её цепочка и A/B-тесты) продолжают работать как раньше — дашборд расхода убрал только дублирующий расчёт денег и дублирующий редактор модели рядом с ними, не саму функцию.
- В «Функциях LLM» остаётся только одно место редактирования модели операции — «Роутинг моделей»; второй копии редактора больше нет.
