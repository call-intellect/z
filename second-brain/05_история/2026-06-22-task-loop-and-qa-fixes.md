Развилки решал сам (зафиксированы в §8 task-loop): резолвер — dependency-free гибрид (без petrovich); морфология «по имени задачи» — каскад exact→includes; `complete` идемпотентен через `@@unique` sentinel; `expiresAt:null` для явных concierge-кандидатов (обходит и магическую TTL-константу); удаление решений — симметрично нормам; видимость через двухшаговый резолв `IssueAssignee` (у `TaskClosureCandidate` нет relation на Issue).

# Чему научился

- **Уведомление «exit 0» от фоновой Bash-обёртки ≠ зелёный инструмент.** `bunx tsc … ; echo "X=$?"` делает успешным весь конвейер даже при tsc-провале — реальный код виден только в логе (`BE_TSC=2` при «completed exit 0»). Всегда проверять реальную строку, не сводку.
- **cwd персистит между Bash-вызовами.** После `cd backend` следующий `bunx tsc` без `cd` упал в корне и напечатал help tsc (не ошибку компиляции). Гонять typecheck/build только из явного `backend/`.
- **Чини класс, не кейс — аудитом, а не по списку из ТЗ.** ТЗ Ф8 называл 3 места битой ссылки `/meetings/:id`; греп `href={\`/meetings/\${` нашёл **ещё 2** (WhatWeLearnedWidget, SprintDashboardClient). Без аудита всего класса остались бы битыми.
- **Агенты гоняют vitest, а не полный strict-tsc.** Кодер Ф7 отчитался «зелёно», но `tsc --noEmit` поймал `mock.calls[0][0]` possibly-undefined в его spec. Полный typecheck — обязательная ступень приёмки, не «агент сказал ок».
- **Доковая конвенция файла перевешивает реактивную чистку комментариев.** В DTO/сервисах с `///`-доком на каждом поле точечное удаление моих строк сделало бы поле единственным недокументированным — хуже консистентности. Чистил только чисто-нарративные `//`-вставки, доковые под плотность соседнего кода оставлял.
- **A/B промпта дешёв и убедителен.** 24 реальных вызова DeepSeek (~$0.01) дали цифру 0/6→5/6, которой ни один снапшот-тест не даст: снапшот доказывает «текст промпта такой», A/B — «модель теперь классифицирует правильно».
