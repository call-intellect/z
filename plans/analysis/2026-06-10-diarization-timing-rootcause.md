# Анализ: транскрипт «дорожками подряд», не по ролям и таймингу — корень и решение

> Дата: 2026-06-10. Прод `korateam.ru`. Доказательная база: код (`merge.worker.ts`, `merger.ts`, `vox.service.ts`) + прод-логи (diag) + живой осмотр встречи `01KTNJW02ARCB6WY58XTFD5EMN` («встреча с Александром», продажи, 44 мин, 4 участника).
> Питает **Ф3** ТЗ [2026-06-10-bugfix-fleet-retest3.md](../tz/2026-06-10-bugfix-fleet-retest3.md) (баги #26/#74) — здесь развёрнутый разбор именно диаризации/тайминга.

## 1. Симптом (как видит пользователь)

Транскрипт встречи не переплетён по ролям и времени. Вместо «Сергей сказал X (0:10) → Александр ответил Y (0:25) → Сергей продолжил Z (0:40)» лента выглядит так: **вся речь одного спикера целиком, затем вся речь второго целиком**. На реальной встрече:

- Вкладка «Транскрипт» → заголовок **«Транскрипт · 3 реплики»** на 44-минутную встречу 4-х участников. Реплика 1: `00:00 СЕРГЕЙ` + весь его 45-минутный монолог одним куском; затем такие же блоки других спикеров. Переплётки нет.
- Блок «Поведение участников» (помечен системой **«Метрики ориентировочные: качество диаризации низкое»**) даёт количественную подпись поломки:
  - **«Всего речи: 130 мин 15 с»** при длительности встречи **44 мин** (≈ сумма 3 дорожек по ~44 мин).
  - **«Перекрёстная речь: 128 мин 15 с»** из 130, **«Тишина: 0 %»** — система считает, что все говорили одновременно всю встречу.
  - Доли: Сергей 100.0 %, Айназ 96.8 %, Александр 95.6 % (сумма ≫ 100 %).
  - В таблице у каждого: **«Монологи: 1, самый длинный монолог 44 мин 32 с / 43 мин 8 с / 42 мин 35 с»** — то есть вся дорожка = ОДИН монолог на всю встречу.
  - Две лишние строки «0 с / 0 %» — пустые дорожки (баг #74, дорожка участника не расшифровалась).

## 2. Архитектура (как задумано)

Кора пишет **отдельную аудиодорожку на каждого участника** (CLAUDE.md, принцип 4 — не полагаться на общий микс). Каждая дорожка транскрибируется **независимо** (Vox, один спикер на дорожку, `diarizationEnabled:false`). Затем стадия `ai.merge` должна **переплести** реплики всех дорожек в единую хронологию по таймкодам.

Алгоритм слияния `mergeWordTimestamps` ([merger.ts:58-140](../../backend/src/modules/ai/services/merger.ts#L58)) **корректен**:
1. Для каждой дорожки берёт смещение входа спикера `trackOffsetMs = trackStartedAt − baseStartedAt` ([:68](../../backend/src/modules/ai/services/merger.ts#L68)) — то есть участник, вошедший на 5-й минуте, корректно сдвигается.
2. Переводит каждое слово в абсолютное время ([:70-71](../../backend/src/modules/ai/services/merger.ts#L70)).
3. Сортирует **ВСЕ слова всех дорожек** по абсолютному времени ([:86](../../backend/src/modules/ai/services/merger.ts#L86)).
4. Нарезает реплики по смене спикера или паузе >1.5 с ([:118-137](../../backend/src/modules/ai/services/merger.ts#L118)).

**Вывод: переплётка «по ролям и таймингу друг за другом» уже реализована и работает — но ей нужны таймкоды на уровне слов или сегментов. Их нет.**

## 3. Корень

### 3.1 Главное: Vox не отдаёт пословные тайминги для живых дорожек (#26)
Submit к Vox в живом конвейере ([vox.service.ts:86-100](../../backend/src/modules/ai/services/vox.service.ts#L86)) **не запрашивает** word-timestamps (per-track вызовы передают `opts={}`, [transcribe.worker.ts:468](../../backend/src/modules/ai/workers/transcribe.worker.ts#L468)). Vox возвращает текст + общую длительность, но без `words[]`/`segments[].words` → ветка `vox.no_words` ([vox.service.ts:240-286](../../backend/src/modules/ai/services/vox.service.ts#L240)). Подтверждено в прод-трейсе: `vox: COMPLETED с текстом, но БЕЗ пословных таймингов — поведение/длительность будут нулевыми` (×3 дорожки этой встречи).

### 3.2 Fallback схлопывает дорожку в ОДИН блок
Без таймингов `merge.worker` строит **одно псевдо-слово на ВСЮ дорожку** `[startMs:0 … endMs: длительность_дорожки]` ([merge.worker.ts:137-164](../../backend/src/modules/ai/workers/merge.worker.ts#L137)). Тогда в `mergeWordTimestamps`:
- каждая дорожка = одно «слово» длиной во всю дорожку → один `turn` на дорожку;
- 3 дорожки → 3 turn'а, каждый «звучит» свои ~44 мин и **полностью накладывается** на соседние → отсюда «перекрёстная речь 128 мин» и «всего речи 130 мин».

То есть симптом — прямое следствие 3.1: нет таймкодов внутри дорожки → нечем нарезать и переплести → одна реплика на дорожку.

### 3.3 Vox УМЕЕТ диаризацию, но для живого пути она выключена
В парсере ([vox.service.ts:438-448](../../backend/src/modules/ai/services/vox.service.ts#L438)) есть `mapDiarizedSegments` — Vox с `diarizationEnabled:true` отдаёт сегменты `{ start, end, speaker, text }` (секунды) — **ровно «по ролям и таймингу»**. Но комментарий прямо говорит: *«per-track путь (живой конвейер) сюда не попадает (`diarizationEnabled:false` → segments отсутствуют)»*. Этот путь используется только для **загруженных файлов** (ТЗ-5 Ф3 upload-диаризации). Живой по-дорожечный путь на него не выходит и полагается только на отсутствующие word-timings.

### 3.4 Дополнительно: пустая дорожка молча теряется (#74)
Часть дорожек (`Настя`/дубли с 0 с) расшифровались как пустые (`vox.empty`) и сохранились как «успех» без диагностики/ретрая ([transcribe.worker.ts](../../backend/src/modules/ai/workers/transcribe.worker.ts), [vox.service.ts:222-234](../../backend/src/modules/ai/services/vox.service.ts#L222)) — спикер исчезает из ленты без сигнала «почему».

## 4. Что чинить (иерархия решений)

Сначала **ШАГ-0 smoke** на реальной прод-модели Vox (`backend/scripts/smoke-vox-diarization.ts`), перебрать имена флага и **посмотреть, что Vox реально умеет** для per-track запроса. От исхода:

| Уровень | Что | Результат для пользователя |
|---|---|---|
| **A. Слова (лучший)** | per-track submit запрашивает word-timestamps; парсер уже умеет `words`/`segments[].words` | полная переплётка, точные таймкоды |
| **B. Сегменты (достаточно)** | если word-level недоступен, но Vox отдаёт **сегменты** `{start,end,text}` — собирать **псевдо-слово НА КАЖДЫЙ СЕГМЕНТ** (а не на всю дорожку), как в `mapDiarizedSegments`, и кормить ими `mergeWordTimestamps` | переплётка по предложениям/сегментам — ровно «по ролям и таймингу друг за другом» |
| **C. Ничего (тупик)** | Vox отдаёт только текст+длительность ни при каком флаге | нечем переплести → решение владельца: сменить модель Vox / добавить forced-alignment (текст готов → выровнять по аудио) |

**Ключевое улучшение кода (независимо от A/B):** текущий fallback ([merge.worker.ts:152](../../backend/src/modules/ai/workers/merge.worker.ts#L152)) делает 1 псевдо-слово на ВСЮ дорожку. Минимально правильнее — 1 псевдо-слово **на сегмент** (если сегменты есть). Тогда даже без пословных таймингов лента переплетётся по предложениям.

**Гард поведенческих метрик:** когда диаризация деградировала (число turn'ов ≈ числу дорожек / полное взаимное наложение) — behavior-metrics не должны показывать абсурд «130 мин речи / 128 мин перекрёстной речи», а честно ставить «недоступно» (сейчас лишь приписка «ориентировочные», но цифры всё равно показываются).

## 5. Масштаб ущерба (один корень — много поверхностей)
Отсутствие таймкодов ломает СРАЗУ: (1) сам транскрипт (3 блока вместо диалога), (2) «Поведение участников» (130 мин/перекрёст), (3) `Оценка качества встречи` («Не удалось рассчитать» — #71 рядом), (4) главы по времени, (5) клипы по таймкодам. Поэтому Ф3 — высокого приоритета, несмотря на severity P1/P2 по отдельным симптомам.

## 6. Доп. проверки, которые стоит сделать на реализации
- ШАГ-0 smoke под фактической прод-моделью (`VOX_MODEL`): дефолт в коде `v3_rnnt` ([env.schema.ts:134](../../backend/src/common/config/env.schema.ts#L134)), в smoke `v3_e2e_rnnt` — **уточнить, какая реально в проде**, и умеет ли она word/segment timings.
- Проверить, выставляются ли `trackStartedAt`/`baseStartedAt` корректно (смещение входа): если все дорожки стартуют с одного `baseStartedAt`, но участник вошёл позже — offset должен это отражать; на этой встрече длительности дорожек близки (43–45 мин), так что вход почти одновременный — но на встречах с поздним входом проверить отдельно.
- После фикса — сверить «Всего речи» ≈ длительности встречи (а не сумме дорожек) и «перекрёстная речь» в разумных пределах.
