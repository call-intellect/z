# Мобильный UX единого чата

## Часть 1. Паттерны конкурентов

### 1.1 Одноколоночная навигация и нижние вкладки (bottom navigation)

Все зрелые мессенджеры сошлись на одной модели мобильной навигации: **список диалогов → тап по строке → экран чата → кнопка «назад» / свайп с левого края** [inferred из всех конкурентов, ниже конкретика].

**Telegram** — единственный крупный игрок, сохранивший навигацию без нижней панели: боковое меню открывается свайпом вправо. Это позволяет использовать всю высоту под список чатов, но конфликтует с моделью большого пальца [triangulated(2): createbytes.com + telegram.org/blog]. В iOS-версии Telegram 2026 добавлен жест pull-down для поиска — отход от традиционной кнопки лупы [claimed: поисковая выдача muz.li 2026-06-21].

**WhatsApp** (Android) поэкспериментировал со свайпаемой нижней навигационной полосой, потом убрал её как противоречащую гайдлайнам Android, затем вернул в бете — решение всё ещё нестабильно [verified: androidpolice.com «WhatsApp's swipeable navigation bar could make a comeback soon» 2025].

**Slack** прошёл наиболее задокументированный путь: сократил число нижних вкладок с пяти до трёх (Home, DM, Упоминания) [verified: slack.design/articles/re-designing-slack-on-mobile/]. Вкладка Home — умный список: каналы и личные чаты с активностью всплывают наверх, остальные — ниже в секциях [verified: slack.com/blog]. Свайп вправо из любой вкладки открывает список воркспейсов (рабочих пространств), свайп влево — возврат в последний чат [verified: xda-developers.com].

**Microsoft Teams** объединил разрозненные «Чаты» и «Каналы» в единый раздел Chat, чтобы убрать переключение контекста (context switching — прыжки между разными экранами) [verified: techcommunity.microsoft.com 2025]. Кастомные секции для группировки пока не продублированы на мобиле — это признанный пробел [claimed: support.microsoft.com].

**Bitrix24** (декабрь 2025): рефреш интерфейса, профиль в верхнем левом углу открывает боковое меню из любого раздела, нижнее меню настраивается пользователем [verified: accessnewswire.com]. Плавающие аватары участников «прилипают» к краю экрана при скролле в групповом чате [claimed: digitaljournal.com/pr].

**Ключевой вывод по навигации**: нижняя панель с 3–4 вкладками — отраслевой стандарт 2025–2026. Исключение (Telegram без нижней панели) обоснованно только при очень простой IA (информационной архитектуре), когда весь продукт — это чат.

### 1.2 Жесты свайпа (swipe gestures)

| Жест | Telegram | WhatsApp | Slack |
|---|---|---|---|
| Свайп влево по сообщению | Ответить на сообщение (reply) | Ответить на сообщение | — |
| Свайп вправо по сообщению | Отметить прочитанным / архив | — | — |
| Свайп с левого края экрана | iOS: возврат назад | iOS: возврат назад | Возврат к последней вкладке |
| Свайп вниз по списку | Поиск (Telegram iOS) | — | «Последние разговоры» |

[triangulated(3): telegram.tips/blog/swipe-left-to-reply/, slack.design, xda-developers.com]

Свайп влево по сообщению для ответа — де-факто стандарт. Пользователи знают этот жест из Telegram и WhatsApp и ожидают его в любом новом приложении.

---

### 1.3 Голосовые сообщения (voice messages) — ключевой паттерн для линейного персонала

**Telegram**:
- Удержание (hold) иконки микрофона → запись
- Свайп вверх на микрофон → фиксация записи (lock), руки свободны
- Свайп влево во время записи → отмена
- Пауза/возобновление поддерживается с 2024 года
- Однократные голосовые (One-Time Voice) — прослушиваются один раз и удаляются [verified: telegram.org/blog/new-saved-messages-and-9-more]

**WhatsApp**: аналогичный паттерн — удержание, свайп вверх для фиксации, свайп влево для отмены [triangulated(2): sammyfans.com + androidpolice.com].

Паттерн «hold → swipe up to lock → swipe left to cancel» стал отраслевым стандартом. Он понятен без обучения, потому что жест отмены интуитивен (назад = удалить).

---

### 1.4 Реакции, долгий тап (long-press), контекстное меню

Долгий тап по сообщению → выплывает шторка (bottom sheet) с эмодзи-реакциями и действиями (ответить, скопировать, переслать, удалить). Это паттерн всех трёх платформ. Преимущество: не нужна видимая кнопка — меньше визуального шума [triangulated(2): getstream.io/blog/chat-ux/ + bricxlabs.com].

---

### 1.5 Статусы прочтения и индикаторы

- **Прочтение**: одна галочка (отправлено) → двойная галочка (доставлено) → синяя двойная галочка (прочитано) — паттерн WhatsApp, скопированный большинством [inferred из общих источников].
- **«Печатает» (typing indicator)**: событие шлётся каждые 2 секунды во время активного набора [verified: getstream.io/blog/chat-ux/]. Должен затухать через ~5 сек если пользователь прекратил печатать.
- **Бейджи (badges) непрочитанного**: «3 важных, 47 всего» — рекомендация против простого числа [verified: getstream.io — «unread count clarity»]. Вывалить сотню непрочитанных → тревожность и отказ открывать.

---

### 1.6 Пуш-уведомления (push notifications)

- Общий click-through rate (доля кликов) у общих пушей — ~4%; контекстный персонализированный пуш даёт ~14,4% [verified: getstream.io/blog/chat-ux/].
- Оптимальная задержка: уведомление через ≤90 секунд после события, затем экспоненциальная задержка для неактивных пользователей [verified: getstream.io].
- **APNs** (Apple Push Notification Service — служба пуш-уведомлений Apple): требует конфигурации в Xcode, токен отличается от FCM (сервиса уведомлений Google) [verified: appstudio.ca 2025].
- **RuStore Push SDK** для React Native: официальная поддержка в SDK версии 2.1.1 и 6.x [verified: rustore.ru/help/en/sdk/push-notifications/react]. RuStore — нативный Android-маркет (магазин приложений) для России, заменяет Google Play как канал доставки пушей без зависимости от FCM.

---

### 1.7 Мобильная поддержка (support desk) — агент с телефона

**Intercom (мобильное приложение для агентов)**:
- Мессенджер-интерфейс сбоку: очередь обращений выглядит как список диалогов, без тикет-решётки (ticket grid — таблица обращений) [verified: usefini.com/guides/intercom-vs-zendesk-support-agents].
- Из карточки диалога доступны: ответ клиенту, внутренняя заметка (internal note — видна только команде), назначение коллеге (assign), откладывание (snooze), пометка приоритетным [verified: intercom.com/help/en/articles/447].
- Быстрые ответы (saved replies / canned responses — заготовленные ответы): вставляются в один клик; AI подсказывает подходящий ответ по истории [verified: intercom.com/help/en/articles/6258745].
- Приложение для агентов Intercom с 2024 года в режиме обслуживания (maintenance mode) — новые фичи не добавляются [claimed: intercom.com].

**Коллизионное обнаружение (collision detection)**: если два агента открыли один диалог одновременно, система предупреждает — предотвращает двойной ответ [verified: guideflow.com/blog, deemerge.ai].

---

### 1.8 Офлайн и «что я пропустил»

- **Автоскролл + возврат к позиции**: при возвращении в чат — «Вы здесь остановились» + кнопка «перейти вниз» [inferred из getstream.io best practices].
- **AI-сводки** (catch-up summaries — краткое содержание пропущенного): Slack AI позволяет пинчем по каналу в режиме Catch Up вызвать сводку за произвольный период [verified: slack.com/help/articles/25076892548883]. Ежедневная сводка утром за предыдущий день [verified: eesel.ai/blog].
- **Умные бейджи**: «3 решения в #проект, 2 вопроса к тебе» вместо «47 непрочитанных» [verified: getstream.io — «3 decisions in #product, 2 questions for you»].

## Часть 2. Рекомендации для «Кора»

### 2.1 Трёхколоночный десктоп → одноколоночный мобильный поток

На десктопе типичная раскладка (layout) единого чата: левая панель (список диалогов) + центр (переписка) + правая панель (контекст: профиль, связанные задачи, файлы, история AI). На мобиле это не помещается. Рекомендуемая схема преобразования:

```
Десктоп: [Список] | [Чат] | [Контекст-панель]
Мобиль:  [Список]
              ↓ тап
          [Чат]
              ↓ тап «ℹ️» или свайп снизу вверх
          [Контекст-шторка]
```

**Контекст-панель** превращается в **выезжающую шторку снизу (bottom sheet)**, вызываемую:
- тапом по имени/аватару в хедере (header — заголовок) чата;
- жестом свайп-вверх с нижнего края переписки.

Шторка должна быть двухвысотной: «половина экрана» (краткий профиль + последние решения) → полный разворот (история AI-анализа, связанные задачи, файлы). Это соответствует паттерну Material Design 3 «bottom sheet with snap points» [triangulated(2): m3.material.io + blog.logrocket.com/ux-design/bottom-sheets-optimized-ux/].

---

### 2.2 Нижняя навигация Коры — рекомендуемая структура

Для продукта «Кора» с единым разделом «Сообщения» (личка + группы + рабочие чаты + поддержка клиентов) рекомендуется 4 вкладки:

| № | Вкладка | Содержимое |
|---|---|---|
| 1 | Сообщения | Единый список: личка, группы, рабочие чаты — сортировка по активности |
| 2 | Поддержка | Очередь обращений от клиентов (если роль — агент) |
| 3 | AI / Кора | «Спросить Кору», сводки, «что пропустил» |
| 4 | Я | Профиль, уведомления, настройки |

Вкладку «Поддержка» можно скрывать по роли (RBAC — управление доступом на основе ролей): линейный сотрудник её не видит, агент поддержки видит.

---

### 2.3 Список диалогов — умная сортировка и фильтрация

По образцу Slack Home:
- **Секция «Сейчас важно»** — диалоги с @упоминаниями (mentions), ответами на твои сообщения, непрочитанными от руководителя.
- **Секция «Остальное»** — все остальные чаты в хронологическом порядке.
- Кнопка-фильтр (chip) «Только непрочитанные» над списком — один тап, не меню.
- Поиск: pull-to-search (потянуть вниз для поиска) по образцу Telegram iOS — не занимает постоянного места на экране.

---

### 2.4 Композер (composer — поле ввода) и голосовой ввод

Голос — **главный способ ввода** для линейного персонала (работника на объекте), у которого руки заняты. Приоритетная компоновка:

```
[ Текстовое поле (expandable) ] [📎] [🎤]
```

- Иконка 🎤 занимает правый нижний угол — в зоне большого пальца.
- **Hold to record** (удержание для записи) → стандартный паттерн WhatsApp/Telegram.
- **Swipe up to lock** (свайп вверх для фиксации) → руки свободны для записи длинного голосового.
- **Swipe left to cancel** (свайп влево для отмены).
- После записи: воспроизведение с waveform (формой волны) перед отправкой — пользователь слышит себя и может перезаписать.
- Голос-в-текст (ASR — автоматическое распознавание речи) Коры уже работает: предлагать пользователю выбор «отправить голосом» или «отправить текстом (расшифровка)» — это снижает барьер для тех, кому неудобно голосовое в публичном месте [inferred из анализа Z-стека].

---

### 2.5 «Что я пропустил» и AI-крючки на мобиле

Для корпоративного продукта главная боль мобильного пользователя — возврат после паузы к сотням сообщений. Рекомендации:

- **Умный бейдж**: «3 решения, 2 вопроса к тебе» вместо числа 47 [по образцу getstream.io].
- **«Нажать → получить сводку»**: в хедере чата кнопка или pull-down жест вызывает AI-сводку за период отсутствия (по образцу Slack AI pinch-to-summarize) [triangulated(2): slack.com + eesel.ai].
- **«Спросить Кору»** в нижней вкладке AI: голосовой или текстовый ввод «Что решили вчера по проекту X?». На мобиле это должно открываться плавающей кнопкой (FAB — Floating Action Button) прямо из экрана переписки — не требовать выхода.
- **Утренняя push-сводка**: одно уведомление «Пока вас не было: 3 решения, 2 упоминания» — вместо пакета из 47 отдельных пушей [по образцу Slack AI Daily Recaps, verified: eesel.ai/blog].

---

### 2.6 Деск поддержки на мобиле (агент отвечает клиентам)

Ключевая проблема маленького экрана: одновременно показать очередь, переписку и внутренние заметки невозможно. Решение:

**Вкладка «Поддержка»** = список обращений с умной сортировкой (SLA (соглашение об уровне обслуживания) / приоритет / ожидание ответа).

Внутри обращения — переключатель в нижнем тулбаре (toolbar — панель инструментов):

```
[ Ответить клиенту ] ←→ [ Внутренняя заметка ]
```

Активный режим меняет цвет фона композера (синий = клиент, жёлтый = внутренняя) — визуальный якорь, предотвращающий ошибку отправки внутренней заметки клиенту [по образцу Intercom inbox UX, triangulated(2): intercom.com + deemerge.ai].

**Быстрые ответы (canned responses)**: тап на «/» в поле ввода → список шаблонов с поиском — стандарт Intercom/Zendesk [verified: intercom.com/help/en/articles/6258745].

**Коллизионная защита**: если коллега уже открыл то же обращение, показывать «Иван сейчас отвечает» до отправки [verified: guideflow.com].
