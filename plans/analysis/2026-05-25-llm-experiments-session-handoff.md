# Передача контекста: сессия по тестированию AI-агентов на реальных вызовах

Эта запись — **полная стартовая точка для нового агента**. Прочитай её целиком, и ты будешь знать всё что было сделано за день и что нужно делать дальше.

## 1. Что в одном предложении

Пользователь и я сравнивали разные архитектуры AI-агентов Z (раздельные шаги vs объединённый вызов) на реальных DeepSeek-V4-Pro вызовах с синтетическими фикстурами. Результат: **для встреч и для специалистов knowledge-core победил «один объединённый вызов»**, для диалоговой цепочки — текущая раздельная архитектура остаётся.

## 3. Ключевые архитектурные находки

### 3.1 «Когда объединять, когда нет» — главное правило

| Признак | Объединять в один вызов? |
|---|---|
| Один и тот же тяжёлый контекст подаётся в несколько шагов | **Да** |
| Каждый шаг работает на своём маленьком входе | **Нет** |
| Промежуточные результаты — большие | Зависит (обычно лучше раздельно) |

### 3.2 DeepSeek-V4-Pro с thinking — формат вывода

**Не поддерживает:**
- `response_format: json_schema strict` — возвращает 400.
- `tool_choice: 'required'` или forced — возвращает 400 «Thinking mode does not support».

**Поддерживает:**
- `tools` + `tool_choice: 'auto'` — рабочий путь. Подмешивай в user-сообщение «верни через инструмент submit_X».
- `response_format: json_object` (мягкий).

**Probe-эксперимент:** [probe-deepseek-formats.ts](../../backend/scripts/eval/probe-deepseek-formats.ts).

**ТЗ:** [2026-05-25-deepseek-pro-output-format-fix.md](../tz/2026-05-25-deepseek-pro-output-format-fix.md).

### 3.3 Кэш промптов DeepSeek работает не так, как я обещал

Я в ТЗ написал «экономия 90% на кэше». Реально — **только 21-24%** на повторных вызовах с одинаковым префиксом. Похоже, DeepSeek кэширует только начальные ~2700 токенов промпта, не весь общий префикс.

**ТЗ нуждается в корректировке:** [2026-05-25-llm-cache-prefix-everywhere.md](../tz/2026-05-25-llm-cache-prefix-everywhere.md) — заменить «90%» на «20-30% реалистично».

### 3.4 Реальные цены DeepSeek-V4-Pro (со скидкой 75%, постоянная)

- Вход без кэша: $0.435 / 1M токенов
- Вход из кэша: $0.003625 / 1M токенов
- Выход (включая thinking): $0.87 / 1M токенов

Я в первый раз использовал старые цены без скидки — пересчитал, поправил во всех скриптах.

### 3.5 KIE / Claude через прокси

- Эндпоинт: `https://api.kie.ai/claude/v1/messages`
- Формат: Anthropic Messages (system + user склеиваются в одно user-сообщение)
- Не поддерживает tools (в нашей интеграции) — только текстовый JSON через инструкцию
- Цены: $1.425/M вход, $7.15/M выход (Claude Opus 4.7) — это в 5-10 раз дороже DeepSeek

### 3.6 Источники данных в проекте Z

| Источник | Объём | Блоков | Кэш-стратегия применима? |
|---|---|---|---|
| Видео-встреча 30-60 мин | 15-30k знаков | 30-60 блоков | Да |
| Звонок 15-30 мин | 8-15k знаков | 15-30 блоков | Да, частично |
| Вечерний чек-ин | 500-2000 знаков | 3-5 блоков | Нет |
| Утренняя планёрка | 5-10k знаков | 10-20 блоков | Маргинально |
| Карточка проекта | 1-5k знаков | 5-10 блоков | Нет |
| Переписка в чате | 1-5k знаков | 5-15 блоков | Нет |

Это значит: **кэш-стратегия выгодна только для больших встреч**. На малых источниках нет смысла.
