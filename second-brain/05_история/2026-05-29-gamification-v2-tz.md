# 2026-05-29 — ТЗ «Геймификация v2 мягко-средняя»

## Что было поставлено

Пользователь попросил провести исследование лучших мировых решений геймификации для корпоративной работы знаниями и написать средне-мягкое ТЗ под российскую компанию 5–100 человек. Цель — мотивировать сотрудников делать утренние/вечерние отчёты, рефлексии, помогать коллегам, озвучивать проблемы, предлагать идеи. Без этого у системы Z нет материала для второго мозга. Каналы доставки — Telegram-бот и виджеты в-приложение. Рамка — гибрид (топ + баллы + уровни + Telegram-пинги) **без токсичности и выгорания**, под РФ-культуру.

В процессе пользователь поставил три уточняющих требования:
1. Доказать «простым человеческим языком», что это лучшее решение.
2. Улучшить ещё на 10% и закрыть **все** открытые вопросы своими решениями с обоснованием.
3. Зафиксировать правило: вся коммуникация с сотрудниками — только русский, без англицизмов.

## Как решал

**Шаг 1. Разведка существующего.** Grep по `gamif|points|badge|leaderboard|achievement|reward|streak|reputation` → нашёл план [plans/tz/2026-05-23-gamification-and-motivation.md](../../plans/tz/2026-05-23-gamification-and-motivation.md), который **запрещал** баллы и рейтинги. Backend уже реализован: модели `Recognition` / `Badge` / `UserBadge` / `ContributionSnapshot` в [backend/prisma/schema.prisma:6809](../../backend/prisma/schema.prisma#L6809), модуль [backend/src/modules/recognition/](../../backend/src/modules/recognition/), 4 cron'а. Не реализован frontend и виджеты. Это означало: новое ТЗ — поверх существующего backend, а не с нуля.

**Шаг 2. Первый pass deep-research через skill `/deep-research`.** 6 углов, 31 источник, 142 claim'а, 25 верифицированных через 3-vote adversarial. Confirmed 10, killed 15. Главные находки: Zhang 2025 (β=0.31), PMC12263921 (employee acceptance ×1.5), Centrical-паттерн (двусторонние kudos), Kim 2026 CMU Tepper (моральные издержки), Hammedi 2021 MDPI (лидерборды → стресс).

**Шаг 3. Первая версия ТЗ.** Записал [plans/tz/2026-05-29-gamification-v2-soft-medium.md](../../plans/tz/2026-05-29-gamification-v2-soft-medium.md) с 8 фазами и 5 открытыми вопросами в конце для пользователя.

**Шаг 4. Доказательство «простым языком».** Разложил аргумент на 5 слоёв: что доказано научно, где я выбирал и почему, где слабо и как митигирую, альтернативы и почему отверг, главный тезис в одной фразе. Это сработало — пользователь дал зелёный свет на улучшения.

**Шаг 5. Второй pass deep-research** (5 узких углов, после явного запроса пользователя «у тебя не должно быть открытых вопросов»). 23 источника, 80 claim'ов, 25 верифицированных, 22 confirmed (88% против 40% в первом pass — это огромная разница в качестве). Ключевые новые находки:
- **Moldon, Strohmaier & Wachs ICSE 2021** (n=433k разработчиков): streak'и провоцируют синглтон-вклады. Прямой урок: за серию НЕ давать зёрна / права уровня.

- **Matthews & Kelemen 2024-2025 JoM** (131-paper обзор): требование явного **inflection point** для соревновательных систем. Это новый раздел в ТЗ с 6 метриками и зонами.
- **Bonusly Gratitude Gauge** (8 сентября 2025): AI-коуч в реал-тайм по 3 сигналам. Встраиваем в Recognition Agent.
- **Mail.ru/VK** — единственный верифицированный РФ-кейс с механиками 1-в-1 как мой ТЗ: Коины + Спасибо + Магазин + Доброкоины. Подтверждает гипотезу.
- **Yahoo Answers** — канон провала peer-points без quality scoring. Подтверждает обязательность AI quality.

## Чему научился

### Поведенческие уроки

**1. Workflow `/deep-research` с structured output регулярно падает на сложных схемах** (failures «subagent completed without calling StructuredOutput after 2 nudges»). В первом pass — 40% confirmation rate, во втором — 88%. Разница в качестве запроса: второй был узко-сфокусирован (5 конкретных углов с готовыми поисковыми терминами), первый — широкий обзор. **Урок:** для deep-research лучше 2–3 узких pass'а, чем один широкий. Также `truncated 21431 chars, full result in /tmp/tasks/<id>.output` — всегда читать output-файл, не полагаться на task-notification summary.

**2. Закон «не возвращать открытые вопросы пользователю».** Пользователь явно сказал «у тебя не должно быть открытых вопросов». Это переформулировало мою работу: вместо «дать варианты на выбор» — «принять решение и обосновать». Это требует уверенности, но эффективнее для пользователя. **Сохранено в memory: feedback_propose_best_solution_with_reasoning** (уже было) — расширил трактовку: открытые вопросы это тоже частный случай нарушения этого правила.

**3. ТЗ переписывать через `Write`, не серией `Edit`'ов, когда изменений >10%.** Я попытался представить серию Edit'ов и понял, что они будут хрупкими (каждый зависит от предыдущего, риск конфликтов). Полная переписка через `Write` дала чистый файл за один шаг.

**4. Forced choice на знакомстве (UI-паттерн).** Default-true плох для отказников (PMC12263921), default-false плох для adoption. Третий путь — модальное окно «Да / Нет / Позже» при первом входе. Паттерн Duolingo/Headspace, opt-in 60–80% без негатива. **Запомнить как паттерн для onboarding в Z** — пригодится в других фичах.

### Технические факты

**1. GitHub natural experiment ICSE 2021** (arXiv:2006.02371, n=433k) — критически важный источник для любых streak-механик в knowledge work. Streak'и удерживают поведение, но раздувают минимально-полезные действия (синглтон-коммиты, weekend-активность). **Применять как универсальное правило**: streak — это leading indicator, не валюта. За серии давать только знаки, не очки и не права.

**2. Matthews & Kelemen 2024-2025 JoM** (DOI 10.1177/01492063241266157) — обзор 131 эмпирической работы. Требование явного «inflection point» (точки перехода в токсичность) — академический стандарт 2024+. Любая соревновательная система Z должна иметь явные пороги и автоматическое уведомление при их пересечении.

**3. Bonusly Gratitude Gauge** (запущен 8 сентября 2025) — AI оценивает каждое сообщение по 3 сигналам: specificity / authenticity / values alignment. **Это эталон AI quality scoring для peer-recognition в 2026.** Z может позаимствовать сигналы + добавить свой дифференциатор (circular pattern detection + time clustering, чего у Bonusly публично нет).

**4. Slack guidelines не задают daily-cap** — только rate limit 1 msg/sec/channel + рекомендация дайджестов. **Microsoft Teams** — hard throttle 20 нотификаций/мин/user. Наш порог 3 сообщения/день/пользователь — на порядки консервативнее любых платформенных. **Сохранить:** ссылки на эти guidelines в `02_architecture/code-pitfalls.md` для будущих ботов Z.

**5. Mail.ru/VK кейс** — единственный публично верифицированный РФ-пример корпоративной геймификации крупной IT-компании. Коины + Спасибо + Магазин призов + Доброкоины — структурно идентично нашему ТЗ. **Но цифр opt-in / DAU / retention нет ни у одного РФ-вендора** (Pryaniky, Mirapolis, Поток, Mail.ru). Системный пробел сегмента → бенчмарки Z строит сам.

### Правила копи

**6. Геймификационные термины — на русском без англицизмов** (расширение existing правила в memory). Конкретные замены:
- Z-coins → **Зёрна** (бренд: «зёрна знаний в памяти компании»)
- Streak → **Серия**
- Streak Freeze → **Сохранение серии**
- Leaderboard → **Топ команды** (не «лидерборд»)
- Kudos / Thanks → **Спасибо**
- Check-in → **Утренний / Вечерний отчёт**
- Opt-in → **Включить участие**

В коде модели остаются на английском (`ZCoinTransaction`, `Level`, `LeagueParticipation`), но все user-facing поля (`nameRu`, `template`, `displayName`) — только русский. AI-агенты получают системный промпт с явным запретом англицизмов в финальном тексте.
