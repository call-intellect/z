> Что это: возможность назначить одного провайдера ИИ «по умолчанию» — и тогда удаление любого другого больше не блокируется, а само переключает всё занятое на этого дефолтного. Для кого: владелец платформы, который управляет каталогом ИИ-провайдеров.
> Цепочка: внутренняя доработка (без рыночного анализа — правка своего же экрана) → **эта архитектура (одобрена)** → ТЗ `plans/tz/2026-07-06-llm-provider-default-fallback.md`. Статус согласования: одобрено 2026-07-06.

# Архитектура «Провайдер по умолчанию» (человеческим языком)

## 1. Что это и зачем

Владелец платформы хочет иметь возможность оставить только ОДНОГО провайдера ИИ (например, экономии ради — платить за один канал, а не за семь) и убрать остальных. Сегодня система это физически не даёт сделать без многочасовой ручной работы: убрать провайдера из каталога нельзя, если он хоть где-то занят — а он занят почти везде, потому что у платформы порядка 250 разных ИИ-задач, у каждой своя цепочка «кто отвечает первым/вторым/третьим». Система отказывает голой технической ошибкой и ничего не предлагает взамен — владелец должен вручную найти и поправить каждое место.

## 2. Как сегодня (от чего отталкиваемся)

- В разделе «Каталог провайдеров» владелец настраивает подключение к нескольким внешним поставщикам ИИ (ключи доступа, адреса) — сейчас их до семи.
- В разделе «Маршрутизация моделей» для каждой из ~250 ИИ-задач задана своя цепочка провайдеров: кто отвечает первым, кто подключается вторым (если первый недоступен), кто — третьим (совсем резервный).
- Если владелец пытается удалить провайдера из каталога, а он занят хоть в одной такой цепочке — система отказывает: «Провайдер используется в активном маршруте — сначала уберите его из маршрутизации». Никакой подсказки, что именно и где менять, нет.
- Единственный способ убрать провайдера сегодня — вручную пройти по всем ~250 задачам, найти те, где он стоит, и вручную поменять на другого. Это долго и легко где-то забыть.

## 3. Что делаем (решение простыми словами)

Добавляем в каталог провайдеров возможность отметить одного провайдера и одну его модель как **«по умолчанию»** — это самый надёжный, всегда доступный вариант платформы. Как только он назначен, поведение при удалении меняется: если владелец удаляет любого ДРУГОГО провайдера, который где-то занят, система больше не отказывает — она сама переключает все места, где он стоял, на провайдера «по умолчанию», и только потом удаляет его. Не назначен дефолт — поведение остаётся прежним (жёсткий отказ), чтобы ничего не переключалось втихую без согласия владельца.

Это расширение уже существующего экрана каталога, не новый раздел.

## 4. Как это будет выглядеть

### Сценарий «было → стало»

**Сценарий: владелец хочет оставить только один провайдер (DeepSeek), остальных убрать**

- **Было:** отмечает провайдера «по умолчанию» — такой возможности нет. Жмёт «Удалить» на OpenAI → голая ошибка «Провайдер используется в активном маршруте taskType=summary — сначала уберите его из маршрутизации». Идёт в раздел «Маршрутизация», вручную ищет все места с OpenAI (их могут быть десятки), меняет по одному. Повторяет для каждого следующего провайдера. Работа на часы, легко что-то пропустить.
- **Стало:** сначала одним кликом отмечает DeepSeek как «по умолчанию». Жмёт «Удалить» на OpenAI → видит понятное предупреждение: «OpenAI используется в 47 маршрутах — все они переключатся на провайдера по умолчанию: DeepSeek / deepseek-v4-flash. Удалить?» → подтверждает одной кнопкой → OpenAI удалён, все 47 мест уже переключены сами. Повторяет для остальных провайдеров за несколько кликов — доходит до состояния «работает только DeepSeek», ничего не трогая вручную в маршрутизации.

### Макет: карточка провайдера в каталоге (новая пометка «по умолчанию»)

```
┌─ Провайдеры ──────────────────────────────────────────────────┐
│  DeepSeek                    ★ По умолчанию   [···]            │
│  OpenAI (через прокси)                        [···]            │
│  Ollama (локальный)                           [···]            │
└──────────────────────────────────────────────────────────────────┘
```
Меню «···» у каждого провайдера получает новый пункт: «Сделать провайдером по умолчанию» (недоступен у того, кто уже дефолт).

### Макет: предупреждение при удалении занятого провайдера

```
┌─ Удалить провайдера "OpenAI (через прокси)"? ──────────────────┐
│                                                                  │
│  ⚠ Этот провайдер сейчас используется в 47 маршрутах.           │
│  Все они переключатся на провайдера по умолчанию:               │
│  DeepSeek / deepseek-v4-flash                                    │
│                                                                  │
│              [ Отмена ]        [ Удалить и переключить ]        │
└──────────────────────────────────────────────────────────────────┘
```

### Макет: попытка удалить самого дефолтного провайдера

Не жёсткий отказ — сразу предлагаем выбрать замену и удалить одним действием:

```
┌─ Удалить провайдера "DeepSeek" (сейчас — по умолчанию)? ─────────┐
│  ⚠ DeepSeek сейчас назначен провайдером по умолчанию.            │
│  Чтобы удалить его, сначала выбери, кто станет новым             │
│  провайдером по умолчанию:                                       │
│                                                                    │
│  Новый провайдер по умолчанию:  [ OpenAI (через прокси)  ▾ ]     │
│  Модель:                        [ gpt-5-mini             ▾ ]     │
│                                                                    │
│              [ Отмена ]         [ Назначить и удалить ]          │
└──────────────────────────────────────────────────────────────────┘
```

### Живой образец текста предупреждения

«OpenAI (через прокси) используется в 47 маршрутах — все они переключатся на провайдера по умолчанию: DeepSeek / deepseek-v4-flash. Удалить?»

## 5. Делаем поверх существующего (масштаб)

Чистое расширение уже существующего экрана «Каталог провайдеров» и уже существующей проверки при удалении. Сегодня эта проверка просто отказывает — станет: отказывает (если дефолт не назначен, как и сейчас) ИЛИ предлагает переключить и удалить (если дефолт назначен). Ничего не создаём с нуля, кроме самой пометки «по умолчанию» и логики автопереключения.

## 6. Границы — что НЕ делаем

- НЕ даём удалить провайдера, который сам назначен «по умолчанию» — сначала владелец обязан передать этот статус другому. Без исключений.
- НЕ придумываем автоматический выбор нового дефолта «на всякий случай» — если дефолт не назначен явно, ничего никуда не переключается, отказ остаётся как сегодня.
- НЕ позволяем назначить «по умолчанию» больше одного провайдера сразу — всегда ровно один на всю платформу (или ни одного, пока не назначен).
- НЕ трогаем неактивных/выключенных провайдеров, которые нигде не используются, — их и сегодня можно удалять свободно.

## 7. Решения, которые я принял за тебя

| # | Решение | Почему так |
|---|---|---|
| Р1 | «По умолчанию» — это ровно одна пара «провайдер + модель» на всю платформу, а не список из нескольких запасных вариантов. | Проще для владельца — один явный ответ на вопрос «куда переключать», не нужно думать о приоритетах внутри дефолта. |
| Р2 | Если после переключения дефолтный провайдер оказался бы дважды в одной и той же цепочке (например, он уже стоял вторым, а первого — удаляют) — второе появление просто убирается, а не дублируется. | Цепочка с одним и тем же провайдером дважды подряд не даёт реальной защиты от сбоя — не создаём видимость резерва там, где его на самом деле нет. |
| Р3 | Если «по умолчанию» вообще не назначен — поведение при удалении остаётся точно как сегодня (жёсткий отказ, ничего не переключается). | Автоматически переключать что-либо без явного согласия владельца — рискованно; молчаливая подстановка без спросу хуже честного отказа. |
| Р4 | Персональные настройки маршрутизации отдельных компаний — тоже переключаются на нового дефолта при удалении провайдера, наравне с общей платформенной маршрутизацией. | Владелец подтвердил (2026-07-06): молчаливый сбой ИИ у компании (обращение к физически удалённому провайдеру) хуже, чем автоматическая подмена на надёжный вариант по умолчанию. |
| Р5 | Удалить провайдера «по умолчанию» можно — но только одним действием «выбери нового дефолта и удали», в одном диалоге (без отдельного предварительного похода в настройки). | Владелец подтвердил (2026-07-06): предпочёл более быстрый путь для себя вместо жёсткого отказа — см. макет в разделе 4. |

## 9. Как поймём, что получилось

- В каталоге провайдеров у ровно одного провайдера видна пометка «★ По умолчанию»; можно передать её другому провайдеру в один клик.
- Попытка удалить занятого провайдера, который НЕ является дефолтом, показывает понятное предупреждение с числом затронутых маршрутов и именем дефолта — и одна кнопка реально удаляет и переключает.
- Попытка удалить провайдера «по умолчанию» — не отказ, а диалог «выбери нового дефолта и удали одним действием»; после подтверждения дефолт-статус переходит новому провайдеру, старый удалён.
- Персональные настройки маршрутизации отдельных компаний тоже переключаются на нового дефолта — ни одна компания не остаётся с ссылкой на удалённого провайдера.
- Владелец может дойти до состояния «работает только один провайдер», не открывая раздел «Маршрутизация» вручную ни разу.
- Если дефолт не назначен — всё ведёт себя как сегодня, без сюрпризов.
