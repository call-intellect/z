# Контур 03: AI-память и семантические карты — как продукты визуализируют «память ИИ»

Задача контура: разобрать продукты на стыке «AI + граф памяти» — как они показывают семантическое пространство, как InfraNodus продаёт «поиск дыр в знаниях» (прямой аналог практичной части Коры), применима ли метафора «звёздного неба» из Nomic Atlas / Embedding Atlas, и есть ли вообще граф-UI у агентных памятей (Zep, mem0, Supermemory, Graphlit).

Легенда тегов достоверности: **[verified]** — первоисточник (доки/репо/релиз); **[triangulated(N)]** — N независимых источников разной природы; **[claimed]** — маркетинг вендора о себе; **[inferred]** — косвенный вывод; **[unverified]** — не удалось проверить.

## Карточки

### 1. InfraNodus — эталон «поиска дыр в знаниях» (главный аналог практичной части)

**Функционально простым языком.** Инструмент Nodus Labs (Дмитрий Паранюшкин): любой текст/заметки/выдача поиска превращаются в сеть — слова-концепты как узлы, совместная встречаемость как рёбра. Поверх сети продукт делает три вещи: (а) показывает топ-темы (кластеры), (б) находит «структурные дыры» — пары тем, которые слабо связаны между собой, (в) через AI-панель генерирует вопросы и идеи, «мостящие» эти дыры. Продаётся именно как машина инсайтов: «что упущено в дискурсе», а не как рисовалка графов. [verified: https://infranodus.com/about/how-it-works, снимок 2026-07-05]

**Как именно устроен конвейер текст → граф** [verified: how-it-works]:
- лемматизация + стоп-слова; узел = лемма/концепт;
- ребро = совместная встречаемость в скользящем окне 4 слов (4-gram) — имитация краткосрочной памяти при чтении;
- размер узла = betweenness centrality (посредническая центральность): чем чаще концепт «мостит» разные темы, тем крупнее;
- кластеры = community detection по модулярности; один кластер = один цвет, узлы кластера стянуты на плоскости (Force Atlas).

**Как показаны дыры (gaps) в UI** [verified: how-it-works + https://infranodus.com/docs/content-gap-analysis]:
- алгоритм ищет пары топ-кластеров с высокой дистанцией и низкой связностью («the two topical clusters that could be better connected»);
- найденная пара подсвечивается на графе, а в боковой панели появляется текстовая формулировка дыры и кнопка «сгенерировать исследовательский вопрос/идею», которая через LLM предлагает мост между кластерами;
- отдельный режим «Difference view»: сравнение двух графов (например, «граф поискового намерения» vs «граф текущего контента») — подсвечиваются словосочетания, которые есть в одном графе и отсутствуют в другом. Прямой паттерн для Коры «где наполнено / где пусто».
- в Obsidian-плагине те же аналитики упакованы в панель: main topical clusters → key concepts (точки входа) → blind spots («некоторые темы плохо связаны — это слепые пятна между вашими идеями») → AI research questions → GPT-4-чат по содержимому графа. [verified: https://infranodus.com/obsidian-plugin]

**Вау-приёмы.**
- Живой граф, растущий по мере набора текста (в редакторе видно, как узлы появляются и кластеризуются) [triangulated(2): how-it-works + туториалы infranodus.com/docs].
- 3D Force Atlas-раскладка («advanced 3D Force Atlas layout») в Obsidian-плагине и отдельный 3D-интерфейс graph.infranodus.com — вращаемый 3D-граф; заявка на VR встречается только как запрос пользователей в поддержке, нативного WebXR не подтверждено. [triangulated(2): infranodus.com/obsidian-plugin + support.noduslabs.com/hc/en-us/community/posts/11410960420764; 3D-техстек — unverified]
- Главный вау у них не визуальный, а смысловой: «граф сам говорит, чего тебе не хватает» — превращение метрик сети в советы.

**Технически** [verified: https://infranodus.com/about/how-it-works]:
- рендеринг графа: **Sigma.js + Graphology** (упоминается и Cytoscape); раскладка Force Atlas 2D/3D;
- бэкенд: **NestJS + Prisma + PostgreSQL** — тот же стек, что у Коры (значит, все их серверные приёмы — BC, модулярность, детекция дыр — переносимы 1:1 на наш бэк);
- алгоритмы: betweenness centrality, community detection (modularity), детектор структурных дыр (structural gaps);
- LLM-слой: GPT-модели для генерации вопросов/идей и анализа; есть официальный MCP-сервер (github.com/infranodus/mcp-server-infranodus) — content gap detection как инструмент для AI-агентов [verified: GitHub];
- open source: старая версия 2020 г. (Node.js + Neo4j, AGPLv3, github.com/noduslabs/infranodus) — устарела, современная версия закрыта; облако от €9/мес [triangulated(2): GitHub README + noduslabs.com].
- лимиты по числу узлов в доках не заявлены [verified: отсутствие в доках].

**Что берём для Коры.**
1. **Формулу инсайт-панели целиком**: темы → ключевые концепты-мосты → слепые пятна → AI-вопрос «мостящий дыру». Это готовый UX-контракт практичной части: «между областью Продажи и областью Продукт нет ни одного связующего факта — спросить на следующей встрече?».
2. Размер узла = betweenness centrality (не degree!) — сразу выделяет концепты-мосты, а не просто частые слова.
3. «Difference view» → наш режим «что спрашивают у Коры vs что в ней есть» (карта пустот по реальным запросам в AI-чат).
4. Стек совпадает (NestJS+Prisma+Postgres) — серверные метрики графа реализуемы без новых технологий; graphology доступна и на фронте (у нас уже есть react-force-graph-2d, graphology совместима).

**Источники:** https://infranodus.com/about/how-it-works (2026-07-05) · https://infranodus.com/docs/content-gap-analysis · https://infranodus.com/obsidian-plugin · https://github.com/infranodus/mcp-server-infranodus · https://github.com/noduslabs/infranodus · ACM WWW'19 paper «InfraNodus: Generating Insight Using Text Network Analysis» (dl.acm.org/doi/pdf/10.1145/3308558.3314123).

### 2. Nomic Atlas (+ deepscatter) — карта миллионов точек как «галактика данных»

**Функционально простым языком.** Облачная платформа: загружаешь тексты/эмбеддинги (векторные представления смысла) — получаешь интерактивную 2D-«карту данных», где похожие по смыслу точки лежат рядом, а поверх регионов автоматически подписаны темы. Это не граф с рёбрами, а «семантическая местность»: плотные скопления = устоявшиеся темы, разреженные окраины = выбросы. [verified: https://docs.nomic.ai/atlas/datasets/data-maps/how-atlas-works/1-key_terms]

**Вау-приёмы.**
- Вид «звёздного неба»: сотни тысяч — миллионы светящихся точек, при отдалении читаются только крупные подписи тем, при приближении проявляются подтемы и отдельные документы (иерархия topic labels) [triangulated(2): docs key terms + docs how-to-visualize-embeddings; точная механика появления подписей по зуму в доках не расписана — inferred по продукту].
- Плавный zoom/pan по миллионам точек без потери кадров — эффект «бесконечной карты»;
- выбор области лассо → мгновенная выборка документов; поиск и фильтры по метаданным подсвечивают точки на карте [verified: docs].
- Автовыбор алгоритма проекции: до 50 000 точек — классические методы, больше — их проприетарный layout-оптимизатор [verified: docs how-to-visualize-embeddings].

**Технически.**
- Рендер — **deepscatter**: собственная WebGL-библиотека (REGL), данные в Apache Arrow Feather, кастомный quadtree-тайлинг (данные догружаются по мере зума, как тайлы карт) — заявлено «более миллиарда точек» в браузере; примеры: 5,5 млн твитов, 20 млн биомедицинских абстрактов, 1+ млн статей arXiv [verified: https://github.com/nomic-ai/deepscatter].
- **Критично для Коры: лицензия deepscatter — CC BY-NC-SA (non-commercial)** — в коммерческий продукт напрямую брать нельзя; 1.2k звёзд; последний релиз v2.10.0 — апрель 2023, развитие затихло (стабилен, но не развивается) [verified: GitHub, снимок 2026-07-05].
- Atlas — облако (данные уезжают к Nomic); тарифы: демо-план, дальше Pro/Enterprise по запросу [triangulated(2): atlas.nomic.ai/pricing + обзоры; точные лимиты бесплатного плана не подтверждены — unverified].

**Что берём для Коры.**
1. Саму метафору **«звёздное небо тем» как альтернативный вау-режим**: блоки-факты как светящиеся точки на смысловой карте, области компании как подписанные «созвездия», пустые регионы видны буквально как чёрные дыры. Для тысяч узлов на организацию это читаемее force-графа.
2. Паттерн «подписи тем по уровням зума» (semantic zoom) — решает главную боль force-графов: кашу из ярлыков.
3. Технологию брать НЕ у них: deepscatter некоммерческий и полузаморожен → брать Apple Embedding Atlas (карточка 3).

**Источники:** https://docs.nomic.ai/atlas/datasets/data-maps/how-atlas-works/1-key_terms (2026-07-05) · https://docs.nomic.ai/atlas/embeddings-and-retrieval/guides/how-to-visualize-embeddings · https://github.com/nomic-ai/deepscatter (релиз v2.10.0, 2023-04) · https://atlas.nomic.ai/pricing.

### 3. Apple Embedding Atlas — open-source «звёздное небо», готовое к встраиванию

**Функционально простым языком.** Открытый инструмент Apple (публикация Apple ML Research, статья arXiv 2505.06386): интерактивная визуализация больших наборов эмбеддингов целиком в браузере — точки, автоматическая кластеризация с подписями, контуры плотности, поиск похожих, перекрёстная фильтрация со связанными графиками (bar/line/bubble). Всё считается локально, данные не покидают машину. [verified: https://github.com/apple/embedding-atlas + https://apple.github.io/embedding-atlas/]

**Вау-приёмы.**
- Контуры плотности (KDE, оценка плотности ядром) поверх точек — «рельеф» смысловой карты: сразу видно ядра тем и разреженные пустоши; order-independent transparency — миллионы полупрозрачных точек без визуальной каши [verified: репо features].
- Автоматические подписи кластеров прямо на карте (autolabeling), realtime-поиск и подсветка ближайших соседей выбранной точки [verified: репо].
- Cross-filter: клик по столбику «источник = встречи за март» → карта мгновенно перекрашивается/фильтруется. Дашборд и карта — одно связанное целое (Mosaic-подход) [verified: репо + overview].
- Есть MCP-интеграция — AI-агент может запрашивать схему и гонять SQL по визуализируемым данным [verified: репо README].

**Технически.**
- Рендер **WebGPU** (WGSL-шейдеры), заявленная шкала — «до нескольких миллионов точек» с плавной производительностью [verified: репо + InfoQ 2025-11: https://www.infoq.com/news/2025/11/embedding-atlas/].
- Стек: TypeScript 33,6% / Rust 25,4% (WASM для вычислений) / Svelte 20,1% / Python 13,3%; данные — DuckDB-WASM + Mosaic (cross-filtering) [verified: GitHub language stats; DuckDB/Mosaic — triangulated(2): arXiv-статья + доки].
- Дистрибуция: `pip install embedding-atlas` (CLI, Jupyter-виджет, Streamlit) и **npm `embedding-atlas` с компонентами `EmbeddingView` / `EmbeddingViewMosaic` / `EmbeddingAtlas` + обёртки для React и Svelte** [verified: https://apple.github.io/embedding-atlas/overview.html].
- **Лицензия MIT, 4.8k звёзд, последний релиз v0.21.0 — 1 июня 2026** — свежий, активно живёт [verified: GitHub, снимок 2026-07-05].

**Что берём для Коры.**
1. **Главный технический кандидат на «вау»-режим «небо тем»**: MIT, npm, React-обёртка, WebGPU, миллионы точек — прямо встраивается в Next.js 16 (наши тысячи узлов для него — лёгкая нагрузка, значит бюджет производительности можно потратить на свечение/анимацию).
2. Паттерн «карта + связанные графики» → наш drill-down: столбики «областей компании» рядом с картой, клик = фильтр карты.
3. Контуры плотности как честный индикатор «наполнено/пусто» без выдумывания метрик.
4. Ограничение: это карта точек, НЕ граф с рёбрами — связи «кто с кем» она не покажет; нужна как второй режим рядом с force-графом, не вместо. [inferred]

**Источники:** https://github.com/apple/embedding-atlas (v0.21.0, 2026-06-01) · https://apple.github.io/embedding-atlas/overview.html · https://machinelearning.apple.com/research/embedding-atlas · arXiv 2505.06386 · https://www.infoq.com/news/2025/11/embedding-atlas/ (2025-11).

### 4. Kumu — ремесленная навигация по «карте отношений»

**Функционально простым языком.** Ветеран (с ~2013) веб-картирования отношений: люди/организации/факторы как элементы, связи как connections. Ценность — не в рендере, а в дисциплине навигации: декорации по данным, метрики, фокус-режимы, повествование по карте. [verified: https://docs.kumu.io/]

**Вау-приёмы / приёмы навигации.**
- **Prompted focus**: читатель стартует с ПУСТОГО экрана и раскрывает карту постепенно от выбранного элемента — рекомендованный приём для больших карт (вместо «вывалить всё сразу») [verified: docs.kumu.io + FAQ how-much-data].
- Decorations: размер/цвет/обводка элементов и толщина/цвет/тип линий управляются данными профиля через CSS-подобный язык — карта как «стилизуемый отчёт» [verified: docs].
- Встроенные метрики (closeness, betweenness, eigenvector centrality) + автоматическая community detection с окраской по сообществам и выделением «мостов» между ними [verified: docs SNA guide].
- Clustering: авто-создание узла на каждое значение поля («работодатель», «навык») и стягивание элементов к нему — мгновенная перегруппировка карты по любому атрибуту [verified: https://docs.kumu.io/guides/clustering].

**Технически.**
- Собственный 2D-рендерер (SVG/canvas), без WebGL; жёсткого лимита данных нет, но на больших импортах «анимации и загрузка начинают тормозить»; для 1000+ элементов рекомендован SNA-шаблон с режимом «fast» — элементы квадратами, связи прямыми линиями (деградация красоты ради скорости) [verified: https://docs.kumu.io/frequently-asked-questions/how-much-data-can-kumu-handle].
- Практический потолок комфорта — низкие тысячи элементов [inferred из их же рекомендаций].

**Что берём для Коры.**
1. **Prompted focus как паттерн drill-down**: вход в граф Коры не «всё сразу», а «пустота → область → темы → сущности → факты», каждый шаг догружается. Совмещает вау (рост на глазах) и практичность (не тонешь).
2. Декорации по данным: толщина ребра = число подтверждающих блоков, цвет узла = свежесть последнего упоминания — легенда «наполнено/протухло» без отдельных экранов.
3. Урок производительности: чистый 2D-DOM/SVG умирает на тысячах — Кора либо canvas/WebGL, либо агрегация уровней.

**Источники:** https://docs.kumu.io/guides/clustering (2026-07-05) · https://docs.kumu.io/disciplines/sna-network-mapping · https://docs.kumu.io/frequently-asked-questions/how-much-data-can-kumu-handle · https://docs.kumu.io/getting-started/first-steps.

### 5. mem.ai — сознательный отказ от графа: «панель вместо карты»

**Функционально простым языком.** AI-заметочник «self-organizing»: внутри — граф знаний + векторная БД, но **визуального графа в продукте НЕТ вообще** — это осознанная позиция. Вместо карты — панель «Heads Up»: при письме/встрече продукт сам подсовывает связанные заметки, коллекции, прошлые разговоры с этим человеком. [triangulated(3): https://aloa.co/ai/comparisons/ai-note-taker-comparison/mem-vs-reflect + https://theprocesshacker.com/blog/mem-ai-review + https://lovable.dev/guides/what-is-mem-ai]

**Вау-приёмы.** Нет визуального вау; их «магия» — проактивность: связи приходят к тебе в контексте работы, а не ты идёшь к связям. Mem 2.0 (начало 2026) — переписанный движок ради скорости [claimed: обзоры 2026].

**Технически.** Закрытый SaaS; деталей рендера нет (нечего рендерить). Knowledge graph + vector DB как внутренняя архитектура [claimed: обзоры/маркетинг].

**Что берём для Коры.**
1. Контр-пример и рынок-сигнал: часть рынка считает граф-визуализацию лишней. Ответ Коры — граф не как «красивая картинка для гиков», а как рабочий экран директора (наполненность, дыры, происхождение) + вау-демо. [inferred]
2. Приём «Heads Up» стоит украсть в ДРУГОМ месте продукта: в карточке встречи/чата Коры показывать «связанные узлы графа» — мост от текста к графу, повышает заходы в визуализацию. [inferred]

**Источники:** https://get.mem.ai/ · https://aloa.co/ai/comparisons/ai-note-taker-comparison/mem-vs-reflect (2025) · https://theprocesshacker.com/blog/mem-ai-review · https://lovable.dev/guides/what-is-mem-ai · https://skywork.ai/skypage/en/Mem-AI-Your-Personal-Knowledge-Engine-in-2025/1976181401534394368 (2025).

### 6. Supermemory — образцовый готовый React-компонент графа памяти

**Функционально простым языком.** Memory API «для эры AI» + консьюмерское приложение (28.2k звёзд GitHub). Для визуализации памяти публикуют отдельный React-пакет **`@supermemory/memory-graph`** и держат живой граф в своей консоли (console.supermemory.ai/graph): документы и «воспоминания» как сеть, где видно, как AI связал факты. Позиционируется как инструмент «сделать память осязаемой и отлаживаемой». [verified: https://supermemory.ai/docs/integrations/memory-graph + https://github.com/supermemoryai/supermemory]

**Вау-приёмы.**
- Типизированная геометрия узлов: документы — прямоугольники, memories — шестиугольники; связи с подписями. [verified: docs]
- **Рёбра-версии фактов: UPDATE (новый факт заместил старый) / EXTENDS (факт дополнен) / DERIVES (из паттерна выведен инсайт)** — эволюция знания видна прямо на графе; можно найти «осиротевшие» memories и неверные цепочки UPDATE [verified: docs + https://docs.bswen.com/blog/2026-06-02-visualize-ai-memory-graph/ (2026-06-02)].
- Два режима одного компонента: console (фильтры по spaces, пагинация, полный контроль, zoom 0.8x) и consumer (упрощённый встраиваемый виджет, 0.5x) [verified: docs].

**Технически** [verified: https://supermemory.ai/docs/integrations/memory-graph]:
- **Canvas 2D (не DOM), собственный рендерер + D3-force симуляция + spatial indexing**;
- оптимизации поимённо: viewport culling (рисуются только видимые узлы), level-of-detail (упрощение при отдалении), change-based rendering (перерисовка только при изменении состояния), pan/zoom через transform контейнера (GPU-матрицы вместо пересчёта геометрии);
- заявленная шкала: «сотни узлов эффективно»; для 1000+ документов — обязательная пагинация (дефолт 500 документов на страницу, props `hasMore`/`loadMoreDocuments`/`totalLoaded`);
- React ≥18, любые браузеры с Canvas 2D + ES2020;
- монорепо: MIT, релиз supermemory-server 0.0.3 от 2026-06-13, стек TypeScript/Cloudflare Workers/Remix/Drizzle/PostgreSQL [verified: GitHub, снимок 2026-07-05].

**Что берём для Коры.**
1. **Ближайший референс кода** нашей force-части: canvas + d3-force + culling + LOD — тот же подход, что react-force-graph-2d, но их список оптимизаций — готовый чек-лист производительности.
2. Типизация узлов формой (не только цветом) — области/темы/сущности/блоки различимы даже в монохроме.
3. **Рёбра UPDATE/EXTENDS/DERIVES → наша «история факта»**: «решение изменилось на встрече 12.03» как видимая цепочка версий — сильный ответ на «почему это здесь».
4. Честный лимит: canvas-force комфортен на сотнях узлов на экране → для «тысяч узлов организации» обязательна агрегация (области → темы) либо WebGL-режим.

**Источники:** https://supermemory.ai/docs/integrations/memory-graph (2026-07-05) · https://github.com/supermemoryai/supermemory (28.2k звёзд, MIT, релиз 2026-06-13) · https://docs.bswen.com/blog/2026-06-02-visualize-ai-memory-graph/ (2026-06-02) · https://console.supermemory.ai/graph · https://deepwiki.com/supermemoryai/supermemory/2.4-memory-graph-visualization.

### 7. Mem0 (+ OpenMemory) — вендор агентной памяти, который граф-UI СВЕРНУЛ

**Функционально простым языком.** Лидер «memory layer for agents». В платформе v2 был Graph Memory: извлечённые сущности + связи и **интерактивный Graph view в дашборде (только Pro/Enterprise)** — «изучай сущности, прослеживай связи, ищи и фильтруй по всему графу» [verified: https://docs.mem0.ai/platform/features/graph-memory]. В платформе v3 — разворот: **граф-визуализации из дашборда удалены**, поле `relations` из API убрано; сущности теперь линкуются невидимо и лишь поднимают ранжирование поиска («entity linking») [verified: https://docs.mem0.ai/migration/platform-v2-to-v3 + сниппет миграционного дока, triangulated(2)]. Локальный OpenMemory-дашборд (localhost:3000, управление памятью + доступами MCP-клиентов) — сворачивается (sunset) в пользу self-hosted сервера [verified: GitHub discussion #3599 + openmemory README].

**Вау-приёмы.** Не было; Graph view был утилитарным и пейволленным.

**Технически.** v3: собственный встроенный граф, «no external graph database» (раньше требовался Neo4j/Memgraph для OSS graph memory) [verified: миграционный док + docs graph-memory].

**Что берём для Коры.**
1. Рыночный сигнал: для API-first вендоров граф-UI — кост-центр, его режут первым. Кора — продукт для людей, у нас граф — экран продукта, и это дифференциатор против memory-API: **они убирают визуализацию, мы делаем её витриной**. [inferred]
2. Их довод «сущности полезнее в ранжировании, чем в отдельном graph-ответе» — совместим с нашей архитектурой: граф для ЧЕЛОВЕКА (навигация/доверие), не только для retrieval. [inferred]

**Источники:** https://docs.mem0.ai/platform/features/graph-memory (2026-07-05) · https://docs.mem0.ai/migration/platform-v2-to-v3 · https://mem0.ai/blog/introducing-openmemory-mcp (2025) · https://github.com/mem0ai/mem0/discussions/3599 · https://mem0.ai/blog/graph-memory-solutions-ai-agents (2026-01-20; сравнение 5 memory-решений — характерно, что колонка «визуализация» в нём вообще отсутствует).

### 8. Zep / Graphiti — темпоральный граф с provenance «всё сводится к эпизодам»

**Функционально простым языком.** Graphiti — open-source движок темпоральных графов знаний для агентов: события-«эпизоды» (сообщения, документы) → сущности и факты; каждый факт-ребро несёт интервалы валидности (t_valid, t_invalid) — при противоречии старый факт не стирается, а помечается невалидным с сохранением истории. Zep Cloud — коммерческая надстройка. В дашборде Zep: кнопка **«View Graph»** на профиле пользователя → интерактивный граф, зум, клик по узлу/ребру открывает детали; есть графы групп. Запущено в декабре 2024. Назначение — «исследовать, как устроена память» = отладка доверия. [verified: https://blog.getzep.com/knowledge-graph-explorer/ (2024-12) + https://help.getzep.com/graphiti/getting-started/welcome + https://github.com/getzep/graphiti]

**Вау-приёмы.** Минимальные: инженерная визуализация. Сильная идея — «everything traces back to episodes»: любой узел графа прослеживается до сырого источника [verified: docs/graph-overview].

**Технически.**
- Открытый референс-вьюер **getzep/zep-graph-visualization: Next.js 15 + React 19 + D3.js (force-directed) + Tailwind + shadcn, MIT**, цвета узлов по типу сущности, панели деталей узла/ребра, zoom/pan, тёмная/светлая тема; 13 звёзд, 6 коммитов — маленький, но это официальный образец под наш же стек [verified: https://github.com/getzep/zep-graph-visualization].
- Graphiti: Neo4j/FalkorDB как хранилище; би-темпоральная модель; инкрементальные обновления без пересчёта батчем [verified: GitHub getzep/graphiti + neo4j.com blog].

**Что берём для Коры.**
1. **Provenance-паттерн — ядро ответа на «почему это здесь, из какой встречи»**: клик по факту → эпизод-источник (встреча/чат, момент времени). У нас данные для этого уже есть (IdeaBlock → источник).
2. Темпоральность как UI: факт с t_invalid отображать «угасшим» (устарел, заменён) — честная память вместо свалки; плюс timeline-слайдер «как выглядел граф месяц назад» [inferred из би-темпоральной модели].
3. Их референс-вьюер (Next 15 + React 19 + D3, MIT) можно разобрать на паттерны панелей деталей — стек совпадает с нашим фронтом.

**Источники:** https://blog.getzep.com/knowledge-graph-explorer/ (2024-12) · https://github.com/getzep/zep-graph-visualization (MIT) · https://github.com/getzep/graphiti · https://help.getzep.com/graph-overview · https://neo4j.com/blog/developer/graphiti-knowledge-graph-memory/ · https://blog.getzep.com/a-visual-guide-to-knowledge-graphs-for-ai-agents/.

## Сводка: топ-выводы контура

1. **Две несмешиваемые парадигмы визуализации памяти.** (а) Force-граф с рёбрами (InfraNodus, Supermemory, Zep): сущности+связи первосортны, комфортная шкала — сотни..низкие тысячи узлов на экране (canvas 2D + culling/LOD; Supermemory прямо пишет «hundreds of nodes», 1000+ только с пагинацией [verified]). (б) Эмбеддинг-карта без рёбер «звёздное небо» (Nomic Atlas, Apple Embedding Atlas): миллионы точек на WebGL/WebGPU, темы как подписанные регионы, пустоты как буквальные дыры в плотности [verified]. Кора с «тысячами узлов на организацию» стоит ровно на границе → двухрежимность: force-граф для drill-down по связям + карта-небо для полного обзора.

2. **InfraNodus — готовый чертёж «практичной» части.** Их формула: betweenness centrality (размер узла = концепт-мост) + кластеры по модулярности (цвет = тема) + детектор структурных дыр между кластерами + AI-панель, генерирующая вопрос-мост через дыру + Difference view (чего нет в графе A по сравнению с B) [verified]. Бонус: их бэкенд — NestJS+Prisma+PostgreSQL, наш стек — переносимо без новых технологий.

3. **Для «неба тем» есть свежий MIT-компонент от Apple.** Embedding Atlas: WebGPU, «до нескольких миллионов точек», плотностные контуры, автоподписи кластеров, cross-filter, npm-пакет с React-обёрткой, v0.21.0 от 2026-06-01, 4.8k звёзд [verified]. Deepscatter (движок Nomic) — CC BY-NC-SA (некоммерческая) и без релизов с 2023 — в коммерческую Кору не годится [verified].

4. **Агентные памяти дружно отступают от граф-UI — это наша полка.** mem.ai графа не имеет принципиально (панель Heads Up вместо карты) [triangulated(3)]; Mem0 в v3 удалил Graph view из дашборда и relations из API [verified]; Graphlit — API-only [verified]; Zep держит утилитарный D3-вьюер для отладки [verified]. Единственный, кто вкладывается в UI-компонент — Supermemory. Красивый «граф памяти компании» как продуктовая витрина у конкурентов по памяти отсутствует.

5. **Provenance и версии фактов — два паттерна доверия, которые надо взять.** Zep: «всё сводится к эпизодам» — клик по факту ведёт к источнику; би-темпоральность (t_valid/t_invalid) позволяет показывать устаревшие факты «угасшими» и мотать время [verified]. Supermemory: типизированные рёбра UPDATE/EXTENDS/DERIVES делают эволюцию знания видимой [verified]. Вместе это ровно наш сценарий «почему это здесь, из какой встречи, не протухло ли».

6. **Навигационные приёмы для «не утонуть в тысячах узлов» уже канонизированы.** Kumu prompted focus (старт с пустого экрана, раскрытие от узла) и деградация рендера на 1000+ элементов [verified]; Nomic/Apple — semantic zoom с иерархией подписей тем [verified/inferred]; Supermemory — viewport culling + LOD + пагинация [verified]. Вывод для Коры: drill-down «область → тема → сущность → факты» с ленивой подгрузкой — обязателен, «весь граф сразу» показывать только в агрегированном виде (области+темы).

7. **Вау и практичность у лидеров разведены по слоям, а не по экранам.** InfraNodus: тот же граф, но панель инсайтов сбоку; Embedding Atlas: та же карта, но связанные графики рядом. Ни один продукт контура не делает «отдельный красивый экран + отдельный полезный» — визуальный слой один, режимы/панели меняются. Для Коры: один canvas, поверх — режимы «полёт/обзор» и «аналитика/дыры». [inferred из совокупности]
