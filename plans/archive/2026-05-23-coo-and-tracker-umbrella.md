# COO + Tracker — зонтичный план единого продуктового рывка

## TL;DR

Это **один интегрированный продуктовый рывок**: бесплатный таск-трекер для команды как точка входа, поверх — AI-операционный директор и второй мозг компании как платный слой. Всё связано: задачи → ingest в knowledge-core → специалисты → дашборд COO. Срок: **23-30 недель веб + 10-12 недель параллельной нативной мобилки**. Все sub-ТЗ ниже — атомарные, маленькие, без падений на размере. Этот документ — план оркестратору: что делать, в каком порядке, что параллельно.

## Принятые решения владельца (свод)

### 7 продуктовых решений (2026-05-23)

| # | Решение |
|---|---|
| 1 | **Сразу средний бизнес (50-200), но простота не теряется.** БЕЗ SSO — главный администратор приглашает по email. |
| 2 | **10-15 шаблонов «команд», не отделов.** В Фазе 4. Метафора — команда. |
| 3 | **Цели → Задачи с Фазы 1.** Связь моделей сразу + AI-агент стратегического согласования. |
| 4 | **Видеовстреча из задачи — да.** Фаза 2, кнопка на странице задачи. |
| 5 | **Мобилка — два потока параллельно:** PWA + нативная Expo. |
| 6 | **1С не сейчас.** Phase 6+ под первого Mid-клиента. |
| 7 | **Закрытый код, проприетарная SaaS.** Никакого open-source. |

## Дополнительные фичи, согласованные в диалоге

1. **Чат-в-задаче** (по образцу YouGile, поверх chat-v2 с голосом) — Фаза 2.
2. **Видеовстреча из задачи** — Фаза 2.
3. **Ленты активности с вопросами агентов** (Probe Feed со статусами доставлен/прочитан/отвечен) — отдельное sub-ТЗ.
4. **Публичная лента инсайтов** — все видят что находят коллеги. Activity Feeds.
5. **Геймификация: «спасибо» / стрики / бейджи / Recognition Agent** — отдельное sub-ТЗ.
6. **Helpfulness Agent (Specialist 3.8)** — выявляет помощников из переписки и созвонов, формирует спотлайты. Отдельное sub-ТЗ.

## Что НЕ входит в этот рывок (откладывается)

- 1С интеграция (Phase 6+ или отдельный sub-ТЗ для Mid-клиента)
- СМЭВ
- Open-source трекера
- Десктоп-приложение (web + PWA + нативная мобилка покрывают потребности)
- ФСТЭК-сертификация (закладываем архитектуру, не запускаем процесс сертификации в Wave 1-3)
- Apple Watch / Siri Shortcuts (мобилка v2)
- Контур.Диадок (ЭДО)

## Метрика готовности к запуску

**Готовы к публичной бета-версии трекера** когда:
- Фаза 1-4 веб закрыты + первичные тесты
- 10 шаблонов команд активны
- Telegram-бот работает
- Импорт из 1 источника (Битрикс24) работает
- COO Dashboard + чек-ины работают для одного пилотного клиента
- Activity Feeds работают
- Helpfulness Agent выдаёт первые спотлайты
- 95%+ unit + integration тестов проходят
- Сертификат хостинга в РФ + 152-ФЗ чек-лист закрыт

## Архитектурный принцип всего рывка

**Каждое событие — источник для второго мозга.** Не существует «события трекера», «события чек-ина», «события переписки» как отдельных миров. Всё попадает в knowledge-core через тот же pipeline (`Source → RawEvent → IdeaBlock → Entity → Card`), просто с разным `signalType`. Это и есть **единый граф знаний компании**.

Если что-то не попадает в граф — оно теряется. Никакие исключения.
