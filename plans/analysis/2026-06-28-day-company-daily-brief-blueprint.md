## 1. Что это и зачем

**«День компании»** — первое и самое видное, что видит владелец при входе: **связный текстовый отчёт «как прошёл день»** с быстрым вердиктом-обложкой и разворачиваемыми блоками. Это реализация **Executive-слоя** (брифинг собственника) в разрезе одного дня.

Сегодня владелец при входе видит **сетку из ~10 виджетов-цифр** («Сегодня») — числа без истории. Разворачиваем на 180°: сверху — **повествование** (что произошло, почему, что делать), цифры уезжают вниз под спойлер.

### Развязка путаницы «Сегодня» vs «Ежедневный отчёт»

Сейчас в кабинете два пересекающихся ежедневных места (это и есть болезнь «расплодили дашборды» из аудита [2026-06-25-dashboards-architecture-audit](2026-06-25-dashboards-architecture-audit.md)):

| | «Сегодня» (`/dashboard`) | «Ежедневный отчёт» (`/dashboard/operations/daily`) |
|---|---|---|
| Что | главный экран при входе | под-страница вкладки «Аналитика» |
| Вид | сетка виджетов-цифр | текстовый дайджест |
| Рассылка | нет | да (Telegram/email, ночью) |

**Решение владельца:** «День компании» = **самый верхний, самый первый экран**. Значит:
- он становится новым верхом `/dashboard` (бывш. «Сегодня»); виджеты-цифры → вниз под «Показать цифры»;
- «Ежедневный отчёт» из «Аналитики» по смыслу — **тот же артефакт**; его рассылка в Telegram становится рассылкой «Дня компании»;
- слияние/чистку делаем **по шагам** позже (что-то удалим, что-то объединим) — сейчас фиксируем, что это одна сущность в двух местах.

## 2. Зафиксированные решения (2026-06-28)

1. **Место** — главный экран при входе владельца (верх `/dashboard`). По шагам сливаем с «Ежедневным отчётом».
2. **Вердикт — 4 оси** (светофор): **Команда · Клиенты · Исполнение · Общий**. + **обязательно читаемый текстовый отчёт** (главный артефакт), + на будущее **озвучка (TTS)** — текст пишем чистой прозой, чтобы лёг в TTS без переделки.
3. **Сборка — map-reduce**: каждый источник сжимаем отдельно → финальный синтез собирает «День компании». Дёшево, стабильно по токенам, сохраняет провенанс (ссылки на источник).
4. **Запуск — самый поздний ночной прогон**: синтез идёт **после** ночной синхронизации Bitrix и chatbox (как финальная стадия), к утру по МСК готово. Зависимость по завершению синков, а не фиксированный час (chatbox-крон бежит 00:00 UTC = 03:00 МСК). + кнопка «Пересобрать».
5. **Каждый блок отчёта** — краткая выжимка → «развернуть» → полный текст + источники.

## 3. Что отдаём агенту — входной пакет (8 блоков)

Не сваливаем сырьё в один промпт — собираем структурированный пакет, где каждый источник пред-сжат.

| # | Блок | Что внутри | Источник в Коре | Полнота |
|---|---|---|---|---|
| 1 | Шапка дня | дата, день недели, кто активен, главная цель + вектор | Goal.isPrimary, goal-vector | факты |
| 2 | Встречи | по каждой: тип, участники, **готовый AI-отчёт** (резюме/решения/задачи/риски) | meeting report pipeline | сжато (отчёт, не транскрипт) |
| 3 | Переписки | сжатие **по каждому чату**: сигналы клиента (боль/отток/запрос), обещания, договорённости, конфликты | chatbox + Bitrix24 | «полностью» по смыслу = per-chat сжатие |
| 4 | Планы и отчёты людей | утро (план) + вечер (факт: сделано / не сделано / что помешало / мысли) + дисциплина (кто не сдал план/отчёт) + **сверка план↔факт по людям** | DailyCheckIn + discipline | структурно |
| 5 | Свободные мысли | сырые смыслы из телеги | IntakeIssue / checkin-fixator | сыро |
| 6 | Исполнение | задачи недели + ход: закрыто/создано/просрочено/застряло за день, блокеры, обещания в риске | Issue + execution feed | факты |
| 7 | Решения дня | что решили; что НЕ превратилось в задачи (утечка) | Decision (impliesAction) | факты |
| 8 | Вчерашний анализ | вчерашний отчёт «День компании» (вердикт + «на что обратить внимание») | снапшот за вчера | замыкание петли |

**Что добавили против первой мысли владельца** (он назвал встречи/чаты/планы/мысли/задачи/идеи):
- **Решения дня** (п.7) — отдельная и более важная сущность, чем «идеи».
- **Исполнение за день** (закрыто/создано/просрочено) — половина смысла «как прошёл день».
- **Дисциплина + настроение чек-инов** — сильнейший сигнал оси «Команда».
- **Конфликты/трения** — ось «Команда».
- **Замыкание петли со вчера** (п.8): «вчера обещали разобрать X → что с X сегодня» — превращает снимок в фильм.
- **Деньги/финансы — осознанно вне MVP** (нет источника) → в реестр не-сделанного.

## 4. Что получаем — шаблон отчёта «Как прошёл день»

**Обложка (вердикт):** эмодзи + заголовок-настроение + одна фраза + 4 оси (Команда/Клиенты/Исполнение/Общий), каждая со статусом и одной строкой «почему» + мета («собрано в …, покрыто N источников»).

**Письмо Коры** — блоки, каждый «кратко → развернуть → полно + источники»:

| # | Блок | Содержание |
|---|---|---|
| 1 | Главное за день | 3–5 фактов, каждый с источником |
| 2 | Что сделано | ключевые результаты |
| 3 | Что не сделано / просрочено | план vs факт компании |
| 4 | **Отчётность и план↔факт** | кто написал план/отчёт (%), **подсветка «кто молчит»**, и сверка план↔факт по людям (сошёлся / разошёлся) |
| 5 | Что помешало | причины языком корневых причин, не симптомов |
| 6 | Решения дня | что решили + что надо завести в задачи |
| 7 | Клиенты | сигналы, обещания, риск оттока |
| 8 | Идеи компании | из отчётов + intake + переписок |
| 9 | На что обратить внимание | рефлексия Коры: риски, паттерны, что повторяется со вчера |
| 10 | 3 действия на завтра | конкретные рекомендации |
| 11 | Динамика ко вчера | стало лучше/хуже по осям |

**Блок «Отчётность и план↔факт» — отдельная цель.** Отчёт не только показывает день, но и **гонит команду наполнять базу**: план утром → отчёт вечером (сделано/не сделано/что помешало/мысли). Из этого: (а) дисциплина — кто написал, кто молчит (подсвечиваем поимённо); (б) **план↔факт** — у тех, кто отчитался, видно, сошёлся ли утренний план с вечерним фактом; у кого нет отчёта — план↔факт не сверить (ещё аргумент добивать отчётность). При большой команде имена сворачиваются в **процент** + короткий список «кто молчит». Полная дисциплина и план↔факт по дням/людям **цифрами** — в отдельном дашборде «Отчётность» (этот разбор — текстом, тот — в числах).

**Вердикт — как считаем (гибрид):** детерминированно считаем вектор сигналов (план-факт %, просрочки, новые блокеры, негативные клиентские сигналы, дисциплина чек-инов, настроение, конфликты) → отдаём агенту как факты → агент пишет нарратив и назначает цвет по каждой оси, но с ограничителями (красный сигнал по ключевому клиенту ⇒ ось «Клиенты» не может быть зелёной). Объяснимость + человеческий текст.

## 4а. Состав главного экрана — «квадратики» (при свёрнутом отчёте)

Порядок сверху вниз (наращиваем по шагам):
1. **Обложка-вердикт** (4 оси) — «как прошёл день» с одного взгляда.
2. **«Читать полный отчёт за день»** — одна кнопка → всё письмо целиком (§4). Идёт **перед** остальными квадратиками: сначала читаем отчёт, потом ниже — постоянные квадратики.
3. **Цель и компас** — стрелка к цели (балл из `goal-alignment`) + «сегодня к цели +N/10»; разворот «Почему так?» → pro/contra (что двигало цель, что мимо). Видно: команда активна, но к цели идёт малая часть — и почему.
4. **Зависшие и просроченные задачи ↔ кто просрочил** (связаны фильтром):
   - слева: просроченные (название + ответственный, **клик → трекер**), топ-5 старейших + «показать все»; ниже — без ответственного / без срока;
   - справа: топ сотрудников по числу просрочек (бар + счётчик); **клик → фильтрует список слева** (видно, у кого всё просрочено и кто «узел»).
5. **Что мешает / риски ↔ Идеи** (два списка рядом, у каждого короткое AI-резюме за день):
   - слева — «Что мешает / риски»: список инсайтов с **бейджем повторяемости** (всплеск ×N / растёт / новое), клик → радар; топ-5 + «показать все»;
   - справа — «Идеи»: список идей/кластеров с бейджем (поддержали N / кластер / ново), клик → идея; топ-5 + «показать все»;
   - сверху каждого — **резюме дневного агента**: что повторяется и что происходит (отдельно по рискам, отдельно по идеям).
6. **Польза Коры за период** — последний виджет: 5 счётчиков пользы (встреч запротоколировано · задач извлечено · задач решено · идей собрано · ответов из памяти). Решения и договорённости/обещания из набора **убраны**. Спойлер «цифры дашборда» удалён — вектор ушёл в компас, «что зависло» — в квадратик задач. **На этом экран закрыт** (больше виджетов не добавляем).

## 5. Пример отчёта (эталон → из него делаем шаблон)

> Тот же текст живёт в прототипе. Здесь — как «золотой образец» формулировок и тона.

**⚠️ День с трением** · Пятница, 27 июня 2026
_Команда в норме, но день держат две вещи: «Молочные реки» 2-й раз написали про молчание поддержки (риск ухода), а интеграция чат-бокса снова сдвинулась из-за неоплаченных коннекторов. Всё критичное опять упёрлось в тебя одного._

- **Команда — Норма** · настроение зелёное (5/6), но Айназ не сдала вечерний отчёт
- **Клиенты — Риск** · «Молочные реки» — 2-е упоминание молчания поддержки
- **Исполнение — Буксует** · закрыто 3 из 7 · блокер оплаты висит 6-й день
- **Общий — Трение** · 1 красная зона, 1 жёлтая — нужен твой шаг

**Главное за день:** повторный сигнал «Молочных рек»; застрявшая 6-й день оплата коннекторов; согласованные с подрядчиком условия внедрения без заведённых задач; запущен 1-й из 10 тестов («Орбита»); идея Айназ про чек-лист онбординга.

**Что помешало:** корень не в людях — узкое место «всё на Сергее» (оплата, подрядчик, КП — только через тебя); Битрикс24 4-ю встречу подряд не даёт дисциплины задач.

**На что обратить внимание (рефлексия):** 3-й день всё критичное упирается в тебя — это паттерн bus-factor, дешевле делегировать оплату/КП. Петля со вчера: 26.06 отмечала молчание поддержки → сегодня повтор, риск вырос ⚠️→🔴.

**3 действия на завтра:** (1) снять/делегировать блокер оплаты; (2) ответить «Молочным рекам» + отправить КП; (3) завести 3 задачи по решению с подрядчиком.

## 6. Архитектура: откуда что берётся (переиспользуем агентов, НЕ плодим новых)

**Принцип:** почти всё сырьё и «умные» куски УЖЕ считают существующие воркеры/агенты. «День компании» — финальный **синтез-слой поверх готового**, а не новые агенты.

| Блок отчёта / квадратик | Данные | Существующий агент/сервис (reuse) |
|---|---|---|
| Встречи | meeting reports | `meeting-report-fast` |
| Переписки (клиенты/внутр.) | chatbox + Bitrix | `chatbox-summary` + `chatbox-analyze.worker` |
| Планы/отчёт + дисциплина + план↔факт | DailyCheckIn | `day-signal-detect` (универсальный фиксатор) + `checkin-discipline` + `WeeklyPerPersonService` + `checkin-sentiment-batch` |
| Свободные мысли | intake | `Specialist315Tasks` / IntakeIssue |
| Зависшие/просроченные задачи + кто просрочил | Issue/tracker | `dashboard.stuck` (stale) + блокеры + агрегат по `assigneeUserId` (счёт просрочек на человека) |
| Решения | Decision | `decision-extract` + throughput/stalled |
| Клиенты под риском | customer risk | `CustomerRiskRadarService` |
| **Что мешает / риски (+ повторяемость)** | Insight | **Specialist 3.5 Insights Radar** — `Specialist35Service` + `insight-extract`/`insight-link-to-decisions`; берёт блоки `signalType ∈ {pain,risk,churn_risk,objection}`, кластеризует, **уже считает динамику** `dynamicLabel ∈ {spike,growing,stable,declining}` (`InsightClustererCron` 7d/30d) + `GET /insights/top`. Повторяющееся подсвечено готово. |
| **Идеи (+ кластеры)** | Idea / IdeaCluster | **Specialist 3.6 Ideas Collector** — `Specialist36Service` + `idea-extract`/`idea-cluster-merge`/`idea-status-summarize`; блоки `signalType ∈ {idea,feature_request}` → `Idea` + `IdeaCluster` (`IdeaClustererCron`) + `weight`/`supporterCount`. `GET /ideas`, `GET /idea-clusters`. |
| **Дневное резюме «что повторяется / что происходит»** | Insight.dynamicLabel + IdeaCluster + вчерашний снапшот | **синтез Дня компании** читает топ инсайтов (с динамикой) + топ идей/кластеров + снапшот за вчера → короткий текст + подсветка повторяющегося. НЕ новый извлекающий агент — повторяемость уже в 3.5/3.6. |
| **Цель/компас + «почему идём/не идём»** | Goal + GoalAlignmentSnapshot | **`strategic-alignment.worker` + taskType `goal-alignment`** (даёт `score` + `explanation` + `signals.pro/contra`) + `getGoalVector` (proScore/contraScore/byDepartment) + `getGoalVectorByPerson` (reasons) |
| Настроение | check-in sentiment | `checkin-sentiment-batch` |
| Сам дневной дайджест | DailyOperationsDigest | **`operations-daily-digest` cron + taskType** (уже двухстадийный — РАСШИРЯЕМ его) |

**Ключевое:**
- «Почему идём/не идём к цели» **уже** считает `strategic-alignment.worker` (крон 04:00) → `GoalAlignmentSnapshot{score, explanation, signals.pro/contra}`. День компании это **читает**. Дневной разрез («сегодня действия двигали цель или нет, и почему») добавляет синтез из дневных данных.
- Дневной отчёт = **расширение** существующего `operations-daily-digest` (он уже бежит ночью двухстадийно), а не новый пайплайн.
- «Зависшие задачи / кто просрочил» — из трекера (`Issue`): stale + overdue + unassigned/no-due; «кто просрочил» = агрегат по `assigneeUserId`. Клик задачи → трекер; клик сотрудника → фильтр списка. Без новых агентов.

**Поток (map-reduce):**
1. (reduce уже есть) per-source summaries: `meeting-report-fast`, `chatbox-summary`, `day-signal`/checkins.
2. (deterministic) сигналы вердикта: план-факт, просрочки, блокеры, негативные клиентские сигналы, дисциплина, настроение, конфликты, customer-risk, decisions stalled, overdue-by-person.
3. (read) последний `GoalAlignmentSnapshot` по активным целям + goal-vector pro/contra.
4. (synthesize) ОДИН capable LLM-вызов: вход = пакет (8 блоков) + цели + вчерашний снапшот → выход = **структурный JSON** `{verdict{4 оси}, sections{...}, goalAlignment{direction, why, pro[], contra[]}, actions[], deltaVsYesterday}`. Мысль владельца: один главный вызов выдаёт и письмо, и секцию цели — сырой JSON не показываем, рендерим в экран.
5. (render) обложка → письмо → компас → зависшие задачи. Всё из JSON + готовых выборок трекера.
6. (persist) снапшот за день (динамика + вход «вчера»).

**Запуск/доставка/промпты:** финальная стадия ночного пайплайна после Bitrix+chatbox sync, к утру МСК; снапшот persist; рассылка поверх существующего; промпт синтеза — из админки (registry + code-fallback).

**Открытый тех-вопрос (в ТЗ):** расширяем `operations-daily-digest` ИЛИ заводим `company-day-synthesize` рядом? Рекомендация — расширить существующий (одна точка, меньше дубля).

2. Перенести согласованное в доводочную аналитику (`plans/analysis/`): точные источники-эндпоинты, правила вердикта, контракт пакета и снапшота.
3. ТЗ (`plans/tz/`): пайплайн map-reduce + синтез-промпт + экран + рассылка + персист, по фазам.
