# Рефлексия — интеграция изменений другого разработчика через rebase + докоммит маркетинга

## Что было поставлено

1. Подтянуть к нам в `dev` 12 коммитов другого разработчика из `origin/dev` (инфра/код: docker compose bun, Prisma 7, NestJS 11, Next 16, локальный LiveKit, vexp MCP-хук в `.claude/`).
2. Сохранить наши 5 локальных docs-коммитов (маркетинг/GTM/онтология) и working-tree-наработки.
3. Закоммитить и запушить оставшийся маркетинг (corner-case: часть корзины успела закоммититься в параллельной сессии).

## Как решал

1. **Перед действиями — разведка.** `git fetch --all`, `git log --graph --all`, `git diff --name-only 4b38130..origin/dev` и `..HEAD` — убедился, что **0 пересечений** по файлам между нашими docs-коммитами и их код-коммитами. Это превратило задачу из «сложный merge» в «чистый rebase».
2. **`git pull --rebase --autostash origin dev`** — одной командой: автостеш uncommitted, rebase 5 наших docs-коммитов поверх 12 их код-коммитов, автоматический unstash. На Windows + Git Bash отработало без вопросов.
3. **Корзины перед `git add`.** Разнёс 19 untracked + 2 modified на:
   - A: «точно моё» (маркетинг/GTM/онтология, ~17 файлов)
   - B: «спорное» (`.claude/hooks/*.py`, `backend/scripts/quick-host-link.ts`, `delivery/`, `docs/z-overview-for-integrators.md`) — оставил пользователю
   - C: предложил в `.gitignore` хук `pre-bash-guard.py` (локальная Windows-замена jq).
4. **Параллельная сессия закоммитила большую часть A пока я перечитывал git log.** Перепроверил `git status` перед `git add` — у меня осталось 3 untracked + 1 modified из изначального плана. Сделал один коммит, push.

## Что вышло

- Rebase 5/5 коммитов без конфликтов, наши хеши изменились (`56ed062 → 7d7e30a` и т.д.), working tree вернулся бит-в-бит.
- Финальный коммит `f44ca68 docs(marketing): анализ конкурентов + market research 2026 + навигация в second-brain/index` запушен в `origin/dev`.
- Ветка `dev` ровно равна `origin/dev`. Зеркало с другим разработчиком восстановлено.
- В working tree остались только спорные файлы корзины B и не моя правка `CLAUDE.md` + новый план `2026-05-21-ontology-process-regulation.md` (созданы в параллельной сессии — не трогаю).

## Чему научился

1. **`git pull --rebase --autostash`** — золотой стандарт для интеграции «чужих» изменений когда нет file-overlap. Одна команда, чистая история, working tree не страдает.
2. **Diff `--name-only` форкпойнт..их / форкпойнт..наши перед любым integration-выбором.** За 30 секунд видно — пересечение есть или нет; от этого зависит выбор между merge / rebase / cherry-pick / ручным разруливанием.
3. **Корзины + явный перечень путей в `git add`** > `git add -A`. Особенно когда в untracked лежат файлы из разных источников (мои, чужие, локальные hook'и для Windows).
4. **Перед `git add` всегда повторный `git status`** — параллельные сессии (другой Claude Code в другом окне) могут уже закоммитить часть из вашей корзины, и ваш `add` подхватит то, что не ваше / устарело.
5. **CRLF-предупреждения git на Windows** — шумные, но безопасные при наличии стандартного `core.autocrlf`. Не блокируют коммит, можно игнорировать.
6. **vexp MCP стал mandatory** (новый `.claude/CLAUDE.md` от другого разработчика): для поиска по коду — `run_pipeline`, а не Grep/Glob/Bash. Для docs-задач (second-brain/marketing) — не критично, но учту для следующего захода в backend/frontend код.
