# Слияние трёх веток разработчика в одну → dev → PR

## Что было поставлено

Другой разработчик наплодил три ветки (все отставали от `dev` на 4 коммита):
- `feature/edinyy-pomoshnik-arhitektura` (26 ↑)
- `feature/task-decision-disambiguation` (15 ↑)
- `fix/meeting-tasks-widget-visibility` (4 ↑)

Задача: слить все три в одну ветку, влить туда `dev`, решить все конфликты самостоятельно, открыть PR. Без уточняющих вопросов.

## Как решал

Сначала измерил топологию через `git rev-list --count` (ahead/behind попарно) вместо того чтобы вслепую мержить три ветки:
- `A..B = 0` → **B полностью внутри A** (task-decision-disambiguation — это нижние 15 коммитов стека edinyy-pomoshnik). Отдельно вливать B не нужно.
- `A..C = 2` → у C два уникальных doc-коммита (ТЗ виджета 404 + рефлексия), остальное общее с A.

План: ветка `feature/edinyy-pomoshnik-merged` от `origin/dev` (так dev сразу внутри — «отставание» снято by construction) → `merge A` → `merge C`.

Предварительно сверил пересечение файлов (`comm -12` списков изменённых файлов A и dev): единственный общий — `second-brain/04_не-сделано/README.md`. Онбординг-правки dev и код единого помощника лежат в разных модулях.

## Что вышло

- **Конфликтов слияния — ноль.** Общий README смержился автоматически объединением строк (ort strategy).
- Итог: 30 ↑ / 0 ↓ относительно dev; все 4 исходных ref содержатся (`HEAD..ref = 0` для каждого).
- Верификация: backend `tsc --noEmit` → 0 ошибок (heap 8 ГБ против ложного OOM), frontend `tsc --noEmit` → 0 ошибок. Маркеров конфликта в коде нет. `schema.prisma` слиянием не затронут → Prisma-клиент в синке.
- Ветка запушена. **PR не создан автоматически:** `gh` не авторизован, `GH_TOKEN`/`GITHUB_TOKEN` пусты — push прошёл по SSH-ключу, но GitHub API для `pr create` требует токен. Отдал владельцу прямую ссылку на создание PR + готовые title/body.

## Чему научился

- **Перед «слить N веток» — измерить containment попарно.** Стеки веток часто вложены (superset/subset): здесь B был полностью внутри A, наивный тройной merge сделал бы лишнюю работу и плодил бы пустые merge-коммиты.
- **Ветка от `origin/dev` + merge фич == «влить dev в фичи»** по конечному состоянию, но даёт чистый PR-дифф против dev и снимает «отставание» без отдельного шага.
- **Push по SSH ≠ возможность открыть PR.** В этом окружении SSH-ключ есть, а GitHub API-токена нет — `git push` работает, `gh pr create` падает. Это потолок автономности здесь.
