# Закрыть дыры: снятый вопрос → сигнал не теряется (research-first мосты)

## Принцип
Когда Кора перестаёт **спрашивать** человека, сигнал не должен исчезнуть. Он обязан приземлиться:
- **задачей** — там, где есть детерминированный владелец (обещание → его автор; эксперимент → владелец эксперимента);
- **авто-заполнением** — там, где ответ выводим из данных (атрибуция клиента по лестнице владения; экспертиза по порогу уверенности);
- **дашбордом/уведомлением** — там, где владельца нет и решать не срочно (сигнал обострился, непривязанные сущности).

Это дословно рубрика судьи (P1–P8): по каждому drop/automate вердикт один — «убрать диалоговый вопрос, но сигнал вынести индикатором в дашборд/сводку; где можно — авто-заполнить». Мы не изобретаем политику, а доводим уже одобренную.

## Решения владельца (2026-07-06, не пересматривать)
1. **Эксперимент** — «эксперимент = задача» владелец делает ОТДЕЛЬНЫМ кодом. В этом объёме: НЕ возвращать сигнал уведомлением — просто оставить снятым (вопрос уже не задаётся). FYI-хвост (на треке владельца): живое проактивное уведомление «эксперимент затянулся» + застревание статуса `running` при результате без урока.
2. **Insight «обострился»/«повторился после плана»** — место = **ДАШБОРД** (пульс рисков), не вопрос и не задача. Риски уже богато на дашборде (`InsightsTopWidget`/`CustomerRiskRadarWidget`/`ChronicBlockersWidget.recurring`/`CauseCategoryMap`/`KnowledgeAtRisk`) → сигнал не потерян. Добавить только то, чего нет: выделенный «обострился» (severity выросла — история в `insights.service.ts` версия-трейл) и, если не покрыт, «повтор после плана».
3. **Новая экспертиза** — снять лишний вопрос `checkNewExpertise`. Профиль пишется по порогу `profileMinConfidence` НЕЗАВИСИМО от ответа (`specialist-3-2-knowledge-clone.service.ts:257-264`), данные не теряются.
4. **Атрибуция клиента/поставщика** — на усмотрение агента. Для цели «не дёргать людей» УЖЕ закрыто (вопрос снят). Активный резолвер/индикатор «непривязанные» = полнота графа, не шум → сделать минимально (индикатор) или отложить; убрать осиротевший предикат.

> Эти решения уточняют колонку «Закрытие» в таблице ниже (Р2 снята — ответ «дашборд»).

## ✅ REALITY-CHECK (пере-проверено первоисточником): «потерянных сигналов» НЕТ — потерян только push
Первая оценка была тревожной («батч открыл 3 дыры»). Чтение самих дашбордов её опровергло — сигналы видны, исчез только диалоговый push-вопрос:
- `experiment.result_without_lesson` — виден на `/experiments` (счётчик уроков + «Уроки ещё не зафиксированы»). Отдельно есть баг застревания статуса (`experiment-status-resolver.cron.ts:133-135` завершает только при `lessonsLen>0`) — но эксперимент на треке владельца.
- `insight.escalation_suggested` / `recurring_after_mitigation` — «обострился» = поле `dynamicLabel` (growing/spike), ЖИВОЕ: считается `insight-clusterer.cron`, фильтр радара «Растёт»/«Всплеск» (`InsightsListClient.tsx:84-93`), дневной/недельный дайджест, лента, `ChronicBlockersWidget.recurring`. `specialist-3-5-insights.service.ts` (метрики) жив — удалён только `specialist-3-5-probe.service.ts` (вопрос).

**Вывод:** батч убрал PUSH-вопрос, но НЕ дашборд-видимость — ровно то, что хотел владелец (дашборд, не вопрос). «Дыр» под срочный фикс нет. Осталось мелкое: осиротевший предикат атрибуции (мёртвый код — убрать) + опциональный индикатор «непривязанные».

## Как поймём, что получилось
- Ни один снятый вопрос не теряет сигнал: для каждого — либо задача, либо авто-запись, либо строка в `/me/notifications`/дашборде (греп-маркер на правило/консьюмер).
- Эксперимент с результатом без урока перестаёт застревать в `running` и всплывает уведомлением.
- Обещание с автором и сроком заводит задачу на автора (без вопроса).
- `new_expertise_detected` больше не эмитится; экспертиза видна в кабинете сотрудника.
