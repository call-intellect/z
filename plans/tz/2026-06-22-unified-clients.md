# ТЗ (черновик) — Единая модель клиентов

## Цель
Свести разрозненные представления «клиента» в одну понятную модель: **компания → люди-контакты → метки каналов**, отделить клиентов от «Команды», оживить карточку-компанию и привязать к ней контакты и переписку.

## Проблема (фидбек #4)
«Команда» мешает сотрудников и клиентов в одной вкладке (фильтр «Сотрудники и клиенты»). Тестировщик: логически неверно, нужен отдельный раздел для клиентов.

## REALITY-CHECK (исследовано в коде 22.06)
- **«Клиенты» в «Команде»** = `Person` с `relationship='external'` (фильтр в `frontend/app/(authenticated)/structure/PersonsTab.tsx:348-350`: «Только сотрудники» employee / «Только клиенты» external). Клиент здесь = **человек-контакт**.
- **«Карточки клиентов»** = `Card` с `kind='client'` (модель `Card`, `schema.prisma:2389`; страница `/cards`, `frontend/app/(authenticated)/cards/`). Клиент здесь = **компания** (CRM-аккаунт). Страница `/cards` **не выведена в меню** и почти пуста.
- **Синхронизация чатов** (`backend/src/modules/chatbox/chatbox-ingest.service.ts`): есть `ChatboxCustomer`/`ChatboxMember`/`ChatboxChannelClient` с полем `linkedPersonId` (привязка «ник/канал → Person»). У клиентских сообщений сейчас `authorPersonId = null` (`chatbox-ingest.service.ts:300`) — спикер-клиент НЕ привязывается к контакту.
- Вывод: «человек-контакт» и «компания-карточка» — **две разные сущности**, не связаны между собой; нет поля «Person → компания».

## Согласованное направление (владелец, 22.06)
- **Клиент = компания** (переиспользуем `Card kind='client'`, вывести в меню).
- **Внутри компании — люди-контакты** (`Person`, каждый отдельная сущность: Петя и Иван из «Молока» — два контакта).
- **«Команда» = только сотрудники** (`relationship='employee'`), внешних убрать.
- Привязка «ник/канал → человек» уже есть (`linkedPersonId`); достроить **«человек → компания»** и шаг **«неузнанный ник → выбрать контакт компании / завести нового»**.
- Починить `authorPersonId` для клиентских сообщений (спикер привязывается к контакту).
- Оживить карточку-компанию: на ней — контакты + их переписка/встречи.

## Открытые вопросы для анализа (до ready-to-implement)
1. Связь `Person(external) → Card(client)`: новое поле/таблица (напр. `CardContact` — в схеме упомянут как «vNext») — спроектировать модель.
2. Где живёт UI «Клиенты»: переиспользовать `/cards` (вывести в меню) или новый раздел; как показывать «компания → контакты → каналы».
3. Миграция существующих `Person(external)` — привязать к компаниям (как определить компанию: по `ChatboxCustomer`/группе?).
4. Сценарий «неузнанный ник»: где и как пользователь подтверждает привязку (без inline-кнопок probe? обычный CRUD-выбор допустим).

## Scope (предв.)
**Входит:** модель компания↔контакт↔каналы; раздел «Клиенты»; чистка «Команды»; фикс `authorPersonId`; шаг привязки неузнанных ников.
**Не входит:** изменение пайплайна графа знаний; импорт внешних CRM.
