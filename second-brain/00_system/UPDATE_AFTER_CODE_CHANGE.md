# UPDATE AFTER CODE CHANGE

## Когда обновлять second-brain после изменений кода

| Тип изменения | Что обновить |
|---|---|
| Новая фича | Создать заметку в `01_projects/` |
| Архитектурное решение | Создать ADR в `02_architecture/` |
| Исправление сложного бага | Разбор в `03_processes/` |
| Удалён модуль/сервис | Обновить все ссылки на него |
| Изменён API/контракт | Обновить соответствующую заметку |

## Что НЕ нужно фиксировать
- Мелкие правки (typo, стили, рефакторинг без изменения логики)
- То, что очевидно из кода или коммита

## Правило
Если через месяц будет непонятно ПОЧЕМУ так сделано — зафиксировать сейчас.
