# Синтез: вау-визуализация второго мозга Коры

## 1. Главные факты ландшафта (сшивка контуров)

1. **Ниша пуста с двух сторон.** РФ: ни один из 12 продуктов баз знаний не имеет граф-визуализации (тройная свежая проверка: release-нота TEAMLY 30.04.2026, обзор Kaiten 12.01.2026, топ-11 vc.ru 13.01.2026) [triangulated(3), файл 09]. Глобально: memory-вендоры сворачивают граф-UI (Mem0 v3 удалил Graph view; mem.ai принципиально без графа; Graphlit API-only) [verified, файл 03]. Единственный «граф» в сознании РФ-аудитории — Obsidian, личный инструмент без командной иерархии [verified, 09].
2. **Рецепт вау уже канонизирован экосистемой** (Obsidian 3D-плагины, D'Arcy Norman 04.2026, примеры vasturiano): тёмный фон → bloom-свечение → частицы → авто-орбита → таймлапс роста → полёт камеры. Всё поверх одной MIT-библиотеки 3d-force-graph; собирается быстро [verified, 01/05/10].
3. **Вау и польза — разные режимы одного экрана, не разные продукты.** Консенсус критики: сырой глобальный граф = «bunch of dots» / hairball с ~200 узлов [verified, 01/08]; все живые кейсы пользы — фильтрованные подграфы. Лидеры (InfraNodus, Embedding Atlas) держат один canvas + сменные панели/линзы [verified, 03].
4. **Масштаб Коры — лёгкий для отрасли, тяжёлый для наива.** Сегодня полный граф тенанта ≈ 530 узлов / 6k рёбер (dev-замер, 00-index), горизонт года — 10–50k узлов. Это ниже порога боли всех движков [04], но выше порога hairball и выше комфорта DOM/наивного force [07/08]. → серверная агрегация обязательна.
5. **«Сервер считает — клиент рендерит» — консенсус всех разобранных систем** (Bloom, Ogma, Graphistry, anvaka, Anytype-worker) [triangulated(4+), 11]. Louvain на наших объёмах — десятки мс; FA2/ngraph — секунды в BullMQ.
6. **Дыры — продуктовая фича №1 практичной части.** InfraNodus продаёт structural gaps + AI-вопрос «мостящий дыру»; red links Wikipedia доказали «видимая пустота провоцирует заполнение»; Foam/Anytype — ghost/сироты [verified, 03/08]. Стек InfraNodus = NestJS+Prisma+Postgres — наши серверные метрики переносимы 1:1.
7. **Шейкаут 2026:** красивые визуальные инструменты без автопритока данных умерли (Kosmik, Napkin-десктоп, Scrintal→пивот) [verified, 02]. У Коры приток автоматический (встречи/чаты) — вау-виз тут витрина конвейера, и никто из 9 игроков «второй волны» не строит карту сам из встреч.

**ADR-решение.** Контекст: владелец зафиксировал 3D + полный граф (тысячи точек) + вау-эффекты + ТЗ с кодом для обычного программиста; стек Next 16/React 19; в repo уже react-force-graph-2d; SaaS → только пермиссивные лицензии.
**Выбор: A — react-force-graph-3d@1.29.1 (+ three@0.185.1, three-spritetext) как единственный рендер вау-режима**, с серверной LOD-агрегацией, удерживающей видимую сцену ≤ ~3–4k элементов.
- B отпадает по производительности ровно на нашем сценарии («тысячи точек» = слайдшоу 1–3 FPS [verified issue #113]) и по невозможности bloom/частиц без форка.
- C отпадает по решению владельца (2D-only) — остаётся **страховкой масштаба** (если видимая сцена когда-то потребует 50k+ живых точек) и донором идеи GPU-переходов.
- D не конкурент вау-части (2D), но и **не нужен как второй движок практичной части**: все практичные паттерны (reducers-подсветка, поиск-полёт, панели) реализуемы на A тем же API + React-оверлеями — второй рендер-стек удорожает поддержку без выигрыша на нашем масштабе. G6/xyflow — только доноры паттернов (timebar, hull, узлы-карточки), не зависимости этого ТЗ.
**Последствия/чем ломается:** (а) если реальный FPS-спайк на нашем железе покажет <30 FPS на 2k узлов с bloom+частицами — режем эффекты по профилю качества (§4, уровни VFX) или мигрируем полотно на C; (б) требует дисциплины «один three в lock-файле»; (в) CSP: inline-шейдеры WebGL — проверить прод-CSP (урок Logseq [01]).

## 4. Целевая сборка (вход для архитектуры)

**Слои клиента (все MIT/Unlicense, сниппеты в 05/10):**
1. Ядро: `react-force-graph-3d` через двойной клиентский wrapper (`'use client'` + `dynamic ssr:false`, ref внутри Inner), изолированное **фасадом-компонентом** (поправка red-team: оболочка заменима на r3f-forcegraph без переписывания продукта).
2. Свечение: UnrealBloomPass (strength 2–4 / radius 1 / threshold 0, фон `#000003`); «светится только важное» — яркостной сегрегацией материалов (threshold 0.3–0.6), без хирургии рендер-цикла.
3. Узлы: glow-спрайты (radial-gradient CanvasTexture, AdditiveBlending, кэш материалов по цвету) + SpriteText-подписи только у областей/тем; листья — подпись по hover.
4. Фон: собственный звёздный слой (равномерная сфера, lerp-градиент цвета, AdditiveBlending; реализован в прототипе) — слой «космос», отличающий нас от голых force-графов. Код GalaxyM1199 не копируем (провенанс — платный курс, поправка red-team).
5. Динамика: частицы ТОЛЬКО на подсвеченных рёбрах (официальный паттерн-смягчение); `emitParticle` на новых фактах; авто-орбита в idle («скринсейвер мозга»); полёт `cameraPosition(…, node, 2000–3000ms)`.
6. Практичные оверлеи (React поверх canvas): поиск-автокомплит → полёт; правый drawer узла (факты/соседи/«спросить Кору»/провенанс); hover-карточка ~400 мс; чипы-линзы (Области/Люди/Темы + период); таймлайн-скраббер с гистограммой; панель «Разрывы»; хлебные крошки + пины (TheBrain).
7. Пустые состояния: NN/g 3 правила + «мозг-заставка» (drawrange plexus, MIT) до первой встречи.

**Слои сервера (всё в стеке Коры, эскизы в 11):**
1. `GraphSnapshot` (таблица JSONB + Redis) — уровни LOD из доменной иерархии: L0 = 12 областей, L1 = +темы, L2 = +сущности (+ghost); блоки — только expand-on-demand вокруг узла.
2. BullMQ sandboxed-джоба: два плоских SELECT → graphology → Louvain (раскраска «скрытых сообществ» поверх областей) → 3D-layout предрасчёт (**d3-force-3d в Node** — тот же движок, что у клиента; поправка red-team, ngraph исключён) → снапшот с x/y/z.
3. Дельты: после встречи — pinning старых узлов через `fx/fy/fz`, посев новых у центроида соседей, 30–60 тиков → `{addedNodes, addedLinks}` → фронт анимирует прорастание. Полный ребилд — ночной cron.
4. Правила отдачи: ответ ≤5k узлов; expand с cursor+фильтром типа связи; ETag/304; рёбра блоков агрегируются в вес ребра сущность–сущность (урок Logseq [01]).
5. Реюз старого ТЗ: `MaturityScorerService` (+scope person) как источник яркости/ghost; `BrainGrowthSnapshot`-идея → метрика-герой «+K фактов за неделю»; nudge через proactive из панели «Разрывы»/ghost-узла.

**Интеграция в продукт:** секция внутри «Памяти» (вкладка «Карта мозга» рядом с картой областей); клик по области в 3D ↔ `/memory/:branch`; клик по теме → живая страница темы; deep link из ответа AI-чата → сцена с подсветкой узлов-источников. Термины UI: «карта знаний компании», «пробелы в знаниях» [09].
