## Что было поставлено

Владелец: в супер-админке нет удобного управления LLM-провайдерами и моделями — нельзя добавить/удалить провайдера, назначить модель для операции, редактировать креды/стоимость, выбрать «напрямую или через proxy.agent-lia.ru», автополучить список моделей. UI разрознён по нескольким пересекающимся разделам. Референс — уже реализованный CRUD провайдеров эмбеддингов (`plans/tz/2026-07-02-embedding-providers-crud.md`, реализован ранее в этот же день) и скрины владельца из другого проекта.

Прошли полную цепочку: аудит (5 параллельных картографов + критик-верификатор через `Workflow`) → tz-author (ТЗ `plans/tz/2026-07-02-llm-providers-models-routing-admin.md`, 4 HIGH-развилки закрыты владельцем через `AskUserQuestion`) → tz-orchestrator (эта реализация, 10 фаз).

## Как решал (10 фаз + 2 внеплановых фикса, фаза за фазой, суб-агенты + независимая приёмка)

**Ключевая находка аудита:** DB-реестр `LlmProvider`/`LlmModel` уже существовал (создан ранее, "SBA α-10"), но был витриной — боевой dispatch шёл по захардкоженному ENV-switch, путь через реестр спал за флагом `USE_PROTOCOL_ADAPTER_REGISTRY=false`, 3 из 5 адаптеров игнорировали baseUrl/ключ из БД, ключи хранились в открытом виде, kie/grsai сеялись фейковым протоколом `custom-http` (smoke гарантированно красный).

- **Ф1** (`2df905c1`): миграция `20260702165640_llm_provider_proxy_defaults` — 4 поля на `LlmProvider` (`useProxy`/`proxyPath`/`timeoutMs`/`defaultModelKey`). Прод-БД без AGE-shadow — миграция через `prisma migrate diff --from-schema <HEAD>/--to-schema <текущая> --script` + ручное применение + `migrate resolve` (канон уже описан в рефлексии embedding-providers этого же дня).
- **Ф2** (`355a7bcc`): шифрование ключей AES-256-GCM (были plaintext) + единый `present()`-маскировщик + idempotent `patch-encrypt-llm-provider-keys.ts`.
- **Ф3** (`30183758`): честные `kie-native`/`grsai-native` адаптеры вместо `custom-http`; `LlmConnectionOverride` во всех 5 легаси-сервисах; единая прокси-формула в `ProviderInfoResolver`; capability/timeoutMs из БД. **По ходу вскрылась третья дыра того же класса** (`OpenAiResponsesProtocolAdapter` тоже игнорировал ProviderInfo — ТЗ поймало только 2 из 3) — почищена в Ф4.
- **Ф4** (`921df594`, **самая рискованная фаза**): `USE_PROTOCOL_ADAPTER_REGISTRY` → `true` по умолчанию (Ship-On) + 29 parity-тестов (для каждого из 7 провайдеров: тот же легаси-сервис вызывается, override соответствует ENV-фолбэку, итоговый результат идентичен legacy-ветке). **По ходу этой фазы найдены и закрыты 2 реальных бага, не пойманных аудитом:** пропущенный `OpenAiResponsesProtocolAdapter` (см. Ф3) и `buildFromEnv('openai-via-proxy')` отдавал непрефиксованный ключ (401 на втором tier дефолт-цепочки в день переключения без DB-строки).
- **Ф5** (`8d0e5951`): дискавери моделей (`POST .../models/discover`, `GET {baseUrl}/models`) + `defaultModelKey` в приоритете выбора модели dispatch. **Закрыт пробел авторства ТЗ:** `useProxy/proxyPath/timeoutMs/defaultModelKey` были в Prisma (Ф1) и в `present()` (Ф2), но НИКОГДА не были в Zod DTO/`create()`/`update()` — физически невозможно было их выставить через API.
- **Ф6** (`52f48041`): единый `PUT /admin/ai-models/:taskType/chain` (заменил дублирующий `LlmRoutesController`, удалён целиком); гард `provider_in_use_by_routes`; `llm.router.defaultChain` — крутилка AdminSetting; фикс дубля `process-template-extract` в реестре taskType (`chat-summary` — уже почищен ДО этой сессии другим коммитом на dev, аудит-текст ТЗ был устаревшим на этот счёт — перепроверено чтением, не тронуто повторно).
- **Ф7** (`860bc08b`): фронт «Провайдеры и модели» (`/admin/ai/catalog`) — полноценный CRUD по образцу embeddings. **По ходу найдены и исправлены 2 доп. бага** в `SmokeTestClient`: `runAll()` ожидал `{runs}`, бэк отдаёт `{items}`; типы истории использовали `ranAt`/`message`, бэк — `startedAt`/`error`.
- **Ф8** (`c659775a`): фронт «Маршрутизация» (`/admin/ai/routing`) единым экраном, устранено тройное дублирование метрик/истории; удалены `admin/llm-routes` (backend уже удалён Ф6 — страница была БИТАЯ на момент старта фазы), `admin/ai-models/*`, `ExperimentsClient`. **Вскрыта и закрыта в этой же фазе регрессия от Ф6:** `FunctionDetailClient.tsx`/`FunctionDetailAnalyticsClient.tsx` (страницы `/admin/usage/functions`, `/admin/analytics/functions`) тоже писали через теперь-удалённый `PUT /admin/llm-routes/:taskType` — переведены на `putChain` (маппинг позиция-в-массиве→tier). Пофиксил сам, не через суб-агента — точечный, хорошо понятный патч.
- **Ф9** (`af596706`): актуальные сиды (kie/grsai честные протоколы, `defaultModelKey` по факту используемых дефолтов, 4 протухшие модели деактивированы, опечатка `gpt-5-4`→`gpt-5.4` в сиде и удалена из `model-prices.ts`) + idempotent `patch-llm-provider-protocols.ts` для уже засеянных до этой фазы БД. Двойной прогон сида и патча на dev-БД — чистый no-op.
- **Ф10** (`21c9190b`): интеграционный тест с РЕАЛЬНЫМ `CryptoService` (не мок) — encrypt→decrypt→dispatch, HTTP-граница мокирована, доказывает DB-значения побеждают ENV-плейсхолдеры; докблок (см. ниже).

**Внеплановые фиксы (вне 10 фаз, найдены/решены по дороге, не отложены):**
- `scripts/dev.ts` — зомби-процессы после Ctrl+C (родитель падал мимо SIGINT-обработчика, дети реродительствовали на init, Ctrl+C бил по чужому foreground-pgrp). Фикс: `detached:true` (own process group) + `process.kill(-pid, sig)` на всю группу + страховочные `uncaughtException`/`unhandledRejection`/`exit`-хендлеры. Проверено живым прогоном (SIGINT → вся группа, включая внуков `next-server`, гарантированно умирает).
- Регрессия Ф6→Ф8 (описана выше в Ф8).

## Что вышло

Каждая фаза принята независимо (typecheck 8GB-heap / lint / build / полный прогон затронутых test-каталогов + re-Read ключевых диффов, НЕ доверял отчётам суб-агентов). Финал: 56+108 backend test-файлов (546-858 тестов на разных срезах фаз) зелёные, frontend typecheck/lint/build чистые на каждой фазе, 1 e2e-интеграционный тест с реальной криптографией. Прод-риск: 1 аддитивная миграция, 2 idempotent-патча (оба дважды прогнаны на dev-БД — no-op), 1 обновлённый сид, **1 поведенческое изменение** (`USE_PROTOCOL_ADAPTER_REGISTRY` false→true) — доказано 29 parity-тестами + отдельным e2e, откат — ENV-флаг без ребилда.

## Чему научился

- **ТЗ, написанное с хорошим аудитом, всё равно пропускает баги того же класса.** Аудит (5 картографов + критик) поймал «2 из 3» адаптеров, игнорирующих ProviderInfo (пропустил `OpenAiResponsesProtocolAdapter`), и не поймал непрефиксованный ключ в `buildFromEnv`. Оба нашлись не при чтении кода заранее, а при **написании parity-теста** — попытка формально доказать эквивалентность вскрывает дыры, которые чтение "по диагонали" не ловит. Урок: для рискованных Ship-On фаз parity/e2e-тест — не формальность, а реальный инструмент поиска багов, писать его стоит ДО уверенности «всё поймано».
- **Одна фаза может задеть код, живущий на 2+ уровня выше по стеку, о которых ТЗ не знало.** Удаление `LlmRoutesController` (Ф6, чистая внутренняя рефакторинг-цель) сломало 2 фронт-страницы в СОВЕРШЕННО другом разделе админки (`/admin/usage/functions`, `/admin/analytics/functions`), которые сами по себе не упоминались нигде в ТЗ. `grep -rln` по потребителям удаляемого API-файла — обязательный шаг ПЕРЕД удалением backend-эндпоинта, а не после того, как typecheck/build случайно это поймает (в данном случае build прошёл бы чисто, т.к. TS не проверяет доступность REST-эндпоинтов — только runtime 404 вскрыл бы регрессию).
- **`scripts/dev.ts` — классическая ловушка "родитель падает мимо cleanup-пути".** `Bun.spawn` без `detached:true` даёт детям тот же pgrp, что и родителю; если родитель гибнет НЕ через свой SIGINT/SIGTERM-хендлер (а через необработанное исключение или внешний SIGKILL), дети становятся сиротами с мёртвым pgrp — Ctrl+C в терминале после этого бьёт по foreground-группе (bash), а не по осиротевшим процессам, которые продолжают жить и писать в тот же tty. Фикс общий для любого orchestrator-скрипта на Bun/Node: `detached:true` + `kill(-pid)` + перехват uncaughtException/exit.
- **TS control-flow narrowing иногда даёт `never` на module-scope `let`, мутируемых внутри `vi.mock()`-фабрики** — обходится оборачиванием в объект-контейнер (`{opts: null}`) + явным `as`-приведением на чтении; чинить «красиво» не тратить время, если формально проверенная логика теста уже верна.
