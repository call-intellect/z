  **дождаться эмбеддингов** (`issue-embed.worker`, `embedding IS NOT NULL` — иначе KNN не сматчит); ORG_B-двойник;
  сгенерить `task-stand-manifest.json` (ground truth).
- **Ф2 inject:** подать 85 входов через **реальный конвейер** (RawEvent/адаптеры, как `clone-build-harness`),
  дождаться `RawEvent.received=0`. **Обязательно:** отдельно и раздельно вызвать три извлекателя

  это прямой замер **Т1**. Для journal/closure — при нестабильном классификаторе дублировать прямой инъекцией
  IdeaBlock с нужным signalType.
- **Ф3 assert (без LLM):** тип исхода (issue/intake/candidate/progress/relation/probe/nothing/error — точный матч
  кодов) + счётчик (ловит проафферацию) + поля (enum точно, title/assignee — нечётко) + **детерминированные
  инварианты** INV-1 (нет закрытий/merge без confirm), INV-2 (нет кросс-тенант), INV-4 (повтор не растит счётчики).
- **Ф4 judge + report:** панель majority-of-3 (линзы: форма задача/не-задача/idea/decision · поля · тип-исход),
  `directLlmCall` deepseek-v4-pro, судья видит эталон из манифеста. Отчёт: scorecard по категориям A–J и по
  механизмам; оси; **статус INV-1..4**; **таблица Т1–Т10** (подтверждён/снят/ruler-defect с доказательством);
  конфиг прогона.
- **Ф5 baseline:** чистка кэшей → run → judge → report на 85 + свежие ~15. Каждый провал — ручной разбор против
  сырой трассы (линейка сама может врать → диагноз `ruler-defect` чинить первым).

## Жёсткие правила

- **Прод не трогать.** `assertNotProd` первым вызовом каждого скрипта. Только локальная синтетика. Единственная
  допустимая правка прод-кода — **аддитивная трасса** (добавить поля в возврат/лог, поведение-нейтрально); лучше
  снимай трассу read-only из БД. Снапшот-тесты промптов не ломать.
- **Живой backend обязателен** (`cd backend && bun run dev`) — конвейер крутится in-process; без него стенд не
  измеряет. dev-инфра: `docker compose -f docker-compose.dev.yml up -d`.
- **Не подгоняй эталоны под ответы.** Банк и предсказания фиксированы. Инвариант R13 — осевой: если стенд
  «ожидает» авто-закрытие/авто-merge, это ошибка эталона, а не бага.
- `createPrismaClient()` из `_lib/prisma.ts` (не голый `new PrismaClient()`); ORG из ENV; per-run архив, не
  перезапись; чистить `bull:*`/answer-кэш/`probe:dedup`/SETNX перед каждым прогоном.
- Крупные изменения кода — по цепочке (уже пройдена: картография→ТЗ). Ты реализуешь ТЗ, не переспрашивая по
  мелочам; необратимые «решения владельца» (менять планку/поведение) — эскалируй.

## Что вернуть владельцу (Definition of Done)

1. Рабочий стенд: `bun run scripts/task-stand/stand.ts all` (и по-фазно) гоняет 85 сценариев.
2. **Baseline-отчёт** `docs/testing/task-stand-report.md`: распределение вердиктов по 4 механизмам; **статус
   инвариантов INV-1..4**; **вердикт по Т1–Т10** — что подтвердилось как баг (с доказательством из трассы), что
   снято; какой извлекатель жив (Т1); честный разбор потолка.
3. Список **приоритетных слабых мест** (подтверждённые Т* + новые находки) → это вход для **отдельного ТЗ-фикса**
   (не делать фиксы в этом задании).
4. `typecheck/lint/build` зелёные; `task-stand.md` README; строка в реестре стендов; прод не тронут.

Ожидаемо по прогнозу (сверь с фактом; резкое расхождение → сначала `ruler-defect`): Т1 покажет, что часть
входов чата/встречи не рождает задачу (осиротевший извлекатель) или рождает через SpecialistsCombined; Т2 —
обещание себе уходит в Goal; Т3 — многоблочное дело даёт неверное число задач; INV-1 (R13) соблюдён.

Начни с чтения пяти входных документов и `index_status`/окружения, затем Ф0.
