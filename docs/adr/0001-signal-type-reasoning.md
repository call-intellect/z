## Контекст

Layer 1 разметки IdeaBlock изначально различал «факты» (`fact`), «решения»
(`decision`), «обязательства» (`commitment`), но не выделял отдельно
**обоснования** — высказывания вида «мы пошли через X, потому что Y».

Без отдельного типа обоснования попадали либо в `fact` (теряя связь с
причинно-следственным контекстом), либо в `decision` (засоряя классификатор
решений). Это ломало две задачи сразу:

- **skill-trait-detect** (γ-1, см. `plans/archive/2026-05-25-knowledge-core-temporal-and-graph-quality.md`):
  специалист анализирует ЛОГИКУ человека — а логика живёт именно в
  обоснованиях. Без `reasoning` он работал по случайным фактам и решениям
  и давал низкий precision.
- **rationale → decision** (волна SBA α-2 wave 1): для построения связки
  «решение ↔ его обоснование» в графе нужно сначала уметь выделить
  обоснование как самостоятельный блок.

Решено вводить отдельный тип `reasoning` плюс два уточняющих подтипа
`rationale` (привязанное к конкретному decision) и `decision_basis`
(фрагмент обоснования внутри блока-decision). Этот ADR — про базовый
`reasoning`; `rationale` и `decision_basis` — отдельные значения с уже
описанной в промпте семантикой.

Связанный контекст:
- ТЗ: `plans/archive/2026-05-23-sba-alpha-2-19-signal-types.md` (волна α-2 wave 1).
- Эксперимент по skill-trait-detect: `backend/test/eval/skill-trait-detect-golden/` (25 кейсов, 96 % accuracy на DeepSeek V4 Pro).

## Решение

**Имя:** `reasoning`

**Семантика:** высказывание, в котором говорящий объясняет ЛОГИКУ выбора —
почему сделано/решено/предложено именно так, а не иначе. Это про
**причинно-следственную связь** в голове автора, а не про сам факт или
само решение.

**Что говорит «нет»:**

- Не `fact` — факт описывает «что есть», `reasoning` описывает «почему так выбрали».
- Не `decision` — решение фиксирует исход, `reasoning` объясняет ход мысли. Один decision может тянуть за собой несколько `reasoning` блоков.
- Не `commitment` — обязательство про будущее действие («я сделаю X»), `reasoning` про объяснение уже сделанного или предлагаемого выбора.
- Не `idea` — идея описывает предложение/гипотезу, `reasoning` объясняет, почему предложение/выбор именно такой.
- Не `rationale` — `rationale` это `reasoning`, **жёстко привязанный** к конкретному `decision` в том же окне разговора. `reasoning` шире — может стоять отдельно («я обычно сначала меряю, потом коммитчусь по срокам»).

**Маркеры (фразы-якоря в тексте):** «потому что», «я учёл», «мы выбрали X над Y», «trade-off», «иначе бы», «логика такая», «исходя из», «дело в том, что», «я обжигался на …, поэтому …».

**Обязательная привязка:** через `mentionedEntities` обязательно связать с
человеком-автором рассуждения (`type='person'`). Без этого `reasoning`
бесполезен для `SkillProfile` / `skill-trait-detect`.

**Отличие от похожих значений:**

| Сравниваемое значение | Чем отличается |
|---|---|
| `fact` | Факт — «что есть»; reasoning — «почему выбрали так». |
| `decision` | Решение — исход; reasoning — объяснение хода мысли. |
| `rationale` | rationale = reasoning, привязанный к конкретному decision в том же окне. |
| `decision_basis` | Узкий подкласс: фрагмент обоснования ВНУТРИ блока-decision (не отдельный блок). |
| `idea` | Идея — что предложить; reasoning — почему именно эта идея/выбор. |
| `expertise` | Декларация знания («я умею X»); reasoning — применение этого знания к конкретному выбору. |

## Примеры

| Текст | Это `reasoning`? | Если нет — какой тип |
|---|---|---|
| «Давайте не закладывать срок, пока не посмотрим, как ведёт себя нагрузка в стейдже — я обжигался на оценках без замеров.» | да | — |
| «Мы выбрали LiveKit над Jitsi, потому что нужна отдельная аудиодорожка на участника — у Jitsi только общий микс.» | да | — |
| «Я бы не давал сроки на этот эпик, пока не разберём контракт с биллингом — там может вылезти неделя.» | да | — |
| «Договорились: релиз через неделю.» | нет | `decision` |
| «Конверсия упала с 8 % до 5 % за апрель.» | нет | `metric_change` |
| «Я возьму на себя интеграцию со Slack до пятницы.» | нет | `commitment` |
| «У меня 5 лет опыта с pgvector.» | нет | `expertise` |

## Альтернативы

1. **Не вводить `reasoning`, расширить семантику `fact`.** Отвергли:
   `fact` про «что есть», а не про «почему так выбрано». Смешение типов
   ломает classifier metrics и засоряет поиск по фактам.
2. **Назвать `justification` / `explanation`.** Отвергли: `reasoning` точнее
   передаёт акцент на ход мысли (а не на оправдание задним числом или
   общее «объяснение»). `justification` уехал бы в плоскость защиты решения
   перед аудиторией, что уже частично покрывает `rationale`.
3. **Сделать `reasoning` атрибутом (tag) на `decision` / `idea`, а не отдельным типом.**
   Отвергли: обоснования живут самостоятельно («я обычно сначала меряю,
   потом коммитчусь») и должны быть индексируемы отдельно для
   `skill-trait-detect`. Тег убил бы возможность отдельно искать
   reasoning-блоки по человеку.
4. **Одно значение `reasoning` без подтипов `rationale` / `decision_basis`.**
   Отвергли: на практике нужна жёсткая привязка обоснования к конкретному
   решению (для графа «решение ↔ почему»). Поэтому `rationale` — подтип
   с обязательной связью на `decision` в том же окне, а `reasoning` — общий
   случай. См. также отдельные ADR на `rationale` (будет) и `decision_basis` (будет).

## Последствия

- **Что изменилось в коде:** `SIGNAL_TYPE_VALUES` пополнен значением
  `'reasoning'` (`backend/src/modules/knowledge-core/prompts/block-ingest.prompt.ts:24`),
  JSON Schema для signalType автоматически подхватывает (через spread
  `[...SIGNAL_TYPE_VALUES]`), описание добавлено в текст промпта на строке ~404.
- **Метрики:** новый bucket `kc_signal_type_distribution{signal_type="reasoning"}`.
  По данным первых dev-прогонов доля reasoning стабилизируется в районе
  8-12 % всех IdeaBlock. Сдвиг >3σ → проверять classifier (Markov-матрица G.2).
- **Промпты:** правка в `block-extraction` уже сделана (см. строка 404 в
  `block-ingest.prompt.ts`). Дополнительно `skill-trait-detect.prompt.ts`
  фильтрует `signalType='reasoning'` как основной источник анализа логики.
- **Обратная совместимость:** старые IdeaBlock с `signalType='fact'`,
  семантически являющиеся reasoning, НЕ переразмечаются автоматически.
  Бэкфилл — отдельный план, если когда-то понадобится (приоритет низкий —
  для skill-trait-detect хватает свежих данных).
