> Что это: возвращаем в раздел «Сообщения» возможность **самому начать переписку** — с коллегой (личка/группа) **и** с внешним человеком/клиентом по ссылке. Для кого: любой сотрудник, который сейчас жалуется, что «чат недоделан — некому и негде написать».
> Цепочка: живая диагностика на проде (кабинет владельца, «Ооо луа», 7 июля) → **эта архитектура** → ТЗ `plans/tz/2026-07-07-messaging-new-conversation.md`
> Одобрено владельцем в чате 7 июля: делаем обе двери (коллега + внешний); «компания↔компания» оставляем отложенным.

# Раздел «Сообщения»: кнопка «Новое сообщение» + выбор сотрудника

## Что это и зачем

В кабинете есть раздел **«Сообщения»** — это внутренний мессенджер компании (личные переписки, группы, каналы, плюс авто-чаты вокруг задач и карточек). Сотрудники говорят, что он «как будто не доделан: писать негде, списка людей нет».

Мы вживую разобрали прод. Диагноз однозначный: **сам чат работает** (внутри переписки можно писать, сообщения ходят), но в интерфейсе **нет ни одной точки входа, чтобы начать переписку с человеком с нуля**. Нет кнопки «написать», нет списка сотрудников. Вкладки «Личные / Группы / Работа» вверху — это только **фильтры уже существующих** бесед, а не способ создать новую.

При этом «начинка» под это уже написана:
- **Бэкенд полностью готов** — есть рабочий метод «создать личку/группу/канал» с выбором участников и проверкой, что все из твоей компании.
- Во фронте даже есть готовая функция-вызов этого метода — но она **не привязана ни к одной кнопке** (проверено: 0 вызовов во всём интерфейсе).
- Есть **готовый компонент выбора людей** — `ParticipantPicker` — который уже используется в 9 местах (создание встречи, приглашения, задачи, календарь).

То есть это не «строить мессенджер», а **приделать последнюю недостающую педаль**: экран «Новое сообщение → выбери коллегу → пиши». Движок и детали уже есть.

**Кто страдает:** вся команда. Люди заходят в «Сообщения», видят вкладку «Личные» — а она пустая и создать личку нельзя. Ощущение «продукт сломан».

## Как сегодня

Беседы в разделе «Сообщения» появляются **только сами**, четырьмя путями:

- **Чат задачи** — заводится автоматически, когда создаётся задача (из встречи или трекера). Виден вокруг конкретной задачи.
- **Чат карточки** — вокруг карточки знаний.
- **Тикеты/Клиенты** — из внешних обращений.
- **Канал «Вся компания»** — должен заводиться автоматически при найме сотрудника, но за флагом; у старых компаний (созданных раньше) его часто **нет вообще** — у владельца в списке он не виден.

А вот **личку и группу вручную создать нельзя** — в интерфейсе для этого ничего нет. Поиск «по людям, группам…» ищет только среди тех бесед, что уже есть, а не по справочнику сотрудников.

## Что делаем

Три вещи, все — на стороне интерфейса + один аккуратный дожим бэкенда.

### 1. Кнопка «Новое сообщение» и выбор человека

В разделе «Сообщения», рядом с заголовком, появляется кнопка **«Новое сообщение»**. По клику — окно с полем поиска и выбором сотрудников (переиспользуем готовый `ParticipantPicker`):

- выбрал **одного** → открывается **личная переписка** с ним;
- выбрал **несколько** → создаётся **группа** (можно задать название; если не задал — соберём из имён участников).

**Было → стало:**

- *Было:* сотрудник открывает «Сообщения» → видит вкладку «Личные» → она пустая → создать нельзя → тупик.
- *Стало:* открывает «Сообщения» → жмёт «Новое сообщение» → набирает «Иван» → выбирает Ивана → сразу попадает в переписку с ним → пишет «привет».

**Как выглядит:**

```
┌──────────────────────────────────────────────┐
│  Сообщения  (7)              [+ Новое сообщение]│
│  🔍 Поиск по людям, группам, PROJ-NN…          │
│  [Всё][Личные][Группы][Работа][Задачи]…        │
├──────────────────────────────────────────────┤
│  M6  MANA-6 · Написать код…                    │
│  M1  MANA-1 · Подготовить обзор…               │
└──────────────────────────────────────────────┘

  клик по «+ Новое сообщение» ↓

┌────────── Новое сообщение ──────────┐
│  ( • Коллега )   ( ○ Внешний/клиент )│  ← переключатель режима
│  Кому:                              │
│  ┌────────────────────────────────┐ │
│  │ иван|                          │ │  ← поиск по сотрудникам
│  └────────────────────────────────┘ │
│   • Иван Петров   — Менеджер         │
│   • Иванна Смирнова — Дизайнер        │
│                                      │
│  [выбрано: Иван Петров ✕]            │
│  Название (для группы, необязательно)│
│  ┌────────────────────────────────┐ │
│  │                                │ │
│  └────────────────────────────────┘ │
│              [Отмена]  [Написать →]  │
└──────────────────────────────────────┘
```

Тот же экран в режиме «Внешний/клиент» (дверь №2, см. ниже):

```
┌────────── Новое сообщение ──────────┐
│  ( ○ Коллега )   ( • Внешний/клиент )│
│  Email или телефон клиента:          │
│  ┌────────────────────────────────┐ │
│  │ client@site.ru                 │ │
│  └────────────────────────────────┘ │
│  Первое сообщение (необязательно):   │
│  ┌────────────────────────────────┐ │
│  │ Здравствуйте! Пишу по…         │ │
│  └────────────────────────────────┘ │
│           [Отмена]  [Отправить ссылку]│
└──────────────────────────────────────┘
  ↓ система создаёт чат, шлёт клиенту magic-ссылку
    на email/телефон и показывает её для «скопировать»
```

**Важный нюанс:** справочник людей содержит и **сотрудников с аккаунтом** (им можно писать в кабинете), и **контакты без аккаунта** (просто карточки людей — им в кабинет написать нельзя). В окне «Новое сообщение» показываем **только тех, у кого есть аккаунт**, чтобы не было мёртвого выбора «написал — а сообщение никому не дойдёт».

### 2. Не плодить дубли личек

Если у меня уже есть личная переписка с Иваном, то повторный «Новое сообщение → Иван» должен **открыть ту же самую**, а не создавать вторую пустую. Сейчас бэкенд об этом не заботится — заложим: для лички между теми же двумя людьми переписка одна.

- *Было:* написал Ивану, завтра снова «Новое сообщение → Иван» → появилась бы вторая ветка с ним, история разъехалась.
- *Стало:* всегда попадаешь в одну и ту же переписку с Иваном.

### 3. Канал «Вся компания» — чтобы он точно был

У старых компаний канала «Вся компания» нет. Сделаем разовый дожим: у каждой существующей компании этот канал **появляется и в него включены все сотрудники** — как и задумано. Дальше он живёт сам (новых людей подхватывает автоматически).

- *Было:* у владельца («Ооо луа») канала «Вся компания» в списке нет.
- *Стало:* канал есть, в нём вся команда, можно написать всем сразу.

### 4. Вторая дверь — написать внешнему человеку/клиенту по ссылке

Тот же экран «Новое сообщение» переключается в режим **«Внешний/клиент»**. Сотрудник вводит **email или телефон** внешнего человека (и, по желанию, первое сообщение) → система:
- создаёт внешнюю переписку,
- генерит **одноразовую magic-ссылку** (живёт 7 дней, можно отозвать, действует только на этот разговор),
- **сама отправляет приглашение** на указанный email/телефон и показывает ссылку сотруднику, чтобы можно было скопировать и переслать вручную.

Внешний человек открывает ссылку **без пароля**, читает и пишет — а прямо из переписки может **завести аккаунт** (код на email/телефон, «теневой → подтверждённый»). Это и есть «написать незарегистрированному, чтобы он подключился».

- *Было:* весь механизм внешних чатов готов на бэке и включён флагом `EXTERNAL_CHAT_ENABLED`, но у сотрудника **нет кнопки его начать** — фича лежит мёртвым грузом.
- *Стало:* сотрудник из «Сообщений» в два поля (email/телефон + текст) начинает внешний чат; клиент получает ссылку, отвечает, при желании регистрируется.

**Границы этой двери (решение владельца, не трогаем):** это переписка с **внешним контактом/клиентом**, не «компания↔компания» как тенант-тенант. Полноценный межкомпанейский контур намеренно отложен (Р-1 анализа поддержки, 9 июня). Служба поддержки (клиенты Коры пишут нам в единый деск + AI-клон) — **отдельная** фича, здесь не трогаем.

## Решения, принятые за владельца (можно поправить)

| # | Решение | Почему так |
|---|---|---|
| Р1 | В окне «Новое сообщение» показываем **только сотрудников с аккаунтом** (кому реально дойдёт). Контакты без аккаунта не показываем. | Иначе выбор «напиши» ведёт в никуда — мёртвая функция, ровно то, на что и жалуются. |
| Р2 | Один выбранный → **личка**, несколько → **группа**. Название группы необязательно; пустое — соберём из имён участников. | Привычная логика любого мессенджера; лишний шаг «выбери тип чата» не нужен. |
| Р3 | Повторная личка с тем же человеком **переиспользуется** (не плодим дубли). | Единая история переписки; иначе сообщения разъезжаются по копиям. |
| Р4 | Канал «Вся компания» **дожимаем разово для всех существующих компаний** и включаем туда всех. | Задумка уже есть в коде, просто не отработала на старых оргах; выкатываем «как задумано», без отдельного включателя. |
| Р5 | Выкатываем **сразу включённым** для всех (Ship-On). Отдельного «показать части пользователей» не делаем. | Это возврат заявленной, ожидаемой функции, а не эксперимент. |
| Р6 | «Новое сообщение» — **одна кнопка с переключателем режима**: «Коллега» / «Внешний/клиент». | Обе двери — одна и та же дыра (недостающий вход); пользователю это один цельный экран «с кем начать переписку». |
| Р7 | Внешняя дверь использует **готовый** механизм `EXTERNAL_CHAT_ENABLED` (magic-ссылка + дорегистрация) как есть; новый контур не строим. | Бэкенд готов и флаг включён — задача только приделать вход, не переписывать. |
| Р8 | «Компания↔компания» (тенант↔тенант) и служба поддержки (единый деск + клон) — **вне scope**, остаются отложенными. | Прямое решение владельца (Р-1 анализа поддержки); внешние идут через дверь №2 как «контакт/клиент». |

## Границы

**Входит:** кнопка «Новое сообщение» с переключателем режима; выбор сотрудника(ов) → личка/группа; переиспользование существующей лички; разовый дожим канала «Вся компания» для старых компаний; **режим «Внешний/клиент»** — старт внешнего чата по email/телефону, показ+отправка magic-ссылки (поверх готового `EXTERNAL_CHAT_ENABLED`).

**Не входит (в этот заход):**
- «Компания↔компания» как тенант↔тенант; служба поддержки/деск + AI-клон (отдельные фичи, отложены — Р8).
- Переименование/настройки группы, добавление участников в уже созданную группу через UI (метод на бэке есть — отдельным заходом при необходимости).
- Приглашение сотрудников (не клиентов) в кабинет — это онбординг, отдельная тема.
- Звонки/«хадлы», опросы, реакции — это уже есть или отдельные фичи.
- Переделка поиска в списке бесед.

## Как поймём, что получилось

- В «Сообщениях» есть кнопка «Новое сообщение» с переключателем «Коллега» / «Внешний/клиент».
- Три сотрудника могут написать друг другу «привет/тест»: выбрал коллегу → попал в переписку → сообщение отправилось и видно у получателя.
- Повторный выбор того же человека открывает ту же переписку, а не новую.
- В каждой существующей компании виден канал «Вся компания» со всей командой.
- В режиме «Внешний/клиент»: ввёл email → создался внешний чат, ссылка показана и ушла на email; по ссылке внешний человек открывает переписку без пароля, пишет ответ, видит возможность зарегистрироваться.
- В интерфейсе всё по-русски, пустых/битых состояний нет.
