# ТЗ-заглушка (vNext) — Snapshot-таймлайн persona + UI редактирования принципов носителем

> **Статус: draft-stub.** Это НЕ готовое ТЗ — vNext-заглушка из анти-scope основного ТЗ
> [`2026-06-11-clone-persona-method-layer.md`](2026-06-11-clone-persona-method-layer.md) (§«Не входит»).
> До явного «начни» владельца — не реализовывать.

## Что это

1. **Snapshot-таймлайн persona** — витрина истории версий `ExecutablePersona` роли: как менялся метод роли
   во времени (новые принципы, сменившиеся ценности, добавленные процедуры), diff между снапшотами,
   «что клон узнал за месяц». Данные уже копятся (persona версионируется, снапшоты weekly + reactive),
   нет только UI-витрины и diff-представления.
2. **UI редактирования принципов носителем** — носитель роли видит свои `RolePrinciple` / черты слоёв
   и может уточнить формулировку или оспорить принцип («это не мой типовой ход»). Сейчас контроль
   только post-hoc у manager/admin (mark-misleading), у носителя UI-входа к принципам нет.

## Почему отложено

- Витрина — read-only продуктовая надстройка: не влияет на качество клона, не блокирует основной слой метода.
- Редактирование носителем — продуктово-этическая развилка (граница между «уточнил формулировку» и
  «отредактировал себя в лучшую сторону» — само-курация ломает revealed-preference принцип слоя ценностей);
  нужно решение владельца о правах носителя.
- Правка принципа человеком должна согласовываться с авто-ресинтезом (cron перезатрёт ручную правку —
  нужен механизм `editedByHolder`/lock по образцу `editedByAdmin` в LLM-маршрутах).

## Что нужно для старта

- [ ] Решение владельца: какие права у носителя (просмотр / комментарий / правка / veto) и видит ли он
      слой ценностей (value/motivation) о себе.
- [ ] Накопленная история снапшотов после выката основного ТЗ (для осмысленного таймлайна нужно ≥3-4 недели).
- [ ] Дизайн взаимодействия ручной правки с `RolePrincipleSynthesisCron` (lock/merge при ресинтезе).

## Каркас будущих фаз (черновой)

- Ф1 — таймлайн снапшотов persona роли (`/roles/[id]/clone` вкладка «История») + diff секций.
- Ф2 — просмотр носителем своих принципов/слоёв + кнопка «оспорить» (probe-диалог, не inline-редактор).
- Ф3 — механизм `editedByHolder`-lock в ресинтезе + аудит правок.
