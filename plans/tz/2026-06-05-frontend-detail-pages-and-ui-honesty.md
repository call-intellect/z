# ТЗ-2. Детальные страницы открываются (Next 16) + честный русский интерфейс

## Цель
(1) Починить **критичный класс-баг**: детальные страницы (таблицы, задачи, спринты, роли, сотрудники и др.) не открываются, потому что `params` читается синхронно в Next.js 16 → `undefined`. (2) Привести интерфейс к честному и русскому виду: бренд «Кора» вместо «Z» в заголовках, единое «Консьерж», убрать наложение двух плавающих помощников, убрать англицизмы, понятные состояния для дампа/подтверждений.

## Зачем (по факту прода 2026-06-05)
- Открытие любой таблицы → `GET /api/v1/tables/undefined` → 404, экран «Таблица не найдена» (жалоба первого тестировщика T7). Карточка сотрудника по прямой ссылке → «Сотрудник не найден», хотя сотрудник есть (тихий провал). Это рушит целые разделы.
- Бренд непоследователен: вкладки показывают «… — Z» (старое имя) на десятках страниц, при «Кора» на других. Англицизмы в русском UI («Follow-up», «action items», «assignee», «prompt», «CustDev», «technology», «AI-чат», «Concierge», «Концьерж»). Тестировщик прямо спросил про опечатку «Концьерж».
- Два плавающих помощника наложены в одной точке — нижний недоступен для клика.

## REALITY-CHECK (проверено чтением кода)
- **Корень бага детальных страниц ВЕРИФИЦИРОВАН эмпирически** (не по типу аргумента, а по поведению): Next.js `^16.2.6` (`frontend/package.json:54`) делает `params` асинхронным (Promise). Сломанные страницы читают его синхронно.
  - ✅ Правильный образец (работает): `frontend/app/(authenticated)/cards/[id]/page.tsx`:
    ```tsx
    export default async function CardDetailPage({ params }: { params: Promise<{ id: string }> }) {
      const { id } = await params;
      return <CardDetailClient cardId={id} />;
    }
    ```
  - ❌ Сломанный паттерн (пример): `frontend/app/(authenticated)/tables/[id]/page.tsx`:
    ```tsx
    export default function TablePage({ params }: { params: { id: string } }) {
      return <TableClient tableId={params.id} />;   // params.id === undefined в Next 16
    }
    ```
  - Эмпирическое подтверждение: прямой SSR-переход на `/structure/persons/<реальный id>` → «Сотрудник не найден» (id не дошёл); `/tables/<id>` → `tables/undefined` 404. **Симптомы разные, корень один.**
- **Список сломанных страниц (22)** — все с синхронной сигнатурой `params: { ... }` в `page.tsx` (греп-маркер `params: { (id|slug|token|boardId|docId|cycleId|taskType): string`):
  `tables/[id]`, `documents/[id]`, `issues/[id]`, `experiments/[id]`, `orchestrator/runs/[id]`, `sprints/[id]`, `sprints/[id]/review`, `team-templates/[slug]`, `roles/[id]`, `roles/[id]/map`, `roles/[id]/clone`, `roles/[id]/clone/history`, `roles/[id]/skill-profile`, `structure/persons/[id]`, `persons/[id]/knowledge-profile`, `persons/[id]/social-contribution`, `persons/[id]/contributions`, `persons/[id]/skill-profile`, `admin/economics/orgs/[id]`, `admin/prompts/[id]`, `admin/ai-models/[taskType]`, `admin/ai/routing/[taskType]`.
  (Остальные ~40 динамических роутов уже на async-`params` и работают — частичная миграция, эти 22 пропустили.)
- **Бренд «Z» в title**: `metadata.title: '… — Z'` минимум в ~40 `page.tsx`/`layout.tsx` (греп `title: '… — Z'`). Это статические литералы — чинятся заменой `— Z` → `— Кора`. (Часть страниц уже «— Кора».)
- **«Концьерж»**: `frontend/src/lib/nav-help.ts:203`, `frontend/src/ui/tour/tours/project.ts:52`, `frontend/src/ui/tour/tours/overview.ts:172`. Кнопка-виджет — англ. «Concierge» (`aria-label="Открыть Concierge"`).
- **Два плавающих помощника**: `frontend/src/ui/concierge/ConciergeFloatingButton.tsx` (класс `fixed bottom-6 right-6 z-40`) и `frontend/src/ui/components/dashboard/AssistantSidebar.tsx` (кнопка «Помощник компании», тот же `fixed bottom-6 right-6 z-40`) — перекрываются; верхняя перехватывает клики нижней. Оба видны в `Sidebar.tsx`/`nav-help.ts`.
- **Англицизмы в мастере встречи**: `frontend/app/(authenticated)/meetings/create/*` («Follow-up письмо», «Задачи (action items)», «assignee», «таймкод», «Дополнительный prompt», типы «CustDev», «Customer Success»). В мастере проекта — категория «technology» у 2 шаблонов (источник — данные шаблонов, проверить seed/конфиг).
- **Дамп/подтверждения**: `/dump` после сохранения не даёт фидбэка «куда попало» (нет ленты/ссылки); `/actions` «Открыть» вопрос ведёт на заглушку `/feed/probe-questions`, а не к ответу; нет указания про канал/уведомление.

## Фаза 1 — Детальные страницы: async `params` на всех 22 роутах `[x]` 🔴 КРИТ
> Фактически найдено **26** синхронных страниц (после merge dev добавились `integrations/import-tracker/[importId]`, `clones/[roleId]`, `clones/[roleId]/chat/[conversationId]`, `admin/feedback/[topicId]`). Чинили все 26 по правилу «класс, не кейс».
**Цель:** каждая из 22 страниц получает реальный `id/slug/token/taskType`, разделы открываются.
**Что входит:** в каждом `page.tsx` из списка REALITY-CHECK заменить сигнатуру на `params: Promise<{…}>` и читать через `await params` (server-компонент) — по образцу `cards/[id]/page.tsx`. Если конкретный `page.tsx` помечен `'use client'` — использовать `const { id } = use(params)` (React `use`). Перед правкой каждого файла перечитать (номера строк дрейфуют), искать якорь `params: {`.
**Что НЕ входит:** правка `*Client`-компонентов, API, доменных мапперов.
**Acceptance (R-PARAMS):**
- Греп по `frontend/app/**/page.tsx`: паттерн `params: { (id|slug|token|boardId|docId|cycleId|taskType): string` встречается **0 раз** (все переведены на `Promise<...>`).
- Ручной/Playwright на проде после деплоя (или локально): открытие таблицы → НЕТ запроса `…/tables/undefined`, таблица рендерится; `/structure/persons/<id>` показывает реального сотрудника; открытие роли/задачи/спринта не даёт «не найдено».
- `bun run typecheck && bun run lint && bun run build` (frontend) зелёные.
**Закрывает:** S1-01, T7.

- Фаза 1: не пропустить `'use client'`-страницы (там `use(params)`, не `await`). Проверить, что после правки `id` реально не `undefined` (Playwright-смоук на 3–4 разных роутах: tables, persons, roles, sprints).

- Фаза 4: категория «technology» может приходить из БД/seed, а не из строки в UI — найти источник, иначе фронт-замена не поможет (тогда — patch данных шаблонов; зарегистрировать в `apply-prod-deploy.ts` при необходимости).
