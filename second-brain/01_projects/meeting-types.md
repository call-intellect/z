# Meeting Types — 13 типов встреч

Тип выбирается при создании встречи и определяет, какой шаблон применит AI-анализ. Это **главное продуктовое отличие** — не «универсальное саммари», а правильный результат под тип.

## Список типов

| Код типа | Название |
|---|---|
| `team` | Командная встреча |
| `standup` | Планёрка |
| `plan_fact` | План / факт по задачам |
| `project` | Проектная встреча |
| `sales` | Продажная встреча |
| `custdev` | CustDev / интервью |
| `partner` | Партнёрская встреча |
| `interview` | Собеседование |
| `customer_success` | Customer Success / сопровождение клиента |
| `review` | Обзорная встреча |
| `retrospective` | Ретроспектива |
| `task_discussion` | Обсуждение задачи (из задачи трекера) |
| `sprint_review` | Итоги спринта |

> Коды зафиксированы в Prisma-enum `MeetingType` (`backend/prisma/schema.prisma`) — это источник правды о type-safety. Отображаемые имена, описания, иконки и привязка к промпту отчёта хранятся в модели `MeetingTypeConfig` (DB-driven, редактируется из админки, code-fallback по умолчанию).
