# Как дойдём с 77 до 99 — единая карта

**ЦЕЛЬ:** recall «Мастера» с **~77-79%** → **95-99% верно**, выдумки ≤2-3%, не выдумывать на пустом.

**Честная рамка:** одного фикса «77→99» НЕТ — это портфель по стадиям конвейера. И часть «провала» — шум/артефакт
замера → **сначала чиним измерение (Шаг 0), потом стадии**.

---

## ⚠️ ВАЖНО: два уровня нумерации (чтобы не путаться)

- **Уровень 1 — ШАГИ (0–4):** большой план к 99%. **Пять штук.** Именно они двигают цифру.
- **Уровень 2 — ФАЗЫ (Ф0, Ф1, Ф2…):** нарезка работы ВНУТРИ одного шага (внутри одного ТЗ). К большому плану
  напрямую не относятся — это просто «кусочки одного шага».

**Где путаница:** «линейка» (Шаг 0) внутри имела **6 фаз Ф0–Ф5** — это НЕ шесть шагов, а шесть кусочков ОДНОГО
шага. Когда агент говорит «фаза 1, фаза 2» — это фазы внутри СВОЕГО шага, а не шаги плана.

```
Большой план (ШАГИ):   0  →  1  →  2  →  3  →  4      = 5 шагов
                       ✅    🔧    ⏳    ⏳    ⏳
Внутри каждого шага — свои маленькие ФАЗЫ (Ф0, Ф1, Ф2…), у каждого шага свои.
```

**Стадии конвейера (что какой шаг чинит):**
```
СЫРЬЁ → [извлечение → БАЗА] → retrieval → резолв → синтез → ОТВЕТ
           Шаг 1                 Шаг 3      Шаг 1/2    Шаг 4
   Шаг 0 (линейка) меряет КАЖДУЮ стадию и атрибутирует провал
```

## Что делаем ДАЛЬШЕ — цикл до 99 (по шагам)

1. **Агент дописал Ф1–Ф4 → меряем линейкой** (когда стенд свободен): recall **до/после** фикса + **атрибуция**
   (на каком этапе ещё теряем). Тут же по ③ — не просел ли поиск. Ты решаешь: катить фикс на прод или нет.
2. **Читаем атрибуцию → выбираем следующий Шаг** по самой большой течи:
   - поиск не поднимает факт → **Шаг 3** (поиск);
   - сыпятся «кто/когда/сколько» → **Шаг 2** (таблицы, сначала ревизия ТЗ);
   - факты есть, ответ неполный → **Шаг 4** (синтез, осторожно).
3. **Тот же круг на каждый шаг:** разложу по-человечески (было → предлагаю → суть) → ты решаешь → агент кодит
   на `work` → линейка меряет → твоё «да» на прод.
4. **Повторяем, пока не 99.**

**Суть:** 99% — не один заход, а цикл «померили → нашли самую большую течь → заткнули → снова померили».
Разница: следующий шаг выбираем **по цифрам линейки, а не на глаз**.

## Как связаны «стенд 111» и «Слой 0» (частая путаница)

- **Стенд 111 вопросов** (`batch-recall-trace.ts` + банк) = «честно ли ОТВЕЧАЕТ чат». Гоняли → **77-79%**.
- **Слой 0 (44 якоря)** = «правильно ли построена БАЗА» (выше по течению). Прогон сделан, дефекты найдены.
- **Ещё не связали:** не доказали, что дефекты базы = причина провалов 111. Это **атрибуция** (делает линейка
  после фикса). После фикса гоняем ОБА + атрибуцию → узнаём, влияет ли на ответ.

## Ожидаемая траектория (гипотезы, не обещания)

- Линейка убирает ~+2-4 фантомных → база **~80-82%**.
- Консолидация + таблицы + поиск → **+8-12** → **~88-92%**.
- **95-99** — многоитерационная арка (отличное извлечение + надёжная линейка), не один заход.

## Диагноз — почему застряли на 77-79 (установлено)

- Линейка врала (7 из 12 «пустых» — ложные) → **починено Шагом 0**.
- Анафора РАБОТАЕТ (гипотеза H3 снята).
- Провалы размазаны по стадиям: retrieval-recall, резолв (ведро ④), полнота синтеза, качество извлечения.
- База фрагментирована (Слой 0): сущности задвоены, блоки-дубли → **чинит Шаг 1**.
- Провенанс-баг (пустые citations) — отдельный фикс-трек.
