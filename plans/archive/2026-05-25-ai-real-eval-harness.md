# Тестовый стенд AI-агентов на реальных вызовах — фаза «малый старт»

## Цель

Эмпирически проверить, можно ли объединить четыре агента цепочки №1 (Главы + Задачи + Резюме + Оценка качества) в один вызов без потери качества — на минимальном масштабе (три синтетические встречи, один прогон каждой).

Если эксперимент покажет, что объединение работает — далее расширяем стенд (больше типов встреч, больше фикстур, больше агентов). Если не работает — оставляем раздельные агенты и фиксируем причину.

## Не цель этой фазы

- Тестировать цепочку №2 (память компании).
- Перестраивать продакшен.
- Запускать нагрузочные прогоны на тысячах фикстур.
- Делать LLM-судью «по всем критериям».

Эти задачи — следующие фазы, по результатам этой.

## Объём первого эксперимента

- **Тип встречи:** продажи (`type=sales`).
- **Фикстур:** 3 синтетические продажные встречи, ~15 тысяч знаков каждая, разные сценарии:
  1. Первая встреча с клиентом, высокий интерес, обсуждают пилот.
  2. Вторая встреча, возражения по цене, ЛПР отсутствует.
  3. Холодный лид, низкий интерес, отказ.
- **Прогонов:** 6 (3 фикстуры × 2 варианта).
- **Модель:** `deepseek-v4-pro` напрямую (без прокси).
- **Бюджет:** ориентир до 3 долларов на весь эксперимент.

## Гипотеза

Один объединённый вызов даст качество **не хуже -5%** по сравнению с раздельными вызовами, при экономии:
- стоимости — 40–60% (меньше входа за счёт того, что транскрипт уходит один раз),
- времени — в 2–3 раза (нет последовательных круглых поездок).

## Фазы

### Фаза 0 — Подготовка стенда (2 минуты)

- [x] Проверить `backend/.env`: ключ `DEEPSEEK_API_KEY` уже есть (подтверждено пользователем).
- [x] Создать папки:
  - `backend/test/eval/sales-merge-experiment/fixtures/` — синтетика.
  - `backend/test/eval/sales-merge-experiment/reports/` — отчёты прогонов (gitignored).
- [ ] Добавить запись в `.gitignore`: `backend/test/eval/**/reports/`.
- [ ] Смоук-вызов DeepSeek через `DeepSeekService` (один вопрос «привет, ответь словом ok») — убедиться, что ключ рабочий. Без вывода ключа в лог.

### Фаза 1 — Генератор синтетики (10 минут)

**Не дёргаем DeepSeek.** Генерируем фикстуры через три параллельных Claude-агента (тулза Agent) — каждый пишет одну продажную встречу.

- [ ] Запустить 3 параллельных Agent с задачей: «сгенерируй транскрипт продажной встречи на русском, ~15000 знаков, 2-3 спикера, временные метки `[mm:ss]`, сценарий: <свой>».
- [ ] Каждый агент сам сохраняет результат в `backend/test/eval/sales-merge-experiment/fixtures/fixture-XX-NAME.json` со структурой:
  ```
  {
    "fixtureId": "fixture-01-pilot",
    "meetingType": "sales",
    "scenario": "Первая встреча, высокий интерес, обсуждают пилот",
    "meta": {
      "clientName": "...",
      "speakers": [{"name": "...", "role": "..."}],
      "expectedFacts": ["...", "..."]
    },
    "transcript": "[00:00] Иван: ..."
  }
  ```
- [ ] Я проверяю глазами все 3 фикстуры, прежде чем двигаться дальше.

**Стоимость для проекта Z:** $0 (фикстуры генерит Claude по подписке пользователя, не DeepSeek).

### Фаза 2 — Прогон Варианта А (раздельные агенты) (3 часа)

Скрипт `backend/scripts/eval/run-variant-a.ts`:

- [ ] Для каждой фикстуры — четыре последовательных вызова к существующим промптам:
  1. `chapters-v2.prompt.ts` → главы.
  2. `tasks-v2.prompt.ts` → задачи.
  3. `summary-v2.prompt.ts` → резюме (markdown).
  4. `meeting-quality-score.ts` → оценка.
- [ ] Каждый вызов — через `DeepSeekService` напрямую, модель `deepseek-v4-pro`.
- [ ] Замеры: токены вход/выход (cached + uncached), миллисекунды на вызов, JSON-валиден ли.
- [ ] Сохранить результат в `reports/<fixture>-variant-a.json`:
  ```
  {
    fixtureId, variant: 'A',
    chapters: {result, tokens, ms, jsonValid},
    tasks: {...},
    summary: {...},
    qualityScore: {...},
    totals: {tokensIn, tokensOut, costUsd, totalMs}
  }
  ```

**Стоимость:** ~3 × 4 × ($0.05 за вызов) = ~$0.6.

### Фаза 3 — Прогон Варианта Б (объединённый агент) (3 часа)

Скрипт `backend/scripts/eval/run-variant-b.ts`:

- [ ] Один новый промпт `backend/test/eval/sales-merge-experiment/merged-prompt.ts` — объединяет четыре задачи в одну JSON-схему:
  ```
  { chapters: [...], tasks: [...], summary: "markdown", qualityScore: {...} }
  ```
- [ ] Для каждой фикстуры — один вызов к `DeepSeekService`, та же модель.
- [ ] Замеры аналогичные.
- [ ] Сохранить в `reports/<fixture>-variant-b.json`.

**Стоимость:** ~3 × $0.10 = ~$0.3.

### Фаза 4 — Сравнение (30 минут)

Скрипт `backend/scripts/eval/compare-variants.ts`:

- [ ] Для каждой фикстуры свести таблицу: стоимость A vs Б, время A vs Б, стабильность схемы (сломан ли JSON).
- [ ] **Судья-модель.** Отдельный вызов DeepSeek-Pro: «вот фикстура, вот выход X, вот выход Y — оцени каждый по 4 критериям (полнота глав, точность задач, осмысленность резюме, корректность оценки качества) шкалой 1-5, объясни». Метки A/Б скрыть за случайными X/Y, чтобы исключить позиционную предвзятость.
- [ ] Я (Сергей) сравниваю **глазами** независимо от судьи. Совпало мнение или нет — отдельная колонка в SUMMARY.
- [ ] Сохранить итог в `reports/SUMMARY.md` — таблицы + комментарии судьи + мои комментарии.

**Стоимость судьи:** ~3 × $0.20 = ~$0.6.

### Фаза 5 — Решение (обсуждение, не код)

По итогам `SUMMARY.md` решаем:
- **A.** Объединение работает → планируем фазу 2 эксперимента (расширение на остальные типы + LLM-судья + nightly прогоны).
- **B.** Объединение проигрывает → оставляем раздельные агенты, фиксируем причину в `second-brain/02_architecture/`.
- **C.** Смешанный результат → обсуждаем компромисс (например, объединить только три из четырёх).

## Что НЕ делаем в этой фазе

- Не трогаем продакшен (никаких изменений в существующих воркерах, промптах, оркестраторах).
- Не делаем «универсальный harness» — это просто три скрипта-эксперимента.
- Не покрываем тестами — это разовый исследовательский прогон.

## Решённые вопросы

1. Ключ DeepSeek — есть в `.env` (подтверждено).
2. Температура генерации фикстур — на усмотрение Claude (агент-генератор сам выберет, целимся в живость).
3. Режим размышления для Варианта Б — **включаем** (иначе сравнение нечестное).
4. Судья-модель — **включаем** (DeepSeek-Pro отдельным вызовом, сравниваем мнение судьи с моим).
5. Генерация фикстур — **через параллельные Claude-агенты**, не через DeepSeek (бесплатно для проекта).

## Итог

Исследовательский эксперимент на 3 фикстурах, ~$1.5 бюджета DeepSeek, ~6 часов чистой работы (вместо завышенных «1 рабочий день»). Цель — получить **первое числовое доказательство** до того, как делать большой стенд.
