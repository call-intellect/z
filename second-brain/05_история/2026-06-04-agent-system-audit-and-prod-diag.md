# Полный аудит системы агентов + прод-диагностика + handoff (2026-06-04)

## Что было поставлено
Владелец начал тестировать систему — «ничего не работает». Задачи по ходу сессии:
1. Разобрать прод-логи встречи: что работает / что нет.
2. **Полный аудит системы всех агентов** (все каналы входа → knowledge-core → граф → задачи/трекер), маппинг на Prisma.
3. **МТЗ на починку** + **боевой тест на синтетике** (локальный dev).
4. Промпт для следующей сессии (handoff).
+ по ходу: 2 новых бага (видео; последовательная транскрибация), подключение прод-доступа.

## Как решал (файлы, прогоны, коммит)
- **Два workflow-аудита:** (1) 8 агентов — 7 корневых причин + `pipelineMap` из 15 узлов; (2) 53 агента — 38 подтверждённых багов / 10 областей с состязательной проверкой (43 проверено, 5 опровергнуто). Выгрузки — в temp-файлах задач.
- **pull `dev@1c0214e4`** в середине — перепроверил находки на свежем коде (merge не трогал блокеры критпути; #7 получил лишь ручную привязку Person через «Команду»).
- **Загадка typecheck-слепоты Prisma решена эмпирически:** свежий `bunx prisma generate` + `tsc --noEmit` = 0 ошибок, хотя `skillTrait.findMany({tenantId})` и `insight.create({dataClassAudit})` невалидны. Причина — Prisma типизирует args через generic `Subset<T,Args>`, и excess-property-check не срабатывает для вложенного `where`/`data`. → `tsc` структурно слеп к этому КЛАССУ.
- **Прод-диагностика `backend/scripts/diag.ts`** (read-only, креды в корневом `.env`, `--env-file`): на боевой failed-встрече `01KT8KYS…` подтвердил B1 (`Vox poll timeout 60×2000ms`, 5 ASR FAIL по ~121с, нет транскрипта/отчёта). Нашёл, что **видео готово** (`Recording.status=ready`, mainVideoUrl, 616МБ faststart), но прячется, потому что встреча `failed`.
- **Транскрибация:** подтвердил последовательную отправку дорожек (цикл `for…await`, `transcribe.worker.ts:174`) и что алгоритм тайм-выравнивания по ролям **уже корректен** (`merger.ts`), но точность держится на `AudioTrack.startedAt = new Date()` бэкенда (риск для позднего участника).
- **Синтез 3 документов** третьим workflow (агенты читали выгрузки с диска), материализация на диск скриптом, дополнение своими находками, коммит `0952acd4` + push.

- 7 файлов в `plans/` + `backend/scripts/` (аудит, addendum, МТЗ №1, харнесс-план, харнесс-скрипты, next-session-prompt). `tsc --noEmit` зелёный. Push в dev успешен.
- B1 доказан на боевых данных (не только логах). Прод-доступ работает.
- Критпуть: **B1 Vox → B2 specialist-routing (14 воркеров/1 очередь, ~13/14 блоков теряются) → B3 draft/canonical → B4 projection skillTrait → B5 AGE search_path → B6 пороги графа → B7 ingestMeeting swallow.** «Починить только Vox» недостаточно.

## Чему научился
- **`tsc` слеп к Prisma-литералам** (Subset generic) — целый класс «код↔схема» ловится только интеграционными тестами против реального Postgres, не typecheck'ом.
- **specialist-routing на одной очереди с 14 воркерами** — `jobName` НЕ маршрутизирует в BullMQ (распространённый миф); тихая потеря блоков без retry.
- **Анализ в temp-файлах задач не переживает сессию** → для handoff материализовать в `plans/`.
- **diag.ts** — сильный рычаг: гипотезу про встречу проверяешь на боевых данных за один вызов. Правило: заход в прод — только по явному подтверждению владельца в сессии.
- Один симптом `failed` тащит за собой исправную запись — артефакты (видео) надо развязывать от статуса AI-конвейера.
