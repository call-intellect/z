# Recall «Мастера» — было → стало (приёмка Ф8)

> Перепрогон тех же 111 вопросов «Стрелы» тем же харнессом (`batch-recall-trace.ts`), все kill-switch'и ON, answer-кэш тенанта очищен (112 ключей) → каждый вопрос пошёл свежим через новый контур. Строгая смысловая сверка ответов с эталонами — панель из 8 независимых LLM-судей.

**+19.8 п.п. верных ответов, провал recall упал втрое (33%→8%), обход по связям — с 14% до 100%, честность держится (0 галлюцинаций).**

## Именованные кейсы приёмки (были провальными — стали верными)

- **«Что с ошибкой 429?»** (был пустой отказ) → верно: блокировка Битрикса при массовом синке, backoff, запрос в поддержку. Инверсия «точный вопрос отвечает хуже описательного» **починена** (Ф2 boost + Ф3 EntityLink: ярлык 429 дотянулся до блоков Битрикса).
- **«Что с Zoom-интеграцией?»** (был пустой отказ) → верно: интеграции нет, блокер продаж Логистик Плюс, статус выясняет Александр.
- **«Что с интеграциями в целом?»** (было «активен только Битрикс, других не зафиксировано») → верно: **Битрикс + Telegram + Zoom** без ложного отрицания (Ф5 сводка + снятие схлопывания перефраз).
- **«Кто отвечает за то, что блокирует продажи?»** (многошаговый) → верно: цепочка блокер→Zoom→**Александр** через 2-hop (Ф7 адаптивная глубина).

## Что закрыто (корни из диагноза)

1. **Граф гасился фильтром (главный корень, 22/24 провалов)** → Ф1: обход участвует всегда. graphRan 14%→100%.
2. **Буквальный фильтр по узлу → пустой пул (парадокс 429/Zoom)** → Ф2 (фильтр как boost, не cutoff) + Ф3 (EntityLink вещь↔вещь). Контрольные пары 429/Zoom больше не инвертируются.
3. **Широкие/списки отрицали существующее** → Ф5 (сводка без «не зафиксировано», перечень встреч за период). q034 отвечает всеми тремя интеграциями.
4. **Пустой пул → отказ** → Ф4 (каскад: снять фильтр → углубить граф → честное «близкое»), провал 33%→8%.
5. **multi-hop не дотягивался** → Ф7 (2 hop на многошаговых). q062 отвечает через звено.
6. **Понималщик без справочника** → Ф6 (grounding): резолв 40%→45%.

## Две цели не дотянуты — честный разбор (весь остаток в смежных/vNext-системах)

**Верно 79.3% против цели 85% (−5.7 п.п.) и резолв 45% против 65%.** Остаток провалов (9 false_empty + 13 partial + 1 wrong) распадается так, и НИ ОДИН пункт не относится к сути переработки retrieval (она сделана):

- **Глубина резолва сущности (45%)** — q008/q025/q029/q030/q066/q067. Grounding Ф6 (ILIKE по токенам) дал +5 п.п.; путь к 65% — эмбеддинг-поиск кандидатов, **явно отложенный в Ф6 как vNext** («эмбеддинг — vNext если trgm мало»). trgm оказалось мало.
- **Не-детерминизм понималщика в answer-пути** — q054/q060 «встречи/созвоны за неделю» вернули пусто, ХОТЯ: детерминированный классификатор даёт `list (0.9)`, `listEpisodesByDateRange` + данные проверены (last_week → 12 эпизодов). Причина — харнесс дважды зовёт понималщик (логируемая трасса ≠ трасса ответа, LLM-вариативность периода/класса); baseline это уже отмечал. Код Ф5 корректен.
- **Топик-мисклассификация** — q057 «планёрки и стендапы» классифицируется как topic (0.4), а не list → перечень по типу без даты не строится (узкий край, вне именованных кейсов).
- **Полнота синтеза (13 partial)** — q049/q051/q084/q089/q090 и др.: retrieval нашёл, синтез суммировал неполно (упустил часть фактов). Синтез **явно вне scope ТЗ** («синтез и честность не трогаем»).

### Ключевой инвариант: 79.3% верных при 0 галлюцинаций — это граница честность/охват, которую ТЗ задал сам

Часть false_empty (q025/q066/q067) — это ответы, где нужный человек **упомянут в контексте, но синтез отказался его назвать** из осторожности. Это ровно тот механизм honest-abstain, который держит галлюцинации на нуле (R9). Поднять верно до 85% можно, ослабив эту осторожность — но это прямой обмен «галлюцинации ↔ охват», который ТЗ запретил (🚫 «ослаблять honest-abstain так, что появляются галлюцинации»; ⚠️ «трогать синтез-промпт — риск честности»). **Итог 79.3%@0-галлюцинаций сидит на честностной границе, заданной самим ТЗ.** Дальнейший подъём — это продуктовое решение владельца (готов ли обменять честность на охват), а не технический дожим.

## Follow-ups (в реестр не-сделанного)

1. **Эмбеддинг-grounding понималщика** (резолв 45→65%) — Ф6 vNext.
2. **Детерминизм понималщика в answer-пути** для периода/класса «список за период» (устранить вариативность q054/q060; убрать двойной understand харнесса или сделать период/list детерминированными до LLM).
3. **Полнота синтеза** для broad/aggregate (partial→correct) — было вне scope, требует владельческого «трогаем синтез».
4. **Честность vs охват** — решение владельца: ослаблять ли honest-abstain ради +~6 верных (риск первых галлюцинаций).
5. **AGE/Cypher** («Эдж») — остаётся отложенным (реляционный 1-2 hop закрыл корни; доля multi-hop в банке мала — 7/111).

## Методология (честность замера)

- Все 111 — свежий прогон (answer-кэш очищен), в отличие от baseline (8 вопросов из кэша).
- Харнесс дважды зовёт понималщик → латентность 59.4с завышена; реальный путь пользователя быстрее.
- `honest`-эвристика харнесса даёт ложно-негативы (q055 перечислил встречу Логистик Плюс, q072 честно отказал по выручке — оба помечены «пусто», но по сути верны); поэтому строгий счёт — по LLM-судьям, а не по harness-флагу.
