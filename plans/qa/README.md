# QA Коры — единый трекер багов и приёмки

> Папка живого контроля качества прод-кабинета `meet.crossmark.ru`. Здесь — **что нашли, что починили, что перепроверили**. Не отчёт-однодневка, а трекер с жизненным циклом каждого бага.

## Зачем папка

Раньше результаты прогонов разъезжались по `plans/analysis/` отдельными датированными файлами (`*-manual-qa-RESULTS`, `*-retest-*`). Найти «а этот баг в итоге починили или нет?» было нельзя. Эта папка сводит всё в **один реестр** с галочкой «исправился / не исправился».

## Как устроено

| Файл / папка | Что это |
|---|---|
| [bugs-registry.md](bugs-registry.md) | **Единый живой реестр** всех багов. Источник правды о статусе. Один баг = одна строка со стабильным ID. |
| [sessions/](sessions/) | Отчёты прогонов тестировщика (по дате). Подробности «как воспроизвёл», скриншоты, diag-трейсы. Реестр ссылается сюда. |
| `../analysis/2026-06-0X-*-RESULTS*.md` | Историческая летопись прогонов 5–7 июня (manual-qa → retest → retest2). Не переносим — реестр на них ссылается. |

## Жизненный цикл бага (статусы)

```
🆕 найден  →  📝 ТЗ написано  →  🔧 исправлено (ждёт ретеста)  →  ✅ проверен-исправлен
                                                              ↘  ❌ проверен-НЕ-исправлен  →  (reopen, назад в 📝/🔧)
```

Доп. статусы: `⏸️ отложен` (есть причина), `🚫 не баг / отклонён`.

**Severity:** `P0` (блокер — раздел/функция нерабочая) · `P1` (серьёзно, но есть обход) · `P2` (заметно, не критично) · `P3` (косметика/копирайт).

## Процесс (цикл)

1. **Нашли баг** (live-тест или diag) → строка в [bugs-registry.md](bugs-registry.md), статус `🆕`, severity, раздел, симптом, доказательство (скрин/трейс).
2. **Написали ТЗ** на фикс (`plans/tz/`) → статус `📝`, ссылка на ТЗ.
3. **Починили** (коммит) → статус `🔧`, ссылка на коммит.
4. **Перепроверили** в кабинете → `✅` (закрыт) либо `❌` (reopen с новым доказательством).

Правило: статус `✅` ставится **только после живого ретеста**, не по факту коммита (коммит ≠ работает на проде).
