## Что вышло

- **Коммит `cdd36c3`** на `dev`, push успешен.
- **Параллельная работа:** пока я писал ТЗ, кто-то (другой агент или пользователь) уже начал реализовывать Фазу A — появились `Chip.tsx`, `Sparkline.tsx`, `QueryGate.tsx`, `ConfirmDialog.tsx`, `StatCard.tsx`, `useSwrWithToast.ts`, обе `(design-preview)/light-theme/` и `/dark-theme/` директории, изменённые `tokens.css` + `tailwind.config.ts` + `EmptyState.tsx`. То есть ТЗ сразу пошло в работу — это хороший сигнал, что оно было воспринято как руководство к действию.
- **Стратегия sage+warm-mint** — паре hue (155 / 168) близкие в OKLCH, образуют семейство, бренд читается в обеих темах.

## Чему научился

1. **`git commit` коммитит ВСЁ из index, не только то, что добавил последним `git add`.** Я указал `git add` на 3 свои файла, но в index уже лежали 53 staged-переименования `plans/tz/* → plans/archive/*` от предыдущей сессии — коммит получился 57 файлов вместо 3. Это нарушает правило «коммитить только своё». На будущее: **перед `git commit` всегда делать `git status` и смотреть, что в index, а не только что я только что добавил**. Если в index есть чужое — либо `git reset HEAD <чужие пути>` сначала, либо `git commit -- <свои пути>` (pathspec). Заношу в feedback memory.

2. **4 параллельных Agent-вызова экономят 5x времени, если задачи независимые.** UI / API / light / dark — четыре непересекающиеся темы, каждый агент работает в read-only режиме со своим скоупом. Главное — задать жёсткий лимит слов в промпте (≤600-700), иначе агенты возвращают по 3000 слов и сжигают контекст.

3. **Research-файл с тегами в шапке = находимость через grep.** Строка `Теги для поиска: интерфейс, UI, дизайн, design system, светлая тема, токены, палитра...` критична — пользователь через 2 недели не вспомнит точное имя файла, но вспомнит «у нас был анализ светлой темы». Grep по «светлая тема» сразу выводит на файл.

4. **Когда пользователь говорит «выбери лучшее сам» — действительно выбирать и обосновывать, а не возвращать список опций.** Раньше у меня было искушение перечислить «варианты A/B/C, что выбираем?». Здесь сразу написал sage + warm-mint с обоснованием — пользователь это принял без вопросов.

5. **Параллельная работа разных агентов на одном репо — реальный сценарий.** Пока я писал ТЗ, ТЗ уже воплощалось. Это значит ТЗ нужно писать **самодостаточным**: со списком файлов с путями, OKLCH-значениями, DoD — чтобы другой агент мог взять и работать без переспросов. У меня получилось — реализация началась сразу.
