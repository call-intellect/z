# Прогон тестирования прода (progon)

**Главный файл (источник правды):** [docs/testing/README.md](../../../docs/testing/README.md) — хаб тестирования. Всё содержимое протокола — там; этот скилл только запускает его.

## Что делать при вызове

1. **Открой хаб** `docs/testing/README.md` и читай раздел «📌 Состояние прогона» — возьми дату **«Последний прогон логов»**. Период = с этой даты по сегодня (прошло 2 дня → берём 2 дня).

2. **Иди по «▶️ Протоколу „запускаем“»** из хаба, по шагам:
   - **Шаг A** — сверь «🔁 Карту ожидаемого функционала» + собери прод-сигналы read-only:
     - `bun --env-file=.env backend/scripts/diag.ts usage --limit 100 --preview 0` — какие taskType бегали, есть ли `FAIL`;
     - `bun --env-file=.env backend/scripts/diag.ts logs --at-least WARN --from <ISO-дата периода> --limit 80` — ошибки/деградации;
     - `... diag.ts meetings --limit 20` / `trace --meeting <id>` — цепочка после видео.
     - Маркеры: `no eligible provider`, `требует apiKey`, `упал`/`fallback`, `P2002`, `ошибка на кластере`.
   - **Шаг B** — из «🧾 Реестра коммитов» бери непроверенные сверху (новые первыми), закрывай три галочки (в проде / применён / работает).
   - **Шаг C** — не хватает логов для доказательства → добавь логирование, пуш на прод, дочитай на следующем прогоне.
   - **Шаг D** — обнови статусы в карте и реестре, добавь строку в «🗒️ Журнал лог-прогонов» с полем «Рефлексия» (что дополнить в карту), обнови «Последний прогон логов» на сегодня.

3. **Прод read-only** — прод-БД с ноутбука недоступна; сигналы только через `diag.ts` (HTTP) или SSH (см. раздел «Доступы» в хабе). Ничего на проде не меняй без явного «да» владельца.

## Границы
- Только read-only наблюдение + запись находок в хаб. Фиксы/мутации прода — отдельно, по решению владельца.
- Креды и доступы — в хабе (раздел «🔑 Доступы»), пароли в gitignored `.qa-cabinet.local.json`, не переспрашивай.
