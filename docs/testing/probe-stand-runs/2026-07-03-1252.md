## Пробелы: где вопросов не хватает (обратная проверка по P1/P3)

- **Момент:** Зафиксировано событие ухода сотрудника или смены роли (из чата, календаря, HR-системы)
  **Вопрос:** «Сотрудник X покидает роль. Какие задачи, клиентские договорённости или неявные знания нужно передать до его ухода?» → руководитель уходящего сотрудника
  **Почему человек:** P1 — система видит факт ухода, но неформальные обязательства, устные обещания клиентам и контекст незадокументированных процессов знает только сам сотрудник или его руководитель. Автоматически это не выводится из данных.

- **Момент:** Обнаружено снижение активности ключевого клиента: падение объёма заказов, рост пауз в коммуникации, негативная тональность в переписке
  **Вопрос:** «Заметили снижение активности клиента Y за последние 2 недели. Что происходит — есть ли риск потери и что планируете предпринять?» → ответственный за клиента (менеджер)
  **Почему человек:** P1 — система видит количественный и тональный паттерн, но причину (бюджет клиента, недовольство качеством, уход контактного лица, активность конкурента) и контекст отношений знает только менеджер, ведущий клиента.

- **Момент:** Два противоречащих стратегических вывода из разных встреч/документов за короткий период (например, «выходим в новый регион» vs «углубляем текущий»)
  **Вопрос:** «В выводах двух недавних встреч есть противоречие: команда A предлагает расширение в регион, команда B — концентрацию на текущем рынке. Какое направление сейчас приоритетнее?» → owner компании
  **Почему человек:** P3 — конфликт стратегических сигналов, машина фиксирует противоречие, но разрешить его может только владелец стратегии, видящий полную картину и внешний контекст.

- **Момент:** Пересечение двух срочных задач/инициатив на одном сотруднике в одном временном окне (конфликт ресурсов)
  **Вопрос:** «У сотрудника X пересекаются две срочные задачи: «A» и «B» — обе со сроками на этой неделе. Какая приоритетнее?» → руководитель сотрудника / постановщик задач
  **Почему человек:** P3 — система видит конфликт загрузки, но приоритет определяется бизнес-контекстом, внешними обязательствами и стратегической важностью, которые не формализованы в данных.

- **Момент:** Открытая роль не закрыта дольше ожидаемого срока, при этом есть кандидаты в воронке
  **Вопрос:** «Роль X открыта уже 3 недели. Что сейчас важнее: дождаться идеального кандидата или ускорить закрытие позиции с компромиссом по требованиям?» → hiring manager / owner
  **Почему человек:** P1 — trade-off между скоростью и качеством найма, бюджетные ограничения и реальная критичность роли известны только hiring manager'у; из данных о длительности открытия роли ответ не выводится.

### consistency_violation.R2 (×2) — drop (убрать)
- пример: «Шаг процесса не создаёт ни одного результата: «QA-стенд: Передать сегмент в рассылку»»
