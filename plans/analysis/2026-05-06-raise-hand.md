# Анализ: Поднять руку (Raise hand)

## Что хотим сделать

Каждый участник встречи (host или guest) может «поднять руку» — UI-сигнал, что хочет высказаться. Состояние видно всем участникам в режиме реального времени. Опускается вручную (кнопкой) или автоматически по триггерам.

## Зачем (цель и ценность)

- На встречах от 5 человек разговор сваливается в перебивания. «Поднять руку» даёт ведущему очередь и не ломает поток.
- Особенно полезно на типах: `team` (командная), `standup` (планёрка), `project` (проектная), `interview` (собеседование).
- Низкая стоимость реализации — не блокирует MVP по срокам.

## Как работает сейчас

Кода нет. В исходном решении (`livekit_ai_meetings_final_solution.md`) фичи не было, добавлена в MVP по решению 2026-05-06.

## Техническая база

LiveKit предлагает два способа транспорта:

### Вариант A — Participant Attributes (рекомендую)

LiveKit нативно поддерживает `participant.attributes` (key-value на участнике). Изменения автоматически пропагируются всем в комнате, включая **тех, кто присоединится позже**.

```ts
// Поднять руку
await localParticipant.setAttributes({ hand_raised: 'true', hand_raised_at: Date.now().toString() });

// Опустить
await localParticipant.setAttributes({ hand_raised: 'false', hand_raised_at: '' });
```

**Плюсы:** не нужен свой стейт-менеджмент, поздний присоединённый участник сразу видит, у кого поднята рука; нет race condition.

**Минусы:** атрибуты persist'ятся для участника на всё время сессии — нужно явно чистить при выходе.

### Вариант B — DataChannel сообщения

Публиковать `{ type: 'hand_raised' | 'hand_lowered', participantId, ts }` через `localParticipant.publishData(...)` reliable.

**Минусы:** поздно присоединённый не видит текущее состояние — нужно делать sync через отдельный запрос или ждать следующего change event.

→ **Идём по варианту A (Participant Attributes).**

## Открытые вопросы

### UX

- [ ] **Иконка** возле имени участника (✋) или подсветка тайла рамкой — что наглядней?
- [ ] **Звуковое уведомление** ведущему при поднятии руки — нужно или нет? (Предложение: нет в MVP.)
- [ ] **Список «очереди»** для ведущего — показывать упорядоченный список поднявших руку или только бейдж на тайлах?
- [ ] **Кнопка «Поднять/опустить руку»** — отдельная в нижней панели, или в меню «...» рядом с микрофоном?
- [ ] **Бейдж в списке участников** — да/нет?

### Поведение

- [ ] **Кто может опустить руку:** только сам участник? Или и ведущий тоже («ведущий услышал, опускает за всех»)?
- [ ] **Автоопускание:** после N секунд/минут неактивности? (Предложение: нет — пусть участник сам опускает; иначе UX путается.)
- [ ] **При выходе** участника — рука автоматически снимается (атрибуты Participant сбрасываются на сервере при disconnect — проверить).
- [ ] **Опускается ли при размьюте** микрофона? (Предложение: да — если участник заговорил, рука опускается автоматически.)

### AI / отчёт

- [ ] **Фиксируем ли** события поднятия руки в AI-отчёте? Например, «Иван 3 раза поднимал руку, но не получил слова». (Предложение: V2 — добавляет ценность для команд, но в MVP усложняет UI и логирование. В MVP — только runtime-индикация без сохранения.)

### Технические

- [ ] **Сохраняем ли** события в БД (для истории)? Связано с предыдущим вопросом про AI.
- [ ] **Webhook от LiveKit** на изменение attributes — нужен ли (для AI-аналитики), или только клиентского отображения хватит?
- [ ] **Limit:** ограничивать ли частоту (rate limit на смену состояния) — пока что один тогл в секунду на участника?

## Что выяснили исследованием

LiveKit `participant.attributes` — официальный механизм. Используется в нативных примерах LiveKit для подобных кейсов (raise hand, status). Атрибуты сбрасываются автоматически при disconnect участника.

## Решения принятые в ходе обсуждения (2026-05-06)

Опираемся на стандарт Zoom (самый популярный) — без изобретения нового.

- **Включаем в MVP.** Транспорт — Participant Attributes (Вариант A).
- **Иконка:** ✋ в углу тайла участника + строка в боковой панели «Участники» с той же иконкой.
- **Очередь:** в панели «Участники» те, у кого поднята рука, **поднимаются наверх и сортируются по времени поднятия**. Отдельного списка-окошка нет.
- **Кто опускает:** сам участник всегда; **ведущий может** опустить любую (одну или «опустить все»).
- **Авто-опускание при размьюте:** **нет.** Пусть участник сам опустит — чёткий сигнал.
- **Звук уведомления:** **нет.** Чтобы ведущий не сходил с ума на встрече с 10 человек.
- **Сохранение в БД для AI:** **нет в MVP.** В V2 можно — «Иван трижды поднял руку, не получил слова» как подсказка к шаблону командной встречи.
- **Кнопка** — отдельная в нижней панели рядом с микрофоном. Не прячем в меню «...» — должна быть видна.
