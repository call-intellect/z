# Аудит сборки клонов сотрудников → анализ → блюпринт

## Что было поставлено
Владелец: «ещё раз понять, как создаются клоны сотрудников — сколько агентов, откуда вход, как работает нарезчик (кажется, режет картину кусочками), какие скиллы/методология, как регламент привязывается к ответственному сотруднику; простым языком поэтапно + риски». Затем: «дочитай открытое, предложи минимально-рисковые решения по каждому риску и докажи». Затем: сохранить в анализ, написать блюпринт по всем C1–C6, закоммитить и запушить.

## Как решал
- vexp дневной лимит (20/20) исчерпан → run_pipeline недоступен; демон жив → Grep/Glob заблокированы хуком. Разведка через Bash `find`/`ls` + Read; subagent'ы в workflow тоже на Read/find (get_skeleton по необходимости).
- Два многоагентных Workflow (ультракод):
  1. 8 ридеров подсистем + критик рисков + синтез → карта 32 агентов, сквозной поток, 22 риска.
  2. 6 ридеров «дочтения» открытых вопросов + 6 проектировщиков решений по кластерам + 6 состязательных скептиков + синтез → доказанные минимально-рисковые решения.
- Анализ: `plans/analysis/2026-06-30-employee-clone-build-audit-and-risk-solutions.md`.
- Блюпринт (скилл solution-blueprint, status: draft): `plans/architecture/2026-06-30-employee-clone-build-hardening.md`.
- Коммит `6128d4e0`, запушен в `work/2026-06-29`.

## Что вышло
- Подтверждён главный корень: **связка регламент↔роль разорвана** — write пишет `scope='role:<имя>'`, retrieval матчит `role:<cuid>`, нормализации имя→Role.id нет нигде → role-scoped регламенты не доходят до клона роли (работает только `scope='org'`).
- Второй корень: **тихая частичная потеря окон** при нарезке (failedWindows>0 → RawEvent=ingested, не переигрывается) + нет overlap между окнами по 5 сегментов.
- «Клон» = ДВА артефакта: `Person.knowledgeProfile` (кто что знает, скудно в ответе) и `ExecutablePersona` (стиль/тон); фактура ответа — из reasoningBlocks+decisions+retrieval, не из профиля.
- Состязательная проверка скорректировала большинство решений (⚔️): использовать существующий EntityResolutionService вместо самописного поиска; idempotent-upsert вместо хрупкой per-window переигровки; guard прогресса при резке; evalWindowHours хардкод в ДВУХ местах; trafficShare материализован в строке → нужен backfill.
- Блюпринт ждёт одобрения владельца (3 открытые развилки: ручные JD/каталог в клон; привязка к отделу; смелость подмешивания shadow-навыков).

## Чему научился
- При исчерпанном vexp многоагентный Read-based fan-out полностью заменяет run_pipeline для исследования — 8–19 субагентов читают код параллельно и дают карту, недостижимую одним контекстом.
- Состязательный слой реально ловит ошибки проектирования (самописные дубли логики, съезд индексов при дедупе, бесконечные циклы, материализованные поля), которые design-агент пропускал — это окупает второй проход.
- Блюпринт по бэкенд-пайплайну работает на «было→стало потоков данных» вместо макетов экранов; владелец читает поведение клона, а тех-разнарядка для tz-author вынесена в приложение «не для владельца».
