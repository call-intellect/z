Это ТЗ сводит ВСЁ в один релиз: вернуть видимость, выкатить готовый фикс + промпты, ускорить агента и **достроить авто-наполнение до всех 10 шаблонов** (мост граф→таблицы с гейтом уверенности). Полный аудит-обоснование — [plans/analysis/2026-06-20-smart-tables-live-audit/](../analysis/2026-06-20-smart-tables-live-audit/README.md).

## Фаза 4 — Авто-наполнение ВСЕХ 10 шаблонов (три группы по источнику) `[ ]` (главная доделка)

**Цель:** «данные сами текут во все 10». Делим по типу источника — усилия разные.

### Группа A — 4 «связанные» (Клиенты/Команда/Поставщики/Регламенты): механизм работает, упор на граф
**Проверено на проде 2026-06-21:** entitySync РАБОТАЕТ — «Команда» = 3 строки, все привязаны к Entity графа; в графе Org 37 сущностей. Таблицы пустеют не из-за модуля tables, а из-за графа: клиентов/поставщиков/документов в нём почти нет, у людей качество хромает («представитель», сырой id вместо `canonicalName`).
- **Это трек knowledge-core, не tables** — граф должен рождать `customer`/`vendor`/`document`-сущности и не плодить мусор-имена. Не дублируем: баги качества графа — [knowledge-core MASTER](2026-06-16-knowledge-core-MASTER.md).
- **В этом ТЗ по Группе A:** только смоук-гард — тест/проверка «строки sync-таблиц привязаны к Entity, `canonicalName` не равен сырому id»; если ловим мусор-имена — строка-указатель в реестр не-сделано на knowledge-core, не чиним здесь.

### Группа B — 4 «мягкие» с готовым источником: мост graphSync (Идеи/Цели/Гипотезы/Обещания)
Поверх инфры Фазы 3, добавить **создание строк** из графовых объектов, с порогом уверенности.

#### 4.1 Новый канал `graphSync` на шаблоне
- Каталог [system-tables.catalog.ts](../../backend/src/modules/tables/templates/system-tables.catalog.ts): добавить опц. `graphSync` параллельно `entitySync`:
  ```ts
  graphSync?: { source: 'idea_block' | 'goal' | 'experiment' | 'action_item'; fieldMap: Record<string,string>; autoCreate: boolean };
  ```
- Проставить (по Р-2): `ideas`→idea_block, `okr`→goal, `hypotheses`→experiment, `promises`→action_item. `risks`/`content_plan` — `null` (пока).
- Prisma `Table`: новое поле `graphSync Json?` (миграция). Backfill для существующих Org (проставить graphSync системным таблицам по `systemKey`).

### 4.2 Row-extractor в enrich-пайплайне
- Расширить `table-enrich.service.ts`: помимо ветки «патч ячеек sync-таблиц» — ветка «создать строку в graphSync-таблице».
- Вход: графовый объект (Goal/Experiment/IdeaBlock/Issue) → маппинг полей `fieldMap` в ячейки. Для свободных формулировок — LLM `table-extract-rows` (уже есть) по схеме колонок.
- **Дедуп строк** по primary-колонке (переиспользовать Jaccard/embedding из R3 `findSimilarTables`) — не плодить дубли при повторных событиях.

### 4.3 Гейт уверенности (БЕЗ очереди подтверждений — Р-3)
- `confidence ≥ table.agent.confirmation_threshold (0.85)` → строка создаётся сразу + `TableCellProvenance` (источник + deep-link на тайминг/объект).
- `confidence < порога` → **фоновый низкоприоритетный пул** (новая таблица `TableRowPendingDraft` или статус-флаг), TTL `table.agent.draft_ttl_days` (новый AdminSetting, дефолт 14). Дозревает при повторном подтверждении из другого источника, иначе истекает. **Никаких пушей владельцу, не в `PendingActionsService`.**
- Строки из графа помечать provenance-источником; ручные правки пользователя НЕ перетирать (анти-самоотравление).

### 4.4 Триггеры
- `meeting.ai_ready` (уже эмитится) — для action_item/idea из встреч.
- `entity.created/updated` расширить на Goal/Experiment/IdeaBlock (шина как в Фазе 2) — чтобы новая цель/эксперимент сразу попадали строкой.
- Throttle на Org уже есть (`table:enrich:jobs:${tenantId}`), бюджет токенов — `max_daily_tokens`.

### 4.5 AdminSettings (новые крутилки — [[feedback_admin_settings_not_env_or_code]])
- `table.agent.draft_ttl_days` (14) — TTL фонового пула спорных строк.
- `table.graphsync.enabled` (true, kill-switch) — аварийный рубильник авто-наполнения.
- Регистрация в `admin-setting-schema-registry.ts` + сид + UI-поле.

### Группа C — Риски (новый извлекатель) + Контент-план (ручной)
- **Риски** (`risks`): в графе нет объекта «риск». Добавить лёгкий извлекатель риск-сигналов поверх уже извлечённых блоков встреч/решений/инсайтов — LLM-классификатор «это риск?» (новый промпт `table-extract-risks` или ветка в `table-extract-rows` со схемой колонок «Реестр рисков»: Описание/Вероятность/Влияние/Митигация/Статус/Владелец). Через тот же гейт уверенности и дедуп. Источник события — `meeting.ai_ready` + decision/insight-апдейты графа. Промпт — cache-friendly.
- **Контент-план** (`content_plan`): организованного источника в прошедших событиях нет (план вперёд). **Авто-извлечение не делаем.** Оставить ручной таблицей; опц. под-задача (vNext) — подтягивать Issue с меткой контент/маркетинг как строки. В каталоге `graphSync: null`.
