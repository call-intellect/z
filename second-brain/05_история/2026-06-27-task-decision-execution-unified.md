# Рефлексия — задача/решение/идея: починка извлечения + сквозное исполнение + журнал хода

## Что было поставлено

Реализовать ТЗ `2026-06-27-task-decision-execution-unified` (6 фаз) как оркестратор: починить жизненный цикл «разговор → знание → исполнение → закрытие». Режим — автономный: развилки решаю сам (найти лучшее → доказать → применить), к владельцу прихожу только с готовым кодом, push по подтверждению. Работа — в изолированном git worktree от финала ветки `sloy-istochnika` (чтобы не мешать продолжающейся разработке), реализация через суб-агентов с независимой приёмкой.

## Как решал (фазы → коммиты)

- **Ф0** `66c69295` — P0-краш создания задач: `pg_advisory_xact_lock` возвращает `void`, Prisma 7 `$queryRaw` его десериализует → `Failed to deserialize column of type 'void'` → транзакция падает, задачи не создаются вообще. Фикс — `$queryRaw`→`$executeRaw` на 2 сайтах. Нашёл и обновил скрытую зависимость: 2 спека трекали именно `$queryRaw`-вызов.
- **Ф1** `eba8f142` — три класса идея/задача/решение: реестр `task-decision-examples` расширен полюсом idea; в block-ingest сужен АНТИ-ДУБЛЬ (предложение+поручение ≠ один decision), добавлен негатив «бытовое не-действие»; правила — в статичный SYSTEM (prompt-cache).
- **Ф2** `60039787` — actionable-решение → задача: `Decision += impliesAction + actionExtractedAt` + миграция; specialist-3-3 заводит задачу через `IntakeService.create(source='decision')` — дедуп, авто-триаж, `DecisionTaskLink('derived')` срабатывают сами в существующем пути; идемпотентность по маркеру + source-block guard.
- **Ф3** `1dd652b2` — закрытие из разговора (P7) + журнал: корень P7 — embed-флап (одна попытка → молчаливый skip); добавлен retry. not-done-ветка пишет полноценный `IssueProgressUpdate` из разговорного блока (порог уверенности, идемпотентность). R13 (без авто-закрытия) цел.
- **Ф4** `49970b0b` — дашборд на исполнении: `classifyImplementationStatus += impliesAction` (не-actionable никогда не stalled), throughput-знаменатель = actionable; `DecisionsWidget` в today-ритме → индикатор-утечка «Решения без действия».
- **Ф5** `1b27ff2a` — надёжность: `StrategicAlignmentWorker` JSON-ремонт (`tryParseJson`+safeParse, skip-не-throw); новый `raw-event-recovery.cron` реэнкьюит застрявшие `RawEvent='received'` + dead-letter алерт древних; 3 метрики.

## Чему научился (грабли и приёмы)

1. **Картография важнее текста ТЗ.** Ветка `sloy` пред-построила половину Ф3 (emitProgress, living-card, cron-журнал) — ТЗ-REALITY-CHECK был устаревшим. Чтение текущего кода переопределило scope: вместо «строить журнал» — «достроить прямой запис из блока + чинить embed». Всегда верифицировать строки/состояние ТЗ по факту.
2. **Диаг-тест ≠ vitest.** `diag-decision-classifier-test.ts` — standalone-скрипт с реальным DeepSeek (`void main()`, нужен ключ). ТЗ-приёмка «bunx vitest run диаг-теста» неисполнима локально → разделил: детерминированный spec на реестр примеров (локально) + расширение диаг-харнеса (компиляция; реальный прогон на проде). Честно отметить, что валидация качества промпта требует живого LLM.
3. **Миграция без локальной БД.** `prisma migrate dev` требует БД; локально её нет. Решение — `prisma migrate diff --from-schema-datamodel <старая> --to-schema-datamodel <новая> --script` (схема→схема, без БД) → ручная папка миграции → `prisma generate`. Применение — на проде через `migrate deploy`.
4. **Регресс прячется в «правильной» правке.** Ф2: кодер засеял `intake.autoAcceptSources` ПОЛНЫМ списком, забыв `chatbox` — а воркер трактует пустой список как «все разрешены». Засев неполного списка заблокировал бы chatbox-задачи. Лучшее решение — убрать сид совсем (пустой дефолт уже разрешает decision). Урок: менять семантику «пустой = всё» на «явный список» — всегда риск выпадения неперечисленного.
5. **Реюз существующего пути дешевле параллельной реализации.** Ф2: `IntakeService.create` уже делает дедуп+создание+enqueue+авто-триаж+линк — один вызов вместо копирования логики specialist-3-15. Искать готовую точку входа до того, как писать «такое же рядом».
6. **ТЗ может ошибаться в деталях кода.** Ф5: ТЗ писало про `RawEvent.createdAt` — фактически поле `receivedAt`. Кодер сверился по схеме и поправил. Префиксы AdminSetting — по фактической конвенции (`knowledge.*`), а не из ТЗ.
7. **«Уже работает» — частый исход в зрелом коде.** R22 (window retry + провайдер-фолбэк + partial-метрика) был уже реализован; реальный пробел — только recovery застрявших RawEvent. Не дублировать готовое, искать узкий незакрытый кусок.
