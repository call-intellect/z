## 0. TL;DR (30 секунд)

- **Категория и цель.** Кора строит **клон сотрудника/должности** автоматически (черты рассуждений → персона → регламенты → процедуры). Владелец хочет: сотрудник уволился — клон отвечает **как эксперт всегда** (позиция → совет → план по «лестнице опоры»), а не «факт есть/нет». Нужно: **измерительный стенд + линейка + петля итераций** до планки (`EXPERT_PASS ≥95%, FABRICATED=0, BOUNDARY=14/14`).
- **Где мы на дорожной карте (≈ 20–25%).** Ядро ПОСТРОЕНИЯ клона доведено до рабочего состояния (Слой 0 — предусловие baseline). **Линейка ответов, судьи, baseline-прогон и разворот поведения (ТЗ-1) — ещё НЕ начаты.**
- **Последнее (эта сессия, 2026-07-05).** Поймана и починена **регрессия построения**, которую занесла память/извлечение: переход эмбеддинга блока на header-less (коммит `d556f11a`) сместил косинусы вниз → порог склейки черт `0.72` стал резать посередине → клоны почти не собирались (черт 23→6, персон 0). Плюс починены два дефекта: verify промоутил без проверки (fail-open) и смена носителя роли крашила (P2002). Итог после фиксов: черт **20 active**, персон **5 active**, verify реально проверяет, смена носителя без краша.
- **Самый важный технический вывод.** Порог склейки черт и содержимое эмбеддинга блока **связаны**: header-full → 0.72, header-less → ~0.60. Это **сопряжённая миграция** — менять порог можно только ВМЕСТЕ с re-embed блоков (детали §3.1, §5).

### 1.3. Планка (приёмка петли)

`EXPERT_PASS ≥95%` на отвечаемых (96 из 110) И `≥90%` на свежем банке ~20; инварианты **`FABRICATED=0`, `BOUNDARY_OK=14/14`, ср. `M≥0.7`**. 5 осей линейки: E экспертность · M верность методу · G заземлённость · L опора на нужный слой · P персона. Вердикт (детерминированно): BOUNDARY → FABRICATED → REFUSED → EXPERT_PASS → WEAK.

### 1.4. Главное противоречие (то, что ТЗ-1 будет разворачивать)

Клон спроектирован ПРОТИВОПОЛОЖНО замыслу — «лучше отказ, чем выдумка». 4 контура отказа: (1) <3 черт → 404; (2) анти-deepfake гейт «<2 блоков по теме» → отказ до LLM; (3) промпт велит отказываться; (4) ответ без цитат → отказ. Экспертный режим по аналогии (`judgmental`) в коде ЕСТЬ, но заперт за флагом `CLONE_V2_ENABLED`. Ретрив — «последние 20 блоков», не поиск по вопросу. **Baseline подтвердит это числом — это точка отсчёта, не повод паниковать.**

## 3. Аналитика этой сессии — что улучшилось / что нет

### 3.1. ✅ Улучшилось (доказано числами на стенде «Стрела» `cmr4ztnfj0001hgbwuij7xc3n`)

| Метрика | Было (порог 0.72, под новым кодом) | Стало (порог 0.60 + фиксы) |
|---|---|---|
| Черт собрано / active | 6 / 6 | **22 / 20** (skill 9, process_marker 6, value 5) |
| verify черт | **fail-open на КАЖДОЙ** (JSON.parse падал) | **checked 22, promoted 20, held 2, fail-open 0** — реально проверяет |
| Персоны active | 0 | **5** (person: 3× по 6/7/3 черт; role: Маркетолог 7, Поддержка 6) |
| Смена носителя роли | **краш P2002** (Unique scope,scopeRefId,version) | **прошла, 0 крашей** |
| Ингест корма | — | 55 ответов → 66 header-less блоков ≈1:1 (дедуп НЕ схлопнул) |

**Корневая причина регрессии (доказана).** Переход дедуп-вектора блока на header-less ([коммит `d556f11a`](../../second-brain/05_история/2026-07-03-extraction-consolidation-fixes.md)) убрал общий контекст-хедер (источник/дата/участники), который раздувал ВСЕ косинусы вверх. Замер ближайших соседей subject-блоков одного носителя: avg сходства ≈0.72 (было бы ~0.80+ с хедером); у Михаила потолок **0.706** — при пороге 0.72 у него **0 кластеров → 0 черт**. На 0.60 у всех носителей достаточно соседей. → Порог склейки калибровался на header-full, а память поехала на header-less.

**Два дефекта построения (починены, коммит `6c593a00`, спеки 46/46):**
- **verify.** `skill-trait-verify` на `deepseek-v4-pro` возвращал прозу-преамбулу («В данном случае…») вместо JSON → `JSON.parse` падал → fail-open промоутил черту БЕЗ проверки. Фикс: (а) промпт — жёсткая директива «весь ответ = один JSON, первый символ `{`, последний `}`», запрет преамбул, шаблон-пример; (б) парсер `extractGroundedVerdict` вытаскивает JSON даже из прозы (страховка). Результат: verify держит 2 негрунтованные черты честно.
- **версионирование.** `handle()` смены носителя имел идемпотентность против ПОСЛЕДОВАТЕЛЬНОГО двойного эмита, но не КОНКУРЕНТНОГО (оба читают max version до записи) → P2002. Фикс: placeholder-create обёрнут в P2002-ретрай с пересчётом версии (паттерн `createRolePersonaWithRetry` билдера).

### 3.2. ⚠️ Что НЕ улучшилось / вскрылось нового (в бэклог)

1. **Сопряжённая миграция «порог ↔ re-embed» (КРИТИЧНО для прода).** Порог 0.60 верен ТОЛЬКО для header-less пространства. На проде re-embed блоков (`backfill-reembed-blocks-no-header`) был owner-gated и, вероятно, ещё НЕ применён → прод-блоки header-full → там порог 0.60 будет ОВЕР-мерджить. **Нельзя менять дефолт порога в сиде, пока прод-блоки не переэмбеддены.** Порог 0.60 стоит только в дев-БД стенда (прямой UPDATE AdminSetting), сид остался 0.72.
2. **Не все клоны переходят планку сборки.** 3 из 5 person-персон, 2 из 4 role-персон. Часть профилей даёт 2–4 черты (ниже/у границы `personaMinTraits=3`). Причина — недопроизводство skill-слоя (см. п.3).
3. **motivation-слой = 0.** Ни одной motivation-черты. Мульти-детектор (skill/value/process_marker на одном кластере) не рождает motivation. Известный «Открыто»-пробел ещё с 2026-07-03.
4. **Ингест медленный** (~3–4 блока/мин, LLM зарейтлимлен): 55 ответов ≈18 мин. Для больших прогонов baseline (110+ вопросов) — заложить время / параллелизм.
5. **Порог 0.60 не «оптимизирован», а «достаточен».** Взят по замеру соседей; не проверен на переусложнение (не сливает ли разные методы в один кластер). До прод-выката — sweep 0.58–0.65 + проверка diversity черт.

## 4. Рефлексия

- **Улучшение памяти РЕАЛЬНО задевает построение клонов через общий слой блоков.** Дедуп-вектор, извлечение (pain/blocker, консолидация), пороги — общие. Любое изменение эмбеддинга блока = потенциальная рекалибровка клон-порогов. Это надо встроить в чек-лист: тронул `embedBlocks`/извлечение → перепроверь клон-стенд.
- **«getDynamic честнее статики» и «порог на новом эмбеддинге» — один класс граблей:** значение, калиброванное на старом пространстве, молча ломается при смене пространства. Порог — это функция от эмбеддинга, а не константа.
- **fail-open в verify маскировал проблему:** система «работала» (черты промоутились), но verify не верифицировал ничего. Тихая деградация. Урок: любой fail-open обязан логировать сырой ответ и метрику — иначе он невидим.
- **Идемпотентность ≠ конкурентная безопасность.** Проверка «уже есть?» перед вставкой не спасает от гонки — нужен либо атомарный аллокатор версии, либо retry на unique-violation.
- **Стенд — правильный инструмент:** он поймал регрессию, которую обычный typecheck/lint/тесты не видят (это про ДАННЫЕ и эмбеддинги, а не про типы). Дисциплина «пере-подготовил стенд под новый код → прогнал → замерил» окупилась.

## 5. Гипотезы (куда двигаться — проверить прогоном, не принимать на веру)

- **Г1 (порог↔эмбеддинг).** Сделать порог склейки функцией от режима эмбеддинга: либо авто-калибровка (перцентиль распределения соседей на тенант), либо явная связка «header-less → 0.60» в одном деплое с re-embed. Убирает целый класс регрессий.
- **Г2 (motivation-слой).** Мульти-детектор забирает контент в skill/value/process раньше, чем доходит до motivation. Проверить: отдельный проход детектора мотивации на тех же кластерах, или переупорядочить/не-эксклюзивно.
- **Г3 (продуктивность skill-слоя).** У части профилей 2–4 черты из 9–15 блоков. Гипотеза: `skillClusterMinObservations=3` + строгий detect режут длинный хвост. Проверить чувствительность к порогу кластера и к detect-промпту.
- **Г4 (Слой 0 baseline готов запускаться).** Построение теперь стабильно (черты+персоны собираются) → предусловие Р7 выполнено, можно писать Фазу 0в (слепая разметка → сверялка) и мерить фиделити ЧЕСТНО.
- **Г5 (verify как ось честности).** Теперь, когда verify реально работает, held-черты — сигнал для оси G/FABRICATED. Использовать в линейке.
