## Чему научился
1. **REALITY-CHECK перед ТЗ — не формальность.** Половина «несостыковок» уже была в коде ветки (просто не выкачена). Написать ТЗ без карты истории = переделывать сделанное. Всегда `git log -- <file>` по ключевым модулям + читать смежные ТЗ со статусом «реализовано».
2. **Прод-замер ≠ синтетический стенд.** Стенд «Стрела» показывал доминирование task-шума; реальный прод (read-only SSH к БД) — инспектор порядка (498), а task ≈ 30. Мерять реальный прод, синтетика врёт по распределению.
3. **«Показывается, а не спрашивается» = снять эмиттер, не строить замену.** Пассивные поверхности (`/experiments`, `/insights`, граф) уже существуют → снятие push-вопроса ничего не теряет (сущность видна), а не требует нового экрана. Это сделало scope выполнимым.
4. **Снос фичи должен уносить её тесты.** Ф7.1 удалила `regulationFamilyProvenance`, но оставила 2 `policy_silent`-теста → они «падали» на стабе. Фикс = удалить устаревшие тесты, НЕ переизобретать снесённую фичу.
5. **Общий рабочий тред с параллельной сессией — реальность.** git index и HEAD разделяются: перед commit всегда `git diff --cached --name-only` + отсеять чужое (`git restore --staged`); `git push` → «up-to-date» означает, что параллельная сессия уже запушила поверх (мой коммит цел как предок). Коммитить строго явными путями, никогда `git add .`.
6. **build EXIT 134 (Abort trap 6) ≠ баг кода.** Это OOM `tsc` на полном emit; `typecheck --noEmit` при этом EXIT 0. Лечится `NODE_OPTIONS=--max-old-space-size=8192`.
