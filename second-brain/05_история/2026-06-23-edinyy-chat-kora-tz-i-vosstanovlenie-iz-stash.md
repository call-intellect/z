## ЧП: untracked-файлы плана пропали, восстановлены из stash
При попытке коммита `git status` не показал моих файлов — их **не было на диске** (`ls` → No such file). Причина: я держал их **untracked** (не коммитил, ждал «начни реализацию»), а параллельная сессия 2026-06-22 сделала `git stash -u` («wip-before-dev-switch») + `reset to origin/dev` — мои неотслеживаемые файлы ушли в **untracked-часть stash** и исчезли из рабочего дерева.
- Нашёл: `git stash show -u "stash@{1}" --name-only` → все 10 файлов там.
- Восстановил ТОЛЬКО свои (не применяя весь stash, чтобы не тронуть чужой WIP): `git checkout "stash@{1}^3" -- <пути>` (untracked-дерево stash хранится в третьем родителе `^3`).
- Версия оказалась актуальной (вариант A) — пересоздавать из контекста не пришлось.

## Чему научился
1. **Untracked plan-файлы уязвимы к `git stash -u`/`clean`/`reset` параллельной сессии** (в репо Z ~12 worktree + hook auto-pull). Урок: длинную работу над планами **коммитить раньше**, не держать часами untracked; усиление [[feedback_parallel_sessions_git_check]].
2. **Рецепт восстановления untracked из stash:** `git checkout 'stash@{N}^3' -- <paths>` (именно `^3` — untracked-tree; `^1`/`^2` это base/index). Точечно, без `stash pop` всего.
3. **Изменение предпосылки разворачивает рекомендацию.** «Поддержка не запущена» превратило вариант B+ (компромисс «не ломать рабочее») в вариант A (единое ядро) — стратегически верный. Всегда проверять РЕАЛЬНЫЙ статус запуска (prod-deploy-log «Накоплено» vs «Архив»), не только наличие кода.
4. **Память устаревает** — «ТЗ не начато» при фактически реализованном Ф1–Ф4. Факт-чек кодом/коммитами/веткой до выводов.
