# Голосовой ввод — флоу

## Принципы

1. **Голос — равноправный канал ввода**, не дополнение к тексту.
2. **Streaming** — пользователь видит транскрипцию по мере её появления.
3. **Низкая латентность до первого слова** — < 1 секунды.
4. **Hands-free режим** для длинных диктовок (с авто-завершением по тишине).
5. **Графа разрешения микрофона** — однократно при первом использовании.

## Push-to-talk

```
1. Пользователь нажимает и удерживает [🎙].
2. Открывается WSS connection: wss://.../api/v1/chat/voice
3. Браузер захватывает audio через MediaRecorder API.
4. Audio chunks (PCM 16kHz mono, 250ms окнами) стримятся через WSS.
5. На сервере — WhisperX обрабатывает chunks по мере поступления.
6. Сервер шлёт в обратную сторону:
   - {type: "transcription_partial", text: "..."}  (по мере появления)
   - {type: "transcription_final", text: "..."}    (после паузы > 1 сек)
7. Пользователь видит транскрипцию в реальном времени.
8. Отпустил кнопку → стрим закрывается.
9. Финальный текст появляется в textarea (можно отредактировать).
10. Кнопка [Отправить] — отправляет в M-02 как обычный dump.
```

## Hands-free

```
1. Пользователь нажимает [🎙] раз (без удержания).
2. Кнопка переключается в красный с надписью «Слушаю…».
3. WSS connection открыт постоянно.
4. Audio стримится непрерывно.
5. Авто-завершение через 3 секунды тишины:
   - Обнаруживается через RMS уровень в браузере < threshold.
   - Сервер также детектит через VAD (voice activity detection в WhisperX).
6. После завершения — переход в шаг 8 push-to-talk.
```

## Технические требования

### Браузер

- `getUserMedia({audio: true})` — запрос разрешения.
- `MediaRecorder` или `AudioWorklet` для захвата.
- WebSocket для стрима.
- Минимальная поддержка: Chrome 90+, Safari 16+, Firefox 110+.
- Mobile: iOS Safari 16+, Android Chrome 90+.

### Безопасность

- Запись начинается только после явного действия пользователя.
- Иконка микрофона активна → красная индикация в браузере.
- Аудио не хранится в localStorage.
- WSS — TLS 1.3 обязательно.

### Сервер

- WhisperX через faster-whisper, модель `large-v3-turbo` для realtime.
- VAD (voice activity detection) для детекции тишины.
- Speakers diarization не нужна для коротких dump'ов (используется только для встреч в M-04).

## Голосовой ответ от AI (опционально)

В будущем — TTS. Не в первом релизе.

Если включить:
- Использовать локальный TTS (Coqui-TTS или OpenVoice) — чтобы не зависеть от внешних API.
- Streaming TTS chunks через WSS.
- Кнопка `[🔊]` рядом с ответом AI — переключение в голос.

## Telegram-бот

Голосовые сообщения Telegram → автоматически транскрибируются через тот же M-04 → дамп.

## Диктовка длинных текстов

Для встреч / длинных интервью / описаний:
- Открыть `/dump` → hands-free режим.
- Можно говорить минутами без перерыва.
- Авто-завершение после 3 сек тишины.
- Если хочется паузы > 3 сек — нажать [Пауза] (тот же значок).

## Мульти-язычность

WhisperX автоматически определяет язык. Поддерживает русский, английский, и десятки других. Метка `multi_language: true` если в одной записи несколько языков.

## Обработка ошибок

| Сценарий | Поведение |
|---|---|
| Нет разрешения на микрофон | Toast «Разрешите доступ к микрофону в настройках браузера» |
| WSS отвалился во время записи | Auto-reconnect, с потерей последних 250 ms аудио |
| Сервер не успевает обрабатывать | Backpressure: replay через 500 ms |
| Слишком тихий звук | Toast «Не слышу. Говорите громче или ближе к микрофону» |
| Запись > 1 час | Авто-разделение на чанки + предупреждение пользователю |

## Запрет

- Никакой автоматической записи без явного действия пользователя.
- Никакого «всегда включён» режима.
- Никакого хранения аудио без consent (для длинных встреч — отдельный flow с явным consent всех участников, см. [08-security-privacy.md](../08-security-privacy.md), M-04).
