# ЕДИНОЕ ТЗ: Убрать лишние подтверждения и «мусор» из уведомлений Коры

## 0. Зачем (исходная боль)

Владельца «засыпает» уведомлениями: на всё нужно подтверждение, очередь «Требует вас» воспринимается как мусор. Цель — **довести автономию до «человек = аварийный стоп»** (Развилка 1, принята): Кора решает сама всё обратимое и выводимое из данных, к человеку идёт только необратимое / деньги-доступ / подлинно неоднозначное.

Это **зонтичное ТЗ** — собирает 4 блока работы. Детальные контракты и точные файлы:строки — в дочерних ТЗ по ссылкам в каждом блоке. Здесь — единая картина, порядок, решения, доказательства, отложенное.

## 1. Принятые решения владельца (2026-06-23)

- **Р1 — глубина автономии:** довести до «человек = аварийный стоп». Принято.
- **Р2 — дефолт intake без исполнителя:** на паузе (анализируется в параллельной сессии). Сюда не входит.
- **Серая зона карточек:** прогонять некритичные карточки средней уверенности через судью (Блок A).
- **Probe — все 4 рычага**, включая черновики (Блок B разблокирован).
- **Конфликты / доставка / задачи (closure/review/draft):** не трогать сейчас (см. §4 Отложено).

## 2. Доказательная база (не на словах)

- **Судья (локальный A/B/C, реальные вызовы `deepseek-v4-flash`, 12 карточек):** A=7/12 → B=9/12 → C=**11/12**, у C — **0 мусора в память**. Скрипт `backend/scripts/judge-ab-test.ts`.
- **Черновики из памяти (реальные данные Org «Ооо луа»):** Кора собрала осмысленный черновик миссии из 40 решений + урок эксперимента даже при бедных данных, честно отметив нехватку. Скрипт `backend/scripts/draft-from-memory-test.ts`.
- **Замер прода:** карточки в очереди — это в основном «серая зона» (~78% light); конфликты автономны (36/40 арбитром); самообучение включено, но 0 сработок (нет наблюдаемости).
- **Баг «Открыть» критической карточки:** проверен живьём — переход и страница исправны, **не воспроизводится** (закрыт).

## 3. Блоки реализации

### Блок A — Карточки: судья с первоисточником + методология + серая зона 🔴 главный выигрыш
**Детали:** [2026-06-23-curation-judge-context-and-methodology.md](2026-06-23-curation-judge-context-and-methodology.md)
- **Проблема:** ИИ-судья критических карточек почти всегда отказывает (provisional сработал 1 раз за 2 недели) — потому что (1) ему не дают первоисточник (`contextBlocks: []`), (2) промпт не по методологии + дешёвая отказная модель. + 78% потока — некритичные «серой зоны» (уверенность 0.6–0.85), которые судья даже не смотрит, и они все идут к человеку.
- **Что делаем:** дать судье цитату-первоисточник; переписать промпт по методологии с требованием цитировать (вариант C); расширить судью на некритичную серую зону.
- **Развилки:** Р-СУДЬЯ (модель flash vs pro — старт на flash), Р-СЕРАЯ (нижняя граница 0.7–0.85).

### Блок B — Probe: черновики из памяти вместо пустых вопросов
**Детали:** [2026-06-12-probe-auto-drafts-phase24.md](2026-06-12-probe-auto-drafts-phase24.md) (разблокирован 2026-06-23)
- **Проблема:** пустые вопросы («уточните миссию», «какой урок», «какой артефакт») висят неделями без ответа.
- **Что делаем:** Кора генерирует черновик из памяти и показывает к подтверждению (HYBRID, не молча). Reason'ы: `experiment.result_without_lesson`, `regulation.process_no_steps`, `companyprofile.missing_mission/vision/strategy`, `process_template.missing_output_artifact`; плюс AUTO для фоновых skill/knowledge.
- **Примечание:** остальные 3 рычага probe (дедуп по теме, «лестница владельца» = `OwnerResolver`, NUDGE→дайджест) — **в основном уже в коде**; доделать семантический дедуп и доподключение — частично Блок C и дочерние probe-ТЗ (`2026-06-17`/`2026-06-20`).

### Блок C — «Кому поручить» по зоне ответственности (умный подбор)
**Детали:** [2026-06-23-skill-routing-connect-meetings-and-owner.md](2026-06-23-skill-routing-connect-meetings-and-owner.md)
- ⚠️ **Перед реализацией обязательно изучить актуальный задачный код** — он пишется в параллельной сессии; сверить с задачными ТЗ и переформулировать (требование владельца).
- **Проблема:** умный подбор (`SkillRoutingService`, по навыкам+ответственности) включён только при ручном создании задачи; при авто-постановке из встреч и в owner-вопросах — подбор по имени.
- **Что делаем:** доподключить `SkillRoutingService` к авто-триажу встреч и к `OwnerResolver` (ступень «смысловой подбор» перед эскалацией к человеку).

### Блок D — Самообучение: наблюдаемость + дочистка дублей
**Детали:** [2026-06-23-subject-memory-observability-and-dedup.md](2026-06-23-subject-memory-observability-and-dedup.md)
- **Проблема:** `SubjectMemory` (Кора учится на ответах) включена, но **ни разу не сработала** (нет ответов на probe) и **её работу негде наблюдать** (нет UI/диага/read-эндпоинта; метрики per-replica; лог-стор не покрывает). Висящие дубли не подчищаются.
- **Что делаем:** read-доступ к правилам + диаг-команда + страница «Что Кора выучила»; дочистка висящих дублей при выводе правила.

## 4. Отложено (осознанно, с причиной)

| Что | Почему отложено |
|---|---|
| **Конфликты** | Арбитр автономен на 90% (36/40), первоисточник у него уже есть. Вернуться, если 4 не разойдутся после ночного крона |
| **Доставка-добивалки** (5×/день + сторож 6ч) | Параллельная сессия пишет код tracker-уведомлений; правки доставки рискуют сломать. Отложено до её завершения |
| **Задачи (closure/review/draft)** | Сейчас 0 в Org; пересекается с задачной подсистемой параллельной сессии |
| **Intake (22 задачи)** | Развилка 2 — анализируется в другой сессии |

## 5. Порядок реализации (по доказанному выигрышу)

1. **Блок A** (судья + серая зона) — главный, доказан, бьёт по ~78% карточек.
2. **Блок D Ф1** (наблюдаемость самообучения) — без неё проверка обучения вслепую.
3. **Блок B** (черновики) — разблокировано, доказано.
4. **Блок C** (умный подбор) — **только после** изучения актуального задачного кода.

## 6. Принципы (общие)

- **Промпты — по методологии** `docs/methodology/prompts/README.md` (роль, якоря смысла, проверяемые критерии, few-shot, self-check, цитата, cache-friendly).
- **Выкат — Ship-On**, наблюдаем прод-метрики, без блокирующего golden ([[feedback_no_golden_ship_and_observe_prod]]). Где есть — A/B на проде.
- **Крутилки — в AdminSetting**, не в код/ENV.
- Каждое решение «кому поручить / что канонизировать» при высокой уверенности — авто (обратимо), при низкой — короткий вопрос с конкретикой.

## 7. Критерий «сделано»

Очередь «Требует вас» в реальной Org падает до единиц; к человеку доходит только подлинно неоднозначное; самообучение наблюдаемо и срабатывает; override-rate авто-решений не растёт.
