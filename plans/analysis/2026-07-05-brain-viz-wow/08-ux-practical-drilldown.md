# UX-паттерны практичной навигации по графу знаний: drill-down, дыры, провенанс

Контур исследования: как реальные продукты делают граф ПОЛЕЗНЫМ, а не только красивым — «ткнул → мгновенно открылось», «видно где пусто», «понятно откуда факт». Собрано по 13 поисковым запросам + 13 первоисточникам (доки, релиз-ноуты, исследования). Дата съёма: 2026-07-05.

## Карточки

### 1. Neo4j Bloom (Explore) — эталон «search-first» графа

**Функционально простым языком.** Инструмент визуального исследования графовой БД Neo4j. Главная идея: вход в граф — не «вот тебе весь граф», а строка поиска («search-first environment»): пользователь печатает, получает подсказки, и на сцену выводится только релевантный кусок графа. Актуальная версия 2.34.0 от 11 июня 2026 [verified: https://github.com/neo4j-devtools/neo4j-bloom/releases, 2026-06-11].

**Вау-приёмы.**
- Поиск понимает «почти естественный язык»: подсказки строятся из меток узлов, типов связей, ключей и проиндексированных значений свойств — пользователь собирает паттерн «Person — WORKS_AT — Company» без языка запросов Cypher [verified: https://neo4j.com/docs/bloom-user-guide/current/bloom-visual-tour/search-bar/].
- 4 типа подсказок в одном автокомплите: граф-паттерны, «search phrases» (сохранённые параметризуемые запросы под человеческой фразой), полнотекстовый поиск (fallback), и Actions — команды UI прямо из поиска: «Clear Scene», «Undo», «Expand selection», «Fit to selection» [verified: там же].
- В 2.34 добавлены GenAI-рекомендации в поиске и полная клавиатурная навигация по графу (доступность) [verified: releases, 2026-06-11].

**Технически.**
- **Card list (список карточек):** каждый видимый узел сцены — компактная карточка с несколькими свойствами; список фильтруется своим поиском; выделение двунаправленное — выбрал карточки → подсветились узлы на сцене и наоборот; внизу списка шорткат-действия Expand/Dismiss [verified: https://neo4j.com/docs/bloom-user-guide/current/bloom-visual-tour/card-list/].
- **Inspector (инспектор узла):** двойной клик по карточке → панель со всеми свойствами (при наведении видно тип данных; с правами на запись — редактирование inline), плюс секция «Relationships & Neighbors»: соседи и связи показаны карточками, по которым можно навигировать дальше, НЕ покидая инспектор [verified: там же].
- **Slicer (слайсер):** интерактивный фильтр-таймлайн по числовым/датным свойствам: ручной скраббинг или playback-анимация; 3 режима воспроизведения (скользящее окно / нарастающий диапазон / сужающийся), настраиваемая скорость, до 5 диапазонов по разным свойствам одновременно [verified: https://neo4j.com/docs/bloom-user-guide/current/bloom-tutorial/slicer/].

**Что берём для Коры.**
- Инспектор «свойства + соседи карточками» — прямой шаблон для панели узла: факт-блоки, участники, связанные темы как карточки, клик → перелетаем.
- Строку поиска как командный центр: поиск сущностей + команды («сбросить сцену», «показать всё про клиента X»). У Коры уже есть чат — поиск по графу и чат могут делить одну строку.
- Slicer — готовая механика «скраббер роста мозга по неделям» (см. паттерн 10).

**Источники:** [verified] https://neo4j.com/docs/bloom-user-guide/current/ (docs 2.34) · https://neo4j.com/docs/bloom-user-guide/current/bloom-visual-tour/search-bar/ · .../card-list/ · .../bloom-tutorial/slicer/ · https://github.com/neo4j-devtools/neo4j-bloom/releases (2.34.0 — 2026-06-11).

### 2. Linkurious Enterprise — панель свойств и фильтры для расследований

**Функционально простым языком.** Платформа граф-расследований (анти-фрод, комплаенс) поверх Neo4j/Neptune. Целевой пользователь — аналитик без кода, задача — «раскрутить» цепочку связей. Текущая версия мануала 4.3.2 [verified: https://doc.linkurious.com/user-manual/latest/page.html].

**Вау-приёмы.**
- Запросы превращаются в кнопки и формы: «turn graph queries into forms and buttons» — сложный Cypher прячется за кнопкой «показать всех связанных с этим клиентом» [claimed: https://linkurious.com/decision-intelligence-platform-graph-visualization/].
- Условия по датам/времени задаются прямо в интерфейсе фильтров — без запросов [verified: https://linkurious.com/blog/linkurious-enterprise-4-3/].

**Технически.**
- **Property panel (панель свойств):** при мультивыборе узлов/рёбер — таблица на каждую категорию узлов / тип рёбер; клик по метке категории вверху панели — прыжок к её таблице; внутри панели свой поиск с подсветкой найденных значений; сортировка по любому свойству; панель ресайзится и по умолчанию свёрнута, чтобы граф оставался главным [verified: https://linkurious.com/blog/linkurious-enterprise-4-2/ + user manual].
- **Filter panel:** фильтры перенесены с верхней панели в выдвижной ящик (drawer) справа — «фильтруй и исследуй бок-о-бок»; применённые фильтры видны в секции «Applied Filters» чипами с крестиком для снятия [verified: https://doc.linkurious.com/user-manual/latest/filter-panel/ + блог 4.2].

**Что берём для Коры.**
- Правый drawer с чипами применённых фильтров — канонический паттерн «фильтры-линзы»: всегда видно, ЧТО сейчас скрыто, снимается одним кликом. Критично против «а почему я не вижу половину графа?»
- Панель свойств «свёрнута по умолчанию, ресайзится» — граф первичен, детали по требованию.
- «Запрос как кнопка» → пресеты линз для Коры: «только решения за месяц», «всё по клиенту X», «что нового с прошлой недели».

**Источники:** [verified] https://doc.linkurious.com/user-manual/latest/filter-panel/ · https://doc.linkurious.com/user-manual/latest/visualization-inspect/ · https://linkurious.com/blog/linkurious-enterprise-4-2/ · https://linkurious.com/blog/linkurious-enterprise-4-3/ · [claimed] https://linkurious.com/decision-intelligence-platform-graph-visualization/.

### 3. InfraNodus — единственный продукт, где «дыра в знаниях» — фича №1

**Функционально простым языком.** Превращает текст в граф: слова/концепты — узлы, совместная встречаемость — рёбра; кластеры тем красятся цветом (community detection — выделение сообществ), влиятельные концепты крупнее (betweenness centrality — центральность-посредничество). Главный продуктовый ход — показывает не только что ЕСТЬ, но и чего НЕ ХВАТАЕТ.

**Вау-приёмы.**
- **Gap Insight panel:** вкладка Analytics → Gap Insight показывает структурные разрывы — пары тем-кластеров, которые релевантны друг другу, но плохо связаны; кнопки «AI: Insight Question» и «AI: Bridge the Gap» генерируют вопрос/идею, соединяющую разрыв [verified: https://support.noduslabs.com/hc/en-us/articles/8113730778012 + https://infranodus.com/docs/content-gap-analysis].
- **Difference view:** сравнение двух графов — «какие комбинации есть в графе А, но нет в графе Б» (у них — запросы аудитории vs контент конкурентов) [verified: https://infranodus.com/docs/content-gap-analysis].

**Технически.**
- Клик по узлу-концепту → в панели показываются конкретные утверждения (statements) из исходного текста, где концепт встречается, с переходом к исходной заметке (для Obsidian-интеграции — прямо на страницу) [verified: https://infranodus.com/use-case/visualize-knowledge-graphs-pkm]. Это и есть провенанс-паттерн «откуда факт».
- Метрики на панели аналитики: центральность, кластеры, diversity score (разнообразие дискурса) [verified: там же].
- Лимиты тарифов: Basic — 50 графов, загрузки до 1 МБ; Premium — 1000 графов, PDF до 50 МБ; триал 14 дней [verified: там же]. Т.е. рабочие графы InfraNodus — сотни/тысячи узлов, не миллионы.

**Что берём для Коры.**
- Панель «Разрывы» как первоклассный инсайт: «Тема "Продажи" и тема "Продукт" почти не связаны — за месяц ни одной встречи, где они обсуждались вместе. Спросить команду?» — это ровно «память компании находит слепые зоны».
- Клик по узлу → цитаты-источники из встреч + ссылка на встречу = наш провенанс.
- AI-кнопка «предложи вопрос, закрывающий дыру» — мостик из визуализации в действие (задать вопрос в чат Коры).

**Источники:** [verified] https://support.noduslabs.com/hc/en-us/articles/8113730778012-Text-Analysis-Workflow-Get-an-Topical-Overview-and-Find-Content-Gaps · https://infranodus.com/docs/content-gap-analysis · https://infranodus.com/use-case/visualize-knowledge-graphs-pkm · [triangulated(2)] https://noduslabs.com/infranodus/.

### 4. Obsidian Graph View + плагины — и главный анти-кейс, и лучшие заплатки

**Функционально простым языком.** Штатный граф заметок Obsidian: узлы — заметки, рёбра — ссылки. Самый массовый граф-UI в PKM (personal knowledge management — личная база знаний) и самый критикуемый.

**Критика (важнее фич).** Статья «Obsidian's Graph View Is Beautiful and Almost Completely Useless» (25 мая 2026): до ~50 заметок граф полезен и «вскрывает структурные дыры»; после ~200 — «hairball» (комок шерсти), консенсус r/ObsidianMD; после 500+ — деградация производительности и полный навигационный коллапс. Причины: узлы и рёбра НЕтипизированы («каждый узел — просто заметка, каждое ребро — просто ссылка»), граф не показывает статус/приоритет/свежесть. Плюс культурный диагноз: «second brain, zero output», 60% PKM-практиков называют настройку системы главным пожирателем времени [verified: https://codeculture.store/blogs/developer-culture/obsidian-graph-view-useful, 2026-05-25; цифра 60% — [claimed] автором статьи].

**Штатные фичи, которые работают.**
- Фильтры: поиск по файлам, тумблеры «tags», «attachments», «existing files only» (скрыть несуществующие цели ссылок) и «orphans» (сироты — заметки без связей) [verified: https://obsidian.md/help/Plugins/Graph+view].
- Groups: поисковый запрос → цвет узлов (раскраска по папке/тегу/пути) [verified: там же].
- Local graph: граф только вокруг активной заметки с настраиваемой глубиной (depth) — ответ сообщества на hairball [verified: там же + forum].
- Display: порог проявления подписей при зуме (text fade threshold), толщина рёбер, размер узлов ∝ числу ссылок; анимация «time-lapse» появления заметок по хронологии [verified: там же].

**Плагины-заплатки (что докупает сообщество).**
- **Breadcrumbs:** типизированные связи (up/down/next/prev/свои) → строится направленная иерархия; след «хлебных крошек» вверху заметки показывает предков до корня; виды Tree и Matrix группируют входящие/исходящие связи по типу [verified: https://www.obsidianstats.com/plugins/breadcrumbs].
- **Juggl:** интерактивный граф на Cytoscape.js — режим Workspace (собираешь рабочий подграф руками: что раскрыть, что скрыть, пины), стилизация узлов/рёбер через CSS/YAML, типизированные связи [verified: https://juggl.io/ + https://www.obsidianstats.com/plugins/juggl].
- **Folders2Graph / ghost-узлы:** контурные «призрачные» узлы для несуществующих файлов, на которые уже есть ссылки; клик по призраку СОЗДАЁТ содержимое и переходит в него [verified: https://www.obsidianstats.com/plugins/folders2graph].
- **Excalibrain:** иерархическая навигация в стиле TheBrain поверх префиксов типов ссылок; требует ручной дисциплины [triangulated(2): Code Culture + форум Obsidian].

**Что берём для Коры.**
- Анти-урок №1: нетипизированный полный граф умирает на ~200 узлах. У Коры типизация есть из коробки (области→темы→сущности→блоки) — это наш ров против «красиво и бесполезно», но показывать по умолчанию надо СРЕЗ, не всё.
- Local graph с глубиной — дефолтный режим после клика по сущности.
- Ghost-узлы «клик создаёт» — паттерн для пустых областей: «Область "Финансы" пуста — подключи встречи/чат».
- Orphans-тумблер — линза «несвязанные факты» для гигиены графа.

**Источники:** [verified] https://obsidian.md/help/Plugins/Graph+view · https://codeculture.store/blogs/developer-culture/obsidian-graph-view-useful (2026-05-25) · https://www.obsidianstats.com/plugins/breadcrumbs · https://juggl.io/ · https://www.obsidianstats.com/plugins/folders2graph · [triangulated(2)] https://forum.obsidian.md/t/.../32864.

### 5. TheBrain — 25 лет UX «активный узел в центре»

**Функционально простым языком.** Старейший коммерческий «второй мозг» (с 1998). Никогда не показывает весь граф: всегда один активный «thought» (мысль) в центре «plex» (сцены), вокруг — зоны: родители сверху, дети снизу (child zone), сиблинги справа [verified: https://forums.thebrain.com/post/visualizing-thought-types-tags-in-the-plex-9603606 + user guide].

**Вау-приёмы.**
- Клик по любому соседу — плавная перестройка сцены вокруг нового центра: постоянное «ткнул → мгновенно перелетел», granularity навигации = 1 клик.
- TheBrain 15 «Cerebro AI»: подсказывает недостающие связи в графе [claimed: https://thebrain.com/products/thebrain/thebrain15].

**Технически.**
- **Past thought list** — лента истории посещённых узлов для «отмотать шаги назад» (аналог браузерной истории) [verified: https://thebrain.com/blog/navigating-beyond-the-plex, 2022-05-04].
- **Pins** — закреплённые «горячие» узлы всегда под рукой [verified: там же].
- Футер заметки: mapped links (по типам parent/jump/child/sibling), backlinks и unlinked mentions (автоматически подчёркнутые упоминания существующих узлов в тексте) с контекстными абзацами [verified: там же].

**Что берём для Коры.**
- Модель «активный узел + зоны родители/дети/сиблинги» — идеальный режим drill-down для иерархии область→тема→сущность→факт: всегда видно «где я, что выше, что ниже».
- История посещений + пины — паттерн 4 (хлебные крошки) в готовом виде: лента «где я был» + закреп «мои темы».

**Источники:** [verified] https://thebrain.com/blog/navigating-beyond-the-plex (2022-05-04) · https://assets.thebrain.com/documents/TheBrain14/TheBrain14-User-Guide-v01.pdf · [claimed] https://thebrain.com/products/thebrain/thebrain15.

### 6. Kumu — фокус-режим и «карта по запросу»

**Функционально простым языком.** Веб-инструмент карт систем и сообществ (SNA — social network analysis). Силён в сторителлинге: подача сложной карты по кусочкам.

**Технически / вау.**
- **Focus mode:** клик-с-удержанием по элементу (или иконка фокуса) → всё остальное скрывается; клавиши +/- расширяют/сужают радиус фокуса по степеням соседства; цифровая клавиша = точное число степеней; направление фокуса настраивается: in/out/all (только входящие / исходящие / все связи) [verified: https://docs.kumu.io/guides/focus].
- **Profile side panel:** выбор элемента/связи → боковая панель с профилем (описание, поля, картинки) [verified: https://docs.kumu.io/overview/user-interfaces/map-editor].
- **Prompted mode:** карта открывается НЕ целиком, а строкой поиска — пользователь вводит запрос, и карта строится от найденного [verified: https://docs.kumu.io/guides/focus-control → controls]. Радикальный ответ на hairball: нулевое состояние = поиск, не граф.
- **Controls:** на карту кладутся интерактивные кнопки/фильтры/кластеризация — «запрос как кнопка» для зрителя [verified: https://docs.kumu.io/guides/controls/focus-control].

**Что берём для Коры.**
- Фокус с регулируемым радиусом (клавиши/слайдер «1-2-3 шага от узла») — простейшая реализация «показать окрестность сущности».
- Prompted mode — вариант пустого состояния для гигантских графов: сначала спроси, потом рисуй.

**Источники:** [verified] https://docs.kumu.io/guides/focus · https://docs.kumu.io/guides/controls/focus-control · https://docs.kumu.io/overview/user-interfaces/map-editor.

### 7. Nomic Atlas — семантический зум как в картах Google

**Функционально простым языком.** Браузерный обозреватель миллионов текстов на 2D-карте эмбеддингов. Не граф связей, а «карта смыслов», но паттерн зума — лучший в классе.

**Технически / вау.**
- Иерархическая тематическая модель: 2–3 уровня тем в зависимости от размера датасета; при отдалении видны крупные темы, при приближении подписи крупных исчезают и проявляются подтемы — прямая аналогия «страна → город → улица» в веб-картах [verified: https://docs.nomic.ai/atlas/capabilities/topics].
- У каждой точки в левой панели виден её путь по иерархии тем от широкой к узкой [verified: там же].
- Подписи тем генерируются автоматически, админ может переименовать — правка мгновенно видна всем [verified: https://docs.nomic.ai/platform/release-notes].

**Что берём для Коры.**
- Готовая формула semantic zoom для «мозга компании»: зум-аут = 12 областей с подписями; зум-ин = подписи областей гаснут, проявляются темы; ещё зум — сущности и блоки. Подписи-уровни привязаны к масштабу камеры, а не к чекбоксам.
- Автоподписи кластеров с возможностью переименования владельцем.

**Источники:** [verified] https://docs.nomic.ai/atlas/capabilities/topics · https://docs.nomic.ai/platform/release-notes · [triangulated(2)] https://communalytic.org/docs/how-to-explore-embeddings-in-nomic-atlas/.

### 8. Cambridge Intelligence (KeyLines / ReGraph / KronoGraph) — вендорская библия UX графов

**Функционально простым языком.** Коммерческие SDK граф-визуализации для расследований (полиция, банки). Их блог — самый цитируемый корпус практических правил UX графов.

**Ключевые правила из их материалов.**
- «Overview first, zoom and filter, then details on demand» (мантра Шнейдермана) как каркас; progressive disclosure (постепенное раскрытие) через зум/фильтры/кластеризацию [verified: https://cambridge-intelligence.com/graph-visualization-ux-how-to-avoid-wrecking-your-graph-visualization/, 2025-06-24].
- Подписи: не рисовать нечитаемо мелкие — прятать до зума (text fade); тултипы для длинных [verified: там же].
- Про hairball: «комки в данных — это хорошо. Просто не подпускайте их к UI»; проектировать от задачи пользователя, а не от модели данных; центральность (betweenness) для размера узлов [verified: https://cambridge-intelligence.com/how-to-fix-hairballs/, 2019-11-25].
- **Time bar (KronoGraph):** гистограмма активности под графом; выделение диапазона фильтрует сцену; трендлайны по узлам; «смотреть, как связи возникают, живут и рвутся»; масштабируется «от горстки до сотен тысяч событий» через агрегацию [verified: https://cambridge-intelligence.com/time/ · [claimed] цифры масштаба — вендор о себе].
- Дихотомия временных визуализаций: анимация интуитивна, но ломает mental map (мысленную карту расположения узлов); таймлайн-подход стабильнее для сравнения периодов [triangulated(2): https://cambridge-intelligence.com/methods-visualizing-dynamic-networks/ + arXiv Segue 1811.04895].

**Что берём для Коры.**
- Time bar-гистограмма под графом = скраббер «мозг растёт» + честный фильтр периода в одном компоненте.
- Правило подписей: до зума — только области, подписи узлов проявляются с масштабом.

**Источники:** [verified] https://cambridge-intelligence.com/graph-visualization-ux-how-to-avoid-wrecking-your-graph-visualization/ (2025-06-24) · https://cambridge-intelligence.com/how-to-fix-hairballs/ (2019-11-25) · https://cambridge-intelligence.com/time/ · [triangulated(2)] https://cambridge-intelligence.com/methods-visualizing-dynamic-networks/.

### 9. Map of GitHub (anvaka) — поиск → полёт камеры на open-source стеке

**Функционально простым языком.** Интерактивная «галактика» из 700 000+ репозиториев GitHub: близко лежат репо, которые звездят одни и те же люди. Бесплатная, в браузере, код открыт [verified: https://github.com/anvaka/map-of-github].

**Вау / технически.**
- Поиск по имени («react» или «facebook/react») → карта сама зумится к месту репозитория и подсвечивает его — образцовый паттерн «автокомплит → полёт камеры» [verified: https://anvaka.org/map-of-github/].
- Клик по точке → мини-карточка: имя + ссылка + действия [verified: там же].
- Кластеры-«районы» подписаны как страны/города на карте, деталь появляется по мере зума.
- В нашем стеке то же делается штатно: react-force-graph имеет `zoomToFit(durationMs, padding)` и `centerAt(x, y, durationMs)` с анимированным переходом; типовой приём — вызвать `zoomToFit()` в `onEngineStop` после стабилизации физики; в 3D — `cameraPosition({x,y,z}, lookAt, ms)` [verified: https://github.com/vasturiano/react-force-graph + issue #368].

**Что берём для Коры.**
- Поиск с автокомплитом по людям/клиентам/темам → анимированный `centerAt`+зум к узлу + пульс-подсветка. Реализуемо на уже установленном react-force-graph-2d без новых зависимостей.

**Источники:** [verified] https://anvaka.org/map-of-github/ · https://github.com/anvaka/map-of-github · https://github.com/vasturiano/react-force-graph (README API).

### 10. Wikipedia: Page Previews + Red Links — два паттерна с измеренным эффектом

**Hover-превью (Page Previews).** Наведение на ссылку → карточка: первые строки статьи + картинка. Цель — «снизить стоимость исследования ссылки». Раскатано на все вики в 2018 после A/B-тестов [verified: https://www.mediawiki.org/wiki/Page_Previews + https://wikimediafoundation.org/news/2018/05/09/page-previews-documentation/]. Исследование юзабилити: доля отключивших фичу — в среднем 0,02% на трёх тестовых вики; превью повышают точность выбора следующей страницы и позволяют «проверить определение, не уходя со страницы» [verified: https://www.mediawiki.org/wiki/Wikimedia_Research/Design_Research/Reading_Team_UX_Research/Hovercards_Usability]. Это сильнейшее эмпирическое обоснование hover-карточек в навигации по знаниям.

**Red links (красные ссылки).** Ссылка на несуществующую статью рисуется красным — видимая «дыра». Политика вики прямо ссылается на исследование: «большинство новых статей создаются вскоре после того, как в системе появляется ссылка на них» — видимая пустота провоцирует заполнение [verified: https://en.wikipedia.org/wiki/Wikipedia:Red_link].

**Что берём для Коры.**
- Hover-карточка узла (имя, тип, 1-2 факта, счётчик «12 блоков · 3 встречи», мини-превью) — с задержкой ~300-500 мс, лениво подгружаемая. Ожидаемый эффект — меньше «кликнул-вернулся».
- Red-link-логика: сущность, которая упоминалась, но не имеет ни одного факт-блока, рисуется «пустым» стилем (контур/пунктир) с CTA «наполнить» — доказанный механизм провокации заполнения.

**Источники:** [verified] https://www.mediawiki.org/wiki/Page_Previews · https://www.mediawiki.org/wiki/Wikimedia_Research/Design_Research/Reading_Team_UX_Research/Hovercards_Usability · https://en.wikipedia.org/wiki/Wikipedia:Red_link · [triangulated(2)] https://www.engadget.com/2018-04-18-wikipedia-page-previews.html.

### 11. NN/g + академическая база — чем снимается «pretty but useless»

**NN/g про пустые состояния** (Kate Kaplan, 2021-09-19): 3 правила — (1) сообщай статус системы («записей за выбранный период нет» вместо пустоты), (2) используй пустоту для обучения («pull revelations» — подсказки в момент взаимодействия, пример DataDog: «Отметьте избранное звёздочкой — оно появится здесь»), (3) давай прямой путь к действию (кнопка «Создать» + «Узнать больше») [verified: https://www.nngroup.com/articles/empty-state-interface-design/]. NN/g также фиксирует: контекстные подсказки в момент задачи работают лучше принудительных туров при первом входе [verified: https://www.nngroup.com/videos/empty-states-in-application-design-guidelines/].

**Таксономия задач графов** (Lee, Plaisant et al., BELIV 2006) — каркас task-first дизайна: задачи делятся на топологические (соседи узла, достижимость, общие связи), атрибутные (найти по свойству), browsing (следование по пути, возврат) и overview (оценка размера/паттернов) [verified: https://dl.acm.org/doi/10.1145/1168149.1168168 + https://datavis2020.github.io/pdfs/lee-beliv06.pdf]. Практический вывод: каждый экран графа должен отвечать на конкретный класс задач, а не «показывать всё».

**Semantic zoom для онтологий** (Wiens et al., 2017): разделение информации на 3 слоя с дискретными уровнями детализации; semantic zoom стабильнее агрегации по layout и лучше контролирует визуальную сложность на больших графах [verified: https://www.researchgate.net/publication/321894105 + emergentmind обзор].

**Expero (UX графов, консалтинг):** после фильтрации до обозримого подграфа контекст добирается обычными таблицами/чартами, и «основные взаимодействия часто уводятся ЗА пределы диаграммы графа» [verified: https://www.experoinc.com/insights/blog/minding-the-sharp-edges-ux-considerations-with-graph-data-part-1-...]. Т.е. граф — один из видов, а не единственный.

**Главная критика граф-визуализаций (сводка):** (а) hairball — плотность связей превращает картину в кляксу [triangulated(3): Cambridge Intelligence, IEEE 8992920, Code Culture]; (б) отсутствие типизации и статусов делает граф нечитаемым для работы [verified: Code Culture 2026-05-25]; (в) «60% времени на систему, 0 на результат» — граф как прокрастинация [claimed: Code Culture]. Снимается: task-first (таксономия Lee), поиск-как-вход (Bloom, Kumu prompted), локальные окрестности вместо полного графа (Obsidian local graph), semantic zoom (Atlas), вынос деталей в панели/таблицы (Expero, Linkurious).

### Топ-выводы

1. **Вход в большой граф — поиск, не граф.** Bloom («search-first»), Kumu (prompted mode) и Map of GitHub сходятся: при тысячах узлов стартовая точка — строка поиска/промпт, полный граф — только как вау-обзор с суперузлами [triangulated(3)].
2. **«Полный сырой граф» умирает на ~200 узлах** (консенсус r/ObsidianMD) — Коре с тысячами узлов на организацию нужен semantic zoom с 2-3 уровнями агрегации (области→темы→сущности) по образцу Nomic Atlas, иначе получим hairball [verified + triangulated].
3. **Панель деталей — карточная и навигируемая:** соседи внутри панели тоже карточки-ссылки (Bloom Inspector) — это создаёт цикл «ткнул → открылось → ткнул дальше» без возврата к сцене [verified].
4. **Дыры — продуктовая фича, не стыдный баг.** InfraNodus продаёт разрывы как главный инсайт; red links Wikipedia доказали, что видимая пустота провоцирует заполнение. Для Коры «где пусто» = двигатель подключения источников [verified].
5. **Провенанс = цитата + источник в 1 клик.** InfraNodus (клик по концепту → утверждения из текста → переход к заметке) — готовая модель «почему это здесь: из какой встречи, кто сказал» [verified].
6. **Hover-карточки эмпирически оправданы:** 0,02% отключений и рост точности навигации в исследовании Wikimedia — самый дешёвый способ снизить стоимость исследования графа [verified].
7. **Таймлайн: скраббер-гистограмма надёжнее чистой анимации** (анимация ломает mental map); Bloom Slicer даёт готовую спецификацию: ручной скраббинг + 3 режима playback + настраиваемая скорость [verified + triangulated].
8. **Task-first снимает «pretty but useless»:** проектировать от 4 классов задач (топология/атрибуты/браузинг/обзор — Lee/Plaisant 2006) и уводить часть взаимодействий в панели и списки (Expero, Linkurious «query as button») [verified].
