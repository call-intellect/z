## Что вышло
- **Полный вертикальный срез датированного прогресса** (модель→API→воркер авто-черновика из графа→лента+колокольчик→catch-up) + паритет (кастом-поля/автоматизации/повторения/worklog) + редизайн карточки + Гант ON.
- Верификация: backend+frontend typecheck/lint/build зелёные на каждой фазе; **финальный интеграционный build обеих сторон зелёный**; спеки Ф7 6/6, R17a 33/33, Ф9 10/10, Ф10 4/4 (с тестом анти-рекурсии), Ф11 7/7, Ф12 7/7; 5 миграций применены на dev-БД.
- Инвариант Р2 «нет авто-публикации без человека» соблюдён: воркер создаёт только `draftState=pending`; колокольчик даёт только Подтвердить/Открыть/Отклонить; видимость черновика — исполнителю задачи, не всем owner/admin.
- Бонус: страница `/admin/tracker` (DomainSettings) со всеми крутилками трекера — закрыт отложенный Д2-UI.

## Чему научился / грабли
- **ТЗ-предположения сверять по схеме:** `Goal` имеет поле `name`, а не `title` (ТЗ R7 ошибся). Ровно та грабля, что ТЗ сам предупреждал «оркестратор выбирает по факту».
- **`prisma migrate dev` НЕ всегда регенерит клиент** — после миграции обязателен явный `bun run prisma:generate`, иначе typecheck падает «нет модели в @prisma/client». Зафиксировал в спеках субагентов.
- **tsc на Prisma 7 клиенте упирается в heap** — `NODE_OPTIONS=--max-old-space-size=8192` лечит OOM (exit 134) typecheck/build.
- **Делегирование с верификацией масштабируется:** 7 субагентов на тяжёлых фазах, каждая перепроверена грепом+спеком — поймал, что `TrackerSettingsClient` сначала нёс только automations (дописал крутилки Ф7/Ф8b), и что `tracker.event_occurred` реально эмитится (движок автоматизаций сработает).
- **Волну 3 нельзя параллелить** — все фазы правят `schema.prisma`+миграции, конфликт; строго последовательно.
