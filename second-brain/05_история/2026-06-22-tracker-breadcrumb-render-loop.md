# 2026-06-22 — Бесконечный рендер-цикл detail-страниц (breadcrumb), вкладки «не кликаются»

## Постановка

Пользователи жаловались: через 7–20 минут в кабинете (прод korateam.ru) вкладки
навигации становятся некликабельными, refresh не помогает — помогает только
закрыть вкладку и открыть заново. Прислали скриншот системного диалога Chrome
«Устраните проблемы в работе вкладок, замедляющие браузер» с вкладкой «Задача — Кора».
Задача: вживую через Playwright найти и устранить причину, проверить консоль,
исправить найденные баги.

## Что сделал

Диагностика на живом проде (Playwright + инъекция инструментов через
`browser_evaluate`):

- Исключил ложные гипотезы: оверлей / `pointer-events:none` на body / Radix
  dismissable-слои / `inert` / зависший главный поток / необработанные JS-ошибки —
  всё чисто. Клик доходит до `document` (capture), но React-onClick не срабатывает;
  `preventDefault` зовёт сам `<Link>` Next — навигация не коммитится.
- `MutationObserver` показал **~25 000 мутаций DOM/сек в простое** на `/issues/[id]` —
  бесконечный рендер-цикл всей страницы. На `/meetings` (без breadcrumb) — **0/сек**.
- Стек через перехват `setAttribute` → рекурсия commit-фазы React-DOM. «Maximum update
  depth» НЕ кидался → апдейты идут извне рендера (через смену значения контекста).
- Сузил до общего хука: все tracker-компоненты страницы тянут `useTrackerLiveRefresh`,
  но изоляция (`/projects` доска c WS-хуками, но без breadcrumb — НЕ зациклена)
  указала на `useRegisterBreadcrumb`.

Корневая причина — в [BreadcrumbContext.tsx](../../frontend/src/ui/components/breadcrumbs/BreadcrumbContext.tsx):
`useRegisterBreadcrumb` в `useEffect` зависел от всего объекта контекста `ctx`,
который меняет идентичность при каждом изменении карты breadcrumbs. Эффект сам
вызывал `register` → `ctx` новый → эффект перезапускался → cleanup `unregister` →
`ctx` новый → `register` → … Перерисовывалось всё поддерево `BreadcrumbProvider`
(вся detail-страница). Цикл занимал планировщик React рендером дефолтного
приоритета → навигация по `<Link>` (`startTransition`, низкий приоритет) голодала
и не коммитилась (вкладки «не кликаются»), CPU горел (предупреждение Chrome),
память росла (заморозка; refresh на detail-странице запускал цикл заново).

Фикс: эффект завязан на стабильные `register`/`unregister` (они `useCallback([])`),
а не на меняющийся `ctx`. Один общий хук → починены все 17 detail-страниц с
breadcrumb (issues, persons, goals, documents, sprints, projects/[slug], cycles,
themes, ideas, decisions, teams, tables, roles, clones).

Коммит `84b72e90` (ветка `frontFix`): фикс + regression-тест
[BreadcrumbContext.spec.tsx](../../frontend/src/ui/components/breadcrumbs/BreadcrumbContext.spec.tsx).

## Что вышло

- `typecheck` — чисто (единственная ошибка не связана: устаревший `.next/dev/types`
  про несуществующую `feed`-страницу).
- `lint` — чисто.
- Unit-тест red-green на реальном React: на баговой версии **зависает** (runaway-цикл),
  на фиксе — проходит за 19 мс, breadcrumb регистрируется корректно.
- `bun run build` — успешно (после локального `bun install`: не хватало
  `@csstools/postcss-oklab-function`, дыра локального node_modules, не код).
- Запушено в `frontFix`.

## Чему научился

1. **Значение React-контекста нельзя класть в deps эффекта, если этот эффект сам
   меняет контекст.** Провайдер пересоздаёт `value` (useMemo по `[state, ...]`) при
   каждом изменении state → новая идентичность → эффект-потребитель с `[ctx]` в deps
   перезапускается → если в нём register/unregister, получается self-feedback-петля.
   Зависеть нужно от стабильных функций (`useCallback([])`), не от объекта-значения.
2. **Бесконечный цикл может НЕ кидать «Maximum update depth exceeded».** Когда апдейты
   идут через смену значения контекста/внешнего стора между коммитами, React крутит
   на скорости планировщика без синхронного гард-исключения. Диагностика — не консоль,
   а `MutationObserver` (мутаций/сек) в простое.
3. **Concurrent React: дефолт-приоритетный цикл голодит транзишены.** Симптом «кнопки/
   дропдауны (pointerdown, дискретный приоритет) работают, а навигация по `<Link>`
   (startTransition) — нет» = не «клики мертвы», а транзишн-навигация не доходит до
   коммита. Полезный различитель при отладке «вкладки не кликаются».
4. **Изоляция сравнением страниц** (зациклена `/issues` vs здорова `/meetings`/`/projects`)
   быстрее, чем чтение минифицированного прод-стека: разница в одном хуке = причина.
5. Локальный `node_modules` может быть неполным — `@csstools/postcss-oklab-function`
   обязателен прод-сборке (см. [[../02_architecture/code-pitfalls|code-pitfalls]] про oklch),
   `bun install` чинит.
