# Доводка хвостов трёх ТЗ — оркестрация Ф1/Ф2/Ф4, обоснованный стоп на Ф3

## Что было поставлено
ТЗ `plans/tz/2026-06-21-three-tz-tails-finalization.md` (4 независимые фазы): Ф1 фронт-якорь `?m=` к сообщению чата; Ф2 UI-страницы AdminSetting для ~100 перенесённых крутилок; Ф3 TZ1 Шаги 9-10 (остаток ~240 ENV-крутилок + хардкоды → getDynamic); Ф4 page-aware документ-якорь (с развилкой — смена парсера). Владелец: «дописать там, где есть развилки — сам найди лучшее, докажи, примени». Веду как `tz-orchestrator` (код руками не пишу — суб-агенты + независимая приёмка), ветка `feature/three-tz-tails-finalization`, в конце commit+push в `dev`.

## Как решал (с файлами и коммитами)
- **Ф1** (`237b48b5`): картографию сделал сам (мелко). Кодер: `externalId` сообщения проброшен `ChatMessageDto`→API→domain (бэкенд-модель уже имела поле), баббл `id=msg-<externalId>`, `?m=` → scroll+подсветка (`ring-accent`, 2.2с) с авто-догрузкой старых страниц до 240, graceful. Приёмка: typecheck/lint/build зелёные, провенанс-безопасность ок (новых данных наружу нет).
- **Ф2** (`40ef424d` scaffold + `19c091f5` страницы): 2 параллельных Explore-агента (фронт-паттерн + выгрузка ключей реестра). Ключевое открытие — **реестр camelCase (`limits.maxApiKeysPerUser`), существующие страницы snake (`limits.max_meeting_participants`) — РАЗНЫЕ непересекающиеся пространства**; старые страницы не трогал. Сначала серийно общий `DomainSettings`-scaffold (с reason-gate, которого НЕ было в эталоне embeddings) → 5 параллельных кодеров на дизъюнктных route-папках → nav-кодер. Итог: **7 разделов / 126 крутилок**, reason-gate проставлен 9 high-ключам по сидовой severity, **0 ключей-сирот** (машинная сверка с реестром через `comm`). Развёл коллизию подписей quotas/limits.
- **Ф4** (`af7d4cb6` парсер+миграция + `8010c92d` якорь): **развилку решил сам** — матрица + Context7 подтвердили `unpdf` (постраничный `text:string[]` по умолчанию, активная поддержка, serverless pdf.js, без native-зависимостей). Картография вскрыла: документ рендерится **плоским текстом в `<pre>`, PDF-вьюера нет** → «страница» это текстовый якорь, не визуальный скролл. Дизайн подстроил: аддитивная миграция `Document.pageCount/pageOffsets`, парсер только PDF-ветка, провенанс `?page=N` (страница цитаты из `pageOffsets`, tenant-scoped batch без N+1, без правок hot-path block-ingest), фронт — разделители «Страница N» + scroll. 35/35 + 5/5 тестов.
- **Ф3 — обоснованный стоп**: при попытке начать W1 вскрылись два рассинхрона (`plans/analysis/2026-06-21-tz1-step9-10-config-knobs-blocker.md`): сид-дефолт ≠ env.schema-дефолт (distill 0.85 vs 0.92 → тихая регрессия hot-path при наивной конверсии) и существующая knowledge-core страница правит мёртвые dotted-ключи. Массовый sweep без пер-ключевой сверки ломает Ship-On. Не стал рушить прод ради «зелёного отчёта» — задокументировал блокер.
- В конце: по доп-просьбе владельца разобрал все незакоммиченные «остатки» (forgotten work) — безопасные закоммитил, мусор/артефакты исключил.

## Что вышло (верификация)
Ф1/Ф2/Ф4 — typecheck/lint/build зелёные (фронт build все 7 admin-роутов + `/documents/[id]`; backend build), vitest по затронутому зелёный, машинные сверки (ключи-сироты, tenant-scoping провенанса, аддитивность миграции). Ф3 не реализована (блокер задокументирован).

## Чему научился
- **Картография ДО дизайна меняет фичу**: «прыжок к странице» предполагал PDF-вьюер, а его нет — документ плоский текст. Без картографии кодер бы пилил несуществующий вьюер.
- **camelCase-реестр vs snake-страницы**: один и тот же домен может иметь ДВА пространства ключей; кросс-сверка `comm` ключей страниц с реестром — обязательный гейт (нашёл бы сирот).
- **Сид ≠ env.schema default — системная ловушка Ф3**: «крутилку в AdminSetting» нельзя переносить механически — admin-значение может молча перебить live-дефолт. Перед конверсией getter'а всегда сверять три источника (env.schema · seed · code-fallback).
- **reason-gate по сидовой severity, не по догадке**: грепнул все high/destructive в сидах → проставил `requiresReason` ровно 9 ключам (worker-knobs кодер пропустил 4 — поймал фактчеком).
- **Честный стоп ценнее ложного «готово»**: Ф3 за один проход = регрессии; задокументированный блокер с доказательством (0.85 vs 0.92) — правильный результат.
