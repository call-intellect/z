# Рефлексия — циклы C3–C5: память клона 60→69%, аггрегат 67→75% (base-recall-floor + цитаты-как-материал)

## Что было поставлено
Владелец: автономно поднимать процент, циклами; после проводки регламентов (C1, 55→67%) бить в память
(она слабее, планка выше). Подсмотреть у recall-чата-v2 (вчера подняли CORRECT 74.8→80 приёмом
«base-recall-floor») и перенести на клона.

## Как решал (циклы)
- **C2 — разбивка стенда** на ПАМЯТЬ (recall) / АНАЛОГИЮ (transfer): развилка числом — память слабее.
- **C3 — root-cause отказов памяти:** клон НАХОДИТ релевантные блоки (косинус 0.46–0.56, гейт проходит),
  но в factual-режиме `isUngrounded` требует дословных `[BLOCK:id]`; LLM пересказал без маркеров →
  `citations=[]` → ложный отказ. Рычаг: **topic-match = заземление** (крутилка `clone.grounding.accept_topic_match`).
- **C4 — промпт-как-материал** (директива владельца: цитаты не нужны дословно, блоки — контекст): V1-промпт
  приведён к модели V2 (без обязательных цитат, привязка в метаданных), + усилена анти-выдумка.
- **C5 — base-recall-floor для клона** (приём chat-v2): по дисциплине «симуляция ДО постройки» доказал, что
  узкий фильтр клона (`subject`-носителя + `SKILL_SUBJECT`) выкидывает ровно блоки-ответы (для «какие
  интеграции» топ-6 широкого поиска — ВСЕ вне узкого подграфа, косинус 0.526>0.46). Построил: `fetchBaseRecallFloor`
  (сырой семантический поиск по canonical org-блокам) + RRF `fuseBlockLists`, подмешан в `loadRoleSubgraph`
  даже когда узкий пуст. Крутилка `clone.retrieval.base_recall_floor`.
- **Судейский guard:** `fabricated=true` с ПУСТЫМ `fabricatedClaim` → не фабрикация (нельзя обвинить без конкретики).

## Чему научился
1. **Один рычаг может быть НЕОБХОДИМ, но НЕДОСТАТОЧЕН — измеряй связку.** C3 в изоляции (снять гейт цитат)
   дал EXPERT 67→63% (отказы→WEAK), C4 частично, и только C5 (floor даёт РЕАЛЬНЫЙ материал) превратил связку
   в +8 п.п. Урок: если рычаг-A открывает ответы, но они слабые — не откатывай A, ищи рычаг-B (данные для ответа).
2. **«Умный» узкий фильтр ретрива системно режет recall — то же, что в chat-v2.** Клон-подграф (subject+SKILL_SUBJECT)
   выкидывал фактические task/status-блоки. Детерминированный широкий floor по сырому вопросу их возвращает.
   **Симуляция floor ДО постройки** (широкий vs узкий на провальных вопросах) окупилась — доказала рычаг за минуты.
3. **LLM-судья даёт самопротиворечивые вердикты** (`fabricated=true` при рационале «опора легитимна, дословно
   совпадает»). Детерминированный guard «нет claim → нет фабрикации» чистит шум. Урок арки повторно: **проверяй
   вердикт-инвариант против рационале/первоисточника, прежде чем чинить продукт** (как раньше — регламенты, которых
   судья не видел).
4. **BOUNDARY-«провалы» ≠ нарушения границы.** Все 4 — `held=true, useful=false` (клон верно не дал прогноз/скидку/
   закрытую встречу, но суховато). 0 breach. Инвариант держится по безопасности; helpfulness отказа — отдельный рычаг.
