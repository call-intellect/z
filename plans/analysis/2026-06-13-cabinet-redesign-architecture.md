**Дата:** 2026-06-13
**Статус:** архитектура (не ТЗ) — основа для HTML-прототипов (Шаг 2) и ТЗ (Шаг 3)
**Вход:** продуктовый аудит `plans/analysis/2026-06-12-product-audit-cabinet-ui-dashboards.md` + разведка кода (8 агентов, факты с `file:line` ниже)

Сведено из 7 прежних ТЗ + дорожной карты (`research-tzs`, сводная таблица):

| Дозированность: топ-5/топ-5, полный список по клику | ТЗ-D D-3 |
| Кабинет «Я» — один пункт с вкладками, self-тон без HR-блоков | ТЗ-E Р3/E-1 |
| Мобилка = быстрый взгляд по роли (дашборды+чек-ин+спросить), полный интерфейс — десктоп | `mobile-cora-exec-manager.md` инвариант №1 |

**Три класса-болезни аудита, которые архитектура обязана закрыть структурно (не косметикой):**
- **Б-2 противоречия:** один источник правды на показатель (одна вьюха/сервис, переиспользуемая всеми экранами) + автотест-инвариант «число на Сегодня == число в разделе».
- **Б-3 экстракция без гейтов:** каждая производная метрика фильтрует «считаем только полные сущности» (обещание = кто+что+срок, иначе «открытый вопрос»; сущность ниже порога уверенности не создаётся).
- **Б-6 пустота≠ноль≠поломка:** у каждого виджета три состояния — данные / нет данных (`—` + причина + CTA) / сбой (плашка «чиним», без чисел).

## 3. Архитектура экранов: состав → источник → вердикт

Легенда вердикта: **✅ ЕСТЬ** (эндпоинт+сервис готовы) · **🟡 ДОСТРОИТЬ** (данные есть, нужен новый расчёт/поле/UI) · **🔴 ПОСТРОИТЬ** (нет, нужен агент/модель).

### 3.1 Топ-бар (глобальный, все роли)

| Элемент | Состав | Источник | Вердикт |
|---|---|---|---|
| **+ Создать ▾** | Встреча · Мысль (дамп) · Задача · Цель | `/meetings/create`; дамп `POST /api/v1/dump` (`dump.controller`); задача `POST /intake`; цель `POST /goals` | ✅ ЕСТЬ (собрать меню) |
| **🔔 Требует вас: N** | счётчик + dropdown топ-5 | `GET /api/v1/pending-actions/count` → `{total,bySource}` (`pending-actions.controller:57`), poll 60с | ✅ ЕСТЬ |
| Поиск | глобальный | `GET /api/v1/search` (`search.api.ts:83`) | ✅ ЕСТЬ |
| OrgSwitcher | переключатель Org | существует (`Sidebar:786`) | ✅ ЕСТЬ |

**«Требует вас» — экран `/actions`** (переименовать из «Подтверждения»):

| Состав | Источник | Вердикт |
|---|---|---|
| Группы: Вопросы Коры · Конфликты карточек · Кандидаты в задачи · Карточки на проверке | 4 провайдера `PendingActionsService` (`curation/conflict/intake/probe`, `pending-actions.service.ts:75`) | ✅ ЕСТЬ |
| Заголовок-СУТЬ у каждого элемента (не «Уточняющий вопрос ждёт ответа») | `PendingActionItem.title` уже готовый RU-текст (`pending-actions-provider.types.ts:9`) — но провайдеры кладут шаблон вместо сути | 🟡 ДОСТРОИТЬ: провайдерам класть реальную суть (текст вопроса/конфликта) в `title` |
| Inline-резолв (Принять/Отклонить из списка) | сейчас только `curation` light (`pending-actions.service.ts:211`) | 🟡 ДОСТРОИТЬ: сквозной `POST /pending-actions/confirm` для conflict (есть `conflicts/:id/resolve`), probe (`notifications/:id/respond`), intake (`intake/:id/triage`) — обернуть в единый резолвер |
| Приоритет + авто-протухание (16-дневные сами закрываются) | `expiresAt` есть у curation+probe; нет у conflict/intake (`research-data` §1) | 🟡 ДОСТРОИТЬ: `expiresAt` на conflict/intake + sweep-крон авто-закрытия |
| Снятие двойного учёта Входящие↔Подтверждения | intake светится и в `/intake`, и в `/actions` | 🟡 ДОСТРОИТЬ: единый показ только в «Требует вас», `/intake` → вкладка-зеркало того же провайдера |

**Усиления дизайна (запрос владельца «ярче, секси, 3D, плавающие плашки»)** — закладываю в прототипы, не нарушая принятый язык:
- ярче акценты данных (насыщенность дата-виз +, неоновые штрихи на ключевых числах через `text-shadow` hero-hue);
- «плавающие плашки» — усиленный объём (многослойные тени + лёгкий parallax-tilt на hover ключевых карточек);
- подсветка полос/цифр — анимированные градиент-бордеры на карточке-якоре «Требует вас» и hero-числах;

## 8. Развилки — решены (с обоснованием, без вопросов владельцу)

| Развилка | Решение | Почему лучше |
|---|---|---|
| Куда деть Операции-пульс (`/dashboard/operations`)? | Вкладка «Пульс сейчас» внутри **Неделя** | Это «текущее состояние», читается на планёрке = недельный ритуал (EOS Level 10). Отдельный пункт меню дублировал бы Неделю |

| 3 ритма для coo или только owner? | coo видит Сегодня+Неделя, «Итоги месяца» — только owner | Месяц = витрина собственнику/совету (board pack); coo живёт в недельном ритме |
| Daily-digest: встроить в Сегодня и удалить `/dashboard/operations/daily`? | Встроить в Сегодня, путь **сохранить** (redirect/«полная версия») | Cron пушит `daily?date=` всем участникам (`daily-digest.cron:251`) — удаление = битые пуши |
| Карточки: переименовать или слить с Проектами? | Переименовать «Клиенты и сделки», вид внутри Встреч/Памяти | Это CRM встреч, ближе к встречам/памяти, чем к трекеру задач |

| Светлая тема в прототипах? | **Да — обе темы** (тёмная дефолт + светлая по референсу владельца), переключатель `data-theme` | владелец дал референс (присланный светлый экран) и просит светлую сразу «sexy как тёмную»; один источник токенов через CSS-переменные (отменяет прежнее «только тёмная») |

## Итог

Целевой кабинет: **8 видимых пунктов владельцу** (3 ритма Сегодня/Неделя/Месяц + 4 рабочих + Я) вместо ~30, **5 — рядовому** (совпадает с уже реализованной мобилкой), **1 очередь «Требует вас»** вместо 4 очередей долгов, **3 входа в Память** вместо 8. Контент не теряется — 6 дашбордных поверхностей перераспределяются в 3 ритма с чёткими горизонтами; каждый показатель проваливается до цитаты-источника; дашборд молчит при норме. ~70% — перекомпоновка готовых эндпоинтов, ~10% — 4 новых строительных блока (авто-название встреч, silence-детектор, merge отделов, UI поиска памяти). Мобильный слой перекраивается синхронно через единый nav-конфиг. Дизайн — на утверждённых `modern/`-токенах, с усилением яркости/объёма/«плавающих плашек» по запросу владельца.
