# Подключение Context7 MCP в проект Z

## Что было поставлено

Пользователь хотел, чтобы у Claude Code в проекте Z был постоянный доступ к свежей документации внешних библиотек — и чтобы это было зафиксировано в правилах проекта, а не оставалось «договорённостью на словах». Требование явное: не просто разовый вызов, а встроенный инструмент с обязательным использованием при работе с библиотеками.

## Как решал

Минимальный набор изменений для полной интеграции MCP-сервера:

1. **Подключение сервера** — `claude mcp add` с `--scope user` и `--transport http`. User-scope, потому что ключ не должен попасть в репозиторий, а инструмент нужен во всех сессиях. HTTP-транспорт проще stdio (не нужен npx, меньше латенси).

2. **Ключ через env-переменную** — `[Environment]::SetEnvironmentVariable("CONTEXT7_API_KEY", ..., "User")` в PowerShell. После установки нужен перезапуск VSCode, чтобы новые процессы увидели переменную.

3. **Allow-permissions** в [.claude/settings.json](../../.claude/settings.json) для `mcp__context7__resolve-library-id` и `mcp__context7__query-docs` — чтобы инструменты вызывались без отдельного prompt'а на каждое использование.

4. **Правило в [.claude/CLAUDE.md](../../.claude/CLAUDE.md)** — отдельный блок «Context7 — свежая документация внешних библиотек (MCP)»: когда обязательно вызывать (Next.js, NestJS, Prisma, LiveKit, BullMQ и т.д.), когда можно не вызывать, и два шага вызова. Граница с vexp зафиксирована явно: vexp — наш код, Context7 — внешние библиотеки.

Коммит: `5f726a1 chore(claude): подключение Context7 MCP — allow-permissions и правило об использовании`.

## Что вышло

- `claude mcp list` → `context7: ✓ Connected`.
- Живой тест `resolve-library-id` на «LiveKit React Components» вернул 5 реальных вариантов с метаданными (количество сниппетов, репутация, benchmark score). Для нашего фронта релевантна `/livekit/components-js` — 237 сниппетов, High reputation.
- Auth через `CONTEXT7_API_KEY` работает, allow-permissions сработали без prompt'а.

## Чему научился

**Урок 1: проверять реальные имена MCP-инструментов через ToolSearch до записи их в правила.** Я по памяти записал имя `get-library-docs` (это имя из старой версии Context7 MCP), а реальное оказалось `query-docs`. Поймали только при живом тесте — пришлось править allow в settings и инструкцию в CLAUDE.md. Цена ошибки была бы выше, если бы заметили в проде через неделю — правило стояло бы, инструмент молча не работал.

**Урок 2: рабочий шаблон интеграции MCP-сервера** — env var + user-scope + HTTP transport + allow в settings + правило в CLAUDE.md. Пять компонентов, и сервер становится частью «инвариантов проекта», а не одноразовой настройкой. Этот шаблон переиспользуем для следующих MCP-серверов (например, если будем добавлять MCP для Linear, Slack, S3-explorer и т.п.).

**Урок 3: ключ виден в plaintext** в `C:\Users\USER\.claude.json` после `claude mcp add` — так работает Claude Code CLI. Если ключ скомпрометируется, ротация = remove + add с новым ключом. Для прод-ключей с высокими привилегиями это аргумент за stdio-транспорт с подстановкой через `${ENV_VAR}` (только тот синтаксис гарантирован).
