## Чему научился (тех. факты о проекте)
- **`dataClass` ≠ доступ пользователя** — только LLM-routing (maxDataClass) + egress (canEmit). В доках назван «конфиденциальностью», что вводит в заблуждение. Для доступа нужна отдельная ось.
- **Граф знаний org-wide общий НАМЕРЕННО** (rbac-access-control.md:126: «иначе разваливается на per-user силосы»). Это не баг, а зафиксированный дефолт — любое разграничение должно сохранить дефолт «видно всем».
- **Casbin в Z самописный** (rbac.service.ts:675 — линейный перебор policy.csv), НЕ node-casbin. model.conf — декларация на будущее. ABAC-проверки делаются отдельными методами RbacService (canViewEmployeeFullCard) — образец для расширения. `getImplicitResourcesForUser` тут НЕ доступен.
- **chat-v2 retrieval двухфазный** (pool → id=ANY → ORDER BY) → pre-filter в pool безопасен для HNSW-recall; `/search` одношаговый → нужен iterative_scan/overfetch. Дефолтный WHERE поверх HNSW = post-filter → обвал recall.
- **RetrievalCache (dialog-layer) ключ без userId/групп** → кэш-hit обходит любой access-pre-filter. Ловушка для любой фичи доступа.
- **subject-атрибуция типонезависима**, гейтится только Set на block-ingest.worker.ts:991; who-ось AxisClassifier зависит от role='subject' → расширение привязки авто-расширяет who-ось. Клоны (specialist-3-7) читают только 3 reasoning-типа с role='subject' — вот почему «что Иван говорил по факту» не работает.
- **DepartmentDomainLink + functional-ось существуют, но при ingest не используются** — готовый мост «тема→домен→отдел» для авто-горизонтали.
- **DataClassPolicyService.derive() + enforcement off/shadow/enforce** — готовый паттерн наследования «строжайшего» + поэтапного выката; группу наследовать тем же derive.

## Чему научился (метод)
- Red-team с НЕЗАВИСИМЫМ retrieval реально переворачивает вывод — первый проход тянул к «умному авто-классификатору», который и дырявый, и ломает позиционирование. Без состязательного прохода отдал бы ТЗ на песке.
- Вопрос владельца про клонов («на чём строится клон, если автор не помечен?») вскрыл, что провенанс — не украшение, а фундамент продукта. Один вопрос изменил приоритет (Р-4 «пока не нужно» → «нужно как фундамент»).
- Упрощение по запросу владельца («группы или уровни — давай простым») дало более чистую модель, чем моя первая (отдельная вертикальная лестница) — всё свелось к одному механизму «группы».
