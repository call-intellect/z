# Анализ: Биллинг-стратегия, paywall и демо-кабинет

**Дата:** 2026-05-28
**Статус:** `[ ]` черновик анализа
**Категория:** монетизация, UX, конверсия

---

## 1. Текущее состояние

### 1.1. Что видит новый пользователь

```
Регистрация (email → пароль на почту)
  → Смена пароля (/onboarding/change-password)
  → Welcome-онбординг 6 шагов (роль → размер → отрасль → боли → стек → фичи)
  → Дашборд (director) или /me (member)
```

**Проблема:** пользователь проходит онбординг, попадает в **пустой кабинет** без проектов, задач, встреч, данных. Ему предлагается «настроить компанию» (6 шагов setup-тура), но это всё — конфигурация, а не демонстрация ценности.

### 1.2. Биллинг сегодня

| Где находится | Что видит | CTA |
|---|---|---|
| `/settings/subscription` | Карточка подписки, оплата картой/счётом | «Оплатить» (Точка-эквайринг) |
| `/settings/billing` | Тариф, таблица фич, квоты | «Связаться с нами» (email/Telegram) |
| `<TierGate>` на закрытых фичах | Замок + «Доступно на тарифе X» | «Подробнее о тарифах» → `/settings/billing` |
| Sidebar | Замок на закрытых пунктах | Клик → `/settings/billing` |

**Подписка при создании Org:** `SubscriptionService.ensureDemo()` создаёт запись `status=DEMO`. Но **DEMO не блокирует ничего** — пользователь может создавать проекты, спринты, встречи, не заплатив ни рубля.

### 1.3. Тарифы

Сейчас один тариф: `tier_standard` (60 000 ₽/мес, 31 место, 150 встреч). Legacy-тиры (`basic`, `pro`, `enterprise`) существуют в коде, но все Org мигрированы в `standard`. Feature-gating через `EntitlementGuard` работает только на ~5 эндпоинтах (goals, exports, director dashboard, public API, web form dump).

### 1.4. Ключевые проблемы

1. **Биллинг невидим.** Чтобы оплатить, нужно знать про `/settings/subscription`. 90% пользователей туда не дойдут.
2. **Нет value demonstration.** Пустой кабинет не показывает, что умеет продукт. Пользователь не понимает, ЗА ЧТО платить.
3. **Нет мотивации платить.** DEMO-статус ничего не ограничивает — можно пользоваться бесконечно бесплатно.
4. **Нет upgrade-триггеров.** При создании проекта/спринта — ни слова о тарифе. Пользователь не знает, что это платная функция.
5. **Нет trial-ограничения.** Нет временного окна «попробуйте 14 дней, потом платите».
6. **Pricing-страницы нет.** Нет публичной страницы с тарифами, куда можно привести из рекламы или из продукта.

## 2. Модель монетизации Z (финальное решение)

### 2.1. Демо-режим (read-only) — без trial

**Как работает:**
- При регистрации пользователь попадает в **демо-кабинет** (read-only).
- Может кликать по всем страницам, открывать встречи, граф знаний, клоны.
- **НЕ может создавать свои данные** (проекты, задачи, встречи, чаты).
- Для создания данных — **обязательная оплата**.

**Почему без trial:**
- Продукт генерирует дорогие ресурсы (видеозаписи встреч, LLM-токены, транскрипты).
- Бесплатный trial = убытки от злоупотребления (можно нажечь тысячи рублей токенов).
- Демо-кабинет показывает ценность без риска.
- Высокий чек (60 000 ₽/мес) — покупка обдуманная, не импульсивная.

**Кто так делает:**
- **Salesforce** — demo sandbox без trial
- **HubSpot Enterprise** — demo-only перед контрактом
- **Monday.com Enterprise** — demo перед оплатой

### 2.2. Тариф: один, масштабируемый по местам

**Базовая цена:** 60 000 ₽/мес (или 576 000 ₽/год — скидка 20%)

**Включено:**
- 150 видеовстреч в месяц
- 31 место (1 owner + 30 пользователей)
- Все фичи (граф знаний, клоны, AI-отчёты, трекер)
- Безлимитные проекты, задачи, документы

**Доп. места:** +1 000 ₽/мес за каждого пользователя сверх 31

**Перерасход встреч:** докупать пакеты (TBD — пока не реализовано)

**Автопродление:** включено по умолчанию, можно отключить

**Возврат:** нет (только отмена автопродления)

### 2.3. User Journey

```
Регистрация
  ↓
Онбординг (6 шагов)
  ↓
Выбор: "Посмотреть демо" или "Оплатить сразу"
  ↓
[Демо] Read-only просмотр заполненного кабинета (12 сотрудников, 3 проекта, 7 встреч)
  ↓
Banner: "Чтобы начать работу, оплатите подписку — 60 000 ₽/мес"
  ↓
[Оплата] Карта или безнал (Точка-эквайринг)
  ↓
Полный доступ (создание данных, встречи, LLM)
  ↓
[Опц.] Добавить места (+1 000 ₽/мес за каждого)
```

### 2.4. Демо-кабинет (Demo Workspace)

**Как работает:**
- При первом входе пользователь видит выбор: «Попробовать демо» или «Начать с нуля».
- Демо — это заполненный workspace: 2-3 проекта, 15-20 задач, спринт, 3-4 встречи с AI-отчётами, граф знаний.
- Демо-данные выглядят как реальные: имена, описания, комментарии — всё живое.

**Кто использует:**
- **Linear** — demo project с задачами и циклами.
- **Notion** — template gallery + sample workspace.
- **Monday.com** — pre-filled board при signup.
- **Asana** — example project при первом входе.

### 2.3. Upgrade-триггеры (моменты для paywall)

| Триггер | Что делаем | Пример |
|---|---|---|
| **Лимит проектов** | 1-й проект — бесплатно, 2-й — paywall | Linear: 3 проекта free, далее Pro |
| **Лимит участников** | До 5 — free, 6+ — paywall | Monday: 3 free, далее paid |
| **Временной trial** | 14 дней — banner «осталось N дней» | Notion: «Trial ends in 5 days» |
| **Исчерпание встреч** | 150/мес — после paywall | Текущий MeetingsBalance |
| **Закрытая фича** | Клик → paywall модалка | Текущий TierGate |
| **Создание спринта** | Если нет подписки → «Активируйте» | Новый |

## 3. Предлагаемое решение

### 3.1. Демо-кабинет

**Что создаём:** seed-скрипт, который при выборе «Демо» заполняет Org:

| Сущность | Количество | Описание |
|---|---|---|
| Проект | 2 | «Разработка продукта» + «Маркетинг Q2» |
| Доска | 2 на проект | default + «Баг-трекер» |
| Задачи (Issue) | ~20 | С реальными названиями, описаниями, статусами |
| Спринт | 1 активный | С привязкой к задачам |
| Цикл | 1 | В проекте «Разработка» |
| Встреча (Meeting) | 3 | С AI-отчётами (pre-generated текст) |
| Граф знаний | ~10 IdeaBlock | Связанные с встречами |
| Цель (Goal) | 2 | С привязкой к задачам |
| Участники | 3 | Анна (PM), Дима (разработчик), Катя (дизайнер) |

**Данные выглядят как настоящие:**
- Задачи: «Рефакторить авторизацию», «Настроить CI/CD», «Дизайн мобильного приложения»
- Комментарии: «Готово, запушил в main», «Нужен ревью от Кати»
- AI-отчёты: реальные summaries, решения, action items

**Технически:** `backend/scripts/seed-demo-workspace.ts` — создаёт все сущности в транзакции. Вызывается из онбординга при выборе «Демо».

### 3.2. Модель доступа: демо → оплата

**Никакого trial.** Продукт генерирует дорогие ресурсы (видео, LLM-токены), поэтому trial без оплаты = убытки.

**Механика:**
1. При регистрации — `Subscription.status = DEMO` (read-only).
2. Пользователь видит демо-кабинет с заполненными данными.
3. Для создания своих данных — обязательная оплата → `status = ACTIVE`.
4. При истечении подписки → `status = SUSPENDED` (read-only, данные сохраняются).

**FSM переход:**
```
DEMO → ACTIVE (оплата)
ACTIVE → SUSPENDED (просрочка платежа, 0 дней grace)
ACTIVE → CANCELED (отмена автопродления)
CANCELED → EXPIRED (окончание периода)
SUSPENDED → ACTIVE (оплата)
EXPIRED → ACTIVE (повторная оплата)
```

**В read-only (DEMO/SUSPENDED/EXPIRED):**
- ✅ Просмотр всех своих данных
- ❌ Создание/изменение/удаление
- ❌ Проведение встреч (тратит видео-токены)
- ❌ Чат с AI/клонами (тратит LLM-токены)

### 3.3. Лимиты по тарифу (Standard — 60 000 ₽/мес)

| Ресурс | Лимит | Перерасход |
|---|---|---|
| Видеовстречи | 150/мес | Блокировка создания до следующего месяца |
| Пользователи | 31 место | +1 000 ₽/мес за каждого доп. |
| Проекты/задачи | Безлимит | — |
| AI-отчёты | Безлимит | — |
| Граф знаний | Безлимит | — |

### 3.4. Paywall-индикаторы

**В демо-режиме:**

| Местоположение | Что показываем |
|---|---|
| Top banner (sticky) | «Демо-режим: просмотр без создания. [Оплатить 60 000 ₽/мес]» |
| Кнопка «Создать» | Disabled + tooltip «Оплатите подписку» |
| Модальное окно | При попытке создать → PaywallModal с тарифом |
| Sidebar badge | «DEMO» рядом с аватаром Org |

**В active-режиме:**

| Местоположение | Что показываем |
|---|---|
| Встречи — прогресс | «N из 150 встреч использовано» (при N > 100) |
| Пользователи | «M из 31 мест занято» + [Добавить места] |

### 3.5. Pricing-страница (публичная)

Новая страница `/pricing` — доступна без авторизации:
- **Один тариф:** Standard (60 000 ₽/мес или 576 000 ₽/год — скидка 20%)
- Что включено (150 встреч, 31 место, все фичи)
- Доп. места (+1 000 ₽/мес за каждого)
- FAQ (почему нет trial, что такое демо-режим)
- CTA «Посмотреть демо» → регистрация

## 5. Архитектурные решения

### 5.1. Проверка подписки

Текущий `EntitlementGuard` проверяет feature-флаги. Добавляем:

1. **SubscriptionGuard** (новый) — проверяет `Subscription.status === 'ACTIVE'` для мутаций.
2. **@RequireSubscription()** — декоратор на методы контроллеров.
3. Backend: блокирует POST/PATCH/DELETE в DEMO/SUSPENDED/EXPIRED.
4. При блокировке: 403 `{code: 'subscription_required', status: 'DEMO'}`.

### 5.2. Проверка лимитов (встречи, места)

1. **MeetingsBalanceGuard** — проверяет `balance.remaining > 0` перед созданием встречи.
2. **SeatsGuard** — проверяет `org.members.length < subscription.seats` при приглашении.
3. При превышении: 403 `{code: 'meetings_limit_reached'}` или `{code: 'seats_limit_reached'}`.

### 5.3. Демо-данные

Seed-скрипт создаёт реалистичные данные. **Важно:**
- Демо-данные помечаются `externalSource: 'demo'` — чтобы можно было массово удалить при сбросе.
- Пользователь может «Сбросить демо» → удалить все `externalSource='demo'` записи.
- При оплате — демо-данные остаются (пользователь уже привык к интерфейсу).

| Риск | Вероятность | Митигация |

## 8. Приоритеты

1. **🔴 Критично (выполняется):** Демо-кабинет — показывает ценность продукта.
2. **🔴 Критично (следующий):** SubscriptionGuard + Paywall UI — блокирует создание в DEMO.
3. **🟡 Важно:** Страница оплаты + управление местами.
4. **🟢 Желательно:** Pricing-страница (публичная, для привлечения).
5. **🟢 Желательно:** Cron проверки подписки + миграция старых пользователей.

## 9. Что НЕ делаем

- **Не делаем trial.** Продукт генерирует дорогие ресурсы (видео, LLM) — trial без оплаты = убытки.
- **Не делаем freemium.** B2B-продукт с высоким чеком — freemium убивает выручку.
- **Не усложняем тарифы.** Один тариф Standard (60 000 ₽/мес) + доп. места. Не нужно 5 тарифов.
- **Не блокируем чтение.** В DEMO/SUSPENDED/EXPIRED пользователь видит данные (но не может создавать).
