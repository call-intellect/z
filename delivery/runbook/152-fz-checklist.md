# Runbook: 152-ФЗ checklist для клиента

Документ для администратора компании-клиента, разворачивающего систему. Помогает соответствовать требованиям 152-ФЗ «О персональных данных».

## Что мы делаем со стороны продукта

| Требование 152-ФЗ | Реализация в продукте |
|---|---|
| Хранение ПД на территории РФ | Self-host на ваших серверах в РФ — вы контролируете |
| Защита ПД (ст. 19) | Encryption-at-rest, TLS, RBAC, audit |
| Согласие субъекта (ст. 9) | Onboarding-flow с явным consent |
| Право на доступ к своим данным (ст. 14) | UI экспорт `/me/export` |
| Право на удаление (ст. 21) | UI «Удалить мой след» + админ-flow |
| Журнал обработки ПД | Встроен в audit-log |
| Уведомление об инциденте (ст. 21.1) | Алерт-система + procedure |

## Что должен сделать клиент

### 1. Уведомление в Роскомнадзор

До начала обработки ПД сотрудников и клиентов — подать уведомление:
- Через сайт rkn.gov.ru → «Реестр операторов».
- Срок: не позднее даты начала обработки.
- Что указать: цели, состав ПД, способы обработки, перечень действий.

Шаблон уведомления — в `templates/rkn-notification.docx` (предоставляется при инсталляции).

### 2. Назначение ответственного за ПД (ст. 22.1)

Для компаний с обработкой ПД более 25 человек обязательно. На практике — рекомендуем всем.

Указывается в админке `/admin/compliance/responsible-officer`.

### 3. Локальные политики

Должны быть приняты внутри компании:
- Положение об обработке ПД.
- Политика конфиденциальности (для сайта/публикации).
- Регламент обработки ПД сотрудников.
- Регламент реагирования на инциденты.

Шаблоны — в `templates/policies/`.

### 4. Согласия

Каждый сотрудник, чьи ПД обрабатываются:
- Подписывает согласие на обработку (бумажное / электронное).
- Согласие включает: цели, состав ПД, срок, право отзыва.

Шаблон — `templates/employee-consent.docx`.

Клиенты компании, чьи ПД обрабатываются:
- Согласие через политику конфиденциальности на сайте + checkbox при регистрации.

### 5. Технические меры защиты

Должны быть реализованы (в инфраструктуре клиента):
- Сетевая изоляция (firewall).
- Шифрование дисков (LUKS / BitLocker).
- Антивирусная защита.
- Регулярные обновления ОС.
- Журналирование действий (наш audit-log).
- MFA для административного доступа.
- VPN для удалённого доступа.

В инфраструктуре делается клиентом. Чек-лист — `templates/security-checklist.md`.

### 6. Реагирование на инциденты

При утечке ПД:
- Уведомить РКН в течение 24 часов.
- Уведомить субъектов в течение 72 часов.
- Зафиксировать в журнале инцидентов.

Шаблон уведомления — `templates/incident-notification.docx`.

## Уровень защищённости

Определяется по приказу № 21 (ФСТЭК):
- УЗ-4 (минимум): ≤ 100 000 субъектов, специальные/биометрические/иные ПД ≤ 100 000.
- УЗ-3: до 100 000.
- УЗ-2: больше.
- УЗ-1: жесткий уровень.

Для большинства клиентов SMB (20-500 сотрудников) — УЗ-4 или УЗ-3.

Состав мер защиты для каждого уровня — в приказе ФСТЭК. Наша инфраструктура (encryption, RBAC, audit) покрывает требования УЗ-4 и большинство УЗ-3.

## Подтверждение соответствия

### Внутренний аудит

Раз в год администратор клиента проводит:
- Проверку настройки доступов.
- Аудит изменений политик хранения.
- Проверку backup и forget-flow.
- Обзор audit-логов на аномалии.

Скрипт: `./scripts/internal-audit.sh` — генерирует отчёт.

### Внешний аудит (опционально)

Для крупных клиентов / контрактов — рекомендуем периодический пентест и внешний аудит соответствия. Партнёры — по запросу.

## Cross-border transfer

Если данные пересекают границу (например, через cloud LLM в США/ЕС) — это transborder transfer. Требует:
- Согласие субъекта (явное).
- Адекватная защита в стране-получателе.

**Поэтому в default-конфиге** для sensitive/private данных мы маршрутизируем в локальные LLM ([07-ai-team.md](../07-ai-team.md)). Cloud LLM используется только для public/internal с opt-in компании.

Если клиент вообще запрещает cross-border — переключаем `routing_policy = local-only`.

## Что делать в случае запроса субъекта

### Запрос на доступ к своим данным

1. Проверка identity (через email-confirmation или MFA).
2. Через `/me/export` или админ-API → ZIP.
3. Передача безопасным каналом.
4. Срок: 10 рабочих дней (ст. 14).

### Запрос на удаление

См. `forget-user.md`.

Срок: 30 дней.

### Запрос на исправление неточностей

Через диалог с AI («исправьте, что у меня имя не Маша, а Мария»). AI применяет change через M-26.

## Аудит-логи (журнал доступа к ПД)

Хранятся:
- 3 года в active storage.
- 5 лет в архиве.

Доступны через `/admin/compliance/audit-log`.

При запросе РКН — формирование выгрузки за указанный период:

```bash
./scripts/compliance-audit-export.sh --from="2026-01-01" --to="2026-12-31"
```
