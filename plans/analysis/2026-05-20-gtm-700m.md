## 0. Executive Summary

Мы строим **«Кору» — память компании**: новую категорию SaaS, где AI-встречи становятся точкой входа, а финальная ценность — единый событийно-структурированный граф знаний всей организации (per-Org Knowledge Core, event-sourced ядро, bitemporal-модель). Целевая аудитория — компании 5-1000 человек в РФ и СНГ, которые «выросли быстрее своей памяти»: при 18-25% ротации в год, 130+ корпоративных SaaS-системах и 5,3 ч/нед на поиск информации они теряют контекст, договорённости и решения. Конкурентов с такой полнотой памяти в РФ нет (mymeet, Контур.Толк, SaluteJazz, Я.Телемост — saммаризируют одну встречу, Notion/TEAMLY — пустые страницы, CRM — структурированные сделки без живого контекста). Окно — 12-18 мес до выхода Сбер GigaMemory; за это время Z должен занять категорийный лейбл и подписать первую сотню платящих средних и крупных компаний.

Цель — **700 млн ₽/мес ARR (8,4 млрд ₽ run-rate) к месяцу 24 при базовой вероятности 45-50% и реалистичном P50 в коридоре 540-600 млн ₽/мес** (700 млн ₽ к M30 при P75). Конструкция — 6 866 платящих организаций, разнесённые по 5 сегментам и 5 SKU (Solo Lite, Team, Business, Enterprise, On-prem) плюс 7 add-ons. Три ключевые ставки: **(1) категория «память компании» как mind-share-моат на 5 лет**; **(2) Knowledge Core в три волны (Decision/valid_from/Stylistic → Phase 6/8/9 + Decision Archaeologist → Phase 11/12 + Employee Clone)** как продуктовый моат, который Сбер не повторит за 12 мес; **(3) regulatory by design (152-ФЗ DPA, Реестр Минцифры с M3, on-prem GA M18, точечный ФСТЭК на M22-M24)** как regulatory-моат, выпиливающий западных конкурентов и открывающий B2G.

## 3. Решение — что такое Кора

### Категория

**«Память компании»** (Company Brain). Метафора в PR/инвесторских материалах — **«второй мозг компании»**. Институциональный регистр — **«институциональная память»**. Один лейбл везде, три стилистические оболочки под канал.

### Принцип

**Memory Is State, not Service.** Кора — не очередной AI-нотакер и не корпоративный поиск, а архитектурный слой: event-sourced ядро + per-Org Knowledge Graph + bitemporal-модель. Каждый разговор, решение, документ — событие в журнале, каждое состояние графа можно восстановить на любой момент в прошлом. Сбер за 12 мес это не повторит, потому что это не фича LLM, а архитектурная ставка.

### 5 продуктовых пластов

1. **AI-встречи нового поколения** — 9 типов (team / standup / plan_fact / project / sales / custdev / partner / interview / customer_success), отдельные аудиодорожки на каждого участника, диаризация ≥90% (vs 70-80% у конкурентов), AI-отчёт под тип встречи.
2. **CRM-карточки** — client/deal/project/topic/custom, автоматический rollup из встреч, чатов и писем; не заменяем Bitrix24/amoCRM, а наполняем их смыслом.
3. **Дашборд директора** — 6 виджетов + AI-чат поверх графа: pulse компании за 30 секунд (что обсуждают команды, какие сделки в риске, прогресс по целям, отклонения).
4. **Многоисточниковая память** — Bitrix24/amoCRM/Telegram/Я.Почта/Я.Календарь/1С/Outlook/Я.Диск/TEAMLY/Jira/GitHub собираются в один граф, дедуплицируются, индексируются с pgvector.
5. **AI-агенты** — Decision Archaeologist («почему мы решили X в марте»), Employee Clone («спроси у клона Маши, она в отпуске»), Process Narrator («собери документ процесса из реальных встреч и решений»), Compliance Agent («forensic-отчёт под 152-ФЗ»).

## 5. Технология и архитектура

### Стек

| Слой | Технология |
|---|---|
| **Frontend** | React 18 / Next.js 14, LiveKit React Components |
| **Backend** | NestJS, PostgreSQL 16 + pgvector, Redis, BullMQ |
| **Медиа** | LiveKit Server (SFU), LiveKit Egress (Composite + Track), отдельный TURN |
| **Storage** | Selectel S3 (prod), MinIO (on-prem/dev), 7-летний retention под 152-ФЗ |
| **ASR** | GigaAM v3 (open-source, SOTA для русского, бесплатно для коммерции) |
| **LLM** | Claude Sonnet 4.6 (primary через proxy.agent-lia.ru), GigaChat 2 Pro (cost-route), YandexGPT 5.1 Pro (fail-over reasoning), T-Pro 32B / Qwen 2.5 32B через vLLM (on-prem) |
| **Embeddings** | text-embedding-3-small, fallback на open-source |
| **Auth** | OIDC + Casbin RBAC (Team/Business), SAML + ABAC (Enterprise) |
| **Observability** | Prometheus + Grafana + Loki, Sentry |

### Принципы

1. **LiveKit — только медиа.** Все токены генерирует backend, гость не получает секретов LiveKit, бизнес-логика — в NestJS.
2. **Per-track audio** — отдельная дорожка на каждого участника → диаризация ≥90% против 70-80% у конкурентов (общий микс разрушает качество).
3. **Event-sourcing** — RawEvent + IdeaBlock с историей слияния; ничего не теряется, любое состояние графа восстанавливается на момент X.
4. **Per-Org Knowledge Graph** — жёсткое tenant-разделение, RLS на БД (Phase 11), ABAC изоляция по client/project в графе.
5. **Memory Is State** — данные = состояние, не сервис. Любой LLM-агент может прочитать его через MCP-протокол.

### AI-pipeline

```
LiveKit Egress (per-track) → S3 raw audio
   ↓
ASR (GigaAM v3) → per-speaker transcript + диаризация
   ↓
LLM-pipeline (LlmRouter):
   • chapters extraction
   • task extraction
   • template-aware report (под тип встречи)
   • RawEvent → IdeaBlock → Entity → Theme (Knowledge Core Ф0-4)
   • Decision class + valid_from/to (Ф0+gap)
   ↓
Per-Org Knowledge Graph (PostgreSQL + pgvector)
   ↓
Agents layer:
   • Decision Archaeologist
   • Employee Clone (Stylistic profile + Personal subgraph + Permissions)
   • Process Narrator
   • Compliance Agent
   ↓
Frontend: 9 типов отчётов + CRM-карточки + Director Dashboard + AI-Chat
```

### Knowledge Core: IdeaBlock + Entity + Theme + граф

- **IdeaBlock** — атомарная единица мысли: 1-3 предложения с источником (встреча/чат/документ), временем и автором.
- **Entity** — 13 классов: Person, Process, Decision, Project, Document, Event, Technology, Customer, Vendor, Product, Goal, Risk, Metric.
- **Theme** — кластер блоков по смыслу (например, «миграция с Salesforce», «найм CTO», «redesign онбординга»).
- **~40 типов рёбер** — owned_by, participated_in, depends_on, uses, produces, mentions, decides, derives_from, valid_from, valid_to.
- **5 моатов**: (1) event-sourced ядро, (2) per-Org граф, (3) bitemporal-модель (valid_from/to), (4) Decision как Entity первого класса, (5) Stylistic profile для Employee Clone.

### 152-ФЗ + Реестр Минцифры compliance by design

- **152-ФЗ:** retention 2555 дней (7 лет), right-to-erase (`DELETE /api/v1/persons/:id/data`), DataClass routing (public < internal < sensitive < private), отдельный документ согласия с 01.09.2025.
- **Реестр Минцифры:** заявка M3, свидетельство M9-M12 (рассмотрение 6-9 мес), Пост. №1937 — контроль ≥50% РФ.
- **ФСТЭК:** точечная аттестация ключевого компонента для конкретного КИИ-клиента M22-M24 (3-5 млн ₽).
- **Security:** AES-GCM-256 для secrets, SSRF-Guard (private CIDR, link-local, cloud-metadata), audit trail (`SuperAdminAccessLog`), soft-delete 30 дней.

### Self-hosted / on-prem

- Полный стек on-prem: LiveKit + Postgres + MinIO + Redis + GigaAM + T-Pro 32B / Qwen 2.5 32B через vLLM + OPA/Casbin.
- Тайминг: M1 — roadmap-commit, M6 — private cloud (изолированный namespace в Selectel/SberCloud), M12 — pilot on-prem (1-2 design partner), M15 — closed beta (3-5 ent), M18 — GA.
- Цена: лицензия 6 млн ₽/год (до 100 seats) → 14 млн (100-500) → от 25 млн (500+); deploy 1,5-4 млн ₽ one-time; maintenance 20% от лицензии.
