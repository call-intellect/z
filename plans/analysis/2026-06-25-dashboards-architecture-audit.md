## 2. Как устроено сейчас (механика ритм-дашбордов)

Поток: `page.tsx` → `*DesktopClient` → **`DashboardCanvas(role, rhythm)`** → `useDashboardLayout` →
если API `/dashboard/layout` вернул `null` (а он возвращает `null`), берётся **`DEFAULT_PRESETS[role][rhythm]`** →
массив id виджетов → из **`WIDGET_REGISTRY`** (20 виджетов) → рендер в **CSS-grid 12 колонок**.

### Реестр виджетов (20) и на каких ритмах
today(10): verdict, goal-vector, plan-fact, load, stale, blockers, ideas, decisions, feed, value
week(+3): trend, weekly-plan-fact, chains
month(+5): month-recap, achievements, weekly-dynamics, maturity, bus-factor
→ **today ⊂ week ⊂ month.** Месяц повторяет всё, что есть на дне и неделе. Это причина «одно и то же по 3 раза».

### Размеры → ширина колонок (SIZE_SPAN)
`sm=3/12`, `md=6/12`, `lg=8/12`, `xl=12/12`. Виджеты ставятся ЛИНЕЙНО по порядку пресета,
CSS-grid авто-разносит по строкам.

## 3. КОРЕНЬ «пустых мест слева/справа» (главный layout-баг)

`DashboardCanvas` = `grid grid-cols-12`, ширины фиксированы по size, порядок линейный, **БЕЗ балансировки/masonry**.
Следствия:
1. **Пустые колонки.** lg(8)→рядом помещается только 4; если следующий виджет md(6) — он не влезает,
   переносится, а 4 колонки справа от lg **остаются пустыми**. Так у `plan-fact`(8), `blockers`(8), `feed`(8).
2. **Разная высота колонок.** В строке из двух md(6): `stale` (20 задач, очень высокий) рядом с коротким
   виджетом (3 строки) → под коротким **огромная дыра**. Это и есть «справа длинный список, слева пусто».
3. `empty:hidden` прячет пустой виджет, но строку/гэп в гриде это не лечит.

**Что хочет владелец (верно):** длинные списки распределить по обеим колонкам (балансированный masonry),
а не складывать стопкой справа.

## 4. «Лента» — почему непонятно, что за события

`feed/cora?type=all&window=N` возвращает `items` РАЗНОРОДНЫХ типов в одном потоке:
- `insight` — риски/боли («…не понимают процесс постановки задач», severity=risk);
- `open_question` — вопросы Коры команде;
- активность — «Айназ подтвердила задачу», «chydo_002 взял задачу», «Сергею поручено…» (assignments/commitments).
В UI у каждой строки только текст + «23 ч назад». **Нет бейджа типа, иконки, фильтра — непонятно, что это и зачем.**
Состав зависит от `window`: на «Сегодня» (window=1) — активность; на 30 днях — insight/open_question.
→ Лента смешивает 3 разных сущности без маркировки. Нужны: тип-бейдж, иконка, фильтр по типу, или разнести на 2 ленты (события vs вопросы/риски).

## 5. «Аналитика» — почему «всё нули» (4 разные причины)

Все эндпоинты 200 (кроме графиков). «Нули» складываются из:
1. **Реальный 0 (хорошие новости, поданы как пустота):** Конфликты 0, Активные блокеры 0 (закрыто 13 за 30д), Провалившиеся цели 0.
2. **Структурный 0 (нет механизма заполнения):** `decisions/throughput` = total 42, doneWithOutcomes 0 → «Доведение решений 0%». Никто не закрывает решения с «результатом» → метрика всегда 0.
3. **Пустые под-блоки:** `maturity` score=0.132, но `weakestDomains=[]`, `topDomains=[]`, stage=null → «Слабые/Сильные места: Нет данных». «Скорость знаний: —» (knowledgeVelocity=null).
4. **Графики не рисуются:** recharts width/height = −1 (контейнер без minHeight) → пустые тёмные полосы.
Плюс: `customer-risk` отдаёт дубли (3 клиента как 20 строк → дутые «критичных 7»); `team-capacity` все 100% (выглядит тревожно/бессмысленно); двойная загрузка.

`OperationsDashboardClient` — **отдельный bespoke-клиент**, НЕ на реестре виджетов (своя вёрстка из 5 секций).

## 6. Сквозные проблемы (все ритм-дашборды)
1. Двойная загрузка всех данных (ререндер), `director` 4–5×.
2. Схлопнутые графики (recharts minHeight).
3. Рассинхрон одинаковых метрик между виджетами (период/источник): Польза month(18/30/64) vs week(11/15/37); цель goalsCount=1 vs goalVector=null vs goalsTree=[]; решения 0/0 (день) vs 16 застряли vs 42 (90д); обещания 112 vs 51.
4. Перегруз длинными лентами без лимитов (stale 20, decisions 16, ideas 22, «Без темы» ×5).
5. Дублирование виджетов между ритмами (today⊂week⊂month).
6. Нет drill-down к содержанию плана/отчёта (только счётчики; эндпоинты содержания 404).
7. Связка с целью сломана (suggested/непервичная цель → «Цель не задана»).
8. Orphan-дашборды (portfolio, value-recap) и дубли (maturity страница+виджет).

### 7.2 Раскладка: балансированные 2 колонки (фикс «пустоты»)
- Левая колонка = «факты/списки» (что зависло, решения, лента), правая = «метрики/сводки» (план-факт, нагрузка, цель) — или masonry-балансировка по высоте.

- Каждому списку: **топ-5 + «показать все»** (нет простыней на 20).
- Графикам — `minHeight` (убрать пустые полосы).

### 7.3 Данные/связки
- Единый ПЕРИОД на дашборд: «Сегодня» — только день; «Польза» не из month.
- Цель: вектор подхватывает активную цель (или CTA «Кора предложила цель — подтвердите»).
- План/факт: формула «сдали / ожидалось / всего», единый источник «кто отметился», ссылка на содержание чек-ина (нужен эндпоинт содержания).
- Дедуп с бэка: customer-risk, recurring-topics, идеи «Без темы».
- Убрать двойную загрузку (один fetch на дашборд).
- Решения: либо ввести фиксацию outcome, либо убрать метрику «доведено %», пока её нечем наполнять.
- Лента: бейдж типа + иконка + фильтр (события / вопросы / риски).

- Слить `/maturity` страницу с виджетом maturity (одно место).
- portfolio → раздел «Цели»; value-recap → виджет «Польза» (не плодить дашборды).

## 10. Перестановка модулей против пустот (без редизайна)

Причина пустот: линейный grid-12, ширины md=6/lg=8/xl=12 по порядку; lg(8) рядом не пускает md(6) → 4 пустые колонки; длинный список рядом с коротким → дыра снизу.

**Минимальный фикс (в рамках реестра/пресетов):** привести «контентные» виджеты к md(6) и расставить парами, крупные (вердикт/цель/польза) — xl(12). Тогда каждая строка = 12, пусто нет, а длинные списки идут парой (слева+справа).

Пример для owner.today:
```
[ verdict            xl 12 ]
[ goal-vector        xl 12 ]
[ plan-fact 6 | load 6      ]   ← было plan-fact lg(8) → дыра 4; стало 6+6
[ stale 6   | decisions 6   ]   ← два длинных списка рядом (как просил владелец)
[ ideas 6   | blockers 6    ]
[ feed              xl 12 ]      ← лента полной шириной (читабельнее)
[ value             xl 12 ]
```
Аналогично выровнять week/month: список+список в строке, графики/метрики парами. Плюс: каждому списку топ-5; графикам minHeight; убрать двойную загрузку.
