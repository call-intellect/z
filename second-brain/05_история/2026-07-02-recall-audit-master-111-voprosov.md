# Аудит recall «Мастера» — 111 вопросов с трассировкой внутренностей

## Что было поставлено
Владелец: перед показом клиенту прогнать большой тест «второго мозга» (100+ вопросов под разными углами, разные диалоги) и понять, почему recall неровный. По ходу владелец сузил до трёх вопросов: правильно ли построена (1) база/граф, (2) поиск по базе «дверь→рёбра», (3) сам chat-v2 и агенты. Отдельно просил показать «на пальцах, как ищется».

## Как решал (файлы, коммиты)
1. **Дозалил тенант «Стрела»** до 4 недель через реальный конвейер: `seed-synthetic-company-week3/4.ts` + `reprocess-stuck.ts` (STRELA_ORG=cmr1qbvpx0001pwbwxbgmh1jl). Итог: 292 canonical-блока, 5193 ребра, 22 темы.
2. **Разобрал внутренности** параллельными суб-агентами: цепочка агентов chat-v2 = 4 LLM-шага (было «5» в памяти владельца — два старых слили в `understand`, три от изъятого iterative-RAG отключены). Генератор `dialog-understand` делает 3 переформулировки, видит историю диалога, но НЕ видит справочник сущностей тенанта. Поиск = «дверь» (semantic+BM25) + `expandViaGraph` (1-hop по IdeaBlockLink), но граф пропускается при активном структурном фильтре (`!structural && graphHops>0`); EntityLink в recall не читается.
3. **Инструментировал retrieval** опциональным `RetrievalTraceSink` (`chat-v2-retrieval-trace.ts` + правки retrieval/synthesis/chat-v2, коммит a09e3a2a) — при trace=null прод не затронут.
4. **Прогнал 111 вопросов** харнессом `batch-recall-trace.ts` (dialog.process для трейса + askEphemeral(collectTrace) для ответа), снимая три слоя. Оценил `analyze-recall-results.ts` + строгий LLM-судья по эталонам.
5. **Два отчёта** в `plans/analysis/2026-07-02-recall-master-*` (коммит 2bd2189e).

## Что вышло (результаты)
- **Верно 59.5% (66/111), 0 галлюцинаций, 0 неверных выдумок**, честно молчит на несуществующем 8/8. Провал recall при наличии данных — 33%.
- **Главный корень (эмпирически): граф-обход заглушён структурным фильтром в 86% (88/103); 22 из 24 провалов — с выключенным графом.** «Дверь→граф» вырождается в «дверь без графа».
- **Гипотеза владельца про слепые синонимы ОПРОВЕРГНУТА числами:** распознал сущность → пусто 15%, не распознал → 28% (распознавание в среднем помогает). Инверсия на парах 429/Zoom: точный вопрос отвечал ХУЖЕ описательного — распознал узел → фильтр по узлу без прямых блоков → пул 0.
- Broad/список-вопросы уверенно отрицают существующее («других интеграций нет», а Zoom/Telegram есть). Списки встреч → 1 из 10.

## Чему научился
- **Эмпирика бьёт теорию.** Код-анализ 3 агентов говорил «граф читается 1-hop». Живая трассировка показала: в бою граф почти всегда выключен фильтром. Без инструментации не увидел бы. Владелец был прав, что просил «добавь логи, покажи на живых примерах».
- **«Ответил» ≠ «ответил верно».** Механический аналитик дал 72% (есть цитаты), строгий LLM-судья — 59.5% (верно по смыслу). Всегда нужен смысловой судья.
- **Гипотезу проверять на масштабе, не на 3 примерах** — инверсия канон/синоним на 6 записях выглядела как правило, на 111 оказалась частным случаем.
- **Ловушки харнесса:** `askEphemeral` внутри сам зовёт `dialog.process` → для трейса двойной вызов understand. Answer-cache отдаёт trace=null на повторах (smoke закешировал 8 вопросов → их трасса пустая, ответы валидны). `... | tail -N` без `-f` буферизует и не стримит прогресс — прогресс надо читать из инкрементального JSON.
- **Предсуществующая ошибка:** `chatbox-chats.service.ts:344` (`title` не на типе) — typecheck ветки work/2026-07-02 красный не из-за моих правок.
