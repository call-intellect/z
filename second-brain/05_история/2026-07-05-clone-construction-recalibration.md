# Рефлексия — рекалибровка построения клонов под новый код памяти + два фикса

## Что было поставлено

Стенд качества клонов использовался в другом заходе (recall / умные таблицы), код `knowledge-core`
за 2 дня изменился. Владелец: изучить изменения, пере-подготовить стенд начисто, прогнать **один цикл**,
прийти с результатами. Затем по решению — два плана: (1) re-tune порога и подтвердить; (2) починить
вскрывшиеся дефекты. В конце — аналитика «улучшилось/нет» + handoff-промпт для нового агента.

## Как решал

1. **Разведка изменений за 2 дня** — прочёл рефлексии recall/extraction. Выделил риск: `d556f11a`
   (дедуп-вектор блока → header-less) меняет эмбеддинги, а мой порог склейки черт `0.72` калибровался
   на header-full.
2. **Чистый пере-замер стенда** — wipe блоков+производной клонов тенанта `cmr4ztnfj` (253 старых
   header-full блока → mixed-space), затем `prepare → channelA → ingest` (55 ответов → 66 header-less
   блоков, атрибуция subject чистая, дедуп НЕ схлопнул перефразировки).
3. **build на 0.72 → регрессия:** черт 23→6, персон 0. Замер ближайших косинус-соседей subject-блоков
   (`embedding <=> embedding`) доказал: avg сходства ≈0.72, у Михаила потолок **0.706** → 0 кластеров.
   Порог режет посередине просевшего header-less распределения.
4. **План 1:** порог 0.60 (дев-БД) → повтор build → черты 6→**20 active** (skill 9, process_marker 6,
   value 5). Регрессия закрыта.
5. **План 2 (два дефекта, коммит `6c593a00`, спеки 46/46):**
   - **verify** — `deepseek-v4-pro` отдавал прозу-преамбулу вместо JSON → `JSON.parse` падал →
     fail-open. Фикс: промпт «весь ответ = один JSON, первый символ `{`…» + шаблон (идея владельца) +
     парсер `extractGroundedVerdict` (страховка). Итог: `checked 22 promoted 20 held 2 fail-open 0`.
   - **версионирование** — смена носителя роли крашила `Unique(scope,scopeRefId,version)`:
     идемпотентность против последовательного, но не конкурентного двойного эмита. Фикс: P2002-ретрай
     placeholder-create с пересчётом версии (паттерн `createRolePersonaWithRetry` билдера).
6. **Финальный build (0.60 + фиксы):** 20 active черт, **5 персон active** (3 person + 2 role), смена
   носителя без краша, `✓ build готов`. Аналитика + handoff `plans/handoff/2026-07-05-clone-quality-next-agent.md`.

## Что вышло (верификация)

- Черты 6→20 active; персоны 0→5; verify реально проверяет (2 честных held, 0 fail-open); смена носителя
  0 крашей. typecheck+lint зелёные; спеки versioning+specialist-3-7 **46/46**.
- Коммит `6c593a00` (verify+версионирование). Порог 0.60 — **только в дев-БД**, сид оставлен 0.72 (см. ниже).

## Чему научился

1. **Порог склейки черт — функция от эмбеддинга блока, не константа.** Смена содержимого эмбеддинга
   (header-less) молча ломает калибровку. Класс граблей тот же, что «getDynamic честнее статики» —
   значение, привязанное к старому пространству, ломается при смене пространства. Тронул `embedBlocks`/
   извлечение → обязателен пере-замер клон-стенда.
2. **Сопряжённая миграция «порог ↔ re-embed».** Порог 0.60 верен только для header-less. На проде re-embed
   был owner-gated (вероятно не применён) → прод-блоки header-full → там 0.60 овер-мерджит. **Нельзя менять
   дефолт порога отдельно от re-embed** — только одним деплоем. Поэтому сид НЕ трогал.
3. **fail-open маскирует поломку.** verify «работал» (черты промоутились), но не верифицировал ничего —
   тихая деградация. Любой fail-open обязан логировать сырой ответ + метрику.
4. **Идемпотентность ≠ конкурентная безопасность.** «Проверь, есть ли уже» не спасает от гонки —
   нужен retry на unique-violation или атомарный аллокатор.
5. **Стенд ловит то, чего не ловят типы/тесты** — регрессию про ДАННЫЕ и эмбеддинги. Дисциплина
   «пере-подготовил под новый код → прогнал → замерил» окупилась.

## Открыто (в baseline / бэклог)

- **Сопряжённая миграция порог↔re-embed на проде** — owner-gate: подтвердить состояние эмбеддинга
  прод-блоков, спланировать совместный деплой.
- **Не все клоны переходят планку сборки** (3/5 person, 2/4 role) — часть профилей 2–4 черты.
- **motivation-слой = 0** — мульти-детектор не рождает motivation (пробел ещё с 2026-07-03).
- **Порог 0.60 «достаточен», не «оптимизирован»** — до прод-выката sweep 0.58–0.65 + проверка, что не
  сливает разные методы.
- Далее по дорожной карте: Фаза 0б (Канал Б) → Слой 0 фиделити → раннер → судьи → BASELINE → ТЗ-1.
