# Проекты и трекер

Встроенный таск-трекер Коры — это проекты, доски, задачи, циклы и календарь в одном месте. Каждое событие трекера попадает в граф знаний наравне со встречами: задача привязана к клиенту, решению, человеку. Через полгода можно спросить «что мы делали по проекту Кейс-1» — Кора покажет и задачи, и встречи, и решения.

## Что Кора делает за вас

- Сама связывает задачи с встречами, клиентами, решениями и документами.
- Сама извлекает задачи из встреч и добавляет в бэклог проекта.
- Сама показывает загрузку команды — кто перегружен, кто свободен.
- Сама принимает задачи по email (если включён email-to-task).
- Сама обновляет прогресс спринта в реальном времени без перезагрузки.
- Сама предлагает AI-подсказки по ходу спринта — что идёт хорошо, что блокирует, что рискует не успеть.

## Что вы делаете сами

- Создаёте проект и настраиваете доску (статусы, приоритеты).
- Создаёте задачи руками или подтверждаете извлечённые из встреч.
- Перетаскиваете задачи по колонкам канбана.
- Привязываете задачу к встрече или документам.
- Работаете в удобном виде: доска, список, календарь или Гант.

## Где найти трекер

| Что | URL | Описание |
|---|---|---|
| Список проектов | `/projects` | Все проекты компании с фильтрами и поиском |
| Создать проект | `/projects/new` | Мастер создания проекта |
| Проект | `/projects/[slug]` | Master-detail: навигация слева, содержимое справа |
| Мои задачи | `/tasks` | Все задачи, назначенные на вас, из всех проектов |
| Мои входящие | `/me/inbox` | Входящие задачи с курсорной пагинацией и бейджем |
| Мои @упоминания | `/me/mentions` | Лента, где вас упомянули в комментариях и задачах |

## Проект — рабочее пространство команды

Проект — это отдельное рабочее пространство: свой набор досок, бэклог, участники, документы, настройки. Проект может быть привязан к клиенту, отделу или быть внутренним.

### Вкладки проекта

После открытия проекта (`/projects/[slug]`) доступны следующие вкладки:

| Вкладка | URL | Что показывает |
|---|---|---|
| **Обзор** | `/projects/[slug]/overview` | Общая картина: прогресс, ключевые метрики, участники, последние события |
| **Доска** | `/projects/[slug]/board` | Канбан-доска: колонки по статусам задач, перетаскивание |
| **Список** | `/projects/[slug]/list` | Плоский список задач с фильтрами: статус, приоритет, назначенный, метка, цикл |
| **Календарь** | `/projects/[slug]/calendar` | Задачи на месячной сетке по датам |
| **Гант** | `/projects/[slug]/gantt` | Временная шкала задач с зависимостями |
| **Циклы** | `/projects/[slug]/cycles` | Итерации проекта (аналог спринтов внутри проекта) |
| **Документы** | `/projects/[slug]/documents` | Документация проекта |
| **Intake** | `/projects/[slug]/intake` | Входящие заявки и идеи для оценки |
| **Нагрузка** | `/projects/[slug]/workload` | Загрузка участников по времени |
| **Интеграции** | `/projects/[slug]/integrations` | Подключения внешних систем |
| **Настройки** | `/projects/[slug]/settings` | Участники, статусы, приоритеты, email-inbox |

### Несколько досок в проекте

Проект может иметь несколько досок. Каждая доска доступна по отдельному URL:

| Вид доски | URL |
|---|---|
| Канбан | `/projects/[slug]/boards/[boardId]/board` |
| Список | `/projects/[slug]/boards/[boardId]/list` |
| Календарь | `/projects/[slug]/boards/[boardId]/calendar` |

Это полезно, когда в одном проекте работают несколько команд или направлений — у каждого своя доска.

## Задача — единица работы

Задача (Issue) — конкретная единица работы. У задачи есть:

- **Название** — короткое описание.
- **Описание** — подробности, контекст, acceptance criteria.
- **Статус** — Backlog / Todo / In Progress / In Review / Done / Cancelled (или свои).
- **Приоритет** — Urgent / High / Medium / Low / No priority.
- **Назначенный** — кто делает.
- **Цикл** — к какой итерации относится.
- **Метки** — теги для фильтрации.
- **Подзадачи** — чек-лист или вложенные задачи.
- **Комментарии** — обсуждение внутри задачи.
- **Активность** — лог изменений (кто что поменял и когда).
- **Версии** — история изменений описания.
- **Чат задачи** — обсуждение в формате чата (scope='issue').

### Карточка задачи (`/issues/[id]`)

Страница задачи — master-detail:

- **Description** — описание и чек-листы.
- **IssueComments** — комментарии с поддержкой @упоминаний.
- **Activity** — лог действий.
- **Versions** — история изменений описания (можно сравнить версии).
- **IssueChat** — чат, привязанный к задаче.

### Быстрое добавление задач

Компонент QuickAdd позволяет создать задачу прямо на доске или в списке — без открытия полной формы. Вводите название, нажимаете Enter — задача создана в нужном статусе.

### Связь задач с встречами

Задача может быть привязана к встрече. Это работает в обе стороны:

- **Из встречи** — Кора извлекает задачи (action items) и предлагает добавить в бэклог.
- **Из задачи** — можно вручную привязать встречу через поле «Связанные встречи».

На странице задачи видно, из какой встречи она появилась, и можно перейти к записи и AI-отчёту.

## Циклы — итерации внутри проекта

Цикл (Cycle) — это итерация внутри проекта, аналог спринта. У цикла есть даты начала и окончания, набор задач и прогресс.

| URL | Что показывает |
|---|---|
| `/projects/[slug]/cycles` | Список всех циклов проекта |
| `/projects/[slug]/cycles/[cycleId]` | Детали конкретного цикла: задачи, прогресс, burndown |

Циклы помогают планировать работу по неделям или двухнедельным спринтам. В конце цикла видно, сколько задач завершено, сколько перенесено.

> **Цикл vs Спринт.** Цикл — итерация внутри одного проекта. Спринт (`/sprints`) — рабочий цикл команды, объединяющий задачи из нескольких проектов. Подробнее — [Спринты](./13-sprints.md).

## Мои задачи (`/tasks`)

Личная страница: все задачи, назначенные на вас, из всех проектов. Группировка:

| Группа | Что включает |
|---|---|
| **Просрочено** | Задачи с прошедшим дедлайном |
| **Сегодня** | Задачи на сегодня |
| **На неделе** | Задачи на текущую неделю |
| **Позже** | Задачи с будущим дедлайном |
| **Без срока** | Задачи без даты |

Это единая точка, где видно всё, что на вас висит. Не нужно заходить в каждый проект отдельно.

### Мои входящие (`/me/inbox`)

Входящие задачи с курсорной пагинацией и бейджем-счётчиком в боковом меню. Сюда попадают задачи, которые были назначены на вас или перенаправлены через Intake.

### Мои @упоминания (`/me/mentions`)

Лента всех мест, где вас упомянули: комментарии к задачам, обсуждения,probe-вопросы. Удобно отслеживать, когда вас зовут в разговор.

---

## Intake — триаж входящих задач

Intake (`/projects/[slug]/intake` или `/intake` для owner/admin) — очередь входящих задач с AI-подсказками по маршрутизации.

Как работает:

1. Задача попадает в Intake (из email, из встречи, из Telegram-сообщения).
2. Кора анализирует содержание и предлагает: в какой проект, какой приоритет, кто должен делать.
3. Вы подтверждаете, меняете или отклоняете.
4. Задача уходит в бэклог нужного проекта.

Для owner/admin пункт «Входящие» в боковом меню показывает **общую** триаж-очередь по всей компании с живым бейджем количества pending-карточек.

## Email-to-task — задачи по email

Каждый проект может иметь свой email-адрес для создания задач. Пишете на `project-alias@...` — Кора создаёт задачу в проекте.

### Настройка

`/projects/[slug]/settings` → секция «Email-в-задачу»:

1. **Включить** переключатель «Принимать задачи по email».
2. Система генерирует `emailInboxAlias` и показывает полный адрес (например `kayrus@inbox.kora.ru`).
3. **Копировать** адрес одной кнопкой.
4. **Сгенерировать новый адрес** — старый перестаёт работать (для безопасности).
5. **Превью последних 10 писем** с бейджами статуса:

| Статус | Что значит |
|---|---|
| `routed` | Письмо успешно превращено в задачу |
| `duplicate` | Такая задача уже существует |
| `rejected` | Письмо отклонено (спам, не по формату) |
| `failed` | Ошибка обработки |

### Зачем

- Клиент пишет на email — задача автоматически создаётся.
- Коллега пересылает письмо с просьбой — задача появляется в бэклоге.
- Не нужно переключаться между email и трекером.

## Виды отображения задач

Кора даёт четыре взгляда на одни и те же задачи. Переключайтесь между ними в зависимости от того, что удобнее сейчас.

### Доска (Канбан)

Колонки по статусам. Перетаскивание задач между колонками. На десктопе — полноразмерная доска, на мобильном — горизонтальная прокрутка.

Подходит для: ежедневной работы, stand-up, визуального контроля.

### Список

Плоский список с фильтрами: статус, приоритет, назначенный, метка, цикл. Сортировка по любому полю.

Подходит для: массовых операций, поиска конкретной задачи, экспорта.

### Календарь

Задачи на месячной сетке по датам. Видны дедлайны и диапазоны.

Подходит для: планирования недели, оценки загрузки, поиска конфликтов дат.

### Диаграмма Ганта

Временная шкала задач с зависимостями. Видно, какая задача блокирует другую.

Подходит для: долгосрочного планирования, выявления критического пути, презентации стейкхолдерам.

---

## Загрузка команды (`/projects/[slug]/workload`)

Визуализация того, сколько задач у каждого участника и на какой период. Помогает:

- Заметить, что Иванов перегружен (15 задач на неделе), а Петров свободен.
- Распределить новые задачи равномерно.
- Обосновать найм нового сотрудника.

---

## Документы проекта (`/projects/[slug]/documents`)

Вики-документация, привязанная к проекту. Загружайте ТЗ, спецификации, протоколы — они связываются с задачами и встречами проекта.

Клик на конкретный документ (`/projects/[slug]/documents/[docId]`) — полная страница документа с историей версий.

---

## Интеграции проекта (`/projects/[slug]/integrations`)

Подключение внешних систем к конкретному проекту: Bitrix24, amoCRM, вебхуки. Каждая интеграция настраивается отдельно для каждого проекта.

---

## Связь трекера с графом знаний

Это то, что отличает трекер Коры от обычного Jira или Linear. Каждое событие трекера попадает в граф знаний:

- **Задача создана** → связывается с проектом, назначенным, циклом, клиентом.
- **Задача привязана к встрече** → связь «эта задача появилась из этой встречи».
- **Задача завершена** → факт «N сделал X к дате Y» попадает в память.
- **Комментарий с @упоминанием** → упоминание фиксируется и связывается с человеком.

Через несколько месяцев можно спросить консьержа: «что мы делали по проекту Кейс-1 за последний квартал» — и получить полную картину из задач, встреч и решений.

## Мобильная адаптация

На мобильных устройствах:

- Доска превращается в вертикальный список с горизонтальной прокруткой колонок.
- Нижняя навигация (`TrackerBottomNav`) для быстрого переключения между вкладками.
- Pill-фильтры со скроллом по горизонтали.
- Карточка задачи — полноэкранный вид с кнопкой «назад».

## Что попробовать

- Создайте проект и настройте доску под свой процесс (добавьте свои статусы).
- Включите email-to-task и попросите клиента написать на email проекта — посмотрите, как задача появится в бэклоге.
- Откройте «Нагрузку» перед планированием спринта — увидите, кому можно дать задачи, а кому хватит.
- Привяжите задачу к встрече и через месяц посмотрите, как собралась история работы.
- Используйте Гант для проекта с зависимостями — видно критический путь.

## Что нельзя

- Нельзя удалить проект без подтверждения владельца (soft-delete с grace-периодом).
- Нельзя перенести задачу в проект, к которому у вас нет доступа.
- Нельзя видеть задачи конфиденциального проекта, если вас в нём нет.
- Нельзя удалить задачу задним числом из чужого отчёта — все действия логируются.
