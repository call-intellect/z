## Главное мета-решение (и урок)
**Отложил §2 Telegram / §3 probe / §4 chat сознательно**, хотя мандат был «всё». Причина: это правки production-критичных потоков (роутинг бота, доставка уведомлений, стриминг чата), которые **нельзя прогнать вживую без инфры** (Docker не поднят, нет доступа к боту/LLM/прод-БД в сессии). Менять их вслепую = риск сломать работающий прод — это прямо противоречит принципу «доказывай, не угадывай / поведение фреймворка проверяй эмпирически».
**Урок:** «реализуй всё» ≠ «выкати непроверяемое вслепую». Лучше отдать честный список отложенного с причиной, чем закрасить риск. Безопасно-проверяемое (typecheck/build/spec) выкатил; прод-чувствительное передал с точными заметками до поднятия dev-стека.

## Инженерные грабли (кандидаты в code-pitfalls)
- **Смена семантики чтения вскрывает host-only дыры:** перевод `getForUser` (owner-only → `canView`) молча открыл мутации, которые гейтили хоста ЧЕРЕЗ этот метод (`renameParticipant`/`setClosedGroupKind`/`retry-ai`). Всегда грепать ВСЕ вызовы метода, чью семантику меняешь. Закрыто `assertMeetingHost`.
- **`tsconfig` не покрывает `backend/scripts/**`** (только `scripts/demo-data/**`) → backfill/patch-скрипты НЕ проверяются `bun run typecheck`; валидируются spec + runtime (vitest-транспиляция). «typecheck зелёный» для скрипта неинформативен.
- **`bun run build` = `tsc`, не Nest-bootstrap** → DI-граф вживую не инстанцирует. Новые инъекции проверять логикой (@Global + @Optional/forwardRef против цикла), не «build прошёл».
- **Prisma `mode:'insensitive'` для `equals` = ILIKE** → `_`/`%` трактуются как wildcards (в email `chydo_002@…` есть `_`). Для точного сравнения по индексу `lower(email)` — `$queryRaw lower()`.
- **Миграцию можно сгенерировать offline** без БД: `prisma migrate diff --from-schema <старая> --to-schema <новая> --script` (Prisma 7 переименовал флаги с `--from-schema-datamodel`).
- **Конвенция backfill/patch в репо: дефолт dry-run, запись `--apply`** (агрегатор `apply-prod-deploy` так и вызывает). ТЗ может ошибаться — сверяй с STEPS.
