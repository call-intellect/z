# TEAMLY — разбор онбординга и tips-системы

> **Контекст:** живой проход регистрации на svmazur.teamly.ru (2026-05-27). Зафиксировал flow, чтобы потом обсудить, какие паттерны применимы к онбордингу Z/Коры.
>
> Бизнес/финансы/позиционирование TEAMLY — в [competitor-teamly.md](competitor-teamly.md).

---

## 📋 Структура онбординга (10+ шагов)

Линейный flow с прогресс-индикатором ("1 из 10", "2 из 10" — пронумерованные подсказки уже внутри интерфейса).

### Шаг 1: Welcome Screen
- **Заголовок:** «Добро пожаловать в TEAMLY! 👋»
- **Подтекст:** «Рады видеть вас среди пользователей нашего продукта. Давайте настроим пространство под ваши задачи — это займет всего пару минут.»
- **CTA:** кнопка «Начать»
- **Визуал:** фиолетовый gradient + cute mascot (персонаж-помощник)

### Шаг 2: Контекст использования
**Вопрос:** «Как вы планируете использовать продукт?»

Три взаимоисключающих варианта:
- 🏢 Для компании
- 👥 Для отдела
- 👤 Для себя

**Важно:** этот выбор определяет весь дальнейший flow — разные user journeys для каждого варианта.

### Шаг 3: Название организации
- **Вопрос:** «Ваша компания»
- **Поле:** текстовый input с лимитом
- **Counter:** «3 / 250» (видимый счётчик символов)
- **Подтекст:** «Введите название организации, в которой вы работаете»

### Шаг 4: Выбор отдела (множественный)
**Вопрос:** «Ваш отдел»
**Подтекст:** «Выберите ваш отдел для более релевантного контента»

**Опции:**
- 🏢 Вся компания
- 👨‍💼 HR — отдел
- 💻 IT — отдел
- 🎧 Поддержка
- 📊 Маркетинг
- 💼 Продажи
- 📋 Проектный офис
- ⋯ Другое

*Примечание:* «*Выберите несколько вариантов» — явно разрешены мульти-селекты.

### Шаг 5: Use Cases (сценарии использования, множественный выбор)
**Вопрос:** «Для чего вы хотите использовать TEAMLY?»
**Подтекст:** «Расскажите, что именно хотите организировать — мы подберем для вас лучший сценарий работы!»

**Опции:**
- 📖 База знаний компании
- 🎓 Обучение и онбординг сотрудников
- 📝 Управление проектами и задачами
- 💬 Совместная работа и коммуникация

### Шаг 6: Размер команды
**Вопрос:** «Сколько сотрудников у вас в компании?»
**Подтекст:** «Предложим оптимальные варианты приглашения пользователей и настройки прав доступа.»

**Опции (single select):** 5-50 / 51-100 / 101-200 / 201-300 / 301-400 / 400+

### Шаг 7: Предложение обучения
**Вопрос:** «Хотите быстро разобраться в TEAMLY?»
- Да, хочу освоить продукт быстрее, запишите на встречу!
- Нет, разберусь в своем темпе.

**Тут sales-funnel:** «Да» = заявка на демо/обучение → передача в продажи.

## 🎨 UI/UX паттерны

### Color & Style
- **Primary:** фиолетовый gradient (~RGB 120, 90, 230)
- **Background:** тёмная тема, белый текст на фиолетовом
- **Buttons:** скруглённые, solid-fill
- **Modals:** с полупрозрачным оверлеем; tip-popup без оверлея, но с подсветкой целевого элемента (border + glow)

### Компоненты
- **Input field:** dark background, скруглённые углы, character counter справа
- **Buttons:**
  - Primary («Далее», «Начать»): solid фиолетовый
  - Secondary («Назад»): outline/ghost
- **Selectors:** grid из карточек, каждая = иконка + текст; чётко видно, single или multi
- **Icons:** простые, моноцветные, встроены в карточки/кнопки
- **Mascot:** один персонаж-помощник проходит через всю воронку (большой на welcome → маленький в углу прогресс-бара)

### Navigation
- **Sidebar слева:** иерархия пространств → папок → страниц
- **Back button:** «← Назад» в топе правой панели
- **Breadcrumbs:** «Список пространств / Стартовое пространство»
- **Прогресс-бар:** тонкая полоса внизу левой панели, по ней «идёт» маскот

### Onboarding tips (привязанные к UI)
- **Position:** float рядом с целевым элементом, со стрелкой
- **Size:** ~400px width
- **Progress indicator:** «N из 10» в топ-центре
- **Кнопки:** «Назад» + «Далее» (на последнем — «Завершить»)
- **Закрытие:** крестик в углу — пропустить остаток

## 🏗️ Архитектурные решения

### Персонализация через профиль
**Цель:** адаптировать контент и рекомендации по ответам.
- **Контекст** (компания/отдел/личное) → разные user journeys
- **Use cases** → шаблоны и рекомендуемые workflows
- **Team size** → настройки приглашения и прав
- **Department** → фильтр для релевантного контента в стартовом пространстве

### Progressive disclosure
1. Минимум на старте (контекст + имя)
2. Уточняющие вопросы (отдел, use cases, размер)
3. Sales-фильтр («хотите обучение?») → если да, лид в продажи
4. Контекстные tips в самом приложении (не отдельный гайд, а 10 точечных подсказок)
5. Bonus-payload в конце для retention/upsell

### Sales & retention механики
- **Прогресс-индикатор** «N из 10» создаёт ощущение завершимости — мотивирует дойти до конца
- **Bonus после онбординга:** +1 мес тарифа, +1000 AI-запросов, PDF-гайды
- **Срочность:** «акция действует ограниченное время»
- **Параллельный pop-up:** скидка с дедлайном (1 июня)

## 💡 Что взять для Z/Коры

### Применимо
1. **Прогресс «N из 10» с маскотом по полосе** — сильный паттерн доводки до конца. У Z маскота нет, но можно сделать индикатор.
2. **Tips, привязанные к UI с подсветкой** — лучше большого «тура»: короткие, в момент, можно пропустить.
3. **Multi-select для use cases при создании Org** — у нас 9 типов встреч; можно при онбординге спросить «какие типы будете чаще всего проводить» и преднастроить шаблоны AI-отчётов.
4. **Размер команды → рекомендации тарифа/лимитов** — естественный квалификатор.
5. **Sales-фильтр «Хотите обучение?»** — лид-механика без агрессии.
6. **Bonus после онбординга** — retention-крюк (для Z это могли бы быть бонусные AI-минуты транскрибации/часы записи).

### Конфликтует с архитектурой Z
- **«Для компании / отдела / себя»** — у Z первичны Org + Host/Guest, личного режима нет.
- **«База знаний» как первичный use case** — у Z это вторичный output, primary = AI-отчёты по встречам и память компании.
- **Стартовое пространство с учебными статьями** — Z скорее покажет демо-встречу с AI-отчётом, а не статьи о том, как создать статью.
- **Department-фильтр контента** — для Z неактуален, отделы не первичная сущность.

### Спорные паттерны
- **Mascot** — у Z пока нет персонажа. Решение брендовое, не UX.
- **Многошаговый wizard на 10 вопросов до первой ценности** — может оттолкнуть. Z (память компании) скорее должна минимизировать setup и сразу дать «попробовать AI-отчёт».

## 📌 К обсуждению с владельцем

- [ ] Нужен ли нам прогрессивный wizard или хватит 2-3 шагов до первой встречи?
- [ ] Делаем ли мы tips, привязанные к UI с подсветкой (или достаточно empty-states + tooltips)?
- [ ] Брать ли паттерн «выбери use cases» для преднастройки AI-шаблонов отчётов по типу встречи?
- [ ] Bonus-механика после онбординга — делаем? Что давать (AI-минуты? часы хранения?)?
- [ ] Sales-фильтр «хотите обучение/демо» в онбординге — нужен на текущей стадии или после GA?
