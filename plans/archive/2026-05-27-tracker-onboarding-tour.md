# Onboarding-тур

## TL;DR

При первом входе пользователь получает короткий тур-знакомство: серия всплывающих подсказок поверх UI, по 10-15 секунд на каждую. Тур запускается автоматически после регистрации, **скрывается навсегда** по кнопке «Пропустить» или «Понятно». Прогресс хранится на сервере (в `User.tourProgress Json`) — если зашёл с другого устройства, тур не повторяется. Срок: 1 человеко-неделя.

## Зачем

Без тура новый пользователь видит сложный интерфейс с 12+ разделами и не понимает с чего начать. У Weeek (на скриншоте) — карточка «Аккаунт... Дальше» — это часть их onboarding. Без аналога мы теряем пользователей на первой минуте.

Тур запускается **после** того, как paritет с конкурентами достигнут (см. зонтик) — иначе будем показывать фичи, которых ещё нет.

## Сценарии туров

### Тур №1: «Знакомство при первом входе»

**Триггер:** `User.tourProgress.welcome === undefined` после первой регистрации (или явный запрос «показать тур» в настройках).

**Шаги (8 подсказок поверх главной страницы):**

1. **Логотип/название** — «Привет! Это Кора — память вашей компании. Покажу основные разделы за 90 секунд.» Кнопки: «Поехали» / «Пропустить»
2. **Левая панель — Главная** — «Ваш дашборд: что важно сегодня»
3. **Встречи** — «Все встречи с записью и AI-отчётом. Можно стартовать видеовстречу прямо отсюда»
4. **Карточки** — «CRM-карточки клиентов и сделок. Встречи привязываются к карточке»
5. **Проекты** — «Задачи команды: доски, циклы, исполнители»
6. **Входящие** — «Сюда падают задачи, в которых вас отметили или назначили»
7. **Помощник компании** — «AI-чат, который знает всё из встреч и решений компании»
8. **Концьерж (плавающий значок)** — «Здесь можно задать любой вопрос: создать задачу, найти встречу, написать в чат» Кнопка: «Готово»

После завершения — `PATCH /users/me/tour-progress` с `{ welcome: { completedAt: now } }`.

### Тур №2: «Знакомство с проектом» (при первом открытии проекта)

**Триггер:** `User.tourProgress.project === undefined` при первом переходе на `/projects/[slug]/*`.

**Шаги (5 подсказок):**

1. **Вкладка «Обзор»** — «Пульс проекта одним взглядом»
2. **Боковая панель досок** — «Несколько досок в одном проекте. Создайте доску для каждого направления»
3. **Канбан** — «Перетащите задачу между колонками, чтобы сменить статус»
4. **Кнопка «+ Задача» в колонке** — «Введите название и нажмите Enter. Без модалок»
5. **Концьерж** — «Скажите словами: ‘создай задачу для Иванова на завтра по объекту Тверская’ — Кора разберёт»

### Тур №3: «Знакомство со встречей» (при первой созданной встрече)

**Триггер:** после `meeting.completed` первой встречи пользователя, при следующем открытии `/m/[id]`.

**Шаги (4 подсказки):**

1. **Транскрипт** — «Полная запись с тайм-кодами и разделением по спикерам»
2. **AI-отчёт** — «Кратко: что обсудили, какие решения, какие задачи»
3. **Извлечённые задачи** — «AI нашёл N действий. Подтвердите — попадут в Входящие»
4. **Привязка к карточке** — «Прикрепите встречу к карточке клиента, чтобы вся история была в одном месте»

## Модель данных

### Расширение `User`

```prisma
model User {
  // ... существующие поля
  tourProgress  Json    @default("{}")
  // Структура: { welcome?: { completedAt, skipped? }, project?: { ... }, meeting?: { ... } }
}
```

`Json` потому что туров может стать больше, не хочется городить отдельную таблицу для key-value на пользователе.

## REST API

```
GET  /api/v1/users/me/tour-progress              # возвращает Json
PATCH /api/v1/users/me/tour-progress             # merge { tourId: { completedAt, skipped? } }
POST /api/v1/users/me/tour-progress/reset         # для админа / debug — обнуляет все туры
```

## DTO (Zod)

```ts
export const UpdateTourProgressSchema = z.object({
  tourId: z.enum(['welcome', 'project', 'meeting']),
  completedAt: z.string().datetime().optional(),  // если undefined — отмечается как started
  skipped: z.boolean().optional(),
}).strict();
```

## Frontend

### Библиотека

**Решение:** свой компонент, не сторонняя библиотека.

Обоснование:
- `react-joyride`, `intro.js`, `shepherd.js` — все имеют тяжёлый CSS, плохо ложатся на наш Tailwind + dark-first + mint
- Нужен полный контроль над focus-trap, accessible-attributes, mobile-адаптацией
- Логика тура — простая: «показать подсказку → ждать клик → следующая»

### Компоненты

`frontend/src/ui/tour/`:
- `TourProvider.tsx` — Context: текущий tour, текущий step, методы `next/prev/skip/complete`
- `TourTooltip.tsx` — позиционированный popover поверх target-элемента (через `@floating-ui/react`)
- `TourBackdrop.tsx` — полупрозрачный overlay с «вырезом» вокруг target
- `useTour(tourId)` — хук, который читает `tourProgress`, авто-запускает если `undefined`

### Регистрация целевых элементов

Target определяется через `data-tour-target="welcome.step-1"`. На странице:

```tsx
<aside data-tour-target="welcome.sidebar-meetings">
  {/* sidebar */}
</aside>
```

`TourProvider` через `document.querySelector('[data-tour-target="..."]')` находит элемент.

### Тур-объявления

`frontend/src/ui/tour/tours/welcome.ts`:

```ts
export const welcomeTour: TourDefinition = {
  id: 'welcome',
  steps: [
    {
      id: 'logo',
      target: '[data-tour-target="welcome.logo"]',
      title: 'Привет! Это Кора',
      body: 'Память вашей компании. Покажу основные разделы за 90 секунд.',
      placement: 'right',
      primaryAction: { label: 'Поехали', kind: 'next' },
      secondaryAction: { label: 'Пропустить', kind: 'skip' },
    },
    // ... остальные шаги
  ],
};
```

### Логика автозапуска

В `app/(authenticated)/layout.tsx` — провайдер `<TourProvider>`. На каждой странице, где есть тур (welcome для главной, project для projects), компонент-обёртка вызывает `useTour('welcome')`. Если `tourProgress.welcome === undefined` — запускается.

### Mobile

Подсказки — full-width bottom-sheet (как dialog), а не позиционированные tooltips (на мобиле tooltip может вылезти за экран).

## Доступность

- ESC закрывает тур (== Skip)
- Tab — фокус на «Дальше/Пропустить»
- `aria-live="polite"` на текущем шаге
- `aria-label="Тур: шаг N из M"` на компоненте

## Локализация

| Английский | Русский |
|---|---|
| Got it | Понятно |
| Next | Дальше |
| Skip | Пропустить |
| Tour | Знакомство |
| Show tour again | Показать знакомство снова |

В настройках пользователя (`/me/settings`) — пункт «Показать тур заново» (вызывает `reset` и стартует тур).

## Метрики Prometheus

```
tour_started_total{tenant, tour_id}
tour_completed_total{tenant, tour_id}
tour_skipped_total{tenant, tour_id, at_step}
```

## Knowledge-core

Тур — это организационная фича, в knowledge-core ничего не идёт.

## Что НЕ делаем

- A/B тестирование разных тур-сценариев — отложено
- Адаптивные туры (показывать разные подсказки в зависимости от роли) — пока один тур для всех. Если будет нужно — расширим `tourProgress` под роль
- Видео-туториалы — отдельный формат, не сейчас
- Тур для администратора (admin-панель) — отдельный ТЗ
- Контекстные подсказки «вы 30 секунд смотрите на пустую страницу, может показать что делать» — не сейчас
