# Orchestrator-prompt — видеовстречи: фикс багов + редизайн просмотра/журнала

Запусти как `tz-orchestrator`. Веди реализацию **двух ТЗ** фаза за фазой силами суб-агентов, с независимой приёмкой (греп / re-Read / свой typecheck-lint-build) и коммитом по фазам. Push — только по явному подтверждению владельца.

## Что читать на старте (в этом порядке)
1. `CLAUDE.md` (корень) и `.claude/CLAUDE.md` — инварианты, Ship-On (принцип 8), правила git/коммитов, vexp-политика.
2. `second-brain/index.md` → `second-brain/01_projects/frontend-pages.md` (если есть) — текущее описание экранов встреч.
3. **ТЗ-1 (баги):** `plans/tz/2026-06-17-meeting-room-three-bugs-fix.md` — 3 фазы, `meeting-room/`.
4. **ТЗ-2 (редизайн):** `plans/tz/2026-06-17-meeting-review-and-journal-redesign.md` — 5 фаз, `meeting-result-v2/` + `meetings-journal/`.
5. Код-якоря из REALITY-CHECK каждого ТЗ — **перечитать перед правкой** (номера строк дрейфуют; искать по символам/классам, указанным в ТЗ).

## Инструменты
- **vexp в этой среде НЕ поднят** (ToolSearch не находит `run_pipeline`). Используй обычные `Grep`/`Glob`/`Read` — PreToolUse-хук их НЕ блокирует, пока демон не запущен. Если демон поднимется — переключись на `run_pipeline`/`get_skeleton`.
- **Context7** при сомнениях по API `@livekit/components-react` / `livekit-client` (TrackToggle `captureOptions`/`publishOptions`, `ScreenSharePresets`, `ScreenShareCaptureOptions.contentHint`) — но в ТЗ-1 эти контракты уже проверены по исходнику `node_modules`.

## Порядок фаз (граф)
Файлы двух ТЗ **не пересекаются** — но веди последовательно, по одной волне на фазу:

**Волна A (ТЗ-1, баги — быстрые, независимые между собой):**
- A1 = ТЗ-1 Ф1 (чат: убрать кастомный topic + мёртвый `TOPIC_PREFIX`).
- A2 = ТЗ-1 Ф2 (`object-fit: contain` на сетку: `kora-video-grid` + правило в `globals.css`).
- A3 = ТЗ-1 Ф3 (`contentHint:'detail'` + `screenShareEncoding` на `<TrackToggle>` экрана).

**Волна B (ТЗ-2, редизайн — строго по порядку, общий файл `MeetingResultPageReal.tsx`):**
- B1 = ТЗ-2 Ф1 (журнал: убрать `md:opacity-0` + статус-чип через `meetingStatusView`). Независима, можно и первой.
- B2 = ТЗ-2 Ф2 (sticky-компакт плеер + сворачивание).
- B3 = ТЗ-2 Ф3 (отчёт inline без `Modal`; удалить `ReportDetailDialog`/`max-h-[60vh]`).
- B4 = ТЗ-2 Ф4 (сворачиваемая колонка AI-чата; условный грид).
- B5 = ТЗ-2 Ф5 (URL-sync `?tab=`/`?report=`).

Внутри волны B соблюдай порядок B2→B3→B4→B5 (один файл — избегаем конфликтов). B1 можно вынести вперёд.

## Факт-чек (НЕ верь отчёту суб-агента)
Память проекта: суб-агент иногда отмечает `[x]` без реальных правок. После КАЖДОЙ фазы — независимая приёмка:
- **Грепни маркеры** из секции Acceptance соответствующей фазы (точные строки приведены в ТЗ): например по ТЗ-1 Ф1 — что `topic:` и `TOPIC_PREFIX` исчезли; по ТЗ-2 Ф3 — что `ReportDetailDialog` и `max-h-[60vh]` исчезли, а `ReportOutputRenderer` рендерится вне `Modal`.
- **re-Read** изменённые участки — глазами, а не по слову агента.
- **Свой прогон** из `frontend/`: `bun run typecheck` (вкл. `.spec`), `bun run lint`, `bun run build` — все зелёные. Без этого фаза НЕ закрыта.
- Проверь `git status` — никаких чужих/несвязанных файлов в индексе (только пути этой фазы). Никогда `git add .`/`-A`.

## Определение «фаза закрыта»
Все Acceptance-предикаты фазы выполнены (грепаемые маркеры + зелёные typecheck/lint/build) И ручной сценарий из Acceptance воспроизведён или явно помечен как требующий живой приёмки (живой комнаты / 2+ участников — для ТЗ-1; qa-tester по `/meetings` и `/meetings/<id>/result` — для ТЗ-2). Тогда — коммит фазы (`fix(meeting-room): ...` / `feat(meetings): ...` / `refactor(meeting-result): ...`).

## Инварианты, которые легко нарушить (следи)
- **UI только по-русски**, ни одного английского слова в подписях/aria; парные токены `bg-{c}`+`text-{c}-fg`, **никогда** `text-white`/жёсткий hex/`slate-` (`feedback_paired_color_tokens`).
- **Ship-On:** оба ТЗ выкатываются БЕЗ флага (Р1/Р6). Не вводи флаг «на всякий», не оставляй старую модалку параллельно новому inline (Р6).
- **LiveKit — только медиа:** не трогай токены/permissions/серверный конфиг (ТЗ-1 Граничные контракты). Simulcast экрана НЕ отключать (ТЗ-1 Р3).
- **Backend не трогаем** ни в одном ТЗ (кнопка удаления уже есть на бэке).

## Failure-modes (если застрял)
- ТЗ-1 Ф3: если TS ругается на тип `contentHint: 'detail'` — взять литеральный тип из `ScreenShareCaptureOptions` (livekit-client), не кастовать `as any`.
- ТЗ-2 Ф5: `useSearchParams` в App Router требует `Suspense`-границы — если падает пререндер, оберни/проверь, что компонент клиентский; `router.replace` с guard на равенство значений, иначе цикл ре-рендера.
- ТЗ-2 Ф3: после удаления `ReportDetailDialog` грепни весь `meeting-result-v2/` — не осталось ли импортов/использований; не сломай `AddReportDialog` (его `Modal` оставляем — это форма выбора шаблона, не просмотр отчёта).
- Если REALITY-CHECK ТЗ разошёлся с кодом (строки уехали, символ переименован) — приоритет у реального кода; зафиксируй расхождение в Итоге ТЗ, не угадывай.
