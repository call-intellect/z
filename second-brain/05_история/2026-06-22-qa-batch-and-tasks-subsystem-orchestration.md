# Как решал

- **Worktree-изоляция.** Вся работа в `c:\work\z-qa-tasks` (НЕ в основном `c:\work\z`) — параллельная сессия в общем каталоге могла бы утянуть коммиты (грабля известна по `project_morning_reminders_delivery_diagnosis`).
- **Порядок волн:** сначала QA-Ф1 (критичный транскрипт по видимости), затем блок A (создать+спросить+запомнить+срок) → C (прямая польза сотруднику: утром вижу задачи, пинок по незакрытым) → B (не терять задачи) → D (видимость руководителю + кроны по МСК) → финальный QA-свип (Ф2–Ф10). Внутри блока — по номеру фазы.
- **Суб-агенты-кодеры** по фазам; моя приёмка после каждой — typecheck (вкл. `.spec`), build, vitest по затронутым файлам + греп ключевых маркеров в коде (probe-reason, eventType, метрики, эндпоинт) до коммита.
- **Итог:** 25 коммитов, миграций Prisma нет (`schema.prisma` не менялся), новых ENV нет. 9 крутилок AdminSetting (5 kill-switch ON + 4 порога), 2 новых сид-скрипта + 2 расширенных (все в `apply-prod-deploy.ts` STEPS), 2 метрики, 1 eventType `issue.overdue`, 2 probe-reason `task.*`, 1 эндпоинт `GET /dashboard/stuck/cross-project`.

# Чему научился

- **`@Global` / явный импорт модуля для cross-module инъекции.** Probe должен исполнять ответ через трекер (`IssuesService.addAssignee`) → ProbeModule импортирует TrackerModule; без этого инъекция падает. Когда ответ на probe начинает «делать», а не только «спрашивать», границы модулей надо пересобирать.
- **Межкодерный typecheck-шум при параллельных кодерах в общем worktree.** Несколько суб-агентов в одном worktree временно ломают чужой typecheck (полуготовые файлы соседа) — приёмку фазы делать только после слияния фазы, а «красный» отделять `git stash`, чтобы не путать свой результат с чужим in-flight (перекликается с `feedback_orchestration_disjointness_and_full_status`).
- **read-union вместо дубль-записи для «не терять».** B2: переписочные `Task` показаны в триаже `/intake` объединением НА ЧТЕНИЕ, без дубль-записи в `Issue` — дешевле и безопаснее, полную унификацию хранилищ откладываем. Принцип «не терять ≠ дублировать».
- **probe как механизм дозапроса + обучения, а не только вопрос.** Связка «создать всегда → спросить недостающее → исполнить ответ → вывести правило `SubjectMemory` → в следующий раз не спрашивать» закрывает корень «молча угадывала» лучше, чем точечный фикс резолвера. Готовая «система обучения» (SubjectMemory) подведена к назначению задач.
- **Минимизация миграций.** B1 пометил низкое качество через существующий `suggestedPriority='low'` вместо новой колонки `IntakeIssue.lowQuality`; D4 закрыл «кроны по UTC» фиксированной `timeZone='Europe/Moscow'` вместо параметризуемого часа. Обе отсрочки явно вынесены в `04_не-сделано` как vNext.
