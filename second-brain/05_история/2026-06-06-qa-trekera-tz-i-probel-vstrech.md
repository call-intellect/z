## Что вышло (верифицировано)
- **Прод отстаёт от `sergdev`:** заголовки «— Z», детальные страницы трекера сломаны (`tables/[id]` → `/undefined` 404; `issues/[id]`/`sprints/[id]` → «не найдено» тихо), хотя в `sergdev` async-params + бренд уже починены (ТЗ-2 Фазы 1–2). → ТЗ-фаза «верифицировать+выкатить».
- **Реальный баг (не лаг деплоя):** «Принять» во Входящих → `POST /intake/:id/triage` `400 target_project_required` молча; у кнопки нет пикера проекта; бэк-DTO уже принимает `targetProjectId` → фикс фронтовый. Сверено логом сервера 05:08:49.
- **Структурные путаницы:** меню без группы «Задачи»; «Входящие» под тремя именами; Спринт=Цикл под двумя именами; «Архив спринтов» открывается как «Архив гипотез»; 10 подвкладок проекта; календарь спрятан внутри проекта.
- **Встречи:** у идущей встречи на платформе только «Открыть результат» — ни «Войти», ни «Скопировать ссылку», ни «Вернуться». В комнате «Ссылка» есть, но молчит (clipboard `NotAllowedError`). Бэкенд rejoin уже работает, ссылка `/m/{id}` детерминирована → ядро фронтовое; авто-приглашение после старта — 1 эндпоинт, переиспользующий `ParticipantPicker` + `deliverMeetingInvites`.
- Решения владельца зафиксированы в ТЗ (Р1–Р7): термин «Спринт», группа «Задачи», развести «Входящие», «Ещё ▾» для подвкладок; во встречах — ДВА способа допригласить (ручная ссылка + авто), и в детали, и в комнате; существующую авторассылку при создании НЕ трогать.

## Чему научился
- **Прод ≠ ветка.** Один и тот же баг может быть «жив на проде» и «починен в sergdev» одновременно — всегда различать «выкатить» vs «писать код». Якорь: заголовки «— Z» = индикатор старого билда на проде.
- **Тихие провалы хуже громких.** `issues/[id]`/`sprints/[id]` падали БЕЗ ошибок консоли и БЕЗ сетевых запросов (синхронный `params` → undefined → клиент не фетчит). Их легко принять за «пусто».
- **Один симптом ≠ один корень.** «Принять» 400 — это фронт (нет пикера), а не отсутствие бэк-возможности (DTO уже готов). Проверять контракт обеих сторон.
- **Shared git index при параллельных сессиях.** Параллельная Claude-сессия сделала `git commit` по общему индексу и подмела мои застейдженные файлы в свой коммит. Урок вынесен в `~/.claude/.../memory/feedback_parallel_sessions_git_check.md`: `git add`+`git commit` одной командой, минимизировать окно; в идеале — worktree на сессию.
