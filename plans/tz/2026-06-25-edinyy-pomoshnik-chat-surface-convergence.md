Поэтому — отдельным ТЗ с визуальной приёмкой, а не вслепую.

## 1bis. Решения владельца + добавленные разрывы (2026-06-27)

Подтверждено живой приёмкой прода (Playwright, аккаунт owner) — [`plans/analysis/2026-06-27-edinyy-master-chat-surface-state.md`](../analysis/2026-06-27-edinyy-master-chat-surface-state.md).

### Сняты развилки (владелец выбрал рекомендованные варианты):
1. **FAB** (обновлено 2026-06-27) — **заметная плавающая кнопка-шорткат, открывает СРАЗУ большое окно** `/chat` (дом Мастера), без промежуточного маленького поповера. Смысл — быстрый видимый переход, чтобы не искать вход в левом меню. Маленький виджет демонтируется целиком (одна поверхность вместо двух — проще в поддержке). Быстрый вопрос «не уходя со страницы» закрывается встроенными scoped-чатами (КФ3), не поповером FAB.
2. **Режим** — **один переключатель собеседника+скоупа** наверху дома: «Помощник компании (общий разбор) | Клон роли | по встрече/задаче (scope)». Снять раздельные вкладки FAB и отдельный `AssistantTargetSelect` chat-v2 — свести в один контрол. У каждого режима свои диалоги в левом списке (скоуп в карточке диалога уже есть).
3. **Объём** — **поэтапно**: сперва КФ2 + двери + названия диалогов (закрывает ~80% боли «не работает»), затем scoped-чаты (КФ3) и Cmd+K (КФ4) под отдельную визуальную приёмку, затем чистка (КФ5).

### Добавленные разрывы (найдены приёмкой, в исходном ТЗ их не было) — включить в КФ2:
- **Р1. У владельца нет двери в чат из меню.** Пункт «Спросить» (`/chat`) в `nav-config.ts` стоит `roles: ["manager"]` + `gateFeature: "feature.chat_org"` → owner/admin/coo его не видят. Единственный их вход — FAB (поповер без истории). Нужно показать пункт «Мастер»/«Спросить» лидерским ролям.
- **Р2. Названия диалогов не генерируются.** В списке `/chat` все диалоги называются «Новый диалог» (отличаются только скоупом и датой) → история нечитаема. `summary` персистится cron'ом, но заголовок списка из содержимого не выводится. Нужен заголовок диалога из первого сообщения/summary.
- **Р3. «Память» не открывает чат.** `/memory` — сетка ссылок на реестры; текст «Спросите у Мастера» есть, а двери/чата нет. По Ф5 арх-ТЗ «Память» должна открывать новый диалог Мастера — не сделано.

## 2. Проблема, которую закрывает это ТЗ
Сейчас в кабинете **три разных движка ответа** на один смысл «спросить у памяти», пользователь видит разную логику:
1. **chat-v2** (`chatV2Api`, `/api/v1/chat-v2`): десктоп `/chat` (`ChatV2Client`), Cmd+K Ask, `IssueChat` (scope:issue), орфан `chat-v2/ChatPanel`.
2. **concierge** (`/api/v1/concierge/*`): FAB `ConciergeChat`, орфан `AssistantClient`, Cmd+K command-mode.
3. **legacy chat** (`chatApi`, `/api/v1/chat`, `/meetings/:id/chat`): мобильный `OrgChatPanel` (тело `/chat` на мобиле), `MeetingChatPanel` (чат результата встречи).

Цель ТЗ: **единственное лицо — Мастер (concierge-движок)**; chat-v2 — внутренний ответчик, его фронт-сёрфейсов не остаётся; legacy chat в Q&A-роли уходит.

## 3. Предусловие (бэкенд) — scope в Мастере
`concierge.process` / `askEphemeral` сейчас отвечают только по org. Для scoped-чатов (встреча/задача) нужно:
- Прокинуть `scope` + `scopeRefId` через `ProcessInput` → `dispatchAskChatV2`/`resumeClarify` → `askEphemeral({scope,scopeRefId})` (он их уже принимает).
- Источник scope в кабинете: фронт передаёт `pageContext`/новый параметр; Мастер кладёт в askEphemeral. На каналах scope=org (как сейчас).
- Приёмка: вопрос в чате задачи находит только её контекст (scope:issue), как сегодня `IssueChat`.

**Переключатель режима (развилка 2):**
- Один контрол наверху дома: «Помощник компании (общий разбор) | Клон роли | scope встречи/задачи». Заменяет вкладки `ConciergeFloatingButton` (`company/clones`) И `chat-v2/AssistantTargetSelect`.
- Список диалогов слева фильтруется/группируется по режиму (скоуп уже в карточке беседы: «Вся компания / Карточка / …»). У каждого режима — свои диалоги.

**Двери (Р1, Р3):**
- **Р1:** добавить пункт навигации к дому Мастера лидерским ролям в `nav-config.ts` (сейчас `/chat` только `roles:["manager"]`). Назвать единообразно с продуктом («Спросить»/«Мастер»). Сохранить `gateFeature` по тарифу, если нужно.
- **Р3:** `/memory` — кнопка/дверь «Спросить у Мастера» открывает новый диалог дома (без кусочного поиска).
- **FAB (развилка 1, обновлено 2026-06-27):** `ConciergeFloatingButton` переделать из поповера в **заметную кнопку-навигацию → `/chat`** (большое окно). Убрать встроенный `ConciergeChat`/вкладки/локальный `mode`-state из FAB — он становится чистой кнопкой перехода (router.push). Виджет-поповер демонтируется.

**Названия диалогов (Р2):**
- Заголовок беседы в левом списке выводить из первого сообщения пользователя (или `summary`, когда готов), а не статичное «Новый диалог». Источник — `ConciergeConversation.summary` (персистит cron) с фолбэком на обрезанный первый user-message.

**Приёмка (визуальная, Playwright/прод):** один дом; левая колонка бесед с осмысленными названиями; «Новый диалог»; цитаты кликабельны; переспрос-уточнение видно; переключатель режима (Помощник/Клон/scope) работает и фильтрует диалоги; пункт меню к чату виден владельцу; плавающая кнопка ведёт сразу в большое окно `/chat` (без маленького поповера); «Память» открывает новый диалог Мастера.
