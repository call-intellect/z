# Pulse Волна 4 — 152-ФЗ + Risk-агенты

## Что было поставлено

Продолжение полной автономии. Волна 4 по ТЗ — 8 фаз (3 недели по плану), фокус на compliance + risk detection. Решение: сжать в 2 агента и **скипнуть 4.6 (Forecaster) и 4.7 (hr_partner role)** в этой сессии — их можно безопасно отложить.

## Что сделано (5 из 8 фаз)

**4.1 — 152-ФЗ opt-in flow**:
- 2 новых поля в Person (`analyticsOptIn`/`analyticsOptInAt`)
- Новая модель ConsentLog (per personId × dataType × timestamp)
- ConsentService с auto-update Person.analyticsOptIn (true только если консенты на checkin_processing+risk_analysis оба =true)
- 3 frontend-страницы: `/onboarding/consents` (Блок C — 3 чекбокса), `/me/privacy/consents` (список+revoke), `/me/privacy/access-log` (audit)

**4.2 — Audit log /me/privacy/access-log**:
- Новая модель KnowledgeAccessLog (viewer×viewed×section×timestamp)
- KnowledgeAccessLoggerInterceptor на PersonsController — best-effort, self-view не логируется, ошибки не валят запрос
- REST `/api/v1/me/privacy/access-log`

**4.3 — Region flag**:
- `Org.region String? @default("ru")` — для будущих 'eu'/'other' conditions
- v1 — UI conditional rendering пока не имплементировал (Org-defaults и для 'eu' пока не требуется)

**4.4 — Meeting-Speaker-Analyzer**:
- MeetingParticipantBehavior.sentimentTextPerSpeakerJson Json?
- Hourly worker, LLM deepseek-v4-flash, JSON-strict вывод {topics, textSentiment, confidence}
- **EU AI Act §1.3 compliance**: явно прописал в SYSTEM «не пытайся угадывать эмоции по голосу/невербалике (их нет в данных)»
- Реплики собираются через Transcript.turns (DialogTurn[]) с speaker-key matching (livekitIdentity/name lowercase) — тот же паттерн что в behavior-metrics-calculator

**4.5 — Burnout-Risk-Detector**:
- Person.riskFlagsJson Json?
- Daily cron, **gate на analyticsOptIn=true** (152-ФЗ integration)
- 4 активных сигнала (sentiment_dip vs 90d baseline, missed_checkins, broken_promises, conflict_mentions)
- 3 TODO сигнала (reply_latency_rise, workload_overload, meeting_noshows) — ждут tracking-инфраструктуры
- **НЕ агрегирует в одну цифру** (ТЗ требование) — только список активных сигналов
- PersonPulse получил секцию «Сигналы для разговора 1:1» с tone-color и предупреждением «Это не диагноз. Повод для разговора 1:1»

## Чему научился

1. **Privacy gate via analyticsOptIn** — изящный паттерн. Burnout-Risk cron фильтрует `where: analyticsOptIn=true`, что автоматически отключает анализ для тех, кто не дал согласие. Никаких отдельных env-флагов или per-feature toggles.

2. **152-ФЗ Block C onboarding** — 3 чекбокса с разными default'ами (все 3 — true). Текст важен: «По 152-ФЗ нужно ваше согласие» + «можно изменить в любой момент» + «отказ отключит pulse-метрики». Это компромисс между пользовательским comfort'ом и legal compliance.

3. **EU AI Act compliance в промптах** — нужно явно писать «не анализируй голос/видео» в SYSTEM, даже если в данных их нет. Зашитая защита от того, что LLM start-fabricating эмоции из имени или контекста.

4. **Self-view не логируется в audit** — простая, но важная проверка (`if person.userId === viewer.userId return`). Иначе access-log замусоривается человек смотрит свою собственную карточку.

5. **Interceptor vs Middleware** — для access log выбрал interceptor: запускается ПОСЛЕ route matching (req.params.id уже разрезолвлен), плюс пишет log ПОСЛЕ успешного ответа (через `tap`). Middleware пришлось бы парсить URL вручную.

6. **Меньше JSON-полей, больше структуры** — `riskFlagsJson` — намеренно НЕ агрегат в одно число. ТЗ требует «не агрегируй в одну цифру», и это правильно: одна цифра = ranking сотрудника = токсично. Список «сигналов для 1:1» — конструктивно.
