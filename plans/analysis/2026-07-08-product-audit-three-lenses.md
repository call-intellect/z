## 1. Кратко для владельца

**Общее состояние.** Продукт инженерно заметно взрослее, чем месяц назад: конвейер знаний закрыл основной класс «тихой потери», чат сведён к одному мозгу, кабинет вылечен от половины июньских болезней, а инфраструктура измерения качества (стенды) — реальная сильная сторона, которой нет у конкурентов. Категория «AI операционный директор для 40–80» в РФ по-прежнему **пуста** — направление разворота подтверждено свежим рыночным поиском.

**Три главных вывода:**

1. **Узкое место сейчас — не «мозг», а «двери».** Утренний брифинг («День компании») реально генерируется и даже уже маршрутизируется в Telegram — но тихо гибнет по дороге (окно «тихих часов» считается по времени сервера, а не получателя; ретрая нет; ссылка в сообщении некликабельна). Открытия брифинга никто не считает — **главная метрика месяца сегодня неизмерима технически**. На телефоне киллер-экрана нет вообще: вкладка «Сегодня» показывает владельцу другой экран. Всё это чинится **днями**, и это самые дешёвые действия с прямым влиянием на метрику месяца.

2. **Системная болезнь — тихие отказы.** Найдено 11 сценариев, где встреча/событие/запись при сбое **молча теряется навсегда** при зелёных логах (упавший AI-провайдер = встречи выпадают из памяти; потерянный вебхук = встреча вечно «идёт»; упавшая дорожка = вечное «отчёт готовится»). Интерфейс усугубляет: при ошибке сервера «День компании» показывает «всё в движении» вместо «не смогли загрузить». А прод при этом слеп: 100+ метрик экспортируются, но их никто не собирает, алертов нет. Для продукта, который продаёт память за 60 000 ₽/мес, тихая потеря = потеря доверия, причём необнаружимая.

3. **Клоны: метод правильный — корм не тот.** Научная основа сборки клона (черты только из объяснённых решений) грамотна и подтверждена стендами на синтетике. Но на реальном проде канал корма даёт **0–1 блок на сотрудника** (замер: 153 встречи, 1117 блоков — у CEO 1 клон-блок), а механизм «Кора сама расспросит» закольцован — включается только у тех, у кого корм уже есть. Плюс память клона отрезана от общего графа: клон уверенно отвечает «не знаю» про то, что память компании знает. Нужен разворот: интервью как первый канал (Stanford: 2-часовое интервью = 85% точности воспроизведения), переписки/документы как источники, память клона — через общий ретрив с фильтром атрибуции.

**Отдельная мина (блокер ближайшего выката):** подготовлена миграция эмбеддингов на локальную модель 768, её сид уже стоит в очереди прод-деплоя — а в коде **~45 мест жёстко прибиты к старой размерности** `::vector(1536)`. Скептик подтвердил и нашёл хуже: SQL-миграция смены колонок — **сирота** (не подключена ни к какому пути деплоя, а prod-deploy-log обещает «авто»-миграцию, которой не существует) — штатный выкат выполнит сид провайдера 768 **без** смены колонок, и запись эмбеддингов сломается независимо от кастов; env-дефолты размерности тоже не перевёрнуты (поиск после миграции навсегда тихо деградирует до BM25). Чинится пакетом за ~1 день (безразмерный `::vector` + настоящая hand-written Prisma-миграция + разворот дефолтов + guard на write-пути) — **до выката**. ✅

## 4. Линза 2 — Инженерия

## 6. Сквозные темы (видны только со всех трёх линз сразу)

1. **Петля ритуала владельца разорвана в доставке, а не в мозге.** Генерация брифинга работает; сломаны: доставка (quiet-hours по UTC, нет ретрая, некликабельная ссылка), витрина на телефоне (другой экран), измерение (нет openedAt). Это кластер MKT-1+F1+F2+UX-1+FE-1 — суммарно ~1 неделя работы, прямое влияние на метрику месяца.

2. **«Ошибка = пусто» — один и тот же анти-паттерн в трёх слоях.** Пайплайны молча теряют данные (KC-R1/R4, MEET-01..05), интерфейс подменяет ошибку пустотой (FE-1, UX-4), eval-контур доставляет сухой fallback как норму (EVAL-1). Инвариант для всех будущих ТЗ: **каждое отказное состояние либо чинится автоматически, либо честно показывается и алертится.**

3. **Кэши, ломающие доверие.** Три независимых бага одного класса (R1, R2, CHAT-2): кэш отдаёт неправильный, но уверенный ответ. Для продукта «доверие к памяти» неправильный уверенный ответ хуже медленного.

4. **Построено, но не подключено.** Мёртвая админ-ручка порога клонов (F3), retryAi без кнопки (MEET-02), listener профиля знаний из одобренного блюпринта (CLN-2), IssueEmbedWorker (реестр), decision_no_owner (реестр), KPI headless (реестр), Волна 0 (F5). Продукт систематически теряет ценность на последней миле подключения. Дешёвый ритуал: перед новой стройкой — проход по «мёртвому грузу».

5. **Наблюдаемость прода = 0 при волне 40–100 платящих.** ARCH-01 (никто не скрапит метрики) + ARCH-03 (Redis-бомба) + EVAL-3 (ноль CI) + R7 (линейка вручную). Один watchdog-крон + GitHub Actions закрывают 80% за дни.

6. **Embedding-миграция 768 — связка мин.** EXT-F1 (~45 хардкодов + миграция-сирота + неперевёрнутые дефолты) + EXT-F2 (все пороги калиброваны на старую модель) + clone-thresholds-fragile (порог черт уже дважды ломался). Правило: смена модели эмбеддинга = атомарный пакет «код-инвариантность + настоящая миграция + re-embed + пере-калибровка порогов + стендовый замер», не три отдельных задачи.
