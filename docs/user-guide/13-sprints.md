# Спринты

Спринт — рабочий цикл команды. Ограниченный по времени отрезок (неделя, две, месяц), в котором команда фокусируется на конкретной цели. Спринт объединяет задачи из разных проектов, привязывает к ним встречи и даёт AI-подсказки по ходу движения.

Это не просто список задач с дедлайном. Спринт в Коре — живой объект: Кора слушает встречи, связанные со спринтом, извлекает из них прогресс и блокеры, генерирует подсказки и в конце собирает итоговый отчёт.

## Что Кора делает за вас

- Сама обновляет прогресс спринта на основе завершённых задач — без ручного проставления процентов.
- Сама генерирует AI-подсказки (SprintHints): что идёт хорошо, что блокирует, что рискует не успеть.
- Сама связывает встречи со спринтом — если на встрече обсуждались задачи спринта, Кора это заметит.
- Сама создаёт итоговый AI-отчёт при завершении спринта.
- Сама обновляет счётчики и виджеты в реальном времени через WebSocket — не нужно обновлять страницу.

## Что вы делаете сами

- Создаёте спринт и выбираете область действия (компания, отдел, клиент, проект и т.д.).
- Добавляете задачи в спринт.
- Проводите встречи и обсуждаете прогресс.
- Завершаете спринт и читаете итоговый отчёт.

## Список спринтов (`/sprints`)

Двухколоночный макет. Слева — карточки всех спринтов, справа — предпросмотр выбранного.

### Левая колонка — список

**Вкладки-фильтры** сверху списка:

| Вкладка | Что показывает |
|---|---|
| **Активные** | Спринты, которые идут прямо сейчас |
| **Завершённые** | Уже закрытые спринты с итоговыми отчётами |
| **Предстоящие** | Запланированные, но ещё не начавшиеся |
| **Все** | Полный список без фильтра |

**Чипы области действия (scope)** — второй уровень фильтрации:

| Scope | Когда выбрать |
|---|---|
| **Компания** | Спринт касается всей компании |
| **Отдел** | Спринт конкретного отдела |
| **Клиент** | Спринт привязан к клиенту |
| **Поставщик** | Спринт привязан к поставщику |
| **Сотрудник** | Индивидуальный спринт сотрудника |
| **Проект** | Спринт привязан к проекту |

Чипы кликабельны, можно выбрать несколько. Фильтр работает мгновенно — URL синхронизируется, ссылка копируется.

**Поиск** по названию спринта с задержкой 300 мс (debounce) — не дёргает сервер при каждом символе.

**Сортировка** — три варианта:

- По дате начала (новые сверху / старые сверху).
- По прогрессу (кто ближе к завершению).
- По количеству AI-подсказок (где больше сигналов — возможно, требует внимания).

**Пагинация** — если спринтов много, список разбивается на страницы.

### Правая колонка — предпросмотр

`SprintPreviewCard` показывает краткую сводку выбранного спринта:

- **Scope-бейдж** — к чему привязан (Компания / Отдел / Клиент / …).
- **Прогресс-бар** — процент выполнения.
- **Счётчики** — сколько задач в каждом статусе (открыто / в работе / готово).
- **Топ-3 AI-подсказки** — самые важные SprintHints.
- **Топ-3 задач без срока** — задачи, у которых нет дедлайна (риск).
- **Кнопка «Открыть спринт»** — переход на дашборд спринта.

На мобильных устройствах правая колонка скрыта — вместо неё всплывающая панель (`Sheet`), которая открывается тапом на карточку.

### Живые обновления

Список обновляется в реальном времени через WebSocket (`/ws/tracker`). События `cycle.*` и `sprint_hint.*` приходят мгновенно — счётчики, прогресс и подсказки обновляются без перезагрузки страницы.

## Создание спринта

Кнопка **«+ Создать»** открывает расширенный мастер создания спринта (`SprintCreateWizard`).

### Шаг 1 — Область действия

Два элемента:

**1. Radio-выбор scope** — 6 вариантов (Компания / Отдел / Клиент / Поставщик / Сотрудник / Проект).

**2. Combobox** — умное поле выбора конкретного объекта. Работает как поиск с подсказками:

- Начинаете печатать название — видите совпадения.
- Если нужного объекта нет — прямо в поле можно создать новый: появится пункт `+ Создать «<ваш запрос>»` для поставщика, карточки, отдела или сотрудника.
- Для выбора `Сотрудник` — двухступенчатый picker: сначала выбираете должность (Role), потом конкретного человека (Person) через назначение (Appointment).

### Шаг 2 — Название и сроки

- **Название** спринта — короткое, человеческое.
- **Длительность** — сколько дней/недель.
- **Дата начала** — когда стартует.

### Что происходит при создании

Один API-запрос (`POST /api/v1/sprints/quick-create`) **атомарно** создаёт:

1. **Project** — рабочее пространство спринта.
2. **Cycle** — итерация (цикл) внутри проекта.
3. **Board** — канбан-доска.
4. **IssueStates** — стандартные статусы задач (Открыто / В работе / Готово).

Это значит, что спринт сразу готов к работе — не нужно отдельно создавать проект, доску и настраивать статусы.

## Дашборд спринта (`/sprints/[id]`)

Основная рабочая страница спринта. Автообновление каждые 30 секунд (SWR refresh).

### Что видите

**Прогресс.** Общий процент выполнения с разбивкой: сколько задач в каждом статусе, сколько просрочено, сколько без исполнителя.

**Три секции задач:**

| Секция | Что показывает |
|---|---|
| **Задачи в работе** | То, над чем команда работает прямо сейчас |
| **Заблокированные** | Задачи, которые не двигаются (с причиной блока) |
| **Завершённые** | То, что уже готово в этом спринте |

**AI-подсказки (SprintHints).** Автоматические выводы системы по ходу спринта:

- Что идёт хорошо (задачи закрываются в срок).
- Что блокирует (повторяющиеся упоминания одного и того же блокера на встречах).
- Что рискует не успеть (задачи без движения ближе к дедлайну).

Подсказки генерируются на основе встреч, связанных со спринтом, и состояния задач.

**Связанные встречи.** Список встреч, привязанных к этому спринту. Клик → страница встречи с записью и AI-отчётом.

**Участники.** Аватарки всех, кто работает в спринте.

### Действия

- **«Создать видеовстречу»** — запускает видеовстречу типа `sprint_review` (обсуждение спринта) прямо из дашборда. Запись встречи автоматически привязывается к спринту.
- **«Завершить спринт»** — закрывает цикл и запускает генерацию итогового AI-отчёта.

## Итоговый отчёт (`/sprints/[id]/review`)

AI-сгенерированный документ по завершённому спринту. Три состояния:

| Состояние | Что видите | Что делать |
|---|---|---|
| **Готовится** | Индикатор загрузки, страница автоматически обновляется каждые 10 секунд | Ждать |
| **Готово** | Полный отчёт: итоги, метрики, уроки, рекомендации | Читать, шерить, обсуждать |
| **Ошибка** | Сообщение об ошибке + кнопка «Пересоздать» | Нажать «Пересоздать» |

### Что внутри отчёта

- Общий итог: что было запланировано vs что сделано.
- Процент выполнения с разбивкой по типам задач.
- Ключевые решения, принятые в ходе спринта.
- Блокеры и как они были сняты (или не были).
- Уроки: что улучшить в следующем спринте.
- Связанные встречи с таймкодами.

## Связь спринтов с AI

Спринты в Коре — не изолированный трекер, а часть единого графа знаний.

### Встречи → Спринт

Если на встрече обсуждались задачи спринта, Кора:

- Привязывает встречу к спринту.
- Извлекает из транскрипта упоминания задач и обновляет их статус.
- Генерирует SprintHint, если замечает проблему (например, «третью встречу подряд обсуждают задачу X, но она не двигается»).

### Спринт → AI-подсказки

AI анализирует:

- Состояние задач (сколько открыто, сколько просрочено).
- Активность встреч (как часто команда обсуждает спринт).
- Содержимое транскриптов (упоминания блокеров, рисков, срывов).

На основе этого генерируются SprintHints — короткие, конкретные, действенные.

### Завершение → Итоговый отчёт

При нажатии «Завершить спринт» запускается AI-пайплайн:

1. Собираются все задачи и их история.
2. Собираются все связанные встречи и их AI-отчёты.
3. Генерируется итоговый документ с выводами и рекомендациями.

## Спринт vs Цикл vs Проект — как связаны

| Объект | Что это | Пример |
|---|---|---|
| **Проект** | Долгосрочное рабочее пространство | «Мобильное приложение» |
| **Цикл (Cycle)** | Итерация внутри проекта | «Sprint 12 — май» |
| **Спринт** | Рабочий цикл, объединяющий задачи из разных проектов | «Подготовка к конференции» |

Спринт может включать задачи из нескольких проектов. При создании спринта автоматически создаётся проект + цикл, но можно привязать спринт и к существующему проекту.

Подробнее — [Проекты и трекер](./14-projects-tracker.md).

## Что попробовать

- Создайте первый спринт через мастер — выберите scope «Отдел» и привяжите к своему отделу. Посмотрите, как автоматически создастся проект, доска и статусы.
- Проведите встречу типа «Обсуждение спринта» прямо из дашборда спринта — посмотрите, как AI-подсказки обновятся после обработки записи.
- Завершите тестовый спринт и прочитайте итоговый отчёт — обратите внимание на раздел «Уроки».
- Попробуйте фильтры: чипы scope + сортировка по количеству подсказок — быстро показывает, где команде нужна помощь.

## Что нельзя

- Нельзя удалить спринт после его начала (можно завершить или отменить).
- Нельзя перенести задачи между спринтами массово — только по одной (для массовых операций используйте [Проекты](./14-projects-tracker.md)).
- Нельзя редактировать итоговый отчёт — это документ, зафиксированный AI. Если нужны правки, создайте задачу-следствие.
- Нельзя видеть чужие спринты, если у вас нет доступа к связанному проекту или отделу.
