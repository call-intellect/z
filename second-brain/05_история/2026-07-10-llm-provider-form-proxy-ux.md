# 2026-07-10 — Понятная настройка подключения LLM-провайдера + поддержка Anthropic в прокси

## Что было поставлено

1. «Бро, нужно UI в добавлении модели сделать более понятным, сейчас какая-то муть» — форма провайдера в `/admin/ai/catalog` не объясняла, как настраивать прокси и в каком виде указывать ключ; для OpenAI и Anthropic прокси настраивается по-разному, и это нигде не было видно.
2. Следом: «По антропику сам прокси нужно доработать?» → да → вариант A (отдельный маршрут `/anthropic/*` в Tozix/openai-proxy) + правка формулы в Z.

## Как решал

**Разведка (главное):** не поверил ни README, ни UI — прогнал живые curl-пробы к `proxy.agent-lia.ru`. Доказал: `/v1/*` уходит на api.openai.com (видно по `Set-Cookie: Domain=api.openai.com`), auth только `Authorization: Bearer префикс:ключ`, а `x-api-key` (которым ходит Anthropic SDK) прокси режет своим 401 до маршрутизации. Плюс по `node_modules` подтвердил: Anthropic SDK постит на `{baseURL}/v1/messages` (свой `/v1`!), OpenAI SDK — на `{baseURL}/chat/completions`. Отсюда два дефекта: прокси не умеет Anthropic вообще, а формула Z (`{root}/{path}/v1`) даёт задвоенный `/v1` для anthropic/kie.

**Z, форма и бэкенд** (коммит `b783e255`, ветка UIfix):
- `effective-connection.util.ts` — формула эффективного подключения вынесена в чистую функцию (единственная реализация: резолвер + admin discover-preview), протокол-зависимая: `PROTOCOLS_APPENDING_OWN_PATH` (`anthropic-messages`, `kie-native`) получают `{root}/{path}` без `/v1`.
- `GET /admin/llm-providers/connection-meta` — адрес прокси + маска префикса (первые 4 символа) для живого предпросмотра. Роут объявлен ДО `@Get(':id')` — иначе перехват параметром.
- `discoverModelsPreview` принимает `useProxy`/`proxyPath` — проверка подключения через прокси до сохранения провайдера.
- Форма (`LlmProvidersClient.tsx`): секция «Подключение» — сегмент «Напрямую / Через прокси», живой предпросмотр «Куда пойдёт запрос» (зеркалит формулу + суффикс протокола), протокол-зависимые подсказки baseUrl, подсказка ключа «префикс добавится сам», префилл `proxyPath=anthropic`, warning только при пустом маршруте, кнопка «Сохранить и проверить» (save → smoke-test → toast).
- Попутно починена устаревшая спека `provider-smoke-test.cron.spec.ts` (мок `'OK'` короче порога ≥5 символов, `SMOKE_MAX_TOKENS` 64→512) — была красной на ветке до меня.

**Прокси** (коммит `b425b45` в Tozix/openai-proxy, клон в `~/dev/work/openai-proxy`):
- `anthropic.controller.ts` (`@Controller('anthropic')`, wildcard-роуты как grsai/kie) + `authScheme: 'x-api-key'` в `proxy.service.ts`: извлечение `префикс:ключ` из `x-api-key` (fallback Bearer), upstream'у всегда чистый ключ в `x-api-key`; `ANTHROPIC_BASE_URL`; `location /anthropic/` в nginx-примере (без него nginx срежет маршрут!); README + `test-proxy.ts`.

## Что вышло (верификация)

- Прокси: `npm run build` ✓; **живой e2e локально** — поднял `node dist/main.js`, запрос с `x-api-key: префикс:sk-ant-invalid` дошёл до настоящего api.anthropic.com и вернул его `authentication_error` (маршрутизация + срез префикса + смена заголовка работают), неверный префикс → 401 прокси, OpenAI-маршрут без регресса.
- Z: tsc/eslint/build (bek+front) ✓; 313 тестов затронутых областей ✓ (включая новые: util-формула, connection-meta, preview-через-прокси, anthropic-кейс резолвера).
- Пуши: Z `UIfix` → origin (новая ветка), прокси → main. Прод-активация: redeploy прокси + nginx location + в админке anthropic → прокси/`anthropic`/чистый ключ (записано в prod-deploy-log, Шаг 11/12).

## Чему научился

1. **Живой проб > чтение доков.** README прокси и код в main не совпадали с моими ожиданиями от ENV Z (`ANTHROPIC_PROXY_URL` существовал в env.schema, но прокси Anthropic никогда не умел — фича была спроектирована, но не реализована). 3 curl-запроса дали твёрдую фактуру за минуту.
2. **SDK сами добавляют пути, и по-разному:** Anthropic SDK — `/v1/messages` (база БЕЗ `/v1`), OpenAI SDK — `/chat/completions` (база С `/v1`), KieService — `/{model}/v1/…`. Любая «универсальная» формула прокси-URL без учёта протокола даёт задвоенный `/v1` — теперь это закреплено в `PROTOCOLS_APPENDING_OWN_PATH` и в UI-предпросмотре.
3. **UI-предпросмотр итогового URL** («Куда пойдёт запрос») — самый дешёвый способ убить класс конфузов конфигурации: пользователь видит ровно то, что построит бэкенд, потому что формула одна и та же.
4. **`x-api-key` не входил в skip-заголовки прокси** — если бы Anthropic-запрос доходил до upstream, префиксованный ключ утёк бы дальше как есть. При добавлении новой auth-схемы проверяй и то, что старая её не пропускает насквозь.
5. Пре-существующие красные спеки на ветке (smoke-cron) чинить стоит, только если они в зоне твоей фичи — остальные шесть файлов зафиксировал в отчёте, не трогая.
