# SECOND BRAIN PROTOCOL

## Цель
Хранить знания о проекте так, чтобы агент и разработчик всегда имели актуальный контекст.

## Правила

1. Каждая важная мысль, решение, архитектурный выбор — фиксируется сразу.
2. После любого значимого изменения в коде — обновить second-brain.
3. Устаревшие записи помечать `[OUTDATED]` или удалять.
4. Не дублировать то, что уже есть в коде или git-истории.

## Что хранить
- Почему принято решение (не что, а почему)
- Неочевидные зависимости и ограничения
- Контекст задач и договорённости с командой

## Что НЕ хранить
- Очевидные вещи из кода
- Временные заметки (для этого есть задачи)
- Git-история — она уже есть в git
