# Тестировщик Коры (qa-tester)

Этот скилл даёт два готовых доступа к тестовой среде Коры, чтобы не вводить
креды каждый раз:

| # | Доступ | Инструмент | Что делает |
|---|--------|-----------|------------|
| 1 | **UI кабинета** | Playwright (MCP `browser_*`) | вход тестовым аккаунтом, клики, приёмка глазами, скриншоты |
| 2 | **Данные / «база»** | `backend/scripts/diag.ts` | read-only разбор прод-данных встречи (цепочка → транскрипт → LLM-вызовы → отчёт → логи) |

> ⚠️ Кабинет живёт на **проде** `https://korateam.ru` (переехал с `meet.crossmark.ru`
> 2026-06-09 при ребрендинге Z→Кора; **старый домен сломан** — отдаёт чужой
> TLS-сертификат, не использовать). Действуй только под тестовым
> аккаунтом и не трогай данные других Org. Любые **деструктивные** действия
> (удаление встреч/записей, смена настроек чужих сущностей, массовые операции) —
> только с явным «да» владельца в этой сессии.

## Где креды (читать в начале, НЕ переспрашивать)

Файл: `c:\work\z\.qa-cabinet.local.json` — gitignored, читается Read-ом.

```json
{ "url": "https://korateam.ru", "email": "...", "password": "...", "landingPath": "/meetings" }
```

Правила:
- Прочитай файл Read-ом **один раз** в начале сессии тестирования.
- Пароль **никогда не печатай в чат** и не вставляй в коммиты/скриншоты. В
  Playwright подавай его прямо в `browser_type` (в UI поле он маскируется).
- Файла нет / поля пустые → скажи владельцу: «положи `.qa-cabinet.local.json` в
  корень с полями url/email/password». Не выдумывай креды.

## Доступ 1 — вход в кабинет через Playwright

Логин-форма (`/login`): поля `#login-email`, `#login-password`, чекбокс
«Запомнить меня» (по умолчанию включён — оставь), кнопка **«Войти»**. Обычный
пользователь приземляется на `/meetings`, супер-админ — на `/admin`. Тестовый
аккаунт — обычный пользователь → `/meetings`.

**Поток (идемпотентный — не логинься, если уже залогинен):**

1. Прочитай креды из `.qa-cabinet.local.json`.
2. `browser_navigate` → `<url>/meetings`.
3. `browser_snapshot`.
   - Видишь список встреч / шапку «Встречи» → **уже залогинен**, переходи к тесту.
     (Сессия «Запомнить меня» живёт в профиле `.playwright-mcp`, часто переживает
     перезапуск.)
   - Редирект на `/login` → продолжай к шагу 4.
4. Заполни форму: `browser_type` в поле Email → `email`; `browser_type` в поле
   Пароль → `password` (refs бери из snapshot; можно `browser_fill_form`).
5. `browser_click` → «Войти».
6. `browser_wait_for` → текст/URL раздела «Встречи» (`/meetings`). Тост «Неверный
   логин или пароль» = проверь креды в файле, не угадывай.
7. `browser_take_screenshot` для фиксации, если нужна приёмка.

Карта разделов (реальные пункты меню тестового аккаунта, сверено 2026-06-07):
- **Главная** — сводка/пульс компании.
- **Встречи** (`/meetings`) — список встреч + AI-отчёты. Основной раздел приёмки.
- **Команда** — участники Org.
- **Карточки** — карточки знаний (память компании).
- **Помощник компании** — AI-чат компании.
- **Проекты / Спринты / Входящие / Архив спринтов** — задачи.
- **Я** — личное пространство.
- `/admin` — **только** под супер-аккаунтом, тестовому юзеру недоступен.
Слева сверху — переключатель Org (тестовый — «ооо ромашка»), снизу — аккаунт.

## Доступ 2 — «в базу»: diag.ts (read-only ПРОД)

Когда нужно понять, что реально произошло с встречей на бэке (а не только как это
выглядит в UI) — используй diag.ts. Это **только чтение** (единственный не-GET —
логин). Ходит в **прод**, логинится супер-админ-ботом из `DIAG_*` в корневом
`.env` (его читает сам Bun через `--env-file`, тебе эти креды видеть не нужно).

> 🔒 **Правило из памяти проекта:** diag.ts читает прод-данные всех Org под
> супер-админом → перед запуском в КАЖДОЙ новой сессии нужно явное «да» владельца
> («можно в прод»). Оно не переносится между сессиями. Токены/куки — никогда в чат.
> (Это касается diag.ts; обычный Playwright-вход тестовым юзером отдельного
> подтверждения не требует — аккаунт для того и заведён.)

Канонический запуск (переменные — в корневом `c:/work/z/.env`):

```powershell
$env:DIAG_API_BASE='https://korateam.ru'; bun run --env-file=c:/work/z/.env c:/work/z/backend/scripts/diag.ts <команда> [--флаги] [--json]
```

> ⚠️ С 2026-06-09 кабинет на `korateam.ru`. diag.ts по умолчанию (`DIAG_API_BASE`) ходит
> на старый `meet.crossmark.ru` (сломан) → **обязательно** задавай
> `DIAG_API_BASE=https://korateam.ru` (через `$env:` в PowerShell или префиксом
> `DIAG_API_BASE=... ` в bash), пока дефолт в `diag.ts`/`.env` не обновят.

Команды (7):

| Команда | Назначение |
|---|---|
| `meetings --status <s> --limit N` | список встреч (найти id тестовой встречи) |
| `trace --meeting <id>` | полная цепочка по встрече: статус → транскрипт → AI → отчёт → логи |
| `report --meeting <id>` | готовый AI-отчёт встречи |
| `llm-calls --meeting <id>` | все LLM-вызовы встречи (модель, статус) |
| `call <aiUsageLogId>` | один вызов целиком (промпт + ответ модели) |
| `chain --trace mtg_<id>` | технический след логов по traceId |
| `logs --at-least WARN --from <дата>` | прод-логи уровня ≥ WARN |

**Цикл приёмки UI ↔ данные:** провёл/нашёл тест-встречу в кабинете → `diag
meetings --limit 5` (взять id) → `diag trace --meeting <id>` (увидеть, отработал
ли конвейер) → `diag report --meeting <id>` (сверить отчёт с тем, что в UI).

## Что проверять (чеклист приёмки)

Подстраивай под задачу, но базовый обход:

- **Вход:** логин проходит, приземление на `/meetings`, шапка/имя аккаунта видны.
- **Список встреч:** грузится без ошибок, карточки кликабельны, статусы корректны.
- **AI-отчёт встречи:** открывается сразу, поля соответствуют типу встречи; кнопки
  «копировать / скачать / печать» работают; нет «AI думает» без объяснения.
- **Медиа:** запись/видео проигрывается (если есть), плеер не висит.
- **Главная / Карточки / Помощник компании:** разделы открываются, нет пустых/
  битых состояний и английских слов в UI (продукт — только русский).
- **Консоль:** `browser_console_messages` — нет красных ошибок на ключевых экранах.
- **Сверка с бэком:** при сомнении — diag.ts (trace/report) по id встречи.

Найден баг → зафиксируй: что делал (шаги), что ждал, что получил, скриншот,
если есть — id встречи и вывод `diag trace`.

## Артефакты и гигиена

- Скриншоты приёмки, которые важны, — в `plans/analysis/<тема>/`; временный
  мусор в корне допустим (он gitignored по маскам), но не коммить его.
- **Никогда не коммить** `.qa-cabinet.local.json` и не делай `git add .` / `-A`.
- Креды и токены — не в чат, не в файлы под git.
- Тестируешь на проде: не плоди мусорные встречи без нужды, прибирай за собой
  только то, что создал сам, и только с подтверждения если действие необратимо.

## TL;DR

1. Read `.qa-cabinet.local.json`.
2. Playwright: `navigate /meetings` → если `/login`, заполни email/пароль → «Войти» → ждём `/meetings`.
3. Тестируй по чеклисту, делай скриншоты.
4. Нужны данные с бэка → `diag.ts` (read-only прод, спроси «можно в прод» один раз за сессию).
