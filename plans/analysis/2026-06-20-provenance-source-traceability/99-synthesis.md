# Провенанс / трассировка первоисточника — синтез и доказательство

## 1. Рамка проблемы

**Формулировка владельца:** у каждой автосозданной сущности должна быть кнопка «провалиться на уровень ниже» к первоисточнику (фрагмент встречи / переписка чата за дату / голосовое предложение сотрудника / кусок документа), чтобы видеть, откуда взялось и правильно ли извлечено.

Это симптом. Под ним — **две конкурирующие корневые формулировки** (Iceberg-проход отделяет симптом от корня):

- **Формулировка-А (доверие/верифицируемость):** «пользователь не доверяет автоизвлечённым сущностям, потому что не может проверить опору». Тогда цель — **верифицируемость**: показать дословную цитату + дать дойти до первоисточника. Метрика «решено»: доля сущностей, у которых клик «Откуда это» приводит к дословной опоре ≤ 1 действие; падение доли «отклонённых/проигнорированных» карточек.
- **Формулировка-Б (исправляемость/обучение):** «пользователь хочет не только увидеть, но и поправить неверное извлечение и научить систему». Тогда цель шире — провенанс как точка входа в коррекцию (привязать к self-improving, `feedback_no_human_in_loop_for_clone_learning`). Метрика: доля «провалившихся к источнику → исправивших».

**Рекомендуемая рамка — А как ядро v1, Б как естественное продолжение** (кнопка «это неверно» рядом с цитатой подаёт сигнал в обучение, но без human-gate). Обе формулировки требуют одного и того же фундамента — единого провенанс-контракта; различаются лишь действиями поверх него.

**Кто страдает (роли Z):**
- **рядовой сотрудник** — получает probe-вопрос/карточку без контекста, не может проверить → игнорирует (прямая связь с `2026-06-20-probe-smart-questions-module.md`);
- **владелец/COO** — видит дашборд «решений/рисков», не может ткнуть в «откуда этот вывод» → не доверяет цифрам (зафиксировано в `project_product_audit_cabinet_2026_06_12`);
- **уходящий сотрудник / клон роли** — знание без провенанса невозможно аудировать;
- **админ Org** — «Подтверждений 47» без опоры невозможно разобрать пачкой.

## 2. Дерево вопросов (MECE) — этапы потока «провалиться к источнику»

Каждая ветвь = будущая фаза ТЗ; без пересечений и пробелов.

1. **Захват источника (ingest).** Сохраняет ли вход достаточно для адресации фрагмента (таймкод встречи / messageId чата / страница документа / аудио голоса)? → ветка A2.
2. **Привязка к сущности (extraction).** Не теряется ли block-линк при создании вершины; различается ли «дословная цитата» vs «вторичная выжимка» (`primarySource`)? → ветки A1, A5.
3. **Хранение указателя (модель данных).** Где живёт указатель — денормализованный снимок на вершине (для списка) и нормализованная истина в `IdeaBlockEvidence` (для глубины)? → A1, red-team ось 1.
4. **Резолв в цепочку (API).** Есть ли единый резолвер «сущность → нормализованная цепочка провенанса», фильтрующий по правам зрителя? → A4, red-team ось 2.
5. **Последняя миля (deep-link).** Можно ли физически перейти к моменту встречи / сообщению / странице / голосу? → A3, A4.
6. **Показ (UI).** Единый компонент «Откуда это»: inline-маркер + дровер с цитатой/таймкодом/уверенностью + честная деградация + разметка «цитата vs вывод»? → A3, E1/E2/E4.

## 3. Ландшафт аналогов (кратко; полностью — [20-external-landscape.md](20-external-landscape.md))

- **Зарубеж citation-UX** (Perplexity/Glean/Copilot/Notion): inline-номер за утверждением + deep-link к пассажу с подсветкой + hover-preview; **инвариант «цитата не даёт новых прав»**; «нет опоры → нет цитат».
- **Meeting-intelligence** (Gong/Otter/Avoma/Fireflies/Fathom) — ближайший класс: все 5 имеют «клик по артефакту → точный момент»; **ни один не показывает числовой % уверенности** (доверие через клик-в-источник). Avoma «иконка-источник у каждой заметки» — прямой образец.
- **OSS** (RAGFlow/Onyx/Verba/Quivr): лучший паттерн хранения — Onyx `source_links: offset→ref` (под-документный якорь) + детект `[N]`→стабильный источник (НЕ self-report LLM, как у Quivr); RAGFlow bbox+снимок страницы — только для документов; инвариант — провенанс иммутабелен через весь pipeline.
- **РФ**: istok.ai — эталон документов (цитата+страница+%+клик); Яндекс Нейро — единственный, кто различает «цитата vs вывод модели»; МТС Линк — «клик по фразе→момент записи». **Никто из РФ не собирает все сигналы вместе** — открытое окно.

## 4. Внутренний baseline (кратко; полностью — [10-internal-baseline.md](10-internal-baseline.md))

**Провенанс-хребет уже построен и работает в проде.** `Source → RawEvent → IdeaBlockEvidence{quote, startMs, endMs} → IdeaBlock` + `sourceBlockIds[]`/`contextBlockId` почти на всех вершинах. Канонический drill-down `GET /knowledge/blocks/:id` существует. Атрибуция автора детерминирована.

**Где разрыв:**
- **Последняя миля:** нет deep-link к таймкоду встречи (`MeetingResultPageReal` не читает `?t=`), к сообщению чата (данные есть в БД, не прокинуты), к странице документа (парсер уплощает в один blob), к голосу (аудио вообще выбрасывается).
- **Единый аффорданс:** `ProvenanceResolver` = 0 совпадений; 6 несовместимых паттернов; «мост недостроен с обоих концов» (фронт-каркас `cite` есть — бэкенд не наполняет; бэкенд `contextBlockId` есть — фронт не рендерит).
- **Точечные потери в коде (🔴):** задачи из встреч теряют block-линк (`evidenceBlockIds:[]` хардкодом); probe-вопрос не несёт первоисточник в payload; snippet Concierge — из вывода LLM, не из дословной evidence.
- **Эталоны полноты внутри Z:** `TableCellProvenance` (готовый `sourceLink` deep-link) и `ChatV2Message.citations` (дословный snippet+таймкод). Их паттерн надо обобщить.

## 6. Матрица вариантов + доказательство

**Кандидаты:**
- **A — Единый контракт + универсальный компонент** (`ProvenanceService.resolve(entityType, entityId, viewerContext)` → нормализованная цепочка; один FE-компонент «Откуда это» с двумя точками входа: inline-маркер `[N]` + дровер с цитатой/таймкодом/deep-link; денормализованный preview на вершине; фильтр прав зрителя; graceful-degradation).
- **B — Только inline-сноски `[N]`** в тексте карточек/ответов (Perplexity-стиль), без отдельного дровера и без общего бэкенд-резолвера — каждая поверхность резолвит ad hoc, как сегодня.
- **C — Точечные bespoke-панели «Источники»** на каждой странице: обобщить вручную regulations-паттерн на Decision/Issue/Task/probe, без общего резолвера.
- **D — Do-minimum / проводка:** дорендерить указатели, что уже доходят (`contextBlockId`, `task_closure.evidenceQuote`, наполнить PendingActions `cite`, плеер читает `?t=`), без нового контракта.

Оценка: ✅ полностью · ◐ частично · ❌ нет. Источник каждой оценки — baseline/red-team.

| Критерий (ограничение Z) | A (единый+компонент) | B (inline-only) | C (bespoke per-entity) | D (проводка) |
|---|---|---|---|---|
| Единообразие по всем 26 типам сущностей | ✅ один контракт | ◐ только текстовые ответы | ❌ N экранов вручную | ❌ только то, что уже доходит |
| Производительность списков (N+1 до S3) | ✅ при денорм. preview (red-team ось 1) | ✅ (inline лёгкий) | ◐ зависит от реализации | ✅ |
| Безопасность деагрегации (`dataClass`/`IdeaBlockAccess` зрителя) | ✅ фильтр в одном месте (red-team ось 2) | ❌ N мест фильтровать | ❌ N мест фильтровать | ◐ узко |
| Покрытие последней мили (meeting/chat/doc/voice) | ✅ централизованный deep-link | ◐ только там, где встроили | ◐ дублирование | ❌ только meeting `?t=` |
| Legacy graceful-degradation | ✅ контракт (red-team ось 3) | ❌ ломается на пустом | ❌ каждый экран сам | ◐ |
| Стоимость поддержки (vs дубли regulations/chat-v2/tables) | ✅ убирает 3 дубля резолва | ◐ | ❌ умножает дубли | ✅ дёшево |
| RU-ров «цитата vs вывод» + честный отказ | ✅ единая разметка | ◐ | ❌ | ❌ |
| Стоимость реализации | средняя-высокая | низкая | высокая (N экранов) | очень низкая |

**ADR-доказательство (почему A, steelman альтернатив):**
- **Контекст Z:** провенанс уже почти весь в данных; разрыв — surfacing + последняя миля + дубли резолва. 3 независимых дубля резолва (regulations/chat-v2/tables) — прямой сигнал, что нужен один контракт.
- **B (steelman):** inline-сноска снижает «cost of verification» сильнее всего (источник прямо у утверждения, istok/Perplexity). НО: B покрывает только текстовые ответы (AI-чат), а у владельца запрос — кнопка у КАЖДОЙ сущности (карточки Decision/Issue/probe — не текстовый поток); inline тоже обязан фильтроваться по правам и ломается на пустом источнике; плохо ложится на mobile-first узкие карточки (`feedback_concierge_entry_visible_button`). **B не отвергается, а поглощается A** как одна из двух точек входа (red-team синтез: «inline-маркер + дровер — не или-или»).
- **C (steelman):** даёт максимально заточенный под каждую сущность UX. НО: умножает дубли резолва (их уже 3), умножает места фильтрации прав (N точек утечки деагрегации), не даёт RU-рва единой разметкой. Карго-культ «у regulations красиво — сделаем везде руками» — это техдолг, а не решение.
- **D (steelman):** дёшево и быстро снимает часть боли (probe-контекст, task_closure-цитата, `?t=`). НО: оставляет 6 несовместимых паттернов и 3 дубля; не закрывает запрос «у КАЖДОЙ сущности». **D — это не альтернатива, а Фаза 0 внутри A** (быстрые победы проводкой, пока строится контракт).
- **Вывод:** A лучше по пригодности под ограничения Z (единообразие + безопасность в одном месте + убирает дубли + RU-ров), вбирая сильные стороны B (inline) и D (быстрая проводка). «Лучше» — не по популярности, а по тому, что A — единственный, кто закрывает запрос «каждая сущность» БЕЗ умножения дыр безопасности и дублей.

## 7. Рекомендация (уточнена red-team)

**Строить Вариант A, но не наивно.** Red-team показал: наивный «один resolve() для списка из 50 карточек» — это N+1 в глубину до S3 и дыра деагрегации. Уточнённая форма:

1. **Денормализованный `previewQuote`/`evidenceRef` на вершине** (как уже у `Task.sourceQuote`) → список карточек рендерится из снимка, ноль join вглубь. Снимок несёт `evidenceId` для инвалидации при merge/supersede блока.
2. **Полный `ProvenanceService.resolve(entityType, entityId, viewerContext)`** тянется **только on-demand по клику** на одной карточке → N+1 не существует.
3. **Один FE-компонент «Откуда это»** с двумя точками входа: inline-маркер `[N]` в тексте ответов (поглощённый B) + дровер с дословной цитатой, таймкодом, кнопкой «перейти к первоисточнику», разметкой «цитата vs вывод», индикатором уверенности.
4. **Централизованный deep-link-резолвер** `rawEventId → {sourceType, sourceExternalId} → deepLink` (обобщить `sourceLink` из Smart-таблиц): встреча → `/meetings/:id?t=startMs`, чат → сообщение в треде, документ → страница, голос → проигрыватель заметки.
5. **Фаза 0 (быстрая проводка, из D):** плеер читает `?t=`; гидрировать probe.question первоисточником; наполнить PendingActions `cite`; не терять `evidenceBlockIds` у задач из встреч; snippet Concierge — из evidence.

Это **поглощает** существующий узкий ТЗ `2026-06-11-probe-question-context-leak-fix` (рендер блока «Контекст» probe — частный случай Фазы 0).

## 8. Инварианты, обязательные к внесению в ТЗ (из red-team)

1. **Deny-by-default фильтрация цепочки по зрителю.** `resolve(..., viewerContext)` фильтрует КАЖДОЕ звено по `IdeaBlockAccess(blockId × группы зрителя)` и `dataClass ≤ maxDataClass зрителя` **до** возврата `quote`. Цитата выше класса зрителя → «источник скрыт правами доступа», НЕ показывается. Покрыть тестом «агрегат виден, источник закрыт» (рядом с `knowledge-access-resolver.service.spec.ts`). Это инвариант Glean «citations never grant new access».
2. **Денормализованный снимок на вершине + on-demand полный resolve.** Список — из снимка (ноль join), полная цепочка — по раскрытию одной карточки. Снимок несёт `evidenceId` для инвалидации.
3. **Graceful-degradation = контракт, не ошибка.** Для `sourceBlockIds=[]` / `primarySource='report'` компонент рендерит честное состояние («создано вручную» / «по AI-выжимке отчёта, не дословно, уверенность X%»), а кнопка «перейти к первоисточнику» **физически отсутствует** при отсутствии deep-link-якоря (НЕ ведёт в пустоту — это убивает доверие ко всем провенанс-контролам). report-блоки помечать вторичными явно.
4. **`[N]`→стабильный источник, не self-report LLM** (Onyx-урок PR #3508): номер цитаты привязан к `ideaBlockId`, не к позиции в потоке; детект маркера, а не доверие модели «что она процитировала» (anti-Quivr).
5. **Провенанс-атрибут иммутабелен через pipeline** `ingest → IdeaBlock → link → Theme` (RAGFlow-урок: при кластеризации/мердже координаты теряются).

## 9. Открытые вопросы владельцу (каждый с рекомендацией)

**В-1. Объём v1 — у каких сущностей «Откуда это» появляется первым?**
- *Рекомендую (первым):* (а) карточки **Decision/Issue/Task/Regulation** + (б) **AI-чат компании** (ChatV2/Concierge) кликабельные citations + (в) **probe-вопрос** «по поводу чего». Документ-bbox, chat-message deep-link и голосовой оригинал — v2. **Почему:** у (а)/(б)/(в) данные богаче всего (`sourceBlockIds`/citations/`contextBlockId`), последняя миля = встреча (`?t=`) уже почти готова; это закрывает 80% боли минимумом новой инфраструктуры. Документ/чат/голос требуют новых полей в `IdeaBlockEvidence` и парсинга — отдельная волна.

**В-2. Индикатор уверенности — числовой % или качественная разметка?**
- *Рекомендую:* **разметка «цитата vs вывод» (`attribution: quoted|inferred`) + coverage «по N репликам из M встреч», БЕЗ числового % для встреч.** Числовой % допустим только для ответов из загруженных документов (как istok). **Почему:** консенсус всего класса meeting-intelligence — % у сводки встречи даёт ложную точность; «цитата vs вывод» — единственный незанятый сигнал на рынке РФ (ров против всех 7 конкурентов, только Яндекс Нейро близок). Порог-гейт уверенности — крутилка в `AdminSetting` (`getDynamic`, принцип 9 CLAUDE.md), не ENV/код.

**В-3. Доступ рядового сотрудника к дословной цитате.**
- *Рекомендую:* **да, рядовой видит цитату — но строго через фильтр прав зрителя** (инвариант 1). Сейчас глубокий первоисточник (`/ingest/:id`) открыт только owner/admin — это надо ослабить до «виден фрагмент, доступный по `dataClass`/`IdeaBlockAccess` зрителя», а не «весь RawEvent». **Почему:** без доступа рядового к опоре фича бессмысленна (его и просят проверять); но без фильтра — эскалация привилегий через деагрегацию. Компромисс — показывать нормализованный фрагмент (цитата+таймкод), а не сырой payload.

**В-4. Сохранять ли голосовой оригинал (аудио free_note) в S3?**
- *Рекомендую:* **да, сохранять аудио в S3** (retention — крутилка в AdminSetting), но в **отдельной под-фазе v2**, не блокируя v1. **Почему:** «голосом загрузил предложение от сотрудника» — прямой кейс из запроса владельца, и сейчас аудио безвозвратно теряется (только ASR-текст). Для v1 достаточно показать ASR-текст + детерминированного автора; «проиграть оригинал» — следующий шаг. Это строка в `second-brain/04_не-сделано/README.md` уже сейчас.

## 10. Допущения и риски (desirability / viability / feasibility)

- **[ASSUMPTION, desirability, средняя уверенность]** Пользователи реально кликают «Откуда это», а не игнорируют. Подтверждается индустрией (citation повышает доверие), но для ЦА Коры (не разработчики) проверяется только на проде. Проверка: метрика кликов по аффордансу после v1.
- **[RISK, feasibility]** Word-timings ASR (Vox/GigaAM) — фундамент deep-link к моменту. Для встреч они есть; для остальных источников таймкода нет by design. Не блокирует v1 (встреча — основной источник).
- **[RISK, viability]** Денормализованный preview-quote создаёт staleness при edit/merge блока — нужна инвалидация по событию merge/supersede (write-amplification приемлема при read-heavy 100:1).
- **[RISK, security]** Без инварианта 1 фича = эскалация привилегий. Митигируется тестом «агрегат виден, источник закрыт».
- **[RISK, trust]** report-блоки (`primarySource='report'`) — вторичная выжимка; показ их как «дословной цитаты» = citation hallucination на уровне продукта. Митигируется инвариантом 3.
