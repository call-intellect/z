## 1. `table-extract-rows` — извлечение фактов из транскрипта по схеме колонок

- **Файл:** `backend/src/modules/ai/services/prompts/table-extract-rows.prompt.ts` · каллер `TableEnrichService.extractFacts` (`table-enrich.service.ts`)
- **Контракт:** `json_object` → `{ facts: [{ propertyId, value, confidence: 0..1, quote, timeSec }] }`. Парсится вручную методом `parseFacts`. Поле `value` — полиморфное (`string|number|boolean|array`).
- **Применимые измерения:** C2 (только прямо подтверждённое — уже задан жёсткий принцип, усилим явность шкалы), D1 (при нескольких упоминаниях того же факта — брать последнее), E2 (обёртка `withInjectionGuard` УЖЕ в коде — не дублировать), E1 (`withAsrNote` УЖЕ в коде — не дублировать), E3 (дата-значения в `date`-колонках; call-site не передаёт дату встречи — отметить пробел).
- **Код-сверка:**
  - `buildSystem()` уже вызывает `withAsrNote(withInjectionGuard(...))` — обе обёртки на месте.
  - `wrapUserData` в USER **не применяется**: `transcriptChunk` кладётся в USER без маркеров. Транскрипт — пользовательские данные, должен быть обёрнут. Это пробел call-site (не в промпте), отметить.
  - Шкала confidence уже описана в тексте SYSTEM (0.9+/0.6-0.8/ниже 0.6), совпадает с `CONFIDENCE_CALIBRATION` по духу, но форматирована иначе — унифицируем.
  - Дата встречи в USER не передаётся → для `date`-колонок со значением «к концу месяца» агент не может дать ISO. Это архитектурный gap call-site.

#### БЫЛО (SYSTEM)
```

## Типы колонок (как форматировать value)
  - `text` — короткая строка
  - `longtext` — длинный текст / заметка
  - `number` — число (верни как число)
  - `currency` — денежная сумма (верни число в рублях)
  - `percent` — процент (верни число 0..100)
  - `date` — дата в формате ГГГГ-ММ-ДД
  - `status` — один из допустимых статусов колонки
  - `selectSingle` — одно значение из набора
  - `selectMulti` — массив значений из набора

## Жёсткие правила
- Возвращай значение колонки ТОЛЬКО если соответствующий факт прямо назван в транскрипте.
  Если факт не упомянут или ты не уверен — НЕ возвращай эту колонку. Лучше пропустить, чем
  выдумать.
- Никогда не додумывай, не обобщай и не выводи значение «по смыслу» — только то, что явно
  сказано.
- Каждый факт относится к указанной сущности (entityLabel). Факты про других участников/
  компании не возвращай.
- `confidence` (0..1) — насколько явно факт назван: 0.9+ если сказано дословно и однозначно;
  0.6-0.8 если есть лёгкая неоднозначность; ниже 0.6 если сомнительно.
- `quote` — короткая дословная цитата из транскрипта, подтверждающая факт.
- `timeSec` — момент (в секундах) начала реплики-источника, если он известен из транскрипта;
  иначе 0.
- `propertyId` — ровно тот `id` колонки из схемы, к которой относится факт. Чужие id не
  выдумывай.

## Формат вывода

`{ "facts": [ { "propertyId": string, "value": string|number|boolean|array, "confidence":
number, "quote": string, "timeSec": number } ] }`
Если в транскрипте нет ни одного подтверждённого факта по колонкам — верни `{ "facts": [] }`.
```

```
## Главный принцип — только явное и только об этой сущности

  - `selectMulti` — массив значений из набора (из схемы)
  - `checkbox` — да/нет (true/false)
  - `url` — ссылка (адрес сайта)
  - `email` — электронная почта
  - `phone` — телефон

## Поля каждого факта
- `propertyId` — ровно тот `id` колонки из схемы. Не выдумывай чужих id.
- `value` — значение в формате типа колонки (см. выше).
- `confidence` (0..1) — насколько явно факт назван:
  · 0.9–1.0: прямая однозначная реплика («бюджет — 500 000 рублей»)
  · 0.6–0.89: явно сказано, но есть контекстная неоднозначность
  · ниже 0.6: сомнительно — лучше не возвращать вовсе, чем ставить низкий confidence
- `quote` — дословная цитата из транскрипта, подтверждающая именно это значение.
- `timeSec` — секунда начала реплики-источника; 0 если не известна.

## Формат вывода
Верни СТРОГО валидный JSON-объект без markdown-обёрток и комментариев:
`{ "facts": [ { "propertyId": string, "value": string|number|boolean|array,

- Не смешивать факты разных сущностей (строго entityLabel).
- Не угадывать ISO-дату из относительных оборотов при отсутствии якорной даты.
- Не возвращать `propertyId`, которого нет в схеме.
```

## 2. `table-infer-schema` — DRAFT схемы таблицы по NL-описанию (pass 1)

- **Файл:** `backend/src/modules/ai/services/prompts/table-infer-schema.prompt.ts` · каллер `TableAgentService.runThreePassPipeline` (`table-agent.service.ts`)
- **Контракт:** `json_object` → `{ name, description, icon, entitySync: {type}|null, properties: [{name, type, isPrimary, config?}] }`. Парсится через `RawLlmSchemaZod` (мягкая схема Zod). Сервис жёстко нормализует результат.

  - `withAsrNote` не используется — не нужен (нет транскрипта).
  - Сервис делает повторные попытки (до `draftMaxAttempts`) и жёсткую нормализацию — промпт не обязан быть единственной защитой.
