# ТЗ: Спринты в Z

## 0. Интеграция с паритет-зонтиком трекера (2026-05-27)

Зонтик паритета (`plans/tz/2026-05-27-tracker-parity-with-competitors.md`)
замержен в `main` (Board / IssueChecklist / ProjectDocument / subtasks UI /
project-overview). Это меняет поверхность Issue/Project, поэтому 4 точечных
корректировки в этом ТЗ:

1. **DashboardDto спринта показывает бэйджи доски / чек-листа / подзадач** —
   у Issue теперь есть `boardId`, `checklistTotalCount/DoneCount`,
   `parentId`. На дашборде спринта рядом с задачей рисуем те же бэйджи
   что и в канбане: «Доска маркетинга» + «☑ 3/7» + «✓ 2/3».
2. **`SprintAnalystService.invalidateDashboardCache(cycleId)` эмитит
   `cycle.updated` event** через `TrackerEventsService` — у
   `OverviewCacheService` уже есть listener на это событие, он сбросит
   `project:overview:{projectId}`. Без этого виджет «Прогресс активного
   цикла» на `/projects/[slug]/overview` будет stale.
3. **Связанные карточки CRM убраны из дашборда спринта** — переиспользуем
   `GET /projects/:projectId/linked-cards` на уровне проекта
   (`/projects/[slug]/overview`). На дашборде спринта оставляем только
   «Связанные встречи» (`Meeting.linkedCycleId`).
4. **Inline-create задачи в дашборде спринта подставляет
   `boardId = projectDefaultBoardId`** — иначе свежая задача создаётся с
   `boardId=null` и пропадает с канбана. Default-доска определяется по
   `Board.isDefault=true` на projectId спринта.

**Tour-step «Спринты»** — оставляем заметку для автора
`tracker-onboarding-tour` (ещё не реализован): в Welcome tour и Project
tour добавить шаг про сайдбар «Спринты». На наш ТЗ не блокирует — все
target-элементы помечаем `data-tour-target="welcome.sprints"` и
`data-tour-target="project.sprints"` сразу.

## 1. Контекст

Реализовать фичу **«Спринты»** как бизнес-методологию управления компанией. Спринт = настраиваемый цикл работы команды с гибкой привязкой (компания / клиент / поставщик / отдел / сотрудник / проект). Помощник по спринтам (новый AI-агент) анализирует обсуждения на встречах и подсказывает руководителю, что идёт не так — но никогда не двигает задачи сам.

Подробное обсуждение архитектуры — в [файле анализа](../analysis/2026-05-27-sprints.md). Все 11 продуктовых/архитектурных вопросов закрыты решениями владельца.

## 2. Шесть продуктовых принципов

1. **AI не двигает задачи сам.** Только показывает, читает, подсказывает.
2. **Никаких жёстких ритуалов.** Никаких обязательных встреч в определённое время.
3. **Длина спринта — настройка**, не методология. 1/2/3 недели.
4. **Гибкая привязка спринта** — компания / клиент / поставщик / отдел / сотрудник / проект.
5. **Задачи добавляются вручную или через подтверждение во входящих.** Никаких автоматических созданий.
6. **Подсказки качества — сразу**, а не пост-фактум.

## 3. Архитектурные решения (краткое резюме 11 закрытых вопросов)

| # | Решение |

| 1 | В коде — `Cycle`, в интерфейсе — «Спринт» |
| 2 | 4 опц. поля привязки в `Project` (customer/vendor/person/department), UX = radio + combobox + inline create |
| 3 | «Спринт компании» = все 4 поля пустые |
| 4 | Цель спринта не задаётся при создании (V2) |

| 8 | Задача — только в одном активном спринте |

## 7. Открытые риски и митигации

| Риск | Митигация |
|---|---|
| Помощник по спринтам выдаёт слишком много шума (false positives) | Дедуп через `(cycleId, kind, hash)` + лимит max N=20 active hints на спринт + severity threshold + `dismissedAt` учитывается при ре-генерации (не предлагать заново то же самое в течение 7д) |
| LLM-стоимость на большом числе спринтов | Cron работает только для `Cycle.status='started' AND endDate > now`. На больших Org — батч 50 за тик. На фазе 2 померить cost-per-cycle через `AiUsageLog` |
| Конфликт ResourceType `sprint_hint` с другими RBAC-правилами | Дополнительно протестировать на manager:strict — должен видеть только своего проекта |
| Frontend WebSocket не успевает за изменениями SprintHint | Polling fallback каждые 30с на странице спринта |
| Финальный отчёт через `CardVersion(resourceType='cycle')` — куда смотреть UI? | На странице `/sprints/[id]/review` — отдельный endpoint `GET /cycles/:id/review` достаёт текущий `CardVersion` |
