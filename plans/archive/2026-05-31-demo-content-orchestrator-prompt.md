# Жёсткие правила работы

## Про sub-агентов

1. **Каждый sub-агент = одна узкая задача** (одна фаза или один seed-модуль). Не «реализуй всё ТЗ» — это растворит ответственность.
2. **Sub-агенты типа** `general-purpose`. Для чисто-исследовательских задач — `Explore`.
3. **Промт sub-агенту обязательно содержит**:
   - Ссылку на конкретный раздел ТЗ (например «реализуй §6.3.1 из ТЗ, файл такой-то»).
   - Какие файлы прочитать перед началом (всегда `types.ts` + эталонный модуль).
   - **Что вернуть в отчёте**: список изменённых файлов с путями, `git status` после своей работы, выхлоп `bun run typecheck` для backend.
   - **Запрет на коммиты** — sub-агент только пишет и проверяет. Коммитишь ТЫ.
   - Правило **«re-Read после каждого Edit»** — иначе пометит сделанным то, что не сделал.
4. **Параллельность**: запускай sub-агентов параллельно (в одном сообщении несколько `Agent` вызовов) **только если их файлы не пересекаются**. Карта зависимостей — в ТЗ §5. Например Фаза 6.1-6.6 разных файлов → параллельно; Фаза 1 (`seedUsers`) → перед всем остальным, последовательно.

## Про факт-чек после каждого sub-агента

После каждого возврата sub-агента — обязательно:

1. `Bash: git status` — проверить, что изменения действительно есть и в нужных файлах.
2. `Grep` ключевых маркеров в файлах (например после Фазы 4.2 — ищи `KnowledgeRiskSnapshot.create` в `pulse-snapshots.ts`).
3. `Read` свежесозданного файла — глазами проверить хотя бы 30 строк структуры.
4. `Bash: bun run typecheck` (в `backend/`) — на каждом шаге, не копи долгу.

Если sub-агент пометил [x], но файла нет / маркер не найден / typecheck красный — **верни ему задачу** через `Agent` снова с уточнениями. Не патчи сам.

## Про коммиты

После каждой ЗЕЛЁНОЙ фазы (typecheck + lint + относящиеся тесты):
```bash
bun run typecheck   # в backend/
bun run lint        # в backend/
# опционально: bunx vitest run <конкретный файл, если есть тест>
git add <явные пути>     # ❌ не git add -A
git commit -m "feat(demo): фаза N — короткое описание"
```

Сообщение коммита — Conventional Commits, на русском после префикса. Префиксы: `feat`, `fix`, `refactor`, `docs`, `chore`, `test`. Скоуп — `demo`, `onboarding`, `dashboard`, `billing`, … что больше всего тронуто.

⚠ **Никогда `git add -A` / `-u` / `.`**. Всегда явные пути.
⚠ **Никогда `--amend`**. Только новые коммиты.
⚠ **Никогда `git push`** без явного разрешения пользователя.
