# Трекер Z/Кора — паритет с Kaiten/Weeek/YouGile

## TL;DR

После 5 фаз трекера (фундамент, фронтенд, AI, РФ-слой, импорт) — недостающий функционал по сравнению с привычными для пользователя Kaiten/Weeek/YouGile. Шесть отдельных ТЗ, разрабатываются параллельно где возможно. Цель: пользователь, привыкший к Weeek/Kaiten, не теряет ни одной функции при переходе на нас. Срок: 7–9 человеко-недель суммарно.

## Контекст и обоснование

Пользователь приходит из Weeek/Kaiten с устоявшейся ментальной моделью:
- В проекте — несколько досок, не одна
- Внутри задачи — чек-лист «0/7» и подзадачи как разные сущности
- В проекте есть вкладки: Обзор, Задачи, Документы, Приложения, Настройки, Загруженность
- Первый вход — onboarding-подсказки

Если у нас этого нет — пользователь не сможет повторить привычный рабочий процесс и закроет приложение. **Стратегия паритета:** дать всё привычное, а сверху — наши преимущества (AI-задачи из встреч, видеовстреча из задачи, граф знаний). См. [plans/analysis/2026-05-23-tracker-as-entry-wedge.md](../analysis/2026-05-23-tracker-as-entry-wedge.md), часть 3 — UX-паттерны простоты.

## Что входит в зонтик

| # | ТЗ | Что добавляет | Сложность | Срок |
|---|---|---|---|---|
| 1 | [tracker-boards](2026-05-27-tracker-boards.md) | Несколько досок в проекте (модель Board + переключение) | M | 2 нед |
| 2 | [tracker-subtasks-ui](2026-05-27-tracker-subtasks-ui.md) | Дерево подзадач в карточке (модель есть, нужен UI) | S | 1 нед |
| 3 | [tracker-checklists](2026-05-27-tracker-checklists.md) | Чек-листы «0/7» внутри задачи (новая модель + UI) | S | 1 нед |
| 4 | [tracker-project-documents](2026-05-27-tracker-project-documents.md) | Вкладка «Документы»: ProjectDocument + связанные карточки | M | 1.5 нед |
| 5 | [tracker-project-overview](2026-05-27-tracker-project-overview.md) | Вкладка «Обзор» проекта + «Загруженность» + «Приложения» | M | 2 нед |
| 6 | [tracker-onboarding-tour](2026-05-27-tracker-onboarding-tour.md) | Тур по интерфейсу при первом входе | S | 1 нед |

**S** = small (≤1 нед), **M** = medium (1.5–2 нед), **L** = large (>3 нед).

## Зависимости и порядок выполнения

```
tracker-boards ──────────────┐
                             ▼
tracker-subtasks-ui ─────────┤
tracker-checklists ──────────┼─→ tracker-project-overview
tracker-project-documents ───┤
                             │
tracker-onboarding-tour ─────┘ (после остальных, чтобы туры покрывали финальный UI)
```

**Можно делать параллельно:**
- Волна 1 (3 нед параллельно): tracker-boards + tracker-subtasks-ui + tracker-checklists
- Волна 2 (2 нед параллельно): tracker-project-documents + tracker-project-overview
- Волна 3 (1 нед): tracker-onboarding-tour (после остальных)

**Критическая зависимость:** tracker-project-overview использует данные досок (количество досок, задач на доске) → начинается после tracker-boards.

## Что НЕ входит в зонтик (откладываем)

- **Time tracking / тайм-трекер** (как у Shtab) — отдельное ТЗ при запросе, не must-have для большинства SMB.
- **Custom поля задачи** (как у ПланФикс) — позже, после валидации MVP.
- **Несколько контактов на карточку** — отдельное ТЗ карточек.
- **Совместное редактирование документа в реальном времени** (Y.js / CRDT) — следующая итерация документов, MVP без realtime.
- **Импорт чек-листов из Weeek/Kaiten** — расширение существующих стратегий импорта (фаза 5), отдельным sub-ТЗ.

## Метрики успеха

- **Сравнительный тест:** взять чек-лист функций Weeek (бесплатный тариф) и Kaiten Free — пройти его на нашем продукте. После зонтика должны быть закрыты все пункты кроме сознательно опущенных в раздел «не входит».
- **Время до первой ценности (TTV):** новый пользователь от регистрации до первой созданной задачи в проекте — ≤5 минут (с onboarding-туром).
- **NPS вопрос «потеряли что-то по сравнению с предыдущим инструментом?»** — ≤10% ответов «да» на бета-группе.

## Связь с архитектурой Z/Коры

Этот зонтик — **поверх существующей архитектуры**, не ломает её:
- Граф знаний (`knowledge-core`) продолжает получать события из трекера. Новые сущности (Board, Checklist, ProjectDocument) тоже эмитят события, тип расширяется (см. отдельные ТЗ).
- AI-фичи (фаза 3) не трогаем — они продолжают работать поверх Issue.
- Multi-tenancy и RBAC — все новые модели имеют `tenantId`, новые ResourceType регистрируются в `policy.csv`.
