# Клон-стенд качества: аудит → проект → банк → методология → Слой 0 → передача

## Что было поставлено
Владелец: изучить в коде всё про создание клонов, зафиксировать как сейчас, предложить улучшения, спроектировать стенд на 100 узконаправленных вопросов (по образцу recall-стенда chat-v2) с линейкой оценки и петлёй итераций «до идеала», плюс заложить методологию создания стендов. Цель — «идеальный клон сотрудника»: уволился человек — клон отвечает как он или лучше, всегда как эксперт. Далее: передать пакет другому агенту.

## Как решал (файлы, коммит)
- Разведка: Workflow из 8 параллельных читателей (код clones/skills/practice-skills/knowledge-clone, планы, стенды, git-дельта) + критик полноты; фоновый агент рыночного ресёрча employee-clone.
- Написал 4 документа + handoff: `plans/analysis/2026-07-03-employee-clone-expert-answer-audit.md` (15 трещин Т1-Т15, 11 гипотез H1-H11), `plans/architecture/2026-07-03-clone-quality-stand.md` (линейка 5 осей, петля, 2 канала кормления, воронка, Слой 0), `docs/testing/clone-stand-questions.{md,json}` (110 вопросов, 13 категорий), `docs/testing/stand-methodology.md`, `plans/2026-07-03-employee-clone-quality-HANDOFF.md` (точка входа).
- Состязательная проверка: Workflow из 4 критиков (факт-чекер против кода, критик стенда, банка, методологии) → применил ~40 правок (вычислимость вердикта, probe-гейты Канала Б, покрытие трещин, устаревшие факты).
- Владелец одобрил Р1 (эксперт всегда), Р2 (проект), Р6 (последовательность ТЗ-0→ТЗ-1→петля), Р7 (Слой 0). По его наводке интегрировал `docs/methodology/synthetic-fidelity-eval-method.md` (Слой 0 — фиделити построения) во весь пакет.
- Коммит `cfee87c3` (6 файлов, docs-only), push в `work/2026-07-02`.

## Что вышло
- JSON банка валиден (110), все внутренние ссылки резолвятся, счётчики сверены.
- Прод-операций нет (только planning-доки, ни кода, ни миграций, ни ENV).
- Пакет самодостаточен для передачи: агент читает handoff + 4 дока и начинает с ТЗ-0.

## Чему научился (грабли и уроки)
1. **Клон спроектирован ПРОТИВОПОЛОЖНО замыслу владельца** — refusal-first (4 контура отказа), «экспертный» judgmental заперт за `CLONE_V2_ENABLED=false`. Замысел «эксперт всегда» = разворот прод-политики, нигде ранее не зафиксированный. Урок: перед проектированием стенда обязателен явный выбор владельцем «что считается идеальным поведением» — иначе стенд наказывает систему за её же спецификацию.
2. **Мис-атрибуция — главный риск любого стенда выхода.** Baseline «50 отказов» без Слоя 0 не различает «отказ из-за политики» (Слой 2/3) от «отказ из-за непостроенной черты» (Слой 0). Без разделения разворот чинит не тот слой. Слоистая модель (вход в базу vs выход) — обязательна.
3. **Правило №1 против тавтологии для клонов острое:** проверять, что черта ВЫВЕДЕНА из свидетельств, а не скопирована из сырья — иначе метрика липовая. Ground truth «по построению» без слепой разметки из источника вырождается в парафраз-цикл.
4. **Канал «расскажи, как решал» УЖЕ реализован** (Ф5/Ф6 06-29) — была ошибка в первичной оценке (думал, не доделан). Факт-чекер поймал по коду. Урок: технические утверждения аудита проверять состязательно против кода, а не по докам-idea-capture.
5. **Пере-сев расщепляется по слою:** фиделити извлечения — на существующей базе без пере-сева; фиделити синтеза черт — после кормления (база пуста). Наблюдение владельца было верным частично — важно назвать границу честно.
6. Мёртвые артефакты в коде: `CLONE_ASK_PER_USER_PER_DAY` (не потребляется), `PERSONA_BUILD_CRON` (декоратор хардкод), температуры режимов (не передаются) — легко принять за рабочие.
