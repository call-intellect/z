## Часть A — Слой-0 пере-проверка (консолидация сработала?)

Baseline ДО фикса (прямой запрос к БД):
- 171 активная Entity; **23 имени существуют как несколько Entity разных типов** (Битрикс=technology+vendor+product,
  Логистик Плюс=client+customer+vendor, retention=goal+topic+metric, …).
- Блокер «Битрикс 429» = **4 отдельных blocker-блока**; webhook-риск = **3**; идея «Моя история» = **2** idea-блока.

Что сделать:
1. Прямой read-only запрос (как `verify-dedup.ts`): посчитать активные Entity, «имён с несколькими типами»,
   и дубли блоков (429/webhook/«Моя история»).
2. Повторно прогнать fidelity по манифестам `strela-manifest.batch{1,2,3-rest}.json` — метод в методологии.

Приёмка Слоя-0:
- «имён с несколькими типами» **23 → ≤3**; «Битрикс»/«Логистик Плюс»/«retention» — по ОДНОЙ канонической
  сущности; общее число Entity упало (171 → ближе к ~143).
- Блокер 429 **4 → 1** canonical (с ≥4 evidence); webhook 3→1; «Моя история» 2→1.
- **Полнота не упала: 44/44 якоря всё ещё `found`** (иначе консолидация что-то потеряла — это регресс, зафиксируй).

## Часть B — Атрибуция до ОТВЕТА (главный вопрос владельца)

Владелец прямо спросил: «влияет ли это на ответ или нет?». ДО фикса банк давал **~77–79% recall УЖЕ с
дефектами** — значит дефекты не фатальны; надо доказать, СДВИНУЛА ли консолидация число.

Что сделать:
1. Прогнать recall-банк (`batch-recall-trace.ts`) ПОСЛЕ фикса, кэш очистить.
2. Оценить строго (панель судей / смысловая сверка против эталона — НЕ по сломанному `usedBlockIds`-флагу;
   см. дефекты линейки в recall-ceiling и ТЗ `2026-07-03-recall-eval-ruler.md`).
3. **Атрибуция по слоям** для каждого провала: факт есть в базе? (Слой 0) → поднялся в retrievalTrace? (Слой 1)
   → дошёл до контекста, но синтез не использовал? (Слой 3). Отнеси каждый провал к одному слою.
   - Связь вопрос↔ожидаемый-блок в банке пока НЕ размечена — либо размести `expectedManifestBlockIds` на
     ~30 якорных вопросах, либо делай лёгкую семантическую трассу (есть ли факт-эталон в базе → поднялся ли).
4. Особое внимание — **ведро ④** (targeted-резолв, напр. q008 «кто по фронтенду» → Анна): консолидация
   сущностей должна была помочь именно здесь. Проверь эти кейсы точечно.

Приёмка Части B — честный вывод:
- recall ДО (~77–79%) vs ПОСЛЕ (число);
- разбивка провалов по слоям {0/1/3};
- **прямой ответ владельцу: подняла ли консолидация recall, или граф стал чище без влияния на ответы.**
