# Playbook оркестрации fan-out

Цель — массовый параллельный сбор, где каждый суб-агент закрывает **одну** MECE-ветвь / контур своим способом, со **своим стартовым запросом** (иначе fan-out — эхо-камера).

## Механизм (в порядке приоритета)
1. **Workflow (primary).** Скилл исполняется в основном диалоге → доступен `Workflow`. Один скрипт фанаутит по контурам через `parallel()`, синтез — после барьера. Это тот же примитив, которым строятся сами скиллы.
2. **Agent (одиночный).** Для точечного глубокого разбора одного игрока/репо.
3. **Skill deep-research / dzen-content-research.** Готовые движки — вызывай как Skill с **узким** заданием на один сегмент.
4. **Fallback (нет Workflow/Agent — headless/субагент):** последовательные `Skill`-вызовы `deep-research` по сегменту за раз. Массовость сохраняется числом прогонов; в выводе честно «fan-out последовательный».

`WebSearch`/`WebFetch` — **deferred**: внутри суб-агента сперва `ToolSearch('select:WebSearch,WebFetch')`, потом вызов.

## Скелет Workflow-скрипта
```js
export const meta = { name:'feature-analyst-fanout', description:'...',
  phases:[{title:'Сбор'},{title:'Состязательная проверка'}] }
const CONTOURS = [
  {key:'foreign-func', q:'<зарубежные аналоги X — функционал, demo/отзывы>'},
  {key:'foreign-tech', q:'<их стек: GitHub/вакансии/dev-блог>'},
  {key:'ru-func',      q:'<российские аналоги X — лендинги/vc.ru/Habr>'},
  {key:'ru-signals',   q:'<госзакупки/тендеры по X — реальные внедрения+цены>'},
  {key:'oss',          q:'<OSS-аналоги X на GitHub — closed issues по проблеме>'},
]
const found = await parallel(CONTOURS.map(c => () =>
  agent(`Исследуй ОДИН контур "${c.key}". Стартовый запрос: ${c.q}. Верни per-source
  файл: карточки игроков (функц.+тех. разрезы), claim'ы с URL+дата+тег. ToolSearch
  WebSearch/WebFetch перед поиском.`, {phase:'Сбор', label:c.key, schema:SRC})))
// синтез ПОСЛЕ возврата всех; затем red-team:
const redteam = await agent(`Опровергни рекомендацию <...>. Свой НЕЗАВИСИМЫЙ retrieval
  (другие запросы, не та же выдача). Усиль отвергнутую альтернативу (steelman).`,
  {phase:'Состязательная проверка', schema:VERDICT})
```

## Промпты-заготовки под контур
- **Зарубеж-функционал:** «Пройди demo/trial/free-tier <продукта>, опиши job по шагам простым языком + гипотезу зачем так. Отзывы G2/Capterra: 20–30 свежих, повторяющиеся жалобы. URL+дата к каждому факту.»
- **Зарубеж-техника:** «Стек <продукта> по GitHub (repo/issues/commits), dev-блогу, вакансиям, changelog. Backend помечай `inferred` (профайлер слеп). Маппинг на стек Z.»
- **РФ-функционал:** «Российские аналоги <X>: Startpack/SaaS Rating/vc.ru/Habr/Telegram. Если dzen-content-research доступен (Playwright, не капча) — используй; иначе обычный web, пометь контур неполным.»
- **РФ-сигналы:** «zakupki.gov.ru + реестр Минцифры по <X>: реальные контракты, цены, заказчики — доказательство внедрений.»
- **OSS:** «GitHub OSS-аналоги <X>: звёзды, лицензия, темпоральный анализ коммитов (от чего отказались / куда движутся), closed-issues по конкретной проблеме фичи.»

## Воронка достаточности (анти-бесконечность / анти-недобор)
Зафиксируй до старта: `~N кандидатов найти → M отобрать для teardown`. Стоп — когда новые источники не двигают gap-таблицу и матрицу вариантов. Числа — в 00-index.

## Сбор и синтез
Синтезируй ТОЛЬКО после возврата всех per-source. Дедупликация игроков (один аналог — одна карточка), протокол сшивки и разрешение конфликтов цифр — см. `analysis-structure.md` и `source-evaluation.md`.

## Состязательный второй проход
Red-team — отдельный суб-агент с **независимым retrieval** (другие стартовые запросы, по возможности другой угол). Задача: опровергнуть рекомендацию, найти контр-источники, усилить отвергнутую альтернативу. Стоп: 1 проход без новых опровержений; нашёл — переписать вывод, повтор (макс. 2 раунда → иначе HIGH-развилка владельцу). Защита от self-preference: не оценивай свой первый проход как «уже доказано».
