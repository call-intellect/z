# 2026-06-13 — Редизайн кабинета: архитектура + HTML-прототипы + ТЗ (3 шага одной оркестрацией)

## Что было поставлено
После продуктового аудита кабинета (`plans/analysis/2026-06-12-product-audit-cabinet-ui-dashboards.md`) владелец дал практическую задачу из трёх шагов:
1. Архитектура будущего кабинета — точное меню, источники данных, что удаляем/объединяем/переносим, по каждому дашборду: какая инфа, есть ли она на сервисе или нужно дописать функционал/агентов.
2. HTML-прототипы всех экранов (главная, дашборды, очередь решений, трекер, календарь) + улучшить дизайн (ярче, объём, «плавающие плашки», свечение).
3. ТЗ на все изменения.
Доп. вводные по ходу: учесть **мобильную версию** (отдельно изучить — «только дашборды, быстро глянуть с телефона»); баги 500/404 владелец уже починил; на будущее — самому находить лучшее решение и не блокироваться вопросами.

## Как решал
**Разведка (2 волны параллельных агентов):**
- Основная волна — Workflow из 7 агентов: карта меню/роутов фронта (`Sidebar.tsx` захардкожен, 8 групп/~30 пунктов), бэкенд дашбордов (`DirectorDashboardController` + `OperationsDashboardController`, 14 виджетов агрегатора), матрица доступности данных (есть/частично/нет по 16 пунктам), дизайн-язык (`modern/tokens.ts`, oklch+стекло), безопасность удалений (deep-link-и бэка → redirect обязателен), трекер+календарь, выжимка 7 прежних ТЗ + инварианты владельца.
- Отдельный агент — мобилка: **открытие — мобильная версия УЖЕ реализована** (2026-06-11, Ф0–Ф7, ветка dev): `MobileShell` viewport-gate <768px, роль-зависимый `mobile-tabs.ts`, PWA, exec web-push. Владелец решал шире «только дашборды»: дашборды по роли + чек-ин + спросить, полный интерфейс — десктоп.

**Результат разложен через node на 7 .md** (workflow вернул JSON 184КБ — распарсил `node -e` в отдельные файлы, читал по частям; так не переполнил контекст).

**Шаг 1 архитектура** — `plans/analysis/2026-06-13-cabinet-redesign-architecture.md`: меню 30→8/5, 6 дашбордов→3 ритма (Сегодня/Неделя/Месяц), 4 очереди→1 «Требует вас», 8 пунктов Память→3 входа; по каждому экрану источник данных (эндпоинт+сервис+file:line) и вердикт есть/достроить/построить; развилки решил сам с обоснованием.

**Шаг 2 прототипы** — `plans/analysis/2026-06-13-cabinet-redesign-prototypes/`: сам написал ядро согласованности (`design-system.css` — зеркало `modern/tokens.ts`, усиленное: glow-блобы, `.glass.float`, свечение цифр) + оболочку с новым меню + эталонный экран «Сегодня». Остальные 9 экранов + мобилку делегировал Workflow из 10 агентов (каждый читает `design-system.css`+`part-today.html` как голден, пишет фрагмент). Сборка node-скриптом `build.mjs` (конкатенация — без CORS file://). Проверил в браузере через Playwright (file:// заблокирован → поднял `python -m http.server`, скриншоты всех экранов + ролевое переключение).

**Шаг 3 ТЗ** — `plans/tz/2026-06-13-cabinet-redesign-rhythms-and-decision-queue.md`: Ф0–Ф10 с привязкой к коду, порядок реализации, 4 новых блока (авто-название встреч, silence-детектор, merge отделов, UI поиска по памяти), инварианты владельца, развилки Р1–Р7.

Ролевое меню работает.

## Чему научился
- **Перед редизайном меню — обязательна разведка deep-link-ов бэка.** Многие роуты (`/decisions`, `/insights`, `/themes`, `/cards`, `/actions`, daily/weekly) зашиты в Telegram-пушах, нарративе дашборда и поиске (`narrative-citations-parser`, `daily-digest.service`, `specialist-*-probe`) — удалять нельзя, только redirect. Нашёл попутно 4 УЖЕ битых cron-ссылки на несуществующие страницы.
- **Мобилка может быть уже сделана** — не предполагать «надо создать»; сначала грепнуть (`MobileShell`, `mobile-tabs.ts`). Сэкономило целый пласт работы, свелось к «синхронно перекроить табы через единый nav-конфиг».
- **Прототипы лучше собирать из фрагментов** одним общим CSS (ядро пишу сам как голден, экраны — параллельные агенты по голден-эталону). Даёт и скорость, и единый визуальный язык. Сборка конкатенацией обходит CORS у file://.
- **Playwright блокирует file://** — для локального HTML поднимать `http.server`.
- Большой JSON-вывод workflow (>180КБ) парсить `node -e` в отдельные файлы и читать по частям — не переполняет контекст.
