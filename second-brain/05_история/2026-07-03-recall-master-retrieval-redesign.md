# Переработка recall «Мастера» (chat-v2 retrieval) — реализация 7 фаз + приёмка

## Что было поставлено

Реализовать ТЗ [`2026-07-02-recall-master-retrieval-redesign.md`](../../plans/tz/2026-07-02-recall-master-retrieval-redesign.md) — целостный контур поиска «Мастера», который перестаёт гасить сам себя структурным фильтром. Семь фаз (Ф1–Ф7), каждая **аддитивна и за kill-switch-крутилкой** (Ship-On: ON по умолчанию), Ф8 — замер перепрогоном тех же 111 вопросов «Стрелы» готовым харнессом. Целевые числа ТЗ: верно ≥85%, провал recall <10%, честность 0 галлюцинаций держится, обход по связям >60%, резолв сущности >65%.

## Как решал

Оркестрация фаза-за-фазой суб-агентами: на каждую фазу — картография кода, точный промпт кодеру, независимая приёмка (греп-маркеры / re-Read затронутых мест / свой `typecheck`+`lint`+`build`+unit-тесты по затронутым файлам) + ревью, коммит по фазам.

| Фаза | Коммит | Что делает |
|---|---|---|
| Ф1 — граф-всегда + инфра 10 крутилок | `b487ebe8` | `expandViaGraph` больше не выключается активным структурным фильтром — обход по связям блоков участвует всегда (при `graphHops>0`); заведены все 10 крутилок (registry + сид + feature-flags) |
| Ф6 — grounding понималщика | `e264fa9d` | перед `understand` в промпт подаётся справочник канонических названий тенанта (Entity/Theme, ILIKE/trgm по токенам вопроса, cap `chatV2GroundingTopK`); резолв синонимов точнее |
| Ф2 — фильтр как boost | `192c10e8` | структурный фильтр перестаёт быть AND-cutoff — совпадение даёт **прибавку к score** (`rankByStructuralBoost`), несовпавшее остаётся в пуле; `runStructuralRoute` не возвращает пустоту при нераспознанной сущности |
| Ф3 — EntityLink в recall | `6116ea86` | от резолвнутых `entityIds` идёт обход по `EntityLink` (вещь↔вещь) → блоки связанной сущности в пул (`expandViaEntityLinks`); трейс помечает via block-link/entity-link |
| Ф4 — каскад расширения | `9212fadf` | бедный/пустой пул → ступени (`applyCascade`): снять фильтр → углубить граф → честное «близкое, точного нет», не отказ |
| Ф5 — сводка широких/списков | `f05ceb19` | overview/list не отбрасывают перефразы; режим агрегации (`broadCoverage`) + полный перечень эпизодов (`listEpisodesByDateRange`) без ложного «других нет» |
| Ф7 — адаптивная глубина 1-2 | `33ddade8` | признак многошаговости (`detectMultiHop`) → `graphHops=2` на цепочечных вопросах, иначе 1; глубже идёт и block-link, и entity-link |

Затронутые файлы кода: `chat-v2-retrieval.service.ts` (expandViaGraph-всегда, `rankByStructuralBoost`, `expandViaEntityLinks`, `listEpisodesByDateRange`, 2-й block-link hop), `chat-v2.service.ts` (`applyCascade`, адаптивный `graphHops`, `detectMultiHop`, `broadCoverage`, `RetrievalResult`), `chat-v2-retrieval-trace.ts` (`viaSource` block-link/entity-link), `query-plan-extractor.service.ts` + `understand.prompt.ts` (grounding). Все 10 крутилок — через `getDynamic` + `admin-setting-schema-registry.ts` + сид `seed-admin-setting-chat-v2-recall.ts` (в STEPS `phase:'seed-base'`) + `feature-flags.md`.

Ф8 — перепрогон: очистил answer-кэш тенанта (Redis `dlg:ans:<tenant>`, 112 ключей), прогнал `batch-recall-trace.ts` на «Стреле» со всеми крутилками ON, оценил панелью из 8 независимых LLM-судей по эталонам. Отчёт «было→стало» — [`2026-07-02-recall-master-after-redesign.md`](../../plans/analysis/2026-07-02-recall-master-after-redesign.md).

## Что вышло

| Метрика | Было | Стало | Цель |
|---|---|---|---|
| Верно (CORRECT по эталону) | 59.5% (66/111) | **79.3%** (88/111) | ≥85% ⚠️ |
| Верно ИЛИ частично | ~59.5% | 91% (101/111) | — |
| Галлюцинации / выдумки | 0 | **0** | 0 ✅ |
| Неверно (WRONG) | 0 | 1 (q064) | 0 ⚠️ |
| Провал recall (ложно «не нашёл») | ~33% | **8.1%** (9/111) | <10% ✅ |
| Обход по связям включился (graphRan) | 14% | **100%** | >60% ✅ |
| Резолв сущности | 40% | 45% | >65% ⚠️ |
| Латентность (харнесс, завышена) | 53с | 59.4с | приемлемо |

Именованные кейсы приёмки — верны: «Что с ошибкой 429?» (был пустой отказ → блокировка Битрикса, backoff, поддержка; инверсия «точный вопрос хуже описательного» починена Ф2+Ф3), «Что с Zoom-интеграцией?» (нет интеграции, блокер продаж, статус выясняет Александр), «Что с интеграциями в целом?» (Битрикс + Telegram + Zoom без ложного отрицания, Ф5), «Кто отвечает за то, что блокирует продажи?» (цепочка блокер→Zoom→Александр через 2-hop, Ф7). Полный разбор — в after-report.

## Чему научился

- **Главный корень recall был не в графе, а в фильтре, который его гасил.** Сам граф-обход был реализован верно, но выключался при активном структурном фильтре (`!structural && graphHops>0`). Снятие этого гейта (Ф1) в одиночку подняло `graphRan` с 14% до 100% — самая дешёвая и самая крупная правка. Урок: перед тем как усложнять (AGE/эмбеддинги), проверить, не заглушён ли уже существующий механизм.
- **Boost вместо hard-cutoff + EntityLink чинят «парадокс точного вопроса».** Когда система распознаёт узел («429»), но у него нет прямых блоков, жёсткий фильтр давал пул=0 — точный вопрос отвечал ХУЖЕ описательного. Boost (не выбрасываем несовпавшее) + обход вещь↔вещь (429→Битрикс) убрали инверсию. Побочно: резолв сущности перестал быть узким местом — контур устойчив даже при 45% резолва (архитектура компенсирует boost'ом и графом).
- **Харнесс дважды зовёт понималщик → логируемая трасса ≠ трасса ответа.** `askEphemeral` внутри сам зовёт `dialog.process`, поэтому для трейса understand вызывается дважды, и из-за LLM-вариативности логируемая трасса может расходиться с трассой реального ответа (разный класс/период). Это объясняет ложные провалы q054/q060 («список за период») и завышенную латентность 59.4с. Урок: при диагностике recall не доверять логам трассы как трассе ответа — считать по строгим LLM-судьям.
- **Answer-кэш (Redis `dlg:ans:<tenant>`) обязательно чистить перед перепрогоном.** Иначе smoke-кэш возвращает старые ответы без трассы (route=null) — baseline это уже словил (8 вопросов из кэша). Перед замером — очистка ключей тенанта.
- **Честностная граница: 79.3% верно при 0 галлюцинаций — это граница честность↔охват, заданная самим ТЗ.** Часть false_empty (q025/q066/q067) — ответы, где нужный человек упомянут в контексте, но синтез отказался его назвать из осторожности (ровно механизм honest-abstain, держащий 0 галлюцинаций). Дожать до 85% нельзя без ослабления honest-abstain — это прямой обмен «галлюцинации ↔ охват», который ТЗ запретил. Дальнейший подъём — **решение владельца**, не технический дожим.
