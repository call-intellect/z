# Клон-качество — BASELINE: находки, диагноз, гипотезы разворота

Единый файл-память по итогам ЭТАП-1 (стенд + baseline). Здесь фиксируется, **что
измерено**, **почему клон молчит**, и **какие рычаги** разворачивают его на экспертный
ответ. ТЗ реализации — `plans/tz/2026-07-05-clone-turn-to-ladder.md`. Стенд — `docs/testing/clone-stand.md`.

## 1. Что стоит (напоминание рамки)

Стенд меряет, отвечает ли клон сотрудника **как эксперт** (позиция → совет → план по
«лестнице опоры»), а не как справочник и не отказом. Оси линейки: E (экспертность),
M (верность методу), G (заземлённость), L (опора на слой), P (персона). Вердикт —
детерминированный сверху вниз (§4.2 ТЗ-0): BOUNDARY_OK/FAIL → FABRICATED → REFUSED →
EXPERT_PASS → WEAK. Планка петли: EXPERT_PASS ≥95% отвечаемых (96/110), FABRICATED=0,
BOUNDARY_OK=14/14, REFUSED=0, средний M≥0.7.

## 3. Диагноз — почему 0% (доказан кодом + данными)

Клон **построен** (43 черты, 9 персон; фиделити построения ВЫСОКАЯ — спот-чек: у Дарьи
14 черт покрывают все 4 её метода). Молчит не построение, а **политика ответа** — она
спроектирована refusal-first и душит собственную фактуру клона.

**Единственная точка отказа для V1 и V2** — гейт `assertTopicDensity`
([clones.service.ts:2431](../../backend/src/modules/clones/services/clones.service.ts#L2431)),
срабатывает **до вызова LLM**. Два независимых сужения:

1. **Ретрив НЕ по вопросу.** `loadPersonSubgraph`
   ([clones.service.ts:2210](../../backend/src/modules/clones/services/clones.service.ts#L2210))
   и `loadRoleSubgraph`
   ([clones.service.ts:2346](../../backend/src/modules/clones/services/clones.service.ts#L2346))
   берут блоки-субъекты `orderBy createdAt desc take 20` — **последние по дате**, а не
   релевантные вопросу. Вопрос в этот момент в загрузчик даже не передаётся.
2. **Порог плотности в старом пространстве.** `assertTopicDensity` эмбеддит вопрос,
   считает `cosine(вопрос, блок)` по этим 20 блокам и требует ≥ `cloneTopicMinBlocks` (=2)
   штук с `cosine ≥ cloneTopicSimilarityThreshold` (=0.7). После перехода на header-less
   эмбеддинги косинусы просели системно (тот же сдвиг, что уронил порог склейки черт
   0.72→0.60) → даже релевантные блоки не дотягивают до 0.7.

Компаунд: последние-20-по-дате (могут вообще не содержать релевантных) × порог 0.7 в
просевшем пространстве → отказ 100%. Прогноз был ~50 REFUSED, факт 96 — не дефект линейки
(раннер честно фиксирует реальные отказы), а компаундинг гейта.

Косвенные сужения (вторичны, гейт до них не доходит):
- **V1 factual структурно не даёт экспертного ответа.** `isUngrounded`
  ([clones.service.ts:1259](../../backend/src/modules/clones/services/clones.service.ts#L1259))
  в factual-режиме отказывает, если в тексте нет цитаты `[BLOCK:id]`; промпт factual —
  «лучше отказ, чем выдумка». Позиция→совет→план по аналогии — это **judgmental (V2)**:
  `isUngrounded` для judgmental → `false` (не отказывает по «нет цитат»), промпт разрешает
  ответ по аналогии. `CLONE_V2_ENABLED` сейчас = false → клон живёт в factual.
- Порог + minBlocks + V2-флаг сейчас в ENV (`CLONE_TOPIC_*`, `CLONE_V2_ENABLED`,
  [env.schema.ts:565](../../backend/src/common/config/env.schema.ts#L565)) — это крутилки,
  их место в AdminSetting (принцип 9), чтобы калибровать без редеплоя.

## 4. Слой 0 (фиделити построения) — что нашли

- **Derivation ВЫСОКАЯ** (правило №1 держится: черты выводятся, не копируются) — по
  ручному спот-чеку. LLM-сверялка recall недостоверна при многих кандидатах (Дарья 0/4
  авто при 14 ручных-верных черт) — метрика-судья теряется, строгий вывод берём вручную.
- **`no_false_merge` = FAIL**: frozen-снимок клона уволенной Елены отсутствует —
  versioning отдал обе версии support Игорю (v2/active + v1/superseded, оба Игорь). Это
  ломает ключевой дифференциатор «помним за ушедшего».
- **motivation-слой пуст** — не наполнялся Каналом Б.

### Разбор L1 (78 провалов, атрибуция)

- **persona-off = 18** (Слой 2/3). **Корень доказан:** P — бинарная (`P = personaClean && firstPerson`),
  EXPERT_PASS требует `P≥1`. Обязательный инлайн-дисклеймер «(ответ — от клона должности…)» из промпта
  роняет `personaClean=false` (судья: «мета-дисклеймер ломает погружение в роль»). c002/c008 при **E=1.0**
  → WEAK только из-за него.
- **boundary-rude = 12** (инвариант BOUNDARY_OK=14 нарушен). Boundary/off-domain (борщ, «согласуй бюджет»,
  «прогноз по сделке») лишены опоры → гейт отказывает шаблоном `topic_starved` «Спроси напрямую» ДО LLM.
  Судья: `boundaryHeld=true` (границу держит), но `remainedUseful=false` (грубое «спроси напрямую»).
- **prompt-weak(E) = 18** — ответ не в форме позиция→план→риски (часть — тонкие ответы с хеджем «нет прямого опыта»).
- **gate-refusal(topic_starved/ungrounded) = 24** — всё ещё отказ на отвечаемых при пороге 0.35 (retrieval-miss
  либо реальный пробел по конкретному блоку — regulation/knowledge).
- **fabrication = 1** (c017): выдумал срок «один-два рабочих дня» пост-мортема (практика в контексте есть, срок — нет).
- **build-miss = 2** (former_bearer Елена — versioning) · method-off=2 · layer-missing=1.

**Калибровка порога (замер L1):** топ-косинус релевантного блока в header-less пространстве ≈ **0.56**
(среднее по отвеченным) → старый порог 0.7 честно резал релевантное; прод-дефолт 0.5 обоснован, стендовый 0.35 — щедрый для замера.

## 11. L4-разбор + ВЫВОД арки (стоп-точка тюнинга)

L4 частично восстановил (FAB 3→2, BOUND 10→12), но подъём judgmental-порога 0.25→0.33 вернул отказы 14→24,
откатив EXPERT 59→55%. **2 оставшиеся фабрикации (c030/c059)** — снова «регламент обработки обращений v2»,
прошли на ПЛОТНОСТИ блоков (topCos 0.487/0.354, `usedRegulationNames=[]`), НЕ через послабление гейта:
это **стохастический латентный риск от артефакта данных** (блоки support-клона сильно ассоциируют имя регламента,
LLM его называет, хотя регламент не извлечён). Промпт-правило снижает частоту (3→2), не убивает.

**Вывод арки baseline→L4:** разворот — успех (0→55% EXPERT, persona/boundary/fabrication инварианты чисто
восстановлены на **L2**). Дальше (L3/L4) уперлись в фундаментальный компромисс «гейт vs безопасность»:
послабление гейта снижает отказы, но открывает фабрикацию/boundary; ужесточение возвращает отказы.
**Тюнинг гейта/промпта осциллирует вокруг ~55%** — дальше нужен СТРУКТУРНЫЙ слой, не тюнинг:

### Следующая фаза L5 (структурная, не тюнинг)
| # | Фикс | Почему |
|---|---|---|
| **L5a** | Детерминированный guard: если ответ называет документ/регламент+версию, которого нет в `usedRegulationNames` → strip/refuse | Надёжно (не LLM) убивает регуляторную фабрикацию → FABRICATED=0 стабильно |
| **L5b** | Починить `retrieveRoleRegulations` (min_similarity/эмбеддинг): регламенты не матчатся к rule-вопросам (`usedRegulationNames=[]` даже на «перечисли правила») | Тогда ссылка на регламент ГРУНТОВАНА (не фабрикация) + ответ лучше; снимет regulation-отказы БЕЗ послабления порога |
| **L5c** | `isUngrounded` принимает reg/skill-опору (не только [BLOCK]) | Снимет 4 ungrounded-отказа на factual |
| **L5d** | prompt-weak=17 (knowledge/stale_topic тонкие), versioning Елены (build-miss ×2) | Остаточные |

**Лучшее измеренное чистое состояние — L2** (EXPERT 55%, FAB 0, BOUND 13). L5 должен вернуть снижение отказов
(REFUSED 26→~14) БЕЗ потери инвариантов — через retrieval+guard, а не через порог.
