# Диагноз recall «Мастера» — числа + план починок

> Парный к `2026-07-02-recall-master-poisk-kak-rabotaet.md`. Данные: 111 вопросов, 12 углов, тенант «Стрела» (4 недели, 292 блока, 5193 связи), полная трассировка через внутренности + строгая смысловая сверка каждого ответа с эталоном.

## Главные числа

| Метрика | Значение |
|---|---|
| **Отвечает ВЕРНО** (смысл совпал с эталоном) | **66 / 111 = 59.5%** |
| Провал recall (данные есть, ответ неверный/неполный/пустой) | 37 / 111 = 33% |
| Честно молчит на несуществующем (правильно) | 8 / 8 |
| **Галлюцинации / выдуманные факты** | **0 / 0** |
| Неверный ответ (перепутал) | 0 |
| Обход по рёбрам (граф) включился | 14 / 103 = **14%** |
| Граф заглушён структурным фильтром | 88 раз |
| Ложных отказов с выключенным графом | **22 / 24** |
| Распознал нужную сущность | 39 / 97 = **40%** |
| Маршрут both / semantic-only | 64% / 36% |
| Цепочки-диалоги держат контекст полностью | 2 / 4 |

**Читается так:** система честная (не врёт, на пустом молчит), но «всегда найдёт ответ» — пока нет: каждый третий вопрос теряет при наличии данных.

## Корни провалов (по числам, ранжировано)

1. **Граф выключается фильтром — главный (86% пропусков графа).** Обход по рёбрам отключён, когда активен структурный фильтр; 22 из 24 отказов — с выключенным графом. Механизм, который дотянулся бы до связанного, не работает ровно там, где нужен.

2. **Слишком буквальный фильтр по сущности-узлу → пустой пул.** Когда сущность распознана (429, Zoom), фильтр ищет блоки, привязанные прямо к узлу, и получает 0 (блоки висят на соседних сущностях). Отсюда парадокс: точная формулировка отвечает хуже описательной. Инверсия воспроизведена на парах 429 и Zoom.

3. **Широкие / списочные вопросы теряют охват и отрицают существующее.** «Что с интеграциями в целом?» → «других не зафиксировано» (а Zoom/Telegram есть). «Покажи все встречи за неделю» → 1 из 10. Опасно: уверенная неполнота выглядит как факт.

4. **Клиент/сущность теряет ключевые факты.** Вопросы про Ромашку не отдают критичную жалобу «отчёт не формируется» и запрос Telegram — узкий фильтр отсекает часть блоков сущности.

5. **Распознавание сущности слабое (40%)** — и, как ни странно, в среднем помогает (пусто 15% против 28%), кроме случая №2.

6. **Цепочки местами рвут контекст** (2 из 4 — идеально, 2 споткнулись на первом-втором ходе).

## Что работает хорошо (не сломать при починке)

- **Честность.** 0 галлюцинаций, 0 выдумок, 8/8 честных «не нашёл» на несуществующем. Это дорогого стоит — фундамент доверия.
- **База и граф построены здорово** (292 блока, 5193 осмысленных связи, люди привязаны).
- **Экспертиза человека и риски** отвечаются хорошо; синонимы часто срабатывают.
- **Синтез и follow-up** в диалоге — в основном держат контекст и не сваливаются в сырой JSON.

## План починок (от дешёвого к глубокому)

### Фаза 1 — дёшево, высокий рычаг (дни)
- **Дать графу работать вместе с фильтром.** Снять безусловное отключение обхода по рёбрам при активном структурном фильтре; либо: если фильтр дал пул меньше порога — расширять графом. Чинит корень №1 (22/24 провалов).
- **Widening при пустом пуле.** Если узкий фильтр по сущности-узлу дал 0 — автоматический откат на семантику + граф, а не отказ. Чинит корень №2 (парадокс 429/Zoom).

### Фаза 2 — средне
- **Широкие/списочные вопросы:** агрегировать шире и не отрицать существующее; формулировать «вот что нашёл, возможно не всё» вместо «другого нет».
- **Списки встреч:** отдавать полный перечень записанных встреч, а не 1 из 10 и не уходить в календарь.
- **Grounding понималщика:** подсовывать короткий справочник реальных названий тенанта перед построением запросов — чинит инверсию и поднимает распознавание.

### Фаза 3 — глубже (по данным)
- Полнее/мягче распознавание сущностей.
- Стабилизировать перенос контекста в цепочках.
- Измерять долю многошаговых вопросов (гейт «когда включать глубокий граф / AGE») — инструментация трассировки для этого уже есть.

## Оговорки по методологии (честность замера)
- **8 вопросов пришли из кеша ответов** (после smoke-прогона) — их внутренняя трасса не снята, но сами ответы валидны; трасс-статистика графа считается на 103, не 111.
- **Латентность 53с завышена** двойным вызовом понималщика в тест-харнессе (нужно для снятия переформулировок); реальный путь пользователя быстрее.
- **Инструментация трассировки** добавлена в код опционально (при выключенном трейсе прод-путь байт-в-байт прежний, typecheck зелёный, 69/69 тестов). В прод не закоммичена — решение оставить её как постоянную наблюдаемость recall за владельцем.
