# 2026-06-11 — Read-only аудит безопасности всего кода Z/Кора

## Что было поставлено
Владелец: read-only security research всего проекта. Ничего не чинить — только найти и задокументировать. Приоритет угроз: (1) утечка между тенантами, (2) утечка системных промптов и данных в LLM, (3) дыры auth/authz, (4) секреты, (5) инъекции/SSRF/path, (6) доступ к файлам/S3, (7) утечки в логах/метриках, (8) supply chain, (9) веб-периметр. Выход — один файл `plans/analysis/2026-06-11-security-audit.md`: сводка по severity, таблица находок, топ-5. Ultracode включён + явная просьба «запускай агентов».

## Как решал
- **Разведка бэкбона вручную** (до агентов): прочитал `main.ts`, `app.module.ts` (регистрация guard'ов), `crypto.service`, `tenant.guard`, `tenant.middleware`, `jwt.service`, `cookie-auth.guard`, `livekit.service`, `all-exceptions.filter`, `env.schema`, CORS-конфиг. Это дало **ключевой инсайт**, который заложил в промпт всем агентам: глобальные `APP_GUARD` = только `Subscription/Entitlement/MustChangePassword/DemoObserver`; `CookieAuthGuard`+`TenantGuard` НЕ глобальные (per-controller opt-in); `TenantMiddleware` ставит `req.tenantId` из `X-Org-Id` без проверки membership. Без этого контекста агенты плодили бы ложные срабатывания.
- **Workflow** (`wf_5afd2f30-bef`): 12 finder-агентов по областям → pipeline-верификация (каждая находка состязательно перепроверяется отдельным агентом с re-Read кода и проверкой митигаций) → структурированный JSON. 53 суб-агента, 1091 чтение, ~742с. Скрипт сначала не распарсился (вложенные backtick'и `$queryRaw` в тексте промпта + мёртвый блок) — переписал через `Write` в `.mjs` и запуск через `scriptPath`.
- **Независимая якорная находка**: пока workflow крутился, сам прошёл по `search.controller` → `search.service` и подтвердил crit cross-tenant холодными руками (с точными строками) до того, как агенты вернулись. Это дало мне опорную точку для сверки их вердиктов.
- Распарсил 275КБ JSON результата через `node -e` (важно: результат вложен под ключ `result`, не на верхнем уровне), выгрузил полные поля в дампы, перенёс в отчёт с дедупликацией.

## Что вышло
- 41 находка от агентов → **34 подтверждено, 5 опровергнуто (с обоснованием по коду), 2 needs-check** → после дедупликации **33 уникальных**.
- По severity: 🔴 2 crit, 🟠 11 high, 🟡 5 medium, ⚪ 13 low, ❔ 2 needs-check.
- **2 crit**: cross-tenant в `/api/v1/search` (PII+документы+решения чужой Org) и в видимости встреч при `scope='org'` (отчёт/транскрипт/видео/аудио + список) — обе нашёл и я, и агенты независимо.
- Систематический корень всех cross-tenant: tenant-изоляция **fail-open** (нет глобального `TenantGuard`, `req.tenantId` из заголовка без membership). Самый рычажный фикс — структурный (SEC-03).
- Коммит `5685cd0f` в ветку `feature/meeting-cabinet-fixes-2026-06-10`. Временные артефакты (скрипт workflow, дампы) удалил.

## Чему научился
- **Состязательная верификация окупается на security-аудите**: 5 из 41 находок были ложными (CSP на JSON-API без HTML; `javascript:`-URL, которые React 19 сам санитизирует; drift реестра npm, закрытый `--frozen-lockfile`+integrity). Без verifier-прохода они бы попали в отчёт как реальные.
- **Опорный контекст в промпте агентам критичен**: ручная разведка бэкбона guard'ов до fan-out резко повысила точность вердиктов (агенты сразу проверяли «есть ли `TenantGuard` на классе», а не гадали).
- **Workflow-скрипт — чистый JS, без вложенных backtick в строках промптов**; результат фонового workflow приходит в `<task-id>.output` под ключом `result`, читать через `node`, а не `Read` (275КБ > лимита).
- В Z **221 контроллер**, и `CookieAuthGuard`/`TenantGuard` — opt-in: это структурный класс багов, который надо закрывать машинным CI-гардом, а не точечно.
