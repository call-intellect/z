## 3. Сквозные мысли и решения сессии (чтобы не забыть)

1. **Хаб уже построен.** `IngestService.ingest → RawEvent → block-ingest (нарезчик) → IdeaBlock + 56 signalType → block-distill → RouterService`. Любой источник входит в одну дверь и размечается ярлыком.
2. **Хаос = обход хаба, а не его отсутствие.** Три обхода: детектор конфликтов (regex по тексту чек-ина), задачи (5 путей), обещания (3 потребителя). + единичные деривативы создают сущности без `signalType` (ThemeSilence→Insight).
3. **Принцип-инвариант стандартизации:** *любой агент берёт сущность из графа по `signalType` (из хаба), не читает сырьё и не ходит в источник.* Новый нарезчик = новый `case` в router + 1 специалист, а не новый воркер со своим чтением.
4. **Не один мега-агент, а 2 прохода.** Нарезчик остаётся (кормит ВСЮ память, не только сущности). 13 специалистов → **1 комбо-извлекатель** (всё из куска за раз). Сверка-с-памятью/дедуп/рёбра — отдельный общий шаг (нужен весь граф, не один текст).
5. **Комбо уже доказан:** на встречах 1 проход бьёт 8 раздельных мастеров **18:13 по качеству и 3.7× по цене**. Надо: обобщить с «только встречи» на все каналы + добавить цели и задачи (сейчас 8 из 10) + в admin-registry. ⚠ риск prompt-cache при дроблении — расширять внутрь комбо, не разбивать наружу.
6. **~12 «настоящих» бизнес-сущностей** достаём из текста (см. список ниже §4); остальное — фундамент графа или производное.
7. **Реалистичная цель — не «всё в нарезчики», а ~25–35 агентов:** слить извлечение в 1 проход + вырезать дубли/обходы. «Думающих ИИ» среди них меньше десятка.
8. **Приоритет слияний:** конфликты (дёшево, твой триггер) → задачи (доказано) → probe-слой → комбо (нужен замер) → дедупы деривативов.

## 4. Артефакт: 3 полки СОЗДАТЕЛЕЙ сущностей (из чата — фиксирую, чтобы не потерять)

**Полка 1 — работают С нарезчиком** (берут кусочек по `signalType` из хаба) → **кандидаты на схлопывание в 1 комбо:**
3-3 решения · 3-1 регламенты · 3-1-process-detector процессы · 3-5 инсайты · 3-6 идеи · 3-7 навыки · 3-2 клон-знаний · 3-8 helpfulness · 3-9 эксперименты · 3-14 цели · 3-15 задачи · 3-12 personal-relation (конфликты) · 3-4 project-customer (триггер Card) · 3-8 role-map · 3-13 sprint-helper. **+ КОМБО (8–9 сущностей за раз, meeting-only).**

**Полка 2 — работают ВОКРУГ нарезчика** (из графа, по расписанию, строят высшие сущности) — **НЕ трогать по сути, только убрать дубли (⚠):**
гигиена графа (entity-resolver, graph-builder, block-linker, reframing) · темы (clusterer/summarize/reframing ⚠) · кластеры (idea ⚠ insight) · профили (knowledge-clone, **7 навыковых**, persona, role-*) · компания/структура (profile/summary/department/domain/maturity) · снапшоты дашборда (forecaster/engagement/**bus-factor⚠knowledge-at-risk**/health/velocity/goal-vector) · чек-ины (day-report-collector, **sentiment⚠reflection-quality**, burnout) · признание (contribution/badge/streak/recognition) · регламент-консолидатор · задачная петля (completion/reconcile/progress/goal-link) · **curation-lifecycle⚠task-reconcile (expire)**.

**Полка 3 — УШЛИ В СТОРОНУ** (создают сущности В ОБХОД хаба) → **вернуть в хаб, не схлопывать:**
1. CheckInConflictDetector — regex по тексту чек-ина → ребро конфликта (твой триггер).
2. meeting-extract-actions — читает полный транскрипт → IntakeIssue.
3. telegram-task-parser — текст бота → IntakeIssue напрямую.
4. me-tasks — фраза помощнику → Issue сразу.
5. meeting-report-fast.tasks — мёртвый выход.
6. ThemeSilenceDetector — Insight без `signalType`.
7. promise-keeper/cascade/network — читают commitment (сносится).

**Список ~12 сущностей (Ярус 1):** Решение · Задача · Идея · Цель · Инсайт/проблема · Эксперимент · Регламент/процесс/политика/инструкция · Знания человека (клон) · Навык · Помощь/вклад · Конфликт · Обещание (факт). Полностью — в [[2026-06-29-agents-plain-language-and-collapse-thesis]] Ч.5.
