# Project Overview — Z / Кора (память компании)

## Что это

Кора (текущее имя кода — Z) — **память компании**: единый граф знаний из всех источников (встречи, чаты, email, звонки, документы, ручные заметки). Категорийное позиционирование зафиксировано в [[../06_marketing/positioning]].

**Первая реализованная вертикаль — AI-видеовстречи на LiveKit** (см. ниже § MVP-вертикаль). Архитектурно встречи — один из источников ingest; следующие источники подключаются через тот же pipeline (`Source` → `RawEvent` → knowledge-core).

Кора деплоится отдельно: свои серверы, своя база, свой код. Crossmark — **одна из внешних интеграций** (среди источников ingest), которая встраивает функциональность Коры в свой пользовательский интерфейс **через программный интерфейс (API)**; архитектурно эти два продукта друг от друга не зависят. Подробнее: [[../01_projects/crossmark-integration]].

LiveKit используется как медиа-движок (аудио/видео/screen share — звук, видео, демонстрация экрана), вся бизнес-логика — на нашем бэке.

## Главная ценность

Пользователь не просто провёл встречу, а сразу получил результат: задачи, решения, follow-up, CRM-заметку, риски, следующий шаг. AI-отчёт **подбирается под тип встречи**, а не «универсальное саммари». На уровне компании всё это копится в едином графе — поиск, AI-чат и дашборд директора работают через всё накопленное.

**Стратегический разворот (2026-06-29):** Кора позиционируется как **AI операционный директор / Chief of Staff** для SMB — память под капотом, а сверху проактивный операционный слой: утренние брифы (`personal-daily-brief`, `exec-morning-push`), дайджесты день/неделя/месяц, очередь решений (`pending-actions`), синтез блокеров, нуджи (`proactive-watcher`). Этот слой уже боевой в коде (`operations/proactive/goals/pending-actions`). Встречи — **первый источник графа**, а не весь продукт. Актуальное позиционирование — [[../06_marketing/positioning]]; карта способностей C1–C12 операционного директора → модули — планируется отдельной заметкой `chief-of-staff-capability-map.md`.

## Основной флоу

1. Авторизованный пользователь создаёт встречу в ЛК → выбирает тип встречи (один из 9).
2. Backend создаёт комнату LiveKit, генерирует `host_token` и `guest_link`.
3. Гость заходит по ссылке без регистрации, указав имя.
4. Во время встречи: камера, микрофон, screen share, чат, участники.
5. Ведущий запускает запись. Egress пишет два формата:
   - общая запись (видео + общий звук + screen share);
   - **отдельные аудиодорожки** на каждого участника (критично для AI).
6. Файлы сохраняются в S3-compatible (Yandex / Selectel / SberCloud / MinIO).
7. После завершения встречи запускается AI-обработка: транскрибация → разделение по спикерам → шаблон по типу встречи → отчёт.
8. Пользователь видит карточку встречи: запись, транскрипт, саммари, задачи, решения, follow-up, отчёт по типу.

## MVP-вертикаль: AI-встречи на LiveKit

**Входит:**
- 1 встреча = до 10 участников
- 9 типов встреч (см. [[../01_projects/meeting-types]])
- общая запись + отдельные аудиодорожки
- AI-отчёт по типу встречи
- гостевой вход по ссылке без регистрации
- поднять руку (см. `plans/analysis/2026-05-06-raise-hand.md`)

**Не входит:**
- вебинары на 100+
- большие конференции
- breakout rooms
- сложные роли зрителей
- зал ожидания

## Принципы

- LiveKit — только медиа. Бизнес-логику в LiveKit не кладём.
- Все LiveKit-токены генерирует только backend. Гость не получает секреты.
- Egress держим **отдельно** от LiveKit SFU (запись съедает CPU и роняет качество звонков).
- В прод нельзя ставить всё на один сервер — разделять SFU / Egress / TURN / Backend / PostgreSQL / Storage.
- Не полагаться только на общий аудиомикс — AI-анализ требует отдельные дорожки на каждого участника.
