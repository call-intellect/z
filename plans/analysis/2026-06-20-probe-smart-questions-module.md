# Умный модуль уточняющих вопросов (probe): разбор класса + доказательство решения

> **Зачем документ.** Владелец получил дайджест уточняющих вопросов, на которые невозможно
> ответить: «Кто отвечает за этот регламент?», «Можете уточнить, пожалуйста?», «К какому
> отделу это относится?». Задача — разобрать модуль целиком, найти **класс** дефектов,
> спроектировать лучший модуль, **доказать решение реальным прогоном LLM** и оформить ТЗ.
> Парный контракт — `plans/tz/2026-06-20-probe-smart-questions-module.md`.

## 1. Как устроен модуль (факт по коду 2026-06-20)

Три слоя:
1. **Наблюдатели** — ~12 специалистов Слоя 3 (`backend/src/modules/knowledge-core/services/specialist-3-*-probe.service.ts`, `processes/.../process-template-probe.service.ts`, `knowledge-core/workers/block-ingest.worker.ts` и др.). Находят пробел → зовут `ProbeService.suggest({ reason, payload{message, contextCardTitle, suggestedActions}, recipientCandidates, priorityHint })`.
2. **Голос Коры** — LLM `probe-formulate` (`knowledge-core/prompts/probe-formulate.prompt.ts`) превращает сигнал в тёплый вопрос; затем LLM-судья `probe-quality-judge` (`probe/prompts/probe-quality-judge.prompt.ts`, Фаза 2, 2026-06-18).
3. **Доставка** — `ProbeDispatcherWorker` (немедленный push, priority ≥ 70) или `ProbeDigestCron` (дайджест, всё остальное).

Вход: пробел в графе. Выход: текст вопроса в Telegram/MAX/кабинет.

## 2. Класс дефектов (почему вопросы без контекста) — подтверждён по коду

| # | Дефект | Доказательство (path:line) | Класс/кейс |

До LLM доходят только хинты ровно 0.7. | `probe.service.ts:196-197`, `probe-dispatcher.worker.ts:181`; распределение хинтов — греп `priorityHint:` (18 точек, медиана 0.5) | класс (системно) |

**Регрессия-первопричина:** `second-brain/03_processes/probe-question-flow.md:74,114` фиксирует, что fallback диспетчера = `payload.message`. В текущем коде `message` из цепочки **выпал**, заменён статической заглушкой (`probe-dispatcher.worker.ts:308-311`). Отсюда потеря контекста.

**Что НЕ дефект:** сам промпт `probe-formulate` и судья — хорошие (см. §4). Фаза 2 (2026-06-18) добавила судью/дедуп/re-ask/повод атрибуции, но **дайджест-байпас (Д1) не трогала**. ТЗ `2026-06-11-probe-question-context-leak-fix` — про фронт-рендер блока «Контекст», другой канал.

## 3. Доказательство: бенч на реальной LLM

Харнесс `backend/scripts/eval/probe-module-bench.ts` — 15 синтетических кейсов (10 «надо спросить» по всему классу reason'ов + 3 adversarial: коды-латиница, мульти-сущность, пустой вход + 2 noise: общее слово, ответ уже во входе). Модель — прод-primary `deepseek-v4-flash`. Скоринг: детерминированный (назвал объект / один «?» / чистота / длина) + LLM-судья контекста (отвечаемость 1–5) + точность гейта.

### 3.1 Кандидаты
- **A — текущий модуль:** базовый промпт + «грязный» `contextCardTitle = message.slice(100)` (как в проде).
- **B — улучшенная формулировка:** чистое имя объекта + русский тип + жёсткое правило «НАЗОВИ ОБЪЕКТ» + запрет пустого «Можете уточнить».
- **C — B + гейт ценности:** перед формулировкой LLM решает `ask/skip` (молчит, когда опереться не на что).

### 3.2 Результат (12 кейсов, где НАДО спрашивать)

| Кандидат | назвал объект | отвечаемость (1–5) |
|---|---|---|
| A (текущий) | 92% | 4.00 |
| B (формулировка) | **100%** | 4.25 |
| C (B + гейт) | **100%** | **4.33** |

**Гейт ценности (C):** шум корректно промолчал 2/3; **ложных пропусков на нужных вопросах — 0/12.**

### 3.3 Качественные доказательства (выжимка)
- `adv-empty` (пустой вход): **A** → «Для какого шага какого процесса не указан результат?» (отвечаемость 1, бесполезно); **C** → **ПРОМОЛЧАЛ** («нет конкретного объекта, нет сути — вопрос был бы пустым»). Это убийство класса «Можете уточнить» в корне.
- `noise-generic` («отчёт»): **A** → спрашивает привязку общего слова; **C** → **ПРОМОЛЧАЛ**.
- `reg-owner`: **A** → «Кто отвечает за регламент по фиксации договорённостей на совещаниях?» (отв. 3); **B** → «Кого вы видите ответственным за регламент «Фиксация договорённостей на совещаниях»?» (отв. 5).
- `adv-codes` (CompanyProfile cmpzl… без Mission/Vision): все 3 кандидата чисто убрали латиницу/cuid (правило 4 промпта работает).

### 3.4 Состязательная таблица (сведение)

| Критерий | A | B | C | Победитель |
|---|---|---|---|---|
| Называет объект | 92% | 100% | 100% | B/C |
| Отвечаемость (человек за 15 сек) | 4.00 | 4.25 | 4.33 | C |
| Молчит, когда спрашивать нечего | нет | нет | **да (2/3)** | C |
| Не пропускает нужные вопросы | — | — | **0 пропусков** | C |
| Транслитерация брендов (Acme→Акме) | да | да | иногда нет | A/B |

**Вывод:** побеждает **C** — улучшенная формулировка + гейт ценности. Решает обе цели владельца: (1) всегда спрашивает, где нужно (0 пропусков); (2) вопросы с контекстом (100% названо, отвечаемость 4.33) и без пустышек (гейт). Единственная правка к C — сохранить из B жёсткую транслитерацию латинских имён.

## 4. Лучшее решение (доказанное) → вход для ТЗ

**Единый «умный конвейер» вопроса**, общий для push и дайджеста:
`гейт ценности (ask?) → формулировка (называет объект) → судья качества → доставка`, с детерминированными фолбэками (message, не пустая заглушка).

Структурно (порядок фаз — в ТЗ):
1. **Стоп-кран дайджеста** (детерминированный, без LLM): `deriveQuestion` использует `humanize(message)` до статической заглушки; закрыть DEFAULT-дыру + машинный гард паритета LABEL↔FALLBACK; убрать дублирующую скобку.
2. **Общий `ProbeFormulationService`** — вынести `formulate()`+`judgeQuality()` из диспетчера (без смены поведения), чтобы дайджест звал то же самое.
3. **Улучшенный промпт формулировки** (proven B) + **чистый объект на входе** (фикс `contextCardTitle` у структурных эмиттеров — фикс класса Д5).
4. **Гейт ценности** `probe-value-gate` (proven C) — kill-switch ON; убивает «Можете уточнить» в корне.
5. **Дайджест формулирует через общий сервис** (закрывает Д1/Д2) — kill-switch ON; фолбэк на §1 при LLM-off.
6. **Судья видит объект** — бракует вопросы, потерявшие имя (защита-сеть).

**Совместимость с prompt caching:** все новые/изменённые SYSTEM-промпты (формулировка, гейт) стабильны, переменные данные — в конце USER (правило `feedback_llm_prompts_cache_friendly`). **Автономность:** гейт и судья — без human-in-the-loop (`feedback_no_human_in_loop_for_clone_learning`); флаги — kill-switch (Ship-On).

## 5. Открытые развилки (закрыты владельцем 2026-06-20)
- **Объём:** оба блока — стоп-кран + LLM-конвейер в дайджесте. ✅ выбрано владельцем.
- **Где формулировать:** лениво в дайджест-кроне, не в `suggest` (не жечь LLM на дедуп/истёкших probe, не тормозить hot-path ingest). ✅ решено (Б-обоснование в ТЗ).
