## 1. Исходное предложение (ДО состязательной проверки)

> ⚠️ Сужено после red-team — см. §7. Короче: в чат идут только Tier 0+1; оркестратор уходит за явную кнопку «Глубокий разбор» (не в горячий путь чата); Tier 2 строится отдельным grounded-агентом, НЕ на ExecutablePersona.

### Трёхуровневая агентная архитектура ответа

### Tier 0 — Понимание запроса (расширить dialog-layer)
Новый мини-агент `dialog-extract-plan` (один дешёвый cache-friendly LLM-вызов, рядом с классификатором): из любого вопроса извлекает **структуру**:
```
{ mode, timeRange{from,to}|asOf, entities[], departmentOrTheme[], signalTypes[], person("я"→personId), aggregation, needsAction }
```
В системный промпт зашиты сегодняшняя дата + таймзона Org + правила границ периода («эта неделя = пн–вс»). `intent` перестаёт быть только метрикой — становится сигналом маршрутизации. Это закрывает корневую слепую зону (§6 99-synthesis).

### Tier 1 — Роутер (точка экономии токенов)
По структуре из Tier 0 — развилка:
- **Дешёвый прямой путь (≈80% запросов: lookup / статус / темпоральный диапазон / провенанс):** существующий `chat-v2` retrieval, НО со **структурными фильтрами** (дата-диапазон / signalType / entity / тема), используя хранимые даты. Один retrieval + один synthesis. Recall-safe (red-team): узкое окно → pgvector ≥0.8.0 iterative scan / partial index / партиции по дате; широкое → overfetch+post-filter. **Без оркестратора** — дёшево и быстро.
- **Тяжёлый путь (сложное / аналитика / сравнение / хронология / «что важного» / требует действия):** включить **существующий оркестратор**, подключив его к чату; он планирует и порождает нужные стратегии-субагенты над **уже отфильтрованным** (по времени/сущности) срезом, синтезирует, **верифицирует**.

Роутер = кост-гейт: тяжёлая мульти-агентная машина запускается только когда вопрос реально её требует. Дешёвые модели на извлечение/маршрутизацию, capable-модели — только на глубокий анализ.

### Tier 2 — Динамические специалисты (идея владельца)
Добавить оркестратору 5-ю стратегию `specialist_analysis`, которая берёт **сгенерированный ролевой промпт** через механизм **ExecutablePersona** (напр. «аналитик-маркетолог»), прогоняет по отфильтрованному срезу и выдаёт **дополнительный слой анализа + рекомендованное действие**. «Пустая заготовка + промпт» — уже существующий примитив; новый специалист = написать промпт, а не код. Это «больше инструментов и возможностей», о которых просил владелец.

> ⚠️ Развилка из red-team (предварительно): «клон стиля» (думать как сотрудник) и «фактический аналитик» — разные задачи; специалист-аналитик должен опираться на отфильтрованные факты графа с цитатами и анти-выдумка-гардом, а не «играть роль». Уточнить в ТЗ; не смешивать с персональным клоном.

### Temporal — по-взрослому
Хранимые даты — полноценное измерение фильтра + bi-temporal рёбра (`validFrom/validUntil`, флаг `biTemporalEdgesEnabled` уже есть) для «что актуально сейчас / что изменилось за период» (отвечает на «кто СЕЙЧАС отвечает за X», а не свалку истории).

## 2. Почему это лучшее (доказательство)

**Матрица (критерии = ограничения и приоритеты Z):**

| Критерий (источник) | Прямой пост-фильтр (пред. предложение) | **Агентная оркестрация (реком.)** | Полный Zep/Graphiti rebuild |
|---|---|---|---|
| Покрытие классов запросов | время+тип (узко) | весь спектр (lookup→аналитика→действие) | факт-эволюция, но не агрегации |
| Переиспользование готового | частичное | **максимум** (оркестратор+persona+search+специалисты) | минимум (новый движок) |
| Единый стек (CLAUDE.md §7) | ✅ | ✅ | ❌ Neo4j+Python |
| Профессионализм/надёжность | базовый | **верификация+ретрай, изоляция контекста, лимиты уже есть** | высокий |
| Оптимизация токенов | высокая | **высокая через роутер-гейт** (тяжёлый путь только по нужде) | низкая (LLM на ingest) |
| «Больше инструментов» (запрос владельца) | нет | **да** (specialist_analysis = промпт, не код) | частично |
| Соответствие бренду (клоны/уходящие) | нет | **да** | да |
| Время-до-ценности | быстро/мелко | поэтапно, дешёвый путь сразу | долго |

**ADR-логика:** «лучшее» = по пригодности под ограничения Z, не по моде. Прямой пост-фильтр — простой, но не профессиональный и узкий (владелец отверг). Полный Zep — мощный, но второй движок против единого стека и дорог. Агентная оркестрация **выигрывает, потому что 90% дорогих частей уже написаны** — это превращает «амбициозно» в «средней сложности», а роутер-гейт держит токены под контролем.

## 3. Оптимизация токенов (явно — приоритет владельца)
1. **Роутер-гейт:** мульти-агентный путь — только для сложных/аналитических/action-запросов; массовый lookup идёт дешёвым одиночным retrieval+synthesis.
2. **Дешёвые модели на служебных шагах:** extract-plan / маршрутизация / verify — `deepseek-v4-flash`; capable — только на специалист-анализ/синтез.
3. **Cache-friendly промпты:** дата/схема в стабильном SYSTEM, переменная часть — вопрос ([[feedback_llm_prompts_cache_friendly]]).
4. **Существующие лимиты оркестратора** (depth=1, лимит субагентов, таймаут) — анти-перерасход уже встроен.
5. **RetrievalCache/AnswerCache** уже есть — переиспользовать на дешёвом пути.

## 4. Последовательность (с учётом надёжности и токенов)
- **Волна 1:** Tier 0 (extract-plan с датой) + Tier 1 дешёвый путь со структурными фильтрами + recall-safe. Закрывает время/тип/сущность/«я» — массовые бытовые вопросы. Оркестратор не трогаем.
- **Волна 2:** подключить оркестратор к чату за роутером ТОЛЬКО для сложных запросов (сравнение/хронология/аналитика); включать через kill-switch с наблюдением.
- **Волна 3:** Tier 2 `specialist_analysis` (динамические ролевые аналитики) + bi-temporal «что изменилось».
- **Волна 4:** отдельный salience-scorer «что важного пропустил» + проактивный recap.

## 5. Риски / открытые развилки (финализируются после red-team)
- **[крит.]** Латентность: оркестратор поллит каждые 1.5с, таймаут 15 мин — для разговорного чата нужен SSE-стрим прогресса и/или «глубокий разбор» как явный режим, не дефолт. (red-team п.1)
- **[крит.]** Почему оркестратор сейчас OFF — выяснить контекст до включения в горячий путь (зрелость/инцидент). (red-team п.2)
- **[крит.]** Динамический промпт-специалист vs галлюцинации: специалист-аналитик ≠ клон стиля; нужен факт-граунд + цитаты + анти-выдумка. (red-team п.4)
- **[ср.]** Надёжность LLM-маршрутизации (цена ошибки в обе стороны) — fail-safe в дешёвый путь.
- **[ср.]** Cold-start ExecutablePersona (нужны traits).

## 6. Открытые вопросы к владельцу
1. **Тяжёлый путь — в основном чате (за роутером) или отдельной кнопкой «глубокий разбор»?** Рекомендую: за роутером, но с явным стрим-индикатором «собираю развёрнутый ответ…», и порогом сложности повыше (экономия + UX). Почему: не превращать каждый чат-вопрос в 15-минутную мульти-агентную задачу.
2. **specialist_analysis — переиспользовать ролевые ExecutablePersona или отдельный «аналитик-шаблон»?** Рекомендую: отдельный аналитик-шаблон (факт-граунд+цитаты), а персональные/ролевые клоны оставить для «думать как X». Почему: не смешивать стиль и факты (риск выдумки).

## 7. Состязательная проверка (red-team) и ФИНАЛЬНАЯ рекомендация

Red-team (независимый проход, code-verified) — вердикт **`survives: ЧАСТИЧНО`**. Это авторитетный итог; §1 — исходный черновик.

### Что выжило (ядро ценности — строим в чат)
- **Tier 0 — понимание запроса:** slot-extractor (структура + сегодняшняя дата + таймзона Org + «я»→personId), `intent` становится РОУТЕРОМ. С метрикой мисроутов и **безопасным дефолтом в дешёвый путь при низком confidence**.
- **Tier 1 — дешёвый прямой путь со структурными фильтрами** (дата-диапазон / signalType / entity), recall-safe pgvector. Здесь вся доказанная экономия токенов (−39% — `[triangulated`: mindstudio 2025]) и покрытие массовых запросов.
- **Temporal как измерение** — хранимые даты + bi-temporal рёбра за уже существующим флагом (`chat-v2-retrieval.service.ts:80-107,474`), БЕЗ оркестратора.

### Что НЕ выжило в чате — оркестратор (SBA δ-1) в горячем пути
`[verified` по коду]:
- **Латентность минуты, не секунды:** синхронный поллинг каждые 1.5с (`orchestrator.service.ts:20,290-320`), таймаут 15 мин (`orchestrator.config.ts`); путь = plan+spawn+poll+synthesize+verify(+retry) — до ~9-13 LLM-вызовов против 2 на прямом пути (5-7× стоимость).
- **Транспорт несовместим:** `chat-v2` — синхронный `Promise`, без SSE; оркестратор — SSE-only. «Подключить в чат» = переписать транспорт чата на стрим, это НЕ «связать готовое».
- **Флаг-сирота:** `ORCHESTRATOR_ENABLED=false` ради cost-safety, только happy-path тесты (нет тестов на латентность/частичные падения/стоимость), не зарегистрирован в `docs/operations/feature-flags.md`; исходный план «OFF→test-tenant→включим» нарушает Ship-On (CLAUDE.md §8, [[feedback_ship_on_flags]]). Вход из Concierge так и не сделан (grep `orchestrator` по `concierge/` = 0).
- **Мисроут асимметричен:** простой→«сложный» бьёт по UX И бюджету сразу.
- **РЕШЕНИЕ:** оркестратор оставить на его **собственной SSE-поверхности `/orchestrator/runs/[id]`** (она уже построена) — за явной кнопкой **«Глубокий разбор»**, где минутная латентность и стоимость — осознанный выбор пользователя (прогрессивный ответ: быстрый дефолт + опциональный долгий drill-down). Перед включением: снять флаг с сироты (строка в `feature-flags.md`), добавить тесты латентность/падения/стоимость, привести к Ship-On (kill-switch, без фазы «test-tenant сначала»).

### Что НЕ выжило совсем — Tier 2 на ExecutablePersona
`[verified` по коду]: анти-deepfake-гард клонов (`clone-respond.prompt.ts:48-53,110-113`) **прямо запрещает** оценки/прогнозы/рекомендации и при <2 reasoning-блоков по теме даёт ОТКАЗ; персона компилируется как **стиль** («думать как X»), не как аналитик (`executable-persona-compile.prompt.ts:16`). То есть «промпт вместо кода» — ложная экономия: для фактического анализа нужен **отдельный grounded-агент** (факты графа + обязательные цитаты + анти-выдумка), отдельным ТЗ. Идея владельца «агент-маркетолог анализирует и предлагает действие» — валидна, но строится как новый grounded-специалист, не переиспользованием клон-примитива.

### Финальная рекомендация (одной формулой)
**В чат:** Tier 0 (понимание+роутер) + Tier 1 (структурные фильтры + recall-safe + temporal). **За кнопку «Глубокий разбор»:** существующий оркестратор на своей SSE-поверхности, после де-сиротизации флага и тестов. **Отдельным ТЗ:** grounded-специалист-аналитик (не ExecutablePersona). Экономию токенов даёт роутер+дешёвый путь, а не оркестратор — поэтому в горячем пути остаётся именно дешёвое и надёжное.

### Что это меняет для владельца
Все твои цели сохранены, но разнесены по правильным местам: **даты** — используются по-взрослому (Tier 1); **оркестратор** — используется (но там, где минута ожидания уместна, а не в живом чате); **динамический агент-аналитик** — будет (но как надёжный grounded-агент, а не клон-стиль). Это и есть «профессионально и надёжно»: red-team уберёг от медленного/дорогого/рискованного в горячем пути.
