# Боевой прод-тест клона должности + ТЗ расширения signalType (methodology_step)

## Что было поставлено
Владелец: полная проверка **обновлённого** модуля создания клона сотрудника на тестовом аккаунте — насоздавать сотрудников/«переговоры», прогнать цепочку, в реальном бою посмотреть, что попадает в БД, что создаются скиллы и описание клона. Уточнение по ходу: проверять **через интерфейс на проде** (а не на стенде), найти последние изменения по клонам, и если сегодня нельзя прогнать — залить максимум синтетики на завтра.

## Как решал
1. **Изучил обновлённый конвейер клона** (2 суб-агента + чтение кода): цепочка ingest → block-ingest (signalType + subject) → диспетчер 3-7-skill → SkillProfile → rebuild (skill-trait-detect) → концепты → verify → ExecutablePersona → ответ клона. Слой метода (value/motivation/process-marker/RolePrinciple/CDM, ТЗ 2026-06-12), «один человек = один клон» (2026-06-16).
2. **Каналы входа на проде** (Playwright korateam.ru, аккаунт owner «ооо ромашка»): «Создать → Мысль» → `/dump` → `POST /api/v1/ingest/dump {text,nonce}`. Помощник/чат память НЕ пополняет.
3. **Залил корпус** «руководителя маркетинга»: 18 «решений» + 11 «подхода». Граф наполнился (102→120 сущностей, дедуп CAC×9 наглядно).
4. **Диагностика через UI-реестры + diag-clone.ts** (написал read-only скрипт: skill-profile/list-clones/run-cron под супер-админ-ботом diag).
5. **Доказательный разбор решения** (4 суб-агента: охват/классификатор/семантика/риски) → ТЗ Вариант A.

## Что вышло
- **Цепочка технически исправна** (ingest, граф, subject-атрибуция, профиль, дедуп — всё работает), но **клон не построился**: `buildVersion=0`, черт 0.
- **Находка №1:** формулировки «решил X потому что Y» → реестр «Решения» (signalType `decision`), не в клон.
- **Находка №2 (корень):** формулировки про подход конвейер метит как **`methodology_step`** («Шаг методологии», 13/20 блоков), `motivation`, `decision` — а клон кормится строго **`{reasoning, rationale, decision_basis}`** и при `<5` делает полный skip. `methodology_step` = «как сотрудник работает» = ядро клона, но до клона не доходит. → у активных Org **0 клонов**.
- **ТЗ написано** `plans/tz/2026-06-22-clone-signaltype-methodology-step.md` (+orchestrator): расширить набор-потребитель на `methodology_step` (единая константа + 3 рубежа + backfill, без правки LLM-классификатора и без миграций). Доказано против B (переучить классификатор — недетерминирован, ломает prompt-cache) и C (снизить порог — не решает).
- Коммиты `1891f741` (ТЗ+анализ+diag-clone+реестр), `7462d12b` (чужие анализы) → `origin/dev`.

## Чему научился
- **Параллельные сессии в общем `C:/work/z` опасны для untracked.** Другая сессия сделала `git stash` (`wip-before-dev-switch`) + `checkout dev` + `pull` — мои незакоммиченные ТЗ ушли в **`stash@{0}^3`** (untracked-tree stash). Восстановление точечно: `git checkout 'stash@{0}^3' -- <путь>` (НЕ применять/удалять весь stash — там чужой WIP). tracked-правка (реестр) откатилась — переприменил Edit'ом. Урок усиливает [[feedback_parallel_sessions_git_check]]: после долгой работы проверять `git status`/ветку ПЕРЕД тем, как полагаться на файлы на диске.
- **Безопасный коммит при чужом staged:** `git commit -- <явные пути>` (+ glob `04_*` чтобы не вводить кириллицу в shell); затем `git pull --rebase --autostash` (autostash прячет/возвращает чужие staged). Никогда `git add -A` когда в индексе чужое.
- **Канал `/dump`:** пакетный fetch требует заголовок `x-org-id` (иначе 403 `tenant_required`); есть rate-limit (429) — лить с паузой ~700мс.
- **Наблюдаемость на проде:** прямого Prisma к прод-БД нет (`DATABASE_URL` локальный), сырые `pending_verification`-черты через API НЕ видны (всё фильтрует `active`). `org-admin/knowledge/metrics` (owner) даёт счётчики графа; UI-реестр «Сущности» → клик на Person показывает привязанные блоки + их тип (так и нашёл корень).
- **Форс конвейера на проде:** `POST /api/v1/admin/crons/:name/run` (super-admin) запускает любой `@Cron` вручную (имя = `ClassName.method`, напр. `SkillTraitVerifyCron.tick`) — тождественно ночному расписанию.
- **Баг-класс, а не кейс:** набор `{reasoning,rationale,decision_basis}` скопирован литералом в ≥6 местах (subject-атрибуция · гейт-воркер · loadSubjectReasoningBlocks · role-principle · 2× clone-subgraph · persona-validation) — рассинхрон и есть корень. Чинить единой константой, а не одной строкой (есть скрытый второй гейт в воркере).
