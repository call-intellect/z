# Главная страница Кора — зонтик «Demo-Org + Tabs»

## Контекст

Сейчас главная страница `/dashboard`:
- Накопила 25+ блоков (пост-Pulse v2 + smart-tables + наша вчерашняя полировка).
- Работает через **копирование демо-данных в каждую новую Org** (старая модель из ТЗ `2026-05-31-demo-auto-seed-and-cleanup.md`), что выкачено и **уже работает** (тост «Готовим демо-данные…» — это оно).
- Не имеет различения «эталон vs своя пустая Org» в UI: пользователь после оплаты получает «ещё одну такую же демо», но без помеченных данных, и не понимает что это его собственная Org.

Параллельно владелец зафиксировал **две независимые цели**:

| Цель | Дочернее ТЗ | Природа |
|---|---|---|
| **A. Единая эталонная Demo-Org** — один shared «ТехноСтрим», все наблюдатели как `demo_observer` | [demo-shared-org-model](2026-06-01-demo-shared-org-model.md) | Backend-fundament + миграция existing Org |
| **B. Tabs + sticky Hero** — главная как «пульт компании», 4 таба, AssistantSidebar.Спросить | [dashboard-main-tabs-restructure](2026-06-01-dashboard-main-tabs-restructure.md) | Frontend-UI поверх существующего API |

Они **должны выкатываться согласованно**, потому что UX главной зависит от обеих:
- Hero KPI и виджеты табов показывают **данные эталона** для observer и **пустоту/skeleton** для своей Org.
- EmptyState на главной — общий компонент, но **рисунок** зависит от контекста (своя пустая vs пустой таб эталона).
- Кнопки CTA в Hero (например, «Запланировать звонок» для топ-1 риска) — `disabled` в эталоне для observer, активны в своей Org для owner.

Этот зонтик закрывает 3 риска несогласованной выкатки:
1. **UI выкачен раньше backend** → пустая своя Org показывает «не настроена», но org-switcher'а ещё нет — пользователь застрял.
2. **Backend выкачен раньше UI** → demo_observer уже работает, но Hero показывает старый mosaic-layout 25 блоков — UX не улучшен.
3. **Edge-case: оплата** → при FSM `DEMO→ACTIVE` listener удаляет membership к эталону + `currentOrgId` переключается на свою; новая своя Org встречается **новым** UI (Hero + табы + EmptyState) — обе части должны быть готовы.

**Главный вывод матрицы:** «своя Org с DEMO» — это **отдельное состояние страницы**, не вариант табов. Tabs/Hero/Pulse-виджеты — для «есть данные». Когда данных нет (свежий owner, не оплатил, нет встреч) — рендерится одна полноэкранная карточка `MainEmptyState` со ссылками «Посмотреть демо» (через org-switcher) и «Оплатить подписку».

Это **арбитраж** между двумя дочерними ТЗ:
- В [dashboard-main-tabs-restructure](2026-06-01-dashboard-main-tabs-restructure.md) Фаза 6 описан **per-таб** empty-state.
- В [demo-shared-org-model](2026-06-01-demo-shared-org-model.md) §5.6 описан **полно-страничный** EmptyState для своей пустой Org.

Они **сосуществуют на разных уровнях**:
- Полно-страничный — когда Org = своя, Subscription = DEMO, данных нет вообще → замещает Hero + Tabs.
- Per-таб — когда Org уже работает (своя ACTIVE или эталон), но конкретный таб не имеет данных.

## Разрешение точек контакта между двумя ТЗ

### 1. Hero KPI (3 числа) в эталоне vs своей пустой Org

| Источник | Решение |
|---|---|
| dashboard-main-tabs-restructure Фаза 2 описывает Hero из 3 KPI с CountUp + sparkline. | В эталоне KPI работают из реальных Pulse-данных. |
| demo-shared-org-model §3.4 описывает org-switcher и поведение «своя пустая Org». | В своей Org с DEMO — Hero вообще не рендерится (правило 3 матрицы), вместо него полно-страничный EmptyState. |

**Арбитраж:** в `DirectorDashboardClient` верхним условием — проверка `Subscription.status === 'DEMO' && !Org.isReferenceDemo && noData`. Если true — рендерится `<MainEmptyState />` и больше ничего. Иначе — Hero + Tabs.

### 2. CTA-кнопки в Hero (например, «Запланировать звонок» в топ-1 риске)

| Контекст | Поведение |
|---|---|
| Эталон + `demo_observer` | `disabled` + tooltip «Это демо. Оплатите чтобы создавать в своей компании». При клике — открыть `<PaywallDialog>` или редирект `/settings/subscription`. |
| Эталон + `super_admin` | активны (bypass guard). |
| Своя Org + `ACTIVE` | активны, paywall не показывается. |

Реализация: в Hero пробрасывается `rbacContext` из `auth-context`, флаг `isReadOnlyDemo = role === 'demo_observer'`. Кнопки получают `disabled={isReadOnlyDemo}` + `aria-describedby` с подсказкой.

### 3. AssistantSidebar.«Спросить» (LLM-чат)

| Контекст | Поведение |
|---|---|
| Эталон + `demo_observer` | Чат-инпут **работает** (read-only LLM запрос — не пишет данных). Это соответствует open question Q3 анализа demo-shared-org. Можно ввести rate-limit per-user через существующие quota (ai-chat-quota). |
| Своя Org + любая роль | Чат-инпут работает как обычно. |

Реализация: `DemoObserverGuard` **не блокирует** LLM-эндпоинт (`POST /api/v1/concierge/ask` или эквивалент), потому что он не мутирует доменные данные. Декоратор `@PublicDemo()` (из demo-shared-org-model §4.3) ставится на этот эндпоинт.

### 4. Онбординг-блок «Настройка 0/6»

| Контекст | Поведение |
|---|---|
| Эталон + любая роль | **не показывать никогда** — эталон уже настроен, и кнопка «настроить» к нему не применима. |
| Своя Org + `owner`/`admin` + DEMO | По правилу 3 матрицы — Hero+Tabs не рендерятся, рендерится полно-страничный `MainEmptyState`. **Онбординг встроен внутрь EmptyState** как один из CTA («Настроить компанию» рядом с «Оплатить»). |
| Своя Org + `owner`/`admin` + ACTIVE + 0/6..5/6 | Полный онбординг-блок между Hero и Tabs (правило 4 матрицы). |
| Своя Org + `owner`/`admin` + ACTIVE + 6/6 | Компактная плашка «✅ Компания настроена · N дн.» на 30 дней, потом скрывается. |
| Своя Org + `member` | Никогда не показывать (правило 5). |

Реализация: 4 состояния онбординга обрабатываются единым компонентом `OnboardingProgressBanner`, который сам решает что рендерить по `(orgContext, role, subscriptionStatus, setupProgress)`. Размещение — между Hero и Tabs.

### 5. Org-switcher

| Источник | Решение |
|---|---|
| demo-shared-org-model §5.2 описывает org-switcher с двумя Org (эталон + своя). | Это **единственный** источник правды для org-switcher. |
| dashboard-main-tabs-restructure его не трогает. | OK, не дублируем. |

**Связь:** когда пользователь в эталоне и кликает свою Org в switcher'е — `currentOrgId` меняется, `DirectorDashboardClient` ре-маунтится (или просто перерисовывается), правило 3/4 матрицы выбирается заново. Tabs `localStorage` (`dashboard.lastTab.<userId>`) — **per-user**, не per-Org. Если пользователь привык к табу «Команда» — он откроется и в эталоне, и в своей Org. Если в текущем Org+Role этот таб пуст — отрабатывает per-таб empty-state или защёлкивается на «Обзор» (выбираем дефолт «не переключать таб насильно», пусть пользователь сам поймёт что пусто).

### 6. EmptyState компонентов

| Уровень | Компонент | Когда показывается |
|---|---|---|
| Страница (замена Hero+Tabs) | `MainEmptyState` (из demo-shared-org-model §5.6) | Своя Org + DEMO + нет данных |
| Таб (замена контента активного таба) | `TabEmptyState` (из dashboard-main-tabs-restructure Фаза 6) | Все виджеты таба пусты, но Org работает (своя ACTIVE без встреч, или эталон+observer но в каком-то узком разделе нет данных) |
| Виджет (один из виджетов в табе) | `WidgetEmptyState` (опц., каждый виджет сам решает) | Только если виджет считает разумным показать что-то, иначе → `null` и его скрывает родитель |

Чёткое правило: рендерится **не более одного empty-state одного уровня одновременно**. Если страница в empty — не рендерим табы/виджеты. Если таб в empty — не рендерим внутри его виджеты.

### 7. Кнопка «💬 Спросите Кору» под Hero

| Контекст | Поведение |
|---|---|
| Любая Org с Hero (правила 1/2/4/5/6 матрицы) | Pill-кнопка под Hero, клик открывает AssistantSidebar на табе «Спросить». |
| Своя Org + DEMO (правило 3, MainEmptyState) | Кнопка либо встроена в EmptyState как один из CTA («Спросите про Кору»), либо AssistantSidebar остаётся плавающей FAB справа (она там уже есть глобально из `AuthenticatedShell`). |

Решение: AssistantSidebar — глобально для всего ЛК (это уже так). Pill-кнопка под Hero — дополнительный entry point, не дублируется в EmptyState.

## Acceptance criteria зонтика (общий DoD)

Помимо DoD каждого дочернего ТЗ, для общей сборки должно выполняться:

1. **Матрица соблюдается во всех 6 строках** (см. раздел «Матрица»). Каждая строка проверена вручную в smoke (В.6).
2. **MainEmptyState и TabEmptyState не дублируются** на экране одновременно — действует правило «один уровень empty одновременно».
3. **Org-switcher** показывает обе Org для нового пользователя; после оплаты собственной Org — эталон исчезает из switcher'а (membership `demo_observer` удалён listener'ом).
4. **CTA-кнопки в Hero** корректно disabled/enabled по матрице, при клике disabled — открывается `PaywallDialog` или редирект на `/settings/subscription`.
5. **Онбординг-блок** виден только в правильных условиях (правила 3, 4 матрицы) — никогда в эталоне, никогда для member.
