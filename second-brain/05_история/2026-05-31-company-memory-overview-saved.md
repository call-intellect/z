# Сохранил обзорную карту второго мозга компании-клиента

Пользователь попросил объяснить «как у нас тут устроен второй мозг» и сохранить объяснение, чтобы не переанализировать в будущем.

3. **Сохранил** в [[../02_architecture/company-memory-overview]] как обзорную карту-онбординг, добавил строку в `index.md` секция «Архитектура».
4. Commit `db19cd9` `docs(second-brain): обзорная карта второго мозга компании-клиента` → push `35e9ecb..db19cd9 dev -> dev`.

## Чему научился

**Главный урок:** фраза «второй мозг» в Z **двусмысленна** — это либо наш разработческий `second-brain/` (папки), либо продуктовая память компании-клиента в Коре (граф знаний). При вопросах «как у нас работает второй мозг», «куда это сохранить», «как устроена эта база» — **первый ход: уточнить, о какой системе речь**. Они вообще не пересекаются: одна про правила работы Claude и разработчика, другая про knowledge-core с IdeaBlock/Entity/Specialists/Curator/Chat-v2/Probe.

**Прикладной урок (для следующего раза):** обзорная архитектурная карта верхнего уровня хорошо ложится в `02_architecture/<name>-overview.md` — отдельно от детального `02_architecture/<feature>.md`. Overview = онбординг + ссылки на детали; feature = техническая истина с воркерами и SQL.
