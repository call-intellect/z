# ТЗ — переработка recall «Мастера» (chat-v2 retrieval) на целостный контур

**Принцип.** Поиск «Мастера» перестаёт гасить сам себя структурным фильтром. Понимание вопроса → мягкая подсказка (boost), а не забор (AND-cutoff); обход по связям (блоков И сущностей) участвует всегда; пустой пул → каскад расширения, а не отказ; широкий вопрос → сводка без ложного отрицания. Всё аддитивно, каждое поведение за kill-switch-крутилкой (Ship-On: ON по умолчанию), замеряется перепрогоном 111 вопросов готовым харнессом.

**Вне scope / отложено владельцем (детали — §Scope):** настоящий граф-движок AGE/Cypher («Эдж») — реляционный обход 1-2 шага закрывает корни, AGE отложен до замера доли multi-hop (реестр не-сделанного, 2026-07-02); переписывание слоя извлечения памяти (фундамент здоров); синтез и честность (0 галлюцинаций — не трогаем); UI чата.

## Цель + Зачем
На живом тесте 111 вопросов «Мастер» отвечает верно 59.5% (66/111), теряет треть при наличии данных (33%), при этом честен (0 галлюцинаций). Причина — не память (292 блока, 5193 связи — здоровы), а слой поиска: он сужается фильтром и гасит обход по связям. **Цель: верно ≥85%, провал recall <10%, честность 0 галлюцинаций держится.** Это прямое обещание категории «спроси — вспомню за всю команду»; 60% рушат первое касание с клиентом.

## REALITY-CHECK (факт по коду, проверено эмпирически)
- **Граф гасится фильтром — ПОДТВЕРЖДЕНО (главный корень).** `chat-v2-retrieval.service.ts`, метод `retrieve`: `expandViaGraph` вызывается только при `!structural && graphHops>0` (якорь-символ: условие с `structural` рядом с `graphHops`; строки дрейфуют — перечитать). Замер: обход включился 14% (14/103), заглушён 88 раз; 22 из 24 провалов — с выключенным графом.
- **Фильтр = жёсткий AND-cutoff.** `fetchCandidates` при активных `structuralFilters` идёт через `rankByStructuralFilter` (полный скан пула с WHERE-предикатами по `entityIds/signalTypes/themeBranches/dateFrom`), отсекая несовпавшее. Инверсия воспроизведена: q043 «Что с ошибкой 429?» → распознан entity-узел «429», фильтр по нему → `poolSize=0` → отказ; описательный синоним без узла → находит.
- **Жёсткий гейт structural-route.** `chat-v2.service.ts` `runStructuralRoute`: `if (personIds.length===0 && entityIds.length===0) return []` (якорь: возврат `[]` при пустых person/entity).
- **`useSingleSemanticQuery`** для `list/temporal/overview` отбрасывает 2 из 3 перефраз (якорь: имя `useSingleSemanticQuery`).
- **EntityLink не читается в recall.** Строится `entity-graph-builder.cron` (60 связей на тесте), но `retrieve`/`expandViaGraph` его не обходят — только `IdeaBlockLink`. Связи вещь↔вещь простаивают.
- **Понималщик без grounding.** `understand.prompt.ts` `DIALOG_UNDERSTAND_SYSTEM_PROMPT` строка «Не добавляй сущности и факты, которых нет ни в реплике, ни в истории»; `buildUnderstandUserPrompt` подаёт только `summary + history + question`, справочник сущностей тенанта НЕ подаётся. Резолв сущности 40% (39/97).
- **Инструментация замера ГОТОВА (не переделывать).** `chat-v2-retrieval-trace.ts` `RetrievalTraceSink` (опциональный, при `trace=null` прод не затронут); `askEphemeral({collectTrace:true})` → `EphemeralAnswer.retrievalTrace`. Харнесс `backend/scripts/batch-recall-trace.ts` + `analyze-recall-results.ts` + банк `docs/testing/strela-recall-questions.json` (111). Тенант «Стрела» `cmr1qbvpx0001pwbwxbgmh1jl` дозалит до 4 недель (292 блока).
- **Предсуществующий typecheck-красный** `chatbox-chats.service.ts:344` (не в scope, но `bun run typecheck` красный не из-за этих правок — orchestrator фильтрует ошибки по своим файлам).

## Принятые решения владельца (не пересматривать)
| # | Решение | Обоснование |
|---|---|---|
| Р1 | Адаптивная глубина обхода: 1 hop по умолчанию, 2 для многошаговых | Многошаговые «кто отвечает за то, что блокирует X» = 2 звена; 1 hop не дотянет. Простые не замедляем. Арх. Р1 |
| Р2 | Расширять при пустом пуле до честного «вот близкое, точного нет» | Показать релевантное рядом лучше молчания; честность помечена. Арх. Р2 |
| Р3 | Реляционный обход 1-2 hop сейчас; AGE/«Эдж» НЕ в scope | Реляционка закрывает корни дёшево/безопасно; AGE окупается лишь на большой доле multi-hop, а она не замерена. Арх. Р3 + реестр |
| Р4 | Фильтр → мягкий boost, не убирать понимание совсем | Полностью убрать фильтр = потерять точность простых вопросов (сейчас работают). Меняем роль, не удаляем |
| Р5 | Честность (0 галлюцинаций) нетронута; расширение всегда помечено «возможно не всё» | Главный актив доверия; охват растёт без риска выдумок |

## Доказательство выбора (кратко; полный разбор — в анализе)
- **Boost vs полное снятие фильтра (Ф2).** A: убрать structuralFilters совсем → простые точные вопросы теряют точность (регресс там, где сейчас хорошо). B: фильтр как boost к score, пул наполняется широко → сохраняем точность + чиним инверсию. Выбран B (Р4).
- **Каскад vs «всегда широко» (Ф4).** A: всегда искать максимально широко → шум, латентность, риск нерелевантного. B: узкий проход сначала, расширение только при бедном пуле → точность где можно, охват где нужно. Выбран B.
- **Challenge-loop:** каждая фаза чинит КЛАСС (не кейс 429, а «узел без прямых блоков»); переиспользуем `expandViaGraph`/`fetchCandidates`/`RetrievalTraceSink` (не новый код); всё за kill-switch (обратимо); порогов-крутилок — через `getDynamic`, не хардкод.

## Фазы (dependency-ordered)

Граф зависимостей: **Ф6 (grounding) ∥ Ф1 → Ф2 → Ф3 → Ф4; Ф5 после Ф2; Ф7 после Ф3; Ф8 после всех.** Ф1/Ф2/Ф3 трогают общий путь `fetchCandidates`/`expandViaGraph`/`runRetrieval` — строго последовательно. Ф6 (понималщик) независим — можно первым.

---
### Ф1 — Обход по связям блоков участвует всегда
**Ценность:** как сотрудник, спрашивающий про конкретную вещь, получаю ответ, собранный и по прямым кускам, и по связанным — потому что обход по связям больше не выключается фильтром.
**Что входит:** снять гашение `expandViaGraph` при активном структурном фильтре — граф-обход добавляет соседей к отфильтрованному пулу всегда (при `graphHops>0`). Убрать/обусловить условие `!structural`. Kill-switch `knowledge.chatV2GraphAlwaysExpand` (bool, ON). Трейс: `graphExpansion.ran` должен становиться true в этих случаях.
**Что НЕ входит:** глубина >1 (Ф7); EntityLink (Ф3).
**Файлы:** `chat-v2-retrieval.service.ts` (`retrieve`, условие пропуска графа, `expandViaGraph`); `chat-v2.service.ts` (`graphHops` проброс, `~:799`).
**Acceptance:** (1) unit: при непустых `structuralFilters` и `graphHops≥1` `expandViaGraph` вызывается (мок/спай); (2) при OFF-флаге — старое поведение (пропуск); (3) `bun run typecheck && lint && build` зелёные по затронутым файлам; (4) на перепрогоне Ф8 `graphRan` растёт с 14% к >60%.
**Закрывает:** корень 1.

### Ф2 — Структурный фильтр как мягкий boost, не жёсткий cutoff
**Ценность:** как сотрудник, задающий точный вопрос («что с ошибкой 429?»), получаю ответ, а не «не нашлось» — потому что распознавание вещи поднимает нужное выше, но не выбрасывает остальное.
**Что входит:** (а) `fetchCandidates`/`rankByStructuralFilter` — `structuralFilters` перестают быть отсекающим WHERE; пул наполняется семантикой+BM25 широко, совпадение с фильтром даёт прибавку к score (boost), несовпавшее остаётся в пуле ниже. (б) `runStructuralRoute` — снять `return []` при пустых person/entity: откат на семантический пул, а не пустота. Kill-switch `knowledge.chatV2FilterMode` ('boost' | 'hard', default 'boost'); 'hard' = старое поведение. Вес boost — `knowledge.chatV2FilterBoostWeight` (float, default подобрать ~0.3).
**Что НЕ входит:** EntityLink (Ф3); каскад (Ф4).
**Файлы:** `chat-v2-retrieval.service.ts` (`fetchCandidates`, `rankByStructuralFilter`, structural WHERE); `chat-v2.service.ts` (`runStructuralRoute` гейт `~:1299-1301`, `bothWays` `~:1160-1176`).
**Acceptance:** (1) q043 «Что с ошибкой 429?» и q050 «Что с Zoom-интеграцией?» на перепрогоне → `honest=false`, `citationsCount>0`, `poolSize>0`; (2) предикат по всем 111: доля `poolSize=0` при непустом фильтре < 5% (было: инверсные пары давали 0); (3) простые точные вопросы (expertise-угол) не деградируют — verdict CORRECT не падает ниже baseline; (4) unit: 'hard'-режим воспроизводит старую фильтрацию.
**Закрывает:** корень 2.

### Ф3 — Обход по связям между вещами (EntityLink) в recall
**Ценность:** как сотрудник, спрашивающий про вещь без прямых записей («429»), получаю ответ через связанную вещь («Битрикс») — потому что система идёт по связям вещь↔вещь.
**Что входит:** от `resolved entityIds` — обход по `EntityLink` (обе стороны, `status=active`, любой `relationType`) → связанные `Entity` → их блоки через `IdeaBlockEntity` → в пул (со сниженным score, как граф-соседи). Глубина 1. Kill-switch `knowledge.chatV2EntityLinkHops` (int 0|1, default 1). Расширить `RetrievalTraceSink` пометкой источника соседа (block-link vs entity-link).
**Что НЕ входит:** EntityLink глубже 1 (в Ф7 через общий адаптив, если решим); построение EntityLink (уже есть).
**Файлы:** `chat-v2-retrieval.service.ts` (новый метод рядом с `expandViaGraph`, напр. `expandViaEntityLinks`; вызов в `retrieve`); модель `EntityLink` (schema — читаем, не меняем); `chat-v2-retrieval-trace.ts` (пометка via).
**Acceptance:** (1) q043 «429» → пул содержит блоки, привязанные к «Битрикс» через EntityLink (трейс: `neighborsAdded` с via=entity-link); (2) `prisma.entityLink.findMany` реально вызывается в retrieval-пути (grep-маркер); (3) unit на обход EntityLink от узла к блокам связанной сущности; (4) tenantId в запросе EntityLink обязателен.
**Закрывает:** корень 2/3.

### Ф4 — Каскад расширения при бедном/пустом пуле
**Ценность:** как любой спрашивающий, получаю «вот близкое по смыслу» вместо «не нашлось», когда точного совпадения нет, — потому что система расширяет круг перед тем как сдаться.
**Что входит:** после сбора пула в `runRetrieval` — если `pool.length < порог` → ступени: (1) снять/ослабить `structuralFilters` → повторить семантику+граф; (2) если всё ещё мало → поднять глубину графа на +1 (в пределах Р1/Ф7); (3) если и там пусто → honest-abstain. Ответы, собранные через расширение, помечаются для синтеза как «близкое, точного совпадения нет» (Р2, Р5). Крутилки: `knowledge.chatV2CascadeEnabled` (bool ON), `knowledge.chatV2CascadeMinPool` (int, default 5).
**Что НЕ входит:** менять текст honest-abstain (`GROUNDEDNESS_HONEST_ABSTAIN`) кроме добавления ветки «близкое»; трогать groundedness-гейт логику (только не мешать расширению).
**Файлы:** `chat-v2.service.ts` (`runRetrieval` — ветка каскада после сбора пула; `resolveAnswer`/synthesis — прокинуть флаг «approximate»).
**Acceptance:** (1) на перепрогоне доля ложных «не нашёл» (FALSE_EMPTY судьи) < 10% (было 22% honest, ~33% провал по смыслу); (2) галлюцинации остаются 0 (расширение помечено, не выдумывает); (3) каскад наблюдаем (метрика `chat_v2_cascade_used_total` или лог); (4) unit: пул<порог → каскад, пул≥порог → без каскада.
**Закрывает:** корень 4 + вклад в цель провал<10%.

### Ф5 — Широкие вопросы и списки: сводка без ложного отрицания
**Ценность:** как руководитель, спрашивающий «что у нас с интеграциями?» / «покажи все встречи недели», получаю полную сводку, а не кусок с «больше ничего нет».
**Что входит:** (а) снять `useSingleSemanticQuery` для `overview`/`list` — не отбрасывать перефразы; (б) режим агрегации для `overview`: собирать по темам (`ThemeIdeaBlock`) + entity-scoped полный набор, обобщать (не top-1); (в) `list` (встречи) — полный перечень источников, не один; (г) синтез-инструкция для broad/aggregate: «перечисли найденное, НЕ утверждай отсутствие того, чего не искал» (правка user-части синтез-промпта, не системной — не трогая честность). Kill-switch `knowledge.chatV2AggregationMode` (bool ON).
**Что НЕ входит:** новый signalType; переписывание `runStructuralAggregate` целиком (расширяем).
**Файлы:** `chat-v2.service.ts` (`useSingleSemanticQuery` `~:1176`, overview/list ветка `runRetrieval`); `chat-v2-retrieval.service.ts` (`runStructuralAggregate`); синтез (user-инструкция broad).
**Acceptance:** (1) q034 «интеграции в целом» → ответ упоминает Zoom И Telegram И Битрикс, без фразы «других не зафиксировано»; (2) q054 «все встречи за неделю» → перечислено ≥ (реальное число встреч недели − 1); (3) broad/meetings avgCites растёт vs baseline; (4) честность держится (пустая тема → честно, без выдумки).
**Закрывает:** корень 3/5.

### Ф6 — Grounding понималщика справочником тенанта (независима, можно первой)
**Ценность:** как сотрудник, называющий вещь по-своему («медиа-движок»), получаю ответ про «LiveKit» — потому что система знает канонические названия компании ещё на входе.
**Что входит:** перед `understand` достать топ-K кандидатов `Entity` (canonicalName/aliases) и `Theme` (name) тенанта, нечётко похожих на слова вопроса (ILIKE/pg_trgm по токенам вопроса, cap по `knowledge.chatV2GroundingTopK`, default 15); передать в `buildUnderstandUserPrompt` новым блоком «Известные названия компании, возможно относящиеся к вопросу: …»; смягчить запрет промпта — разрешить подставлять КАНОНИЧЕСКОЕ имя из справочника вместо разговорного (не выдумывать вне справочника). `entityHints` тогда содержат каноны → резолв точнее. Kill-switch `knowledge.chatV2UnderstandGrounding` (bool ON).
**Что НЕ входит:** менять число перефраз (остаётся 3); эмбеддинг-поиск кандидатов (ILIKE/trgm достаточно; эмбеддинг — vNext если trgm мало).
**Файлы:** `query-plan-extractor.service.ts` (`understand` — сбор кандидатов + передача); `understand.prompt.ts` (`buildUnderstandUserPrompt` — блок справочника; смягчение запрета в SYSTEM); резолв — переиспользовать `EntityResolutionService`/существующий матч.
**Acceptance:** (1) резолв сущности на 111 > 65% (`resolvedEntityIds/PersonIds` непусты; было 40%); (2) синоним-вопросы контрольных пар (медиа-движок→LiveKit, CRM→Битрикс) → `entityHints`/резолв содержат канон; (3) грануляция: справочник cap соблюдается (≤ topK); (4) prompt caching: справочник — в user-части (переменная), SYSTEM стабилен (раздел «Совместимость с prompt caching» соблюдён); (5) unit на инъекцию справочника.
**Закрывает:** корень 6 + вклад в 2.

### Ф7 — Адаптивная глубина обхода 1-2 (Р1)
**Ценность:** как руководитель, спрашивающий «кто отвечает за то, что блокирует продажи?», получаю ответ через цепочку (блокер→Zoom→Александр) — потому что на многошаговых вопросах система идёт на 2 шага.
**Что входит:** признак многошаговости вопроса (эвристика в понималщике: вложенный «то, что…», «кто отвечает за X, который…»; или ось understand `multiHop`); при нём `graphHops=2`, иначе 1. `knowledge.chatV2GraphHops` (уже есть, default 1, max 2) + `knowledge.chatV2AdaptiveHops` (bool ON). Обход 2 hop — и для block-link, и для entity-link (Ф3).
**Что НЕ входит:** глубина >2 (это AGE-территория, Р3); community-summaries.
**Файлы:** `chat-v2.service.ts` (`graphHops` вычисление адаптивно); `chat-v2-retrieval.service.ts` (`expandViaGraph`/`expandViaEntityLinks` — параметр глубины); понималщик (признак multiHop — опц. ось или эвристика).
**Acceptance:** (1) q062/q037-подобные multistep → находят конечную сущность через 2 hop (трейс: соседи на 2-м уровне); (2) простые вопросы остаются на 1 hop (латентность не растёт для них — проверить по `seconds` в трейсе); (3) multistep avgCites/verdict растёт vs baseline; (4) unit: multiHop-признак → hops=2.
