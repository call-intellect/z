# Форма регистрации «еле видна» на части устройств — oklch без fallback

## Что было поставлено

Владелец показал два скриншота `korateam.ru/signup`: у одних форма открывается
нормально, у других — почти невидима (карточка сливается с фоном, мятная кнопка
«Получить пароль на почту» тёмно-серая, текст еле читается). Задача: найти
причину «у некоторых хорошо, у некоторых еле видно».

## Как решал

1. Нашёл цепочку: `app/signup/SignupForm.tsx` → `AuthShell` → токены `src/ui/tokens.css`.
2. Заметил, что фон страницы в проде — `oklch(0.16 0.012 250)` (через Playwright
   `getComputedStyle`). Все цвета проекта заданы в **`oklch()`**.
3. Проверил собранный prod-CSS из браузера (`fetch` same-origin): главный файл
   135 КБ, **191 `oklch()` и ни одного rgb/hex fallback**; `--bg-base:oklch(...)`,
   `--accent:oklch(...)` — голый oklch.
4. Воспроизвёл баг: на свежем Chrome принудительно переопределил все
   oklch-переменные на невалидное значение (симуляция движка без oklch) и снял
   скриншот — получилось **точь-в-точь** как на «битом» скриншоте владельца.
   Это доказало причину: браузеры без поддержки `oklch()` (Chrome <111, Safari
   <15.4, Firefox <113, **старый Android WebView**, in-app браузеры мессенджеров)
   получают невалидные значения переменных → элементы теряют цвет.

## Что вышло

- Причина: `oklch()` без fallback. Tailwind v4 (`@tailwindcss/postcss`)
  **намеренно** генерит только oklch (его минимальная цель — Chrome 111+ /
  Safari 16.4+ / Firefox 128+), browserslist/autoprefixer в проекте нет.
- Фикс (выбран владельцем — авто-вариант): PostCSS-плагин
  `@csstools/postcss-oklab-function` (`preserve: true`, P3 выключен) после Tailwind
  в `frontend/postcss.config.mjs`. Генерит rgb-fallback перед каждым oklch.
- Эмпирически опроверг своё опасение: плагин v5.0.5 **обрабатывает и
  custom properties** (`--x: oklch()` → пара `--x:rgb(...)` + `@supports`-блок
  с oklch), а не только прямые `color:`. Старые версии этого не умели.
- Верификация: `bun run build` ✓; в собранном CSS каскадный fallback для всех
  переменных в обеих темах (`--bg-base:rgb(9,14,18)` → `oklch`,
  `--accent:rgb(102,230,186)` → `oklch`); regression на свежем Chrome — вид цел.
- Коммит `3f485686` (ветка dev, запушен). Чинит весь сайт, не только signup;
  эффект — после пересборки фронта.

## Чему научился

- **Tailwind v4 не даёт oklch fallback by design.** Любой сайт на нём с целевой
  аудиторией «обычные люди по ссылке из мессенджера» обязан иметь fallback,
  иначе часть пользователей видит сломанный UI и молча уходит. Класс багов —
  не только signup.
- **Проверяй ограничения библиотеки эмпирически, а не по памяти.** Я был
  уверен, что postcss-oklab-function не трогает custom properties (так было в
  старых версиях) — мини-тест за минуту показал обратное и спас выбранный план.
- **Воспроизведение через симуляцию в браузере** (поломка переменных + скриншот)
  — дешёвый и убедительный способ доказать причину «у некоторых» без доступа к
  устройству пользователя.
