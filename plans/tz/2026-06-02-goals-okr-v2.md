# ТЗ: Граф целей (Goals OKR v2) — цели, которые сами рождаются из встреч и всегда правятся руками

> **Анализ-основание:** [plans/analysis/2026-06-02-goals-okr-research-and-gap.md](../analysis/2026-06-02-goals-okr-research-and-gap.md) (разделы 6Б/6В — рекомендованное решение и согласованные развилки).
>
> **Суть:** превратить текущий «термометр согласованности» в **граф целей** — двухуровневую OKR-надстройку (Цель → измеримые Key Results), где цель появляется двумя равноправными путями (авто из встреч + руками), выстраивается в дерево «главная → подцели», прогресс обновляется сам из родных источников (счётчик встреч / задачи трекера / метрики графа), а еженедельный «пульс» подсвечивает, что движется / застряло / выполнено. **Ручной контроль первичен (M0)** — авто это удобство поверх него.

---

## 0. Принципы и границы scope

**Цель ТЗ:** достроить (не переписать) существующий модуль `goals` и подключить новый специалист графа знаний.

**В scope:** расширение `Goal`; новые модели `GoalKeyResult` + `GoalKeyResultCheckpoint`; FK `Idea.goalId` / `Cycle.primaryGoalId`; полноценный ручной CRUD + дерево + supersede; специалист `3-14-goals` (extract + hierarchy-link); авто-прогресс KR; еженедельный пульс (клон COO-дайджеста); UI дерева и пульса на `/goals` + дашборде; мост к гипотезам.

**Вне scope (vNext):** кросс-Org бенчмаркинг целей; индивидуальные цели по сотрудникам (только компания/отдел на этом этапе — см. §10); грейдинг 0.0–1.0 в конце цикла (фиксируем как vNext); внешние интеграции для прогресса.

## 1. Зафиксированные решения владельца (2026-06-02) — НЕ пересматривать без согласования

### M0 (hard) — ручной контроль первичен
- Любое поле любой цели и любого KR **правится в любой момент** через UI/API, независимо от источника (`source ∈ {ai, manual}`).
- **Создать цель/KR руками** = первоклассный путь, равный авто.
- **Перепривязка в дереве** (сменить родителя подцели) — руками.
- **«Передумали через 2 дня»** = правка или supersede; прежняя версия уходит в историю (bitemporal `validFrom/validUntil/supersededById`), но текущая цель отражает новое решение. Удаление/архив — в любой момент.
- **AI никогда не перетирает поле, отредактированное человеком** — флаг `manualOverride` на уровне поля (JSON-набор имён «прибитых» полей).

### Развилка 1 (✅) — измеримый ориентир = таблица `GoalKeyResult` + история `GoalKeyResultCheckpoint`, не JSON.
### Развилка 2 (✅) — три слоя: `Goal` (исход, владеет прогрессом) → `Idea` (гипотеза, `Idea.goalId`) → `Cycle`/спринт (исполнение, `Issue.goalId` + `Cycle.primaryGoalId`). Специалист целей **НЕ создаёт** задачи/спринты/идеи.
### Развилка 3 (✅) — промоут: AI-цель появляется как `state=suggested` («предложено Корой»), активируется тапом owner'а или авто при повторе/высокой confidence; ручная — сразу `active`; обязательного одобрения НЕТ.

### 2.1 Расширение `model Goal` (schema.prisma:3762)

Добавить поля (in-place, существующие НЕ трогаем — `parentGoalId`, `horizon`, `entityId`, `cachedAlignment*`, `weight` уже есть):

```prisma
  /// Источник появления цели. 'manual' (owner завёл) | 'ai' (специалист 3-14 добыл).
  source            GoalSource   @default(manual)
  /// Жизненный цикл предложения: suggested (AI-кандидат, виден но отличим) |
  /// active (официальная) | dismissed (отклонён человеком). Ручная цель → active сразу.
  promotionState    GoalPromotionState @default(active)
  /// Статус движения для пульса (вычисляется авто, правится руками).
  progressStatus    GoalProgressStatus @default(on_track)
  /// Провенанс: блоки графа, из которых добыта цель (GIN-индекс). Пусто для ручных.
  sourceBlockIds    String[]     @default([])
  /// Уверенность извлечения 0..1 (для AI). NULL для ручных.
  confidence        Decimal?     @db.Decimal(4, 3)
  /// Набор имён полей, «прибитых» ручной правкой — AI их не перетирает (M0).
  manualOverride    Json         @default("{}")
  /// bitemporal (паттерн как Decision/IdeaBlock) — для «передумали через 2 дня».
  validFrom         DateTime?
  validUntil        DateTime?
  recordedAt        DateTime     @default(now())
  supersededById    String?
  supersedes        Goal?        @relation("GoalSupersedes", fields: [supersededById], references: [id], onDelete: SetNull)
  supersedeChain    Goal[]       @relation("GoalSupersedes")

  keyResults        GoalKeyResult[]
  linkedIdeas       Idea[]       @relation("IdeaGoal")
  linkedCycles      Cycle[]      @relation("CyclePrimaryGoal")

  @@index([tenantId, promotionState])
  @@index([tenantId, validUntil])
```

Новые enum'ы (рядом с существующими `GoalStatus`/`GoalHorizon` на schema.prisma:705-730):

```prisma
enum GoalSource { manual ai }
enum GoalPromotionState { suggested active dismissed }
enum GoalProgressStatus { on_track at_risk stalled achieved dropped }
```

> ⚠️ Существующие `GoalStatus { active | paused | achieved | abandoned }` и `GoalHorizon { strategic | annual | quarterly | monthly | sprint }` НЕ менять (проверено прямым чтением schema.prisma:705-730). `progressStatus` — отдельная ось «движение для пульса», `status` остаётся жизненным циклом.

### 2.2 Новая модель `GoalKeyResult` (измеримый ориентир, 0..N на цель)

```prisma
model GoalKeyResult {
  id            String   @id @default(cuid())
  tenantId      String
  goalId        String
  goal          Goal     @relation(fields: [goalId], references: [id], onDelete: Cascade)
  /// Текст результата («Провести встречи с клиентами»).
  name          String
  /// Единица измерения («встреч», «%», «₽»). NULL — без числа (но тогда это веха в Goal, не KR).
  unit          String?
  startValue    Decimal  @db.Decimal(18, 4)
  targetValue   Decimal  @db.Decimal(18, 4)
  /// Текущее значение — обновляется авто из источника или руками.
  currentValue  Decimal  @db.Decimal(18, 4) @default(0)
  /// Откуда тянуть currentValue авто: 'manual' | 'meeting_count' | 'issue_rollup' | 'metric_entity'.
  sourceKind    GoalKrSourceKind @default(manual)
  /// Параметры источника (например {meetingType, since} или {entityId}). JSON.
  sourceConfig  Json     @default("{}")
  source        GoalSource @default(manual)
  manualOverride Json    @default("{}")
  createdById   String?
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  checkpoints   GoalKeyResultCheckpoint[]

  @@index([tenantId, goalId])
  @@index([goalId])
}

enum GoalKrSourceKind { manual meeting_count issue_rollup metric_entity }
```

### 2.3 Новая модель `GoalKeyResultCheckpoint` (история значений — для тренда пульса)

```prisma
model GoalKeyResultCheckpoint {
  id           String   @id @default(cuid())
  tenantId     String
  keyResultId  String
  keyResult    GoalKeyResult @relation(fields: [keyResultId], references: [id], onDelete: Cascade)
  value        Decimal  @db.Decimal(18, 4)
  /// Кто/что записал: 'auto' (источник) | 'manual'.
  recordedBy   String   @default("auto")
  note         String?  @db.Text
  createdAt    DateTime @default(now())

  @@index([keyResultId, createdAt])
  @@index([tenantId, createdAt])
}
```

> Идиома Z: текущее значение в `GoalKeyResult.currentValue` (кэш) + неизменяемая история в `GoalKeyResultCheckpoint` — ровно как `GoalAlignmentSnapshot` (schema.prisma:3843) и `PersonGoalContribution`.

### 2.4 Тонкие FK для слоёв (развилка 2)

- **`Idea.goalId String?`** + relation `goal Goal? @relation("IdeaGoal", ...)` + `@@index([tenantId, goalId])` (model Idea, schema.prisma:5508). Гипотеза, двигающая цель.

- **`Issue.goalId`** — уже есть (schema.prisma:7858, relation `"IssueGoal"`), используем как есть для роллапа.

## 3. Совместимость с prompt caching (обязательный раздел, memory `feedback_llm_prompts_cache_friendly`)

Новые taskType — все cache-friendly: стабильный SYSTEM, переменные данные (цитаты блока, контекст) в конце USER. SYSTEM не меняем на каждый вызов.

| taskType | Цепочка провайдеров | Назначение |
|---|---|---|
| `goal-extract` | **capable**: `deepseek/deepseek-v4-pro` → `openai-via-proxy/gpt-5.4-mini` → `ollama/qwen3.5:9b` | извлечь цель + горизонт + (опц.) измеримый KR + провенанс |
| `goal-hierarchy-link` | **cheap**: `deepseek/deepseek-v4-flash` → `openai-via-proxy/gpt-5.4-mini` → `ollama/qwen3.5:9b` | арбитр: какая цель — родитель данной |
| `goals-pulse-summarize` | как `operations-daily-digest` (та же цепочка) | связный текст еженедельного пульса |

> **НЕ использовать `anthropic`** (не закупаем — memory `project_z_infra_and_ai`). Старый `patch-goal-alignment-route.ts` с `anthropic` — legacy, новые маршруты сидим без него через `seed-llm-task-routes-goals.ts` по образцу `seed-llm-task-routes-sprints.ts` (TaskRouteSeed + tier/providerName/model, `editedByAdmin=false`).

Промпты — code-fallback в `backend/src/modules/knowledge-core/prompts/goal-*.prompt.ts` (паттерн `decision-extract.prompt.ts`: SYSTEM с `withInjectionGuard`/`withConfidenceCalibration` + USER-builder + JSON Schema strict), admin-editable через registry. **`goal-extract` обязан уметь вернуть null** (блок не является целью) — анти-плодёж.

### Фаза 3 — Авто-прогресс KR [ ]
**Цель:** числа двигаются сами.

**Acceptance:** на дашборде видно дерево с цветами статусов и блок «на этой неделе: …»; пн утром формируется пульс-дайджест, при включённом тумблере уходит в Telegram owner/coo (фильтр ролей как в digest). Цвета — только парные токены.
**Тесты:** unit на агрегатор пульса (счётчики по progressStatus), e2e на эндпоинт дашборда с goalsTree.

### Фаза 5 — Мост к гипотезам [ ]
**Цель:** «цель = проверить гипотезу».
**Входит:** UI-связь `Idea.goalId` (в карточке идеи — «двигает цель…») и `Cycle.primaryGoalId` (в мастере/дашборде спринта — «продвигает цель…»); при `Idea.status→shipped` (есть событие idea.status_changed) специалист целей **предлагает** checkpoint-обновление KR (probe, не авто-запись в KR без подтверждения, т.к. это outcome). Специалист целей по-прежнему не создаёт идеи/спринты.
**Acceptance:** идею можно привязать к цели; завершённая гипотеза порождает предложение обновить KR; спринт показывает свою цель.
**Тесты:** unit на связь, на probe при shipped.

## 8. Риски и митигации

| Риск | Митигация |
|---|---|
| AI плодит псевдоцели из болтовни | порог confidence + KNN-dedup + cap фокуса + `state=suggested` (не official) |
| Ложная иерархия родитель↔подцель | провенанс к цитате + ручная перепривязка (M0) + mark-wrong |
| AI перетирает ручную правку | `manualOverride` на уровне поля — жёсткое правило в сервисе |
| Output вместо outcome | `goal-extract` SYSTEM предпочитает outcome-формулировку (урок анализа §3А.2) |
| Приватность финансовых/HR-целей | DataClassPolicy (internal/sensitive), пульс через policy-маршрутизацию |
| Новый signalType ломает governance | НЕ вводим — матчим на существующие `commitment/decision/plan_item`, LLM фильтрует |
