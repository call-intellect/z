# Разграничение доступа к знаниям — как включить и как этим пользоваться

> Дата: 2026-06-11. Фича `knowledge-access-groups` РЕАЛИЗОВАНА в коде (ТЗ `plans/tz/2026-06-06-knowledge-access-groups-and-provenance.md`, Ф1–Ф8).
> Технический рунбук выката — `docs/operations/prod-deploy-log.md §🔐`. Этот файл — практическая инструкция: как владельцу включить и как объяснить пользователям.

## Две оси доступа — это важно понять

В Коре две независимые «оси», которые ограничивают, кто что видит в памяти (AI-чат, поиск, клоны):

1. **Закрытые группы — «Руководство» / «Совет» / «Личное».** ← **ЭТО ТО, ЧТО НУЖНО.**
   Помечаешь встречу как закрытую → её знание видят только члены этой группы. Остальные — нет. Владелец/админ видят всё.
2. **Отделы (автоматическая ось).** Кора при разборе встречи сама вешает на знание метку отдела (по теме/участникам/автору). По умолчанию знание с меткой отдела видит **только этот отдел**.

⚠️ **Подводный камень:** если просто включить разграничение в компании, где у сотрудников заполнены отделы, ось №2 начнёт прятать знание одного отдела от другого — это НЕ то, что нужно для «все видят всё, кроме закрытого». Ниже — как это нейтрализовать.

## Часть A. Что сделать владельцу, чтобы включить (по шагам)

### Шаг 1. Выкатить код (один раз)
```bash
# на проде, из корня проекта
docker compose up -d --build backend frontend
docker compose exec backend bun run scripts/apply-prod-deploy.ts --mode update
```
После этого появятся группы «Руководство», «Совет» и группы по отделам. Флаг ещё `off` — **ничего не меняется, все видят всё**.

### Шаг 2. Нейтрализовать ось отделов (чтобы «все видели всё, кроме закрытого»)
Выбери ОДИН вариант:
- **Если в тест-компании отделы НЕ заполнены** (у людей нет отдела) → ничего не делай. Метки отделов не навешиваются, знание остаётся открытым. Это самый простой случай.
- **Если отделы заполнены** → открой матрицу полностью: в `/company-admin/access-groups` для каждого отдела укажи, что он видит ВСЕ отделы. Тогда метки отделов перестанут прятать знание, и ограничивать будут только закрытые группы.

> Если этот шаг пропустить при заполненных отделах — сотрудники одного отдела перестанут видеть знание других. Это можно вернуть в любой момент (Шаг 5 — откат).

### Шаг 3. Заполнить закрытые группы
В `/company-admin/access-groups` добавь нужных людей в **«Руководство»** и **«Совет»** (владелец/админы уже там автоматически). «Личное» создаётся само под конкретного сотрудника.

### Шаг 4. Включить разграничение
В корневом `.env`:
```
KNOWLEDGE_ACCESS_ENFORCEMENT=enforce
```
```bash
docker compose up -d backend   # подхватить настройку + рестарт
```
> (Необязательно) Можно сначала поставить `=shadow` на день — система посчитает, что *было бы* скрыто, ничего не пряча. Проверка: `docker compose exec backend sh -c 'curl -s localhost:3000/metrics | grep kc_access_'`. Если хочешь сразу — ставь `enforce`.

Готово. Теперь работает: по умолчанию всё открыто, а помеченные закрытыми встречи видны только своей группе.

### Шаг 5. 🔴 Откат (мгновенно, если что-то не так)
```
KNOWLEDGE_ACCESS_ENFORCEMENT=off
```
```bash
docker compose up -d backend
```
Всё возвращается к «всем видно всё», данные не теряются.

## Часть B. Короткая инструкция для пользователей (простым языком)

> Это текст, который техспециалист даёт сотрудникам.

**Как работает доступ к памяти компании в Коре**

- **По умолчанию вся команда видит всё.** Любой сотрудник через AI-чат, поиск и память видит знания со всех встреч компании — в этом смысл общей памяти.
- **Если встречу нужно скрыть от большинства** — при создании или настройке встречи выбери закрытую группу:
  - **«Руководство»** — знания встречи увидят только руководители (члены группы «Руководство»).
  - **«Совет»** — только члены «Совета».
  - **«Личное»** — только сам сотрудник, HR и владелец.
- **Что это даёт:** знания из закрытой встречи (решения, факты, задачи) не появятся в AI-чате и поиске у тех, кто не в группе. Для них этой встречи как будто нет.
- **Владелец и администратор видят всё всегда** — для них ограничения не действуют.
- **Если встречу не помечать** — её знания открыты всей команде (обычный режим).

**Коротко:** хочешь, чтобы встречу видели не все → отметь её закрытой группой. Не отметил → видят все.

## Чего пока НЕТ (если понадобится — отдельная небольшая доработка)

- **Включение per-компания.** Сейчас разграничение — один общий рубильник на всю платформу (ENV). Включить отдельным компаниям независимо нельзя — только всем сразу. Для мульти-тенант-продакшена это стоит сделать настройкой на уровне компании.
- **Подсказка-онбординг в кабинете.** Инструкция из Части B пока не встроена в интерфейс — её объясняет техспециалист. Можно добавить экран-подсказку владельцу при настройке команды.
