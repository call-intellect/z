# Рефлексия: цепочка из 5 ТЗ «единый помощник» + 2 доп-фикса

## Что было поставлено
Реализовать ОДНОЙ цепочкой 4 связанных ТЗ (владелец: «это 4 стадии одной цепочки,
все идут в код, ничего не откладывать; развилки решай сам, не возвращайся»):
1. **dialog-layer** — слитый history-aware «модуль понимания запроса».
2. **chat-v2** — единый промпт-ответчик + человеческий контекст + таблицы.
3. **помощник (concierge)** — развилка/руки/уточнитель, без дубля с chat-v2.
4. **channels** — Telegram/MAX → помощник (синхронизация).
По ходу владелец добавил: **ТЗ#5** — селектор клона у окна ввода кабинета
(вынесенный из chat-v2), и **3 доп-ТЗ в очередь** (Ф7 intent-questions,
перенос задачи в проект, карта должности на /me).

## Как решал (порядок 1→2→3→4→5, потом A/B)
- **Картография фронт-лоудом.** Запустил Workflow из 4 параллельных read-only
  агентов + отдельные разведки (селектор клонов, task-эндпоинты). Это дало точные
  path:line и сниппеты ДО написания промптов кодерам — окупилось многократно.
- **Фаза за фазой, по одному-два кодера, своя приёмка между фазами** (typecheck
  всего backend + build (DI) + targeted-тесты + греп маркеров + re-Read критичной
  логики), коммит по ТЗ. Push не делал (жду подтверждения).
- Коммиты: `3f63f7c1` (ТЗ#1), `13b0cd9c`+`5e3498f9` (ТЗ#2A/2B), `f49e7212` (ТЗ#3),
  `33ae43aa` (ТЗ#4), `4e9f1fec` (ТЗ#5), `dfb82a6f` (Ф7), `b207743d` (перенос задачи).

## Ключевые решения (принял сам, как просил владелец)
- **create_task без правки policy.csv.** `intake_issue/write` = только owner/admin/coo
  (рядовой 403). Решение Р-2: новый self-эндпоинт `POST /api/v1/me/tasks` на
  существующем праве `issue/write` (рядовой им владеет), self-assignee=сам, проект
  «Входящие». Это «действие над своими данными», НЕ изменение матрицы доступа →
  в рамках полномочий. Telegram-парсер раньше обходил RBAC прямым prisma-insert —
  не образец для tool-router (он ходит через REST+RBAC).
- **clone — НЕ режим chat-v2.** Селектор кабинета зовёт существующий
  `clonesApi.askRole` (route уже несёт RBAC/квоту/dialog-layer), а не новый
  параметр в chat-v2 ask. Понимание/синтез остаются «по одному разу».
- **ask_chat_v2 терминальный = capture-and-replace** (не «прерывать на ask»):
  если за turn единственный инструмент — ask_chat_v2, отдаём его текст+цитаты,
  отбросив второй синтез модели; смешанный turn — обычный цикл. Корректно для
  обоих случаев без угадывания интента.
- **SIGNAL_TYPE_CONTEXT_RU как `Record<SignalType,string>`** — compile-guard:
  новый тип без русского ярлыка ⇒ сборка падает. ТЗ называл ~25 значений — их ~57;
  типизация сама заставила покрыть все.
- **Таблицы chat-v2: @Optional кросс-модульный инжект** (KnowledgeCore→Tables,
  ребро одностороннее, цикла нет) + Promise.allSettled + fail-safe → ветка таблиц
  не валит графовый ответ.

## Что вышло (верификация)
- Вся цепочка зелёная: финальный blast-radius прогон (dialog-layer + knowledge-core
  + chat-v2 + concierge + conversational + clones) = **1173 passed / 0 failed**.
  Каждая фаза: typecheck (весь backend, вкл .spec) + build (DI) + targeted-тесты.
- Доп-фиксы: backend tracker 287 passed (+move), frontend 14 (+selector/move);
  Ф7 — снапшот tasks-unified перегенерирован (дискриминатор), 2 теста зелёные.
- Доказательство «не сломал ранее»: пред-существующие 11 инфра-падений (Redis/DB,
  вне blast-radius) одинаковы ДО и ПОСЛЕ доп-фиксов → A/B добавили 0 падений.

## Чему научился (грабли и уроки)
- **Фактчек отчётов суб-агентов критичен (×2 в этой сессии).** (а) Кодер ТЗ#3b
  заявил «`GET /api/v1/me/inbox` не существует → search_tasks 404» — оказалось
  существует (`me-inbox.controller.ts:53`), агент не посмотрел; (б) кодер Ф7 вернул
  кривой финал «I'll stop polling» вместо отчёта и **не перегенерировал снапшот** —
  поймал только своим прогоном (2 failed). Урок: всегда свой греп+тест, не верить
  «зелёному отчёту». [[feedback_agents_can_lie_about_edits]]
- **Карта/ТЗ может врать про код — проверяй источник.** ТЗ Ф7 утверждал «остаток
  из ChatBox» — по коду ChatBox пишет в `Task`, НЕ `IntakeIssue`; реальный источник
  B7 — telegram-task-parser. ТЗ me-role-map утверждал «маппер summaryCache→blocks
  уже есть» — его нет нигде. Картографы-агенты вскрыли обе ошибки ТЗ.
- **Pre-existing phantom-CRLF `.snap` — не мои.** В дереве с начала сессии висели
  modified .snap (tasks-unified/type-*/knowledge-core) — это line-ending шум
  (исходники промптов не менялись), НЕ параллельная работа. Стейджил только реально
  свои; при перегенерации «Snapshots 2 updated» = ровно мой дискриминатор.
- **Reserved-решение владельца ≠ «решай сам».** Несмотря на общий «решай сам»,
  владелец явно зарезервировал продуктовый выбор по карте должности — выношу ему,
  не реализую односторонне (orchestrator §15б).
