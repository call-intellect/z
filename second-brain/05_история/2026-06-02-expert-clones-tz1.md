# Экспертные клоны — обсуждение идеи и ТЗ #1

## Что было поставлено

Владелец принёс идею: через супер-админку создавать «экспертов» (специфических людей-экспертов), заливать в них контент (ссылки YouTube/Rutube, файлы), система скачивает видео → аудио → транскрибирует → строит «второй мозг» эксперта, после чего эксперт продаётся компании, и сотрудники компании могут задавать ему вопросы («проанализируй наш маркетинг за месяц и предложи план»). Просил изучить код, докрутить идею, разбить на этапы.

## Как решал

1. Изучил, как сейчас собирается память и устроены клоны (без vexp — daemon не поднят; обычный grep/Read):
   - **ingest** — уже generic с адаптерами (`meeting`, `document`, `text`, `email`, `telegram`, `phone-call`, `tracker`). Точка входа `IngestService.ingest()` → `RawEvent` → `block-ingest.worker` → граф (`IdeaBlock` + `Entity` + связи). Новый источник = новый адаптер.
   - **ASR** есть (`vox.service`, `transcribe.worker`); диаризации на встречах почти нет — там дорожка на участника.
   - **клоны** строятся из `SkillProfile` (traits «почему я так решил») → `ExecutablePersona`; scope `person`/`role`; `clone-respond` жёстко анти-дипфейк (TOPIC_STARVED — молчит, если мало рассуждений).
   - **доступ** к клону уже есть: `CloneAccessGrant` (per-user, внутри Org).
   - **чего нет:** скачивания видео (yt-dlp/ffmpeg).
2. Развёл идею на 2 ТЗ (по настоянию владельца): #1 «рождение эксперта», #2 «работа эксперта» (думающий помощник).
3. Сверил схему (`Org`, `Source`, `ExecutablePersona`, `CloneAccessGrant`, `Plan`/`Subscription`, `tier-config`) и убедился: вся система tenant-scoped, глобальной сущности нет.

## Что вышло

ТЗ #1 написано: `plans/tz/2026-06-02-expert-clones-creation.md` (коммит 88802cf, ветка feature/demo-shared-org-gaps-fix). 5 фаз: кабинет → приём материалов → постройка мозга → z-admin UI → продажа доступа.

## Архитектурные решения (главное, чему научился на этой задаче)

- **Эксперт = системный Org-кабинет** (`Org.kind='expert_cabinet'`). Это переиспользует весь pipeline один-в-один и даёт изоляцию знаний эксперта «бесплатно» (через `tenantId`). Знания эксперта НЕ должны попадать в граф фактов компании — иначе ломается ядро («кто решил X» вернёт блогера из YouTube).
- **Доступ продаётся компании (per-Org), не пользователю** → новая модель `ExpertAccessGrant`, а НЕ `CloneAccessGrant` (тот per-user внутри одной Org). Эксперт глобальный, создаёт только супер-админ.
- **Эксперт-консультант ≠ текущий style-клон.** Текущий `clone-respond` молчит при нехватке рассуждений (анти-дипфейк). Эксперту это противопоказано — ему надо «анализируй и советуй». В ТЗ #2 — отдельный движок ответа без этого гейта.
- **Скачивание видео** — Python-микросервис `media-fetch` в `infra/` (yt-dlp+ffmpeg), по уже узаконенному паттерну Д2 из document-ingest ТЗ. В `backend/` Python не вводим (CLAUDE.md §7).
