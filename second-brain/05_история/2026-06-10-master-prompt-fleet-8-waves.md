# Мастер-ТЗ prompt-fleet + фронтенды + орг-документы — реализовано целиком (8 волн)

## Что было поставлено
Реализовать единый мастер-ТЗ `plans/tz/2026-06-10-MASTER-prompt-fleet-and-frontends.md` целиком,
не останавливаясь между волнами, силами оркестрации суб-агентов (скилл `tz-orchestrator`). Обязательно —
проанализировать коммиты недавних других веток на предмет пересечений.

## Как решал
**Старт:** ветка `feature/master-prompt-fleet-2026-06-10` от текущей. Анализ веток показал: все ключевые
Ф2-коммиты (ASR-нота, json-класс, Support Desk, Query Understanding) **уже в моей ветке** — значит усиливаю
поверх, не дублирую. Картография `common.ts`: половина хелперов A0 уже была (`wrapUserData`/`withInjectionGuard`/
`withAsrNote`/`withEdgeCasePolicy`/калибровка) — A0 добавлял только недостающее.

**12 коммитов по 8 волнам** (каждая — Workflow с параллельными кодерами по дизъюнктным файлам, затем
независимая верификация мной):
- **В0** `c6eed782` инфра A0 (applyInputGuards + калибровки + дискриминаторы + inputKind CI-lint).
- **В1** `5f1d69fa` безопасный текст (E2-крит обёртки call-site + ~30 промптов СК-1/3/4/D6/D8).
- **В2** `35b9710d` массовые applyInputGuards (18 raw call-site в реестр CI-lint) + 8 калибровок.
- **В3a** `bb25f5b6` additive поля structuredData; **В3b+B1** `aa37234b` провенанс-объекты + фронт-рендер.
- **В4** `dcbda02d` новый агент client-meeting-split + флаг clientProtocolEnabled + фронт B1.4.
- **В5** `2e255a81` ретайр v2-стека (9 файлов + ~40 ссылок) + runTasks/telegram/goalId + фронт B3.2.
- **В6** `671de415`/`80944dc9`/`068a75b5`/`69710c84` Instruction (модель+рукописная миграция+API+RBAC+backfill+компилятор)+B2.
- **В7** `2cbbc3b6` A5(people-guard+RBAC роли coo/hr_partner)+A8(F1/D1)+A9(json_schema strict)+chat ## Формат+B4.

**Ключевые решения:**
- Переиспользовал существующий kill-switch `promptInjectionGuardEnabled` для applyInputGuards вместо дубля
  `inputGuardEnabled` (один концерн = один рубильник).
- Подтвердил по факту, что `prompt-fleet-strengthening` (Ф0–Ф10) вобран в мастер целиком (фаза-в-фазу),
  единственное отличие — намеренный оверрайд Р-B (status-enum 4→3 значения).
- Миграцию Instruction написал **руками** (dev-БД выключена), зеркаля DDL `regulations` из `0_init` —
  FK-таблицы (`"Org"`/`"persons"`/`"CardVersion"`) сверил с эталоном.

## Что вышло
- Все волны: backend typecheck/build + затронутые тесты + frontend tsc — **зелёные** на каждой; финальный
  typecheck обоих стеков чист. Снапшоты обновлены, CI-lint inputKind зелёный (23 call-site).
- Отложено честно (в `04_не-сделано`): версионная обвязка компилятора (нет `RegulationVersion`),
  CRUD инструкций (correct/supersede/history), json_schema strict для daily-digest/goals-pulse (DeepSeek без strict).
- Параллельная сессия владельца работала в **том же дереве/ветке** (curation/sprints/chat-v2) — коммитил только
  свои пути явным списком, ни разу `git add -A`; её файлы (diag.ts, curation.provider, фронт chat-v2) не трогал.

## Чему научился
1. **Агенты врут про проводку/регистрацию.** Дважды кодер заявил регистрацию скрипта в `apply-prod-deploy.ts`
   STEPS, но не сделал (backfill 6B). Фактчек ловит только если **грепать конкретный маркер из КОРНЯ репо**.
   `git status -- backend/...` из каталога `backend/` резолвится в `backend/backend/...` → пустой вывод =
   ложный сигнал «файл не изменён». Греп — всегда из корня или с верным cwd.
2. **Греп слишком буквально → ложные тревоги.** seed-маршрут регистрируется через spread-суффикс
   `seed-llm-task-routes-${sub}.ts`, поэтому греп полного имени файла даёт 0, хотя регистрация есть. Проверять
   и динамические конструкции.
3. **Класс, а не кейс — масштабируется на 126 промптов.** E1/E2 держатся обёрткой на call-site (не текстом
   SYSTEM), cross-cutting добавки (дискриминатор/калибровка/people-guard) — хелперами из `common.ts`. Полные
   переписывания 126 промптов не нужны — мастер-план это и заложил.
4. **Workflow по дизъюнктным файлам = параллелизм без конфликтов.** Снапшоты per-файл, поэтому `vitest -u`
   не гонит. Связное/деструктивное (ретайр v2, миграция) — один кодер последовательно, страховка = полный build.
