# Golden-набор для агента `skill-trait-detect`

Этот набор защищает агента γ-1 — Specialist 3.7 (SkillProfile) — от двух классов
регрессий, которые невидимы до тех пор, пока пользователь не увидит формулировку
своего «клона»:

1. **«Приговорный» стиль формулировок.** Любые слова вроде «перфекционист»,
   «выдающийся», «идеальный», «ответственный», «грамотный» — это пустые ярлыки,
   а не описание поведения. Они моментально подрывают доверие.
2. **Отсутствие qualifier'а.** Формулировка должна быть гипотезой
   («похоже», «склонен», «в большинстве случаев», «часто»), а не приговором.

Дополнительно — защита от тихого ухудшения после смены primary-модели в
`LlmTaskRoute` (по ТЗ модель критичного агента переводится на DeepSeek V4 Pro
с явной фиксацией — см. `plans/tz/2026-05-25-clone-reliability-hardening.md`,
фаза 6.4 и 6.5).

## Содержимое

- `fixtures/01..20-*.json` — 20 валидных кейсов, разные виды поведенческих черт
  (осторожность с оценками сроков, требование данных перед решением,
  делегирование ранних оценок, поиск edge cases, опора на исторические инциденты,
  предпочтение асинхронной коммуникации и т.д.).
- `fixtures/21..25-reject-*.json` — 5 отказных кейсов: цитаты без рассуждения
  (commitments, рутинные согласия, эмоциональные реакции, технические вопросы,
  риторические пустые фразы). На них агент должен вернуть пустой `sourceBlockIds`.

Каждая фикстура содержит 3+ цитат с реалистичной речью на русском и временными
метками за разные даты в апреле-мае 2026.

## Формат фикстуры

```jsonc
{
  "fixtureId": "01-cautious-deadlines",
  "category": "valid",           // "valid" | "reject"
  "personName": "Сергей",
  "personRole": "backend lead",  // null допустим
  "quotes": [
    { "blockId": "...", "quote": "...", "observedAt": "ISO-8601" }
  ],
  "expected": {
    "shouldExtract": true,                                // false → ожидается отказ
    "categoryGloss": "осторожность с оценками сроков",    // подсказка человеку, что должно получиться
    "categoryKeywords": ["оценк", "срок"],                // хотя бы одно по подстроке должно появиться в category|statement
    "statementContainsQualifier": true,                   // обязателен «похоже»/«склон»/«часто»/«обычно»/...
    "minObservations": 3,
    "expectedConfidence": "medium",                       // опц. — если предсказуемо
    "forbiddenWords": ["идеальный", "выдающийся", "перфекционист"]
  }
}
```

Поле `expected` — это **не точная строка ожидаемого выхода**, а набор инвариантов:
проверяем category по ключевым словам (стемминг подстрокой), требуем qualifier,
длину полей по JSON-схеме, и что `sourceBlockIds` — подмножество входных `blockId`.

## Как запустить

Обычный прогон (mock-режим, без вызовов LLM):

```bash
bunx vitest run backend/test/eval/skill-trait-detect-golden/skill-trait-detect-golden.spec.ts
```

или коротко:

```bash
bun run test:unit -- skill-trait-detect-golden
```

Этот режим проверяет:

- структуру 25 фикстур (формат, числа, даты);
- что user-промпт `SKILL_TRAIT_DETECT_USER_TEMPLATE` собирается без ошибок и
  содержит каждое имя и blockId;
- что механика инвариантов (`checkInvariants`) ловит запрещённый стиль,
  отсутствие qualifier'а, неверный confidence, чужие blockId и подмену отказа
  на извлечение.

Реальный прогон через LLM (эксперимент со своим бюджетом, не на CI):

```bash
SKILL_TRAIT_DETECT_GOLDEN_REAL=1 bun run test
```

Этот блок сейчас содержит `it.todo` — точка расширения для интеграции
с `LlmRouterService` (DeepSeek V4 Pro). При подключении каждая фикстура
прогоняется тем же путём, что и в проде, и ответ проверяется через
`checkInvariants`.

## Когда обновлять

- При правке `backend/src/modules/knowledge-core/prompts/skill-trait-detect.prompt.ts`
  (формулировки системного промпта, схема `skill_trait_detect_v1`).
- При смене primary-модели агента в `LlmTaskRoute` (по ТЗ — DeepSeek V4 Pro,
  заморозка через `pinnedVersionNote` + snapshot-тест seed).
- При появлении нового класса поведенческих черт, не покрытого 20 валидными кейсами.
- При обнаружении нового «приговорного» паттерна в проде — добавлять в
  `forbiddenWords` соответствующих фикстур.
