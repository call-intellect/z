# AI-директор по ценности (Value Director)

> **Статус: идея, не реализовано** — в коде нет ни модуля, ни модели `AgentBriefing`, ни taskType `value-director` (проверено 2026-06-17). Документ перенесён из `second-brain/01_projects/` в `plans/analysis/`: это план будущей фичи, а не текущее состояние.

> Цифровой сотрудник из «AI-совета директоров», который помогает CEO держать клиентскую ценность в фокусе ежедневно. Работает поверх памяти компании (Z/Кора), применяя методологию из [[../06_marketing/client-value-framework]].
>
> **Канонический ID:** `value-director`
> **Полное имя (RU):** AI-директор по ценности
> **Полное имя (EN):** Value Director
> **Короткое:** VD-агент
> **Принадлежит:** AI-совет директоров — будущий слой агентов-советников CEO (см. §10).

---

## 1. Зачем он нужен

Внутри компании за клиентскую ценность отвечает человек — **Value Officer** (см. [[../06_marketing/client-value-framework]] §10). Он ведёт карты ценности, делает аудиты, считает метрики — это операционная работа.

**AI-директор по ценности** дополняет его сверху:
- **синтезирует** сигналы из памяти компании за CEO, чтобы CEO не тонул в деталях,
- **проактивно подсвечивает** риски (упал LTV, формулировка ценности не сходится с фидбеком, появилась новая боль клиента),
- **отвечает на вопросы CEO** в формате «второго мнения» — на основе методологии и данных, а не «мне кажется».

Это **первый агент** в будущем AI-совете директоров Z/Коры. Каждый будущий агент закроет одну зону (продукт, продажи, люди, финансы, риски). VD-агент — про ценность.

---

## 2. На что опирается (методология)

Полностью наследует методологию из [[../06_marketing/client-value-framework]]. Любой ответ или сигнал агента — это применение одного из этих фреймов к данным компании:

- Ценность = **результат для клиента**, не процесс компании.
- Карта ценности из 5 вопросов (клиент → боль → ценность → метрика → влияние на прибыль).
- Чек-лист формулировки (5 пунктов).
- 3 ошибки переоценки (больше чем нужно / никто не знает / не сойдётся P/L).
- Формула прибыли через 4 статьи затрат на ценность (создание / обслуживание / удержание / информирование).
- Чек-лист устойчивой компании (6 пунктов).
- 4 рычага роста (↑ ценность, ↓ расходы, ↑ LTV, правильный CAC).

Если вывод нельзя свести к одному из этих фреймов — агент честно говорит «вне моей зоны».

---

## 3. Источники данных (что читает из памяти компании)

Z/Кора уже строит единое информационное ядро (`knowledge-core`). Агент работает **поверх** ядра, без прямых обращений к Prisma.

| Источник | Что берёт |
|---|---|
| `IdeaBlock + Entity + Theme` (knowledge-core) | Граф знаний из встреч/чатов/заметок — сигналы о клиентах, болях, ценности |
| `Card` (CRM-структура) | История клиентов, сделок, проектов |
| AI-отчёты по встречам | Особенно типы «продажа», «фидбек», «онбординг» |
| Метрики ценности | Как только Value Officer (человек) их заведёт |
| Цели компании + strategic alignment | Сверка «ценность ↔ стратегия» (Phase 9) |
| Дашборд директора | Общий контекст состояния бизнеса (Phase 8) |
| Внешние сигналы (опционально) | Отзывы клиентов в открытых источниках, новости по сегменту |

Доступ — через `/api/v1/knowledge/search`, `/api/v1/knowledge/graph/neighbors`, RAG по картам, `/api/v1/cards/:id/themes`.

## 4. Инструменты (tools агента)

Tool-use через LlmRouter. Каждый инструмент = эндпоинт Backend Z.

- `value_map_lookup(icp_or_product)` — получить актуальную карту ценности
- `value_metric_query(product, period)` — динамика метрики ценности
- `signal_search(query, since)` — поиск в knowledge-core по теме (встречи / чаты / фидбек)
- `client_journey(card_id)` — собрать историю клиента целиком
- `audit_value_formulation(text)` — прогнать формулировку через чек-лист 5 пунктов
- `profit_breakdown(period)` — разложить экономику по 4 статьям затрат на ценность
- `cac_ltv(segment, period)` — посчитать соотношение
- `draft_digest(period)` — сгенерировать черновик дайджеста ценностных сигналов
- `compare_to_competitors(value, competitor)` — сравнить нашу формулировку ценности с тем, как её даёт конкурент (опционально, читает [[../06_marketing/competitors]])

## 5. Артефакты (что выдаёт)

Тот же ритм, что у человека-Value Officer, но автоматизированный.

| Период | Артефакт | Куда |
|---|---|---|
| **Daily** | 1 ценностный сигнал из свежих данных + интерпретация + рекомендация | Лента «AI-совет директоров» на дашборде CEO |
| **Weekly** | Сводка по 1 метрике ценности (по очереди по продуктам): динамика, гипотеза, что проверить | Виджет «Ценность недели» |
| **Monthly** | Аудит 1 карты ценности по чек-листу из 5 пунктов + предлагаемые правки | Отчёт CEO + diff к карте |
| **Quarterly** | Quarterly value review (портфель ценностей, CAC/LTV, риски, 4 рычага) | PDF/MD-отчёт CEO |
| **On-demand** | Ответ CEO в чате: «что у нас с ценностью для сегмента X?» | Чат-дашборд |
| **Proactive** | Алерт при триггере (CAC > LTV, формулировка не прошла аудит, LTV упал ≥ X%, новая повторяющаяся боль в фидбеке) | Push в дашборд + email/Telegram |

Формат любого артефакта: **наблюдение → импликация → рекомендация → метрика для проверки**.

---

## 6. Как взаимодействует с CEO

- **Виджет на дашборде** — блок «AI-совет: Ценность» с последним сигналом и одной кнопкой «подробнее».
- **Отдельный чат с агентом** — режим «спроси директора по ценности».
- **Проактивные алерты** — когда сработал триггер, агент сам пишет CEO.
- **Утренний брифинг** (опционально) — короткий текст «3 ценностных сигнала за вчера + 1 рекомендация».

## 7. Промпт-каркас (high-level)

Полный промпт хранится в **prompt registry** (admin-editable, с code fallback — по правилам skill `z-ai-agent-rules`). Скелет:

- **Identity.** «Ты AI-директор по ценности компании. Твоя единственная зона — клиентская ценность как драйвер прибыли.»
- **Methodology.** Содержимое [[../06_marketing/client-value-framework]] грузится в системный контекст; все ответы должны быть выводимы из этих фреймов.
- **Boundaries.** Не давай советов по продукту, найму, технологиям, маркетинговым текстам. Если вопрос вне зоны — переадресуй другому агенту совета.
- **Style.** Короткие, конкретные рекомендации с цифрами. Всегда — «что конкретно предлагаю сделать».
- **Format.** Структурированный ответ: наблюдение → импликация → рекомендация → метрика для проверки.
- **Tools.** Перечень доступных функций (§4) + правила их использования.
- **Anti-patterns.** Никаких общих слов без цифр. Не повторяй то, что CEO уже знает из дашборда. Не давай совета, противоречащего методологии (self-check перед ответом).

**Prompt key:** `agent.value-director.system` (registry).
**Версионирование:** через стандартный prompt registry, A/B через `experimentGroup` в `AiUsageLog`.

## 8. Границы и антирол

- **Не делает:** продуктовых решений, найма, архитектурных рекомендаций, маркетинговых текстов, прогнозов выручки, юридических выводов.
- **Не заменяет:** Value Officer (человека) — он по-прежнему ведёт карты ценности и операционные аудиты. Агент — синтезатор и второе мнение.
- **Не выходит за методологию:** если совет не выводим из фреймов §2 — честно говорит «вне моей зоны».
- **Не вмешивается в данные:** только читает, ничего не пишет в knowledge-core / cards / metrics. Все правки идут через человека.

## 9. Метрики качества самого агента

Как поймём, что VD-агент полезен:

- **Action rate** — % сигналов агента, которые CEO принял к действию (отмечает в дашборде).
- **Time-to-insight** — время от события в данных до сигнала от агента.
- **Override rate** — как часто Value Officer (человек) правит выводы агента. Высокий → методология агента кривая, надо тюнить промпт.
- **Coverage** — % продуктов и ICP, по которым у агента есть актуальная карта ценности.
- **CEO satisfaction** — раз в месяц CEO ставит одну оценку «Помог ли агент в этом месяце? 1–5».

Метрики собираются автоматически в новую таблицу `AgentBriefing` (kind, scope, period, content, ceoAction, override).

## 10. Место в AI-совете директоров (будущее)

VD-агент — **первый** из линейки агентов-советников CEO. Следующие на очереди (порядок — гипотеза):

- **AI-директор по продукту** (Product Director) — фичи, бэклог, retention продуктовых решений.
- **AI-директор по продажам** (Sales Director) — воронка, конверсия, причины потери сделок.
- **AI-директор по людям** (People Director) — найм, удержание, нагрузка, сигналы выгорания.
- **AI-директор по финансам** (Finance Director) — кассовый разрыв, юнит-экономика, рентабельность.
- **AI-директор по рискам** (Risk Director) — концентрация клиентов, юридические/операционные/кибер-риски.

**Принципы AI-совета** (общие для всех агентов):
1. Один агент = одна зона ответственности (нет агентов-универсалов).
2. Все опираются на единую память компании (knowledge-core).
3. У каждого admin-editable промпт в registry.
4. Все встроены в один и тот же дашборд CEO как члены «совета».
5. Агенты могут переадресовывать вопросы друг другу.
6. Каждый агент имеет антирол — «что НЕ делает».
7. Качество агента измеримо (action rate, override rate, CEO satisfaction).

Отдельный документ `ai-board-of-directors.md` создадим, когда появится второй агент.

## 11. Реализация в Z (технически)

- **Промпт:** prompt registry, key `agent.value-director.system`. Admin-editable, code fallback. Правила — skill `z-ai-agent-rules`.
- **LLM:** Claude Sonnet через `proxy.agent-lia.ru`. LlmRouter, новый `taskType: 'agent-value-director'`.
- **Tools:** новый модуль `backend/src/modules/agent-value-director/` — сервис-оркестратор + эндпоинты-инструменты (§4).
- **Очереди:** BullMQ — расписания (daily / weekly / monthly / quarterly) + on-demand queue для чата + watcher на метрики и фидбек.
- **Хранение:** новая модель Prisma `AgentBriefing` (id, agentKind, scope, period, content, recommendation, metric, ceoAction, override, createdAt).
- **UI:** виджет «AI-совет: Ценность» на `/dashboard`; страница `/dashboard/value-director` с историей сигналов и чатом.
- **RBAC:** доступ — owner / admin / роль `ceo` (новая). Member видит только агрегаты без чувствительных деталей.

> Детальное ТЗ на реализацию — отдельный план в `plans/tz/<дата>-ai-value-director.md` (создаётся при готовности к разработке).
