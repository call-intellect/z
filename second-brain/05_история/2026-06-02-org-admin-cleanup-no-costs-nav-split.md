# Что было поставлено

Пользователь (роль владельца платформы, оркестратор) по скриншоту кабинета указал на три проблемы в org-кабинете:
1. «Настройки» и «Админка компании» дублируют друг друга — оба пункта рейла открывают один и тот же второй сайдбар.
2. Визуальное «наложение интерфейсов» — сайдбар рисуется дважды.
3. Владелец Org видит расходы/себестоимость LLM (доллары, провайдеры deepseek/ollama, разбивку по функциям) — этого быть не должно: клиент платит за тариф, остальное на платформе.

Сначала — анализ (несколько итераций уточнения), затем ТЗ, затем реализация в роли оркестратора (я раздаю агентам, принимаю работу).

# Как решал

**Анализ → ТЗ.** Прочитал код и установил корни:
- Дублирование: `/settings/admin/*` физически вложен в `/settings`, поэтому переиспользует `SettingsSidebar`, где admin-разделы уже подсекция «АДМИНКА». Двойной сайдбар — `settings/admin/layout.tsx` рендерит `SettingsSidebar` второй раз поверх родительского `settings/layout.tsx`.
- Расходы: `/settings/admin` редиректил на `usage` («Экономика»), + карточка «LLM расход» в knowledge-core, + frontend `org-admin-usage.api`, + backend `OrgAdminUsageController`.
- Ревизия вкладок: реально нужны клиенту только **Доступ к памяти** + **Источники** + **Встречи**; «Ядро знаний» — инженерная отладка не для владельца; «Участники» — дубль «Организации».

ТЗ: `plans/tz/2026-06-02-org-admin-cleanup-no-costs-nav-split.md` (7 фаз).

**Оркестрация.** Ветка `feature/demo-shared-org-gaps-fix` (была активна параллельная сессия — чужие незакоммиченные docs/планы; целевые файлы чистые). Раздал двух агентов параллельно (непересекающиеся стеки):
- backend-агент: удалил `org-admin-usage.controller.ts` + разрегистрация в `admin.module.ts`; вырезал `llm.costUsd` из `org-admin-knowledge.service.ts`.
- frontend-агент: удалил «Экономику» + «Ядро знаний» + их api/домены; создал route-группу `(authenticated)/company-admin/` (`layout` + `CompanyAdminSidebar` + 3 вкладки через `git mv`); очистил `SettingsSidebar` от `ADMIN_ITEMS`; удалил дубль-`settings/admin/layout`; рейл → `/company-admin`; redirect-заглушки старых путей; поправил `nav-help.ts` + тур `overview.ts`.

Коммит `5ff6746` (31 файл, +364/−1572), push в origin.

- **Независимый прогон typecheck**: frontend EXIT 0, backend EXIT 0 (агенты сообщали build OK, я перепроверил сам).
- Гигиена git: в коммит вошли только мои файлы; чужие незакоммиченные (CLAUDE.md, docs/*, чужие планы) остались вне индекса — стейджил явными путями.

- Prod: только код, без БД/ENV/миграций — достаточно `docker compose up -d --build`.

# Чему научился

- **`git add` на уже-удалённый (через `git rm`/`git mv` агента) путь рушит ВСЮ команду** (`fatal: pathspec ... did not match`), и тогда не стейджится ничего. При смешанном дереве с удалениями стейджить по **директориям** через `git add -A -- <dir>` — он корректно ловит удаления/переименования, а явные пути удалённых файлов не перечислять. Связано с [[02_architecture/code-pitfalls]].
- **Параллельный агент может неверно атрибутировать конкурентные правки.** Frontend-агент решил, что backend-файлы менял «tozix/другая сессия», хотя это был мой backend-агент, писавший одновременно. Вывод подтвердил: при параллельной работе агентов фактчек состояния делаю сам, отчётам про «чужие правки» не доверяю вслепую.
- **В Next.js дочерний layout не заменяет, а вкладывается в родительский** — чтобы у раздела был свой сайдбар, он должен физически выйти из-под родительской route-группы (новый top-level путь `/company-admin`, а не `/settings/admin`). Это и есть корень бага двойного сайдбара.
