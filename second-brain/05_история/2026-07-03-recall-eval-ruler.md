# Рефлексия — линейка измерения recall (Шаг 0 роадмапа «77→99»), Ф0–Ф5

## Что было поставлено

Владелец дал добро писать Шаг 0 роадмапа «77→99» — **линейку измерения recall** — ПАРАЛЛЕЛЬНО с тем, как
другой агент чинит извлечение (консолидацию) в реальном коде. Условие: линейка — изолированный dev-only
eval-слой (`scripts/eval/*`), НЕ трогает горячий recall-путь; стенд не запускаю (занят другой фичей) —
только unit-тесты + сухой прогон на замороженных данных. Цель линейки: заменить сломанный сигнал харнесса
(7 из 12 «пустых» прогона-111 — ложные) честной постадийной картиной с атрибуцией провала по слоям.

## Как решал

Как оркестратор ТЗ: 2 параллельные картографии (read-only) → фазы Ф0–Ф5 через прямую реализацию с приёмкой
(typecheck+lint+unit) и коммитом на каждой фазе. Фазы:
- **Ф0** gold-набор (50 вопросов из банка-111): **отклонился от ТЗ осознанно** — вместо `expectedBlockIds`
  сделал `expectedBlockSignatures` (`{entity, phrases}`), т.к. block-id нестабильны при пере-севе (наблюдал
  299→321). Read-only верификатор: 0 unresolved / 0 weak.
- **Ф1** `classify-outcome.ts` — честный классификатор исхода БЕЗ `usedBlockIds`; фикстуры — реальные записи
  прогона-111 (q008→real_fail, q054/q055/q088/q109/q110→answered, q068/q074→honest_empty).
- **Ф2** вынес разбор банка в чистый `parse-bank.ts`, убрал гейт `LIMIT===∞` (цепочки всегда), валидатор банка.
- **Ф3** `stage-metrics.ts` — сигнатурный retrieval recall@k, resolve hit-rate, lift, aggregate.
- **Ф4–Ф5** `judge/panel.ts` (majority-of-3, gold в промпте, `LlmCall` инъекция) + оркестратор
  `run-recall-eval.ts` (`evaluateCorpus` + `renderReport`) + замороженная фикстура 50 записей.

## Что вышло (честно)

**Ф0–Ф5 реализованы, 67 unit зелёные, typecheck+lint+build зелёные.** Сухой прогон на замороженной фикстуре
(без стенда) дал честную атрибутированную картину на gold-50: **отвечено 84% · честно-пусто 10% · реальный
провал 6%** (q002/q008/q098), retrieval 0.81 · резолв 0.90, и точную атрибуцию **q008 → retrieval=0** (блок
Анны не поднялся — ровно известный провал ведра ④). Это несравнимо честнее старого «12 пустых».

**Граница (честно):** это НЕ живой прогон. Живой прогон gold-набора + судья + атрибуция реального recall по
слоям — **под стенд** (стенд занят соседней фичей). 67 unit + сухой прогон это готовят, но не заменяют.
Коммиты `30fb4dcc`/`2247055d`/`723ee3ce`/`69d19c83`/`46a690a6` на `work/2026-07-02`.

## Чему научился

1. **`\w` и `\b` в JS-regex НЕ матчат кириллицу** (ASCII-only даже без `u`-флага). `данн\w*` рвётся на
   «данных», `\bнет\b` не ловит «нет» после пробела перед кириллицей. Фикс: `[а-яё]` + lookaround
   `(?<![а-яё])…(?![а-яё])`. Цена — один упавший unit, поймал сразу. Кандидат в `code-pitfalls`.
2. **Два тенанта «Стрелы» + `.env STRELA_ORG` указывает на чужой.** Соседняя фича (клон-стенд) подняла свою
   «Стрелу» (`cmr4ztnfj…`) и выставила `STRELA_ORG` в `.env`. Мой верификатор читал env → бил в чужой тенант
   (LiveKit=0!). Урок: eval-скрипты ПИНЯТ канонический org явно (`eval-config.ts RECALL_EVAL_ORG`), как это
   делает `batch-recall-trace.ts`, а НЕ читают `STRELA_ORG`. Иначе тихо меряешь не тот граф.
3. **Dev-БД — движущаяся мишень при параллельных фичах.** Число блоков «Стрелы» двигалось 299→321 в процессе
   (соседняя фича пере-сеивала). Отсюда решение заземлять gold на стабильные сигнатуры, а не frozen block-id.
4. **Активный блок «Стрелы» = `status=canonical` + `mergedIntoId=null` (299 шт).** 22 блока `merged_into`.
   Entity активна при `mergedIntoId=null` (171). IdeaBlock-текст ищется по `name`/`criticalQuestion`/`trustedAnswer`.
5. **Встречи (стендапы) живут в Meeting-записях, не в IdeaBlock** — meetings-вопросы нельзя заземлять на
   block-сигнатуры «стендап» (0 хитов), только на mustMention + прокси.
6. **Параллельные агенты в общем рабочем дереве — реально.** Видел untracked-файлы соседних агентов
   (`backend/clone-stand/`, их планы, правки consolidation-ТЗ) в своём `git status`. Спасло правило: стейджить
   ТОЛЬКО свои явные пути, `git add .` никогда. Мои 6 коммитов чужого не задели.
