## A. Командные чаты: Slack, Microsoft Teams, Discord

### Slack

**Модель непрочитанного (unread model)**

Слева — сайдбар (боковая панель) с каналами и личками (DM, то есть прямыми сообщениями). Жирный шрифт = есть непрочитанное. Красная метка = упоминание (@mention) или ключевое слово. После вступления в более чем 30 каналов сайдбар автоматически переключается в режим «только непрочитанные» («Unread only»). Треды (обсуждения, запущенные из сообщения) с непрочитанными ответами всплывают наверх в отдельном разделе «Threads».

[47,2 млн пользователей отправляют 1,5 млрд сообщений в день] → [источник: speakwiseapp.com, снято 2026-06-21] → verified (статистика основана на публичных данных Slack).

[85% сотрудников сообщают, что мессенджеры увеличивают стресс; среднее — 28,6 уведомлений из каналов в день] → [источник: speakwiseapp.com, снято 2026-06-21] → triangulated(2): подтверждается исследованием Slack Engineering (How Slack Rebuilt Notifications).

**Треды (threads)**

Тред — ответ на сообщение в канале, живёт «под» родительским сообщением. Можно также транслировать ответ обратно в канал. Проблема: информация расщепляется на два слоя — канальный поток и поток тредов, — пользователь теряет контекст. [74% технологических руководителей говорят, что сотрудники тратят время на поиск информации по разбросанным тредам] → [источник: supportbench.com, снято 2026-06-21] → claimed (данные приводит вендор-конкурент Slack).

**Каналы + личка**

Каналы организованы вертикально в сайдбаре. Личка — отдельный блок снизу. Звёздочка / пин позволяют фиксировать важное. Принципиальная проблема: при 18+ активных каналах вовлечённость резко падает. [Engagement plummets after 18 channels] → [источник: speakwiseapp.com, снято 2026-06-21] → inferred (методология исследования не раскрыта).

**@упоминания**

Три типа: `@user` — уведомление конкретного человека, `@here` — все онлайн в канале, `@channel` — все подписчики. Плюс ключевые слова (нотификации по триггерному слову). Редизайн 2024–2025 упростил настройку уведомлений канала до трёх опций: «Все новые», «Упоминания», «Заглушить».

[В перестроенной системе большинство пользователей выбирает «Упоминания и личка» как дефолт] → [источник: slack.engineering/how-slack-rebuilt-notifications, снято 2026-06-21] → verified.

**Действия над сообщением (message actions)**

Наведение мыши → панель emoji-реакций + «…» — сохранить, напомнить, переслать, начать тред, добавить в закладки. Slash-команды (`/remind`, `/poll`, `/giphy` и т.д.) — быстрый ввод без мыши.

**Huddles (быстрый созвон, буквально «перебежка»)**

Один клик по иконке наушников в шапке канала или личного чата → аудио-сессия с дроп-ином (drop-in, то есть можно войти и выйти в любой момент без расписания). Канал с активным хаддлом помечен в сайдбаре — видно кто внутри. Старт аудио, опционально видео, шаринг экрана, заметки в тред хаддла. [Исходно вдохновлён Clubhouse] → [источник: cnbc.com, снято 2026-06-21] → verified.

**Поиск**

Полнотекстовый по всему воркспейсу (рабочему пространству). Фильтры: канал, пользователь, дата, тип файла. Работает через `CMD+K` (быстрый переход).

**Редизайн 2024–2025: что сломали**

[Убрали панель переключения воркспейсов — иконки воркспейсов скрыты за одной кнопкой; потеряны `CMD+число` для переключения] → [источник: flagsmith.com, снято 2026-06-21] → verified (Slack в итоге вернул опцию отката).

[Навигационная панель заменена общими категориями «Activity / DMs / More» без конкретики — требует дополнительных кликов] → [источник: medium.com/@SkylerSchain, снято 2026-06-21] → verified.

[Низкий контраст новых тем — текст сложнее читать] → [источник: medium.com/@SkylerSchain, снято 2026-06-21] → inferred (субъективная оценка авторов).

**AI-функции (2025–2026)**

Сводки непрочитанных каналов и тредов. «Today» — персональный утренний дайджест по всем каналам + задачам. [Пользователи экономят в среднем 97 минут в неделю] → [источник: slack.com/help/articles/25076892548883, снято 2026-06-21] → claimed.

### Microsoft Teams

**Объединённый интерфейс чатов и каналов (с июня 2025)**

До 2025 — две отдельные вкладки: «Chat» и «Teams» (каналы). С июня 2025 объединены в один список. Чаты отображаются первыми, ниже — команды и каналы. Критика: «всё, что я вижу — чат, чат и ещё чат» — каналы вытеснены. [Unification rolled out June 2025, Windows/Mac/web/mobile] → [источник: techcommunity.microsoft.com, снято 2026-06-21] → verified.

**Модель непрочитанного**

Постоянные фильтры («Unread», «Chat», «Channels», «Meetings») — включил раз, остаётся. Фильтр «Meetings» показывает только чаты встреч. Выбор: показывать превью сообщения / временную метку / ничего. Переключение скорости рендера: улучшение на 10% через кэш-партиционирование. [Granular cache partitioning → 10% chat switching speed improvement] → [источник: techcommunity.microsoft.com/blog/microsoftteamsblog, снято 2026-06-21] → claimed.

**Кастомные секции (custom sections)**

Пользователь создаёт именованные разделы в сайдбаре и перетаскивает туда чаты и каналы. Предотвращает «усталость от скролла» — аналог папок в почте, но для мессенджера.

**@mention view**

Единый агрегатор всех упоминаний из чатов, каналов и встреч в один список. Работает одинаково для обоих типов общения — унифицированный UX.

**New Message (глобальный compose)**

Отправить сообщение в любой чат или канал без навигации к нему — централизованная точка ввода.

**Треды в каналах**

В новом опыте Teams принял «пост-с-ответами» (post-and-reply) — новые посты сверху, ответы раскрываются под постом. Раньше был поток, похожий на Slack — теперь ближе к форумной модели.

**Нотификации**

Кompact / comfy — выбор размера уведомления. Индивидуальная настройка для каждого канала + глобальный дефолт. @mention view собирает все упоминания вместо показа разными метками.

**Что тяжело (не копировать)**

Историческое наследие: группы (Teams / каналы / подканалы) создают трёхуровневую иерархию. Даже после объединения чата и каналов сложность навигации выше, чем у Slack. SharePoint и встроенные вкладки (Files, Wiki, Apps) перегружают интерфейс нерелевантными для чата вещами.

### Discord

**Серверы → категории → каналы (иерархия)**

Сервер (server, то есть рабочее пространство сообщества) делится на категории, внутри — каналы. Типы каналов: текстовый, голосовой, форумный (forum channel), сцена (stage), объявления (announcement). Иконки серверов — в крайней левой полосе.

**Голосовые каналы — always-on (всегда открытые)**

Голосовой канал не закрывается сам по себе — это «комната», в которую можно зайти в любой момент. Не нужно планировать или рассылать ссылки. Самый сильный паттерн Discord — асинхронный дроп-ин. [Discord's always-on voice: open rooms, drop in whenever, no scheduling] → [источник: medium.com/@sohail_saifi, снято 2026-06-21] → verified.

[Discord обрабатывает голос дифференцированно: разговорная речь ≠ музыка ≠ пение ≠ игровые команды] → [источник: medium.com/@sohail_saifi, снято 2026-06-21] → claimed (технические детали от автора, не от Discord официально).

**Форумные каналы**

Каждый тред — отдельный «пост» с тегами и сортировкой. Хорошо работает для Q&A и баз знаний. Плохо работает: пользователи не всегда начинают тред с нужной точки контекста — теряется начало обсуждения. [Community feedback: "honey we have forums at home" — реализация неинтуитивна] → [источник: support.discord.com community posts, снято 2026-06-21] → inferred (пользовательские отзывы, не системная проблема).

**Треды в текстовых каналах**

Тред = ответ на сообщение, архивируется автоматически после неактивности. Активные/архивные треды — два состояния, архивный нельзя редактировать без разархивирования. Отделяют боковые обсуждения от основного потока.

**Stage-каналы (сцены)**

Один говорит — остальные слушают. AMА (ask me anything, вопрос-ответ с публикой), вебинары, таунхолы. Ведущий управляет микрофонами слушателей.

**Проблемы UX 2025**

Увеличили верхнюю полосу навигации — отнимает место у чата. Уменьшили иконки серверов — сложнее кликать. [Пользовательские жалобы на Discord support, 2025] → [источник: support.discord.com/hc/en-us/community/posts/31042353812119, снято 2026-06-21] → verified (официальный форум Discord).

**@упоминания, реакции, действия над сообщением**

Те же паттерны: реакции emoji, Reply (ответить), Forward (пересослать). Slash-команды для ботов.

**Поиск**

Поиск по серверу с фильтрами: from:/in:/mentions:/before:/after:/pinned. Работает хорошо для небольших серверов; на крупных — медленный без платной индексации.

## B. Поддержка как мессенджер: Intercom, Zendesk, Front, Missive

### Intercom

**Архитектура инбокса**

Слева — список разговоров с фильтрами (все / назначены мне / упомянут / Fin-разговоры / конкретный статус). Слева снизу — переключатель команды/очереди. По центру — переписка с клиентом. Справа — панель контекста: история клиента, его атрибуты, данные из CRM и 350+ интеграций (Salesforce, Jira, Slack).

**Внутренние заметки vs ответ клиенту**

Переключатель в compose-зоне: «Reply» (ответ клиенту) / «Note» (внутренняя заметка, видна только агентам). «Side conversations» — отдельная боковая переписка с коллегой или внешним сервисом, не видимая клиенту. [Intercom: внутренние заметки + side conversations для coordination без выхода в Slack] → [источник: intercom.com/helpdesk/inbox, снято 2026-06-21] → verified.

**Назначение агентов**

Ручное и автоматическое (workload management, round-robin, ограничение нагрузки на агента inbox assignment limits). Очереди/команды — маршрутизация по теме разговора (conversation topics → правила → назначить в команду X).

**AI-черновики (Fin AI Copilot)**

Каждый агент получает Copilot: суммаризация разговора, черновик ответа из базы знаний + истории прошлых разговоров, 3 релевантных внутренних статьи. [Copilot «increases agent efficiency by 31%»] → [источник: intercom.com/helpdesk/inbox, снято 2026-06-21] → claimed.

**AI-агент Fin**

Fin обрабатывает запросы автономно до момента, когда нужен человек. Автохэндофф с полным контекстом — агент видит всю переписку Fin'а. [Fin resolves 50–70% tickets for properly-onboarded customers] → [источник: fayedigital.com, снято 2026-06-21] → claimed (не независимая проверка).

**Объединяют ли командный чат и поддержку?**

Частично — через «Notes» и «Side conversations» внутри тикета. Отдельного командного чата (в смысле Slack-канала для команды) нет; для этого интеграция со Slack/Teams. [Intercom: нет встроенного командного чата — для этого интеграция] → [источник: intercom.com changelog, снято 2026-06-21] → inferred.

### Zendesk

**Архитектура Agent Workspace**

Слева — список тикетов (views — настраиваемые выборки: «Мои тикеты», «Все неназначенные», «По приоритету»). Центральная область — переписка по тикету. Справа — «Context panel» (панель контекста): история клиента, прошлые тикеты, данные из CRM, знания из базы.

**Внутренние заметки vs публичный ответ**

Переключатель в нижней зоне compose: «Public reply» (публичный ответ, идёт клиенту и по email) / «Internal note» (внутренняя заметка с поддержкой форматирования, вложений, emoji). С 2025 — новая настройка: администратор может включить «draft mode by default» — каждый ответ сначала в черновик, только потом агент отправляет. [Draft mode by default — новая настройка 2025] → [источник: support.zendesk.com/hc/en-us/articles/10140103140122, снято 2026-06-21] → verified.

**Назначение агентов**

Тикет назначается одному агенту (single-owner model). Эскалация через группы. Обнаружение коллизий (collision detection): уведомление, если другой агент уже смотрит тот же тикет. Skills-based routing (маршрутизация по навыкам агента).

**Фильтрация разговоров**

Фильтры: «All» / «Public messages» / «Internal notes» / по каналу (email, чат, голос, соцсети). New messages marker (маркер новых сообщений) внутри длинного тикета.

**Командный чат**

Встроенного командного чата нет. Интеграция со Slack — уведомления о тикетах в Slack-канал. [Zendesk: командный чат = интеграция Slack/Teams, не встроенный чат] → [источник: zendesk.com docs, снято 2026-06-21] → verified.

**Что тяжело**

Enterprise-модель: SLA (соглашения об уровне обслуживания) с кастомной эскалацией, Zendesk Explore (аналитика с дэшбордами) — мощно, но настройка занимает недели. Не подходит для малых команд без администратора.

### Front

**Архитектура**

Слева — список разговоров (email + SMS + WhatsApp + соцсети + чат). Разговор назначается как тикет, но выглядит как обычная почта. Центр — переписка. Справа — боковая панель с данными клиента, тегами, историей.

**Внутренние заметки vs ответ клиенту**

Внутренний комментарий (internal comment) — отдельный блок внутри треда, видимый только команде. @mention коллеги в комментарии → уведомление. Ответ клиенту — обычный compose.

**Обнаружение коллизий (collision detection)**

Реального-времени предупреждение: «Иван уже пишет ответ на это». Live draft preview (предпросмотр черновика вживую) — коллега видит, что вы набираете. Предотвращает двойные ответы. [Front: collision detection + live draft previews] → [источник: hiverhq.com, снято 2026-06-21] → triangulated(2): описано в hiverhq и featurebase.

**Маршрутизация**

Многоуровневые условия: по языку, по тегу VIP, round-robin, по времени суток. Мощнее, чем у Zendesk в настройке без кода.

**AI Copilot**

Черновик ответа из базы знаний + прошлых разговоров. Smart QA — автоматическая оценка качества каждого разговора. Smart CSAT — вывод удовлетворённости без опроса. Autopilot — автономное закрытие рутинных запросов. [Copilot: $20/user/month add-on на Starter/Professional; включён в Enterprise] → [источник: featurebase.app/blog/missive-vs-front, снято 2026-06-21] → verified.

**Объединяют ли командный чат и поддержку?**

Частично: @mention в комментариях + прямые сообщения между агентами внутри Front. Нет полноценного командного чата с каналами, как в Slack. [Front: нет Slack-подобного канального чата; только inline-комментарии и @-DM] → [источник: front.com, снято 2026-06-21] → inferred.

---

### Missive

**Архитектура — ключевое отличие: единый экран команды + клиента**

Слева — список разговоров (email, SMS, WhatsApp, соцсети, чат). По центру — переписка с клиентом. В той же переписке, не в отдельной панели — командный чат (internal chat, то есть внутренние сообщения команды). Весь разговор — одна вертикальная лента: сначала письмо/сообщение клиента, затем блок внутреннего обсуждения команды, затем следующее письмо, и т.д.

[Missive: internal chat находится «в теле» переписки, не в отдельной боковой панели — команда обсуждает без выхода из экрана клиента] → [источник: missiveapp.com/blog/effortless-customer-support, снято 2026-06-21] → verified.

**Совместное редактирование черновика (live co-editing)**

Несколько агентов могут одновременно редактировать один черновик ответа клиенту. Аналог Google Docs, но для ответа на email. [Missive: live co-editing on shared drafts] → [источник: hiverhq.com/blog/best-shared-inbox-software, снято 2026-06-21] → triangulated(2).

**@упоминания в комментариях**

`@коллега` внутри разговора → коллега получает уведомление и открывает разговор с полным контекстом. Не нужно пересылать письмо.

**Назначение**

Ручное назначение + правила (rules) с автоматизацией. Нет SLA и продвинутой аналитики (это сознательный trade-off). [Missive: no SLAs, no advanced routing, no real reporting] → [источник: hiverhq.com/blog/best-shared-inbox-software, снято 2026-06-21] → triangulated(2).

**AI**

С начала 2025 — AI-правила автоматизации. Перефразирование, перевод, суммаризация тредов. Нет автономного AI-агента типа Fin. [Missive: AI-driven automation rules from early 2025] → [источник: capterra.com, снято 2026-06-21] → claimed.

**Командный чат без поддержки**

Missive поддерживает чаты «только команда» (без клиента) — отдельные «чатрумы» внутри того же приложения. Это ближе всего к «единому экрану» командного чата + поддержки в одном продукте среди всех четырёх рассмотренных инструментов.

| **Internal notes / внутренняя заметка** | Все четыре (Zendesk, Intercom, Front, Missive) | **Да** — базовый паттерн; переключатель «ответ клиенту» / «заметка для команды» — обязателен |
| **AI-черновик ответа** (Copilot, Fin Copilot) | Intercom Fin Copilot | **Да** — суммаризация + черновик из базы знаний = прямая ценность; у Коры уже есть LLM-инфраструктура |
| **AI-агент первой линии** (Fin, Autopilot) | Intercom | **Да, в будущем** — сейчас не MVP; у Коры есть Concierge-основа; не копировать архитектуру Intercom слепо |
| **Унифицированный список чатов + каналов** (как Teams 2025) | Microsoft Teams | **Осторожно** — хорошо при ≤20 сущностях; при большем числе требует кастомных секций; Teams сам критикуют за «всё — чат» |
| **@mention view** (все упоминания в одном месте) | Microsoft Teams, Slack | **Да** — агрегатор упоминаний нужен; без него пользователи теряют адресованные им сообщения |
| **Форумные каналы** (Discord-формат) | Discord (с оговорками) | **Нет для MVP** — высокий UX-порог освоения; годится для Q&A-базы знаний, но Discord сам получает критику за сложность |
| **Stage-каналы** (один говорит, все слушают) | Discord | **Нет** — узкий кейс (таунхолы, AMA); перегрузит простой продукт |
| **Трёхуровневая иерархия** (workspace → команды → каналы → подканалы) | Teams / Slack (сложный) | **Не копировать** — Teams критикуют за сложность; плоская структура каналов + теги предпочтительнее |
| **Notification fatigue / бесконечные метки** | Slack (проблема) | **Избегать** — не вводить «@channel» и «@all» без явного ограничения; дефолт = «только @me» |
| **Жёсткая workspace-иерархия** | Slack (проблема редизайна) | **Не копировать** — скрытые workspace за кликом = потеря быстрого переключения; держать доступ на поверхности |
| **Тикет-модель с SLA и эскалацией** (Zendesk-стиль) | Zendesk | **Нет для MVP** — тяжело; оставить для будущей фазы поддержки Коры с реальными SLA |

## Что перенести в Кору (приоритизированно)

**Высокий приоритет (прямое решение UX-проблем, малая сложность)**

1. Переключатель «ответ» / «внутренняя заметка» в compose-зоне любого диалога — базовый паттерн из всех четырёх продуктов поддержки.
2. Командный внутренний чат в теле переписки (паттерн Missive) — без этого команда убегает в Slack/Telegram за каждым уточнением.
3. @mention view — агрегатор всех упоминаний из разных чатов/диалогов в один список.
4. Huddle / quick audio одним кликом из любого диалога или встречи — снижает барьер голосового обсуждения без полного видеозвонка.

**Средний приоритет (нужна проработка)**

5. Collision detection при совместной работе с диалогом — обязателен до запуска multi-agent inbox.
6. AI-черновик с контекстом из базы знаний Коры — прямая ценность от графа знаний: Copilot на основе memory.
7. Фильтр «только непрочитанные» — автовключение при большом числе диалогов (порог из AdminSetting).
8. Always-on голосовые комнаты в контексте встреч/проектов — быстрее ситуативного звонка.

**Не копировать**

- Сложную иерархию workspace → организации → каналы → подканалы.
- Массовые @channel/@here уведомления без ограничений.
- Форумные каналы в Discord-стиле без зрелого Q&A контента.
- Тикет-SLA-эскалацию как core-модель на первых фазах.
- Скрытие важных элементов навигации за дополнительным кликом (грабля редизайна Slack 2024).
