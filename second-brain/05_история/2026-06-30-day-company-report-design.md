# Сессия: проектирование дневного отчёта «День компании» (промпт + вход + виджеты)

## Что было поставлено

Спроектировать новый дневной отчёт компании под прототип `plans/analysis/2026-06-28-day-company-prototype/index.html`:
переписать промпт текстового отчёта, разобрать что подаётся на вход (с атрибуцией «кто сказал»), привести
виджеты дашборда (риски/блокеры/идеи) к группировкам, зафиксировать решения под будущее ТЗ.

## Как решал

- Вытащил текущие промпты дашбордов (день/неделя/месяц компании = `operations`, директорский = `dashboard`),
  сверил дневной с прототипом — нашёл разрывы (проза vs структура, запрет имён, нет петли/динамики, лишние «решения»).
- Переписал промпт в `report-prompt-v2.md` (письмо как в прототипе, 12 секций, имена, петля/динамика ко вчера,
  свободный «взгляд директора»; убрал сущность «решение»).
- Исследовал вход 4 слоями через параллельные суб-агенты `Explore` (каналы ингеста, авторство в графе,
  авторство Битрикс/чатбокс, сигналы/повторяемость, существующий дашборд, конфликты). Свёл в `input-sources.md`.
- Зашёл на прод (`korateam.ru`, аккаунт владельца) через qa-tester + Playwright, снял реальный дневной дашборд;
  снял прототип; переделал низ прототипа (блокеры/риски-по-причине/идеи-кластерами) и переснял.
- Зафиксировал решения владельца по 9 вопросам ТЗ.

## Что вышло

`report-prompt-v2.md` + `input-sources.md` (полная карта входа + все решения) + обновлённый прототип + 3 скрина.
Коммит `d022dd82` (ветка `work/2026-06-29`). Открытое (ждёт владельца): конфликты (как показывать) и
цели/компас (пишется отдельное ТЗ). Prod-операций нет — это plans/analysis-артефакты.

## Чему научился (тех-факты проекта)

- **Дневной отчёт — агрегатор, не извлекатель.** Первый этап (`knowledge-core` block-ingest + специалисты)
  уже даёт IdeaBlock/Insight/Idea/решения/идеи с атрибуцией. Не плодить новые агенты — забирать из графа.
- **`Insight.dynamicLabel`** (growing/spike/stable/declining) пересчитывается синхронно при каждом повторе
  на окне 7д/30д (`Specialist35Service.recalcMetrics`) — это ЖИВОЙ признак повторяемости для дневной
  подсветки; недельный `topic-recurrence-detector` для этого НЕ нужен.
- **Авторство сигналов лежит в трёх местах:** `IdeaBlockEvidence.authorPersonId` (не на самом блоке),
  `Idea.createdByUserId` (это User, не Person), `Insight` — косвенно через `sourceBlockIds`. Нет индекса
  под выборку по автору+дате.
- **Конфликты между сотрудниками** — 2 отдельных агента (`PersonalRelationBuilderWorker` на team_friction +
  `CheckInConflictDetectorCron` 04:00 по чек-инам) → `EntityLink relationType='conflicted_with'` с участниками.
- **Чекины/планы/отчётность — закрытая фаза Ф1–Ф8** (`DailyCheckIn` 4 части + `DayReportCollectorService` из
  графа, крон 05:00 МСК). Дневной отчёт компании читает план↔факт оттуда; генерацию держать позже 05:00 (07:00).
- **Битрикс/чатбокс подписаны по спикерам** (per-message `authorPersonId`, резолв `BitrixUser.linkedPersonId` /
  `ChatboxMember.linkedPersonId`; клиент → null корректно).
- **Под богатый прототип формат выхода обязан быть структурным** (гибрид), не сплошной Markdown — иначе нет
  баров/чипов/карточек/светофора осей.
