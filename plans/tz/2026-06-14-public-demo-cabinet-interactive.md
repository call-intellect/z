# ТЗ — Интерактивное публичное демо кабинета Коры для сайта

## Цель

Превратить статичный прототип редизайна кабинета (`plans/analysis/2026-06-13-cabinet-redesign-prototypes/`) в **самодостаточную интерактивную витрину для размещения на сайте**, где потенциальный клиент без регистрации и без бэкенда может «потыкать»: каждая вкладка реально переключается, каждая значимая карточка открывает детальный экран/панель, есть рабочий (офлайн-скриптовый) чат «Спросить Кору», и весь кабинет наполнен богатой непротиворечивой выдуманной компанией. Десктоп и мобилка — синхронно.

**Метрика успеха (проверяемо):** на собранном демо нет ни одного видимого декоративного элемента-обманки в пределах перечня R-критериев ниже — каждый `.pill`/таб переключает контент, каждая карточка из инвентаря §6 открывает деталь, чат отвечает на ≥24 заготовленных вопроса. Открывается двойным кликом по файлу `index.html` из `file://` (без сервера) и не пишет ошибок в консоль.

## Зачем (болезненное состояние)

Сейчас прототип красив, но «мёртвый»: внутри экранов `.pill`-вкладки (`Канбан/Список/Календарь`, `Дневник/Лента/Реестры`, периоды, отделы), карточки встреч/задач/людей, счётчики и CTA — **декоративны**, обработчиков нет. Работают только переключатель экранов (`data-goto`), роли (`data-role`) и темы (`data-theme-btn`). Для витрины на сайте этого мало: посетитель должен почувствовать продукт «руками», иначе демо не продаёт.

Позиционирование Коры — «память компании / memory layer» (приоритет источника — `second-brain/06_marketing/positioning.md`, `messaging.md`, не CLAUDE.md). Демо обязано показывать именно ценность: ритмы → очередь решений → встречи/задачи/память → чат по памяти → клоны ролей.

## Доказательство выбора (два прохода + challenge-loop)

**Проход A (выбран).** Vanilla JS поверх собранного `index.html`: единый делегированный движок взаимодействия (`data-action`), общий слой оверлеев/модалок, общий tab-движок, общий toast; данные и база знаний — во внешнем `demo-data.js`; чат — клиентский матчер по ключевым словам.

**Проход B (отвергнут).** Пересобрать демо как мини-SPA (React/Vite) или подключить чат к реальному LLM-эндпоинту. **Ось отличия:** runtime/сборка и синхронность ответа (живой LLM vs скрипт).

| Критерий | A (vanilla static) | B (SPA / live LLM) |
|---|---|---|
| Соответствие Р1 (ноль бэкенда, ставится куда угодно) | ✓ | ✗ нужен билд/деплой/ключи |
| Контроль ответов чата для клиента (без галлюцинаций) | ✓ курируем | ✗ риск выдать клиенту чушь |
| Работает офлайн (`file://`, iframe) | ✓ | ✗ CORS/ключи/сеть |
| Стоимость и риск проду | ✓ ноль | ✗ ключи, расход, утечка домена |
| Скорость реализации | ✓ | ✗ |
| Маркетинговая «живость» | ✓ скрипт + анимация печати | ✓ (но не нужна ценой рисков) |

→ Сошлись на A. **B отвергнут:** противоречит Р1/Р4 и вносит риск показать проспекту неконтролируемый ответ.

**Challenge-loop по A:**
1. *Корень, не симптом?* Класс-проблема = «каждый интерактивный элемент декоративен». Корневой фикс — **один** делегированный движок + **один** механизм оверлеев + **один** tab-движок, переиспользуемые на всех 10 экранах, а не 50 точечных хендлеров. ✓
2. *Самое эффективное?* Без фреймворка, без роутер-библиотеки; ~1 файл `app.js` (event-delegation). Реальный LLM отложен с числовым триггером: подключать только если владелец захочет live-ответы и согласует ключ/прокси. ✓
3. *Нет кода ради кода?* Переиспользуем существующие CSS-классы (`.glass/.stat/.chip/.list-row/.pill/.btn/.ai-card`) и токены `design-system.css`; новых стилей — минимум (оверлей, чат). KB реально используется чатом. ✓

## Scope

### Входит
- Б1 Демо-копия из артефактов прототипа в новой папке (Ф0).
- Б3 Единый движок взаимодействия `data-action` + слой оверлеев + tab-движок + toast (Ф0).
- Б6 Канон данных `demo-data.js` — одна непротиворечивая выдуманная компания (Ф1).
- Рабочие вкладки/фильтры/сортировки на всех экранах (Ф2).
- Drill-down: встречи (Ф3), задачи + очередь решений (Ф4), команда/человек/роль/клон + «Я» (Ф5).
- Чат «Спросить Кору» (офлайн KB, 2 домена) + плавающий значок-помощник (Ф6).
- Мобилка `mobile.html` синхронно (Ф7).
- Полировка: микроанимации, hover-состояния, проверка светлой темы, README запуска (Ф8).

### Не входит (с судьбой)
- Реальный LLM-вызов из чата → vNext, только по явному согласию владельца + ключ/прокси (см. Challenge-loop п.2). Сейчас — офлайн-скрипт.
- Реальный бэкенд/auth/БД/сеть → не нужно (Р1).
- Изменения в `frontend/` приложении и в прототипе редизайна `2026-06-13-...` → **запрещены** (Р2): демо изолировано.
- Перенос интерактива в реальный кабинет `frontend/app/(authenticated)/*` → отдельное ТЗ редизайна (`relates_to`), не здесь.
- Аналитика/трекинг посетителя сайта → vNext (можно добавить тег позже, в scope не входит).

### Граничные контракты
- Демо **не импортирует** ничего из `frontend/src/*` и не ходит в API — полностью автономно (только свои `app.js`/`demo-data.js`).
- `design-system.css` копируется как есть; править его допустимо только аддитивно (новые классы для оверлея/чата), существующие токены/классы не переименовывать.

## Контракт: единый движок взаимодействия (Б3)

Вся интерактивность — через делегирование на `document`, по атрибуту `data-action`. Никаких инлайновых `onclick`.

```html
<!-- примеры разметки, которую читает движок -->
<button data-action="open-meeting" data-id="m-orbita-demo">…</button>
<button data-action="open-task"    data-id="t-12">…</button>
<button data-action="open-person"  data-id="p-anna">…</button>
<button data-action="open-decision" data-id="d-3">…</button>
<button data-action="tab" data-group="tasks-view" data-tab="kanban">Канбан</button>
<button data-action="decision-accept" data-id="d-3">Принять</button>
<button data-action="ask-kora">Спросить Кору</button>
<button data-action="close-overlay">×</button>
```

```js
// app.js — каркас (обязательная форма)
window.DEMO = window.DEMO || {};
document.addEventListener('click', (e) => {
  const el = e.target.closest('[data-action]');
  if (!el) return;
  const a = el.dataset.action;
  const H = ACTIONS[a];
  if (H) { e.preventDefault(); H(el); }
});
const ACTIONS = {
  'tab': activateTab,
  'open-meeting': el => openOverlay('meeting', el.dataset.id),
  'open-task': el => openOverlay('task', el.dataset.id),
  'open-person': el => openOverlay('person', el.dataset.id),
  'open-decision': el => openOverlay('decision', el.dataset.id),
  'decision-accept': el => decisionAction(el.dataset.id, 'accept'),
  'decision-return': el => decisionAction(el.dataset.id, 'return'),
  'ask-kora': openChat,
  'close-overlay': closeOverlay,
  // … все экшены здесь, ни одного инлайн-onclick
};
```

**Слой оверлеев.** Один контейнер в DOM (добавляется `app.js` либо лежит в `index.html`):
```html
<div id="overlay" class="overlay" hidden>
  <div class="overlay-scrim" data-action="close-overlay"></div>
  <div class="overlay-panel" role="dialog" aria-modal="true"><!-- сюда рендерится деталь --></div>
</div>
```
- `openOverlay(type, id)` берёт сущность из `DEMO`, рендерит шаблон детали по `type`, показывает панель (slide-in справа на десктопе, fullscreen на мобилке), вешает `Esc`→close, блокирует скролл body.
- Закрытие: по скриму, кнопке ×, `Esc`. Без перезагрузки страницы.

**Tab-движок.** `data-group` + `data-tab`; контент-группы помечены `data-tabpanel="<group>:<tab>"`. `activateTab` тогглит `.active` на кнопках группы и `hidden` на панелях группы. Один универсальный обработчик на все вкладки всех экранов.

**Toast.** `toast(text)` — всплывающее уведомление снизу (для mock-действий «Принято», «Слайды готовятся», «Интеграция подключена»), автоскрытие ~2.5с.

## Инварианты (не нарушать)
Только русский UI (англ. — лишь бренды/термины в скобках) · никаких ₽/финансовых KPI и точных цен · никаких рейтингов людей числом — фраза-действие («держит слово», «нужна помощь»), не score · парные цветовые токены `design-system.css`, без `text-white`/жёстких hex/slate · чат отвечает только текстом (голос — лишь имитация ввода, опц.) · никаких inline-кнопок как «уточняющих вопросов» продукта (подсказки-чипы чата — это навигация по демо, разрешено) · демо не ходит в сеть/API/LLM.
