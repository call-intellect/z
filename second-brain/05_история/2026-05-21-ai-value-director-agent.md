# Рефлексия — AI-директор по ценности (Value Director agent)

## Что было поставлено

После создания [client-value-framework.md](../06_marketing/client-value-framework.md) пользователь попросил описать **цифрового сотрудника** на основе той же методологии, который будет частью «AI-совета директоров» при CEO. Просил:
1. Правильно назвать.
2. Ещё раз проанализировать framework-документ.
3. Описать роль, задачи, источники данных, инструменты.

## Как решал

- **Имя выбрал параллельно человеческой роли:** человек = Value Officer (Сотрудник по ценностям), AI = **Value Director (AI-директор по ценности)**. Логика: пользователь сам ввёл метафору «совет директоров», значит агенты — «директора». «Officer» оставил за человеком, чтобы не было путаницы.
- **Создал [01_projects/ai-value-director.md](../01_projects/ai-value-director.md)** — 12 секций:
  1. Зачем (как дополняет человека-Value Officer)
  2. Методология (наследует фреймворк §2)
  3. Источники данных (knowledge-core + cards + AI-отчёты + метрики + цели + дашборд)
  4. Инструменты (9 tool-функций для tool-use)
  5. Артефакты (тот же ритм daily/weekly/monthly/quarterly + on-demand + proactive)
  6. Взаимодействие с CEO (виджет / чат / алерты / утренний брифинг)
  7. Промпт-каркас (high-level скелет, key `agent.value-director.system`)
  8. Границы и антирол
  9. Метрики качества самого агента (action rate, override rate, CEO satisfaction)
  10. Место в AI-совете директоров (планируемые коллеги: Product/Sales/People/Finance/Risk + 7 общих принципов совета)
  11. Реализация в Z (модуль, LlmRouter taskType, BullMQ, Prisma `AgentBriefing`, UI)
  12. Связанные документы
- **Добавил обратную ссылку** в [client-value-framework.md §13](../06_marketing/client-value-framework.md) на агента.
- **Обновил [second-brain/index.md](../index.md)** — добавил запись в раздел «Проекты».
- В техническую часть положил привязки к существующей архитектуре Z: knowledge-core, LlmRouter, prompt registry, BullMQ, dashboard CEO (Phase 8), strategic alignment (Phase 9), skill `z-ai-agent-rules`.

## Что вышло

- Документ описывает агента **дисциплинированно**: с границами, антиролом и метриками качества самого агента. Это не «AI-бот, который умеет всё».
- Заложил **расширяемость** — описал AI-совет директоров как паттерн с 7 общими принципами, чтобы будущие агенты создавались по тому же шаблону.
- Не уходил в реализацию (нет ТЗ, нет схемы Prisma в деталях, нет полного промпта) — это документ-концепция в `01_projects/`, ТЗ создаётся отдельно при готовности к разработке.

## Чему научился

1. **Когда у роли уже есть человеческое имя — AI-двойник называю иначе, но из той же категории.** Человек = Officer (исполнитель), AI = Director (советник). Это сразу снимает путаницу «кто из них что делает».
2. **Описывая AI-агента, обязательно описывать антирол.** Без него агент расплывается в «универсального помощника», теряя ценность. Антирол держит фокус.
3. **Метрики качества САМОГО агента важнее, чем его выводов.** Action rate / override rate / CEO satisfaction — это то, что позволит понять, работает ли он, и тюнить промпт.
4. **Первый агент в линейке — это шаблон.** Сразу выделил «принципы AI-совета» (7 пунктов) — теперь будущие агенты (Product/Sales/People/Finance/Risk) создаются по копии, а не с нуля. Это экономит время и держит единообразие.
5. **AI-агенту нужны границы по данным:** «только читает knowledge-core, ничего не пишет». Без этого начнут спорить, кто хозяин данных. Записал явно в §8.
