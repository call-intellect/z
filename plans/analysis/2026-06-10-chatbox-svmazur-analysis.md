## Что это за функция (не путать)

Это **не самописный «читатель Telegram-группы»**, а **коннектор к внешнему SaaS «Call Intellect: Чаты»** (`https://app.agent-lia.ru`, далее ChatBox). ChatBox сам агрегирует мессенджеры (Telegram, виджет на сайте и т.п.); Кора по токену тянет из него готовые чаты/сообщения/участников и зеркалит в свои таблицы, а затем (опционально) прогоняет через тот же конвейер знаний, что и встречи.

## Как подключён

- Клиент API: [chatbox-api.client.ts](../../backend/src/modules/chatbox/chatbox-api.client.ts). Base URL — ENV `CHATBOX_API_BASE_URL` (по умолчанию `https://app.agent-lia.ru`), префикс `/api/v1`, авторизация `Bearer <token>`.
- Токен — долгоживущий per-tenant, лежит зашифрованным в `ChatboxIntegration.tokenEnc`. Конфиг (workspaceId + токен) отдаёт `ChatboxIntegrationService.getConfigForSync`.
- Подключение/настройка интеграции — раздел кабинета «Чаты → Интеграции → Чат бокс» (`/chats/integrations/chatbox`), гейт по фиче `feature.chatbox`. Отключить интеграцию может **только владелец Org** (в логах видно `DELETE /api/v1/chatbox/integration → 403` от не-владельца).

## Как работает (конвейер)

1. **Cron-синк** — [chatbox-sync.cron.ts](../../backend/src/modules/chatbox/chatbox-sync.cron.ts):
   - `runHourly` (каждый час) — интеграции с `syncMode in (hourly, realtime)`;
   - `runDaily` (каждый день 03:00) — интеграции с `syncMode = daily`.
   - Общий kill-switch `chatbox.enabled` (admin settings, по умолчанию ON). Ставит `incremental`-job в очередь `chatbox.sync`.
2. **Синк** — [chatbox-sync.service.ts](../../backend/src/modules/chatbox/chatbox-sync.service.ts): тянет каналы → клиентов (Customer) → identity клиентов (ChannelClient) → участников (Member) → чаты+сообщения в зеркальные таблицы `Chatbox*`. Инкрементально по курсору `lastIncrementalSyncAt` (чаты desc по `updatedAt`).
3. **Связка «это наши сотрудники»** — `autoLinkMembers`: участник ChatBox ↔ `Person` Коры **по email** (case-insensitive), `linkMode='auto'`; ручную привязку (`manual`) не перетирает.
4. **Сессионизация** — `ChatboxSessionService.rebuildSessions`: сообщения чата группируются в «сессии» (диалоги). Закрытая сессия (`endedAt != null`) — кандидат на анализ.
5. **Анализ сессии** — [chatbox-analyze.cron.ts](../../backend/src/modules/chatbox/chatbox-analyze.cron.ts) берёт closed-сессии **только у интеграций с `analysisEnabled=true`** и ставит job в `chatbox.analyze`; воркер [chatbox-analyze.worker.ts](../../backend/src/modules/chatbox/chatbox-analyze.worker.ts):
   - best-effort LLM-саммари сессии (`taskType=chatbox-summary`);
   - **мост в knowledge-core** — [chatbox-ingest.service.ts](../../backend/src/modules/chatbox/chatbox-ingest.service.ts): сессия → `RawEvent(sourceType='chatbox')` через **тот же `IngestService.ingest`, что и встреча/звонок** → дальше block-ingest worker строит IdeaBlock'и/граф. Атрибуция по говорящему: реплики менеджера → `authorPersonId` ответственного сотрудника, реплики клиента → `null`.
   - **Это ровно то, что хочет владелец: «забрали переписку → запускается та же цепочка, что после встречи».**

## Что сделано / что НЕ сделано

**Сделано (работает):**
- Подключение интеграции + хранение токена (шифрованно), kill-switch `chatbox.enabled`.
- Регулярный синк (hourly+daily), зеркальные таблицы, инкрементальный курсор, пагинация с капом.
- Сессионизация, автосвязка участников по email, ручная привязка.
- Полный мост в knowledge-core (та же цепочка, что встречи), идемпотентность по `sessionId`, per-message атрибуция автора.
- UI: раздел «Чаты», панель AI-анализа в детали чата, ручной запуск анализа, медиа в сообщениях (картинки/аудио/видео).

**НЕ сделано / узкие места (для ТЗ доработки):**
1. **`analysisEnabled` по умолчанию OFF** — главный разрыв. Авто-анализ не идёт, пока владелец не включит тумблер; у «Ооо луа» он выключен → переписка не попадает в граф. Это и противоречит принципу Ship-On (выкатывать включённым).
2. **Матчинг сотрудников — только по email.** Участники мессенджеров (особенно Telegram) часто без email → автосвязка `Member→Person` почти не сработает. Нужен матчинг по имени/телефону + понятный ручной экран «это сотрудник X».
3. **Видимость для владельца.** Нет наглядного ответа «переписка пришла → проанализировано N диалогов → вот карточки». Сейчас статус анализа лежит в детали чата, агрегата нет.
4. **Наблюдаемость.** Нет метрик/алертов «синк отстал», «сессии висят в pending», «analysisEnabled выключен, а синк копит». Диагностика возможна только через логи.
5. **Контракт `sendMessage`** ChatBox иногда без message id (WARN) — проверить, не теряются ли исходящие.

## Рекомендация (войдёт в ТЗ `plans/tz/2026-06-10-chatbox-finishing.md`)

- **Решение по гейту**: либо `analysisEnabled` ON по умолчанию (Ship-On), либо это осознанное «решение владельца» (анализ переписки сотрудников — чувствительные данные) — тогда тумблер должен быть на видном месте и для «Ооо луа» его надо включить. Рекомендация: сделать включение явным шагом мастера подключения ChatBox (владелец сразу решает «анализировать переписку — да/нет»), дефолт — предлагать «да».
- Матчинг сотрудников: email → (телефон, имя) → ручной экран сопоставления участников.
- Дашборд/виджет «Чаты в памяти»: сколько диалогов забрано, сколько проанализировано, ссылки на карточки.
- Метрики синка/анализа + алерт «копим, но не анализируем».
