# Анализ: AI-пайплайн — выбор провайдеров и архитектура обработки

## Что хотим сделать

Спроектировать пайплайн AI-обработки записанной встречи: транскрибация → разделение по спикерам (диаризация) → склейка диалога → применение шаблона по типу встречи (LLM) → итоговый отчёт в БД.

Выбрать конкретных провайдеров для каждого этапа.

## Зачем (цель и ценность)

Главная продуктовая ценность — **«не саммари, а правильный результат под тип встречи»**. Без качественной транскрибации и диаризации все типы (sales, custdev, interview…) превращаются в «мутный пересказ».

Также важна цена: AI-обработка на 100 встречах в день = существенный OPEX, нужен ориентир.

## Как работает сейчас

Кода нет. Есть продуктовое решение, фиксирующее формат входа: **отдельные аудиодорожки на каждого участника** (см. `recording.md`) — это упрощает диаризацию.

## Решение по провайдерам — закрыто (2026-05-06)

Провайдеров **не выбираем** — у компании свои внутренние API:
- **ASR:** GigaAM v3 RNN-T на `vox.agent-lia.ru` (свой self-hosted сервис).
- **LLM:** Anthropic Claude Sonnet (`claude-sonnet-4-6`) напрямую через `api.anthropic.com`.
- **Fallback при блокировке Anthropic из РФ:** MiniMax-M2.5 → GPT-5.2 через `proxy.agent-lia.ru`.

Подробности (ENV, SDK, цены, retry): см. [[../../second-brain/02_architecture/ai-integration]] и memory reference `LLM Integration Handover (Crossmark)`.

Это снимает все вопросы выбора, ниже — только вопросы интеграции.

### Диаризация

При отдельных аудиодорожках на участника диаризация **не нужна** — спикер известен по `participant_id`. Остаётся только VAD-чистка случаев «открытый микрофон + чужой голос фоном» на этапе ASR (`punctuationMode: 'pro'`, `diarizationEnabled: false`).

### Экономика на встречу (10 человек × 60 мин)

- ASR: 60 мин аудио × 10 дорожек = ~600 минут → Vox (свой сервис, биллинг внутренний).
- LLM: ~25k input + ~3k output → `claude-sonnet-4-6` × ($3 + $15)/1M ≈ **$0.12 на встречу**.

## Архитектура обработки (решение от 2026-05-06)

После завершения встречи — **цепочка из 4 этапов**, каждый — отдельная задача в очереди BullMQ (библиотека очередей задач поверх Redis):

```
meeting_finished (webhook от LiveKit)
     ↓
[1] transcribe   — каждая дорожка → Vox → текст с временными метками
     ↓
[2] merge        — склеить транскрипты по времени в единый диалог
     ↓
[3] analyze      — диалог + шаблон по типу → Claude Sonnet → итоговый отчёт
     ↓
[4] notify       — статус ai_ready, уведомление пользователю
```

**Прогресс пользователю** — через статус `Meeting.status` + polling (опрос браузером раз в 5 секунд). WebSocket для MVP избыточен.

**Retry-стратегия** — переиспользуем `WorkerAiClient` из Crossmark: на Vox `[3000, 8000]ms`, на Anthropic streaming — без retry (стрим нельзя перезапустить, делаем fallback на non-stream).

## Закрыто по умолчанию (решение от 2026-05-06 — пользователь дал автономию)

- [x] **Промежуточный транскрипт** — храним в S3 (Selectel) как `meeting_<id>/transcripts/raw.json`. Этапы `transcribe` → `merge` обмениваются ссылками, не телом. Файлы покрываются той же retention-политикой, что и аудио.
- [x] **Промпты по типам встреч** — в коде (TypeScript-модуль `prompts/<meeting_type>.ts`), версионируется через git. Миграция в БД — V2-фича, когда продакт-команда захочет править без релиза.
- [x] **Схема `ai_usage_logs`** — копируется из Crossmark целиком: `companyId / agentType / jobId / model / provider / inputTokens / outputTokens / reasoningTokens / costUsd / durationMs / success / errorText`. Единый формат отчётов между Crossmark и Z.
