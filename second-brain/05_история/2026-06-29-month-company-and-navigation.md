# Рефлексия — «Месяц компании» + навигация по датам/архив (оркестрация 2 ТЗ)

## Что было поставлено
Два парных ТЗ, реализовать оркестратором фаза-за-фазой, в отдельной ветке, с мержем в локальный dev и пушем:
1. `plans/tz/2026-06-29-month-company-monthly-brief.md` — «Месяц компании» (Ф1–Ф6): модель `MonthlyOperationsDigest` → свод 4 недель одним LLM-проходом → герой на `/month` + компас/темп + блоки решить/фокус + доставка.
2. `plans/tz/2026-06-30-report-date-navigation-archive.md` — навигация по датам + архив (Ф1–Ф5): `available-periods` ×3 + общий `PeriodNavigator` + подключение к героям дня/недели/месяца + архив + empty-state.

Порядок выведен из зависимостей: ТЗ-2 потребляет артефакты ТЗ-1 (месячный герой/контроллер/`getByPeriod`), поэтому сначала ТЗ-1, потом ТЗ-2.

## Как решал
Оркестрация суб-агентами: картография (Read по точным якорям ТЗ — vexp на free-кепе backend недокрывает) → самодостаточный промпт кодеру → независимая приёмка мной (re-Read + свой build/tsc/lint/vitest) → коммит по фазам. 11 кодовых фаз, коммиты `9c36a0b6..82e3a893`. Месяц — чистое зеркало уже работающей «Недели компании» (тот же `generate`/`clamp`/`fallback`/компресс-вход паттерн).

**Параллелил непересекающиеся фазы** для скорости: Ф5b+Ф5c ∥ Ф6 (фронт+weekly-per-person vs крон+monthly-service); ТЗ-2 Ф1 ∥ Ф2 (backend vs PeriodNavigator). Условие безопасности — строго непересекающиеся наборы файлов (коммичу я, кодеры не коммитят).

## Чему научился
- **`goalContributionNet` был equality-матч по одному `weekStart`** (наследие «Недели»). Для месяца переведён на **range-sum по окну** `[from..to]` — backward-compatible: недельное окно Пн–Пт содержит ровно один понедельник → результат идентичен, месячное → сумма 4–5. Смена равенства на диапазон невидима для мока спека (он возвращает фикс-массив) — менялась только агрегация. Перекликается с граблей «weekStart equality-матч» из рефлексии «Недели».
- **Конфликт «фиксированный @Cron-час vs крутилка часа»** (ТЗ дал и `@Cron('0 6 1 * *')`, и `monthlyDigestLocalHour`): решил `@Cron('0 * * * *')` (часовой) + гейт по МСК (1-е число && час===крутилка) — крутилка реально работает и тестируема, глобально как value-recap. Это паттерн weekly-крона (часовой + гейт), а не фиксированное выражение.
- **«Числа — код, проза — LLM»**: `pace.{factToGoal,planToGoal,etaIso}` считаю детерминированно (snapshot.score / линейный план по `targetDate` / проекция по delta), у LLM беру только `leadingSignal` (текст). `Goal` не имеет числового таргета (только `targetDate`/`status`/`isPrimary`) — пример из ТЗ (6/10) был иллюстративным, в коде честные null при нехватке данных.
- **Реальность опережает ТЗ**: таб «Месяц» в rhythm-switcher и weekly `/latest` уже существовали (добавлены при «Неделе») — REALITY-CHECK ТЗ устарел; не дублировал. Перед реализацией «как в ТЗ» — грепать факт.
- **schema.prisma — особый файл**: `///`-доки полей и `//`-секции это сквозная конвенция (правило «без комментариев» целит в прикладной TS), сохранял стиль соседей.
- **Параллельные кодеры по непересекающимся файлам** заметно сократили wall-clock без потери контроля качества (приёмку каждого делал отдельно).
